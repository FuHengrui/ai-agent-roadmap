第三章　Trae Builder 模式：让 AI 从 0 到 1 建项目

阶段 16 · Vibe Coding 实践　|　工具实操　|　难度 ★★☆
这一章在解决什么问题

Chat 模式已经很方便了，但有个局限：它"被动"。 你要喂它代码、给它上下文、等它回答——你要什么，它才做什么。如果需求是"帮我做一个 Todo List 网站"这种完整的项目呢？Chat 模式会让你东一句西一句地喂半天。

Builder 模式解决的就是"从 0 到 1 的完整开发"：你只提一个总需求，AI 主动读取项目文件、拆解任务、创建或修改文件、生成并运行命令、分析运行结果，最后给你一个能预览的成品。 它像一位"自动编程实习生"——你布置任务，它自己跑流程，你负责验收。

学完这一章，你能回答：Builder 模式和 Chat 模式的本质区别、怎么启用 Builder、怎么注入多模态需求、怎么批量接受/拒绝代码变更、怎么让 AI 跑命令并分析结果、怎么预览成果、怎么回退建造过程。这一章是 Trae 实战力的核心，也是最接近"Vibe Coding"真谛的一章。

这一章在整个知识库里的位置 上一章：Chat 模式——你在侧边栏问、AI 答，你手动落地。 本章 ← 你在这里：Builder 模式——你给总需求，AI 自动拆解、改文件、跑命令、给预览 下一章：上下文与 Rules——让 AI 更懂你的项目和偏好（Chat/Builder 都受益） 再往后：模型切换与自定义模型 → MCP 旅行助手 → Cursor → Codex 阶段终点：三款工具都能做到"一句话起项目"
学习提示

Builder 模式的核心是一条闭环工作流：读取上下文 → 拆解任务 → 创建/修改文件 → 运行命令 → 分析结果 → 预览 → （不满意）回退。学的时候盯住这条闭环，每一步的按钮操作遇到时再对照即可。

1① Builder 模式是什么：主动干活的 AI
要解决什么

先分清 Builder 和 Chat 的本质区别——这是 Trae 三种工作面里最重要的概念分界。

核心思路

Builder 模式下，AI 助手会主动读取当前项目中的文件内容，拆解任务并逐步执行，包括：

  • 提取相关上下文
  • 创建或修改文件
  • 生成并运行终端命令
  • 分析命令运行状态

对比 Chat 模式：Chat 是"你问它答、你手动落地"；Builder 是"你给任务、它自己跑完整流程"。一句话：Chat 偏问答，Builder 偏执行。Builder 适合"做一个 XX"这种完整需求；Chat 适合"这段代码什么意思""帮我改个函数"这种局部小需求。

坑在哪
现象原因 / 怎么办
用 Builder 问"这段代码什么意思"杀鸡用牛刀；小问答用 Chat 更快更省 token
用 Chat 说"帮我做个完整网站"会得到一堆零散建议而非成品；这类需求应切 Builder，让它完整执行
以为 Builder 会自动改所有文件它产出的每处变更都要你批准（下一节细讲），不会偷偷动你的代码
2② 启用 Builder：三步开关
要解决什么

Builder 模式怎么打开？很简单，三步。

核心思路

启用 Builder 模式的步骤：

  1. 使用快捷键（macOS：Command + U；Windows：Ctrl + U）打开侧边对话框；
  2. 在侧边对话框的左上角，点击 Builder；
  3. 在 Builder 对话框中，点击 启用 Builder 按钮。

启用后，对话框中还可以选择你想使用的大语言模型——和 Chat 一样，可以按任务强度选模型。

坑在哪
现象原因 / 怎么办
找不到"启用 Builder"按钮确认左上角已切到 Builder Tab；首次使用会有个额外的启用确认按钮
Builder 和 Chat 的模型记混两者模型独立选择；Builder 承担重活，建议留更强的模型给它
回退功能找不到入口回退绑定"最近活跃的 Builder 窗口"——启用 Builder 后回退按钮才可用（见第 ⑥ 点）
3③ 多模态输入：贴图说话
要解决什么

有些需求用文字说不清——报错截图、设计稿、参考样式，一张图胜过千言万语。Builder 支持带图提问。

核心思路

你可以在会话中添加图片，例如：

  • 报错截图：AI 直接读报错信息并分析原因；
  • 设计稿：AI 照着设计稿写页面；
  • 参考样式：告诉 AI"做成这种风格"。

多模态输入让表达更精准高效，避免"我说不清，你猜不对"的来回拉扯。

坑在哪
现象原因 / 怎么办
图片太糊 AI 读不清截图尽量高清、只截关键区域；报错截图建议附上完整报错文本
只有画图需求误传截图多模态用于"AI 读图辅助编程"，不是让 AI 给你画图；画图走生图工具
4④ 生成并处理代码变更：接受还是拒绝
要解决什么

Builder 自动改代码，但你得有"最终决定权"。接受/拒绝的粒度怎么控制？这是 Builder 模式最重要的操作点。

核心思路

根据你的需求，AI 助手会自动创建新文件或编辑已有文件，并自动保存生成的代码。你可以选择接受或拒绝代码变更，支持三种粒度：

1. 处理多文件内的所有变更：点击输入框上方待审查文件列表中的 全部接受 或 全部拒绝 按钮，批量处理当前项目中的所有代码变更。

2. 处理单文件内的所有变更：在编辑器内打开文件，点击上方提示条中的 接受（快捷键 macOS Command + Enter；Windows Ctrl + Enter）或 拒绝（macOS Command + Backspace；Windows Ctrl + Backspace）。

3. 处理单处代码变更：鼠标悬浮至某处代码变更，点击右上角 ^Y 按钮（macOS Control+Y；Windows Alt + Y）接受，或 ^N 按钮（macOS Control+N；Windows Alt + N）拒绝。

原则：小改逐处审，大改按文件审，全盘信任才用"全部接受"。

坑在哪
现象原因 / 怎么办
无脑"全部接受"风险最大：AI 可能改了你不想动的地方。验收前先浏览变更列表
记不住三组快捷键不用硬记：鼠标悬浮到变更处也有按钮；快捷键是效率进阶
拒绝后想再恢复被拒绝的变更不会自动重来；可重新发消息让 AI 再改，或使用回退版本
变更列表里文件很多全部接受前先扫一眼文件名，确认没有无关文件被改动
5⑤ 生成并运行命令：让 AI 自己跑
要解决什么

项目开发常常要跑命令：装依赖、建目录、起服务。Builder 模式下 AI 会"顺手把命令跑了"，还能分析结果。

核心思路

根据你的需求，AI 助手会适时推荐必要的 Shell 命令供你运行，你可以选择运行或跳过某个命令，AI 会根据你的操作继续后续工作：

  • 点击 运行 后，终端将运行该命令；
  • 命令运行后，AI 助手会自动读取并分析运行结果；
  • 如果运行异常，AI 会自动分析原因并给出建议解决方案；
  • 若命令运行成功，点击命令卡片右上角的终端按钮，可以看该命令的运行日志。

这条"跑命令 → 读结果 → 给建议"的闭环，让 AI 真正进入"干活"状态，而不是只给一堆命令让你自己处理。

坑在哪
现象原因 / 怎么办
AI 推荐了危险的命令（如 rm -rf）你有"运行/跳过"的决定权；读一眼命令内容，危险命令跳过并让 AI 换方案
命令失败后 AI 没自动重试点运行后 AI 通常会自动分析；偶尔需要你追问一句"报错了，怎么处理"
多个命令连续执行顺序错乱命令按推荐顺序运行；有依赖的命令（先装依赖再启动）确认 AI 排好序，必要时手动干预
6⑥ 预览成果：在 Webview 和浏览器里看效果
要解决什么

写完了、跑通了，成果长什么样？Builder 提供"预览"能力，让你直接看渲染效果。

核心思路

AI 助手完成开发需求后，会提供预览按钮：

  • 点击后，Trae 会打开 Webview 窗口，用于展示开发成果；
  • 预览过程中，若你继续与 AI 助手对话、修改需求，开发成果会在 Webview 窗口中实时更新；
  • 在 Webview 窗口右上角，点击在浏览器中打开按钮，可在系统浏览器中打开窗口预览成果。

预览能力特别适合网页类项目：边看效果边改需求，即时反馈。

坑在哪
现象原因 / 怎么办
预览空白项目可能依赖服务端（如后端 API）；确认命令运行成功且服务已启动
改需求后预览没更新确认新对话在同一 Builder 会话内；必要时重新点击预览刷新
网页项目预览样式错乱可能与浏览器兼容性有关；用"在浏览器中打开"验证真实环境表现
7⑦ 回退版本：Builder 的"后悔药"
要解决什么

Builder 改了一大堆文件，结果方向错了。Chat 章节讲过回退，这里 Builder 的回退是"项目级"的撤销。

核心思路

你可以将项目回退到指定会话轮次发起前的版本。注意三条限制（与 Chat 一致但更关键，因为改动更大）：

  • 回退操作不可撤销；
  • 仅支持在最近活跃的 Builder 窗口中回退版本；
  • 仅支持回退至最近 10 轮会话内的版本。

操作步骤：

  1. 找到目标对话气泡；
  2. 点击左侧的回退按钮；
  3. 对话框中展示本次回退会影响的文件；
  4. 点击文件名查看将发生的变更，确认影响范围；
  5. 点击确定，Builder 开始回退项目。
坑在哪
现象原因 / 怎么办
Builder 大改后回退到 10 轮之外超出能力范围；强烈建议在每次 Builder 大动作前后用 Git 提交（Codex 章节细讲），Git 是终极后悔药
回退影响文件很多、担心误伤回退前务必点文件名逐一看变更；不可撤销，务必确认后再点确定
"最近活跃窗口"提示回退前先在当前 Builder 窗口发一条消息激活它，再进行回退操作
8⑧ 管理历史对话：Builder 也留痕
要解决什么

Builder 每轮建造都值得留档。和 Chat 一样，Builder 也有历史记录管理。

核心思路

点击 Builder 窗口右上角的历史会话按钮后，左侧会显示历史记录窗口，展示 Chat 模式和 Builder 模式的所有对话记录：

  • 查看：点击某条对话，跳转至该对话的位置；
  • 删除：鼠标悬浮至该对话，点击右侧删除图标。

同 Chat 模式：对话记录删除后无法恢复。Builder 的历史尤其有价值——它记录了你"怎么一步步把项目建出来"的完整过程。

坑在哪
现象原因 / 怎么办
清空 Builder 历史后想复盘项目过程删了就没了；重要项目建议把关键 Builder 对话/结果沉淀到项目 README 里
历史记录里 Chat 和 Builder 混在一起历史窗口同时展示两类记录；识别图标/标签区分，或按需删除无关项
9⑨ Chat 与 Builder 选型对照：什么需求用哪种
要解决什么

两个模式都会用了，但"什么时候用哪个"才是实战中最常见的纠结。给一张对照表。

核心思路
维度Chat 模式Builder 模式
开口方式提问/小需求给完整任务
AI 主动性被动回答主动拆解执行
文件操作生成代码块由你落地自动创建/修改文件
命令操作推荐命令由你跑自动跑并分析结果
变更控制你手动插入/应用接受/拒绝三种粒度
产物回答/代码片段可预览的完整成果
典型场景解释代码、修 bug、写函数从 0 建项目、重构、批量实现功能
回退支持（10 轮内）支持（10 轮内）

实战建议：项目级需求用 Builder，代码级小问题用 Chat；Builder 干活前，建议先用 Chat 把方案聊清楚，减少 Builder 返工。

坑在哪
现象原因 / 怎么办
项目级需求用 Chat，来回十几轮换 Builder：把总需求+"验收标准"一次说清，让它整段执行
小修小补用 Builder起 Builder 有开销（读取项目、拆解、跑命令）；纯问答用 Chat
两个模式混在一个会话里用建议按任务开新会话，保持对话纯净，避免上下文互相污染

本章小结

这一章你掌握了 Trae 最"自动"的工作面——Builder 模式：

拿到了什么为什么要紧
核心闭环：读上下文 → 拆任务 → 建/改文件 → 跑命令 → 分析结果 → 预览这是 Builder 自动开发的大脑回路
启用三步：Ctrl+U → 点 Builder → 启用 Builder一个快捷键+两次点击，AI 进入"干活模式"
多模态输入：贴报错截图/设计稿/参考样式说不清的用图说，需求表达更精准
变更三级审批：全部接受/按文件接受/按处接受你把控最终决定权，AI 改什么你说了算
命令自动运行：运行/跳过 + 自动分析失败AI 从"给命令"升级为"执行命令并排错"
预览：Webview 实时预览 + 浏览器打开边改边看效果，网页开发体验拉满
回退：10 轮内可回退，不可撤销，限活跃 Builder 窗口方向错了有药，但配合 Git 才稳妥

一句话记住本章：Builder 模式 = 你出总需求，AI 读项目、改文件、跑命令、给预览，你只负责审批和验收——这是 Trae 里最接近"Vibe Coding 理想"的一章。
