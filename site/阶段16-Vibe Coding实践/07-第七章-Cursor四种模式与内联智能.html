第七章　Cursor 四种模式与内联智能：Chat / Agent / Ask / Manual

阶段 16 · Vibe Coding 实践　|　工具实操　|　难度 ★★☆
这一章在解决什么问题

Cursor 的 AI 到底怎么"用起来"？很多人的困惑是：一边是"能动手"的 Agent，一边是"只问答"的 Ask，还有"最听话"的 Manual，到底啥时候用哪个？ 这一章把 Cursor 的四种 AI 交互模式讲透，顺便把内联智能（代码提示、补全、重构建议）也一并收编——因为它是嵌在编辑器里的"第五种 AI"。

核心问题是"匹配"：任务重（建项目、重构）就该 Agent 出手；任务轻（问个意思、解释报错）就该 Ask；需要完全自主掌控（教学、精控）就用 Manual；日常顺手的补全就交给内联智能。用对模式，效率翻倍；用错模式，要么杀鸡用牛刀，要么 AI 乱改你的代码。

学完这一章，你能回答：Agent 模式和普通 AI 的五个区别、Agent 的三大典型场景、Ask 能做什么不能做什么、Manual 适合谁、内联智能五种应用场景、四种模式怎么对比选型，以及第六种隐藏能力——内联智能的技术实现要点。

这一章在整个知识库里的位置 上一章：你认识了 Cursor 并完成了安装，学会了三组快捷键（K/L//）。 本章 ← 你在这里：Cursor 四种 AI 模式 + 内联智能——这是 Cursor 所有高级功能（上下文、规则、插件开发）的操作地基 下一章：精准上下文（@Docs/@Web）——让 AI 答得准 再往后：Cursor Rules 规则体系 → Chrome 插件实战 → Codex 阶段终点：你能像挑选工具一样按任务选对 AI 模式
学习提示

本章表格多、对比多，建议按"四个模式两个维度"记：是否主动、是否改代码。Agent（主动+改）、Ask（主动+不改）、Manual（被动+不改）、Chat（轻问答入口）。内联智能单独记它"嵌在行内不打断"的特性。

1① Agent 模式是什么：会动手的 AI
要解决什么

Agent 是 Cursor 的核心能力。它和"普通 AI（如 ChatGPT）"到底差在哪？为什么说 Cursor 的 Agent 能"自动做一系列任务"？

核心思路

Agent 模式是 Cursor 中的核心能力之一，定位为开发者的智能编程伙伴。它借助深度 AI 集成，能主动理解代码上下文并执行复杂操作，显著提升开发效率。

核心功能（五个）：

  • 上下文智能提取：自动分析当前项目的代码结构，理解上下文信息；
  • 终端命令执行：无需切换窗口，直接在编辑器内运行命令；
  • 文件操作支持：轻松进行文件的创建、修改、删除等操作；
  • 语义搜索：通过语义理解快速定位关键代码段；
  • 多工具连续调用：Agent 最多可连续调用 25 个工具，支持复杂任务自动完成。

和普通 AI（如 ChatGPT）的对比是理解要点：

对比项普通 AI（如 ChatGPT）Agent 模式
能不能动手只能说能执行
能不能读全项目只能读片段可读整个项目上下文
能不能跑命令不行可以
能不能自动做一系列任务不行连续执行多个任务（最多 25 个）

一句话：普通 AI 是"嘴"，Agent 是"手+脚+眼睛"。

坑在哪
现象原因 / 怎么办
以为 Agent 会无限自动执行上限 25 个工具调用，用完会暂停等你继续；复杂需求可分多轮推进
以为 Agent 改代码不需要你确认改动会反映在编辑区/变更里，你仍要审查；开工前把需求说清楚能少返工
把"Agent 模式"和"Chat"混为一谈同在一个输入框，但模式不同能力不同：Chat 偏问答，Agent 偏执行
2② Agent 三大典型场景：重构、修 Bug、完整项目
要解决什么

"复杂任务"太抽象，落到具体场景上——Agent 到底怎么帮我们干活？

核心思路

三个典型应用场景：

1. 代码重构

Agent 分析代码上下文，提出结构优化建议并生成重构后的代码——把"怎么重构"和"重构代码"一起交付。

2. Bug 修复

自动检测、标注错误，提供修复建议并可一键完成修复——从"找 bug"到"改 bug"一条龙。

3. 完整项目生成

例如让 Agent 创建一个"Todo List Web 应用"，它会：

  • 搭建项目结构；
  • 编写前后端代码；
  • 自动生成测试代码；
  • 输出使用说明。

对比 Trae：Trae 的 Builder 也做"从 0 到 1"，Cursor 的 Agent 是同类能力但走 25 工具连调路线，两者理念同源、实现独立。

坑在哪
现象原因 / 怎么办
让 Agent 重构大项目不交代边界Agent 会按自己理解改；先给改哪里、改成什么样、不动哪里的约束
完整项目生成后不验收自动生成的测试/使用说明要亲手跑一遍，别把"生成了"当"能用了"
一个需求让 Agent 全包（含部署）Agent 能力边界内可做命令执行，但外部部署动作（账号、凭证）需你自己确认执行
3③ Ask 模式：只问答、不改代码的"讲解员"
要解决什么

很多场景你只需要"看懂"，不需要"改"——理解代码、解释报错、求优化建议。Ask 模式就是为此设计的。

核心思路

Ask 模式专注于代码理解、问题解答与知识补全，与 Agent 注重执行不同，它提供的是基于上下文的智能问答体验。

Ask 模式能做什么：

  • 理解代码含义；
  • 定位错误和解释报错；
  • 性能和结构优化建议；
  • 学习参考和文档补全。

使用方式（激活）：

  • 选中代码后按快捷键（如 Cmd + K / Ctrl + K）；
  • 右键菜单中选择 "Ask about this code"；
  • 直接输入自然语言问题并指定相关代码块。

常用问法示例：

这段代码在做什么？
为什么这里会报错？
有没有更好的写法？
这个变量的类型是什么？
这个函数能不能改得更简洁？

关键：Ask 不直接修改代码——它解释和给建议，改不改由你决定。

坑在哪
现象原因 / 怎么办
用 Ask 问"帮我改一下"，发现没改Ask 本来就不改代码；改造需求请切 Agent 模式
选中代码后按快捷键没反应确认选中了代码且焦点在编辑器；部分情况先右键用"Ask about this code"
问"这么写对不对"得到模棱两可回答附带上下文（文件/报错），并明确"请给出结论+依据"
4④ Ask vs Agent 对比：一张表选对模式
要解决什么

两个模式都会了，何时用哪个？下面这张表可直接用。

核心思路
对比维度Ask 模式Agent 模式
核心定位智能问答/解释智能执行/操作
工作方式基于代码上下文的提问和解答接收指令并调用工具或执行动作
是否修改代码不直接修改代码可以修改、创建、删除文件
使用频率高频次中高频（复杂任务用）

选型口诀：看一眼——看不懂用 Ask，动一改用 Agent；只动嘴用 Ask，又动嘴又动手用 Agent。

坑在哪
现象原因 / 怎么办
把"Ask 不改代码"当成安全区随便问虽不改代码，但上下文里可能暴露隐私代码给厂商；敏感项目仍建议配合隐私模式
小改动也启动 Agent改一个变量名用 Agent 是浪费；内联智能/手动改更快
5⑤ Manual 模式：最"听话"的 AI
要解决什么

有人不想要 AI 主动介入，只想要一个"随叫随到、不叫不动"的助手——这是 Manual 模式的定位。

核心思路

Manual 模式是 Cursor 中最基础、最"听话"的 AI 使用方式——"手动使用"。用户需要主动输入请求（Prompt），AI 根据输入响应，不会主动介入编程过程。AI 更像工具箱里的"智能助手"，不主动打扰，只在你召唤时才工作。

核心特点：

  • 主动触发：必须由用户输入命令或点击 AI 面板按钮触发；
  • 响应内容：基于当前输入或代码上下文生成；
  • 可控性强：不会自动修改代码，所有建议由你手动选择是否采纳；
  • 无打扰：不会在你写代码时跳出来自动提示；
  • 支持多种任务：改写代码、生成函数、解释报错、翻译注释、生成测试用例等。

使用场景：需要对 AI 生成内容充分控制的开发流程；习惯逐步交互、细化任务拆分的开发者；复杂项目中每一步修改都要确认审查；教学或调试排错时精准可控的辅助。

坑在哪
现象原因 / 怎么办
Manual 和 Ask 傻傻分不清Ask 被动响应但可带上下文理解深；Manual 更"无打扰"，完全由你发起。差异不大时按顺手选
想要自动建议却开了 ManualManual 不开自动提示；想要自动补全建议，换内联智能（第 ⑧ 点）
6⑥ 三模式对比汇总：一张表收官
要解决什么

Ask/Agent/Manual 三个模式放一起，到底怎么快速记住？

核心思路

三模式总对比表：

模式是否主动是否修改代码用途
Ask 模式是否轻量问答、快速交互
Agent 模式是是自动理解意图、重构、创建新文件等
Manual 模式否否手动触发、自主掌控，适合教学或有经验的开发者
Chat 模式（上一章讲的入口）问答入口视操作而定聊天式问答，可辅助上述模式的对话载体

选择逻辑：要动手→Agent；只看懂→Ask；要绝对掌控→Manual；日常随手聊→Chat。

坑在哪
现象原因 / 怎么办
模式选错导致 AI 不动手检查输入框当前模式标签（Agent/Ask/Manual），切到 Agent 再发执行类需求
把"是否主动"记反锚点：Agent=主动出击，Manual=被动等待；Ask 介于中间（你来问它才答）
7⑦ 什么是内联智能：嵌在行内的 AI
要解决什么

除了四个模式，Cursor 还有一类"不打开对话框"的 AI——写代码时它直接在行内出现。这是什么？

核心思路

内联智能指智能功能直接嵌入在代码编辑器的编辑界面内，与代码内容无缝结合，实时显示和交互，帮助开发者在编写代码的"行内"获得智能辅助——把 AI 的能力"贴近代码"，无需跳转窗口或打开其他面板。

四个核心特点：

特点说明
实时性随代码输入即时触发，反馈快速
上下文感知基于当前文件乃至整个项目的代码上下文智能推断
无缝集成直接显示在代码编辑区域，不打断思路
交互便捷支持点击、展开、编辑、采纳建议等交互

它和"打开对话框问 AI"的差别，就像"边打字边有联想"和"写完让 AI 通读"的差别——前者融进行为，后者打断流程。

坑在哪
现象原因 / 怎么办
觉得内联提示烦（一直弹）可在设置里调整提示的触发频率或关闭；它对新手友好、对老手可选
以为内联智能=自动补全会改文件提示是建议，采纳才生效；不按 Tab/点击就不会写入
8⑧ 内联智能的五大应用场景
要解决什么

内联智能到底能在哪些具体场景帮我？逐个数。

核心思路

1. 智能代码补全

输入代码时结合上下文和历史记录，推荐最合适的代码片段/函数调用；输入变量名、函数名时自动提示匹配项并支持快速选取。

2. 代码错误和警告提示

在代码行内或旁边标注语法错误、潜在逻辑漏洞（拼写错误、类型不匹配、变量未定义等即时警告）。

3. 重构建议和代码优化

在相关代码处提示重构可能性——函数拆分、命名优化、循环简化；鼓励规范化、模块化，提升可维护性。

4. 文档注释生成

在函数定义或类上方内联提示缺少注释，提供自动生成选项；帮快速补全符合规范的 API 文档。

5. 单元测试建议

代码变更时，内联提示可能需要新增或修改的测试用例；支持快速跳转生成测试代码模板。

一句话：补全、纠错、重构、注释、测试——五个高频开发动作，全在行内完成。

坑在哪
现象原因 / 怎么办
内联建议的补全全盘接受补全≠正确：涉及业务逻辑处要人工核对，尤其测试建议别盲信
注释生成会"画蛇添足"和 Rules 配合（定义注释风格）再生成；注释也要审，避免噪音
9⑨ 内联智能的技术实现：它背后靠什么
要解决什么

"边写边提示"不是魔法，了解一下它是靠什么技术实现的，有助于你判断何时可信、何时要警惕。

核心思路

内联智能的关键技术实现要点：

技术点说明
上下文感知语义理解结合语法树（AST）、类型信息、代码调用关系进行深度语义解析
模型推理与缓存机制采用大模型推理辅助决策，并缓存历史结果减少延迟
编辑器插件集成通过 VSCode、IntelliJ 等编辑器扩展实现 UI 层和交互层支持
事件驱动机制监听代码输入、保存、切换文件等事件触发智能响应
异步反馈与并发处理保证智能提示不会阻塞编辑体验，异步加载和更新内容

通俗讲：它"听懂"你的代码结构（AST+类型），"想得快"（模型+缓存），"不卡手"（异步）。理解这点，你就知道它的建议"基于上下文"而非"凭空猜测"——但也仅此而已，真伪仍要人审。

坑在哪
现象原因 / 怎么办
以为内联智能是"读心术"它依据当前代码上下文推断；上下文断（新文件、缺 import）时建议质量下降
以为缓存机制=永远快首次分析（新项目/大文件）仍会慢；缓存是"第二次起快"

拿到了什么为什么要紧
Agent 模式：主动、能动手、读全项目、跑命令、25 工具连调复杂任务的"执行者"：重构、修 Bug、完整项目
