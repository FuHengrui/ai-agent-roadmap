第二章　能做什么：四大应用场景

阶段 14 · 小龙虾 OpenClaw 实战　|　平台实操　|　难度 ★★☆
这一章在解决什么问题

OpenClaw 到手之后，到底能帮我干什么？ 这是所有人第一次接触"个人 AI 助理"时心里最大的问号。上一章讲了它是什么——一个能用自然语言驱动、替你操作各种软件工具的智能体，但"是什么"不等于"有什么用"。如果对能力的想象不落地，真上手要么不知道让它干什么，要么让它干它根本不该干的事。

讲义给了一句总纲：用自然语言替代人工完成重复性工作。 这句话是 OpenClaw 所有功能的地基，但太抽象，不拆开就落不了地。这一章把它拆成一张地图：三大核心场景（个人办公、团队协作、开发辅助）× 四大类能力（基础办公自动化、跨工具协同操作、轻量定制化需求、开发辅助），每类再拆成具体能做的事。

学完这一章，你心里会有一张"需求 → 功能"对照表：老板让你汇总 Excel，你知道该走"数据简单处理"；想让 OpenClaw 每天 18 点自动出报告，你知道这叫"自动化规则设置"。心里有这张图，下一章部署完才知道往哪个方向试、要试什么。

这一章在整个知识库里的位置 上一章（认识 OpenClaw）：你搞清了它是什么——能听懂自然语言、替你操作文件和软件工具的个人 AI 助理 本章 ← 你在这里：它能干什么——四大应用场景全景，解决"它能帮我做什么" 下一章：怎么部署——准备云服务器、安装 OpenClaw，让它真正跑起来 再往后：部署完成后对接钉钉 / 企业微信 / 飞书等平台工具，并在实际工作中启用这些能力 阶段终点：独立完成 OpenClaw 部署 + 多平台接入
学习提示

本章是"功能地图"章，不写代码、不装环境。把注意力放在"一个需求对应哪类能力"上；下一章部署完，你要做的就是回到这张图，从最贴近自己工作的场景一个个试。

1① 价值全景：三大核心场景 × 四大类能力
要解决什么

对 OpenClaw 的第一印象容易走两个极端：要么觉得它"就是个会聊天的"，要么以为它"什么都能干"。动手之前先要有一张全景图——它覆盖哪些场景、分成哪几类能力，否则往下看每个小功能时，看不到它在整张图里的位置。

核心思路

讲义给它定了最简单的一句定位：用自然语言替代人工完成重复性工作。展开就是三大核心场景：

场景服务谁典型诉求
个人办公所有人文档、文件、日程、数据这些日常杂活不再亲手做
团队协作需要跨工具办事的人让消息和文档在多个工具之间自动流动
开发辅助开发者与编程新手写代码、看日志、管服务器这些"技术活"也能对话完成

三大场景落到具体能力，就是讲义说的四大类：

大类包含的能力（对应本章小节）
基础办公自动化文档处理 ②、文件与日程管理 ③、数据简单处理 ④
跨工具协同操作通讯工具集成 ⑤、办公软件集成 ⑥、多场景适配 ⑦
轻量定制化需求私有知识库接入 ⑧、简单 API 接入 ⑨、自动化规则设置 ⑩
开发辅助代码生成与解释 ⑪、日志分析与远程运维 ⑫

一句话记忆：办公自动化打底，跨工具协同做连接，定制化需求补个人化，开发辅助照顾技术活。

坑在哪
现象原因 / 怎么办
以为 OpenClaw 只是"聊天机器人"它是能动手办事的智能体：生成文档、发群消息、拉代码都是真实操作，聊天只是入口
把"场景"和"类"混为一谈场景是为谁服务（个人/团队/开发），类是干什么活（办公/协同/定制/开发），两者是对同一批能力的两种切法
想一次性全铺开先盯住自己最高频的重复动作挑一类入手——比如天天做 Excel 就先试 ④，全铺开最容易半途而废
2② 文档处理：总结、纪要、模板一嘴搞定
要解决什么

写工作总结、整理会议纪要、套模板、转格式、从旧文档里扒数据——这些活儿的共同点是重复且套路化，恰恰是自然语言指令最好使的地方。你需要知道：OpenClaw 能"写"哪些文档、"改"哪些格式。

核心思路

讲义把文档处理拆成四类能力：

能力含义例子
生成文档直接产出成品文档"帮我写一份本周工作总结，分三项"
格式转换一种格式转另一种TXT 转 PDF
数据提取从文档里捞出指定信息从 Excel 提取 2026 年 1 月销售数据
编辑排版对既有文本做修改和排版"把标题加粗、正文改成小四"

讲义给了一条完整示例指令：

帮我将2026年1月销售数据Excel转换为PDF并按区域分类

这条指令有示范意义："转换格式 + 分类整理"可以一步完成，不用先手动转格式、再手动归类——把最终想要的样子说清楚，其他交给它。

坑在哪
现象原因 / 怎么办
指令含糊："帮我把这个 Excel 处理一下"它猜不准你要转格式 / 改内容 / 算数据。指令要说清"对象 + 动作 + 结果"，如"把这份 TXT 转成 PDF 并加页码"
生成的文档拿来就发生成的是初稿。对外发送前复核数字、人名、期限；AI 写的总结尤其要回看原始材料对口径
把"数据提取"和"数据计算"混着问提取是把指定字段捞出来（属文档处理）；算平均值、总和属于 ④ 数据简单处理，分开问更准
3③ 文件与日程管理：自动分类 + 提醒同步
要解决什么

电脑里文件越堆越乱、重要会议怕忘、待办散落在好几个 App 里——这些都是"整理类"的重复劳动。你要知道它按什么维度替你把文件摆好、把日程管住。

核心思路

讲义给出三个能力点：

  • 文件分类：按后缀名、创建时间、用途等维度，自动分类本地或服务器上的文件
  • 日程管理：设置会议提醒、待办事项
  • 同步联动：日程和待办可同步至已关联的通讯工具（钉钉 / 企业微信 / 飞书，见 ⑤）

示例指令：

把下载文件夹里所有 PDF 按月份建子文件夹移进去
周五 9:00 有一场评审会，提前 15 分钟用企业微信提醒我

关键认知：分类维度由你给，它不猜。OpenClaw 不知道你的"合理摆放"是什么样，必须把"按什么分、分到哪、叫什么名"说清楚，它才动得了手。

坑在哪
现象原因 / 怎么办
只写"整理一下我的文件"没有维度就没法执行。给条件："按后缀名分""按创建时间分"或"按用途分"
提醒发不到手机/群提醒要送到通讯工具，前提是已经接入对应工具（见 ⑤）；没接入就只会停留在应用内部
分类规则不可逆大批量移动前，先让它"预览将怎么分"或按小样目录试跑一次，避免分完找不到
4④ 数据简单处理：不装分析软件也能算 Excel
要解决什么

要做汇总、求平均、求和、筛选，第一反应是学函数或者装数据分析软件——但很多是一次性小统计，学工具的成本比干活还高。你要确认：不碰工具、只说人话，能不能把数算出来。

核心思路

讲义明确：无需专业数据分析工具，通过自然语言指令即可完成基础统计：

操作说法
求和 / 平均"帮我算一下这张表所有订单的总金额和平均值"
汇总"按月份汇总各地区销售额"
筛选整理"筛出销售额大于 10 万的客户，按金额倒序排列"

它替代的是手动点 Excel 的机械操作，适合一次性、结果边界清楚的轻量统计；数据量极大、要复杂建模时，那属于专业工具和大数据栈的领域，别硬用这一招。

坑在哪
现象原因 / 怎么办
反复改口径：一会儿平均、一会儿总和开口前先想清楚算哪个字段、按什么分组、结果要几列，一次说清比来回问更准
把轻量统计当大数据分析几万行内的 Excel 级统计没问题；百万行级也硬塞给它，会卡在工具能力边界上
结果口径没确认"平均值"是全表还是筛选后？模糊时先补一句"按整张表算，还是按筛选后的行算"再让它动手
5⑤ 通讯工具集成：让消息在应用之间"跑腿"
要解决什么

工作消息散在钉钉、企业微信、飞书里，把方案发到某个群、把沟通记录存到本地——这类"搬消息"是纯体力活。你要知道 OpenClaw 接入通讯工具后，能替你做哪些真实的收发动作。

核心思路

讲义给出两条代表能力：

能力示例指令
发送到群聊"将这份项目方案发送给研发部群聊"
同步记录"同步今天的客户沟通记录至本地文档"

前提是先关联（接入）钉钉 / 企业微信 / 飞书之一，它才有权限替你发消息。注意区别：这不是简单"发一条通知"，而是内容可来自你的指令或文档、目标可以是具体群组的完整动作。

配合 ⑩ 的自动化规则，"每天 18 点汇总群聊消息生成报告"这类需求，还能从"手动下指令"升级成"到点自动跑"。

坑在哪
现象原因 / 怎么办
没接入就喊"发到飞书"在没接通的工具上只会报错。先完成工具授权与绑定（下一章部署与接入部分会做）
发错群、发错内容对外发送是真实动作。正式内容发送前，自己先核对收件群和内容无误再放行
以为只能人工触发结合自动化规则可以定时自动执行；手动发、定时发是同一能力的两种用法
6⑥ 办公软件集成：WPS/Office 免手动启动
要解决什么

过去用 WPS/Office 干活有一条固定流程：启动软件 → 打开文件 → 编辑 → 另存为，光点击就花掉几分钟。你要知道 OpenClaw 能否把"打开、编辑、保存"压缩成一句话。

核心思路

讲义：关联 WPS、Office 等办公套件后，直接通过指令打开文件、编辑内容、保存至指定路径，无需手动启动软件。

示例指令：

打开 D 盘项目下的方案.docx，把第二页报价改成 5800，保存到桌面

和 ② 文档处理的分工：② 偏向从无到有生成 / 转换文档，⑥ 偏向对已有文档文件执行"打开—编辑—保存"这类操作动作。前者是"造文档"，后者是"动文档"。

坑在哪
现象原因 / 怎么办
以为所有格式都能直接编辑核心支持办公套件的常见格式；特殊格式先转成常见格式（如 TXT 转 PDF）再操作
指令里路径写错文件不存在直接失败。路径不确定就先说"帮我在 D 盘项目里找到方案.docx"确认对象
重要文件被覆盖编辑保存是覆盖式操作。动重要文件前，先让它"另存为副本再改"或明确保存到新路径
7⑦ 多场景适配：Git 拉代码、浏览器开网页
要解决什么

OpenClaw 不只在办公室软件里转，还能碰到开发者的代码仓库和普通人的浏览器。这两类人诉求不同，但都需要知道：接入这些工具之后，它能做到什么程度、做到哪一步为止。

核心思路

讲义把这条能力按用户拆成两条线：

使用者接入工具能做什么
开发者Git 代码仓库指令拉取代码、生成简单代码片段
普通用户浏览器自动打开指定网页并保存内容

两条线的示例指令：

把 Git 仓库 main 分支的最新代码拉到本地
打开产品官网首页，把产品介绍部分保存成文档

注意它的边界在可控的确定性动作（拉取、打开、保存）；需要登录态的复杂网页操作、会改动远端仓库的动作，都不在"一句话代跑"的默认范围内。

坑在哪
现象原因 / 怎么办
以为浏览器能"全自动办完所有事"讲义定位是打开网页、保存内容这类确定性动作；涉及登录态和账号操作的，先确认权限与合规
Git 操作不看仓库就执行拉取前核对分支与地址；涉及提交、推送这类改动远端的动作，先人工确认再放行
以为两条线只能选一个同一个会话里既能拉代码也能开网页。它是多工具协同，不是一次只能用一个工具
8⑧ 私有知识库接入：问自己的文档，答自己的业务
要解决什么

问公网 AI 得到的答案再全，也不认识你公司的规章制度、产品资料和个人业务文档。要让 AI 回答"你自己的东西"，就得把专属资料主动喂给它。这一节认识"私有知识库"解决什么问题、和普通搜索差在哪。

核心思路

讲义：可导入个人或团队专属知识库（业务文档、产品资料、规章制度），输入相关问题即可快速检索答案，适配企业培训、个人学习等场景。

对比通用问答 / 公网搜索私有知识库
数据来源网上公开内容你自己导入的文档
答案特点通用、可能过时贴合你的业务、随文档更新
典型用途常识咨询制度问答、产品答疑、培训考核

一句话理解：它让"问 AI"从"问全世界"变成"问你的资料库"——张开嘴之前，先确认自己要问的是哪一摊资料。

坑在哪
现象原因 / 怎么办
以为知识库 = 聊天记忆它是主动导入的文档集合，不是聊天记录缓存；没导入的东西依然答不上
只导入不维护文档更新后知识库要同步更新，否则答的是旧版制度、旧版产品参数
一股脑全导进去按用途分组（培训用、查制度用）检索才准；含敏感信息的资料注意访问权限
9⑨ 简单 API 接入：考勤、客户信息一句话查
要解决什么

考勤记录、客户信息这类数据通常锁在 OA、CRM 内部系统里，查一条要开系统、点好几层菜单。提到 API 你可能发怵，但讲义给它的定位是"简单"API 接入——你要先搞清楚它解决什么问题、接线的思路长什么样。

核心思路

讲义：支持接入公开 API 或企业内部接口（如 OA 系统、CRM 系统接口），实现员工考勤查询、客户信息调取等个性化数据查询。

环节人话解释
API 是什么系统之间约定好的"取数接口"，你想查的数据它已经暴露好了
OpenClaw 做什么听懂你的自然语言问题 → 替你调用对应接口 → 把结果整理给你听
典型说法"查一下今天哪些同事还没打卡""调取客户 A 最近的沟通记录"

价值在把"点系统找数据"变成"一句话要数据"，让 OA/CRM 里的数据问得动、答得出。

坑在哪
现象原因 / 怎么办
以为 API 接入要先写一堆代码简单接入通常是配置接口地址与凭证，不是从零写代码；复杂的企业级对接才需要开发能力
没权限就硬调内部接口内部接口要有效授权与凭证；涉及员工、客户数据注意合规，别拿个人权限乱查
密钥、Token 到处贴任何密钥/Token/密码都不要写进文档或聊天明文，放环境变量或配置文件，只记录"它存在、放哪"
10⑩ 自动化规则设置：定时定点，自己干活
要解决什么

人最消耗精力的不是把活儿干完，而是每天重复同一个动作：18 点汇总群聊、收到 PDF 就分类放好。手动下指令只算"方便"，到点自动跑才算"解放"。你需要理解"规则 = 触发条件 + 动作"这个模式。

核心思路

讲义给了两个现成规则，正好覆盖两种触发方式：

规则触发方式自动执行的动作
每日 18 点汇总群聊消息生成报告定时（到点触发）汇总群聊消息 → 生成报告
收到 PDF 文件自动分类保存事件（新文件出现触发）识别 PDF → 按规则存入对应文件夹

核心一句话：设置后自动执行、无需手动触发。它的本质是"你定好触发条件和动作清单，OpenClaw 当哨兵，一满足就干活"。这也是 ⑤⑥ 里各种"发送、保存"能力能被调起来自动跑的原因。

坑在哪
现象原因 / 怎么办
规则设了但从不执行先查前置依赖：汇总群聊得先接入通讯工具（⑤），存文件得目录可写；缺一环就静默失败
触发与动作写得含糊"每天生成报告"没说几点、汇总哪个群、发到哪——时间、对象、产出、去向都要写具体
设完再不复查自动任务出过一次错可能一直错。定期抽查产出（报告内容、文件位置）是否正常
11⑪ 代码生成与解释：新手的第一位编程陪练
要解决什么

编程新手最难的不是"不想学"，而是第一行代码憋不出来、报错看不懂。你需要知道：OpenClaw 能把"写码、讲码、纠错"三件事，降到什么样的门槛。

核心思路

讲义：支持生成 Python、Java 等多种语言的基础代码片段、解释代码含义、排查基础语法错误，助力新手快速上手。

能力怎么开口
生成片段"用 Python 写一段读取 CSV 并打印前 10 行的代码"
解释代码"这段代码每一行在做什么，讲给我听"
排查语法错误把报错原文和代码一起贴给它："这个报错在哪一行，怎么改"

它的定位是陪练不是替考：帮你起步、帮你纠错，但关键逻辑仍然要你自己理解和验证。

坑在哪
现象原因 / 怎么办
拿生成代码当"免学编程"定位是辅助新手快速上手；关键业务逻辑不理解就盲贴生产环境，风险自负
报错只给一半信息排错要报错原文 + 相关代码一起给，只说"报错了"它无法定位
生成完不验证让它生成后就在本机跑一遍。它给的是"很可能对"，不是"保证对"
12⑫ 日志分析与远程运维：看得懂日志、管得了服务器
要解决什么

服务器出问题最折磨人的两件事：日志几百行懒得逐行看、命令一条条敲还怕敲错。你要知道 OpenClaw 能把"看日志"和"管服务器"简化到什么程度、边界在哪。

核心思路

讲义给了两项能力：

能力干什么
日志分析导入服务器或程序运行日志，自动筛选异常信息、分析错误原因，不用手动逐行看
远程运维用对话式指令完成服务器状态查询、日志清理、程序启动等操作

示例指令：

导入这台服务器的错误日志，筛出今天所有异常并分析可能原因
帮我看下服务器 CPU 占用，超过 80% 就清理 7 天前的日志

核心价值：把"翻日志、敲命令"变成"说人话、看结论"，运维的重复劳动减到只剩"确认和执行"。

坑在哪
现象原因 / 怎么办
清理、重启不确认就执行日志清理、程序重启是影响服务的动作，正式环境先确认影响面再放行
权限不足反复重试远程运维需要对应权限与凭据，报权限错先补授权，别原地重复执行
把"分析原因"当"确诊"它给的是基于日志的推断；真生产故障要人工结合环境、数据复核后再定论
