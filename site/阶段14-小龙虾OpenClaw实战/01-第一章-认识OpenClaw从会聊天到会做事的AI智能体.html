这一章在解决什么问题

学了十几章，为什么 AI 还是只会"聊天"？ 前面阶段里你调大模型、建 RAG、学 Agent 理论，AI 都能说会道——但让它"帮我把这个文件夹整理一下""替我把这份文件转成 PDF"，它就无能为力了。问题不在模型不够聪明，而在于它没有"手和眼睛"：看不到你的屏幕，碰不到你的文件，只能困在对话框里。

"会聊天的 AI"和"会做事的 AI"根本分界在哪？ 分界在于能不能直接操作系统。一个能动手的 AI 可以看屏幕、点按钮、改文件、跑命令、定时干活——这就是 OpenClaw 喊出的定位："一个真正会做事的 AI"（The AI that actually does things）。它把大模型从对话工具改造成能跨平台、跨应用执行复杂任务的"数字员工"。

1① 一个真正会做事的 AI：OpenClaw 是什么
要解决什么

你已经很熟悉"聊天式 AI"：能问答、能写作，但一说到"帮我做件事"就歇菜。这一节先建立总印象：OpenClaw 是什么、从哪来、官网在哪——它是整个阶段的主角。

核心思路

OpenClaw 是一款2026 年初发布的开源、本地优先（Local-first）的 AI Agent 框架，官网是 https://openclaw.ai/ 。它的核心定位是"一个真正会做事的 AI"（The AI that actually does things）：将大语言模型（LLM）从"会聊天"的对话工具，转变为能够直接操作用户计算机、执行跨平台跨应用复杂任务的"数字员工"。

一句话区分它和聊天机器人：

聊天机器人OpenClaw（Agent 框架）
能力边界生成文字回答看屏幕、点按钮、读写文件、执行命令
是否操作计算机否，活在对话框里是，直接操作你的系统和应用
完成方式输出答案，剩下你自己干端到端执行，把活干完才汇报

所以要强调：OpenClaw 不是一个更聪明的聊天机器人，而是一个能让 AI 动手干活的系统。它本身不是大模型，而是"驱动 LLM 动手"的框架——模型负责想，框架负责做。

2② 本地优先 Local-first：数据与隐私的控制权
要解决什么

用惯云上 AI 后总有一个隐忧：对话内容、上传的文件都经过别人的服务器，数据和隐私的控制权不在自己手里，敏感文档更不敢喂给云端。需要一个"代码在自己机器上跑"的方案。

核心思路

这一条在产品定位里排第一位：本地优先（Local-first）——与完全依赖云端服务的 AI 产品不同，OpenClaw 的核心程序在用户自己的硬件（个人电脑、Mac Mini 或云服务器）上运行，用户拥有对数据和隐私的最高控制权。

这背后是"Local-first 软件"理念：程序主体与用户数据默认落在本地设备，云端只是可选的增强。

程序在哪跑厂商服务器你自己的设备
数据谁持有厂商你自己
断网可用性基本不可用本地功能照常
敏感数据合规难评估数据不出设备，最可控

注意边界："本地优先"不等于"完全不联网"。它指程序和数据优先落本地，LLM 推理等重活仍可能按你的配置调用云端模型——但控制权、开关都在你手里。

坑在哪
现象原因 / 怎么办
以为本地优先=断网单机，完全不能联网本地优先指程序与数据默认在本地，联网能力由你配置，不是一刀切断网
以为本地优先=永远不能远程访问官方明确允许把程序装在自己的云服务器上，既本地控制又远程可用
觉得"都放本地了还谈什么隐私"本地化只是第一步，接入哪些模型、开放哪些目录、权限怎么控仍要自己把关
3③ 开源与可扩展：MIT 许可证 + 技能/插件
要解决什么

闭包产品的功能由厂商说了算：你不喜欢它的边界、想要的扩展它不给，就只能干等。你需要一个可以自己改、自己加能力的开放系统。

核心思路

OpenClaw 采用 MIT 许可证，代码完全开放。它的核心价值是提供一个强大的框架，而非封闭的产品——开发者可以通过"技能（Skills）"和插件系统无限扩展其功能。

MIT 是最宽松的开源许可证之一：可自由使用、修改、再分发，甚至用于商业产品，只需保留版权声明。这意味着：

  • 你可以阅读源码，搞清它每一步在干什么；
  • 你可以改代码，定制自己的行为；
  • 你可以加 Skills，把任何新能力教给它（第 ⑨ 点展开）。

一句话：你得到的不是一款成品，而是一套可以无限组装的骨架。

坑在哪
现象原因 / 怎么办
以为"开源=免费云端账号"开源是代码开放，不等于厂商托管服务免费；两者是两回事
以为只有程序员才能扩展技能（Skills）以 Markdown 指令集形式存在，普通用户也能写、能装，后面章节专门实操
以为 MIT 许可证=可以随便改名不保留版权可以商用，但需保留版权声明。开源≠无协议，用前看一眼 LICENSE
4④ 通用计算机控制：打破 API 孤岛
要解决什么

传统自动化绕不开一个死穴：只能集成提供 API 的应用。银行老系统、剪辑软件、某些网页应用没有开放接口，自动化就卡死——这就是"API 孤岛"。要打通它，必须换一种思路。

核心思路

OpenClaw 不仅仅依赖 API 进行集成，而是模拟人类使用计算机的方式：视觉识别屏幕 + 控制键盘鼠标，来操作任何图形界面应用，从而打破传统自动化的"API 孤岛"。

它的工作链条其实是"看 → 想 → 动 → 验"：

环节做什么类比
感知用视觉模型识别屏幕上的按钮、文本框、图标人"看"屏幕
规划决定该点哪里、输入什么人"想"下一步
执行模拟鼠标点击、键盘输入、滚动人"动手"
验证再看一遍屏幕确认结果人"检查"

这套机制的意义：有没有 API 不再重要——只要人眼能操作的界面，它就能操作。对旧软件、无接口网页来说，这是唯一的自动化出路。

坑在哪
现象原因 / 怎么办
以为"视觉控制=提前录好固定坐标"它是实时识别 UI 元素再决定动作，窗口移动、界面变化也能应对；固定坐标方案一改动就废
以为有了视觉控制就不需要 API两者互补：API 快、稳、准；视觉控制兜底"没有 API"的场景。它的定位是"打破孤岛"，不是取代 API
界面识别失败就以为功能坏了识别是概率性的，界面太乱、元素过小时会失败；后面实战会用截图与日志定位，属于调优不是缺陷
5⑤ 消息驱动交互：聊天即操作
要解决什么

能做事了，但总不能在每次指挥时打开控制台敲命令、写脚本吧？门槛太高。你要的交互方式是零学习成本的——用你已经天天在用的聊天软件下指令。

核心思路

OpenClaw 是以消息驱动的交互：用户主要通过日常使用的即时通讯工具（WhatsApp、Telegram、Slack、钉钉、微信等）与它交互，用自然语言下达指令，实现"聊天即操作"。

体验上：它像一个住在你聊天软件里的"数字员工联系人"——你发一句"帮我把这个文件夹按日期整理好"，它领命执行并回你结果。消息就是指令，回复就是反馈，全程没有命令行、没有界面切换。

这也是它和"网页版 AI"最大的体验差异：AI 主动进入你已有的工作流，而不是让你进入它的网页。

坑在哪
现象原因 / 怎么办
以为用 OpenClaw 必须有编程基础交互层就是聊天，谁都会用；编程能力是给"扩展功能"用的，不是使用门槛
以为聊天只能"问问题"聊天里可以下操作指令："转 PDF""发送到某群""整理文件"都是任务，不只是问答
一上来就想把全部 IM 都接上IM 候选有一堆，先挑一个自己常用的走通全流程，其余按需再加，别一次性铺开
6⑥ 跨平台消息集成：在哪个聊天软件都能指挥它
要解决什么

你说"用聊天软件指挥它"，可不同团队用的工具不一样：老板用钉钉，你爱用 Slack，国外同事用 WhatsApp。必须覆盖主流 IM，让每个人在自己习惯的角落里指挥 AI。

核心思路

OpenClaw 支持集成 WhatsApp、Telegram、Slack、Discord、iMessage、钉钉等多种主流 IM。用户可以在任何习惯的聊天应用中，像与朋友对话一样向 AI 下达指令、接收反馈。

这意味着集成之后：

  • IM 里多了一个"AI 联系人"，聊天即操作（承接第 ⑤ 点）；
  • 团队各用各的软件不影响协作——入口随便选，干活的是同一个 AI；
  • 指令与反馈都落在聊天记录里，随时回溯。
坑在哪
现象原因 / 怎么办
以为要专门装 OpenClaw 客户端不需要——核心在本地跑，你用它已有的聊天软件当遥控器
以为 IM 集成只是"让它给你发通知"是双向交互：你下指令、它执行并回报，还能追问、中途改需求
一个 IM 配不上就用不了先确认常用那一个的接入方式；不同 IM 的配置步骤，实战章节会逐个走
7⑦ 计算机视觉与控制：给 AI 装上"眼睛和手"
要解决什么

填表单、操作剪辑软件、管理本地文件——这些桌面软件和网页大多没有 API。为此 OpenClaw 必须能"看"屏幕并"动手"。这一节讲清楚它的"眼睛"和"手"具体有什么能力。

核心思路

OpenClaw 能够"看到"并理解屏幕上的内容：识别按钮、文本框、图标等 UI 元素，然后模拟鼠标点击、键盘输入、滚动等操作。它的功能体系就围绕"为 AI 装上眼睛和手脚"展开——能感知（看屏幕）并行动（操作键鼠、文件、网络）。

代表作场景：自动化操作任何没有提供 API 的桌面软件或网页应用——填写表单、操作剪辑软件、管理本地文件。

技术上是三类能力合力：

能力干什么
屏幕视觉理解把像素变成"界面元素清单"（哪里是按钮、哪里是输入框）
元素定位在变化的位置上找到目标元素，不靠固定坐标
键鼠模拟把"意图"变成真实的点击、输入、滚动事件
坑在哪
现象原因 / 怎么办
以为它能操作一切，连安全认证环节都交给它验证码、支付、解锁等敏感认证应本人完成。它替代的是重复劳动，不是安全边界
识别慢就以为是坏了视觉识别是逐帧理解，比纯 API 调用慢是正常的；优先让它处理"没有别的办法"的场景
一次识别失败就手动接管先确认截图里目标是否清晰；界面元素太密集时可先调整窗口再重试，这属于调优不是缺陷
8⑧ 文件与系统管理：能读写文件、能执行命令
要解决什么

大量重复劳动发生在文件系统层面：下载文件夹一团乱、几百个文件要改名、装软件、跑脚本——这些事以前要么手动点，要么写脚本。你要的是一句话搞定。

核心思路

OpenClaw 具备读、写、编辑本地文件和执行 Shell 命令的能力。典型场景：整理下载文件夹、按指令批量修改文件名、安装软件、运行代码脚本。

这意味着它可以：

  • 整理：按类型、时间把散乱文件归档；
  • 批量改：几百个文件按规则重命名；
  • 运维：安装软件、执行系统命令；
  • 执行：帮你跑一段代码脚本并反馈结果。

这也是"会做事"最实在的一环：文件系统是它在电脑里干活的主战场，配合视觉控制（第 ⑦ 点），既能"看界面"又能"动文件"。

坑在哪
现象原因 / 怎么办
给了 Shell 权限就什么都敢让它跑命令执行权限=破坏力。只授它需要的目录与权限，来历不明的脚本先审查再执行
以为它只能"看看文件"它能读能写能改，覆盖整理、改名、安装、执行一条龙，别低估也别滥用
误删了文件找不到原因破坏性操作前确认动作与范围；关键数据先备份，这是对"会做事的 AI"的基本纪律
9⑨ 可扩展技能系统 ClawHub：Markdown 写的"技能库"
要解决什么

框架再万能也覆盖不了所有需求：你想管智能家居、盯股票、自动回邮件——每个需求都改内核代码不现实。需要一个让 AI"现学现用新本事"的机制。

核心思路

开发者可以创建、发布和分享"技能"——以 Markdown 文件形式存在的指令集，AI 可以动态学习并使用这些技能。社区已贡献了数千种技能，涵盖日程管理、邮件处理、智能家居控制、股票交易、内容生成等，极大地丰富了它的能力。

要点拆开看：

概念理解
技能的本质一份 Markdown 指令集，教 AI"这件事该怎么做"
动态学习用的时候按需加载，不需要重装程序
来源社区已有数千种，也可以自己写、自己发布
意义功能无限扩展，呼应第 ③ 点的 MIT + Skills 设计

类比：如果 OpenClaw 是手机，技能就是应用商店——但更轻，它只是一个文档，AI 读了就会干。

坑在哪
现象原因 / 怎么办
以为技能是"安装包/插件程序"技能本质是 Markdown 指令集，不是编译好的程序；加载即阅读、阅读即生效
以为技能必须自己开发社区已有数千种现成的，先搜先用，不够再写；实战章节会演示一次完整流程
装了技能就以为万事大吉技能描述"怎么做"，效果还受模型能力和执行环境影响；跑了不对先回头读技能说明的细节
10⑩ 持久化记忆：AI 记得你，才像个员工
要解决什么

默认情况下模型每次对话都是"失忆"的：今天告诉它的偏好，明天就忘。一个记不住任何上下文的 AI 做不成"长期员工"。需要跨对话的记忆能力。

核心思路

OpenClaw 能够记忆历史对话和任务上下文，形成长期记忆，并在后续交互中运用这些知识。典型用途：记住用户偏好、项目背景、常用联系人信息，提供更具个性化和连贯性的辅助。

记忆什么效果
用户偏好邮件格式、文件习惯不用每次重说
项目背景任务上下文自动衔接，不用重复交代
常用联系人说"发给老王"它就知道是谁

结合本地优先（第 ② 点）：记忆数据同样存在你的设备上，个性化与隐私两不误——这是它与云端"记忆型"产品的重要差异。

坑在哪
现象原因 / 怎么办
以为记忆=原样存聊天记录记忆是提炼后的上下文（偏好、背景、联系人），不是聊天日志堆砌
以为记得一次就永远正确事实会过期（联系人离职、项目换背景）。发现它记错了及时纠正，必要时清理记忆
忘了敏感信息也在记忆里记忆内容受本地优先保护，但密钥、密码等敏感值仍不该写进对话让它去记，口令类信息走专门保管
11⑪ 跨设备节点系统 Node System：让另一台设备替你干活
要解决什么

你在公司，却想用家里电脑下载一个大文件；想让 AI 报一下你当前的位置。一台设备只装一个 AI 不够——需要主从式的多设备网络。

核心思路

OpenClaw 支持跨设备节点系统（Node System）：在多个设备（Mac、Windows、iOS、Android）上安装节点，主程序可以远程调用这些节点执行任务。

两个典型场景：

  • 在办公室电脑上接收指令，调用家里的 Mac Mini 执行一项下载任务；
  • 通过手机节点获取当前 GPS 位置。

一句话理解：主程序是"大脑"，各设备节点是"手足"——大脑在任何一端，手脚分散在不同设备上，指令远程下发、结果远程回收。

坑在哪
现象原因 / 怎么办
以为每个设备各装一套互不联通的 OpenClaw是主程序 + 节点的架构：节点负责执行、主程序统一调度，才能跨设备联动
节点暴露出来不做访问控制节点可被远程调用，等同给设备开了远程口子；只放信任设备，并关注鉴权配置
以为手机节点只能收 GPS节点能执行主程序下发的任务；GPS 只是举例之一，能力取决于节点权限与安装的功能
12⑫ 任务调度与主动行为：Cron 定时干活
要解决什么

"每天早上整理邮件"这种任务，你不想天天手动发一次指令；"股价跌破阈值就提醒我"这种，你甚至没空等它发生。需要 AI 在设定时间/条件下自己启动——主动行为。

核心思路

OpenClaw 内置 Cron 作业调度器，可以执行定时任务，或基于特定事件触发主动行为：

  • 每天早上 8 点自动整理邮件并生成摘要报告；
  • 当特定股票价格低于阈值时主动发送提醒。

Cron 是 Unix 系统经典的定时工具，表达式按"分 时 日 月 周"五个字段书写，例如：

# 每天 8:00 执行邮件整理与摘要
0 8 * * *  mail_summary
# 每 30 分钟检查一次股票价格
*/30 * * * *  check_stock_price

和"被动等待指令"不同，这条能力让 AI 从"你问我答"跨进"主动值守"——像真正的员工一样到点干活、出事汇报。

坑在哪
现象原因 / 怎么办
以为"主动行为"是 AI 自己"想起来了"背后是调度规则在驱动：时间或事件条件满足才触发。规则配错=行为不触发，不是 AI 偷懒
Cron 表达式写错没反应五个字段（分 时 日 月 周）的顺序与取值范围要核对；先设一个 1 分钟后触发的测试任务验证，再上正式任务
时区遗忘导致"时间对不上"定时任务按所在时区触发，跨时区使用先统一约定时区，否则 8 点会在"错误的 8 点"执行
