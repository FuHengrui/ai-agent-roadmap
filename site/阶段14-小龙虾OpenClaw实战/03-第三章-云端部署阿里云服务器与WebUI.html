第三章　云端部署：阿里云服务器与 WebUI 管理

阶段 14 · 小龙虾 OpenClaw 实战　|　平台实操　|　难度 ★★★
这一章在解决什么问题

OpenClaw 写好了、跑通了，可它到底该住哪？ 前面你认识了 OpenClaw 能做什么，也看它在本地跑起来的样子。但只跑在自己的电脑上有两个硬伤：电脑一关机、一休眠、一断网，OpenClaw 就"失联"了，有人发消息没人回；本机还要装别的软件、干别的活，环境容易互相干扰。

答案是把 OpenClaw 部署到云服务器上——一台 24 小时在线、自带公网 IP、环境干净独立的机器。 这一章走完"云部署"的完整闭环：在阿里云控制台买一台轻量应用服务器 → 放通端口 → 用 SSH 登进去安装 OpenClaw → 最后在浏览器里打开 WebUI 管理面板。你会发现"部署到云端"一点也不玄：核心只有三步——放通端口、安装配置、访问 WebUI。

学完这一章，你能独立回答：为什么要用云服务器而不是只跑在本机？三步部署流程每一步在干什么？WebUI 面板里哪个入口是配置模型和通道的？

学习提示

本章全程动手操作。公网 IP、端口、密码这些信息先记在备忘录里——它们会在一章里反复出现。另外记住：云服务器是全新环境，装好只是第一步，让它按你的规则干活是下一章三份配置文件的事，别在本章就开始搬配置。

1① 为什么部署在云服务器：本地优先，不等于只能本地
要解决什么

前两章只讲了 OpenClaw 能做什么，还没真正装过；本章是第一次把它装起来跑。先看清本机运行的两个短板：电脑做不到 7×24 开机，OpenClaw 一"下线"，平台上来的消息就没人回；本机还要干别的活，装来装去容易互相污染。你先得想明白一件事：到底把它放哪跑，它才能不掉线。

核心思路

"跑在哪"的选择，本质是在线时长 × 是否公网可达的权衡：

跑在哪7×24 在线公网可达适合谁
个人电脑关机 / 休眠就下线一般没有固定公网 IP本地调试、学原理
家用小主机（如 Mac Mini）可以常开，但断电断网就挂要自己搞内网穿透愿意自己运维的人
云服务器机房托管，持续在线自带公网 IP大多数人的第一选择

关键认知：本地优先 ≠ 只能本地。 本地是用来"调试快、改着方便"的；真正要常驻服务，还是交给云服务器——它不关机、有固定公网 IP、环境全新干净，出了乱子还能随时重置重建。

坑在哪
现象原因 / 怎么办
电脑一合盖，OpenClaw 就不回消息了它跟着你的电脑一起休眠了。常驻服务要找一台"自己不睡觉"的机器，这正是云服务器的意义
以为"部署"就是本机的东西原样搬上去云服务器是全新环境，安装部署要重新走一遍流程；配置文件是下一章的内容，别提前搬
一上来就买顶配套餐学习和起步阶段，按控制台引导选入门配置即可；后面真不够了再扩容，先跑起来再说
2② 第一步：创建阿里云轻量应用服务器
要解决什么

前置工作是"买一块永远不关机的场地"。但阿里云控制台入口在哪、机器怎么买、配置怎么选——第一次进去容易迷路。这一节把购买流程拆开讲。

核心思路

打开阿里云官网 https://www.aliyun.com/ ，进入控制台后，购买轻量应用服务器。三个关键选项：

购买项怎么选
地域选离你访问网络近的节点，延迟低；地域购买后不易更改，想好再下单
系统镜像选 Linux 发行版（如 Ubuntu / CentOS），OpenClaw 部署在 Linux 上最顺手
套餐规格按控制台引导选入门配置即可，轻量应用服务器套餐固定、管理简单

为什么选"轻量应用服务器"而不是其他型号？因为它是最省心的形态：公网 IP 自带、防火墙规则可视化、重置密码两三个按钮搞定——本章接下来要做的放端口、重置密码、查 IP，它全给你准备好了入口。

坑在哪
现象原因 / 怎么办
买完不知道自己的公网 IP 是多少控制台"实例列表"里每台实例都显示公网 IP；后面 SSH 和 WebUI 都要用它，先记下来
地域选太远，打开 WebUI 明显变慢地域影响网络延迟；购买后难以更换，规划好再下单
买完就想直接登录新购实例默认没有能直接登录的密码，先看 point ⑦「重置密码」
选了 Windows 镜像不是不能跑，但本章主线是 Linux + SSH，跟着主线走最省事，选错了就重装镜像再来
3③ 放通服务器端口：三步流程第①步
要解决什么

机器买好了，但它像一栋"所有门都锁着"的房子。OpenClaw 的 WebUI 要对外提供服务，可云服务器默认只放行少量端口，外部浏览器根本进不来。第一步先做的不是装软件，而是开门。

核心思路

云服务器自带防火墙。通常 22 端口（SSH 登录）默认放行，而 OpenClaw WebUI 用的 18789 端口默认不放行——所以必须先手动放行它。

操作位置：阿里云控制台 → 选中该实例 → 进入防火墙页面 → 添加规则 → 协议选择 TCP、端口填 18789 → 来源按需（学习阶段可选 0.0.0.0/0）→ 保存生效。

类比：端口是"门牌号"，防火墙是"大门"。你不需要把所有门都打开，只需要打开要用（22、18789）的那几扇，而且开得越少越安全。

坑在哪
现象原因 / 怎么办
服务启动了，浏览器却打不开 WebUI大概率 18789 没放行。回控制台防火墙页面补规则，再刷新浏览器
为省事把所有端口 1-65535 全放通等于把整栋房子的门全敞开，任何人都能扫描探测你的机器。只放行用得到的端口
改完规则还是不生效检查规则是否已保存、协议端口是不是 TCP / 18789；部分控制台需要确认后才生效
4④ 安装并启动 OpenClaw：三步流程第②步
要解决什么

门开好了，下一步"住人"——把 OpenClaw 装进服务器。卡住的人大多是两处：一是登录命令怎么敲，二是"装完之后呢"？这一节讲清楚安装环节的定位与动作。

核心思路

先通过 SSH 登进服务器，再按官网安装文档执行安装，流程高度统一：

ssh root@服务器公网IP     # 登进服务器（前提：密码已重置、22 端口已放行）
# 注意：本章用 root 演示；如果第 5、6 章用的是 /home/用户/.openclaw/…，就把下面的路径换成你的部署用户，别混着抄
# 登录后在命令行里按 OpenClaw 官网安装说明执行安装

安装完成后注意两件事：

  • OpenClaw 会启动服务，并生成 WebUI 访问地址和 token——这是 point ⑤ 要用到的素材，记下来
  • "配置"的重心是 AGENTS / SOUL / USER 三份文件，那是下一章的正式内容；本章把服务装起来、能启动、能打开面板就算完成
坑在哪
现象原因 / 怎么办
以为"安装 = 配置完成"安装只是把程序放进机器；让它按你的规则干活靠配置文件，那是下一章
安装进行到一半不动或报错多为网络或依赖问题，重试或用国内镜像源，别反复中断安装
装完没记下 URL 和 token启动输出里有 WebUI 地址；丢了就去看启动日志重新找，别凭记忆拼
5⑤ 访问 OpenClaw WebUI：URL 与 token
要解决什么

服务启动了，地址也生成了——但那一串 URL 里每段是什么？里面的 token 是干嘛的，能不能发给别人？搞不清这两点，后面要么打不开，要么被陌生人打开。

核心思路

OpenClaw 启动后，用浏览器直接访问 Web 管理界面，地址格式如下：

http://服务器公网IP:18789/

只有两部分：公网 IP（服务器地址）和 :18789 端口。打开后界面会让你填访问令牌（token）——在服务器上跑 openclaw config get gateway.auth.token 取到，粘进面板就行。token 不要拼进 URL，更别把带 token 的地址发群里。

token 才是"钥匙"：拿到 URL 只能打开登录页，还得再填 token 才能进面板。所以 URL 泄露风险低于 token，但两个都别外发——发截图、发群里都要打码。

坑在哪
现象原因 / 怎么办
地址能开但提示无权限 / 401token 填错或过期：回服务器重新取一次，粘贴时别带多余空格
把带 token 的链接直接发群里等于把管理权限送人；token 泄露要主动换掉（改 gateway.auth.token 或跑 openclaw doctor --generate-gateway-token）再重启，光重启不会换
浏览器提示"非私密连接 / 不安全"WebUI 走 http 明文，浏览器会警告；学习阶段可直接忽略，长期公网使用考虑域名 + HTTPS
公网 IP 变了，旧地址打不开去控制台重新查公网 IP，用新 IP 重新拼 URL
6⑥ SSH 远程连接工具选型
要解决什么

要登进服务器装 OpenClaw、看日志、改配置，你需要一个"远程登录工具"。Windows 上这类工具一大堆，选哪个、区别在哪？先把战场扫一遍再动手。

核心思路

SSH 是管理云服务器的标准姿势，常见工具各有特点：

工具平台特点
XshellWindows老牌稳定、会话管理强，本章演示用它
FinalShellWindows国产，带图形化监控和文件管理
MobaXtermWindows / Linux终端 + SFTP 一体，功能齐全
系统自带 TerminalWindows / Mac / LinuxWindows 10+ 自带 OpenSSH，PowerShell 里直接 ssh；Mac/Linux 同理

无论用哪个，背后是同一件事：主机 IP + 端口（默认 22）+ 用户名 + 密码。工具只是"壳"，这四要素才是核心——换工具不换思路。

坑在哪
现象原因 / 怎么办
下到满屏广告的"破解版 Xshell"一律从官方渠道下载；FinalShell / MobaXterm 免费版完全够用
在几个工具间反复横跳工具只是通道，先选一个用熟（建议 Xshell 或 FinalShell），别把时间耗在挑工具上
Mac / Linux 用户以为必须装软件终端直接 ssh 用户名@公网IP 就能连，四要素一样不少
7⑦ 重置服务器实例密码
要解决什么

公网 IP 有了、SSH 工具备好了，可登录时要输的密码是哪来的？新购的云服务器并不会自动给你一个能登录的密码。首次使用前，必须先到控制台把密码设好。

核心思路

在登录云服务器之前，先在控制台完成"重置密码"：

  1. 控制台 → 实例列表 → 选中这台实例 → 重置密码（设置密码）
  2. 设置一个强度足够的密码：别用纯数字、别用生日手机号这类弱密码
  3. 按提示重启实例，新密码才会生效

之后无论是 SSH 登录，还是后续所有鉴权环节，用的都是这一组凭据。

坑在哪
现象原因 / 怎么办
重置完密码还是登录失败重置密码后通常需要重启实例才生效，回控制台重启后再试
密码设得太简单被暴力破解云服务器被自动化扫描是常态，用长密码（大小写 + 数字 + 符号）是第一道防线
密码忘了随时可以再重置，但重置要重启实例、期间服务中断；密码第一时间记进密码本
8⑧ 用 Xshell 登录服务器
要解决什么

四要素都齐了（IP、22、用户名、密码），具体在 Xshell 里怎么连？这一步卡住的人最多——不是不会填，而是填错地方、填错值。

核心思路

Xshell 里的标准操作流程：

  1. 新建会话：名称随意，主机填服务器的公网 IP，端口默认 22，协议选 SSH
  2. 连接后输入用户名（Linux 发行版通常是 root 或初始化时设置的用户）和密码
  3. 看到 # 或 $ 提示符 = 登录成功，接下来所有安装、看日志、改配置都在这个黑窗口里完成

登录成功后的唯一"操作台"就是命令行；WebUI 管配置，命令行管安装和运维，两者分工不同。

坑在哪
现象原因 / 怎么办
连接超时 / 无法连接按链排查：IP 是不是公网 IP、22 端口防火墙有没有放行、密码重置后有没有重启、本机网络是否正常
把内网 IP 填进主机栏Xshell 里只能填服务器的公网 IP，内网地址从本地连不到
密码连续输错被锁定冷静核对密码与用户名再试，别硬刷；多次失败会有冷却或封禁
9⑨ WebUI 管理面板解读：配置模型与通道
要解决什么

终于进了面板，看到一堆按钮和输入框——哪些是现在要用的？给 OpenClaw 接大模型、接消息平台，分别该去哪个区域？这一节把管理面板的地图认一下。

核心思路

WebUI 是 OpenClaw 的管理面板，核心作用集中在两块：

面板区域干什么什么时候用
模型配置选择大模型供应商、填写 API Key、设定默认模型决定 OpenClaw"怎么思考"的引擎
通道（channel）配置配置各消息平台接入通道（微信、飞书等）阶段终点"五平台接入"就是在这里逐个接

一句话定位：模型决定 OpenClaw 的"大脑"，通道决定它"长在哪"。 本章只需要认清这两个入口长什么样、是干什么的，具体的接入和配置在后续章节逐个做。

坑在哪
现象原因 / 怎么办
把"通道"当成"模型"去配置channel 指平台接入接口，模型指大模型服务，两者在面板里分区放置，别混填
面板里改完配置感觉没生效多数配置需要保存并让服务重启 / 重载才生效，改完看一眼运行状态
API Key 明文截图外发Key 和 token 一样是敏感凭据，泄露了要立即作废重建，别外传
10⑩ 三步部署流程复盘
要解决什么

完整走了一遍，但流程还有不少环节容易忘、容易乱。把三步压缩成一张"部署地图"，以后从零部署或排查问题，照着地图走就行。

核心思路

OpenClaw 云端部署 = 三步，各有使命：

步骤动作解决什么问题
① 放通服务器端口控制台防火墙放行 22 / 18789让外部"进得来"
② 安装并启动 OpenClawSSH 登录后按官网文档安装，装完先能跑起来让程序"住进去"（配置是下一章的事）
③ 访问 WebUI 管理面板浏览器打开 URL + token让人"管得着"

串起来就是完整链路：买机器 → 重置密码 → Xshell 登录 → 放端口 → 装 OpenClaw → 浏览器开 WebUI。今后部署出问题，就沿这条链一段段排查：IP 对吗 → 22 通吗 → 登录成了吗 → 18789 放了吗 → URL 抄对了吗 → token 对了吗。

坑在哪
现象原因 / 怎么办
跳步：没放端口就去开 WebUI打不开多是第①步漏了，回控制台补防火墙规则，而不是重装程序
部署完觉得"任务结束了"本章只是"装上并能管"；让它按你的规则干活，是下一章三份配置文件的事
一卡住就从头重装一遍多数故障只是链路中某一环，按"IP→端口→登录→URL→token"逐段排查，比重装快得多

本章小结

这一章你实际拿到的是六样东西：

拿到了什么为什么要紧
为什么部署在云服务器7×24 在线 + 公网 IP，OpenClaw 才能常驻回消息
阿里云轻量应用服务器创建流程地域 / 镜像 / 套餐怎么选，部署的"场地"到手
三步部署流程放端口 → 安装配置 → 访问 WebUI，部署不再是玄学
WebUI URL 与 token 的安全认知会拼地址，更知道 token 为什么不能外传
SSH 登录实操工具、密码、四要素，最后一米自己走通
WebUI 面板地图模型配置、通道配置两个入口认得清、不混用
