1① RPM：手动安装软件包
要解决什么

拿到一个 .rpm 安装包（相当于 Windows 的 .exe 安装程序），怎么装上？

核心思路

RPM（Red Hat Package Manager）是红帽系发行版的底层包管理工具：

rpm -ivh jdk-17.rpm          # i 安装 v 显示过程 h 显示进度条
rpm -e jdk-17                # e 卸载
rpm -q jdk-17                # q 查询指定包是否已装
rpm -qa | grep jdk           # qa 列出所有已装包里含 jdk 的
rpm -qf /usr/bin/java        # qf 反查：这个文件属于哪个包

懂 RPM 的意义：它是 yum 的地基（yum 底层就是 rpm），排查"这个文件谁装的"全靠 -qf。

坑在哪
现象原因 / 怎么办
rpm -ivh 报"依赖 xxx 缺失/deptest failed"这是 RPM 依赖地狱：装 A 要 B，装 B 要 C……手动一个个装会疯掉，这就是 yum 存在的原因
rpm -e 卸载报依赖错误有别的包依赖它；--nodeps 可强制卸，但可能弄崩别的软件，慎用
下载的 rpm 包有 32/64 位之分装不上架构要匹配：x86_64 系统装 x86_64 包，i386 包不兼容
2② yum：自动解决依赖的"软件商店"
要解决什么

RPM 手动装依赖装到崩溃，有没有"输个名字，全自动装好"的方式？

核心思路

yum = 在线软件商店：它从配置好的仓库（repo）里找包，并自动把所有依赖一起装好：

yum install -y httpd          # 安装（-y 跳过确认）
yum remove -y httpd           # 卸载
yum list | grep mysql         # 列出可用包
yum search mysql              # 搜索
yum update -y                 # 升级全部（生产环境慎用：先备份）
yum provides /usr/bin/java    # 查"哪个包提供这个文件"（比 rpm -qf 更全）

rpm 和 yum 的关系一句话：rpm 是"手动拧螺丝"，yum 是"请装修队"——装修队（yum）干完活，螺丝（rpm）也都在。

坑在哪
现象原因 / 怎么办
yum 报"不能连接到仓库/网络"仓库在远程，必须联网；内网环境要配本地镜像源
不写 -y，命令卡在"Is this ok [y/N]"回车默认 No 就退出了；批量脚本里一定带 -y
yum install 装了一半断网重新执行同一条命令，yum 会续装（事务机制），别急着重启
3③ 配置阿里云 yum 源：下载慢的救命药
要解决什么

官方源在国外，yum install 龟速还经常超时。国内怎么换源？

核心思路

"源"就是 yum 去哪里下载包的地址列表，配置文件在 /etc/yum.repos.d/*.repo。换阿里源三步走：

# 1. 备份原配置（养成好习惯）
mv /etc/yum.repos.d/CentOS-Base.repo /etc/yum.repos.d/CentOS-Base.repo.bak

# 2. 下载阿里源配置（wget 见第六章）
wget -O /etc/yum.repos.d/CentOS-Base.repo \
  https://mirrors.aliyun.com/repo/Centos-7.repo

# 3. 清缓存并重建
yum clean all
yum makecache

换完 yum install 立刻变快。补一句仓库文件长啥样（/etc/yum.repos.d/ 下）：

[base]                      # 仓库名（id，不能重复）
name=CentOS-$releasever - Base
baseurl=https://mirrors.aliyun.com/centos/$releasever/os/$basearch/
enabled=1                   # 1=启用
gpgcheck=1                  # 1=校验签名
坑在哪
现象原因 / 怎么办
换源后 yum 还走老地址repo 没被新文件覆盖或 enabled=0；yum repolist 看正在用哪些仓库
换源后报错"找不到 metadata"没 yum clean all 清缓存；清完 makecache 重建
仓库名（[base] 等）重复后面加载的覆盖前面，规则就乱了；检查 .repo 文件里的 id 唯一
4④ JDK 安装：解压 + 配环境变量
要解决什么

跑 Java 程序前得有 JDK。怎么在服务器上装好并让 java -version 直接可用？

核心思路

JDK 通常以 .tar.gz 提供，解压即用，关键是配上环境变量（复用第七章知识）：

# 1. 解压到统一目录（/usr/local 是第三方软件惯例位置）
tar -zxvf jdk-17_linux-x64_bin.tar.gz -C /usr/local

# 2. 配置环境变量（追加进系统级 profile）
vim /etc/profile

文件里加三行：

export JAVA_HOME=/usr/local/jdk-17.0.10
export PATH=$PATH:$JAVA_HOME/bin

然后激活并验证：

source /etc/profile
java -version        # 输出 java version "17.0.x" 即成功

以后换 JDK 版本只需换目录、改 JAVA_HOME，PATH 不用动。

坑在哪
现象原因 / 怎么办
java -version 报 command not found① PATH 没加或没 source；② JAVA_HOME 路径写错；按顺序查
配好后重开终端又失效export 没写进 profile 文件，只在当前 shell 敲过；写文件 + source
解压出来目录名带版本号，路径写错用 ls /usr/local 看真实目录名，别照记忆写
系统自带的 openjdk 版本太老yum remove -y java* 清掉老版本再装自己的 JDK
5⑤ Tomcat 安装：解压即用的 Web 服务器
要解决什么

JDK 有了，还差个 Web 容器来跑 Java 项目（比如 JSP/Servlet 应用）。Tomcat 怎么装？

核心思路

Tomcat 是纯 Java 写的，跨平台，解压即用：

# 1. 解压（建议同时配个 CATALINA_HOME 方便后续命令）
tar -zxvf apache-tomcat-9.0.xx.tar.gz -C /usr/local
# 2.（可选）配置环境变量后 source
vim /etc/profile

加两行：

export CATALINA_HOME=/usr/local/apache-tomcat-9.0.xx
export PATH=$PATH:$CATALINA_HOME/bin
# 3. 启动（bin 目录下的脚本）
sh /usr/local/apache-tomcat-9.0.xx/bin/startup.sh
# 验证：浏览器访问 http://192.168.66.100:8080 出现 Tomcat 欢迎页

停止用 shutdown.sh，日志在 logs/catalina.out。

坑在哪
现象原因 / 怎么办
startup.sh 报"Neither the JAVA_HOME"JAVA_HOME 没配或配错——Tomcat 启动前提是能找到 JDK
启动报错但浏览器打不开看 logs/catalina.out 日志；多半是端口被占或权限问题
8080 被别的程序占用改 conf/server.xml 里的端口，或用 netstat 找出占用者杀掉（见第 ⑫ 点）
远程访问 8080 失败检查虚拟机防火墙是否放行 8080（firewall-cmd --add-port=8080/tcp --permanent 然后 --reload）
6⑥ MySQL 安装：用 yum 官方仓库一条龙
要解决什么

装数据库 MySQL 不比 JDK 解压即用——它有服务、有仓库、有初始化流程。正确的装法是什么？

核心思路

MySQL 官方提供 yum 仓库，装法就三步：

# 1. 下载并安装 MySQL 官方仓库包（提供 mysql-community-server 这个包）
wget https://dev.mysql.com/get/mysql80-community-release-el7-7.noarch.rpm
rpm -ivh mysql80-community-release-el7-7.noarch.rpm

# 2. 用 yum 安装服务端（依赖全部自动解决）
yum install -y mysql-community-server

# 3. 启动并设开机自启
systemctl start mysqld
systemctl enable mysqld

装完后 MySQL 首次启动会自动生成 root 临时密码，写在 /var/log/mysqld.log 里——别急着猜密码。

坑在哪
现象原因 / 怎么办
仓库 rpm 装完 yum install 报 gpg 校验失败没有官方 GPG key：临时加 --nogpgcheck（或先 rpm --import 官方 key）；生产别长期禁用校验
systemctl start mysqld 后马上看状态闪退第一次启动要初始化数据目录，稍等再看；还失败就看 /var/log/mysqld.log
装到别的发行版（Ubuntu）报错那是 rpm 系专用；Ubuntu 用 apt 装 mysql-server，别混
7⑦ MySQL 初始化：临时密码 → 改密码 → 开远程
要解决什么

MySQL 装好了，但 root 密码是"系统随机生成"的，而且默认只允许本机连。怎么登录、改密码、开远程？

核心思路

四步走：

# 1. 从日志里捞出首次生成的临时密码
grep "temporary password" /var/log/mysqld.log
# 输出示例：A temporary password is generated for root@localhost: xxxxxxxx

# 2. 用临时密码登录
mysql -uroot -p
# 提示输入临时密码

# 3. 在 mysql> 里改密码（首次必须改，否则啥也干不了）
ALTER USER 'root'@'localhost' IDENTIFIED BY '你的新强密码';

如果系统默认密码策略太严（要求大写+小写+数字+符号），先放宽再改：

SET GLOBAL validate_password.policy = LOW;
SET GLOBAL validate_password.length = 6;

第 4 步，开远程连接（默认可选）：

-- 允许 root 从任意主机连接（生产环境建议建专用账号而非开放 root）
CREATE USER 'dev'@'%' IDENTIFIED BY '你的新强密码';
GRANT ALL PRIVILEGES ON *.* TO 'dev'@'%';
FLUSH PRIVILEGES;

别忘了防火墙放行 3306（虚拟机里）：

firewall-cmd --add-port=3306/tcp --permanent
firewall-cmd --reload
坑在哪
现象原因 / 怎么办
乱试密码导致 mysql -uroot -p 一直失败临时密码必须去 /var/log/mysqld.log 里找，别猜
改密码时提示"密码不符合策略"先 SET GLOBAL validate_password.policy=LOW 再 ALTER USER
本机能连、远程软件连不上主因三个：没授权远程账号（'dev'@'%'）、3306 防火墙没放行、MySQL 只绑了 127.0.0.1
讲义里的示例密码直接抄教学环境弱口令只用于练习，生产绝不使用；关键词：强密码、别外泄
8⑧ MySQL 卸载：装坏了怎么清干净
要解决什么

MySQL 装乱了/要换版本，卸载时明明 rpm -e 了却还残留一堆目录和用户，重装还冲突。

核心思路

干净卸载四步（顺序别乱）：

# 1. 停服务
systemctl stop mysqld

# 2. 用 rpm 反查并删除所有 mysql 相关包
rpm -qa | grep mysql
rpm -ev --nodeps 上面查到的每个包名

# 3. 删残留目录和配置文件
rm -rf /var/lib/mysql /etc/my.cnf

# 4. 删自动创建的用户和组（可选，清理彻底）
userdel mysql
groupdel mysql

卸载干净再重装，能避免大量"端口被占/数据目录冲突"的疑难杂症。

坑在哪
现象原因 / 怎么办
只 rpm -e 主包，/var/lib/mysql 数据还在数据目录要手动清（上一步 rm -rf）；不清会导致重装初始化冲突
卸载后端口 3306 还被占用有可能残留进程没杀干净：`netstat -atnlpgrep 3306` 找到 PID 再 kill
重装包时说"包已经安装"上次没卸净：rpm -qagrep mysql 再把残留包删掉
9⑨ ps：查看进程快照
要解决什么

服务器上现在跑了哪些程序？哪个进程占了多少资源？怎么看？

核心思路

ps 是"拍一张快照"（静态的），最常用两种流派：

ps -ef          # 全量进程列表（System V 风格）
ps aux          # 全量列表（BSD 风格），带 CPU/内存百分比

ps aux 输出列：

USER   PID  %CPU  %MEM  STAT  START  TIME   COMMAND
root  1234   0.3   1.2   Ss   10:00  0:01   sshd
列含义
USER进程归属用户
PID进程号（杀进程靠它）
%CPU / %MEMCPU / 内存占用百分比
STAT状态：S 睡眠、R 运行、Z 僵尸、T 停止
COMMAND命令名

日常组合：ps aux | grep mysql 只筛需要的进程。

坑在哪
现象原因 / 怎么办
ps auxgrep xxx 结果里有"自己"grep 进程也会匹配到关键字；加 `grep -v grep` 排除
想持续看动态变化ps 是快照，会动的东西用 top（下一知识点）
进程 CPU 显示 100%ps 里 %CPU 是累计值/瞬时值，精确到秒；结合 top 看才直观
10⑩ top / htop：动态盯 CPU 和内存
要解决什么

服务器突然变卡，谁的锅？——需要"活"的监控，看每秒谁在抢资源。

核心思路 
top                # 动态刷新（每 3 秒默认），q 退出
top -d 2 -p 10604  # 每 2 秒刷新，只看 PID 10604 这个进程

顶部信息看懂三块：

top - 10:00:00 up 2 days, load average: 0.30, 0.15, 0.10
Tasks: 120 total, 1 running, 119 sleeping
%Cpu(s): 2.0 us, 1.0 sy, 96.0 id
  • load average：1 / 5 / 15 分钟平均负载（排队任务数），不是 CPU 占用率；接近/超过 CPU 核数说明压力大；
  • 进程列表默认按 CPU 排序，看 %CPU 和 %MEM 列找罪魁祸首；
  • 按键：P 按 CPU 排、M 按内存排、q 退出。

htop 是 top 的增强版（支持鼠标，更直观）：

yum install -y htop     # 先装（依赖 epel 源可先 yum install epel-release）
htop
坑在哪
现象原因 / 怎么办
load average 高就当"CPU 用满了"负载是"排队的任务数"，IO 瓶颈也会让它高；结合 %Cpu 列和 top 里的 wa 值判断
CPU 列加起来超过 100%多核机器一核 100% 是一核全忙；要看 lscpu 查核数再判断是否真满载
Windows 习惯"内存 used 高=危险"Linux 把空闲内存当缓存，看 available；free -h 里 available 才是真实可用的
11⑪ kill：终止进程
要解决什么

有个进程卡死/占资源，怎么干掉它？——先找 PID，再 kill。

核心思路 
kill 1234            # 温和终止（SIGTERM，让进程自己善后）
kill -9 1234         # 强杀（SIGKILL，不留缓冲，进程直接没了）
killall nginx        # 按命令名杀全部同名进程

找 PID 的三条路子：

ps aux | grep httpd   # 常规：从输出第二列看 PID
pgrep httpd           # 直接输出匹配的 PID
pidof nginx           # 输出进程 PID（更简洁）

补一个后台概念：命令后加 & 让它在后台运行：

./start.sh &          # 后台执行，马上回到提示符

原则：先温和（kill）后强杀（kill -9）——硬杀可能丢数据（比如没落盘的写入）。

坑在哪
现象原因 / 怎么办
kill 了 PID 进程还在信号没杀掉：换 kill -9；或 PID 找错了（grep 出了自己）
kill -9 后数据丢了/服务起不来-9 不给善后时间；非必要先普通 kill，等服务自己退出
杀了父进程，子进程还活着部分子进程不随父死亡；killall 或逐个处理
12⑫ netstat / lsof：查端口占用
要解决什么

"8080 端口被占用""MySQL 的 3306 通不通"——这些"端口问题"怎么查？

核心思路 
netstat -a              # 列出所有连接
netstat -at             # 只看 TCP
netstat -au             # 只看 UDP
netstat -atnlp          # 最常用组合：全监听 TCP + 不反查域名 + 显示程序名
netstat -r              # 查看路由表

-atnlp 拆解：a=全部连接 t=TCP n=显示数字 IP（不查域名）l=只看监听 p=显示程序名。

按"端口找进程"用 lsof：

lsof -i:8080            # 谁在监听 8080 → 输出 PID 和程序名

排障流程例：Tomcat 起不来 → netstat -atnlp | grep 8080 → 发现被别的进程占 → kill 或改端口。

坑在哪
现象原因 / 怎么办
netstat 显示 :::8080 以为异常::: 是 IPv6 监听格式，同端口 IPv4/IPv6 都监听着，正常
-p 看不到程序名权限不够：加 sudo 或切 root 再看
netstat -atnlp 没输出自己的想看项先确认有没有装 net-tools；CentOS 7 最小装可能没有，yum install -y net-tools
13⑬ systemctl：现代服务管理器
要解决什么

"服务"（MySQL、sshd、防火墙）怎么启动、停止、重启、设开机自启？老命令 service 和新命令 systemctl 什么关系？

核心思路

服务 = 常驻后台、监听端口的守护进程。老一代由 System V init 管（service/chkconfig 命令），新一代由 systemd 管，主命令 systemctl：

systemctl start mysqld      # 启动
systemctl stop mysqld       # 停止
systemctl restart mysqld    # 重启
systemctl reload mysqld     # 重载配置（不中断服务）
systemctl status mysqld     # 查看状态
systemctl enable mysqld     # 开机自启
systemctl disable mysqld    # 取消开机自启
systemctl is-enabled mysqld # 查询是否开机自启

新旧命令对照表（System V init → systemd）：

System V initsystemctl作用
service foo startsystemctl start foo启动
service foo stopsystemctl stop foo停止
chkconfig foo onsystemctl enable foo开机自启
chkconfig foo offsystemctl disable foo取消自启
chkconfig --listsystemctl list-unit-files --type=service看全部自启状态

配套工具：systemd-analyze（看启动耗时）、hostnamectl（看/改主机名）、timedatectl（看/改时区和时间）。

坑在哪
现象原因 / 怎么办
systemctl start 显示启动成功但 status 是 failed服务崩了：journalctl -u 服务名 看它的日志，别只看绿色/红色
新系统里 service 命令还能用是兼容层；新环境一律学 systemctl，别再学 service 了
改了服务配置没重启改配置后要 restart（或 reload）；光 start 不生效
14⑭ crontab：定时任务
要解决什么

"每天凌晨 3 点备份数据库""每周一三五备份项目"——这类固定时间重复做的事，怎么自动化？

核心思路

crond 是 Linux 的定时任务服务，用户用 crontab 命令管理自己的任务：

crontab -e        # 编辑定时任务（打开一个文件，写入一行规则）
crontab -l        # 查看自己已有的任务
crontab -r        # 清空所有任务

规则是五个时间字段 + 命令：

分 时 日 月 周   命令
*  *  *  *  *   /usr/bin/tar -zcvf backup.tar.gz /opt/wwwroot
字段取值范围符号含义
分0-59* 任意，*/10 每 10 分钟
时0-235-7 5 到 7 点
日1-311,15 每月的 1 号和 15 号
月1-121,5,8 1/5/8 月
周0-6（0=周日）1,3,5 周一三五

常见例子：

30 3 * * 1,3,5  /usr/bin/tar -zcvf backup.tar.gz /opt/wwwroot   # 周一周三周五 3:30 备份
0 2 * * *  ls /opt > /tmp/log.txt                                # 每天 2:00 执行
*/5 * * * *  /opt/check.sh                                       # 每 5 分钟一次

命令必须写绝对路径（crontab 环境里 PATH 不完整，写 ls 可能找不到）。

坑在哪
现象原因 / 怎么办
定时任务"没执行"首要怀疑命令路径：写成 /usr/bin/tar 全路径；再看 crond 服务在不在（systemctl status crond）
执行了但看不到输出输出不会上屏；脚本里重定向到文件 >> /tmp/job.log 2>&1 才能留痕
周和日都设置了二者是"或"关系（满足其一就执行）；想精确匹配就不要同时设
改完任务想立即测试crontab -e 存盘即生效；测试用 */1 * * * *（每分钟）验证完再改回
