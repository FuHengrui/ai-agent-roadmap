第三章　用户与用户组管理

阶段 18 · 云原生开发环境与 DevOps 工具链　|　Linux 基础　|　难度 ★★★
这一章在解决什么问题

一台 Linux 服务器往往几十个人用：开发、运维、业务人员都往里挤。问题来了——系统怎么知道谁是 root、谁只能看不能动？你怎么给新同事开账号、给离职的人销号？

Windows 那套"一个管理员密码包打天下"在服务器上根本行不通：谁拿到 root 密码就能删全世界。Linux 的答案是用户 + 用户组 + 权限这套体系：一人一个账号，身份决定能干什么。本章就搞定账号的增删改查、密码管理，以及 su / sudo 这两种"临时变身管理员"的方式——这是进服务器的第一张门禁卡。

开始之前

上一章的虚拟机连得上就能开始，这章不用装新东西，useradd、passwd 这些要自己敲。

学到这儿就够了

能说清 UID/GID 和 /etc/passwd 是什么，能建用户、改属组、用 su/sudo 切身份，这章就算过了。

这一章在整个知识库里的位置 上一章：虚拟机网络配置与 XShell 远程连接——你已经能远程登录服务器 本章 ← 你在这里：搞清"谁"在用这台机器，管理账号与身份 下一章：文件类型与权限管理——身份有了，接下来就是"这个身份能碰哪些文件" 阶段终点：云原生开发环境与 DevOps 工具链，权限意识是云原生安全的第一课
学习提示

本章命令都是"字母拼成的"：useradd、usermod、userdel、passwd、groupadd……看着多，但用法高度一致（都是"命令 + 用户名 + 选项"）。建议把命令佳句列在纸上，跟着敲两遍，再来做 quiz。

1① 多用户系统：凭什么一台机器能给一群人用
要解决什么

Windows 一般是"一个人一台电脑"，服务器却是几十个人同时登录。系统怎么保证大家互不干扰、各干各的？

核心思路

Linux 是多用户多任务系统：可以同时让很多人登录，每人的操作、文件、进程在系统眼里都是"某个用户"的。

  • 每个登录者都是一个用户，系统只认"你是哪个用户"这个身份；
  • 文件、进程、权限全挂在用户头上：你的进程别人杀不死，你的文件别人改不了；
  • 这就是为什么服务器不怕"人杂"——不是没人管，而是系统按身份自动管。

一句话：Linux 的一切操作，背后都在问一句"以谁的身份在干"。

坑在哪
现象原因 / 怎么办
普通用户想删别人的文件，被拒绝权限机制拦住了；这是特性不是故障，越权操作要么换身份（su/sudo），要么就别想
用 root 登录后所有文件"都可以动"root 是超管，权限约等于无边界的通行证；所以日常用普通用户，偶尔才切 root
2② 用户与用户组：一人一账号，一组一权限
要解决什么

公司 30 个人都要能读项目目录，难道要一个个授权？人多了权限就乱成一锅粥。

核心思路

用户组（group）= 一批具有相同权限的用户组成的集合。思路是：授权给"组"，组内所有人自动生效；新人进来加入组就行，不用动任何权限设置。

用户和组有四种关系（这四条直接记）：

关系含义
一对一一个用户只能属于一个组（这个组就是他的基本组）
一对多一个用户可属多个组（扩展组），一个组也有多个成员
多对一多个用户属于同一个组
多对多多个用户属于多个组（用户可以加入扩展组）

成本一句话：以后找人授权，先找组，别一个个发权限。

坑在哪
现象原因 / 怎么办
以为"一个用户只能在一个组里"用户有基本组（默认、跟用户名同名）+ 多个扩展组；groups 用户名 可查
新建用户似乎自动出现一个"同名组"正常：useradd 默认创建一个与用户名同名的组作为基本组，不用自己建
3③ UID 与 GID：用户的身份证号
要解决什么

系统怎么判断"你是 root"？看用户名？不是——名字可以重复、可以改，判断身份靠的是编号。

核心思路

UID（用户 ID）= 用户的身份证号，GID = 组的身份证号，系统内部只认编号不认名字。

三段式划分（口径统一，别用老教材的说法）：

区间谁在用说明
0root超级管理员，唯一
1 ~ 999系统用户给服务程序（sshd、mysql 等）用，不能登录，防提权
1000 起普通用户日常开发登录的用户，从 1000 开始往上排
坑在哪
现象原因 / 怎么办
背了老教材"普通用户 500 起、伪用户 1~499"那是旧系统的口径；现代发行版统一为系统用户 1~999、普通用户 1000 起
手滑删了用户，发现一堆文件变成"无主"文件只认 UID 不认名字；被删用户的文件属主显示为数字，需要 chown 重新归属（第 11 章会细讲文件归属）
4④ 用户信息住在哪：/etc/passwd 与 /etc/shadow
要解决什么

useradd 建的用户，账号信息到底存哪去了？出了问题该去哪查？

核心思路

两个文件记住就够了：

  • /etc/passwd：每个用户一行，字段用冒号分隔：用户名:x:UID:GID:备注:家目录:登录shell；
  • /etc/shadow：密码的加密信息（只有 root 能读，权限很严）。

看实例（一行拆开解释）：

dev:x:1000:1000:dev:/home/dev:/bin/bash
 │  │  │    │    │      │        └─ 登录 shell：/bin/bash 可登录
 │  │  │    │    │      └────────── 家目录 /home/dev
 │  │  │    │    └───────────────── 备注
 │  │  │    └────────────────────── GID=1000，属于 1000 号组
 │  │  └─────────────────────────── UID=1000，普通用户
 │  └────────────────────────────── x 占位：密码不在这，在 shadow
 └───────────────────────────────── 用户名

注意第二个字段是 x 不是密码——密码被挪到 /etc/shadow 里了，这是安全考虑。

坑在哪
现象原因 / 怎么办
cat /etc/shadow 没权限，以为系统坏了正常！shadow 权限极高，只有 root 能读；用 root 身份再看
手改 /etc/passwd 后用户登录不了格式少一个冒号、字段错位都会翻车；要改用户信息用 usermod 等命令，别手工编辑
5⑤ useradd：创建用户账号
要解决什么

来了个新人，怎么给他开一个能登录的账号？

核心思路

最简用法就是 useradd 用户名，常用选项一次记全：

useradd dev                    # 新建用户，默认建同名组、家目录 /home/dev
useradd -d /home/dev2 dev      # 指定家目录
useradd -u 2000 dev            # 指定 UID
useradd -s /sbin/nologin dev   # 指定 shell：不能登录（服务账号专用）
useradd -g bigdata dev         # 指定基本组
useradd -G docker,bigdata dev  # 指定扩展组（可多个，逗号分隔）

重点：加了 /sbin/nologin 的用户叫服务账号——程序以它身份跑（比如 mysqld），但人不能登录它，防提权。

坑在哪
现象原因 / 怎么办
useradd 之后登录，密码错误进不去useradd 不会设置密码，必须再 passwd dev 设密码才能登录
用 useradd -s /sbin/nologin 建的用户登录被拒不是密码错，是 shell 被禁；服务账号本来就该这样，别改成 /bin/bash 除非确实需要
useradd 报"用户已存在"用户名重复；id 用户名 或 grep 用户名 /etc/passwd 先确认
6⑥ usermod：修改用户信息
要解决什么

账号建错了/人要换部门了，不想删了重建（重建会丢归属关系），怎么改？

核心思路

usermod 选项 用户名，和 useradd 的选项几乎一一对应：

usermod -l dev2 dev        # 改名
usermod -u 2000 dev        # 改 UID
usermod -g bigdata dev     # 改基本组
usermod -G docker dev      # 改扩展组（注意：会覆盖原扩展组，想追加要带上原来的组名）
usermod -s /bin/bash dev   # 改登录 shell
usermod -L dev             # 锁定账号（暂禁登录，不解锁）
usermod -U dev             # 解锁

改完用 id dev 查看属组和 UID 是否变化。

坑在哪
现象原因 / 怎么办
usermod -G 后，用户原有的扩展组不见了-G 是"整体替换"；想保留原组必须把原组名一起写进去，如 usermod -G bigdata,docker dev
改了 UID，发现该用户名下文件还是旧 ID文件属主记录的是数字 UID；改 UID 后旧文件变"无主"，需要 chown 纠正
锁定账号后用户还在线-L 只阻止新的登录，已登录会话不会强制断开；可把用户踢下线或等会话结束
7⑦ userdel：删除用户
要解决什么

人走了，账号怎么办？直接删会不会留下垃圾？

核心思路 
userdel dev          # 删除账号（保留家目录）
userdel -r dev       # 删除账号 + 家目录 + 邮箱收件目录，删得干净

删除会影响的文件：/etc/passwd、/etc/shadow 里的账号行，以及（加 -r 时）/home/dev 整个目录。删完可以用 id dev 验证，会提示用户不存在。

坑在哪
现象原因 / 怎么办
userdel 后 /home 下还留着家目录没加 -r；要么接受"留目录"，要么手动 rm -rf /home/dev（确认不需要再删）
用户正登录着，userdel 报错或删不干净先看谁在线（who/w），把目标用户会话结束再删
删了用户后出现一堆"无名数字属主"文件该用户在其他目录（/tmp、/opt）还留有文件；要一并清理或 chown 给别人
8⑧ passwd：密码管理与账号锁定
要解决什么

账号建好了，密码谁来设？用户把密码忘了怎么办？临时禁用一个账号怎么搞？

核心思路

passwd 是密码管理的瑞士军刀：

passwd dev              # 给 dev 设/改密码（交互输入两次）
passwd -l dev           # 锁定账号（lock，等用于 usermod -L）
passwd -u dev           # 解锁
passwd -S dev           # 查看密码状态（是否已设、是否锁定）
passwd                  # 不带用户名：改自己的密码（普通用户只能改自己）

规则提醒：

  • root 可以给任何用户改密码；普通用户只能改自己的，且旧密码要输对；
  • 服务账号建议锁定，需要时再解锁。
坑在哪
现象原因 / 怎么办
useradd 后直接登录，一直说密码错误没设过密码！先 passwd 用户名 设一遍
输入密码屏幕上一个字都不显示这是正常设计（安全），不是键盘坏了；输完回车即可
passwd 提示"密码太短/太简单"被拒系统有密码策略（默认 8 位起且不能太简单）；练习环境可自行设置，生产环境别为省事降级
想给服务账号设个弱口令方便测试教学环境弱口令仅用于本地练习；生产环境一律强密码 + 锁定不登录
9⑨ groupadd / groupmod / groupdel：用户组管理
要解决什么

要新建一个项目组、给组改名、删掉废弃的组，怎么操作？

核心思路

三个命令对应组的增、改、删：

groupadd bigdata              # 新建组
groupadd -g 1600 bigdata      # 指定 GID
groupmod -n bigdata2 bigdata  # 改组名（new 前 old 后）
groupmod -g 1600 bigdata      # 改 GID
groupdel bigdata              # 删除组

配合验证：grep bigdata /etc/group 或 groups 用户名 看用户归属。

坑在哪
现象原因 / 怎么办
groupdel 报错拒绝删除该组还有用户引用（比如是某用户的基本组）或还有文件属这个组；先 usermod -g 把用户移走，或 chgrp 掉文件再删
改组名后，之前按组授权的文件权限还有效吗文件属组记录的是 GID；改名只是改名字，授权依然挂在 GID 上，一般不受影响
10⑩ su：切换用户身份
要解决什么

日常用普通用户 dev 登录，办一件事需要管理员权限——不想退出重登，怎么办？

核心思路

su = switch user，切换身份：

su - root        # 切到 root（强烈建议带 -：连环境变量一起切，干净）
su - dev         # 切到 dev
exit             # 退回之前的身份

重点：

  • 切到谁就要谁的密码（普通用户切 root 输 root 密码）；root 切任何普通用户不需要密码；
  • 带 - 和不带的区别：不带 - 只换身份、保留原 shell 的环境变量，容易踩"命令找不到"的坑。
坑在哪
现象原因 / 怎么办
su - root 输的是 dev 的密码，一直错要的是 root 的密码；反过来说，root 切 dev 不用密码
忘记带 -，切过去 java、yum 全"command not found"环境变量没切（PATH 还是普通用户的）；su - root 重来
在公司生产机上频繁 su - root危险：root 密码在多人间流传；更稳的做法是用 sudo（下一知识点）
11⑪ sudo：给普通用户发"特事特办通行证"
要解决什么

把 root 密码告诉下手的人，风险太大：他知道了就能为所欲为。有没有"只给某个命令的权限、还要留日志"的方案？

核心思路

sudo = 让受信任的普通用户以 root 身份执行指定命令：

  • 不需要 root 密码，输入自己的密码就能执行；5 分钟窗口内免密再输（可配置）；
  • 权限边界由 /etc/sudoers 决定，谁能用、能用哪些命令，白纸黑字；
  • 必须用 visudo 编辑（不要直接 vi）：它带语法检查，改错了不至于立刻废掉 sudo。

配置示例（visudo 里加一行）：

dev ALL=(ALL) ALL

含义（从左到右）：谁（dev） 在哪台机器（ALL） 以谁身份（root） 执行哪些命令（ALL）。

再进一步还可以收窄到只有特定命令：

dev ALL=(ALL) /usr/bin/systemctl restart mysqld

这样 dev 只能重启 MySQL，动不了别的。

坑在哪
现象原因 / 怎么办
提示 "dev is not in the sudoers file"访客不在授权名单；root 执行 visudo 把 dev 加进去
直接用 vi 改 /etc/sudoers，语法改坏了sudo 全废、root 都救不回；所以必须用 visudo，它保存前会检查语法
sudo 也要输密码？输谁的？输自己的密码（不是 root 的）；不想每次都输可配 NOPASSWD，但生产环境不建议
以为 sudo = susu 是"换成 root 身份干一会儿"；sudo 是"以 root 身份单独执行某条命令"，粒度完全不同

本章小结

问题答案
系统怎么认人UID/GID 数字编号；root=0、系统用户 1~999、普通用户 1000 起
账号信息存在哪/etc/passwd（账号资料）+ /etc/shadow（密码加密信息）
建用户/改用户/删用户useradd / usermod / userdel（-r 连家目录一起删）
密码怎么管passwd 设改锁；-l 锁定 -u 解锁 -S 查看状态
组怎么管groupadd / groupmod / groupdel；授权先找组
su 和 sudo 区别su 整体换成目标用户（要目标密码）；sudo 单条命令提权（要自己密码，权限写在 sudoers）
编辑 sudoers必须用 visudo，语法检查，别用 vi 硬改

一句话总结：Linux 用 UID/用户组给每个人发"身份证"，一条 useradd/passwd 就能开账号、锁定或删除；要临时当管理员，轻量用 su、可控用 sudo（visudo 管白名单）——身份管理搞明白，下一章才能谈"文件让谁碰"。
