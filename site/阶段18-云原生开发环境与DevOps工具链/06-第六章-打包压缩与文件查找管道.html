这一章在解决什么问题

上一章你会操作单个文件和目录了，但真实工作很快遇到三个新问题：① 目录里几十上百个文件，怎么"打包"成一份带走或备份？② 不知道文件放哪了、内容里想找一行关键词怎么办？③ 一个命令的输出想"喂"给下一个命令、报错想存到文件里怎么办？

学习提示

本章的"主角"不是单个命令，而是组合：tar 和 find 独立用，grep/wc/管道/重定向经常连在一起用。练习时多从"组合"角度想：查日志→过滤→统计，这三步就是一个真实排障小场景。

1① 为什么要打包压缩：成千上万的小文件没法"一份份传"
要解决什么

要把整个项目目录（几百个文件）发给别人或做备份——一个个文件拷？传 1000 个小文件慢到哭，还容易漏。

核心思路

Linux 的做法两步走：

  1. 打包（tar）：把目录里所有文件合成一个文件（.tar），方便传输和备份；
  2. 压缩（gzip/xz）：再把这个大文件压小（.tar.gz / .tar.xz），省空间省带宽。

关键认知：.tar.gz 不是一种神秘格式，而是"tar 打包 + gzip 压缩"两个动作的合称。tar 负责"合"，gzip 负责"缩"，两者各干各的。

app/ 里的 500 个文件
      │ tar 打包
      ▼
   app.tar（一个文件）
      │ gzip 压缩
      ▼
   app.tar.gz（更小）
坑在哪
现象原因 / 怎么办
以为 .tar.gz 和 .zip 是同一种东西机制不同：tar 只管打包，压缩靠 gzip；.zip 是"打包压缩一体"。两者都常见，别混
只拷走 .tar.gz 不带目录名，解压出来一堆散文件解压前先看包内容（第 ③ 点 -t 参数），确认里面有没有目录层
2② tar 打包压缩：-zcvf 四件套
要解决什么

把 /opt/app 整个目录打包成 app.tar.gz，命令怎么写？

核心思路

背下这个模板，一个字母都不要放错位置：

cd /opt && tar -zcvf ~/app.tar.gz app   # 先 cd 到父目录、用相对路径打包：包内顶层是 app/，不会触发「绝对路径」警告，包内变成 opt/app
选项含义
-ccreate，创建包
-vverbose，把正在处理的文件名打印出来
-z用 gzip 压缩（加不加决定是否 .gz）
-ffile，后跟打包出来的文件名

⚠️ -f 后面必须紧跟文件名，不能和其他选项堆成 -zcfv；位置本身不必在最后，这是 tar 最经典的语法约束，顺序反了必报错。

变体：不压缩只打包 tar -cvf app.tar /opt/app（去掉 -z 就是只打包、不压缩）。

坑在哪
现象原因 / 怎么办
"tar: -zcfv: 不知名的选项"选项顺序/组合写错；-f 一定要在最后且紧跟文件名
打包出来文件名叫 app.tar.gz 但其实是没压缩的忘了 -z；没 -z 就不会压缩，名字带 .gz 是骗自己的
打包整个系统（tar / 或 /etc）会把正在变化/锁定的文件打乱，还可能打包出权限问题；要备份指向明确目录
3③ tar 解压：-zxvf 与指定位置
要解决什么

拿到一个 .tar.gz，怎么解开？想解到指定目录呢？怎么在不解开的情况下偷看包里有啥？

核心思路 
tar -zxvf app.tar.gz           # 解压到当前目录
tar -zxvf app.tar.gz -C /opt   # -C：解压到指定目录
tar -ztvf app.tar.gz           # -t 只列内容不真正解压（先看包里有啥）
选项含义
-xextract，解包
-z先用 gzip 解压
-v显示过程
-f后跟包文件名
-C指定解压目标目录
-t查看包内文件列表，不动文件

解压前先 -t 看结构是好习惯：有的包自带一层目录（app/…），有的"裸奔"（一堆文件直接撒出来），先看能避免解出来一团乱。

坑在哪
现象原因 / 怎么办
解压后文件撒到当前目录到处都是包内本来就没有顶层目录；先 -t 看，再决定要不要先 mkdir 一个目录再解进去
解压覆盖了旧文件没有提示直接覆盖同名文件；解压到新目录或先备份
报 "gzip: stdin: not in gzip format"包其实不是 gzip 压缩的（可能是纯 .tar 或 .zip）；去掉 -z 再试，或用 file 命令看真实类型
4④ gzip / gunzip：单文件压缩
要解决什么

只有一个文件想压缩，也要走 tar 吗？——单文件直接用 gzip。

核心思路 
gzip note.log          # 压缩成 note.log.gz（原文件消失！）
gunzip note.log.gz     # 解压回 note.log
gzip -k note.log       # -k 保留原文件（新版本可用）
zcat note.log.gz       # 不解压直接查看内容

血的教训：gzip 压缩后会删除原文件，只剩 .gz。tar 内部调用的就是 gzip，所以 "tar -z" 全家桶和 gzip 是一家人。

坑在哪
现象原因 / 怎么办
gzip 完发现"原文件没了"这是 gzip 的默认行为：压缩后删除原文件；要保留用 -k 或先复制一份
gunzip 抢了 .gz 文件才想起来没备份再次强调：压缩前先想好原文件要不要留
5⑤ grep：在"文件内容"里捞关键词
要解决什么

日志有 10 万行，我想找所有带 "error" 的行——总不能一页页翻。

核心思路

grep 搜的是"内容"（和 find 搜文件名是两码事）：

grep "error" app.log         # 打印匹配的行
grep -i "error" app.log      # -i 忽略大小写（Error/ERROR 都能命中）
grep -n "error" app.log      # -n 带行号，好定位
grep -v "error" app.log      # -v 反选：打印【不包含】error 的行
grep -c "error" app.log      # -c 只数匹配几行
grep -r "error" /opt/app     # -r 递归搜整个目录
grep -E "error|fail" app.log # -E 支持正则 | 或关系

排障标准动作：grep -i error /var/log/messages | tail -n 20（先过滤再取尾）。

坑在哪
现象原因 / 怎么办
想搜目录却报错"是目录"grep 默认不递归目录；加 -r 或在文件上搜
grep 搜不到明明「肉眼可见」的词先看大小写（加 -i）；再看特殊字符：. 在任何模式下都是正则元字符、要写 \.；竖线 `\ 只有 -E`（egrep）下才是元字符，基本模式下是普通字符
grep 出来的"进程"里总有 grep 自己经典现象：`ps aux \grep xxx 会匹配到自己；排除技巧 grep -v grep`
6⑥ find：不知道文件在哪，按"名字"找
要解决什么

只记得文件名叫啥，忘了放哪个目录，怎么全盘找？

核心思路

find 搜的是"文件名"（和 grep 搜内容互补）：

find / -name "install.log"        # 在 / 下按名字找
find /opt -name "*.conf"          # 通配符：所有 .conf 文件
find / -name "vm*"                # 以 vm 开头的文件
find / -type f -name "*.log"      # -type f 只要文件（不要目录）
find / -type d -name "logs"       # -type d 只要目录

关键语法：find 起点路径 -条件。条件可以叠：find /data -name "*.log" -type f。

坑在哪
现象原因 / 怎么办
find / 全盘扫半天还报一堆权限错误全盘扫描慢+权限报错正常；尽量把起点缩小（/opt、/var、/home）
-name 没加引号，通配符被 shell 先展开了find -name *.log 的 * 会被 shell 先当匹配当前目录的文件；加引号 -name "*.log" 才是让 find 自己展开
找到了但是"Permission denied"打不开权限不够；sudo find 或切 root（这是权限问题不是搜索问题）
7⑦ find 进阶：按大小、时间、用户找
要解决什么

磁盘突然满了，想知道"哪个大文件占的？"；想过期日志，"7天前的老文件"在哪？

核心思路 
find /var -size +1G            # 大于 1G 的文件（+ 大于 - 小于）
find /var -size -10k           # 小于 10k 的文件
find /opt -mtime -7            # 7 天内修改过的（-7 = 7 天以内）
find /opt -mtime +30           # 30 天没动过的（+30 = 超过 30 天）
find / -user dev               # 属于用户 dev 的文件
find /tmp -type f -exec rm -f {} \;   # -exec：把找到的每个文件拿去执行命令

-exec 是"找到即处理"：{} 代表每一个匹配结果，\; 结尾。上面那句就是"删掉 /tmp 下所有文件"（演习谨慎）。

坑在哪
现象原因 / 怎么办
-size 单位写错（53M、1G 大小写）-size 的单位：k 小写，M/G 大写（写成 +1g 会被 find 拒绝）；-size +1g 小写 g 可能不被识别
-exec rm 直接把文件全删了-exec 执行是真删，先跑一遍不加 -exec 的 find 预览再补 -exec
-mtime -7 和 -mtime 7 分不清-7=7天以内；7=恰好第7天；+7=超过7天。带不带符号语义差很远
8⑧ wget：命令行下载
要解决什么

服务器上没有浏览器，要下载 JDK、Tomcat、repo 文件，怎么弄？

核心思路 
wget https://example.com/app.tar.gz       # 最基本的下载
wget -O my.tar.gz URL                      # -O 重命名保存
wget -P /opt URL                           # -P 下载到指定目录
wget -c URL                                # -c 断点续传（断了再来）
wget -b URL                                # -b 后台下载，看 wget-log 日志

服务器装软件全靠它：后面第 8 章的 yum 仓库、JDK 下载，第一步大多都是 wget。

坑在哪
现象原因 / 怎么办
wget 报证书错误/无法建立 SSL 连接https 证书链不全：yum install -y ca-certificates 补根证书
下载一半断了，重新下又要从头加 -c 续传
明明下了，当前目录找不到文件可能被 -P 指到别的目录，或用 -b 在后台（看当前目录的 wget-log）
9⑨ 管道符 |：让命令"接力"
要解决什么

"ps 输出一大堆进程，我只想看含 mysql 的"——一个命令做不到，怎么办？把两个命令接起来：前一个的输出，变成后一个的输入。

核心思路 
ps aux | grep mysql              # 进程列表 → 过滤出 mysql
cat /etc/passwd | wc -l          # 数一数系统有多少个用户
grep error app.log | tail -n 20  # 过滤日志 → 只看最后 20 行
ls /etc | less                   # 目录内容太多 → 分页翻着看

方向记牢：管道左边"产出数据"，右边"消费数据"，数据流是左→右。

一个经典例子（数禁登录用户数）：

grep "/sbin/nologin" /etc/passwd | wc -l

一条命令完成"找出所有不能登录的账号 → 数出数量"。

坑在哪
现象原因 / 怎么办
管道方向写反（tail \grep）语法没错但逻辑反了；想清楚谁是源头、谁做后处理
管道后面接的不是"能吃输入的命令"有些命令（如 rm 的部分参数）不读标准输入，管道就白搭；要处理文件路径改用 find -exec 或 xargs
10⑩ 重定向：> >> 2> 2>&1
要解决什么

命令的结果想存进文件而不是打印在屏幕；报错信息想单独留档；日志想追加而不是覆盖。这些是"重定向"的活。

核心思路

Linux 三种标准通道：0=标准输入(stdin)、1=标准输出(stdout)、2=标准错误(stderr)。

echo "hello" > note.txt       # > 覆盖写：note.txt 内容 = hello
echo "again" >> note.txt      # >> 追加写：在原内容后面加一行
ls /a 2> err.log              # 2>：只把【错误信息】写进 err.log
ls /a > all.log 2>&1          # 2>&1：错误也合并进 all.log（最常用）

对照表：

符号含义
>标准输出覆盖写（破坏性！）
>>标准输出追加写
2>标准错误覆盖写
2>&1把标准错误并入标准输出（一起进文件）
<从文件读入（反向，用得少）

经典场景：crontab 定时任务里 命令 >> backup.log 2>&1——正确输出和报错都留档。

坑在哪
现象原因 / 怎么办
命令报错了，但 > 的文件里是空的报错走 stderr，> 只接管 stdout；要一起收就 2>&1 或单独 2>
用 > 存脚本输出，发现覆盖了昨天的覆盖是破坏性的；要保留历史用 >> 追加
以为 > 是"另存一份"它是把本该上屏的内容重定向了，屏幕就什么都不打印了——别在等输出
11⑪ 通配符：* ? [ ]
要解决什么

只记得文件开头几个字，或者想一次匹配很多相似文件（全部 .log），一个个敲名字太蠢了。

核心思路

Shell 提供"模糊匹配"符号：

符号含义例子
*任意多个任意字符ls *.log 所有 .log；ls vm* 所有 vm 开头
?恰好 1 个任意字符ls sda? 匹配 sda1/sda2/sda3…不匹配 sda10
[0-9]集合内任意一个ls sda[0-9] 匹配 sda 后跟一位数字
[abc]a/b/c 之一ls f[abc].txt

注意 * 和 ? 的差别：/dev/sda* 会把 sda9、sda10 都算上；/dev/sda? 只匹配一位数字（sda10 不匹配）。磁盘多分区场景这个坑很常见。

坑在哪
现象原因 / 怎么办
ls sda? 少了 sda10? 只代表 1 个字符；要"任意位"用 *
find 里用通配符没效果find 的 -name 自己处理通配符，但 shell 可能先展开了它；加引号 -name "sda*" 让 find 自己管
rm *.log 误删了不该删的通配符壳展开后再删，没有任何确认；删除前先 ls *.log 看将要删什么

本章小结

问题答案
打包压缩tar -zcvf 打（-c）缩（-z）成 .tar.gz；-f 永远最后、紧跟文件名
解压tar -zxvf；-C 指定位置；-t 先看内容再解
单文件压缩gzip（会删原文件）/ gunzip 还原
搜内容 vs 搜名字grep 搜内容（-i 忽略大小写、-v 反选、-r 递归）；find 搜名字/大小/时间/-exec
下载wget，-O 改名、-P 目录、-c 断点续传
管道A \B：A 的输出变成 B 的输入，左产右消
重定向> 覆盖、>> 追加、2> 错误、2>&1 合并
通配符* 任意多位、? 1 位、[0-9] 集合；find 里记得加引号

一句话总结：把目录打包成 tar.gz 带走或备份，用 find 按名字/大小/时间从磁盘里捞出目标文件，用 grep 在内容里过滤目标行，再用管道（|）和重定向（> >> 2>&1）把命令串成一条流水线——单条命令做不成的事，组合起来就能做。
