第五章　目录与文件操作命令

阶段 18 · 云原生开发环境与 DevOps 工具链　|　Linux 基础　|　难度 ★★★
这一章在解决什么问题

前四章你装了系统、配了网络、建了账号、看懂了权限——现在终于到"天天要用的操作"了：看文件、建目录、复制、移动、删除、查看日志。这些命令（cd、ls、mkdir、cp、mv、rm、cat、tail、vim…）你马上会在后面每一章、以及以后每一天的工作里反复敲。

很多同学在这一步的命令都"背过"，但真上手就露馅：cp 复制目录忘了 -r 报错；rm 把不该删的删了找不回来；tail 看日志忘了 -f 说"不更新"；vim 进去了退不出来。这一章把这些命令的日常用法 + 高频坑一次讲清，讲完你就能流畅地在 Linux 里"逛街"了。

这一章在整个知识库里的位置 上一章：文件类型与权限管理——能看懂文件了 本章 ← 你在这里：动手操作文件和目录（导航、增删、查看、编辑） 下一章：打包压缩与文件查找管道——文件多了，学打包备份、查找过滤、管道重定向 阶段终点：云原生开发环境与 DevOps 工具链，文件操作是运维最底层的肌肉记忆
学习提示

本章命令密度大，但互相独立，适合"边敲边记"。建议把虚拟机开着，每讲一个命令就在 /tmp 下建个练习目录敲一遍——命令这玩意儿，看 10 遍不如敲 3 遍。vim 一节单独多给点时间。

1① 路径：绝对路径 vs 相对路径，还有 . .. ~
要解决什么

/usr/local/bin 和 ../local/bin 都是"找地方"，到底啥区别？什么时候用哪个？

核心思路
  • 绝对路径：以 / 开头，从根一路指过去，任何时候、任何菜鸟看，指的都是同一个地方；
  • 相对路径：以当前所在位置为起点，. 表示当前目录，.. 表示上一级目录，~ 表示当前用户的家目录。

举例（当前在 /var/log 时）：

写法类型实际指
/etc/hosts绝对根下的 etc/hosts
../etc/hosts相对先回 /var，再进 etc → 还是同一个文件
./syslog相对当前目录下的 syslog
~/note.txt相对当前用户家目录下的 note.txt

选择原则：脚本/配置文件里一律用绝对路径（不依赖"当时在哪"），手敲时哪种短用哪种。

坑在哪
现象原因 / 怎么办
写路径总报 "No such file or directory"多半漏了开头的 /：etc/hosts 会去当前目录找 etc，而不是根下的 /etc
在别的地方敲 ./install.sh 报找不到文件./ 是"当前目录"的 install.sh；文件不在当前目录就得写全路径或用 cd 过去
2② 目录约定：学会"猜"文件在哪
要解决什么

Linux 下的文件分散得到处都是，全靠记？不用——目录本身有约定，学会这层就能猜。

核心思路

发行版都遵守同一套"文件系统标准"，记住几个高频位置，找文件基本靠猜：

要找什么去哪个目录
系统命令/bin、/usr/bin、/sbin
配置文件/etc（如 /etc/hosts、/etc/sysconfig）
日志/var/log（如 /var/log/messages）
用户家目录/home/用户名、/root
第三方软件/opt、/usr/local
临时文件/tmp
设备/dev

以后的坑几乎都源于这几个路径：日志在 /var/log 不在 /log，配置在 /etc 不在 /config——先猜对位置，再谈操作。

坑在哪
现象原因 / 怎么办
按"常见习惯"去 /log、/config 找，找不到Linux 的约定是 /var/log、/etc；正视习惯差异，别硬找
在 /var/log 乱删"不认识的日志"日志是排障命根子；不确定先 tail 看内容，别删
3③ pwd 与 ls：我在哪？这里有什么？
要解决什么

一上服务器就迷路：现在在哪个目录？这里面都有啥？

核心思路

两个命令解决"迷路问题"：

pwd              # print working directory：打印当前目录
ls               # 列出当前目录内容
ls -a            # -a 包括隐藏文件（. 开头的文件）
ls -l            # -l 长格式（权限/属主/大小/时间）
ls -h            # -h 大小换成人性化单位（K/M/G，常和 -l 连用）
ls -d /etc       # -d 只看目录本身，不列里面的内容
ls /opt          # 指定目录，不一定非要在那个目录里

注意：隐藏文件用 ls 默认看不到（名字以 . 开头），用 ls -a 才显示。比如 ~/.bashrc 配置就在"看不见"的地方。

坑在哪
现象原因 / 怎么办
明明有 .bashrc 却 ls 看不到隐藏文件要用 ls -a；这是特性不是丢了
ls -l 后文件大小显示一大串数字看不懂加 -h：ls -lh 变成 2.3K、45M 这种
4④ mkdir 与 rmdir：建目录、删空目录
要解决什么

要给项目建一层层目录，删的时候又想连空目录一起收拾掉。

核心思路 
mkdir note                # 建一个目录
mkdir -p a/b/c            # -p 一次性递归创建多层目录
mkdir -m 711 note         # -m 建目录时直接指定权限
rmdir note                # 删除【空】目录
rmdir -p a/b/c            # 从里到外删掉一层层空目录

关键词：rmdir 只能删空目录，目录里有东西它会报 Directory not empty。

坑在哪
现象原因 / 怎么办
rmdir 报 "Directory not empty"这是保护不是 bug；目录不为空时用 rm -r（见下一点），别硬删
mkdir a/b/c 报"没有那个文件或目录"没加 -p 时父目录 b 不存在会失败；要一次建多层就 mkdir -p
5⑤ rm：高危命令，没有后悔药
要解决什么

要删文件、删目录。但 Linux 没有回收站，删了就是真没了——怎么安全地用 rm？

核心思路 
rm note.txt          # 删文件（默认会询问？不，默认直接删，别心存幻想）
rm -i note.txt       # -i 逐个确认再删（安全习惯）
rm -f note.txt       # -f 强制，不询问不报错
rm -r dir            # -r 递归删目录（目录和里面所有内容）
rm -rf dir           # 递归+强制：最狠的组合，慎用

血泪经验：

  • rm 不可逆：没有回收站，删完用 extundelete 之类也未必能救回；
  • 经典事故：rm -rf /（多打了空格或少打了目标）可能把系统都删了；
  • 生产环境三连：先 ls 把路径看对 → 用 -i 确认 → 再回车。
坑在哪
现象原因 / 怎么办
删文件时它根本不问直接没了默认就是不问，-i 才会逐个确认；养成本能加 -i
rm -rf /var/log （结尾多一个空格）变成删多了一个参数空格分隔参数，多空格可能让路径变成"多个对象"；手别抖，先 ls 预览
搜到"删不掉，加 -f"的帖子就无脑 -f-f 是"不报错"，不是"恢复"；权限不够先看属主/chattr，别用 -f 掩盖问题
rm -rf 一个正在使用的目录进程还在读写，行为不可预期；先停进程再删
6⑥ cp：复制文件与目录
要解决什么

要备份配置、复制模板，把一个文件/目录变成两份。

核心思路 
cp note.txt /opt/              # 复制到目录（保留名字）
cp note.txt note.bak           # 复制并改名
cp -r app /opt/app.bak         # -r 递归复制整个目录
cp -i note.txt /opt/           # -i 目标已存在时先询问
cp -p note.txt /opt/           # -p 保留属性（时间、权限等），备份常用

记住：复制目录必须加 -r（recursive），否则报 omitting directory。

坑在哪
现象原因 / 怎么办
cp 目录报 "omitting directory"忘加 -r；目录复制必须 cp -r
复制大文件/跨盘复制半天同盘 cp 快、跨文件系统/网络盘慢；提前选对路径
cp 覆盖了重要文件没提示默认直接覆盖；加 -i 让它问你，或先确认目标不存在
7⑦ mv：移动与改名
要解决什么

文件想挪个位置，或者想改个名——注意：改名的本质也是 mv。

核心思路 
mv note.txt /opt/          # 移动到目录
mv note.txt rename.txt     # 改名（目标不存在 = 改名）
mv app /opt/app            # 目录也可以整目录移动
mv -i note.txt /opt/       # -i 目标存在时询问

规律一句话：mv 到"不存在的名字"= 改名；mv 到"已存在的目录"= 移动进去。同文件系统内 mv 只是改目录项，瞬间完成，比"复制+删除"省太多。

坑在哪
现象原因 / 怎么办
以为 mv 改名和移动是两种命令其实是同一个操作：把"名字"从一处挪到另一处
跨文件系统 mv 大文件卡半天跨盘 mv = 复制+删除；要快就把源和目标放同盘
mv 覆盖了同名文件默认直接覆盖，重要文件用 mv -i
8⑧ cat / tac / nl：一口气看完整个文件
要解决什么

配置文件不长，想看全部内容，用哪个命令？

核心思路 
cat /etc/hosts        # 从头显示全部
tac /etc/hosts        # 从尾到头显示（cat 倒着写，中文按行反序）
nl /etc/hosts         # 带行号显示（number line）
cat -A file           # -A 显示隐藏字符（调试换行/空格），进阶用

适合小文件：几十上百行以内直接 cat。cat 不只"看"，还能拼接文件、和重定向配合（见第六章）：cat a.txt b.txt > c.txt。

坑在哪
现象原因 / 怎么办
cat 一个大日志，终端黑压压刷到怀疑人生大文件别用 cat，用 less（下一点）分页看
cat 文件末尾看不到（被刷走）内容超过一屏 cat 一次性全输出；要看最后几行用 tail
9⑨ more / less：大文件分页看
要解决什么

几百上千行的日志和配置，cat 会刷屏，怎么一页一页翻？

核心思路 
more /var/log/messages     # 空格翻页，q 退出，只能往下翻
less /var/log/messages     # 升级版：↑↓ 翻行、空格翻页、q 退出
less +G /var/log/messages  # 直接从文件末尾开始看（看新日志好用）

less 比 more 强在哪：

  • 支持方向键上下翻，more 只能往下空格；
  • 按 /关键词 搜索，按 n 跳到下一个匹配；
  • less -N 显示行号。

口诀：less is more（既能多又能少，功能全面超越 more）。

坑在哪
现象原因 / 怎么办
进入 less 后按什么都没反应可能误进入搜索模式按了 /；按 Esc 退出搜索，再按 q 退出
more 想往回翻翻不了more 不支持回翻，换 less
退出时按了很久还是没退出按 q 退出分页器，别用 Ctrl+C 硬掐（也能退但可能残留状态）
10⑩ head / tail：只看头尾，日志利器
要解决什么

只想看配置文件开头几行，或日志最后几十行——更常见的是实时盯着日志。

核心思路 
head -n 10 /etc/passwd      # 前 10 行（默认前 10）
tail -n 20 /var/log/messages # 后 20 行
tail -f /var/log/messages    # -f 持续跟踪：新日志一产生就滚出来（按 Ctrl+C 停）
tail -f -n 50 app.log        # 从末尾 50 行开始实时跟踪

排障标配：tail -f 日志 + 另一边操作复现问题，一边滚一边看。

坑在哪
现象原因 / 怎么办
tail 之后屏幕不再更新没加 -f；实时跟踪必须带 -f
tail -f 停不下来这是"一直等着看"的行为；按 Ctrl+C 退出，不是 Ctrl+Z
想看"日志最后有多少行"却数错wc -l（见下一点）更可靠，别数屏
11⑪ wc：统计行数、字数、字节
要解决什么

"这个文件一共多少行？""这段日志多少字？"

核心思路 
wc /etc/passwd               # 行数 字数 字节数
wc -l /etc/passwd            # 只看行数（最常用）
wc -w note.txt               # 只看字数
wc -c note.txt               # 只看字节数

和管道组合威力巨大（第六章详讲）：cat app.log | wc -l 数一数今天日志有几行。

坑在哪
现象原因 / 怎么办
wc -l 数出来的行数和"眼睛看到的行数"不一样超长行在终端上自动换行显示，wc 按逻辑行（换行符）统计；正常现象
想数目录里有多少文件，wc -l 目录 报错wc 不认目录；先 `ls -l 目录wc -l` 数行
12⑫ vi/vim：Linux 上躲不开的编辑器
要解决什么

服务器上往往没有图形界面，改个配置全靠 vim（vi 的增强版）。它没菜单、没鼠标，第一眼是劝退的——但掌握后效率极高。

核心思路

先把三种模式搞懂，其余都是字面功夫：

命令模式（默认）── i/a/o ──→ 输入模式
   │                          │
   └─────── Esc ←─────────────┘
   │
   输入 : 进入末行模式（:wq 保存退出）
模式能干什么怎么进
命令模式移动光标、删行、复制、搜索启动 vim 就是它
输入模式敲字改内容按 i（光标前插入）a（后插）o（换行插入）
末行模式保存/退出/查找替换/设行号命令模式下按 :

必背命令清单（命令模式下直接按）：

dd            # 删除当前行
yy            # 复制当前行
p             # 粘贴到下一行
u             # 撤销上一步
/关键词        # 向下搜索，n 跳下一个
G             # 跳文件末尾，gg 跳文件开头
:vsp 文件      # 垂直分屏（进阶）

保存退出组合（末行模式）：

:wq        # 保存并退出（写盘 + 退出）
:w         # 只保存
:q         # 没改过就退出
:q!        # 不保存强制退出（改坏了不想要了）
:set nu    # 显示行号

新手保命口诀：想退出？先按 Esc 回到命令模式，再 :q! 或 :wq。

坑在哪
现象原因 / 怎么办
进去后乱按，怎么都退不出按 Esc 回命令模式 → 输 :q! 回车。记住：先在键盘上找 Esc
改了半天配置，:q 退出去，白改了要保存就 :wq；只 :q 会因"有未保存修改"被拒或直接丢弃
按 Ctrl+S 屏幕卡死像死机vim 里 Ctrl+S 是 XON/XOFF 流控，会冻结终端；按 Ctrl+Q 恢复
光标动不了/按字母不打字说明还在命令模式；按 i 进入输入模式才能打字
搜索后想跳到下一个命令模式按 n 跳下一个匹配；N 跳上一个

本章小结

问题答案
绝对/相对路径绝对以 / 开头永远一样；相对依赖当前位置；. 当前、.. 上级、~ 家目录
在哪/有什么pwd 看位置，ls(-a 隐藏/-l 详情/-h 大小) 看内容
建/删目录mkdir(-p 递归)；rmdir 只能删空目录，非空用 rm -r
rm 为什么危险Linux 无回收站、默认不询问；先 ls 再 rm，重要操作用 -i
复制/移动cp 目录要 -r；mv 改名/移动一体，目标不存在=改名
查看文件小文件 cat；大文件 less；只头尾 head/tail；实时日志 tail -f；统计 wc -l
vim 三模式命令/输入/末行；i 进入输入，Esc 回命令，:wq 保存退出，:q! 放弃退出

一句话总结：先从 pwd/ls 搞清楚"我在哪、有什么"，再用 mkdir/cp/mv/rm 增删挪移（rm 永远先 ls 再下手），用 cat/less/tail 按需看文件（看日志认准 tail -f），最后掌握 vim 的命令/输入/末行三模式——这套组合拳就是你以后在服务器上的日常。
