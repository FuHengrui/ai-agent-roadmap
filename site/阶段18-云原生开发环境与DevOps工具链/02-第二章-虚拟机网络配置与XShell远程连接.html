第二章　虚拟机网络配置与 XShell 远程连接

阶段 18 · 云原生开发环境与 DevOps 工具链　|　Linux 基础　|　难度 ★★★
这一章在解决什么问题

上一章装好的 CentOS 还"困"在虚拟机窗口里，复制粘贴都别扭——而真实的服务器都在机房里，你根本摸不到它。所以运维和开发的第一步，都是从自己的电脑远程连到服务器上操作。

但远程连接有个前提：虚拟机的网络得配对。很多同学就卡在这一步：要么虚拟机连不上网，要么主机 ping 不通虚拟机，XShell 连了半天全是 timeout。这一章先把三种网络模式讲明白（NAT / 桥接 / 仅主机），再一步步把 IP 配成固定的，最后用 XShell 连上去。配完这一章，你才真正开始"用"你的 Linux。

这一章在整个知识库里的位置 上一章：Linux 概述与版本安装——你有了一台虚拟机里的 CentOS 本章 ← 你在这里：让这台虚拟机"能上网、IP 固定、能被远程连上" 下一章：用户与用户组管理——连上去之后，第一件事是搞清谁能用这台机器 阶段终点：云原生开发环境与 DevOps 工具链，远程运维是一切操作的基础
学习提示

本章是纯操作章，没有复杂代码，建议"边看边点"：开着一个虚拟机窗口跟着步骤走，卡在哪一步就回看哪一步。网卡配置配乱了很正常，把网络设置初始化再配一次就行，不会伤到系统。

1① 为什么要远程连接：服务器不坐在你面前
要解决什么

虚拟机窗口里也能敲命令，为什么还要费劲配网络、装 XShell？直接在窗口里用不就行了？

核心思路

现实里的服务器长这样：一台没有屏幕、没有鼠标的主机，躺在机房里，只能通过网络"连"上去操作。所以：

  • SSH 服务：Linux 上默认开启的远程登录服务，监听 22 端口，验证通过就给你一个远程命令行；
  • XShell：Windows 上的 SSH 客户端，填上服务器 IP、账号、密码，回车就进入那个命令行；
  • 一旦学会这一招，你连的是虚拟机、云服务器、树莓派，操作方式完全一样。

所以本章配网络的目标非常具体：让 XShell 能从这台 Windows 连上虚拟机里的 Linux。

坑在哪
现象原因 / 怎么办
XShell 双击连接没反应先别怀疑 XShell——网络没通时连接只会无限 timeout；先做第 ⑨ 点的 ping 排查
以为远程登录 = 远程桌面SSH 是纯命令行通道，比图形远程轻得多，也是服务器运维的主流方式
2② 三种网络模式总览：NAT / 桥接 / 仅主机
要解决什么

虚拟机软件给了一张"网卡选择页"，三种模式选错就上不了网、或者外面连不进来。它们到底差在哪？

核心思路

把三台设备记清楚：A=你的 Windows 主机，A1/A2=虚拟机，B=外网的机器（比如同事电脑）：

模式虚拟机能否上外网外面能否访问虚拟机和主机互通对应虚拟网卡
NAT✅ 能❌ 不能✅ 能VMnet8
桥接✅ 能✅ 能✅ 能物理网卡
仅主机❌ 不能❌ 不能✅ 能VMnet1

记忆口诀：桥接 = 虚拟机和真实电脑平起平坐；NAT = 虚拟机躲在主机后面出门；仅主机 = 虚拟机闭关，只认主机。

      桥接                     NAT                   仅主机
  ┌──────────┐           ┌──────────┐          ┌──────────┐
  │ A  A1 A2 │ ←→ B      │ A  A1 A2 │          │ A  A1 A2 │
  │  各自独立IP│            │  └─ 出网全靠A  │        │  └─ 只和A互通 │
  └──────────┘           │ B 看不到  │          │ B 看不到  │
                         └──────────┘          └──────────┘
坑在哪
现象原因 / 怎么办
三种模式的名字和效果对不上用两把尺子衡量：能不能出网 + 外面能不能进来，一组合就清楚了
以为 NAT 下虚拟机没有"网络身份"NAT 下虚拟机同样有 IP，只是这个 IP 是 VMware 私网里的，外面的设备不认识
3③ 桥接模式：虚拟机直接"插"进你的局域网
要解决什么

同事要访问我虚拟机里跑的 MySQL，该用哪种模式？

核心思路

桥接 = 在物理网卡和虚拟网卡之间架一座桥，虚拟机的网卡直接接到你家的路由器（或公司局域网）里：

  • 虚拟机拥有局域网内的一个真实 IP，和你的主机、同事的电脑同网段；
  • 所以：A ↔ A1/A2 互通，A1/A2 ↔ B 也互通——外面可以直接访问虚拟机；
  • 代价：局域网要"愿意"给 IP。IP 资源紧张、或对 IP 管理严格的网络（如公司办公网），桥接可能拿不到地址。

一句话：想让别人访问你的虚拟机 → 桥接；自己学习用 → 一般用不上。

坑在哪
现象原因 / 怎么办
桥接模式下虚拟机拿不到 IP / 时通时断办公网 DHCP 绑定了 MAC 或 IP 紧张；换 NAT 模式最省事
桥接后虚拟机的 IP 和公司网段冲突换 IP 或换模式；公司网络下别乱占用地址
4④ NAT 模式：能出网、外人进不来（学习首选）
要解决什么

学习阶段只想要两件事：虚拟机里能 yum 装软件（要出网），主机能连上虚拟机（要互通）。外面谁也别想进来。怎么配？

核心思路

NAT（网络地址转换）= VMware 的虚拟网络服务扮演一台路由器：

  • 虚拟机的流量先到 VMware 的"虚拟路由器"，再由它转成主机的流量出外网；
  • 外部网络看到的都是"主机的 IP"，看不到虚拟机，天然安全；
  • 主机 ↔ 虚拟机互通走的是 VMnet8 这张虚拟网卡——注意：VMnet8 网卡的作用就是让主机和虚拟机互相通信，别把它当成"接外网的卡"。
 VMs(A1/A2) ──┐
              ├── VMnet8 ── VMware NAT 路由 ── 主机物理网卡 ── 互联网
 主机(A) ─────┘

学习、练手阶段，NAT 基本是唯一需要记牢的模式。

坑在哪
现象原因 / 怎么办
以为 NAT 模式下虚拟机"和主机没什么联系"NAT 能出外网且能和主机互通，只是外部连不进来
外网同事想访问你 NAT 虚拟机里的 MySQL，连不上正常！NAT 默认不允许外部进入；对外开放要做端口映射（进阶内容，学习阶段不需要）
5⑤ 仅主机模式：闭关修炼
要解决什么

有没有一种模式：只让虚拟机和主机互相访问，彻底不碰外网？

核心思路

仅主机（Host-only）模式，对应的虚拟网卡是 VMnet1：

  • 虚拟机和主机在同一私网，互相能通；
  • 虚拟机不能访问外网，外网更进不来；
  • 用途：隔离环境练实验、不让虚拟机联网乱下载、调试只涉及主机的网络问题。

结论（直接记）：NAT 和仅主机都不占用局域网 IP、都只能和本机互通；唯一区别是 NAT 能出外网，仅主机完全不能。所以三道网络模式里"最安全"的是仅主机模式。

坑在哪
现象原因 / 怎么办
虚拟机配成仅主机后 yum install 报网络错误这不是故障，是模式特性——仅主机根本没有出网通道
选择题问"哪种网络模式最安全"答案通常选仅主机（NAT 虽然外人进不来，但至少能出网，语义上不如仅主机封闭）
6⑥ 规划网段和网关：先定好"门牌号"
要解决什么

配置之前脑子要有一张表：网关多少？虚拟机多少？主机多少？不先规划，后面填 IP 全靠猜。

核心思路

本教程的统一规划如下（照抄即可）：

角色IP
NAT 网关（VMware 虚拟路由）192.168.66.1
主机上的 VMnet8 网卡192.168.66.10
虚拟机 CentOS192.168.66.100

操作路径（VMware Workstation）：编辑 → 虚拟网络编辑器 → 选中 VMnet8 → 修改子网 IP 为 192.168.66.0 / 掩码 255.255.255.0 → NAT 设置 → 网关填 192.168.66.1。

编辑器里入口乱、按钮是灰的？八成是没点"更改设置"要管理员授权。

坑在哪
现象原因 / 怎么办
"更改设置"按钮是灰的 / 点了没反应需要管理员权限：点"更改设置"后确认 UAC 弹窗（系统要你同意），才能编辑子网和 NAT
网关 IP 填了别的网段网关必须和子网同网段（都在 192.168.66.x），后面主机、虚拟机的 IP 也要同网段，否则互相找不到
7⑦ 配置主机的 VMnet8 网卡：主机这条"腿"也要固定
要解决什么

主机和虚拟机要互相通信，主机这一端也得有固定地址，不能 DHCP 乱变。

核心思路

Windows 这边要给 VMware 虚拟网卡设静态 IP，路径（Win10/11）：控制面板 → 网络和 Internet → 网络和共享中心 → 更改适配器设置 → 找到 "VMware Network Adapter VMnet8" → 右键属性 → 双击 "Internet 协议版本 4 (TCP/IPv4)"：

字段填什么
IP 地址192.168.66.10
子网掩码255.255.255.0
默认网关192.168.66.1

改完在 Windows 的 cmd 里敲 ipconfig，能看到 VMnet8 的 IP 变成 192.168.66.10，这步就成功了。

坑在哪
现象原因 / 怎么办
改错网卡，把 WiFi/以太网搞没了只改 VMnet8，别碰你的物理网卡；认准名字里带 "VMware" 的那一张
主机上根本找不到 VMnet8装 VMware 时虚拟网卡没装上或被杀毒/优化软件禁用；在虚拟网络编辑器里"还原默认设置"重建
填完 IP 提示"和别的适配器冲突"说明 192.168.66.10 已被占（比如虚拟机多开）；调整成 192.168.66.11 之类的相邻地址即可，虚拟机端的网关/.100 不受影响
8⑧ 编辑虚拟机的网卡文件：改成静态 IP
要解决什么

虚拟机默认 DHCP 自动拿 IP，重启后可能变。而 XShell 只认 IP——IP 变了就连不上了。所以要改成静态 IP。

核心思路

Linux 网卡配置住在 /etc/sysconfig/network-scripts/，文件名 ifcfg-网卡名（常见 ens33）。用 vim 打开它：

vim /etc/sysconfig/network-scripts/ifcfg-ens33

修改/新增这几行：

BOOTPROTO=static        # 原来是 dhcp，改成 static 用静态 IP
ONBOOT=yes              # 开机自动激活网卡（原来是 no 必改）
IPADDR=192.168.66.100   # 本机 IP
NETMASK=255.255.255.0   # 子网掩码
GATEWAY=192.168.66.1    # 网关，指向 VMware NAT 网关
DNS1=223.5.5.5          # 首选 DNS（阿里公共 DNS）
DNS2=223.6.6.6          # 备用 DNS

不会 vim 的照着做三步：① 打开后按 i 进入输入模式（左下角出现 -- INSERT --）；② 改完按 Esc 回到命令模式；③ 输入 :wq 回车 → 保存并退出。

最后重启网卡让配置生效，再确认 IP：

service network restart    # 或 systemctl restart network
ip addr                    # 网卡应显示 192.168.66.100
坑在哪
现象原因 / 怎么办
改了文件但不生效没重启网卡；改完记得 service network restart
找不到 ifcfg-ens33，文件名是 ifcfg-eth0网卡名因环境而异（ens33/eth0/ens160…）；先 ls /etc/sysconfig/network-scripts/ 看真实文件名
在 vim 里乱按一番退不出去按 Esc → 输入 :q! 回车（不保存强退）；要保存就 :wq
只加了 IPADDR，忘了把 BOOTPROTO 改 static不改成 static，IP 会被 DHCP 覆盖，白配
9⑨ 验证网络：ping 三连定位
要解决什么

配置完了，怎么确认真的通了？总不能直接盲试 XShell。

核心思路

按顺序 ping，哪一步断就在哪一步查：

ip addr                 # ① 先确认自己有 IP：应显示 192.168.66.100
ping -c 4 192.168.66.1  # ② 通 = 和 VMware 网关通了（NAT 链路 OK）
ping -c 4 223.5.5.5     # ③ 通 = 能出外网
ping -c 4 baidu.com     # ④ 通 = DNS 解析也 OK

判断技巧：能 ping 通 223.5.5.5 但 ping 不通域名 → DNS 没配好，回去查 ifcfg 里的 DNS1/DNS2。

主机这边也验证一下：在 Windows cmd 里 ping 192.168.66.100，能通就说明主机 → 虚拟机方向 OK，XShell 的前提已具备。

坑在哪
现象原因 / 怎么办
虚拟机 ping 网关通、ping 外网不通NAT 服务没起来或 Windows 防火墙拦了转发；检查 VMware NAT Service 是否运行
主机 ping 不通虚拟机，但虚拟机里 IP 明明是对的Windows 防火墙默认拦 ping（ICMP）；先 ping 网关定位，再临时关防火墙测试
一直"请求超时"而不是"找不到主机"超时 = 路由通不通（链路层问题）；"找不到主机" = DNS 问题，两个排障方向完全不同
三种网络模式来回换，IP 混乱改模式后主机 ↔ 虚拟机两端 IP 都要重新对应；建议固定用 NAT + 上面这套规划，别来回切
10⑩ XShell 远程连接：第一次"摸"到服务器
要解决什么

网络都通了，怎么从 Windows 端"坐进"那台 Linux？

核心思路

XShell 是 Windows 上常用的 SSH 客户端（同类还有 MobaXterm、FinalShell），用法就三步：

  1. 打开 XShell → 新建会话；
  2. 填写：
  • 名称：随便（如"我的 CentOS"）
  • 主机：192.168.66.100
  • 端口号：22（SSH 默认端口）
  • 协议：SSH
  1. 双击会话 → 第一次连接会问是否接受主机密钥指纹，接受 → 输入用户名（root）和密码 → 回车。

看到 [root@node01 ~]# 就成功了。之后的操作体验和虚拟机窗口完全一致，但复制粘贴、开多会话管理多台机器都方便太多。

坑在哪
现象原因 / 怎么办
报 "Connection refused"（拒绝连接）SSH 服务没启动/没装：虚拟机上 systemctl start sshd 并 systemctl enable sshd
报 "timeout"（超时）网络没通，回头做第 ⑨ 点的 ping 三连
第一次弹出"接受指纹"以为是病毒这是 SSH 防中间人攻击的机制：确认是"自己的服务器"就接受
root 远程登录被拒绝检查 /etc/ssh/sshd_config 的 PermitRootLogin 是否 yes，改完重启 sshd

本章小结

问题答案
三种网络模式怎么选NAT 能出网外人进不来（学习首选）；桥接和局域网平起平坐（同事要访问时用）；仅主机只和主机通（最安全）
VMnet8 是干嘛的主机和虚拟机互通的那条"虚拟网线"，NAT 模式下必配
静态 IP 在哪配虚拟机 /etc/sysconfig/network-scripts/ifcfg-网卡名，改 BOOTPROTO/ONBOOT/IPADDR/GATEWAY/DNS
改完必须做什么重启网卡 service network restart，否则不生效
怎么验证ping 网关 → ping 外网 IP → ping 域名，逐层定位
XShell 连不上怎么查先 ping：超时=网络，refused=SSH 服务，别乱猜

一句话总结：给虚拟机配 NAT + 静态 IP（网关 .1、主机 .10、虚拟机 .100），把主机和虚拟机两端的"门牌号"都定死，再用 XShell 走 SSH（22 端口）连上 192.168.66.100——从此操作 Linux 就像在操作一台真正的远程服务器。
