学习提示

本章约一半是概念、一半是安装操作。概念部分听个明白就行，不用背；安装部分建议边看边点，亲手装一台自己的练习机。装坏了也没关系——虚拟机随时可以重来，这恰恰是它最大的优点。

1① Linux 是什么：一个学生写出来的操作系统
要解决什么

你天天听说"Linux"，但它到底是个啥？和你电脑里的 Windows 是一回事吗？不搞懂这个，后面所有命令都是在背单词而不是学系统。

核心思路

1991 年，芬兰赫尔辛基大学的学生林纳斯·托瓦兹为了自己玩，写了一个操作系统内核，并放到网上免费分享。结果全球的程序员都来帮他改，越改越强——这就是 Linux 的开始。

两个时间点别记混：

  • 1991 年：Linux 诞生（托瓦兹开始动手写）
  • 1994 年：内核 1.0 正式发布（别被网上老题目的答案带偏，1.0 不是 1991）

所谓"内核"，通俗讲就是操作系统的"发动机"：管 CPU、管内存、管磁盘、管网络这些最核心的活儿。Linux 是内核的名字，我们平时用的 CentOS、Ubuntu 都是"内核 + 一堆软件"组成的整装车（见第 ③ 点）。

坑在哪
现象原因 / 怎么办
测验/网上的题选"内核 1.0 是 1991 年"1991 是诞生年份，内核 1.0 正式发布是 1994 年，两个数字对应两件事
以为 Linux 是某家公司做的产品它是全世界开发者共同维护的开源项目，没有"Linux 公司"，这才是它能长盛不衰的根本
2② Linux 两大特点：免费 + 自由
要解决什么

免费的系统和软件多了去了，为什么偏偏 Linux 能统治服务器？"免费"只是表象。

核心思路

Linux 作为自由软件，有两个真正要命的特点：

  1. 免费提供源代码——你不用付一分钱就能拿到全部代码；
  2. 允许自由修改、复制、分发——任何人觉得哪里不好，改完还能再发出去。

后果是：全世界几万人一起帮它修 Bug、加功能、适配新硬件。不是某家公司养 Linux，是整个社区养 Linux。这种"改得动、搬得走"的可控性，是企业敢把业务核心放上去的最大理由。

坑在哪
现象原因 / 怎么办
以为 Linux 的优势就是"不要钱"真正的价值是可控 + 社区生态；一个开源产品如果没人维护，免费也没人敢用
以为"自由软件"= 随便拿、随便商用还得注明开源不等于无规则，不同许可证约束不同；学习阶段记住"开放协作"这点即可
3③ 内核与发行版：发动机和整车
要解决什么

老师一会儿说"Linux"，一会儿说"CentOS""Ubuntu"，两个词来回混用，到底谁是 Linux？

核心思路

用车的比喻一次说清：

Linux 内核（发动机）                发行版（整车）
──────────────────────────────────────────────────
管 CPU/内存/驱动/网络       =     内核 + 应用程序
你看不到它，它在最底层              + 包管理器 + 安装器
                                 你装的就是这一整台：CentOS / Ubuntu

发行版 = 打包：把 Linux 内核和一堆常用软件（Shell、编辑器、服务器程序）打包成一份"装完就能用"的系统，再配上自己的软件商店（包管理器）。所以：

  • 你说"我装了 Linux"，实际是装了某个发行版；
  • 各大发行版共用同一个内核，区别在外围软件、包管理器、更新节奏。
坑在哪
现象原因 / 怎么办
以为 Ubuntu 和 CentOS 是两款"完全不同的系统"它们内核同源，差别在外围生态；换一个发行版，前面学的命令 90% 原样能用
选择题问"哪个不是 Linux（Ubuntu/Debian/CentOS/Windows）"答案 Windows——Ubuntu、Debian、CentOS 都是发行版
4④ 发行版怎么选：先看清两大门派
要解决什么

网上一搜 Linux 全是发行版名字（Red Hat、Ubuntu、SuSE、Gentoo、Debian、CentOS……），到底该装哪个？

核心思路

发行版按血缘分几派，记住两大主流就够：

门派代表包管理 / 安装命令适合
红帽系RHEL、CentOSrpm / yum企业服务器、云主机（国内最主流）
Debian 系Ubuntu、Debiandpkg / apt桌面开发、个人服务器
其他SuSE / Gentoo / Arch 等各不相同特定行业、极客折腾

选型口诀：做企业级、跟教程走 → CentOS 系；自己学习练手、图资料多 → Ubuntu 也行。本阶段全程以 CentOS 为例，你之后换成任何红帽系发行版都能无缝衔接。

坑在哪
现象原因 / 怎么办
在 Ubuntu 上敲 yum 报 "command not found"两派包管理器不同（Ubuntu 用 apt）；先确认发行版，再决定命令
以为换发行版 = 全部重学命令和目录标准大体一致，差异主要在"怎么装软件"那一步
5⑤ Linux 用在哪：服务器才是主场
要解决什么

你平时看到的"电脑"都是 Windows/macOS 桌面，Linux 装在哪？为什么学云计算、大数据、DevOps 的人都绕不开它？

核心思路

Linux 的主场是服务器，不是个人桌面：

┌──────────────────────────────────────────────────┐
│  服务器（Web / 数据库 / 大数据 / 云主机）         │ ← Linux 统治区，几乎不用桌面
├──────────────────────────────────────────────────┤
│  嵌入式（路由器、机顶盒、安卓底层、IoT 设备）     │ ← Linux 内核，量大面广
├──────────────────────────────────────────────────┤
│  个人桌面                                       │ ← Windows 更普及，Linux 桌面是少数人折腾
└──────────────────────────────────────────────────┘

你在云上买的一台台云服务器，几乎都是 Linux。所以不是"Linux 没人用"，而是在你看不见的地方它都在用。

坑在哪
现象原因 / 怎么办
觉得"Linux 又丑又难用，Windows 不是挺好"服务器要的是稳定、省资源、可脚本化，不是好看；Linux 在服务器领域份额压倒性领先
以为学 Linux 只是为了"装个系统"真正的用途是搭环境：装 JDK、装 MySQL、配 Nginx——本阶段后面几章全是这件事
6⑥ 虚拟机：在 Windows 里"套娃"一台练习 Linux
要解决什么

我电脑就是 Windows，想学 Linux 又不敢直接装双系统（怕搞坏引导、怕误格盘）。有没有"随便折腾、坏了重来"的办法？

核心思路

用虚拟机（VMware）：用软件在真实的 Windows 系统里，模拟出一台完整的"电脑"（CPU、内存、硬盘、网卡都是软件的），在这台虚拟电脑里再装 Linux。

  • 虚拟机和外界唯一的通道是虚拟网卡，玩坏了不影响你的 Windows；
  • 支持快照：装之前拍一张，之后怎么折腾都能一键还原；
  • 真实服务器上的软件、命令、网络行为，虚拟机里 100% 一致，学完直接上手服务器。

注意一个经典误解：一台物理机可以开多台虚拟机、装多个 Linux——虚拟机不是"一台机器只能装一个系统"。

坑在哪
现象原因 / 怎么办
虚拟机一开，整个 Windows 卡成 PPT内存分太多了。低配电脑给虚拟机 2GB 左右足够练命令，别贪多
以为"虚拟机里只能装一台 Linux"可以开 N 台虚拟机装 N 个系统，只要硬盘和内存够
双系统才是"真装"，虚拟机是"假装"学习/练手阶段虚拟机更优：快照回滚、随时删除，成本远低于双系统
7⑦ 下载 CentOS：官网慢？用镜像站
要解决什么

CentOS 官网下载慢到怀疑人生，好不容易下完还可能是坏文件。怎么又快又稳地拿到安装镜像？

核心思路

CentOS 官方把历史版本都放在归档站 https://vault.centos.org/；国内下载务必走阿里镜像：

CentOS 官方归档：  https://vault.centos.org/
阿里云镜像站：    https://mirrors.aliyun.com/

选镜像要认准三件事：

要看的含义
版本号7.x 系列（教程普遍用 7）
架构x86_64（家用电脑基本都是）
镜像类型DVD（完整，推荐）、Minimal（最小，练命令够用）

下载完得到一个 .iso 文件：在 VMware 里把"这张光盘"插进虚拟机（设置 → CD/DVD → 使用 ISO 镜像文件）。

坑在哪
现象原因 / 怎么办
下载速度几 KB/s 到崩溃官网源在海外；直接换阿里镜像站
下载了 aarch64 架构装不上家用 x86 电脑选 x86_64；aarch64 是 ARM 开发板用的
安装时提示"找不到 install media"ISO 没挂载对：VMware 光驱设置里选"使用 ISO 镜像文件"，不要选"稍后安装"
8⑧ VMware 安装 CentOS：这几个选项必须看准
要解决什么

安装向导一路 Next，但有些选项选错后面很麻烦（比如 root 密码忘了、分区不对）。哪些是必须留神的？

核心思路

关键就五处，其余基本默认：

步骤选什么备注
软件选择最小安装（Minimal）练命令不需要图形桌面，省资源
安装位置自动分区新手别手动分区，默认自动即可
网络先把网卡开关打开（ON）具体 IP 配置下一章做
root 密码设一个自己能记住的忘了只能重置，比较麻烦
创建用户建一个普通用户（如 dev）平时用 dev 登录，要管理员权限再 su - root

装完重启，输入 root 密码回车，看到 [root@node01 ~]# 就成功了——这就是传说中的"命令行"。

坑在哪
现象原因 / 怎么办
root 密码设成了复杂的，可又忘了只能进应急模式重置；练习环境直接重装最快
装完没有"图形界面"因为选了最小安装——本来就不带桌面，命令练手完全够
选了带桌面的完整版，内存不够跑低配机器务必最小安装，能省近 1GB 内存
登录时报"密码错误"但明明输对了看是否开了大写锁定，或输密码时光标位置的 * 号不对（Linux 输入密码不显示任何字符）
9⑨ 认识根目录：Linux 的"C 盘地图"
要解决什么

装完登录，输入 ls / 出来一屏陌生目录名：etc、bin、home、var……都干什么的？不知道这个，后面 cd 到哪都会慌。

核心思路

Linux 是树形结构：一切从根 / 开始，没有盘符（没有 C:、D:）。装完系统第一件事就是认地图：

目录装的是啥类比
/etc系统配置文件（hosts、yum 源都在此）注册表
/bin /sbin /usr/bin命令程序（ls、ps 就藏在这）C:\Windows\System32
/home普通用户的家目录用户文件夹
/rootroot 管理员的家目录Administrator
/var日志等不断增长的数据（/var/log）日志库
/tmp临时文件，随便放临时文件夹
/boot启动内核文件引导区
/dev硬件设备映射（硬盘、键盘都是"文件"）设备管理器
/mnt /media临时挂载 U 盘、硬盘"插入的磁盘"
/opt /usr/local第三方软件安装处Program Files
/proc /sys内存映射的虚拟目录，反映系统实时状态任务管理器

一句话记忆：配啥找 /etc，跑命令找 /bin，用户找 /home，日志找 /var。

坑在哪
现象原因 / 怎么办
以为根目录 / 相当于"C 盘里的某个文件夹"/ 是整棵树的根，没有盘符概念；/etc 是"根下的 etc 目录"，不是某个盘的子文件夹
好奇去 /etc 里乱改配置，然后系统起不来讲义明确警告：/etc 是关键目录，改错可能导致系统无法启动；动手前先备份
分不清 /bin 和 /sbin/bin 普通用户也能用；/sbin 主要是管理员用的系统管理命令

本章小结

问题答案
Linux 是什么1991 年诞生的开源操作系统内核，1.0 于 1994 年发布
内核和发行版什么关系内核=发动机；发行版=内核+应用软件打成的整车
发行版怎么选红帽系（rpm/yum）做服务器；Debian 系（apt）做开发；本教程用 CentOS
Linux 主要用在哪服务器与嵌入式，不是个人桌面
怎么安全地学虚拟机里装，坏了随时重来，还能做快照
下载慢怎么办用阿里镜像站
装完第一件事认识根目录结构，尤其 /etc /home /var /bin

一句话总结：Linux 是无偿开源的操作系统内核，被各国企业打包成 CentOS、Ubuntu 等发行版，统治了服务器市场；本章用 VMware 虚拟机 + CentOS 镜像搭了一台随便折腾的练习机，并认清了根目录这张"地图"——下一章就远程连上去，开始真正敲命令。
