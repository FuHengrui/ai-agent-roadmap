第二章　jieba中文分词

阶段 22 · 自然语言处理与Transformer架构　|　中文分词　|　难度 ★☆☆
这一章在解决什么问题

中文一句话连在一起没有空格，机器根本不知道词的边界在哪里。"武汉市长江大桥"这种句子，切错一个位置意思就全变了。这一章解决中文 NLP 的第一道工序：分词。我们用 Python 最流行的中文分词库 jieba，搞懂精确模式、全模式、自定义词典这些概念，并亲眼看到同一个句子在不同模式下切出的结果差别。

开始之前

只要一个能跑 Python 的环境，装个 jieba 就能跟着敲，不用 GPU。

学到这儿就够了

能说清三种分词模式的区别，能用自定义词典纠正切分，能对着结果判断切得对不对，这章就算过了。

上一章→本章→下一章 上一章建立了 NLP 的整体认知，知道"词法层"是第一步。本章动手做词法层最重要的事：分词。下一章继续在 jieba 上做关键词抽取（TF-IDF/TextRank）和词性标注——它们都以"分好词"为前提。
1① 为什么中文分词是必修课
要解决什么

"我/爱/自然语言处理"和"我爱/自然/语言处理"，哪种切法对？影响有多大？

核心思路

中文文本没有天然分隔符，分词就是把连续的汉字序列按语义切成一个词序列的过程。它是绝大多数中文 NLP 任务的前置步骤：

  • 关键词抽取：先分词，才知道哪些是"候选词"。
  • 词性标注：词的边界错了，词性必然错。
  • 词向量/模型输入：模型输入的基本单位是"词/token"，不是整句话。

分词质量直接决定下游效果。切得不对，模型看到的语义单元就是错的，后面怎么调参都难补。

坑在哪
现象原因 / 怎么办
用"按字"代替分词按字切会让"自然语言"变成一个字一个字的碎片，丢失词义信息，模型更难学
以为分词结果必须唯一正确歧义是客观存在的，工程上用概率选最可能的切法即可，不追求绝对正确
2② jieba 是什么
要解决什么

市面上分词工具那么多，jieba 凭什么成为入门首选？

核心思路

jieba（结巴分词） 是 Python 生态最流行的中文分词库，特点：

  • 易用：pip install jieba 一条命令装完，调用接口极简。
  • 算法成熟：基于前缀词典实现高效词图扫描，结合 HMM 模型处理未登录词。
  • 三种模式：精确模式、全模式、搜索引擎模式，覆盖不同场景。
  • 可扩展：支持自定义词典、动态调词，能适配专业领域词汇。

cut() 是核心函数，返回生成器，lcut() 直接返回列表，日常用 lcut() 更方便。

坑在哪
现象原因 / 怎么办
跳过安装直接复制代码运行前先 pip install jieba，避免 import 报错
忘了 lcut() 返回列表cut() 返回生成器只能迭代一次，要下标访问或重复用就转成列表
3③ 精确模式：默认也最常用
要解决什么

拿到一句话，最稳妥的默认切法是什么？

核心思路

精确模式试图把句子最精确地切开，每个字符都属于且只属于一个词，不产生冗余，是默认模式、也是文本分析最常用的模式：

import jieba

text = "我来到北京清华大学"
words = jieba.lcut(text)
print(words)
# 输出：['我', '来到', '北京', '清华大学']

精确模式适合需要"干净的词序列"的场景：关键词抽取、词频统计、词性标注、分类特征提取。

坑在哪
现象原因 / 怎么办
期望精确模式 100% 分对遇到未收录词可能切碎或切错，需要配合自定义词典
精确模式处理长文本效率低长了就分句后再逐句分词，或批量处理，别一次喂超长文本
4④ 全模式：看着"啰嗦"但有用
要解决什么

有没有一种模式能把所有可能的词都找出来？它有什么用？

核心思路

全模式把句子中所有成词的组合都切出来，一个词也不漏：

import jieba

text = "我来到北京清华大学"
words = jieba.lcut(text, cut_all=True)
print(words)
# 输出：['我', '来到', '北京', '清华', '清华大学', '华大', '大学']

注意输出里有"清华"和"清华大学"两个词——这是全模式的特点：宁多勿漏。它不能直接作为下游任务的输入（词太碎、有重叠），但适合做候选词发现，比如搜索引擎的索引切分、词库扩充的候选挖掘。

坑在哪
现象原因 / 怎么办
拿全模式结果直接做关键词统计重叠词导致重复计数，"清华大学"和"大学"被当两个独立词，统计失真
以为全模式比精确模式"更对"全模式的目标是召回(recall)，不是精确(accuracy)，用途完全不同
5⑤ 搜索引擎模式：兼顾精度与召回
要解决什么

既要分得准、又想覆盖长词内部的关键单元，怎么办？

核心思路

搜索引擎模式在精确模式的基础上，把长词再次切分为短词，为搜索引擎提供更丰富的索引单元：

import jieba

text = "我来到北京清华大学"
words = jieba.lcut_for_search(text)
print(words)
# 输出：['我', '来到', '北京', '清华', '华大', '大学', '清华大学']

它比精确模式多出"清华""华大""大学"这些子词。这样搜索引擎既能命中"清华大学"整词搜索，也能在用户搜"清华"时召回该文档。适合搜索索引、召回场景，兼顾精度和召回。

坑在哪
现象原因 / 怎么办
分析任务误用搜索引擎模式文本分析（情感、主题）要的是精确模式；搜索场景才用 cut_for_search
混淆全模式和搜索引擎模式全模式输出有重叠词；搜索引擎模式同样会产出互相重叠的子词，区别是以精确模式结果为主干、只在长词上补子词
6⑥ 自定义词典：让 jieba 认识专业词
要解决什么

"深度学习""自然语言处理"这类垂直领域词，默认词典不认识怎么办？

核心思路

jieba 内置词典不全覆盖垂直领域，通过 load_userdict() 加载自定义词典，强制保留指定词、指定词性和词频：

import jieba

jieba.load_userdict("my_dict.txt")
# my_dict.txt 每行格式：词 词频 词性
# 自然语言处理 100 n
# 大模型 100 n

text = "我们研究自然语言处理与大模型"
print(jieba.lcut(text))
# 输出：['我们', '研究', '自然语言处理', '与', '大模型']

自定义词典的典型来源：专业术语表、人名地名表、品牌词表、领域黑话。比在代码里逐个 add_word 更推荐，因为词典文件可复用、可维护。

坑在哪
现象原因 / 怎么办
忘了给自定义词设词频词频过低可能依旧被切碎（被默认路径覆盖），设个较大词频（如 100）才能压过默认切分
一行写多个词词典一行只能一个词，多了会解析异常；格式严格为"词 词频 词性"
7⑦ 动态调整：代码里临时改词
要解决什么

不想维护词典文件，就想针对这一句话临时把某词拼回去，怎么做？

核心思路

用 add_word() / del_word() 在运行时动态调整：

import jieba

text = "大模型今天发布新版本"
words = jieba.lcut(text)
print(words)  # 实测：['大', '模型', '今天', '发布', '新', '版本']

jieba.add_word("大模型")   # 默认会被切成「大/模型」，加了才合成一个词
words = jieba.lcut(text)
print(words)  # 加之前：["大", "模型", "今天", ...]；加之后：["大模型", "今天", ...]

add_word 适合轻量、临时的修词；如果要长期、大规模生效，还是建自定义词典文件更规范。del_word 则用于让某个不该成词的组合拆开。

坑在哪
现象原因 / 怎么办
每次运行时重新 add_wordadd_word 是内存级修改，每次运行都要重新执行；长期词应写入词典文件
add_word 后仍被切错调整词频或使用自定义词典加载，单次 add_word 的权重可能不足
8⑧ 分词之外的常见坑：标点、英文、数字
要解决什么

真实文本里全是"你好123, hello world！"这种混合内容，分词怎么处理？

核心思路

真实语料常混有标点、数字、英文，处理时要分层：

  • 标点：一般先按标点断句，再对每句分词；标点本身通常不进词表。
  • 英文/数字：jieba 默认会把连续的英文/数字切成一个 token（"GPT-4" 这类带连字符的需单独处理）。
  • 未登录词（新词/人名）：靠 HMM 模型在词图里找"隐状态"组合，能解决一部分，但覆盖不了就得上自定义词典。

工程口诀：先清洗（去噪、规范），再断句，再分词，再按需加载领域词典。

坑在哪
现象原因 / 怎么办
直接拿带 HTML/换行的原文分词脏字符会污染词序列，先清洗正则去掉标签和异常字符
期望一个分词配置通吃全部场景新闻、代码注释、医疗文本的词表完全不同，按领域维护不同词典

本章把 jieba 分词的核心能力过了一遍：

问题答案
为什么分词中文无空格，机器需要语义单元
精确模式最精确切分，默认且最常用

搜索引擎模式精确切分 + 长词补子词，适合搜索召回
