第八章　LSTM门控机制

阶段 22 · 自然语言处理与Transformer架构　|　LSTM　|　难度 ★★★
这一章在解决什么问题

上一章歌词生成到后面句子越来越不连贯——RNN 的梯度消失让"远方的词"传不过来。这一章给出第一个治本方案：LSTM（长短期记忆网络）。它靠"细胞状态 + 三个门"给信息修了一条直通高速公路：该忘的忘掉、该记的记下、该读的读出。搞懂遗忘门、输入门、输出门，你就掌握了整个深度学习里"记忆机制"的典范。

开始之前

接着前面的 PyTorch 环境，这章不用装新东西；上一章歌词生成的失败现象先记着，那就是这章要治的病。

学到这儿就够了

能说清三个门各自管什么、细胞状态为什么能缓解梯度消失，能对着公式讲出一次更新，这章就算过了。

上一章→本章→下一章 上一章 RNN 实战暴露了两大痛点：梯度消失、长依赖记不住。本章用 LSTM 的三门控机制正面解决它。下一章把"门控"再做减法（GRU）并加上"反向读取"（双向 RNN）——一个更省、一个看得更全。
1① 从 RNN 到 LSTM：在记忆上做文章
要解决什么

RNN 的 h_t 既要"当记忆"又要"当输出"，哪里出了问题？

核心思路

RNN 的问题根源：只有一条隐藏状态通道，信息进来只能"连乘叠加"，距离一远梯度就消失。

LSTM 的解决办法：加一条"细胞状态（Cell State）"C_t 作为独立的知识通道，再加三个门控制信息的流速：

  • 细胞状态 C_t：长长的传送带，贯穿整个序列，允许信息"直通"不衰减——梯度消失的治本解。
  • 隐藏状态 h_t：仍然对外输出，但内容由"读门"决定。
  • 三个门（Gate）：均是 sigmoid 输出 0~1 的"开关"（0 全关、1 全开），分别管 忘什么、存什么、输出什么。

一句话：RNN 是"一个处理器边走边记"，LSTM 是"传送带 + 三个检查站"。

坑在哪
现象原因 / 怎么办
把 h_t 和 C_t 混为一谈h 是对外短时记忆（输出），C 是对内长时记忆（传送带），两套并行
以为门是"硬开关"门输出是 0~1 连续值（sigmoid），是"比例阀"不是"开关"
2② 遗忘门：决定扔掉什么
要解决什么

上一句话已经用不上了（比如句号后换了新主题），怎么从记忆里删掉？

核心思路

遗忘门（Forget Gate） 负责决定细胞状态里哪些旧信息可以丢：

f_t = sigmoid(W_f · [h_{t-1}, x_t] + b_f)
C_t = C_{t-1} * f_t        # 旧状态按 f_t 比例保留/遗忘

做法：把"上一个隐藏状态 h_{t-1}"和"当前输入 x_t"拼起来，过一个 sigmoid 得到 0~1 向量，再逐元素乘到旧细胞状态 C_{t-1} 上——值接近 0 的位置旧信息被遗忘，接近 1 的位置被保留。

直觉例子：读到"他说他不喜欢这家店，"时保留"不喜欢"；随后读到"但是……"时把"不喜欢"弱化、准备承接转折。

坑在哪
现象原因 / 怎么办
以为遗忘门"清空记忆"它是按元素比例遗忘，位置不同比例不同，不是一格全删
忘记它作用的对象f_t 乘的是 C_{t-1}（旧细胞状态），不是 h
3③ 输入门：决定记住什么
要解决什么

当前这句的关键信息（"北京"）怎么"写进"长期记忆？

核心思路

输入门（Input Gate） 决定把当前输入的新信息写入细胞状态多少：

i_t = sigmoid(W_i · [h_{t-1}, x_t] + b_i)   # 写多少
g_t = tanh(W_g · [h_{t-1}, x_t] + b_g)      # 写什么（候选值）
C_t = C_{t-1} * f_t + i_t * g_t             # 新旧合成

两项分工：

  • g_t（候选记忆）：当前输入提炼出的新信息候选（tanh 输出 -1~1）。
  • i_t（写入比例）：决定候选信息写多少进传送带。

最终细胞状态 = 旧状态按遗忘门保留 + 新候选按输入门写入。这两步合并就是 LSTM 的"更新记忆"阶段。

坑在哪
现象原因 / 怎么办
把"写什么 g_t"和"写多少 i_t"混了一个管内容、一个管权重，两个门缺一不可
忘了 C 更新是"乘加"合成C_t = C_{t-1} * 遗忘 + g * 输入，加号让梯度有了直达通道（梯度消失解药）
4④ 输出门：决定对外说什么
要解决什么

记忆里有的是存货，当前这一步对外输出哪个"版本"的隐藏状态？

核心思路

输出门（Output Gate） 决定从细胞状态里"读出"多少作为对外隐藏状态 h_t：

o_t = sigmoid(W_o · [h_{t-1}, x_t] + b_o)   # 读多少
h_t = o_t * tanh(C_t)                        # 把细胞状态压缩后按比例输出
  • tanh(C_t)：把传送带上的信息压缩到 (-1,1)，作为"候选输出内容"。
  • o_t：决定这坨内容放多少到 h_t 外面去。

至此 h_t 既包含了"长期记忆提炼的结果"，又可以被下一个时刻当作"短期输入"继续使用——这正好满足 RNN 的 h_t 传递约定。

坑在哪
现象原因 / 怎么办
以为 h_t = C_th_t 是"过滤后的 C_t"（先 tanh 再乘 o），形状相同但内容不同
忘掉门都是 sigmoid、候选值用 tanhsigmoid 管"比例"，tanh 管"内容"，这是 LSTM 的固定分工
5⑤ LSTM 完整公式走一遍
要解决什么

三个门 + 传送带，整步计算串起来是什么顺序？

核心思路

LSTM 单步完整计算（t 时刻）：

1. 遗忘门：  f_t = σ(W_f·[h_{t-1}, x_t] + b_f)
2. 输入门：  i_t = σ(W_i·[h_{t-1}, x_t] + b_i)
3. 候选值：  g_t = tanh(W_g·[h_{t-1}, x_t] + b_g)
4. 更新状态：C_t = C_{t-1} * f_t + i_t * g_t
5. 输出门：  o_t = σ(W_o·[h_{t-1}, x_t] + b_o)
6. 输出：    h_t = o_t * tanh(C_t)

把三步门控公式放到一起对比就很清晰：三个 sigmoid 门（忘/写/读）+ 一个 tanh 候选（内容）+ 传送带更新 + tanh 压缩输出。所有参数 W、b 都靠 BPTT 训练，与 RNN 一样共享。

坑在哪
现象原因 / 怎么办
死记公式顺序记住三个角色：忘（f×旧）、存（i×g）、出（o×tanh(C)），顺序自然就串起来了
以为 LSTM 参数是 RNN 的 3 倍多一点每组门控都有自己的 W，参数量约 4 倍，训练更慢但收益大
6⑥ 为什么 LSTM 解决了梯度消失
要解决什么

同样是 BPTT，LSTM 凭什么就能把远距离信息传回来？

核心思路

关键在于细胞状态更新的"加法直通"：

C_t = C_{t-1} * f_t + i_t * g_t

反向传播时，沿 C 链路的梯度仍然是连乘 ∂C_T/∂C_t = ∏f_t；它不指数衰减，是因为 f_t 通常接近 1，而且这条路径不经过 tanh 和矩阵乘法。至于「每一层加一项 i_t*g_t 」，那是前向的更新，不是反向的梯度路径：

∂C_t / ∂C_{t-1} ≈ f_t ≈ 1（当门全开时）

梯度沿传送带一路畅通，不再指数衰减，"去年在北京"这种远古信息就能一路传回。这被称为梯度高速公路。代价也很明确：遗忘门全开时记忆不衰减，但该忘的忘不掉会信息过载——所以门也是要学的（模型自己学会什么时候开、什么时候关）。

坑在哪
现象原因 / 怎么办
以为 LSTM 梯度永远不会消失极端情况（遗忘门趋 0）梯度仍会断，但门是自适应学习的，绝大多数情况能保持
把门当"免费午餐"LSTM 参数多、更慢、更容易过拟合，小数据上未必比 RNN 好，要因场景选型
7⑦ 实战：PyTorch 的 nn.LSTM
要解决什么

手写公式太累，PyTorch 一行怎么把 LSTM 用起来？

核心思路

PyTorch 的 nn.LSTM 把上述全部公式封装好：

import torch.nn as nn

lstm = nn.LSTM(
    input_size=64,   # 词向量维度
    hidden_size=128, # 隐藏状态/细胞状态维度（相等）
    num_layers=2,    # 堆叠 2 层
    batch_first=True,
)

import torch

x = torch.randn(16, 20, 64)   # [batch, seq_len, hidden]      # [batch, seq, embed]
out, (h_n, c_n) = lstm(x)
# out : [16, 20, 128]  每步输出
# h_n : [2, 16, 128]   每层最后时刻隐藏状态
# c_n : [2, 16, 128]   每层最后时刻细胞状态

用法要点：把上一章 CharRNN 里的 nn.RNN 换成 nn.LSTM，其余代码（Embedding/Linear/训练/采样）一行不用改，生成长句的连贯性通常立竿见影。

坑在哪
现象原因 / 怎么办
解包写错nn.LSTM 返回的是 2 个：out, (h_n, c_n) = lstm(x)；写成三个变量会 ValueError
想单步自回归却用 out推理生成时通常喂上一步的 out 当本步输入，或手动管理 h、c 状态
8⑧ LSTM 的局限与后续演进
要解决什么

LSTM 都解决了记忆，怎么还会被 GRU、Transformer 取代？

核心思路

LSTM 的硬伤集中在"顺序处理"：

  1. 不能并行：第 t 步必须等第 t-1 步算完，序列越长越慢（GPU 白搭）。
  2. 参数量大：3 个门 4 套矩阵，训练慢、易过拟合。
  3. 长距离依赖仍有限：几百上千 token 的跨度，连乘优势也不再明显。

后续演进：GRU 把三个门减到两个（更省参数，效果接近）；注意力机制/Transformer 让所有位置一步直达（并行 + 超长依赖），直接终结了 RNN 时代。但 LSTM 依然是理解"门控记忆"的教科书，也是现代某些时序任务的首选。

坑在哪
现象原因 / 怎么办
以为 Transformer 全面碾压 LSTM短序列、时序预测、小数据场景 LSTM 仍有价值；"碾压"主要在超长文本与并行训练维度
跳过 LSTM 直接学注意力不理解"为什么需要门控/记忆"，就看不懂注意力解决的是同一类问题的另一条路

本章小结

本章把 LSTM 的门控机制拆解完毕：

组件作用公式要点
细胞状态 C长时记忆传送带C_t = C_{t-1}*f + i*g
遗忘门 f旧信息忘多少sigmoid([h_{t-1}, x])
输入门 i新信息写多少sigmoid × tanh 候选
输出门 o对外读多少h = o * tanh(C)
解决什么梯度消失/长依赖加法直通 = 梯度高速公路
实战nn.LSTM 一行替换返回 out,(h,c)

一句话记住本章：LSTM 靠"传送带式细胞状态 + 遗忘/输入/输出三个 sigmoid 门"给信息修了条直通公路，梯度不再连乘消失，长句记忆大幅增强；它用自己的"加法"换来了“写得更久、记得更远”，代价是不能并行、参数多——这也为 GRU 和注意力机制埋下了伏笔。
