1① uv：现代 Python 项目依赖管理
要解决什么

传统 pip + venv 用起来繁琐：分开创建虚拟环境、逐个 pip install、没有锁文件。uv 把这些合而为一。

核心思路

做完数据库后，进入 2.AI智能体Web系统构建实战/后端 目录（或新建工作目录），用 uv 初始化项目：

uv init operation        # 创建项目目录并初始化（含 pyproject.toml）
cd operation
uv venv                 # 创建虚拟环境 .venv

随后用一条命令把全部依赖装齐（uv 会自动解析版本、生成 uv.lock）：

uv add fastapi uvicorn tortoise-orm aerich pydantic-settings
uv add "pymysql" cozepy dashscope pyjwt oss2
uv add "python-multipart" python-dotenv

要点：uv 的 uv add 会同时更新 pyproject.toml 并生成 uv.lock，团队其他人 uv sync 一条命令还原一模一样的环境——这就是"可复现构建"。装好后 uv run uvicorn main:app 即可在虚拟环境里跑起来。

坑在哪
现象原因
用系统的 python -m pip 装依赖，污染全局环境必须先 uv venv 建虚拟环境，所有依赖装进 .venv；pip list 查不到属正常
直接 pip install 而不是 uv add不经过 uv 安装的包不会进 pyproject/uv.lock，换机器无法复现环境
2② Python 版本锁定与 .python-version
要解决什么

AI 相关依赖（cozepy、dashscope）对 Python 版本敏感，版本漂移会导致各种诡异错误。项目必须钉死 Python 版本。

核心思路

uv 生成 .python-version 文件，内容如 3.12，再用命令确认解释器版本：

uv python pin 3.12     # 锁定 3.12
python --version       # 期望输出 Python 3.12.x

.python-version 的作用：任何人在任何机器上执行 uv 命令，都会自动使用该版本。版本不匹配时某些 SDK（尤其涉及事件循环、二进制编译的包）会报 TypeError: __init__() got an unexpected keyword argument 之类难懂的错误。

坑在哪
现象原因
Python 3.11 下 coze SDK 报错、3.12 下正常AI SDK 对不同小版本支持不一致；务必用 .python-version 钉死，别用"当前机器默认版本"
只在本机好了，换机器又崩版本约束只写进 .python-version + pyproject（requires-python），缺一不可
3③ pyproject.toml：项目元数据与依赖清单
要解决什么

pyproject.toml 是 Python 项目的"身份证 + 依赖清单 + 工具配置"，Aerich 的迁移配置也写在这里（或 config.py 里）。

核心思路

uv init 生成的 pyproject.toml 核心结构：

[project]
name = "operation"
version = "0.1.0"
description = "智能运营平台后端"
readme = "README.md"
requires-python = ">=3.12"
dependencies = [
    "cozepy>=1.x",
    "dashscope>=1.x",
    "fastapi>=0.1xx",
    "pyjwt>=2.x",
    "pymysql>=1.x",
    "tortoise-orm>=0.2x",
    "uvicorn>=0.3x",
    ...
]

注意：Aerich 的数据库配置（TORTOISE_ORM 指向 config.py）两种写法都行——写在 pyproject [tool.aerich] 或直接在 aerich init 时指定。讲义采用标准做法：config.py 里导出 TORTOISE_ORM，Aerich 通过导入该配置工作（下一章揭晓）。

4④ .env：五类凭据的分组与读取
要解决什么

上章已 List 过 .env 的结构。这里解决"代码如何读到它"：用 python-dotenv 加载 + os.getenv 读取。

核心思路

config.py 的读取模式：

import os
from dotenv import load_dotenv

load_dotenv()   # 读取项目根目录的 .env 到环境变量

DB_HOST = os.getenv("DB_HOST", "localhost")
DB_PORT = os.getenv("DB_PORT", "3306")
DB_USER = os.getenv("DB_USER", "root")
DB_PASSWORD = os.getenv("DB_PASSWORD", "root")
DB_NAME = os.getenv("DB_NAME", "baizhan_operation")

要点：

  • os.getenv(key, default) 提供默认值兜底——本机五连：localhost/3306/root/root/baizhan_operation，一套 .env 就能跑。
  • 敏感项（JWT_SECRET、COZE_TOKEN、QWEN_KEY、OSS 密钥）不给默认值，缺失即显式报错，避免"无声地用错密钥"。
坑在哪
现象原因
改了 .env 但代码没生效load_dotenv 只在进程启动时读一次；改了 .env 必须重启 uvicorn
密钥项给了默认值默认值 = 把生产密钥写进代码；敏感项必须强制在 .env 提供
5⑤ config.py：数据库连接串与 URL 编码
要解决什么

Tortoise-ORM 需要 DB URL（mysql://user:pass@host:port/db），但 MySQL 密码里若含 @ # : / 等特殊字符，直接拼串会解析错误。这必须用 quote_plus 处理。

核心思路 
from urllib.parse import quote_plus

DATABASE_URL = (
    f"mysql://{DB_USER}:{quote_plus(DB_PASSWORD)}"
    f"@{DB_HOST}:{DB_PORT}/{DB_NAME}?charset=utf8mb4"
)

TORTOISE_ORM = {
    "connections": {"default": DATABASE_URL},
    "apps": {
        "models": {
            "models": ["app.models", "aerich.models"],
            "default_connection": "default",
        }
    },
    "timezone": "Asia/Shanghai",
}

三个要点：

  1. quote_plus(DB_PASSWORD)：密码中的特殊字符 URL 编码，如 p@ss → p%40ss。不编码，Tortoise 连库直接保错。
  2. apps.models.models 含两个模块名："app.models"（自己的模型）与 "aerich.models"（迁移版本表 aerich），缺 aerich.models 则迁移失效。
  3. charset=utf8mb4：与建库字符集呼应，保证中文与 emoji 正常读写。
坑在哪
现象原因
密码含 @ 时配好半天连不上连接串把 @ 当成了分隔符；必须 quote_plus 编码后再拼 URL
aerich migrate 报"模型未注册"TORTOISE_ORM 的 models 列表漏了 "app.models" 或路径写错
报 "Unknown charset: utf8mb4_0900_ai_2"版本/驱动不兼容排序规则，改用通用 charset=utf8mb4
6⑥ Tortoise-ORM 配置结构逐字段解释
要解决什么

TORTOISE_ORM 是 Aerich 迁移和数据访问的唯一配置源。逐字段理解它，后续 models 与迁移都不会跑偏。

核心思路

配置的层次结构：

  • connections.default：默认数据库连接（DATABASE_URL）。
  • apps.models.models：要纳管的模型模块列表——迁移时 Aerich 扫描这些模块收集模型定义。
  • apps.models.default_connection：该 app 使用的连接名。
  • timezone：写入时间戳的时区，设 Asia/Shanghai 保证 created_at 存的是北京时间。

这个配置同时被三个入口使用：uvicorn 启动时（main.py 的 register_db）、Aerich 迁移命令（aerich init/init-db 时）、测试脚本（如果需要独立连库）。一份配置多处复用，改一处全生效。

7⑦ pydantic-settings 与 .env 的另一种姿势
要解决什么

有些工程用 pydantic-settings 把配置封装成 Settings 类。讲义用 dotenv + os.getenv 的轻量方案——理解两者差异，读源码才不困惑。

核心思路

两种方案：

  • 轻量派（讲义采用）：load_dotenv() + os.getenv，看不懂设置类、无校验，但直白好调。
  • 工程派（pydantic-settings）：class Settings(BaseSettings) 字段带默认值与类型校验，配置即模型。

取舍：小项目/教学用轻量派足够；生产项目建议 Settings 类（类型校验 + 自动忽略未知字段的坑更少）。源码里两套风格可能混存（pyproject 装了 pydantic-settings），读代码时以实际 import 为准。

坑在哪
现象原因
混用 pydantic-settings 与 os.getenv，改了 Settings 类但 os.getenv 读的还是旧值两套读取源互不相通；一个工程只选一种方式统一读配置

本章小结

  • uv 三连：uv init → uv venv → uv add，依赖进 pyproject + uv.lock，可复现构建
  • .python-version 钉死 Python 3.12，避免 AI SDK 版本敏感问题
  • pyproject.toml：元数据 + 依赖清单 + Aerich 配置入口
  • .env 五类配置 + load_dotenv + os.getenv（带默认值兜底，敏感项不给默认）
  • config.py：DATABASE_URL 用 quote_plus 编码密码，charset=utf8mb4
  • TORTOISE_ORM：connections/apps/models 结构，"app.models" + "aerich.models" 缺一不可
  • 配置读取两派：轻量 os.getenv 与 pydantic-settings，混用会互相干扰
  • uv 日常：uv run/uv add/uv remove/uv sync；IDE 必须切 .venv 解释器

8⑧ uv 常用命令速查与 IDE 联动
要解决什么

uv 的命令不止 init/add 三个。日常高频操作（跑脚本、装新依赖、还原环境、删除依赖）分别用什么？IDE 识别不到依赖又是怎么回事？

核心思路

日常命令速查：

想干什么命令
跑项目脚本/服务uv run python xxx.py / uv run uvicorn main:app
加新依赖uv add 包名（自动解析+锁文件）
删依赖uv remove 包名
按锁文件还原环境uv sync（克隆仓库后第一条命令）
升级某个包uv add 包名@latest 或手动改 pyproject 再 sync
看已装包uv pip list

IDE 联动的坑：VS Code 打开项目后，如果没选 .venv 解释器，import 全部飘红（"ModuleNotFoundError: fastapi"）。解决：Ctrl+Shift+P → Python: Select Interpreter → 选 .venv\Scripts\python.exe。命令行能跑 ≠ IDE 能跑，两个入口都要指向同一个虚拟环境。

坑在哪
现象原因
终端正常但 VS Code import 全红IDE 解释器没切到 .venv；切到项目虚拟环境即好
uv sync 后代码报缺模块新装的包没进 pyproject（偷懒用 uv pip install 装）；统一走 uv add
克隆源码后别人机器跑不起来只提交 pyproject+uv.lock，别人 uv sync 即可；别拷 .venv 目录
