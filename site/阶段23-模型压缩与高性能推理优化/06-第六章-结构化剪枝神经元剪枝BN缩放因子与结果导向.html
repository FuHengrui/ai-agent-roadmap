第六章　结构化剪枝：神经元剪枝、BN缩放因子与结果导向

阶段 23 · 模型压缩与高性能推理优化　|　剪枝进阶　|　难度 ★★★
这一章在解决什么问题

非结构化剪枝虽然压缩比高，但受制于稀疏硬件落地难。结构化剪枝直接删除神经元/通道，模型结构规整、任何框架都能直接加速。本章回答三个进阶问题：怎么衡量一个神经元重不重要（神经元剪枝）、怎么用 BN 缩放因子当"重要性计分器"（如经典网络瘦身算法）、以及"结果导向剪枝"如何按输出重构优化，最后与"网络瘦身（Network Slimming）"方法合流，覆盖结构化剪枝的主流实战路线。

上一章→本章→下一章 上一章完成了非结构化剪枝（掩码/稀疏度/DNS）。本章转向结构化剪枝：神经元剪枝、BN 缩放因子路线、结果导向剪枝与网络瘦身。下一章开启第二座大山：量化——浮点如何换成低精度表示。
1① 结构化剪枝为什么"香"：规整结构的红利
要解决什么

放弃一部分压缩比也要选结构化剪枝，图的是什么？

核心思路

结构化剪枝在"层内"做整块删除，产出的是规则稠密矩阵（通道/卷积核变少）：

  • 通用算子直接加速：不需要稀疏算子，任何深度框架的卷积/矩阵乘都能享受加速。
  • 结构可复现：剪枝后的模型结构就是一个小模型，可直接导出部署。
  • 内存带宽友好：规则结构利于缓存局部性，实际运行更接近理论速度。

代价：自由度低，压缩比通常不如非结构化。工程选型逻辑：硬件支持稀疏→非结构化（冲压缩比）；硬件普通→结构化（保实际加速）。

坑在哪
现象原因 / 怎么办
拿压缩比一刀切选型结构化压缩比低但实测快，衡量标准是"实测吞吐/延迟"，不是理论数字
以为结构化剪枝=删层结构化剪枝在层内剪通道/卷积核，层结构保留，与深度剪枝（Layer Drop）不同
2② 神经元剪枝：按重要性整删神经元
要解决什么

结构化的最小单元是"神经元"，怎么决定是否删除它？

核心思路

神经元剪枝（Neuron Pruning）：把一整列的权重（一个神经元关联的所有输入连接）删掉。

关键问题：怎么给神经元打分（重要性）？

  • 常用方案：权重向量的 L1/L2 范数——一个神经元的权重向量幅值越大，它对输出的整体贡献越大，越重要。
  • 打分后排序，删掉分数低于阈值的神经元，再微调恢复。

动手流程：

对每一层:
  1. 计算每个神经元的 L2 范数（或 L1）
  2. 按范数排序
  3. 保留范数较大的前 k 个神经元，删除其余
4. 用保留的权重初始化小网络，微调

删除神经元=删除矩阵的一整列，网络宽度变小，宽度 × 深度都规整，直接受益于通用加速。

坑在哪
现象原因 / 怎么办
跨层统一比较范数各层幅值尺度不同，按层比较才公平，避免一层被剪光
只删不微调删除结构后准确性下降，必须微调补偿（同所有剪枝）
3③ BN 缩放因子当"计分器"：网络瘦身思路
要解决什么

除了手动算范数，有没有一种"训练自带"的重要性信号？

核心思路

Batch Normalization（BN）层自带"缩放因子 γ"：BN 输出为 γ·(归一化值) + β。训练时 γ 是可学习参数，γ 越大，该通道对输出影响越大。

因此可以把 γ 当通道重要性的现成计分器：

1. 训练时对 γ 施加 L1 稀疏正则（惩罚，逼 γ 稀疏化）
2. 训练后 γ 接近0的通道 = 冗余通道
3. 按 γ 阈值/排名删除通道
4. 微调恢复精度

这就是经典论文 Network Slimming（网络瘦身） 的核心思路：让网络自己学会"哪些通道没用"，然后剪掉。优点是自动化程度高、与常规训练无缝结合。

坑在哪
现象原因 / 怎么办
给所有γ加一样强的正则稀疏正则强度是超参，太强可能整层通道被剪光，太弱区分不出冗余
忽略 BN 层 γ 与 β 的配合剪通道时要把对应 BN 统计量一并删除，结构要整体联动
4④ L1 稀疏正则：怎么"逼"γ 变 0
要解决什么

网络瘦身中"逼 γ 稀疏"具体是怎么做到的？

核心思路

在损失函数中加入 L1 正则项，作用于 BN 的缩放因子 γ：

loss = 原损失 + λ · Σ|γᵢ|
  • L1 范数的特性：对大的值惩罚小，对小的值惩罚相对大，会把"本就不太重要"的 γ 推向 0，形成稀疏（而 L2 会让值均匀变小，无法稀疏化）。
  • λ 控制稀疏力度：λ 越大，γ 越稀疏，剪枝时能剪的通道越多，但过大可能伤精度。

训练收敛后，γ≈0 的通道直接判定为冗余，进入剪枝流程。这样不需要人为设计重要性公式，网络自己"指认"了冗余通道。

坑在哪
现象原因 / 怎么办
用 L2 正则替代 L1L2 给不出"0"，无法产生稀疏，必须用 L1
λ 调得过大把所有通道都逼近 0 会把模型剪成空壳，λ 要与精度一起观察调节
5⑤ 结果导向剪枝：从输出/损失反推重要性
要解决什么

"看权重大小"可能失真，能不能直接看"它对结果的影响"？

核心思路

结果导向剪枝（Result-oriented / Loss-based pruning）：不直接看权重/γ 的幅值，而是评估"删掉某结构后，对模型输出/损失的影响"。

常见做法：

1. 定义剔除候选（某个通道/连接组）
2. 模拟删除，计算输出变化或损失上升幅度
3. 损失上升小的 → 冗余，可剪
4. 损失上升大的 → 关键，保留

泰勒展开近似是重要实现手段：用一阶梯度信息近似"删掉参数后的损失变化"，避免真的逐一重算。这类方法更"懂任务"，但计算开销更高，常用于追求高品质剪枝的场景。

坑在哪
现象原因 / 怎么办
把"结果导向"与"权重幅值"混用结果导向基于任务损失，权重幅值基于参数本身，后者是前者的近似特例
忽略计算成本逐结构评估开销大，多用梯度近似/批量评估，别真的一个通道一个通道重算
6⑥ 结构化剪枝的常见误区：误伤"宽而浅"结构
要解决什么

结构化剪枝在实施中普遍踩的坑是什么？

核心思路

几个高发误区：

  1. 不看层角色一刀切：网络浅层（特征提取）与深层（语义判别）冗余程度不同，统一剪会误伤关键特征。
  2. 忽略与 BN 的联动：剪通道必须同步删掉对应 BN 的 γ/β 与统计量，否则结构错位。
  3. 训练与剪枝脱节：如果训练时没用 L1 稀疏正则，γ 天生不稀疏，事后按 γ 剪效果差一半。
  4. 只剪一次不迭代：结构化剪枝同样适合"剪→微调→再剪"的迭代策略。

对策：分层定稀疏目标 → 剪前先训好稀疏化（+L1）→ 结构联动删除 → 迭代微调。

坑在哪
现象原因 / 怎么办
剪完直接跑原图前向流程通道数变了，所有下游层的输入维度都要配套重建
忘了 BN 统计量的对齐γ/β/均值和方差与通道一一对应，删除要整套同步
7⑦ 结构化与非结构化：实战中的组合
要解决什么

两种剪枝真的只能二选一吗？

核心思路

实践中经常混用或分场景使用：

  • 场景一（边缘/移动端）：必须结构化剪枝（通道级），因为目标芯片只有通用算子；可搭配量化进一步瘦身。
  • 场景二（云端服务）：若推理引擎支持稀疏（如 SparseGPU/专用库），可用非结构化冲更高压缩比。
  • 场景三（大模型瘦身）：常走"蒸馏减小模型 → 结构化/半结构化剪枝 → 量化"的组合链路。

选型口诀：硬件决定粒度，指标决定松紧，精度决定是否上线。

坑在哪
现象原因 / 怎么办
为追求压缩比忽视硬件硬件不支持稀疏时，非结构化剪出的"压缩比"只是纸面数字
一次组合太多技术剪枝+量化+蒸馏叠加调试难度成倍增加，先小步验证再推广
8⑧ 本章小结：结构化剪枝全路线图
要解决什么

整理结构化剪枝的知识地图，关键在哪几个节点？

核心思路

结构化剪枝的四条技术路线汇总：

① 神经元剪枝：按权重向量范数打分，删低分神经元 → 网络变窄
② BN缩放因子（Network Slimming）：训练加L1正则逼γ稀疏 → 按γ剪通道
③ 结果导向剪枝：按删除后的损失/输出影响排重要性（可用泰勒近似）
④ 迭代策略：剪→微调→再剪，逐步收敛；与量化等可组合

共同铁律：通道删除必须整链路联动（下游层+BN），剪后必须微调。至此剪枝两座山头（非结构化/结构化）收官，下一章进入量化。

坑在哪
现象原因 / 怎么办
只记"剪通道"三个字打分方式（范数/γ/损失）是灵魂，不同打分配不同算法
忘记与后续技术衔接剪枝完还要微调、可再量化，把压缩当"一次动作"还是"一条链路"决定成败

本章小结

这一章覆盖结构化剪枝的三条主线：

路线核心思路代表
神经元剪枝按权重向量范数对神经元打分排序经典通道剪枝
BN缩放因子γ 当重要性计分器，L1 逼其稀疏Network Slimming
结果导向按删除后的损失影响评估重要性泰勒展开近似

操作铁律：整链路联动删除（含 BN、下游层）、剪后必须微调、可迭代进行；硬件普通时优先结构化剪枝。

一句话记住本章：结构化剪枝按"整块"删除神经元/通道——三种打分法各有套路：按权重向量范数删低分神经元、用 BN 层缩放因子 γ（配 L1 稀疏正则）训练出稀疏结构再剪（Network Slimming）、或按"删除后损失影响"做结果导向剪枝；铁律是删通道要整链路联动（BN 与下游层同步删）且剪后必须微调；硬件不支持稀疏加速时，结构化剪枝是比非结构化更靠谱的落地方案。
