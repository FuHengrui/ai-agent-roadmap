第五章　非结构化剪枝实战：掩码、稀疏度与动态网络手术

阶段 23 · 模型压缩与高性能推理优化　|　剪枝实战　|　难度 ★★★
这一章在解决什么问题

上一章有了时机与流程总纲，本章落到工程细节：非结构化剪枝里"掩码（Mask）"怎么生成与锁定、"稀疏度（稀疏率）"设多少合适、"权重幅度 vs 梯度幅度"哪个才是重要性依据、以及经典算法"动态网络手术"如何让被剪的连接复活。这些细节决定剪枝是"精度略降"还是"模型废掉"。

上一章→本章→下一章 上一章讲了剪枝时机与六步流程。本章专攻非结构化剪枝实操：掩码机制、稀疏度选择、重要性判据（Weight/Gradient Magnitude）、动态网络手术。下一章切到结构化剪枝：神经元剪枝、BN 缩放因子与结果导向剪枝。
1① 掩码（Mask）机制：剪枝的"开关矩阵"
要解决什么

剪枝代码里"置0"是怎么在实际训练/推理中生效的？

核心思路

掩码（Mask）：与权重同形状的 0/1 矩阵，标记每个权重"剪掉（0）"还是"保留（1）"。

使用方式：

前向计算: out = (W ⊙ M) @ x
反向更新: W ← W - lr * (grad ⊙ M)
  • ⊙ 是逐元素相乘。
  • 前向时，被掩码的权重乘 0，等于没参与计算。
  • 反向时，梯度同样要乘掩码，被剪掉权重的梯度不更新——否则它们会在微调中"复活"。

这就是上一章提到的"掩码锁定"：Mask 一旦生成，训练期间保持不变（除非用动态网络手术）。掩码最终也被保存下来，配合稀疏存储表示模型。

坑在哪
现象原因 / 怎么办
只在前向乘掩码，反向不乘被剪权重会通过梯度复活，稀疏度立刻"缩水"
把掩码当临时变量掩码是模型的一部分，剪枝后必须随模型一起保存/加载
2② 稀疏度（Sparsity）怎么定
要解决什么

到底剪掉百分之多少合适？稀疏度是谁说了算？

核心思路

稀疏率定义：被置0的连接占比。稀疏率=0.8 意味着剪掉 80% 的连接（保留 20%）。

稀疏度选择的两难：

  • 太保守（如 20%）：省得少，收益不明显。
  • 太激进（如 95%+）：精度大幅下降，甚至无法微调恢复。

工程上的确定方法：

1. 从低稀疏度开始（如 0.5）
2. 逐步提高，观察验证集精度曲线
3. 找到"精度还能接受"的最大稀疏度（拐点）
4. 可多次做"剪枝-微调"迭代，冲击更高稀疏度

结论：稀疏度不是拍脑袋，是"精度-压缩"曲线上的拐点选择，且与模型结构、任务难度强相关。

坑在哪
现象原因 / 怎么办
一步剪到 90%+高稀疏度要渐进，一步到位极易崩精度
用统一稀疏度套所有层不同层冗余不同，逐层设稀疏度（重要层少剪）效果更好
3③ 重要性判据一：Weight Magnitude（权重幅度）
要解决什么

判断"哪个权重不重要"的第一个标准是什么？

核心思路

Weight Magnitude（权重幅度）：用权重的绝对值大小衡量重要性——|w| 越大越重要。

理由：输出 = Σ wᵢ·xᵢ。|wᵢ| 大的项对输出的影响大；把它置0，输出变化明显，所以要保留；|wᵢ| 小的项影响微乎其微，置0损失小。

实现：对所有权重按 |w| 排序，按稀疏度阈值置0（排在后 x% 的剪掉）。这是最简单、最常用的判据（对应工具如 PyTorch 的 torch.nn.utils.prune 默认行为）。

坑在哪
现象原因 / 怎么办
直接看符号不看绝对值权重正负都有意义，重要性看幅值（大小），与符号无关
全网络统一排名不同层的权重幅值尺度不同，最好层内排名，避免某层被剪光
4④ 重要性判据二：Gradient Magnitude（梯度幅度）
要解决什么

除了权重大小，还有别的更"懂训练"的重要性依据吗？

核心思路

Gradient Magnitude（梯度幅度）：用梯度的绝对值衡量重要性——梯度大的权重对损失影响大。

直觉：梯度 = 损失对权重的敏感度。梯度大，说明这个权重稍微一动，损失就显著变化——它是真"干活"的参数；梯度小则类似"摆件"，剪掉无妨。

工程落地：

1. 统计一段时间（若干 batch）的平均梯度幅值
2. 可与权重幅度结合成综合分数，如: score = α·|w| + β·|g|
3. 按 score 排序剪枝

梯度判据更"动态"，能捕捉到训练后期哪些参数仍在被持续更新优化，常用于训练中剪枝。

坑在哪
现象原因 / 怎么办
拿单步梯度判断梯度波动大，要用滑动平均/累计才稳定
把两种判据对立权重幅度+梯度幅度的组合判据往往比单一判据更稳，可调权重系数
5⑤ 经典算法：动态网络手术（Dynamic Network Surgery）
要解决什么

非结构化剪枝"剪了就回不来"，有没有能反悔的算法？

核心思路

动态网络手术（Dynamic Network Surgery, DNS） 是训练中剪枝的经典算法（2017），核心创新是 "再生长"（regrowth）机制：

每一段训练周期:
  1. 正常训练更新所有权重
  2. 用特定判据识别"重要但被剪"的权重（如梯度大）
  3. 让部分"该活"的连接复活（掩码置1）
  4. 再剪掉现在不重要的连接
  → 在剪枝与再生长之间动态平衡

比喻像外科手术：不仅要切除坏组织（剪枝），还要让误切的好组织复活（再生长）。它解决了静态剪枝"一步错步步错"的问题，在 ImageNet 等任务上以更低稀疏度达到更高精度。

坑在哪
现象原因 / 怎么办
以为 DNS 只是"剪了再剪"核心是"再生长"，剪与生双向动态平衡，别忽略 regrowth
把 DNS 当训练后方法DNS 是训练中动态剪枝，需要训练循环配合，不是训完一刀切
忽视实现细节判据选择、再生长比例、调度频率都是超参，需要调
6⑥ 剪枝的 Tips：稀疏度与训练步数
要解决什么

剪枝有哪些 engineering tips？

核心思路

剪枝实操上有几条关键经验：

  1. 稀疏度要"渐进式"提高：不要一次剪到位，逐渐从低稀疏度升到高稀疏度（Sparse Training 风格）。
  2. 开始剪枝的步数：通常在训练前期（部分 epoch 后）开始剪，给模型先学点基础；起步太早结构未成形、太晚则回旋余地小。
  3. 微调/恢复训练步数：剪枝后要给足微调步数，让剩余权重重新适应；步数不足精度回不来。
  4. 分阶段多轮剪枝：剪→微调→再剪→再微调，比单轮大剪更稳。

这些"步数/比例"属于工程经验，具体值随模型与数据集走，需要用验证集试探。

坑在哪
现象原因 / 怎么办
把 tips 里的数值当圣经数值是启发式，不同模型要重测，重点理解"渐进+微调"原则
忽略调度（schedule）设计什么时候开始剪、多快达到目标稀疏度，这些时间表要明确设计
7⑦ 非结构化剪枝与硬件落地：稀疏算子的必要性
要解决什么

非结构化剪枝的理论收益，为什么到了实际部署常常"打折扣"？

核心思路

非结构化剪枝产生的是不规则稀疏矩阵：非0元素位置随机分布，无法直接映射到 SIMD/矩阵乘法加速单元。

  • 有稀疏算子（如 DeepSparse、Intel 稀疏库、部分 IPU/稀疏 GPU 加速器）：能跳过0值计算，理论收益逐步兑现。
  • 无稀疏算子（普通 GPU 上的密集矩阵乘）：矩阵里还是塞满0参与计算，剪了等于白剪（只省存储不省时间）。

所以：

结论：非结构化剪枝的"加速"必须绑定稀疏算子/硬件
如果目标设备不支持 → 优先选结构化剪枝

这一条决定了现实中很多团队"转投结构化"。

坑在哪
现象原因 / 怎么办
用 CPU 密集算预测加速无稀疏算子时非结构化剪枝几乎不加速，实测是唯一标准
以为稀疏度越高硬件收益越大稀疏算子通常要求"每行至少 N 个非0"等约束，稀疏度不是越高越好
8⑧ 本章小结：非结构化剪枝完整操作手册
要解决什么

学完本章，非结构化剪枝的"菜谱"是什么？

核心思路

汇总本章全部操作要点：

掩码：前向与反向都乘 Mask，剪掉的权重永不更新
稀疏度：渐进提高，找"精度-压缩"曲线拐点
重要性：Weight Magnitude（幅度）或 Gradient Magnitude（梯度），可加权组合
动态网络手术：训练中动态"剪+再生长"，允许误剪复活
工程Tips：渐进稀疏、选好开始步数、给足微调步数、多轮迭代
落地前提：必须有稀疏算子/硬件，否则改用结构化剪枝

至此非结构化剪枝的"理论-算法-工程"已闭环，下一章进入结构化剪枝。

坑在哪
现象原因 / 怎么办
学完不评估硬件非结构化剪枝落地前第一件事：确认目标硬件支持稀疏加速
把掩码与稀疏存储混为一谈掩码是训练期控制，稀疏存储是保存/部署格式，两件事

本章小结

这一章完成了非结构化剪枝的实战闭环：

主题核心结论
掩码机制前向+反向都乘Mask，剪掉的权重锁死
稀疏度渐进提高，按精度-压缩曲线拐点定
Weight Magnitude\w\越大越重要，最简单常用
Gradient Magnitude梯度大=敏感=重要，动态判据
动态网络手术剪枝+再生长动态平衡，容错
工程Tips渐进、选时点、多轮微调
落地前提需稀疏算子/硬件，否则选结构化

一句话记住本章：非结构化剪枝的实操三件套——用掩码锁定（前向反向都乘Mask，权重永不复活）、按重要性判据（权重幅度或梯度幅度）排序剪掉、稀疏度渐进提高并给足微调步数；高级玩法"动态网络手术"支持误剪复活；但铁律是"落地必须配稀疏算子/硬件"，否则理论收益在普通GPU上兑现不了，就要转向结构化剪枝。
