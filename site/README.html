二、把链接丢给 AI，让它带你做

这一步能省掉你一半的时间，但有个前提：先分清你手里的是哪类 AI。

两类 AI，别搞混

类型常见的能干什么 / 不能干什么
聊天 AI
（网页、App）		 DeepSeek、豆包、Kimi、通义、文心一言、ChatGPT、Claude、Gemini 能讲步骤、出题、看报错、改代码片段。但它碰不到你的电脑——装软件、跑命令、读文件，都得你自己复制粘贴
能动手的 AI
（装在电脑上）		 国内：DeepSeek Harness（DSH）、WorkBuddy、Trae（字节）、CodeBuddy（腾讯）、通义灵码（阿里）
国外：Cursor、Claude Code、Codex CLI		 能直接读你的文件、替你敲命令、自己看报错。要装、要授权，个别要付费或填 Key

一句话判断：能让它自己在你电脑上装东西的，才是「能动手的 AI」；只是跟你聊天的，再聪明也只能给你抄命令。

给权限之前先看一眼

这类工具拿到的是你电脑的读写和命令权限。第一次用，只给它一个新建的空文件夹（专门学这个项目用），别把整个磁盘或者桌面给它。

路线 A：手里只有网页版 AI（最常见）

也能用，就是多一步「复制粘贴」。流程固定成四步，别跳：

步做什么
1把下面的提示词（含这一章的链接）发给 AI
2它给你一条命令，你在「终端」里敲——Windows 上按 Win + R，输 powershell 回车，出来的黑框框就是
3敲完把黑框框里的输出整段选中复制（右键→标记→框选→回车），原样贴回给 AI
4它给下一条。装完一个，再回来说一句「下一步」
它说「打不开这个链接」怎么办

很多网页版 AI 读不了外部链接。打开那一章，Ctrl + A 全选 → Ctrl + C 复制 → 整段贴给它，再说「这是我正在学的一章」。 贴完再发提示词，它就有内容可依了。

路线 B：用能动手的 AI（Trae / Cursor / WorkBuddy / DSH 都行）

装好之后一般都有个对话框。用法：新建一个空文件夹 → 用它打开这个文件夹 → 把提示词发过去。它会自己在文件夹里建文件、敲命令、跑起来给你看，你只需要盯着它做了没有、报错没有。

好处是不用你复制粘贴；坏处是它改错了你也看不出来——所以每做完一步，问它一句「你刚才改了什么、为什么这么改」。

麻烦你当我的老师，按这一章的顺序带我过一遍，但别复述原文。

这样来：
· 一次只讲一个知识点：先用一句话说清它解决什么问题，再给我一个具体例子；
· 讲完你问我一个问题，让我用自己的话答，你只指出我说错或漏掉的地方，别替我重讲；
· 我答不上来，就换个更小的例子或更土的说法，别直接把结论给我；
· 整章讲完，用三句话收尾：最该记住的、最容易搞错的、接下来该练什么。

开始之前，先用三行告诉我这章大概分几块、每块是干什么的。
为什么不是「给我讲一遍」

听一遍只会觉得懂了。上面这段的核心是讲—问—纠：它讲一段，你用自己的话答一次，它只纠错不重讲。 说不出来，就是没懂——这比「再听一遍」有用得多。

六、最值钱的是「坑在哪」—— 千万别跳过

为什么它最值钱

因为别的地方不会告诉你。

操作类的坑，你搜一下能搜到；但「你以为是这样、其实是那样」这种认知上的坑——没人会主动告诉你，你只会在踩了之后才知道。

整套笔记的「坑」大致分两类：

类型长什么样例子
操作坑 报错 → 原因 → 怎么办 「EXPOSE 8080 写了但外面还是连不上」→ EXPOSE 不是开门，-p 才是
认知坑 ★ 你以为 X，其实是 Y 「以为 RAG 就是向量检索」→ 向量只是检索的一种实现，RAG 是架构

读法建议：第一遍先扫一遍标题就够了，心里有个印象；等到你真动手、真报错了，再回来查这一块——那时候印象会深得多。

七、卡住了怎么办

症状先做这个
报了个错，不知道什么意思用搜索框或 Ctrl + F 搜报错里的关键词 —— 八成就写在某个「坑在哪」里
代码跑不通，但不知道哪错了把报错完整地贴给 AI（别只贴一行），让它先告诉你"哪一行出的事"——第二节有现成的提示词
这一章完全看不懂回去看「在全局框架里的位置」——十有八九是上一章没看
环境装不起来跳到阶段 17 / 18 / 19，那三块专门解决这个
看懂了但不会写正常。看和写之间隔着十遍练习

八、学到什么程度算学会了

最低标准：能答出章末自测题，而且不是靠背的 及格：能对着不懂的人把这个知识点的「要解决什么问题」讲清楚 真会了：能自己写出代码，而且知道换掉某个参数会发生什么
一条最实用的判断标准

学完一个知识点，合上页面问自己：「它要解决什么问题？」 如果你只能说出"它是什么"，说明还停在背的阶段。 能说出"没有它的话，哪里会很难受"——那才是学会了。
