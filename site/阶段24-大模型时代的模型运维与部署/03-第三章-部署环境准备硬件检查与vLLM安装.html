第三章　部署环境准备：硬件检查与 vLLM 安装

阶段 24 · 大模型时代的模型运维与部署　|　环境搭建　|　难度 ★★☆
这一章在解决什么问题

选型定了 vLLM，接下来就是环境：跑大模型服务器不是随便一台机器都行——GPU 型号、显存大小、CUDA 版本都有硬门槛；装库也有讲究（venv 隔离、pip 安装）。本章给出可照抄的部署环境清单与安装步骤，让环境这一步不踩坑。

上一章→本章→下一章 上一章完成了 vLLM 特性与选型对比。本章进入实操第一步：硬件要求核对、Python 虚拟环境准备、vLLM 安装。下一章讲模型下载与启动部署参数。
1① NVIDIA GPU 与显存门槛：先查硬件再谈部署
要解决什么

装 vLLM 之前，机器应该满足什么硬件条件？

核心思路

硬件底线：

硬件项要求
GPUNVIDIA（CUDA 生态）
显存≥ 24GB（能跑 7B~13B 级别模型）
CUDA≥ 11.8

为什么 24GB：7B 模型 FP16 权重≈14GB，再算上 KV 缓存与激活，"刚好塞进 24GB"是能流畅服务的最低线。显存是部署的第一约束，模型/位宽/并发全围绕它设计。

补充常识：

预估显存 ≈ 权重大小(参数量×精度字节) + KV缓存 + 激活
例: 7B × FP16(2字节) ≈ 14GB → 24GB 卡勉强
    7B × INT4(0.5字节) ≈ 3.5GB → 量化后小卡也能跑
坑在哪
现象原因 / 怎么办
只看 GPU 型号不看显存同代卡显存差异巨大，显存才是决定性指标
用 INT4 权重占用来预估 FP16精度不同权重占用差 4 倍，估算前先定精度
无视 CUDA 版本版本过低装不上/跑不动新内核，先 nvidia-smi 查 CUDA
2② 用 nvidia-smi 检查 GPU 与驱动
要解决什么

第一步动手：怎么确认机器 GPU/CUDA 达标？

核心思路

在终端执行：

nvidia-smi

输出应包含：

  • Graphics：GPU 型号（如 RTX 4090、A100）。
  • Memory-Usage：总显存/已用显存（验证 ≥24GB）。
  • CUDA Version：驱动支持的 CUDA 版本（≥11.8 才满足 vLLM 要求）。

如果 nvidia-smi 找不到：说明没有 NVIDIA 驱动/显卡，vLLM 无法工作，需要先装驱动或用 CPU 替代方案（vLLM 基本不适用）。

坑在哪
现象原因 / 怎么办
把驱动 CUDA 当运行库 CUDAnvidia-smi 显示的是驱动支持上限，容器内还要装对应 CUDA 运行库
显存被其他进程占满部署前 nvidia-smi 看已用显存，避免"显存够但被占"的假象
3③ CUDA ≥ 11.8 意味着什么
要解决什么

为什么 vLLM 对 CUDA 版本有硬要求？

核心思路

CUDA 是 NVIDIA GPU 的编程接口，vLLM 的高性能内核（PagedAttention 等）依赖它编译/运行：

  • 版本太低：无法调用新算子/新指令，甚至编译失败。
  • 版本匹配：驱动 ≥ 运行库版本即可（驱动向下兼容，运行库要求写在 vLLM 文档里）。

官方要求 CUDA ≥ 11.8 是底线，建议用当前主流稳定版（如 12.x 系列）——越新对新一代 GPU 与算子的支持越好。注意分清三层：驱动（driver）≥ 运行库（runtime）≥ PyTorch/vLLM 编译版本。

坑在哪
现象原因 / 怎么办
只装驱动不装 CUDA 工具包vLLM 通过 PyTorch 依赖 CUDA 运行库，容器镜像（如 NVIDIA NGC）能省不少事
版本号记混记住"驱动>运行库>框架"的版本金字塔，从上往下兼容
4④ Python 虚拟环境（venv）：隔离是惯例
要解决什么

为什么安装前要建虚拟环境？怎么建？

核心思路

vLLM 依赖的 PyTorch 等包版本敏感，直接装进系统 Python 容易与其他项目冲突（依赖地狱）。标准做法：为 vLLM 单独建虚拟环境。

python -m venv vllm_env        # 创建
source vllm_env/bin/activate   # 激活（Windows: vllm_env\Scripts\activate）

之后所有 pip install 都只影响该环境，互不污染。用 conda 建环境同样可行（conda activate 建环境），原理一致。

坑在哪
现象原因 / 怎么办
跳过 venv 直接装升级其他包时可能把 vLLM 依赖冲垮，生产环境必须隔离
激活后忘了在当前终端换个终端窗口要重新 activate，否则 pip 还装进旧环境
5⑤ 安装 vLLM：一条命令
要解决什么

虚拟环境就绪后，装 vLLM 的命令是什么？

核心思路

核心命令：

pip install vllm

装完验证：

python -c "import vllm; print(vllm.__version__)"

注意事项：

  • 首次安装会拉取 PyTorch、CUDA 相关大包，体积大、耗时长，耐心等待。
  • 网络不稳可换国内镜像源（如清华源）加速。
  • 遇到 Python 版本不匹配时，按 vLLM 文档要求选对应 Python（通常 3.10~3.12）。
坑在哪
现象原因 / 怎么办
安装超时直接重试改用国内镜像/加长超时更有效，别原地反复重试

7⑦ Windows 上的特别提醒
要解决什么

在 Windows 机器上装 vLLM 有什么要注意的？

核心思路

vLLM 生态主要在 Linux：官方预编译与容器镜像都以 Linux 为准。Windows 注意事项：

  1. 官方支持有限：Windows 上 vLLM 需要手动编译或借助 WSL2/Linux 容器，不推荐直接装。
  2. 推荐路线：Windows → WSL2（Ubuntu）→ vLLM；或直接 Linux 服务器/NGC 容器。
  3. 本书默认 Linux 服务器/云 GPU 环境，请按对应 shell 命令执行。

如果坚持 Windows 直装：需满足 CUDA 环境与编译器，按官方 issue/文档折腾，成本高。

8⑧ 本章小结：环境三步走
要解决什么

把环境准备阶段浓缩成可执行清单。

核心思路

环境三步走：

① 硬件核对
   nvidia-smi → GPU型号 / 显存≥24GB / CUDA≥11.8
② 环境隔离
   python -m venv vllm_env → activate
③ 安装验证
   pip install vllm → python -c "import vllm"

这三步完成即具备跑 vLLM 的前提。Windows 用户走 WSL2/容器；Linux/云 GPU 用户直接执行。下一步：下载模型、启动服务。
