第五章　服务验证与基础调用：curl 与 OpenAI SDK

阶段 24 · 大模型时代的模型运维与部署　|　验收实战　|　难度 ★★★
这一章在解决什么问题

服务起来了，怎么确认真能用？验证环节分两路：用 curl 直接打 HTTP 接口看裸响应，用 OpenAI SDK 走"正经客户端"流程。同时把配套的 server.py 源码吃透——它演示了从客户端视角调用 vLLM 服务的标准写法。本章是部署链路最后的"关门验收"。

上一章→本章→下一章 上一章完成了模型下载与服务启动。本章验收：curl 验证 /v1/models 与对话接口、OpenAI SDK 调用、server.py 源码拆解、常见故障排查。至此阶段24 完结，模型部署"从装到用到验"全链路闭环。
1① 验证第一步：curl 查模型列表
要解决什么

服务说"起来了"，怎么用一分钟确认它真的在工作？

核心思路

最轻量的验证：用 curl 请求模型列表接口（OpenAI 兼容格式）：

curl http://localhost:8000/v1/models

成功响应示例（JSON）：

{"object": "list", "data": [{"id": "qwen", ...}]}

看到返回的 id 字段，说明三件事同时成立：服务进程在跑、端口能通、模型加载完成。这个 id 就是启动时配置的 served-model-name，后续所有请求的 model 字段都填它。

坑在哪
现象原因 / 怎么办
curl 连接被拒服务没起/端口错/监听地址不对，回查第四章启动配置
返回的 id 与预期不同客户端请求里的 model 要以返回 id 为准，否则报 404
2② 用 curl 发起一次对话请求
要解决什么

模型列表验证通过，怎么发一条真正的对话？

核心思路

用 curl 直接 POST 对话接口（OpenAI 格式）：

curl http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen",
    "messages": [{"role": "user", "content": "你好，介绍一下你自己"}],
    "max_tokens": 100
  }'

响应里 choices[0].message.content 就是模型生成的内容。要点：

  • model 填 served-model-name（不是本地路径）。
  • messages 是 OpenAI 标准的 role/content 列表。
  • max_tokens 限制本次生成长度。

一个 curl 通了，就证明"服务→模型→生成→回传"整条链路可用。

坑在哪
现象原因 / 怎么办
JSON 格式写错引号/逗号错一个就 400，先本地格式化再提交
model 名填错报模型不存在，回 /v1/models 查真实 id
3③ 用 Python OpenAI SDK 调用
要解决什么

生产代码一般不用 curl，SDK 怎么接？

核心思路

OpenAI 官方 Python SDK（工业标准）：

pip install openai

调用代码（和 server.py 同款思路）：

from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8000/v1",
    api_key="EMPTY",
)
resp = client.chat.completions.create(
    model="qwen",
    messages=[{"role": "user", "content": "你好"}],
)
print(resp.choices[0].message.content)

三个关键点：base_url 指向 vLLM、api_key 随便填（vLLM 本地不校验）、model 填 served-model-name。

坑在哪
现象原因 / 怎么办
base_url 忘了带 /v1路径写错直接连接失败，vLLM 接口都在 /v1 下
api_key 填了真密钥本地 vLLM 不校验 key，填占位符即可，别把真实密钥填进去
model 与返回 id 不一致一切以 /v1/models 返回的 id 为准
4④ server.py 源码逐行拆解
要解决什么

配套的 server.py 只有 9 行，它演示了什么？

核心思路

配套的服务器端示例源码语义（9 行演示）：

from openai import OpenAI       # ① 引入官方 SDK

client = OpenAI(
    base_url="http://localhost:8000/v1",   # ② 指向 vLLM 服务
    api_key="EMPTY",                       # ③ 本地服务key可占位
)

response = client.chat.completions.create( # ④ 发起对话
    model="qwen3-0.6b",                    # ⑤ 模型名（对应当前加载的模型）
    messages=[{"role": "user", "content": "你好"}],
)
print(response.choices[0].message.content) # ⑥ 打印生成结果

核心价值：完整示范了"客户端 ↔ vLLM 服务"的最小可用代码——接入 vLLM 的服务调用范式就是这 6 步，看懂它即掌握接入方式。

坑在哪
现象原因 / 怎么办
照抄 model 名不核对server.py 里的模型名要与实际 served-model-name 一致，换模型要改
只用 print 不用异常处理生产代码要 catch 网络/超时错误并做重试，示例仅教学用途
5⑤ 流式输出的客户端写法
要解决什么

上一章提过流式输出，客户端代码怎么开？

核心思路

OpenAI SDK 加一个参数即可开启流式：

resp = client.chat.completions.create(
    model="qwen",
    messages=[{"role": "user", "content": "讲个故事"}],
    stream=True,          # 开启流式
)
for chunk in resp:        # 逐块读取
    delta = chunk.choices[0].delta.content
    if delta:
        print(delta, end="")

优势：

  • 首 token 更快到达（不用等全部生成完）。
  • 逐段输出，用户体感接近 ChatGPT。
  • 配合 vLLM 前缀缓存与连续批处理，高并发下体验更好。

教学要点：流式与普通模式的唯一差别就是 stream=True + 迭代响应。

坑在哪
现象原因 / 怎么办
忘了迭代流式对象stream 模式必须 for 循环消费，直接取 choices 会拿不到内容
