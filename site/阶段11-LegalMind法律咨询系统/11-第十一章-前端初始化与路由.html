1① 工程初始化：Vue3 + Vite8 + Tailwind4 + Pinia
要解决什么

一个现代前端项目怎么快速立起来？工具链选型本身就有讲究：Vite 管构建、Tailwind 管样式、Pinia 管状态、Vue Router 管页面。

核心思路

目录结构约定（src 下三大目录，各司其职）：

src/
├── api/        # axios 封装 + 各资源 API（chat.js、documents.js、cases.js、auth.js）
├── stores/     # Pinia 状态（auth.js、chat.js）
├── router/     # 路由表 + 守卫
├── views/      # 页面组件
├── components/ # 可复用组件
├── App.vue
└── main.js
  • Vite8 + Vue3 组合是最新稳定组合：Vite 负责开发热更新与生产构建。
  • Tailwind4 用 CSS-first 配置（无需 tailwind.config.js，靠 @import "tailwindcss" 一行进 CSS）。
  • 图片、字体等静态资源统一放 public/。
坑在哪
现象原因 / 怎么办
npm run dev 报 Node 版本不支持Vite8 要求较新的 Node；先 node -v 看版本，版本不够就装对应 LTS，别硬降 Vite 版本绕行
@import "tailwindcss" 放进 style.css 但页面没有样式Tailwind4 的 CSS-first 配置要确保这条 import 在全局样式文件里、且被 main.js 引用了；检查构建日志有没有 tailwind 相关内容
2② main.js：Pinia + Router 挂载顺序
要解决什么

main.js 是前端入口，它决定"全局有哪些能力"。挂载顺序有讲究：Pinia 必须在 Router 之前——因为路由守卫里要用 Pinia store（auth）判断登录态。

核心思路 
import { createApp } from 'vue'
import { createPinia } from 'pinia'
import App from './App.vue'
import router from './router'
import './style.css'

const app = createApp(App)
const pinia = createPinia()

app.use(pinia)      // 1. 先 Pinia：让守卫能用 auth store
app.use(router)     // 2. 再 Router：守卫里访问 useAuthStore() 才有值
app.mount('#app')

为什么必须先 Pinia 后 Router：Vue Router 的全局前置守卫在路由导航前执行，守卫里要 useAuthStore() 判断登录态；而 useAuthStore() 必须等 Pinia 安装后才能工作（否则报 "getActivePinia was called with no active Pinia"）。顺序反了，前端直接白屏。

坑在哪
现象原因 / 怎么办
报错 "getActivePinia was called with no active Pinia"Pinia 还没安装就在守卫/组件外调 useAuthStore；把 app.use(pinia) 放到 app.use(router) 之前，且不要在 store 外提前调用
3③ 路由表：五路由 + meta 元信息
要解决什么

应用有哪些页面？哪些登录才能进？路由表 + meta 一次性说清楚，守卫逻辑只认 meta。

核心思路

router/index.js：

const routes = [
  { path: '/', component: HomeView, meta: { requiresAuth: false } },
  { path: '/login', component: LoginView, meta: { requiresAuth: false, guestOnly: true } },
  { path: '/chat', component: ChatView, meta: { requiresAuth: true } },
  { path: '/documents', component: DocumentsView, meta: { requiresAuth: true } },
  { path: '/cases', component: CasesView, meta: { requiresAuth: true } },
  { path: '/:pathMatch(.*)*', component: NotFoundView },
]

const router = createRouter({
  history: createWebHistory(),
  routes,
})
  • meta.requiresAuth=true：chat/documents/cases 三页必须登录。
  • meta.guestOnly=true：login 页对已登录用户反而不该看到（登录了还看登录页？跳回首页）。
  • 404 兜底路由 /:pathMatch(.*)*：输错地址给友好的 NotFound 页。
坑在哪
现象原因 / 怎么办
404 兜底路由放在最前面，所有页面全变 404路由匹配按顺序，/:pathMatch(.*)* 必须放在路由表最后；放在前面会吞掉所有真实路由
4④ 路由守卫：beforeEach 三行逻辑
要解决什么

"没登录不能进 chat"怎么落地？全局前置守卫在每次导航前执行：读 meta → 查登录态 → 决定放行还是踢去登录页。

核心思路 
router.beforeEach((to, from, next) => {
  const authStore = useAuthStore()
  const requiresAuth = to.matched.some((r) => r.meta.requiresAuth)

  if (requiresAuth && !authStore.token) {
    next({ path: '/login', query: { redirect: to.fullPath } })
  } else if (to.meta.guestOnly && authStore.token) {
    next('/')
  } else {
    next()
  }
})

三行核心逻辑：

  • requiresAuth 且无 token → 踢到 /login，并带上 redirect（登录成功后自动跳回原页面）。
  • guestOnly 且已登录 → 去首页（别浪费登录页）。
  • 其余 → 放行。
  • 用 to.matched.some() 而非 to.meta：子路由继承父路由 meta，深层路由也能取到。
坑在哪
现象原因 / 怎么办
直接读 to.meta.requiresAuth，嵌套路由永远 false子路由的 meta 不会自动合并父级；用 to.matched.some(r => r.meta.requiresAuth) 逐级向上找
守卫里用 next() 处理完异步再 next，页面跳转错乱现代 Vue Router 推荐直接 return true / { path } 替代 next；至少保证每次导航只调用一次 next

6⑥ axios 拦截器：自动带 token、统一 401 处理
要解决什么

现象原因 / 怎么办

401 跳转造成死循环（登录页自己也发 401 请求）响应拦截器对 /login 相关请求或已处于登录页时跳过重定向，否则死循环白屏
