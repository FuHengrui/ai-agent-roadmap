第十一章　LLaMA-Factory 框架：训练方法与数据集注册

阶段 12 · 大模型高效微调与对齐技术　|　|　难度 ★★★
这一章在解决什么问题

到目前你练过"手写 LoRA"和"Unsloth 提速"两套方案，但每次还要搭环境、写代码。LLaMA-Factory 是"微调界的全家桶"：一个框架覆盖全参数/高效/量化三大类十几种子方法，WebUI / 命令行 / API 三套入口，把微调从"写代码"变成"配配置+点按钮"。

这一章回答：

  1. LLaMA-Factory 是什么、支持哪些训练方法、你的项目该选哪个；
  2. 环境怎么装（软硬件清单 + 一键安装）；
  3. 最重要的是：数据集注册——自己收集的指令数据怎么变成这个框架认得的格式（dataset_info.json 登场）。

目标不是"换库"，而是理解"框架帮你封装了什么、你仍需负责什么"。

这一章在整个知识库里的位置 前五章：手写 + Unsloth 两套微调路线（原理与工具加速） 本章 ← 你在这里：LLaMA-Factory 认识 → 环境安装 → 数据集格式与注册（dataset_info.json） 下一章：WebUI 微调 + SwanLab 监控——点按钮训练，全过程可视化（阶段 12 收官） 再往后：整个阶段结束，你能在三种技术路线间按需选择 阶段终点：手写懂原理 → Unsloth 提速 → LLaMA-Factory 提效
1① LLaMA-Factory 是什么：一个框架管全部
要解决什么

微调方法太多了：全参数、LoRA、QLoRA、Freeze、DoRA……再叠加不同轮术，排列组合十几套。LLaMA-Factory 的核心价值就是：一套框架、统一入口，切换方法只改一个参数。这一节建立全局认知。

核心思路

LLaMA-Factory 定位：

维度说明
训练方法全参数微调 / LoRA / QLoRA / DoRA / Freeze / GaLore / BAdam / Adam-mini 等
研究+场景指令微调、偏好对齐（DPO/ORPO/PPO）、多模态、评估
入口WebUI（浏览器界面）、命令行 CLI、Python API
支持模型Llama、Qwen、DeepSeek、Mistral、Gemma 等主流开源阵容

为什么它"一个顶三"：

  • 你的手写 LoRA 相当于只实现"LoRA"一种方法；
  • 换方法/换模型时，你手写要改代码，LLaMA-Factory 只改 YAML 配置或界面下拉框。

但注意边界——它封装了 LoRA 的训练执行，不等于你不需要懂原理（第 4~7 章此时继续回本）：换数据、排查 loss、判断效果，靠的还是你已经掌握的底层知识。

坑在哪
现象原因 / 怎么办
"用框架就不用学原理了"框架把复杂藏起来，一出问题反而更难排查。原理是排错的地图——本阶段顺序（先手写后框架）就是为此设计
十几种子方法吓退主线只重点用 LoRA/QLoRA（效率和原理你已通）；其他方法了解即可。先精两个，再广了解
把 LLaMA-Factory 当"只支持中文模型"主流开源模型都支持，只是中文生态好。按任务语言选模型，不是按框架限制
2② 训练方法速查：全参数 vs LoRA/QLoRA vs Freeze
要解决什么

框架里第一个要填的选择就是"训练方法"。四个候选（全参数、LoRA、QLoRA、Freeze）分别花多少显存、训多快、效果多好？这一节用一张表说清，帮你按电脑配置选。

核心思路
方法可训练参数显存速度效果适用
全参数全部最高慢最好显存充裕、要做深度对齐
Freeze后若干层中中中想过渡试试
LoRA补丁（~1%）低快接近全参默认首选
QLoRA补丁 + 4bit最低快稍降低显存首选

选择决策树：

  1. 显存 < 12GB → QLoRA；
  2. 显存 12~24GB、任务简单 → LoRA；
  3. 显存 24GB+、任务复杂（深度指令/对齐） → 全参数；
  4. 只想快速试水 → Freeze 或直接 LoRA。

呼应前文：QLoRA / LoRA 就是你已掌握的 LoRA+量化组合，只是现在一个下拉框搞定。

坑在哪
现象原因 / 怎么办
显存 8GB 硬选全参数必 OOM。按决策树先算显存，8GB 走 QLoRA
以为全参数一定"最值"效果最好但成本最高；LoRA 在许多任务上 90%+ 效果、10% 成本。按任务复杂度选，别无脑全参
Freeze 和 LoRA 选不明白其实就是"冻层训层"vs"加补丁"。默认 LoRA/QLoRA，Freeze 只在想对照实验时用
3③ 环境安装：软硬件要求 + 一键装
要解决什么

框架有了，装之前先看它的软硬件要求——版本不匹配（python3.9 环境、torch2.0、transformers4.49、peft0.14、trl0.8.6）全是踩雷区。这一节给清单+安装命令+验证。

核心思路

软硬件依赖：

组件建议版本
Python3.9+（示例环境）
PyTorch2.0+（CUDA 版）
transformers4.49.0（LLaMA-Factory 对此版本有绑定）
peft0.14.0
trl0.8.6
显卡NVIDIA，显存按上节决策树

4④ 数据集格式：Alpaca 与 ShareGPT 两种模板
要解决什么

框架统一用 JSON 文件管理数据，但字段名有讲究：Alpaca（单轮 instruction/input/output）与 ShareGPT（多轮 conversations 数组）。这块写错，数据加载直接失败——这一节把两种格式切开看。

核心思路

Alpaca 格式（单轮，第 9 章已见，重复以示对比）：

[
  {
    "instruction": "解释什么是神经网络",
    "input": "",
    "output": "神经网络是由多层神经元组成的计算模型……"
  }
]

ShareGPT 格式（多轮对话）：

[
  {
    "conversations": [
      {"from": "human", "value": "介绍下你自己"},
      {"from": "gpt", "value": "我是基于……的 AI 助手"},
      {"from": "human", "value": "你会什么？"},
      {"from": "gpt", "value": "我会……"}
    ]
  }
]
维度AlpacaShareGPT
形态单轮指令-回答多轮对话
字段instruction/input/outputconversations[from/value]
适用指令数据集对话/助手数据

选定一种，全文件保持一致；混用会导致框架解析错乱。

坑在哪
现象原因 / 怎么办
单轮数据硬套 ShareGPT缺 from/value 结构报错。单轮用 Alpaca，多轮用 ShareGPT，别混
conversations 里 from 值填错了（如写 "user" 而非 "human"）字段值有约定。human/gpt 是示例约定，按框架文档写对；写错角色对调，训练出来的模型会"反着说话"
JSON 少个逗号/括号框架解析失败是最常见错误。先 python -m json.tool 文件.json 校验再喂给框架
5⑤ dataset_info.json：数据集的"注册表"
要解决什么

数据文件备好了，框架还"不认"。要让 LLaMA-Factory 认识它，得在 dataset_info.json 里登记：文件路径 + 字段映射（columns）+ 标签（tags）。这是框架数据侧的"户籍系统"。

核心思路

先看框架默认的 data/dataset_info.json，注册一条自己的数据集（义形式）：

{
  "my_training_data": {
    "file_name": "my_data.json",
    "columns": {
      "prompt": "instruction",
      "query": "input",
      "response": "output"
    },
    "tags": {
      "role_tag": "from",
      "content_tag": "value"
    }
  }
}

逐字段翻译：

  • file_name：数据文件（和 dataset_info.json 同目录）；
  • columns：把框架标准字段（prompt/query/response）映射到你的文件字段（instruction/input/output）；
  • tags：ShareGPT 多轮格式里角色/内容字段名（from/value）。

登记后，WebUI 数据集下拉框里就会出现 my_training_data——选中即用。

坑在哪
现象原因 / 怎么办
忘登记，WebUI 里找不到自己的数据只放文件不登记 = 没户口。改 dataset_info.json 加一条（或用 WebUI 上传按钮自动登记）
columns 字段名和你文件对不上框架按映射取字段。逐字段核对：prompt↔instruction / response↔output
文件路径不对（放错目录）file_name 是相对 data/ 的路径。确认文件在 data/ 下，否则报 file not found
6⑥ 注册中文医疗数据：一个完整案例
要解决什么

这里用中文医疗数据集做一个完整注册示范——这是本阶段"数据集注册"的标准例题。照它走一遍，你就掌握了"任意垂直领域数据进框架"的通用流程。

核心思路

流程四步：

  1. 备数据：chinese_medical.json（Alpaca 结构，instruction/input/output）；
  2. 放位置：拷进 data/ 目录；
  3. 注册：dataset_info.json 加条目：
{
  "chinese_medical": {
    "file_name": "chinese_medical.json",
    "columns": {
      "prompt": "instruction",
      "query": "input",
      "response": "output"
    }
  }
}
  1. 验证：WebUI 里训练页的数据集下拉框能找到 chinese_medical，能预览前几条。

验证时不点训练，先看"预览样本"对不对——包括 system 提示是否自动拼接（LLaMA-Factory 会按模板拼），这一步能提前暴露字段错位。

坑在哪
现象原因 / 怎么办
医疗数据里 input 字段全空空 input 合法（query 可无）；但要和模板一致。预览确认拼接后的文本完整，别只盯原始 JSON
预览内容乱/错位字段映射错了。回 dataset_info.json 核对 columns；再不行用 python 打印一条样本看字段
数据集太大，WebUI 预览卡只取 query 示例即可，预览本身只载前几条。响应慢不代表错，耐心等
7⑦ 数据质量管理：喂给框架前先过筛
要解决什么

框架不校验数据质量，烂数据照样开训——然后你收获一个"拉胯模型"。上线前必须过质量关：去空、去重、查短长、查标签对错。这一节的检查项与第 5 章呼应，但按框架的数据形态再走一遍。

核心思路

四道筛子（可写成脚本跑）：

#检查说明
1空 contentoutput/response 为空的剔除
2重复样本去重（同 instruction+output）
3超长/超短长度异常的剔（token 量化后再看，或先按字符粗筛）
4角色标签对ShareGPT 里 from 值规范（human/gpt 交替合法）

示例（Python 粗筛思路）：

import json
with open("data/chinese_medical.json", encoding="utf-8") as f:
    data = json.load(f)

clean = [d for d in data
         if d.get("output") and len(d.get("output", "")) > 10]
print("原始:", len(data), "清洗后:", len(clean))

再对接第 12 章的患病监控思路：清洗比例、条目数记录进文档，训练前心里有数。

坑在哪
现象原因 / 怎么办
跳过清洗直接训空样本让 loss 抖动、重复样本让模型学说车轱辘话。清洗是 10 分钟，返工是 2 小时
清洗脚本和训练数据分开，忘了同步清洗结果另存 _clean.json 并在 dataset_info.json 指向清洗版。文件名里带 clean 标记，避免误用旧版
清洗过头（把所有长答案都删了）长度阈值别拍脑袋。看一眼数据长度分布（print 前 50 条长度），设合理阈值
