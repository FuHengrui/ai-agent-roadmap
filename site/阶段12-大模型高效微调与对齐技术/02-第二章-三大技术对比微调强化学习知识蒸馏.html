第二章　三大技术对比：微调·强化学习·知识蒸馏

阶段 12 · 大模型高效微调与对齐技术　|　|　难度 ★☆☆
这一章在解决什么问题

"让模型变得更强"这件事，市面上至少有三条路：微调、强化学习、知识蒸馏。你刷帖时看到"DeepSeek 用 RL 训练出推理能力""小模型蒸馏大模型""微调让模型懂业务"——听起来都是"改造模型"，到底是一回事还是三回事？选错路线，项目方向直接跑偏：你花三个月微调想得到"更聪明的模型"，其实该走强化学习；你想"压缩模型部署到手机"，却在一头扎进微调。

这一章把三条路线并排摆开，讲清各自的目标、数据需求、成本、应用场景，以及背后的"异同"——学完你就能在不同场合准确说出"这事该用哪种手段"。

这一章在整个知识库里的位置 上一章（微调全景）：定义了微调是什么、全量/高效怎么选——你认识了第一条路线 本章 ← 你在这里：把微调和强化学习、知识蒸馏放一起对比——"让模型变厉害"的三条路，各管一摊 下一章：LoRA 原理——回到微调主线，深挖高效微调里最主流的 LoRA 为什么高效 再往后：手写 LoRA → Unsloth → GGUF/Ollama → LLaMA-Factory，全都是"微调"这条路线的落地 阶段终点：你能判断"这个需求该微调、该 RL、还是该蒸馏"，并且亲手跑通微调全流程
1① 微调：让 AI 更聪明（适应任务）
要解决什么

三大技术里你其实已经认识第一个了，但它和强化学习、蒸馏的区别，光靠上一章的印象还不够。先把微调单独钉死定义，后面对比才不会散。

核心思路

定义：微调 = 在已预训练的大模型基础上，用较少的任务特定数据对模型再训练，以适应特定任务。

三层要点：

维度微调的特征
目标用少量标注数据优化预训练模型，适应具体任务（文本分类、问答、生成）
特点计算量相对小，在有限数据和资源下提升特定任务性能
应用下游任务：情感分析、机器翻译、推荐系统

一句话记忆：给一个已经聪明的模型"补课"，让它专精某一科。 这套思路本阶段接下来八章都在实践。

坑在哪
现象原因 / 怎么办
以为微调是"从零教模型做任务"微调的前提是预训练已教会语言与常识，只补任务专业度；从零训练是另一个量级的工程。这一阶段的微调代码都是 from_pretrained 加载底座，没有一个人从随机权重开始
以为微调后"什么任务都能干活了"微调是改行为，不是换底座。它擅长把模型从一个领域调到另一个领域；模型本身的推理上限由底座决定，微调突破不了这个上限
2② 强化学习：让 AI 更能决策（试错拿奖励）
要解决什么

"我不只想要模型会答，我想要它自己在复杂环境里做一连串最优决策"——这是微调解决不了的问题，因为微调学的是"给定输入给正确输出"，而决策要的是"在动态环境里不断行动、不断调整"。DeepSeek-R1 的推理能力、AlphaGo 的棋力，都来自这条路。

核心思路

定义：强化学习（Reinforcement Learning）= 通过与环境互动，学习如何最大化长期奖励。它和微调的本质区别：微调是"看数据学"，强化学习是"行动-反馈-调整"。

维度强化学习的特征
目标通过与环境的交互，学习最优行为策略，最大化累积奖励
特点强调动态决策，靠探索与利用的平衡优化策略；不依赖预定义数据集，依赖与环境的持续交互
应用游戏 AI（AlphaGo）、机器人控制、自动驾驶

什么是"探索与利用"：已知的动作能拿稳定奖励（利用），没试过的动作可能拿更高奖励（探索）——智能体不断平衡这两者，最终学到最优策略。

坑在哪
现象原因 / 怎么办
以为"RL 就是给模型打分然后微调"RLHF（人类反馈强化学习）确实"套在"微调流程里，但 RL 的核心是环境交互 + 策略迭代；做 LLM 对齐时，环境=奖励模型/规则，交互=生成-评分-更新。直接拿"评分高的回答"当监督学习用，是简化版不是 RL
以为"RL 需要的数据少，好上手"RL 训练不稳定、超参多、成本高（后面的对比表里计算成本就是"高"）。没有专门环境/奖励设计，别轻易上 RL
3③ 知识蒸馏：让 AI 更高效（小模型学大模型）
要解决什么

模型越强参数越多，部署到手机、边缘设备、低功耗终端就成了难题——一个 70B 模型你不可能塞进手机。有没有办法"把大模型的能力压缩进小模型"？这就是知识蒸馏干的事。

核心思路

定义：知识蒸馏 = 把复杂、计算密集的教师模型的知识，转移到小型、高效的学生模型上。学生模型通过学习教师模型的决策过程/表示，在保留较高性能的同时，大幅降低计算和存储成本。

维度知识蒸馏的特征
目标通过教师模型"知识转移"帮助小模型提升性能，尤其在计算受限设备上
特点核心是知识迁移，在模型压缩和部署上有优势；学生性能接近教师，但参数量小得多
应用模型压缩、边缘计算、低功耗设备部署

一个直觉类比：大模型是教授，小模型是实习生——实习生不重读一遍博士课程，而是跟着教授做事、学教授的判断方式，最后干活水平接近教授但身价比教授便宜得多。

坑在哪
现象原因 / 怎么办
把蒸馏和"量化"混为一谈量化（GGUF 的 Q4 等）是压缩同一个模型的数值精度，参数量不变；蒸馏是训练一个新小模型，参数量本身更小。两者可以叠加，但原理完全不同
以为"蒸馏后小模型 100% 等于大模型"学生模型只能接近教师，会损失一部分能力（尤其长尾知识）。蒸馏适合"够用就好"的场景，不能指望无损还原
4④ 核心对比表：三兄弟同框
要解决什么

单独讲各有各的道理，但真到选型时你需要一张"并排歧视"的表——目标、数据、成本、场景四列一对照，几分钟就能定位。

核心思路

一张表直接背：

方法微调强化学习知识蒸馏
核心目标让大模型适应具体任务让 AI 通过试错找到最优策略让小模型学到大模型的知识
数据需求需要少量特定任务数据需要环境交互数据需要教师模型的知识
计算成本低 - 中高低
应用场景文本分类、机器翻译游戏 AI、自动驾驶轻量化 AI 部署

加三个判读技巧：

  • 想让它懂行 → 微调
  • 想让它会决策 → 强化学习
  • 想让小模型变强/想部署到小设备 → 知识蒸馏

三者不是互斥的，实战中经常组合：先预训练（底座）→ 微调对齐（懂行）→ RLHF 强化（会决策）→ 蒸馏成小模型（好部署）。

坑在哪
现象原因 / 怎么办
只看"计算成本"一列选型成本低不代表适合：蒸馏"成本低"是因为教师模型已经训好了，你自己还得先有个强教师；微调"成本低中"也要求数据质量。选型顺序是目标→场景→成本，不是反过来
想"用蒸馏解决任务能力不足"蒸馏是搬运知识不是创造知识。教师弱，学生只会更弱；任务能力不足该换更强的底座或走微调/RL 路线，蒸馏解决不了
5⑤ 一句话总结与使用心法
要解决什么

三兄弟定义和表格都背了，但记忆最牢固的方式是"一句话画像"——遇到新问题，先对号入座。

核心思路

三句话总结，是本章的"压缩包"：

技术一句话画像
微调让 AI 更聪明（适应特定任务）
强化学习让 AI 更能决策（学会最优策略）
知识蒸馏让 AI 更高效（小模型学习大模型）

再用身份打个比方（不容易忘）：

  • 微调 = 转岗培训（员工还是那个员工，换了个岗位能力）
  • 强化学习 = 实战练兵（在真战场试错，练出最优打法）
  • 知识蒸馏 = 师傅带徒弟（教授把毕生功力压缩传给新学生）
坑在哪
现象原因 / 怎么办
以为"更聪明/更能决策/更高效"是同一个目标的不同说法三个词对应三种完全不同的优化对象：知识（微调）、策略（RL）、容量（蒸馏）。项目里混着用，就会做出"微调想提推理、蒸馏想降错误率"这种错配
背完一句话就去开发，不看场景细节一句话是快速入口不是决策终点：真下手前还要看数据形态（有没有环境？有没有教师？）——见下一个知识点
6⑥ 选型三步法：从需求走到技术
要解决什么

概念都懂，一到真实需求就懵："用户抱怨模型不会写合同""老板要上手机端""模型推理总是一本正经胡说"。把模糊需求翻译成"该用哪条路线"，是本章实用性最高的技能。

核心思路

一个需求翻译三步法：

第一步 问：用户到底缺什么？
   "回答不专业/不合规"  → 缺"懂行" → 微调
   "决策/规划/推理不灵" → 缺"策略" → RL（或换更大底座）
   "模型太大跑不动"    → 缺"容量适配" → 蒸馏/量化

第二步 问：我手上有什么原料？
   有领域数据 → 微调可走
   有环境/奖励信号 → RL 可走
   有强教师模型 → 蒸馏可走
   什么都没有 → 先停：方案还没成立，别硬选

第三步 问：成本与时效允许吗？
   快速验证 → 微调（LoRA 数小时）
   长期重投入 → RL（周级）
   部署受限 → 蒸馏+量化（容量和精度权衡）

实际案例：电商客服"答得不标准"→ 数据现成 → 微调（LoRA）；手机端要跑 7B 模型 → 先量化，不行再蒸馏 + 量化 → 部署路线。

坑在哪
现象原因 / 怎么办
"用户说不够聪明，我就上 RL""不够聪明"十有八九是任务数据或检索没喂好，直接上 RL 又贵又慢。先排查 prompt/RAG/微调，RL 是最后一张牌
"先选技术再找理由"常见病：因为"RL 听起来高级"就上 RL。选型必须先有需求缺口 + 原料证据，再定技术，顺序反了项目必烂尾
7⑦ 三大路线在 LLM 工程里的真实位置
要解决什么

脱离 LLM 工程背景看三兄弟都是"理论课"；真实项目里，它们其实分布在大模型生命周期的不同阶段。搞清楚位置，你才知道自己正在哪一环。

核心思路

把大模型生命周期画成流水线，三兄弟各站一段：

预训练（底座，通用能力）
   │
   ▼
SFT 微调（懂行：领域数据 + 指令数据）★ 本阶段主线
   │
   ▼
RLHF / PPO（对齐价值观、提升推理）★ 强化学习路线
   │
   ▼
蒸馏 / 量化（压缩部署：GGUF、小模型）
   │
   ▼
推理服务（Ollama、VLLM、WebUI）

关键判断：

  • 微调（SFT）是几乎所有 LLM 项目的必经一步：先让它懂你的领域；
  • 强化学习是对齐/推理增强的进阶：数据难造、成本高，一般公司不急用；
  • 知识蒸馏 + 量化是部署阶段的"最后一公里"：模型训好了，怎么塞进你的设备才是问题（第 10 章 GGUF/Ollama 就是部署侧）。

所以本章不是"三选一"，而是帮助你判断"我目前在哪个环节、下一步该动哪个技术"。

坑在哪
现象原因 / 怎么办
以为"这个阶段只做微调，RL 和蒸馏与我无关"术语无关，问题有关：部署时你会遇到"模型太大"（蒸馏/量化）、对齐时你会听到"RLHF"。知道它们的存在和边界,遇到时才知道往哪查
把"蒸馏"当"学习率/训练技巧"蒸馏是训练流程再造（学生模仿教师输出），不是调参。框架里它通常作为独立的训练目标出现，不是 TrainingArguments 里哪个开关
8⑧ 本章决策卡：一句话跳出答案
要解决什么

最后把所有判断浓缩成一张"应急决策卡"，遇到场景直接查——这也方便你日后复习时一眼抓住重点。

核心思路

把整章内容压缩为四行决策卡：

你的需求路线一句话理由
让它回答得更专业/更合规矩微调（SFT/LoRA）智力够，缺业务细节 → 补课
让它自己会决策/打游戏/控机器人强化学习需要动态策略 → 实战
让它变小变快还能部署知识蒸馏（+量化）知识搬运压缩 → 拜师
多技术组合（DeepSeek-R1 等）预训练→SFT→RL→蒸馏工程流水线，本来就串着来

记不住整段也没关系，把"聪明/决策/高效"三个词记住，就能在 90% 的讨论里对上号。

坑在哪
现象原因 / 怎么办
决策卡没有覆盖"换底座/换硬件"的选项这是另一条增产路（不调模型，换更强的底座或加显卡），机械套卡会漏解。卡内优先，卡外记得：先看底座和硬件有没有余量
把决策卡当"必须遵守的唯一路线"项目情况千变万化，卡只是启发式起点；任何技术选型最终都要回到数据可得性和算力预算做二次确认

本章小结

这一章你实际拿到的是：

拿到了什么为什么要紧
三兄弟的准确定义微调=懂任务、强化学习=最优策略、蒸馏=知识搬运——目标先分清，路线不会跑偏
