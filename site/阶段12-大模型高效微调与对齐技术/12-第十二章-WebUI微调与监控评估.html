1① 启动 WebUI：llamafactory-cli 一行起服务
要解决什么

LLaMA-Factory 的图形界面怎么起来？答：一条命令起本地 Web 服务，浏览器操作。这一节给出启动方式、页面结构、以及"服务起不来"的常见原因。

核心思路

启动（命令行）：

llamafactory-cli webui
# 浏览器自动打开 http://localhost:7860

页面四个主标签（对应框架四大能力）：

标签干什么
Train训练（选模型/方法/数据/参数）
Chat加载模型对话评估
Evaluate跑评估指标
Export导出 LoRA 合并/转换

起不来的排查顺序：

  1. 依赖装齐没（llamafactory-cli --version）；
  2. 端口被占（换 --port）；
  3. 换 Python 环境后 gradio 版本冲突（重装匹配版 gradio）。

另外：本机磁盘不足时后台模型加载会异常，训练前看一眼剩余空间。

坑在哪
现象原因 / 怎么办
命令找不到 command not found没装 llama-factory 或不在当前环境。确认 pip install 成功、换到 factory_env 再试
浏览器打不开 localhost:7860服务没起来（看终端报错）/端口冲突。换 --port 7861 再启动
WebUI 打开但下载模型卡死网络/HF 镜像问题。设 HF_ENDPOINT 镜像（第 10 章思路）或手动放模型到缓存路径
2② 模型与路径设置：选模型、选量化、配保存
要解决什么

Train 页顶部"模型名称、微调方法、模型路径"是最先要填的三项。它们对应什么、QLoRA 怎么开、LoRA 权重存哪——填错一步训练启动即报错。

核心思路

Train 页关键字段：

字段填什么说明
模型名称下拉选（如 qwen2.5 系列）模型家族
微调方法lora / qlora / fullQLoRA 是本章首选（低显存）
模型路径本地路径或 HF 名没试过的先去 Chat 页验证能加载
数据集勾选第 11 章注册的 chinese_medical支持多选
附加路径LoRA 输出目录（如 saves/medical-lora）可含中文名
学习率2e-4（LoRA 常规起点）第 6 章学过的参数现在变成填表
训练轮数教材示例 3~5数据量大可 1~2

量化开关：QLoRA 方法下选 4bit（或按显存选 8bit）。

先 Chat 后 Train 是好习惯：在 Chat 页把模型加载通、确认路径可用，再回 Train 页开训，把"模型加载失败"这类问题在训练前暴露。

坑在哪
现象原因 / 怎么办
训练开始即报模型加载错模型路径/HF 名错。先去 Chat 页验证模型能加载，别在 Train 页硬试
数据集下拉找不到你的数据没注册或注册后没重启 WebUI。刷新/重启 webui 让 dataset_info.json 生效
输出路径和已存在 LoRA 重名会被覆盖。每次实验用新目录名（如 saves/medical-lora-v2），保留历史
3③ 训练参数页：把学过的超参翻译成表单
要解决什么

WebUI 的"训练参数"页字段很多，但每一个都对应你学过的概念：train batch size、gradient accumulation、learning rate、warmup、logging steps……这一节给一张"表单字段 ↔ 第 6 章概念"对照表，避免瞎填。

核心思路

对照表（左：WebUI 字段；右：对应概念/推荐值）：

WebUI 字段对应概念默认/推荐
批处理大小（per_device_train_batch_size）每卡批次4（显存小→2）
梯度累积gradient_accumulation_steps2~4（等效 batch=乘积）
学习率learning_rate2e-4
训练轮数num_train_epochs3
warmup 步数warmup_steps5~100（按总步数）
日志间隔logging_steps10~50
最大序列长度max_seq_length2048
权重衰减weight_decay0.01
优化器optimadamw_torch / adamw_8bit

填表口诀：显存不够 → 降 batch + 提累积；要更快 → 适当加大 batch（显存允许）——和第 6 章三维取舍完全一致，只是从代码变成表单。

第一次跑的建议：全部用框架默认，只改"数据轮数/学习率/输出路径"三个，跑通后再微调其余——少变量更容易定位问题。

坑在哪
现象原因 / 怎么办
字段看不懂就全开最大并行度/长度开太大直接 OOM。先用默认值跑通再逐步加
忘看"总步数"就调 warmupwarmup 和总步数要匹配（总步数少 warmup 就小）。先预览总步数（日志第一行会打印）
把训练超参改来改去不记录参数是实验变量。固定一套基准，每次只动一个变量，并记进实验清单
4④ 开始训练：队列预览、点提交、看日志
要解决什么

参数填完，界面上的"开始"怎么按、按完看什么？这一节讲 WebUI 训练的交互节奏：预览命令、提交队列、日志区三个信号，以及"卡在 0/1"的心态。

核心思路

训练侧的三个区块：

区块作用观察点
预览命令点"预览命令"看将要执行的完整命令行（含全部参数翻译）核对关键参数没填错
训练日志启动后滚动输出loss/epoch/learning_rate 三行
状态区当前队列状态（queued/running）是否真的在跑

操作节奏：

  1. 填好参数 → 点"预览命令"（习惯性核对）；
  2. 点"开始" → 看日志出现 loss 行；
  3. loss 应逐步下降，训练完成日志显示 "Training completed"。

"卡在 0% 很久"的两个真实原因：模型还在下载/加载（看终端下载进度）；或数据预处理大（多进程转换，dataset_num_proc 可调）。不是死机，等一等。

坑在哪
现象原因 / 怎么办
预览命令和你预期不符总比在界面上猜安全。逐项对照参数，发现错位立刻改表单
训练中断（显存/磁盘）检查点已自动存（按保存策略）。续训：回到 Train 页选"检查点路径"勾 resume（框架支持续训）
日志乱跳/有 WARNING大多是显存碎片或调度警告，非致命。看有没有 ERROR / 训练是否继续推进判断
5⑤ SwanLab 接入：训练可视化监控（API Key 走环境变量）
要解决什么

光看终端日志不过瘾也不直观。SwanLab 是实验跟踪平台：训练曲线、超参对比、项目归档全部云端可视化。这一节完成接入——并特别示范密钥纪律：API Key 走环境变量，绝不写进代码/文档。

核心思路

SwanLab 三步接入：

# 2. 登录并拿 API Key（https://swanlab.cn 注册后，个人设置里生成）
#    示例：你的密钥长这样：<your_swanlab_api_key>（不要抄真实值！）

# 3. 本地终端（Linux/macOS）或设置面板导入环境变量
export SWANLAB_API_KEY="<your_swanlab_api_key>"
# Windows 命令提示符：set SWANLAB_API_KEY=<your_swanlab_api_key>
# 1. 安装 SDK
pip install swanlab
# 4. 启动 LLaMA-Factory 训练时同时启动 swanlab 日志开关
llamafactory-cli train config.yaml --use_swanlab

关键纪律（必读）：

  • API Key 是账号钥匙；示例里出现过的 SwanLab Key 可能是真实密钥，这里一律用 <your_swanlab_api_key> 占位；
  • 密钥只进环境变量，不写入 .py/.yaml/.md/任何会被提交的配置；
  • 泄露了立即去 SwanLab 设置里吊销重建。

WebUI 里的选项：训练参数页通常有 "use_swanlab" 开关；勾上后日志会显示 SwanLab 项目 URL，点开就是实时曲线面板。

坑在哪
现象原因 / 怎么办
训练日志卡在 "Waiting for SwanLab"Key 没配/配错。检查环境变量已 export，再重启训练
把 Key 写进 YAML 配置并共享配置会漂进仓库/文档，等于钥匙交给别人。只走环境变量，任何配置文件里出现真实 Key 一律视为泄露
曲线面板开了但全是空白训练刚启动数据未回传 / 网络问题。等前几个 step 日志回传再看；还有问题查 swanlab 官网项目页
6⑥ 训练完成：SwanLab 曲线的判读
要解决什么

训练完毕，SwanLab 面板里一堆曲线。哪些值得看、什么形态算"训好了"？这一节把"监控"落到"判断"：loss 曲线、学习率曲线、可能出现的过拟合形态。

核心思路

SwanLab 面板重点看三组：

曲线健康形态异常形态
train/loss下降后趋平不降=学习率低/数据错；陡升=爆了
eval/loss（如有）下降后趋平回升=过拟合（第 6 章同款判读）
learning_rate按 warmup+调度变化突变=配置错

实操建议：

  • 开训后定时瞄一眼（不用盯着），异常立刻停（省电省时间）；
  • 同一个数据集不同参数跑两组，SwanLab 能对比曲线，这是它比终端日志强的地方；
  • 把最终 loss 值和主要参数记进实验记录，作为"这版模型训得如何"的档案。

"完美训练"不存在的判据：看到 loss 平稳下降即可收工；追求更低 loss 属于另一阶段（数据扩容/换模型）。

坑在哪
现象原因 / 怎么办
只盯 train/loss 下没下降过拟合靠 eval/loss 看出。有 eval 数据就同时看两个
curve 全绿就觉得"一定能用"loss 低≠业务好用。最终判决看下一节 Chat 实测，监控只是第一道闸
曲线对比时参数记混SwanLab 面板按 run 管理。每个实验起清楚的名字（数据量_方法_参数）
7⑦ Chat 评估：训练完立刻实测
要解决什么

训练的最终裁判不是曲线，是"问它问题它答得怎么样"。LLaMA-Factory 的 Chat 页就是干这个的：加载 LoRA 权重 → 对话实测 → 与原始模型对比，验证微调是否达到预期（第 7 章对比思路的界面版）。

核心思路

具体流程：

# 方式一：命令行加载检查点
llamafactory-cli chat --model_name_or_path Qwen2.5-7B \
  --adapter_name_or_path saves/medical-lora
# 方式二：WebUI 的 Chat 页
# 模型路径=底座，附加路径=你的 LoRA，点"加载模型"

实测三条线（每线 2~3 个问题）：

线问什么看什么
训练集内数据集里类似问题风格/知识点是否被学到
领域泛化未在数据里的医疗问题是否迁移而不是死记
通用能力常识/闲聊通用知识是否崩坏

判定标准：领域回答有明显提升、通用能力不掉 = 成功；领域提升但常识崩 = 过拟合，回第 6 章调参。

坑在哪
现象原因 / 怎么办
Chat 页加载后答非所问模板/系统提示没按模型卡配（第 10 章 TEMPLATE 同款坑）。在 Chat 页确认模板选择
只测训练集问题就宣布成功背题不是本事。必须测训练集外的问题（第 7 章同款结论）
微调后通用能力崩了过拟合/数据偏科。减轮数、降学习率、扩数据三选，重跑一轮再评估
