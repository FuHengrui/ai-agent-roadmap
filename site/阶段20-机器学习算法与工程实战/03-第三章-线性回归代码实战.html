这一章在解决什么问题

前两章是理论：模型是直线、损失是 MSE、最优解是解析解。这一章把它落地成能跑的代码，完成"造数据 → 手写解析解 → sklearn 一行建模 → 画图看效果"的完整闭环。

学完这一章你会得到两个资产：

  1. 一套固定的代码套路：numpy 造数据、矩阵运算、模型 fit/predict、可视化——后面所有章节都复用。
  2. 对"模型=参数"的实感：亲手算出 w0、w1 的那一刻，"机器学习"就祛魅了：它不过是一堆数字的加减乘除。
上一章→本章→下一章 上一章推导出解析解 w* = (XᵀX)⁻¹Xᵀy。本章前半是开发环境准备（Anaconda/Jupyter 简述），后半是代码实战：用 numpy 造模拟数据 → 手写解析解 → sklearn 的 LinearRegression 对比 → 可视化。下一章进入梯度下降法：解析解太慢，我们改用"一步步下山"的方式求最优解。
1① 开发环境：Anaconda + Jupyter Notebook
要解决什么

写 Python 机器学习代码，环境装什么、在哪写、怎么组织？环境折腾不好，代码再对也跑不起来。

核心思路

推荐的组合（阶段 17 已详细讲过环境搭建，这里只给最小配置）：

  • Anaconda：自带的 Python 解释器 + 预装 numpy / scipy / matplotlib / sklearn 等全部常用库，一步到位，无需一个个 pip。
  • Jupyter Notebook：Anaconda 自带，支持分格执行——一段代码一个格子，边写边看输出，特别适合算法学习。
  • 打开方式：Anaconda Navigator 启动 Jupyter，或命令行输入 jupyter notebook。

本阶段所有代码都建议在 Jupyter 里逐格跑：数据格、训练格、画图格分开，哪步出错肉眼可见。

坑在哪
现象原因 / 怎么办
环境装了一堆库还是 import 报错大概率有多个 Python 环境混用；在 Jupyter 里先 import sys; print(sys.executable) 确认用的是 Anaconda 的 Python
代码在 Jupyter 能跑，命令行跑不了Jupyter 内核绑定了 Anaconda 环境；命令行也要用同一个解释器（conda activate 后再跑）
2② 用 numpy 制造模拟数据
要解决什么

真实数据集还没拿到之前，怎么先验证"解析解公式对不对"？——自己造一份"已知答案"的数据：真实的 w 是我们定的，让算法算出来跟我们定的对比。

核心思路

用 numpy 的随机函数造一份线性数据：

import numpy as np

np.random.seed(1)               # 固定随机种子，保证每次结果一致
X = 2 * np.random.rand(100, 1)  # 100 个样本，1 个特征，值域 [0,2)
y = 4 + 3 * X + np.random.randn(100, 1)  # 真实公式 y=4+3x，再加正态噪声
  • np.random.seed(1)：把随机数"存档"，下次运行得到同一批数据——复现实验结果的前提。
  • np.random.rand(100,1)：100×1 的 0~1 均匀分布矩阵，×2 放大到 [0,2)。
  • np.random.randn(100,1)：标准正态噪声（均值 0、方差 1）。
  • 真实参数：w0=4，w1=3（后面算法算出来应该接近这个值）。
坑在哪
现象原因 / 怎么办
不设 seed，每次跑结果都变随机数无罪，复现才重要；正式实验一律先设 seed
忘了加噪声，数据全在直线上那解析解会完美回归真实参数，但太"假"；噪声让模拟更接近真实世界，也测试模型的抗噪能力
3③ 给 X 拼接全 1 列（X_b）
要解决什么

解析解公式和 sklearn 建模时，截距 w0 去哪了？模型 y = w0 + w1·x 是两个参数，但 X 矩阵只有一列 x。

核心思路

技巧：给 X 左边拼一列全 1，得到 X_b。这样：

y = w0·1 + w1·x = [1, x] · [w0, w1]ᵀ

把"截距求值"变成"普通权重求值"，整个模型统一成矩阵乘法 y = X_b·w，解析解公式直接套用，无需特判截距。

X_b = np.c_[np.ones((100, 1)), X]   # 左边拼一列 1，形状 (100, 2)

np.c_ 是"按列合并"：把常数 1 列和 X 并排放。

坑在哪
现象原因 / 怎么办
忘了拼全 1 列，结果预测永远过原点模型变成 y = w1·x，少一个自由度；截距必须靠这一列 1 吸收
把列 1 拼在右边位置无所谓，只要公式对应 w 的顺序一致即可；习惯拼左边更直观
4④ 手写解析解：np.linalg.inv 一步求解
要解决什么

公式都推导好了，代码怎么写？这是本节的高光：5 行代码算出最优参数。

核心思路

按解析解公式 w* = (XᵀX)⁻¹Xᵀy 逐段翻译：

w_best = np.linalg.inv(X_b.T.dot(X_b)).dot(X_b.T).dot(y)
print("w0 =", w_best[0], " w1 =", w_best[1])
# 输出接近 w0=4, w1=3（因为有噪声不会完全相等）
  • X_b.T：转置（100×2 → 2×100）。
  • X_b.T.dot(X_b)：2×2 矩阵。
  • np.linalg.inv(...)：求逆。
  • 最终结果：2×1 的列向量，即 [w0, w1]。

这就是"机器学习"第一次实体化：所谓学到的模型，就是这两个数字。

坑在哪
现象原因 / 怎么办
报 LinAlgError: Singular matrixXᵀX 不可逆：特征列线性相关或样本太少；删冗余列或加样本
手写矩阵运算是为了炫技？不是：它让你理解 sklearn 内部在做什么；而且大矩阵场景下 np.linalg.pinv（伪逆）更稳
5⑤ sklearn 一行建模：LinearRegression
要解决什么

手写过了、原理懂了，但实际工程总不能每次都求逆。sklearn 把线性回归封装成了几行代码。

核心思路 
from sklearn.linear_model import LinearRegression

lin_reg = LinearRegression()   # 创建模型对象
lin_reg.fit(X, y)              # 训练：内部解正规方程
print("w0 =", lin_reg.intercept_, " w1 =", lin_reg.coef_)
  • fit(X, y)：传入特征矩阵和标签向量，自动完成求解。
  • intercept_：截距（w0）。
  • coef_：权重数组（w1...wn）。
  • sklearn 内部自动处理了"全 1 列"这件事，所以这里传原始 X 即可，不用 X_b。

统一接口再次印证第一课的话：所有算法都是 fit 训练、predict 预测。

坑在哪
现象原因 / 怎么办
fit 后忘调 predict，拿模型对象直接当函数模型对象不是函数；预测要显式 lin_reg.predict(X_new)
X 传成一维数组报错sklearn 要求 X 是二维（m×n）；一维要 reshape：X.reshape(-1, 1)
6⑥ 做出预测并可视化
要解决什么

参数算出来了，效果怎么样？得把预测线画出来和真实点放一起比对——这是所有 ML 项目的第一步验收。

核心思路 
import matplotlib.pyplot as plt

X_new = np.array([[0], [2]])          # 取两个端点
y_pred = lin_reg.predict(X_new)       # 预测这两点的 y

plt.plot(X, y, "b.")                  # 真实数据：蓝点
plt.plot(X_new, y_pred, "r-")         # 拟合直线：红线
plt.xlabel("x"); plt.ylabel("y")
plt.show()

观察点：红色拟合线应穿过蓝色散点的"中间地带"，而不是穿过所有点——因为噪声数据本身不共线。手感比数字更能验证模型有没有学对。

坑在哪
现象原因 / 怎么办
画出来线歪得离谱先检查数据是否线性；再检查是否忘了拟合截距（拼列/参数设置）
在 Jupyter 里画图不显示Notebook 里加 %matplotlib inline；脚本环境则必须 plt.show()
7⑦ 用测试集验证：新增未知样本
要解决什么

拟合效果好，但那是"做过的题"。怎么模拟"没见过的新数据"来验证泛化？

核心思路

简单方案：把 100 个样本切出大部分训练、留一部分当测试：

X_train, X_test = X[:80], X[80:]
y_train, y_test = y[:80], y[80:]

lin_reg.fit(X_train, y_train)
y_test_pred = lin_reg.predict(X_test)

rmse = np.sqrt(np.mean((y_test - y_test_pred)**2))
print("测试集 RMSE =", rmse)
  • 训练集只学前 80 条，后 20 条从未参与训练，属于"线上验证"。
  • RMSE（开方后的 MSE）单位是 y 的原始单位（这里 y 量级在 4~10，RMSE ≈ 1 量级即正常，因为噪声标准差就是 1）。

评估只看测试集误差——这是贯穿全阶段的铁律。

坑在哪
现象原因 / 怎么办
拿训练集 RMSE 当成"模型水平"那是"背答案"成绩；必须看测试集，测试集误差才是真实泛化能力
简单地"前 80 后 20"切分数据有顺序相关性时这种切分不公平；正式做法用 train_test_split 随机切（实战里会用到）
8⑧ 认识模型的"工件"：参数就是模型本身
要解决什么

训练完模型存哪了？模型到底是个什么对象？理解这一点，才能理解"部署模型"。

核心思路

对线性回归而言，模型 = 一组参数 + 预测公式：

  • lin_reg.intercept_ + lin_reg.coef_ 就是全部"知识"。
  • 预测公式：y = w0 + w1·x1 + ... + wn·xn，是程序内写死的一行代码。
  • 所以保存模型 = 保存这两个数组；加载后无需重新训练即可预测。
import pickle
with open("lin_model.pkl", "wb") as f:
    pickle.dump(lin_reg, f)          # 把整个模型对象存盘
# 下次直接用：
# with open("lin_model.pkl", "rb") as f:
#     model = pickle.load(f)
#     model.predict(X_new)

这套"训练 → 存盘 → 加载 → 预测"是生产环境的标准流程，后续章节（保险实战、逻辑回归音乐分类器）都会用到。

坑在哪
现象原因 / 怎么办
每次预测都重新训练一遍白烧算力；训练一次、序列化保存、部署时只加载
用 pickle 加载陌生来源的模型文件pickle 能执行任意代码，只加载你信任的模型文件（安全常识）

本章小结

代码会说话了，来盘点本章的产出：

步骤代码产出
造数据np.random.seed + rand + randn已知真实参数 (4,3) 的模拟数据
