第十五章　集成学习：森林、Boosting 与梯度提升

阶段 20 · 机器学习算法与工程实战　|　集成学习　|　难度 ★★★
这一章在解决什么问题

上一章结尾抛了句狠话：单棵决策树"精度一般"。那怎么救？——"三个臭皮匠，顶个诸葛亮"：把一堆弱模型组合成一个强模型，这就是集成学习（Ensemble Learning）。这一章学两大门派 + 一个王牌：

  • Bagging 门派：并行训练一堆"各自为战"的树，投票/平均——代表作随机森林（Random Forest）。
  • Boosting 门派：串行训练，后一棵树"专治前一棵树的错"——代表作Adaboost 和 GBDT（梯度提升决策树）。

GBDT 尤其值得高度重视：它是 XGBoost、LightGBM、CatBoost 这些"Kaggle 霸主"的祖师爷，也是当前表格数据领域最强的模型家族。学完本章，你手里就有了对抗绝大多数结构化数据的"终极大招"。

1① 集成学习总览：越乱越好 vs 越错越补
要解决什么

"集成"具体怎么把弱模型变强？两大门派的核心机制分别是什么？

核心思路

集成学习 = 训练多个基学习器（弱模型），再按规则组合（投票/平均/加权）。两大门派：

门派训练方式代表作关键直觉
Bagging（并行式）各模型独立并行训练随机森林人人有票：让模型各不相同，平均掉彼此的错误
Boosting（串行式）模型逐个串行，后一个学前一个的错Adaboost、GBDT循序渐进：每人专治前人的病，最后合力
  • 共同前提：基学习器要"好而不同"——都得比瞎猜强一点（好），又不能一模一样（不同，否则集成=单模型）。
  • 为什么有效：若每个模型错误是"随机独立"的，误差会互相抵消；Bagging 靠"随机性制造差异"，Boosting 靠"关注错样本制造差异"。

至此，解决单树"精度一般"的方案正式登场。

坑在哪
现象原因 / 怎么办
集成 100 个完全一样的决策树一模一样=啥也没集成，投票结果与单树无异；必须注入随机性（Bagging）或序列纠错（Boosting）
基学习器太弱（比瞎猜还差）集成救不动；基学习器至少比随机的略好是前提
2② Bagging：随机抽样的并行投票
要解决什么

"一群树并行投票"具体怎么实现？为什么不直接重复训练同样的树？

核心思路

Bagging（Bootstrap Aggregating，自助采样聚合）：

  1. 从训练集有放回地随机抽样（bootstrap）造出 n 个不同的"自助样本集"（每个和原数据等大，有的样本重复出现、有的缺席）。
  2. 在每个自助集上训练一棵独立决策树。
  3. 预测时：分类投票（多数票），回归平均。
  • 为什么要"有放回"：让每棵树的训练数据各不相同（差异 → 错误独立 → 可抵消），还不浪费样本。
  • Bagging 的效果：方差显著下降（单棵树"跳得厉害"，一群树"平均下来稳"），偏差基本不变。
  • 额外福利：未被抽中的样本（约 1/3，OOB 袋外样本）天然可当验证集评估——不需要额外切验证集让 Bagging 比"单树+手工验证"更省事。

Bagging 本质：用"并行 + 平均/投票"换稳定性。

坑在哪
现象原因 / 怎么办
有放回抽样的结果和原数据"差不多"就不加随机差异正是关键；把"不放回"理解成普通切分=没有 Bagging 效果
忘了 OOB 可以免切验证集随机森林自带 oob_score_，避免"反复看测试集"的泄漏（联合上一章教训）
3③ 随机森林：Bagging + 特征随机
要解决什么

Bagging 只随机了"行"（样本）；如果所有树都用同一策略挑特征，还不是一模一样？——随机森林再抽"列"（特征）。

核心思路

随机森林（Random Forest） = Bagging 决策树 + 特征子采样：

  • 除了每棵树用不同自助样本，每次分裂只在随机抽出的"特征子集"里挑最优切分（分类默认 √n 个特征；回归默认 max_features=1.0，即全部特征，p/3 只是 Breiman 的经验建议）。
  • 双随机（行随机 + 列随机）让树之间的差异被拉满，从而大幅压低方差、抗过拟合。

                            random_state=42, oob_score=True)
rf.fit(X_train, y_train)
print(rf.score(X_test, y_test))
print(rf.oob_score_)        # 袋外验证分数（免切验证集）
print(rf.feature_importances_)   # 特征重要性（集成后更稳）
  • n_estimators：树的数量（默认 100），越多越稳但有收益递减。
  • 重要福利：特征重要性（多棵树平均）比单树更可靠，直接做特征筛选。

调参三板斧：n_estimators（越多越稳）、max_depth/min_samples_leaf（剪枝防过拟合，同单树）、max_features（控制列随机强度）。

坑在哪
现象原因 / 怎么办
n_estimators 拉到 1 万收益递减且慢；100~500 常见，用 OOB 曲线确认"够用"即可
忘了设置 max_depth深树+随机森林仍有泄漏风险；规范设置两个剪枝参数
把 oob_score 当万能OOB 是袋外验证（out-of-bag，每棵树没用到的那些样本），它和真正的留出测试集都要看（两者口径不同）
4④ Adaboost：给"错题"加权的串行提升
要解决什么

Boosting 门派的思路：串行纠错。Adaboost 具体怎么"记住前树的错误"？——给样本加权。

核心思路

Adaboost（Adaptive Boosting，自适应提升）流程：

  1. 第一棵弱树在原始数据上训练，所有样本权重相等。
  2. 算这棵树的加权错误率，并给树一个话语权 α（错误率越低、α 越大）。
  3. 提高被分错样本的权重、降低分对样本的权重（"错题加粗标记"）。
  4. 下一棵弱树在重新加权的数据上训练（被迫更关注错题）。
  5. 反复 N 轮，最终预测 = N 棵树的加权投票（α 越大话语权越大）。
  • 关键数学：样本权重更新公式 w_i ← w_i · exp(α·[y_i≠ŷ_i])——错题权重乘大、对题权重乘小，归一化后继续。
  • 思想一句话："这轮谁错了，下轮就多练谁"——像错题本学习法。
from sklearn.ensemble import AdaBoostClassifier
ada = AdaBoostClassifier(n_estimators=50, random_state=42)
ada.fit(X_train, y_train)
  • 优势：偏差快速下降（比 Bagging 更能"啃硬骨头"）。
  • 风险：对噪声很敏感（离群点被强行加倍关注 → 模型被脏数据带偏）；数据噪声大时优先 Bagging。
坑在哪
现象原因 / 怎么办
以为 Adaboost 每棵树都在"重新采样"数据数据不变，变的是样本权重（模型训练时要支持 sample_weight，决策树支持）
数据噪声大还硬上 Adaboost错题里混着噪声，越练越偏；噪声场景优先随机森林（鲁棒）
5⑤ GBDT：让树去拟合"残差"的梯度提升
要解决什么

Adaboost 用"加权错题"难再接大模型；换个更普适的框架：每一轮新树去拟合"上一轮整体预测的残差（错误）"。这就是 GBDT 的核心——梯度提升（Gradient Boosting）。

核心思路

GBDT（Gradient Boosting Decision Tree）流程（以回归为例）：

  1. 初始预测：常数（如均值）。
  2. 计算残差 r_i = y_i - ŷ_i（"还差多少没预测对"）。
  3. 训练一棵小树，专门拟合残差（输入 x，输出逼近 r_i）。
  4. 更新预测：ŷ = ŷ + 学习率 × 新树输出。
  5. 重复 2~4 若干轮：每一轮都在"补前一轮的缺口"。

为什么叫"梯度提升"：残差其实就是 MSE 损失关于预测值的负梯度（对 ŷ_i 求导 J=(1/2)(y-ŷ)² → 负梯度 = y-ŷ = 残差）。所以整套路子就是用树去拟合损失函数的负梯度——框架与第 4~6 章"梯度下降"同构，只是"下降的单位"从参数更新变成"加一棵树"。 （对分类任务：把树拟合目标换成"分类损失（log loss）的负梯度"，公式不同但框架一致。）

三个必须知道的概念：

  • shrinkage（学习率）：每轮新树贡献缩水（0.01~0.1），换取更多轮次、更稳收敛。
  • n_estimators：树的数量（轮数）。
  • subsample：每轮随机抽一部分样本训练（行随机），缓解过拟合（随机梯度提升）。
坑在哪
现象原因 / 怎么办
把"拟合残差"理解成"拟合 y"第 3 轮以后树拟合的是残差（y-当前预测），不是原始 y；这是 GBDT 和 Adaboost 的分水岭
学习率设 1 还想多轮叠加学习率大 → 前期全押注首棵树 → 过拟合；学习率设小（0.1 或 0.05）+ 树多加
6⑥ 随机森林 vs GBDT：两派正面交锋
要解决什么

两大门派都强，工程里到底选谁？给一张"打架"的决策表。

核心思路
维度随机森林（Bagging）GBDT（Boosting）
训练方式并行，互不影响串行，链式依赖
降低什么方差（稳定）偏差（精准）
对噪声鲁棒敏感
调参少（early 就很好）多（学习率、树数要配合）
表格数据精度强更强（普遍实战结论）
训练速度可并行，快串行，慢
高维稀疏（文本）一般表现弱（树不适合稀疏）
代表实现sklearn RFsklearn GBDT / XGBoost / LightGBM

选型一句话：追求上限、数据干净 → GBDT 系（XGBoost/LightGBM）；求稳、不想调参、有噪声 → 随机森林；稀疏高维（文本/ID 类）→ 线性模型或 LR，别硬用树。 树家族在"纯表格、中高维稠密"数据上是王者。

坑在哪
现象原因 / 怎么办
表格数据一上来就神经网络表格数据的王是树系（RF/GBDT），深度学习赢在图像/文本；先跑树系基线再谈别的
稀疏高维还硬堆 GBDT树按"阈值切分"，稀疏特征信息被稀释；LR/线性+正则更合适
7⑦ GBDT 工程实战：从分类到回归一鱼两吃
要解决什么

GBDT 代码怎么用？sklearn 接口把分类/回归分成两个类，各自字段要记清。

核心思路 
from sklearn.ensemble import GradientBoostingClassifier, GradientBoostingRegressor
from sklearn.model_selection import train_test_split

# 分类任务
gbc = GradientBoostingClassifier(n_estimators=200, learning_rate=0.1,
                                 max_depth=3, random_state=42)
gbc.fit(X_train, y_train)
print(gbc.score(X_test, y_test))
print(gbc.feature_importances_)       # 特征重要性

# 回归任务（如保险花销，第九章的进阶候选）
gbr = GradientBoostingRegressor(n_estimators=100, learning_rate=0.1,
                                max_depth=3, random_state=42)
gbr.fit(X_train, y_train)

三件事：

  1. max_depth=3 是经典配置：GBDT 的树要"浅而多"（弱学习器接力），深树反而过拟合。
  2. learning_rate（shrinkage）+ n_estimators 是搭配调：学习率小 → 树要多；一般 grid 一起搜。
  3. 评价照旧：分类 accuracy/混淆矩阵、回归 RMSE。

性能预告：sklearn GBDT 只是"教学级实现"；工业实战请用 XGBoost / LightGBM / CatBoost（更快、更强、可 GPU），原理同 GBDT 框架——学通本章后再换库几乎零成本。

坑在哪
现象原因 / 怎么办
GBDT 树的深度拉到 10+深树+串行 = 狂过拟合；默认 3 起步，浅树多位接力才显功力
分类/回归类搞混GradientBoostingClassifier vs Regressor 字段独立；别把分类评估（accuracy）用到回归任务上
学了 GBDT 就忘 sklearn 的相对慢大数据换 XGBoost/LightGBM；概念已在手，换库是 API 迁移不是重学
8⑧ 实战综合：用集成模型客场挑战保险数据
要解决什么

集成模型到底比基线强多少？回到第九章的保险花销数据，用随机森林/GBDT 客场打一场"换武器"对照。

核心思路

沿用第九章的流程（标准化、切分），只换模型部分：

from sklearn.ensemble import RandomForestRegressor, GradientBoostingRegressor
from sklearn.metrics import mean_squared_error
import numpy as np

from sklearn.linear_model import Ridge   # 基线模型要用

models = {
    "Ridge(基线)": Ridge(alpha=10),
    "RandomForest": RandomForestRegressor(n_estimators=200, max_depth=8, random_state=42),
    "GBDT": GradientBoostingRegressor(n_estimators=200, learning_rate=0.1,
                                      max_depth=4, random_state=42),
}
for name, model in models.items():
    model.fit(x_train_s, np.log1p(y_train))
    rmse = np.sqrt(mean_squared_error(np.log1p(y_test),
                                      model.predict(x_test_s)))
    print(f"{name}: 测试 RMSE={rmse:.4f}")

预期：随机森林/GBDT 的测试 RMSE 大致持平或略低于 Ridge 基线，不是「明显」——这份数据才 1338 行、又是哑变量为主，线性模型本来就很难被打败。树系的优势在于能自动发现特征交互（如"吸烟×肥胖"），但要显示出差距得靠更大的数据或更细的调参。具体数字以你实跑为准，别拿本节当基准。 更进阶的对比口径：学习率配 0.05 + 树数 500 再试，探索"deep 基线 vs 树系"的差距。

注意：树系不用归一化也行，但这里沿用同一管线保持公平对比；实践上建议"树系不动 scaler、线性模型带 scaler"各自最佳化后再比。

坑在哪
现象原因 / 怎么办
对比时只换模型不统一口径公平对比 = 同一套切分(同 random_state)、同一目标(log1p)、同一评估(RMSE on 测试集)
树多了就把 max_depth 也拉大RF/GBDT 同样要剪枝（max_depth/min_samples_leaf），深树在集成里也过拟合
9⑨ 特征重要性：树家族白送的"筛选器"
要解决什么

"哪些特征最重要"是每个项目的灵魂问题。树系模型怎样免费回答？

核心思路
  • 特征重要性 ≈ 该特征在树分裂中被选中的频次 × 带来的不纯度下降（按树/森林平均）。
  • sklearn 一行出：model.feature_importances_，值归一化成和为 1。
  • 用法一：直接写报告（"吸烟、BMI 是花销最强预测因子"——与第九章 EDA 结论互证）。
  • 用法二：递归消除/阈值筛选——把重要性低的列删掉重训，精简模型。
import matplotlib.pyplot as plt
imp = gbr.feature_importances_
plt.barh(range(len(imp)), imp)
plt.yticks(range(len(imp)), feature_names)
plt.show()

工程纪律：重要性与数据分布绑定，特征一换、数据一变就作废，不得跨数据集套用。

坑在哪
现象原因 / 怎么办
只看重要性不看方向重要性只有"量级"没有正负（树不输出方向）；要"正负影响"请回看线性模型的 coef_
把重要性当全局真理单次划分的噪声也会进重要性；多跑几次、用交叉验证或置换重要性复核才稳

要解决什么

核心思路

决策树家族关系图（背这一条链）：

决策树（单树：可解释、易过拟合）

本章小结

集成学习三巨头收工：

算法机制一句话特征适用
随机森林Bagging：行随机+列随机，并行投票/平均稳、抗噪、少调参默认基线、有噪声
AdaboostBoosting：错题加权，串行训练偏差降得快、怕噪声数据干净、分类
GBDTBoosting：逐轮拟合残差（负梯度）精度上限高、参数配对调表格数据追求上限
关键参数n_estimators / learning_rate / max_depth学习率小+树多+浅树按数据规模调
免费福利oob_score / feature_importances_免验证集、特征筛选所有树系项目

一句话记住本章：集成学习 = 一群"好而不同"的树团战——Bagging 并行各练各的再投票（随机森林加一重列随机，稳而抗噪），Boosting 串行"专治前树的错"（Adaboost 给错题加权、GBDT 让新树直接拟合残差即负梯度，浅树多棵+小学习率精度封顶）；表格数据处理不了的就用树系（RF 求稳、GBDT 追上限、XGBoost/LightGBM 上工业）。
