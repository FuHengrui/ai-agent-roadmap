第九章　保险花销预测实战：一个完整的回归项目

阶段 20 · 机器学习算法与工程实战　|　项目实战　|　难度 ★★★
这一章在解决什么问题

前八章学了一堆"招式"，这一章全部串起来打一套组合拳：用公开的 insurance 数据集（个人年龄、性别、BMI 等特征 → 预测医疗花销 charges）跑一个完整回归项目。两个版本：

  • 基础版（常规流程）：读数据 → EDA → 对数矫正 → 哑变量 → 清洗 → 切分 → 标准化 → 多项式 → Ridge → 评估。这是一条"标准流水线"，任何表格回归任务都能照搬。
  • 进阶版（深度 EDA 驱动）：先花大力气探索数据，发现"性别、地域和花销基本无关"、"BMI≥30 是医学分水岭"、"有无孩子观念不同"——然后砍特征、做语义分箱，用更小的模型拿到更好的成绩。

两个版本的对比是本项目最大的价值：机器学习的上限不在算法，在于对数据的理解（EDA）。"杀鸡不用牛刀"——懂得数据，可以事半功倍。

上一章→本章→下一章 上一章备齐武器：Ridge/Lasso/ElasticNet、多项式升维、归一化纪律。本章在真实表格数据上打完整流水线（基础版 + 进阶版），并在结尾用进阶版的点睛之笔（不要盲目全套操作）垫定"数据理解 > 操作堆砌"的价值观。下一章进入分类算法：线性回归的近亲——逻辑回归与 Softmax。
1① 认识数据：insurance 花销数据集
要解决什么

项目第一件事：数据长什么样？有哪些列、什么类型、目标是谁？

核心思路 
import pandas as pd
import numpy as np

data = pd.read_csv("./data/insurance.csv", sep=',')
data.head(n=6)          # 默认显示前 5 行，传参可看更多

典型字段（本数据集）：age（年龄）、sex（性别）、bmi（体重指数）、children（子女数）、smoker（是否吸烟）、region（地区）、charges（医疗花销，目标 y）。

要点：

  • read_csv 的 sep 参数：数据用逗号还是制表符分隔都要显式指定（'，' 或 ' '），别默认。
  • pandas 读进来是 DataFrame（数据框）：二维表格，有行有列，是数据分析/挖掘的容器主角。
  • 目标变量确认：charges 是连续数值 → 回归问题，评估用 RMSE。
坑在哪
现象原因 / 怎么办
没看 head 直接建模先"认识数据"再动手：列名、类型、缺失、量级都在这两眼之间
把分类列（region）当数值直接算语义是离散类别，需要编码（后面 get_dummies）——EDA 阶段就要标记各列角色
2② EDA 第一步：目标变量分布（为什么右偏）
要解决什么

拿到 y 先画直方图。为什么 charges 的直方图是"右偏"的？右偏怎么修？

核心思路 
import matplotlib.pyplot as plt
%matplotlib inline          # Jupyter 内嵌显示（脚本环境用 plt.show()）
plt.hist(data['charges'])

观察：绝大多数人花销集中在低区（几千块），少数重症花销极高（几万块），尾巴拖向右边——右偏（长尾）分布。

为什么必须关注：线性回归的假设是误差服从正态分布（回溯第二章！）。y 本身右偏，直接建模会让大值样本主导损失、残差严重偏离正态，模型被少数重症样本带偏。

修复手段：取对数 np.log(data['charges'])。log 会把大值"压缩"、小值拉开，右偏被矫正成近似正态——之后预测出来要 np.exp 还原。log 变换是长尾目标的标准预处理（保险案例用 np.log / np.log1p 语义一致，log1p=log(x+1)，对含 0 的数据更稳）。

坑在哪
现象原因 / 怎么办
跳过直方图直接训练EDA 第一步就是看 y 的分布；右偏不修，整个模型被离群值污染
log 变换后忘记还原预测值在"对数空间"，交付要给用户真实花销 → 必须 exp/log1p 逆向
3③ 特征工程第一刀：get_dummies 哑变量编码
要解决什么

sex、smoker、region 是文本类别，怎么喂给只会算数的线性模型？

核心思路

独热编码（One-Hot / 哑变量）：把每个类别值变成一列 0/1。

data = pd.get_dummies(data)   # 文本列自动拆成 0/1 列
  • sex→[sex_male, sex_female]（或含原列，注意 drop_first 惯例），region→4 列，smoker→1 列。
  • 原理与第三章"全 1 列"同族：把离散信息变成数值特征。
  • 备选工具：sklearn 的 LabelEncoder / OneHotEncoder，或 DataFrame 的 map 自定义映射（任选其一——理解语义即可）。

做完 get_dummies 后，data 变成了全数值表，可以直接进模型了。

坑在哪
现象原因 / 怎么办
类别太多（如 100 个城市）直接 dummies会造出 100 列稀疏恐怖；先考虑频数编码/合并低频类别（工程权衡）
忘记目标列还在表里下一步就要 drop('charges') 分离 X 和 y，别把目标当特征喂回去
4④ 切分 X 与 y，处理缺失值
要解决什么

把目标列分离，把可能存在的空值填掉——数据准备的标准动作。

核心思路 
x = data.drop('charges', axis=1)   # 特征矩阵：去掉目标列
y = data['charges']                # 目标向量

x.fillna(0, inplace=True)   # 空值填充为 0（本数据集可能无空值，纯演示）
y.fillna(0, inplace=True)
  • drop(..., axis=1)：按列删（axis=1 是列，axis=0 是行——axis 记反是高频错）。
  • fillna(0)：缺失补 0。真实项目要根据业务定策略（均值/中位数/模型预测填充），直接补 0 是简单演示；严肃做法用 SimpleImputer。

坑预警：早期示例里的老导入 from sklearn.cross_validation import train_test_split 已经在新版本中被移除——必须用新路径 sklearn.model_selection（见下一节），这是版本迁移的经典坑。

坑在哪
现象原因 / 怎么办
axis=1 / axis=0 搞混记"行是 axis=0，列是 axis=1"；drop 列用 axis=1
空值直接不处理开训大多数模型不接受 NaN；至少先 fillna，否则 fit 报错或结果畸形
5⑤ 切分训练/测试集：新版 API 的正确姿势
要解决什么

切分用哪个函数、参数怎么设、装到哪个包？（注意版本迁移坑）

核心思路 
from sklearn.model_selection import train_test_split   # 新版路径！

x_train, x_test, y_train, y_test = train_test_split(
    x, y, test_size=0.3)    # 测试集占 30%
  • test_size=0.3：测试集 30%，训练集自动 70%。
  • 版本坑：旧写法 sklearn.cross_validation.train_test_split 在新版 sklearn（≥0.20）已被移除，import 直接报错 → 一律用 sklearn.model_selection。这是网上老教程最常见失效点，务必记住。
  • 加分参数：random_state=42（固定切分，可复现）、stratify=y（分类任务分层采样，回归无需）。
坑在哪
现象原因 / 怎么办
从老博客抄 cross_validation 报 ImportError版本迁移；改成 model_selection 即可
忘记写 random_state每次切分不同，实验结果不可复现；写死一个 seed
6⑥ 标准化：只从训练集学参数
要解决什么

多项式、Ridge 都需要先缩放。怎么规范地标准化？（第七章纪律的实战执行）

核心思路 
from sklearn.preprocessing import StandardScaler

scaler = StandardScaler(with_mean=True, with_std=True).fit(x_train)
x_train_scaled = scaler.transform(x_train)   # 用训练集学的 μ、σ
x_test_scaled  = scaler.transform(x_test)    # 测试集只 transform
  • 先 fit 训练集、再 transform 两个集——绝不直接对测试集 fit_transform（违背同分布假设，泄漏信息）。
  • with_mean/with_std 默认都是 True：同时做均值归一化（减均值）和方差归一化（除方差），这就是"标准归一化"的完整含义。

这一节是第七章"fit/transform 纪律"的实战落地：scale 的参数只属于训练集。写错这一步，测试评估等于作弊。

坑在哪
现象原因 / 怎么办
图省事 fit_transform(x_train) 后对测试集也 fit_transform测试集用了自己的一套 μ/σ，分布假设破坏；测试集永远只 transform
先归一化全量再切分归一化“偷看”了测试分布 = 数据泄漏；先切分后归一化
7⑦ 多项式升维 + Ridge 训练
要解决什么

花销与特征未必线性——升维捕捉曲线，Ridge 防升维后的过拟合。两个武器搭配使用。

核心思路 
from sklearn.preprocessing import PolynomialFeatures

poly_features = PolynomialFeatures(degree=2, include_bias=False)
x_train_poly = poly_features.fit_transform(x_train_scaled)  # 训练集 fit+transform
x_test_poly  = poly_features.transform(x_test_scaled)       # 测试集仅 transform

from sklearn.linear_model import Ridge
reg = Ridge(alpha=10.0)            # 正则强度 10：升维后刹车踩重些
reg.fit(x_train_poly, np.log1p(y_train))   # y 也要 log 矫正！

两个细节：

  • y 进模型前取 log1p（对应第二步 EDA 的对数矫正），预测输出在 log 空间。
  • degree=2 + alpha=10：升维加马力（degree>1 让曲线拟合），强正则踩刹车（防 2 阶交叉项过拟合）。这就是上一章结尾"油门 + 刹车"搭配的实例。

代码里还注释了可替换候选：LinearRegression（无正则，易过拟合）、GradientBoostingRegressor（集成模型，下一章+后续内容）。

坑在哪
现象原因 / 怎么办
对多项式特征也直接测试集 fit_transform老规矩：poly 参数只看训练集，测试集只 transform
只升维不加密正则degree=2 就开始过拟合；alpha=10 是实测验证过的组合
8⑧ 评估：RMSE 与单位还原
要解决什么

模型训完，怎么评？log 空间的误差怎么换算回"元"给业务看？

核心思路 
from sklearn.metrics import mean_squared_error

y_predict = reg.predict(x_test_poly)   # log 空间的预测

# 训练集 RMSE（log 空间）
np.sqrt(mean_squared_error(y_true=np.log1p(y_train),
                           y_pred=reg.predict(x_train_poly)))
# 测试集 RMSE（log 空间）
np.sqrt(mean_squared_error(y_true=np.log1p(y_test), y_pred=y_predict))

要点：

  • RMSE = sqrt(MSE)：把平方单位还原，与 y 同量纲，直观可比（log 空间下"低 0.1"意味着花销猜测误差缩小约 10%）。
  • 训练/测试都算：对比两者差异看是否过拟合（训练远低测试=过拟合信号）。
  • 若要"元"为单位：np.exp(reg.predict(...)) 还原再算 RMSE——两种口径都能用，报告时写清口径即可。

评估铁律再强调：以测试集 RMSE 为最终成绩。

坑在哪
现象原因 / 怎么办
只报训练 RMSE那是背答案成绩；测试 RMSE 才是验收值
log 预测直接当"元"汇报log 空间误差≠真实元误差；给业务方要还原（exp）后的数字
9⑨ 进阶版：EDA 驱动砍特征与语义分箱
要解决什么

基础版跑通了。进阶版的核心思想：不盲目全套操作，先搞懂数据，用小模型拿好成绩。看看它"砍"了什么、"换"了什么。

核心思路

进阶版新增三把刀：

  1. KDE 分布对比（核密度估计）：用 seaborn 的 sns.kdeplot 按不同组画 charges 分布曲线，直观发现——male/female 曲线几乎重合（性别与花销无关）；四个 region 曲线也几乎重合（地域无关）；而 smoker 两条曲线分得极开（吸烟强相关）；children=0 与 >0 分布明显不同、>0 之间差别不大（"有孩子"与"没孩子"是质变）。
  2. 砍特征降维：既然 region、sex 与 y 相关性极低，直接删：
data = data.drop(['region','sex'], axis=1)
  1. 语义分箱（apply 自定义函数）：利用医学先验 + 数据探索结论，把连续值变成有业务含义的标签：
def greater(df, bmi, num_child):
    df['bmi'] = 'over' if df['bmi'] >= bmi else 'under'     # BMI≥30 肥胖，医学阈值
    df['children'] = 'no' if df['children'] == num_child else 'yes'  # 有无孩子
    return df

data = data.apply(greater, axis=1, args=(30, 0,))
  • BMI≥30 医学上定义为肥胖（over），否则 under——用医学知识做阈值。
  • children：0→'no'，>0→'yes'——用分布观察做二值化（有孩子后观念变化，个数不重要）。
  • 之后照旧 get_dummies → 切分 → poly → Ridge(log1p)。

结果：特征变少、语义变强，模型更简单且成绩更好——这是"杀鸡不用牛刀"的实证。

坑在哪
现象原因 / 怎么办
觉得"砍特征=丢信息"不敢砍无信息特征只会稀释模型 + 拖慢训练 + 加大过拟合风险；EDA 证实相关低就果断砍
分箱阈值拍脑袋阈值要有依据：bmi=30 是医学分界线，children=0 来自分布观察；先验证后分箱
apply 传参写法忘记 argsapply(函数, axis=1, args=(30,0,)) 中 args 按顺序传给函数形参
10⑩ 两个版本对比：数据理解才是上限
要解决什么

基础版 vs 进阶版都跑完了。为什么"步骤更少"的进阶版反而更强？这件事对整个机器学习生涯有什么用？

核心思路

两版对比表：

维度基础版进阶版
特征处理get_dummies 全保留砍 region/sex，bmi/children 语义分箱
数据量特征更多特征更少更精
评估结果达标基线更优（测试 RMSE 更低）
模型复杂度需要 alpha=10 压住过拟合更轻松，天然简洁

结论的三层教训：

  1. 先理解数据，再选操作：EDA 不是走形式，它直接告诉你"哪些列没用、哪些列值得分箱"。
  2. 操作不是越多越好："全套流水线"是兜底，不是最优；针对数据特点定制流程才高效。
  3. 机器学习的上限 = 从业者对业务/数据的理解：smoker、BMI 阈值来自领域常识，算法只是把常识翻译成数字。

学完本模块（线性回归全家族），你已经有能力完成一个规范的回归项目了。

坑在哪
现象原因 / 怎么办
直接抄进阶版的"砍列"去别的项目每个数据集的相关性不同；砍列前必须自己做 EDA 验证（本项目的教训恰恰是"别盲抄"）
认为"流程越短越高级"长短不是目的，适配数据才是；该全套时照样全套
