第十三章　密度聚类：聚"任意形状"的 DBSCAN 与它的兄弟们

阶段 20 · 机器学习算法与工程实战　|　聚类算法　|　难度 ★★☆
这一章在解决什么问题

KMeans 家族有个"天生的残疾"：它偏好球形簇。但现实数据经常长这样——月牙形、环状、S 形、疏密不均。硬拿 KMeans 切，会把弯月拦腰截断、给环形的空洞硬塞一个中心。这一章学密度聚类（Density-Based Clustering）：把"簇"定义为密度相连的区域——点密集的地方连成一个簇，稀疏的地方算噪声。

主角是 DBSCAN（基于密度的带噪空间聚类），两个参数（epsilon、minPts）就能处理任意形状、自动发现噪声点、甚至不用预先指定簇数 K——这对 KMeans 来说是降维打击。配角是它的两个进阶兄弟：OPTICS（解决 epsilon 难选的痛点）和 MeanShift（均值漂移，一张图即可理解）。

1① 密度聚类的核心思想：人以群分，密者自聚
要解决什么

KMeans 用"距离最近的中心"定义归属，为什么对形状无能为力？密度聚类的替代思路是什么？

核心思路
  • KMeans 的问题：中心是"球心"，任何分配都在向"球形"收敛——弯月、环形天然装不下。
  • 密度聚类的思路：不看中心，看"邻居"。如果一片区域里样本"挤得够密"（密度达标），这些点彼此连通，就归为一簇；密度稀薄的区域是噪声，不强行归类。

举个日常画面：广场上跳广场舞的大爷大妈聚成几堆（密度高），旁边零星散步的人（密度低）不算任何一队。"密则成簇，疏则噪声"——这句话是密度聚类的全部世界观。

  • 好处 1：簇形状任意（只要密度连通，弯成啥样都行）。
  • 好处 2：自动识别噪声点（离群点不再干扰中心，因为根本没有中心）。
  • 好处 3：不用预先定 K（簇数由密度结构自然涌现）。
坑在哪
现象原因 / 怎么办
以为密度聚类只看"点与点的最近距离"看的是邻域密度与连通性，不是"离哪个中心近"
簇内疏密不均（density varying）单一密度阈值难以兼顾；此时用 OPTICS（本章后面）
2② DBSCAN 的三型点：核心点、边界点、噪声点
要解决什么

"密度达标"怎么严格定义？DBSCAN 把所有点分成三类——先记住这三型，整个算法就通了一半。

核心思路

定义依赖两个参数：

  • epsilon（ε）：邻域半径（以某点为中心画多大圈）。
  • minPts（MinPts）：圈内至少有多少个点才算"够密"。

三类点：

  1. 核心点（Core Point）：ε 邻域内的点数 ≥ minPts。→ 它有资格"拉人入伙"（扩张簇）。
  2. 边界点（Border Point）：邻域点数 < minPts，但落在某个核心点的邻域内。→ 它自己是"边缘住户"，但被核心点拉进簇。
  3. 噪声点（Noise/Outlier）：邻域点数 < minPts，且不在任何核心点邻域内。→ 孤魂野鬼，不归类。

簇的定义：由核心点及其邻域不断"连通"扩张，把边界点包含进来，所形成的最大连通区域。核心点的邻域重叠 → 连锁反应，整个高密度区熔成一个簇。

坑在哪
现象原因 / 怎么办
把边界点误当噪声边界点"属于某簇"（靠核心点带进来）；噪声是"进不了任何簇"的点。两者邻域稀疏程度相同，区别只在"有没有核心点罩着"
以为 minPts 越小越好太小→噪声点全变核心点，噪声被吞进簇；一般取 ≥ 维度+1，常用 5
3③ DBSCAN 完整流程：一路"滚雪球"
要解决什么

三型点定义好了，算法执行起来是什么样？为什么它能聚任意形状？

核心思路

流程（以代码句法看）：

from sklearn.cluster import DBSCAN
from sklearn.preprocessing import StandardScaler

X_scaled = StandardScaler().fit_transform(X)
db = DBSCAN(eps=0.5, min_samples=5).fit(X_scaled)

labels = db.labels_        # 每个点的簇号；-1 表示噪声
n_clusters = len(set(labels)) - (1 if -1 in labels else 0)

执行过程：

  1. 扫描所有点，按"ε 邻域密度"标记三型。
  2. 从任一未访问的核心点出发，把"邻居递归扩张"（核心点→其邻域内的核心点→再扩张……），滚雪球式吞并连通密度区。
  3. 所有连通区都成簇；边界点并入相邻簇；孤立噪声点标记 -1。

为什么任意形状行得通：扩张只依赖"邻域连通"，不依赖"到中心距离"——弯月形只要密度连通，就整条算一簇。

  • eps：半径，越大簇越大越少；min_samples：minPts。
  • 必须先标准化（距离敏感，老规矩）。
坑在哪
现象原因 / 怎么办
labels 里 -1 是什么sklearn 约定 -1 = 噪声点，不是第 -1 个簇；画图统计时注意排除
eps 设太小/太大太小→全变噪声；太大→全合成一簇。eps 定不准？→ OPTICS（本章⑤）
4④ eps 与 minPts 怎么选：k-距离图
要解决什么

DBSCAN 最劝退的就是两个参数凭感觉。有没有系统性的选参方法？

核心思路

k-距离图（k-distance plot）选 eps：

  1. 取 k = min_samples - 1（一般就取 4 或 5）。
  2. 算每个样本到它的第 k 近邻居的距离，全部从小到大排序画图。
  3. 曲线出现"膝盖/尖峰"的位置，对应一个适宜 eps——因为"密度突变"边界就在那。

minPts 的经验法则：min_samples ≥ 特征维度 + 1（太小会把噪声读成簇），常用 5~10；数据规模大可稍增。

网格速查：

现象参数倾向
噪声点太多eps 太小 → 增大 eps
全并成一团eps 太大 → 减小 eps
强噪声场景增大 min_samples
变量差异大先标准化再看 k-距离图

工程建议：先 StandardScaler → 画 k-距离图定 eps → 跑 DBSCAN → 画图目检 → 微调，一次拿下。

坑在哪
现象原因 / 怎么办
k-距离图"膝盖"不明显数据密度渐变时就是会模糊；结合业务与可视化小幅扫参数
min_samples 拍脑袋取 2太小 → 噪声全变核心点，簇被噪声污染；至少维度+1 起步
5⑤ OPTICS：治"eps 难选"的进阶版
要解决什么

DBSCAN 只有一个全局 eps，遇到"密度不均匀"的数据（有的簇很挤、有的很松）顾此失彼。怎么办？

核心思路

OPTICS（Ordering Points To Identify the Clustering Structure）：不直接给最终簇，而是先输出一张可达距离图（reachability plot）——把每个点按"密度可达顺序 + 可达距离"排序画图。

  • 图中"山谷"是稠密簇，"山峰"是簇间空隙——簇结构一览无余，不用猜 eps。
  • 可以在图上任意"切一刀"（选一个 eps 级别），得到该密度水平下的簇；换一个水平再切，得到不同粒度——一套数据多档聚类。

与 DBSCAN 的关系：OPTICS 本质是 DBSCAN 的"全 eps 视角"版本，参数同样是 min_samples（max_eps 只是上限保护，常设大值）。数据密度变化大时优先 OPTICS；需求简单、密度均匀时 DBSCAN 足够。

from sklearn.cluster import OPTICS
op = OPTICS(min_samples=5, max_eps=2.0).fit(X_scaled)
op.labels_        # 默认自动切出的簇
op.reachability_  # 可达距离，绘图用
坑在哪
现象原因 / 怎么办
以为 OPTICS 不用调任何参数至少 min_samples 要合理；它免掉的是"eps 的选择"，不是全部调参
忽略可达距离图图里有 OPTICS 最强信息（多档簇结构）；只看 labels 等于买椟还珠
6⑥ MeanShift：让每个点"跟着人多的地方走"
要解决什么

除了"密度阈值"，还有没有更直观的密度聚类思路？——有：均值漂移。名字即全部：把每个点反复移向"它邻居的均值"，直到不动。

核心思路

MeanShift（均值漂移）流程：

  1. 对每个点，求它周围（带宽 bandwidth 内）邻居的均值位置。
  2. 把点移动到这个均值位置（漂移）。
  3. 重复，直到所有点不再大幅移动——收敛到密度峰值（模式）。
  4. 落在同一峰值的点归为一簇。
  • 类比：水滴在凹凸地形上滚动，最终滚进最近的"洼地"（密度极大处）。
  • 优点：簇数自动确定（有几个峰值就几个簇），无需预知 K，也无需指定 eps。
  • 参数：bandwidth（窗口半径）——相当于是"密度视野"，可用 estimate_bandwidth 自动估。
  • 代价：比 DBSCAN 慢（每点迭代移动），大数据不划算。
from sklearn.cluster import MeanShift, estimate_bandwidth
bandwidth = estimate_bandwidth(X_scaled, quantile=0.2)  # 自动估带宽
ms = MeanShift(bandwidth=bandwidth).fit(X_scaled)
ms.labels_

quantile 控制估计带宽的宽松度（0.2~0.3 常见），决定"视野大小"。

坑在哪
现象原因 / 怎么办
以为 MeanShift 不需要任何参数bandwidth 就是"隐形的 eps"，只是给了自动估计手段；结果对 bandwidth 同样敏感
数据量大还用 MeanShift每点迭代很慢；规模大优先 DBSCAN/OPTICS
7⑦ 三种密度聚类横向对比
要解决什么

DBSCAN、OPTICS、MeanShift 都学了一遍，何时用谁？给一张决策画像。

核心思路
算法核心思想参数输入 K？噪声识别强度/弱点
DBSCAN邻域密度+连通扩张eps, min_samples不需要✔（-1）快；密度不均时 eps 难选
OPTICS先建可达图再切档min_samples (max_eps 上限)不需要✔密度不均最优；略慢、要读图
MeanShift点向密度峰值漂移bandwidth不需要弱（默认并入簇）簇数自动；慢，不适合大数据

选型一句话：密度均匀 → DBSCAN；密度不均 → OPTICS；想"簇数全自动 + 少调参"且数据不大 → MeanShift。

三者共同点：无需指定 K、可处理任意形状、对离群点天然耐受——这就是它们替代 KMeans 家族的价值所在。

坑在哪
现象原因 / 怎么办
密度聚类和 KMeans 家族混着用却不对比形状数据优先密度派；球形数据密度派也 OK 但 KMeans 更快；用可视化对比后选型
忽略"噪声点要不要保留"DBSCAN 的 -1 可直接当异常检测结果送业务；是收益不是 bug
8⑧ 代码实战：月牙数据上的 KMeans vs DBSCAN
要解决什么

"密度聚能聚任意形状"不能只靠嘴说。拿经典月牙（two moons）数据跑对比实验，一眼见分晓。

核心思路 
from sklearn.datasets import make_moons
from sklearn.cluster import KMeans, DBSCAN
from sklearn.preprocessing import StandardScaler
import matplotlib.pyplot as plt

X, _ = make_moons(n_samples=300, noise=0.06, random_state=42)
X = StandardScaler().fit_transform(X)

km = KMeans(n_clusters=2, n_init=10, random_state=42).fit(X)
db = DBSCAN(eps=0.3, min_samples=5).fit(X)   # eps 可从 k-距离图定

fig, ax = plt.subplots(1, 2, figsize=(10, 4))
ax[0].scatter(X[:,0], X[:,1], c=km.labels_, cmap='viridis'); ax[0].set_title("KMeans: 把月牙硬切成两半")
ax[1].scatter(X[:,0], X[:,1], c=db.labels_, cmap='viridis'); ax[1].set_title("DBSCAN: 形状自然")
plt.show()

预期画面：KMeans 把上下两弯月"对角线切开"（各半合并），DBSCAN 完整保留两弯月形状。这就是"球形偏好 vs 密度连通"的直观战争。

若改 noise=0.15（噪声变大），DBSCAN 的 -1 噪声点会稀疏分布——顺手能看到"噪声识别"的表现。

坑在哪
现象原因 / 怎么办
DBSCAN 结果也"歪"多半 eps 没调对（大了串簇、小了全噪声）；回 k-距离图/多试几档
拿聚类结果直接当标签彩图交付，不标参数聚类报告必须写明 eps、min_samples、是否标准化、噪声点占比——可复现是底线
9⑨ 聚类模块收尾：监督与无监督的"全家福"
要解决什么

从第十一章到本章，聚类武器库集齐了。最后竖一面"选型墙"，把整个无监督聚类模块钉住。

核心思路

完整的聚类选型墙：

数据状况首选备注
球形簇、数据量中等KMeans（+KMeans++）默认第一枪
球形但想更稳二分 KMeans局部最优难缠时

本章小结

密度聚类全家桶收工：

算法一句话本质关键参数最强卖点
DBSCAN邻域密度连通成簇eps, min_samples任意形状+噪声自动-1
OPTICS可达图展示全密度结构min_samples密度不均也能多档切

通用纪律先标准化→可视化→跑参→验收—形状决定派系

一句话记住本章：密度聚类靠"密则成簇、疏则噪声"整活——DBSCAN 用 eps 邻域+minPts 把核心点滚雪球连通成任意形状的簇并自动标噪声，k-距离图定 eps；密度不均上 OPTICS 看可达图，小而美且想全自动用 MeanShift；月牙数据上 KMeans 硬切、DBSCAN 保形，这一对比就是理解密度的最好教材。
