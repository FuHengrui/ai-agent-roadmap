第三章　AutoDL 云 GPU 平台与实例创建

阶段 19 · 大模型开发工具平台　|　云端算力　|　难度 ★★☆
这一章在解决什么问题

ModelScope 的白嫖额度有限（GPU 36~64 小时），真到做项目、微调大模型时根本不够。AutoDL 是另一条路：按小时租一块真 GPU，用几分钟付几分钟的钱，练手、复现论文、临时跑实验都非常合适。但你很快就会遇到新问题：这么多种 GPU（3090/V100/A100）、这么多配置，我到底该选哪块？要不要加硬盘？几块卡？ 选错就是又贵又慢。这一章就是把"租 GPU"这件事讲透。

先说结论：AutoDL 租 GPU = 控制台点几个按钮，关键决策只有三个——任务类型→GPU 型号、任务规模→硬盘容量、并行度→GPU 数量。本文教你三张表就能定。

本章是操作型章节（点后台为主），无代码。建议边看边点。

上一章→本章→下一章 前面把 ModelScope 当成"免费但额度有限"的算力入口。这一章跳出来讲"按需付费"的 AutoDL：它是怎么注册、怎么选 GPU、怎么租一个能跑大模型的实例。下一章继续接着这个实例讲"远程开发"（SSH 免密、PyCharm、VSCode）——选好机器只是开始，把开发工具接上去才真正能干活。
1① AutoDL 是什么
要解决什么

ModelScope 免费额度用完、又不想买上万的显卡（而且买了也只是入门卡），需要一个"用完就退"的 GPU 租赁服务。

核心思路

AutoDL 是一个面向 AI 开发者的 GPU 云计算平台。它解决三类典型问题：

  • 没有本地 GPU——用云上算力补位；
  • 本地显卡不够用——入门卡跑不动大模型，直接租高配；
  • 临时跑实验/训练模型——按小时计费，用多久付多久，不用养设备。

和整机云服务器不同，AutoDL 更像是"GPU 网吧"：注册登录后，选配置→点租用→立刻得到一台装了深度学习环境的 Linux 机器，按小时扣费，不用时关机即停止计费。

适用人群：学生练手、论文复现、大模型 LoRA/全量微调、短期实验。它不适合的：需要长期稳定服务器、需要高可用生产环境的业务（那种场景建议用大型云厂商的包月服务器）。

坑在哪
现象原因 / 怎么办
把 AutoDL 当普通云服务器买它是按小时租 GPU 算力，不是长期服务器；长期运行服务按小时计费会很贵
抢不到想要的 GPU热门型号（如 4090、A100）高峰期可能无货；可用"预约/排队"或选同参数替代型号
2② 注册与进入控制台
要解决什么

花钱之前得先有个账号，并且知道"我的机器在哪管理"——很多人注册完找不到入口。

核心思路
  1. 打开 AutoDL 官网，手机号注册/登录（通常还需要实名与绑定支付方式，按提示完成）。
  2. 登录后进入控制台，这就是所有操作的基地：「我的实例」里能看到你租的每一台机器及状态。

控制台是后续所有操作（创建、开机、关机、续费、看计费）的统一入口，先把控制台这个位置记牢。注册到控制的路径非常短：注册 → 实名 → 进控制台，三步到位。

坑在哪
现象原因 / 怎么办
控制台一直提示"未实名"国内 GPU 平台普遍要求实名才能租用，按平台指引上传信息；不实名无法创建实例
分不清"实例"和"镜像"实例=你租的那台机器（花钱按小时）；镜像=机器上跑的系统/环境模板（选一次即可）
3③ 租用新实例的入口与流程
要解决什么

账号有了，下一步就是点哪、怎么填，才能成功创建一台机器。

核心思路

在控制台「我的实例」菜单下，点击 「租用新实例」，进入配置页。核心流程四步：

  1. 选定地区与计费方式：按提示选择机房区域与按量/包月等方式（新手先按量计费，灵活）；
  2. 选择 GPU 型号：按下一知识点的方法选（这是最关键的一步）；
  3. 选择镜像：选预装好的 PyTorch 等深度学习镜像（选系统镜像时优先官方预装 PyTorch 的）；
  4. 确认硬盘与数量：按任务需要选数据盘扩容，确认提交后等待开机。

提交后实例状态会从"创建中"变为"运行中"。从"运行中"开始计费——这个起始点要记住，很多人以为点击创建那一刻就开始花钱，其实关机状态是不计费的。

坑在哪
现象原因 / 怎么办
提交后一直"创建中"高峰期排队；等 1-3 分钟刷新，部分地区/型号排队时间不同
选错了配置想改未开机前可删除重建；已开机就要关机后重新租或者续租，别硬扛错误配置
4④ 按任务类型选 GPU 型号
要解决什么

3090、3080、2080TI、V100、A100……一大堆型号，选贵的怕浪费，选便宜又怕跑不动。需要一张"任务→GPU"的对照表。

BERT 训练RTX3090 / RTX3080 / RTX2080TI可以选便宜的 2080
大模型 LoRA 微调V100 32GB / V100 SXM2 32GBV100 32GB 起步
大模型 FT（全量）微调A100 40GB PCIE / A100 SXM 80GBA100 40GB PCIE 起步

决策口诀：

  • 训中小模型（BERT 级别）→ 消费级卡（3090/3080）足够，别上 A100 浪费钱；
  • 微调几 B~几十 B 大模型，显存优先：LoRA 用 V100 32G，全量微调用 A100——显存不够直接跑不起来，降级必炸；
  • 多卡场景注意：SXM2/SXM4 版本使用 NVLINK 互联，多卡性能优于 PCIE 版本；要拼多卡就优先选 SXM 版。

看显存而不是看"显卡多新"：模型参数量决定你需要多大显存。粗估：7B 模型 LoRA 微调约需 24~32G 显存，70B 全量微调需要多卡 A100/H100 级别。

坑在哪
现象原因 / 怎么办
选了显存不够的卡，训练直接 OOM先看任务所需显存再选卡；LoRA 起步 V100 32G，别拿 2080TI（11G）硬跑 7B 模型
多卡训练选了 PCIE 版多卡场景 PCIE 卡间通信慢，SXM/NVLINK 版性能明显更好；要拼多卡优先 SXM
同型号卡价格差异大部分旧卡或共享卡会便宜，先确认是"独享实例"且显存完整，避免买到被共享的鸡肋配置
5⑤ 按任务选硬盘容量
要解决什么

系统默认只给 50GB 硬盘，而大模型文件动辄几十上百 GB——硬盘不够，镜像都拉不下来，模型存不进去，训练直接失败。该扩多大才不浪费？

核心思路

AutoDL 默认提供 50GB 硬盘，选择 GPU 时一定选可以扩容更多硬盘的服务器。不同任务的硬盘需求：

任务类型推荐拓展硬盘备注
BERT 训练不需要拓展数据集小
大模型 LoRA 微调150GB 及以上（理想 300GB）500GB 以内足够
大模型 FT 微调300GB 及以上（理想 500GB）多多益善、不设限

为什么要这么大：大模型权重动辄一个文件几十 GB（7B 模型 fp16 约 14GB，70B 约 140GB），加上数据集、tokenizer、缓存、多个 checkpoints，"150GB"听着夸张但跑一遍就满。

扩容原则：宁大勿小——硬盘是打包在机器里按容量计费的，扩到 300G 比 50G 贵不了多少，但真到训练中断再扩容要迁移数据，反而更麻烦。磁盘不够是 AutoDL 新手第一大坑。

坑在哪
现象原因 / 怎么办
拉到一半提示磁盘已满50GB 默认盘装不了大模型；提前按任务表扩容，或清理数据集/旧 checkpoints
想事后扩容部分实例支持关机后加盘，但要迁移数据且可能重启；最好创建时一次配够
数据盘和系统盘混淆一般把模型/数据放数据盘（如 /root/autodl-tmp），系统盘只管环境，别把大文件堆系统盘
6⑥ 选 GPU 数量：1 块还是 8 块
要解决什么

GPU 数量决定训练速度和能撑多大模型，但也直接决定价格（N 倍计费）。选多了浪费，选少了跑不动。

核心思路

GPU 数量与训练任务的关系（官方参考）：

数量适合场景
1 块数据集较小的训练任务，如 Pascal VOC 等
2 块同单块，但可一次跑两组参数（并行实验）或把 batchsize 扩大
4 块中等数据集训练任务，如 MS COCO 等
8 块经典配置：适合各种训练任务，方便复现论文结果
更多大参数模型、大规模调参、超快完成训练（烧钱模式）

怎么定：

  1. 先看显存是否够（单卡跑得动就别上多卡）；
  2. 单卡能跑 → 看速度是否可接受，接受就 1 卡最省钱；
  3. 速度不可接受或要复现论文的 batch 设置 → 上 4/8 卡。

新手铁律：先在 1 张卡上把代码调通，再上多卡正式跑。用多卡 + 没调通的代码 = 多倍价格跑 bug。

坑在哪
现象原因 / 怎么办
买 4 卡但代码不支持多卡训练慢还多花钱；先确认框架脚本支持 DDP/多卡，或先单卡调通
多卡训练 OOM多卡各自有显存，但 batch 会分摊；确认 DataLoader 和 batch size 是按"per-GPU"配置的
按量计费下多卡=单价×卡数速度没提升多少但价格翻倍；快跑完再想想是不是 1 卡就够
7⑦ 选择 PyTorch 镜像
要解决什么

GPU 机器上要能立刻用深度学习框架，而不是从零编译安装（可能装一天）。选对镜像开机即用。

核心思路

创建实例时需要选择系统/环境镜像。AutoDL 提供多类预装镜像，其中 PyTorch 镜像最常用——它预装了 PyTorch、CUDA、常用依赖，开机就能 import torch 直接训练。

选择要点：

  • 版本匹配：选与本项目 torch 版本兼容的镜像（已在别处跑通的项目，镜像版本尽量一致，避免 API 差异）；
  • 官方 vs 社区：优先官方镜像（稳定）；特殊需求（如特定 CUDA 版本）再找社区镜像；
  • 会写 Dockerfile 的话：可以用镜像+自定义依赖的方式，环境完全可控（对应本项目 Docker 章节）。

开机后验证环境：python -c "import torch; print(torch.__version__, torch.cuda.is_available())" 输出 True 即算力可用。

坑在哪
现象原因 / 怎么办
torch.cuda.is_available() 返回 False镜像与 GPU 驱动不匹配（极少数）；换个新版本镜像重开实例，别在旧环境死磕
镜像版本太旧装不了新包选最新官方 PyTorch 镜像；或在新镜像里 pip upgrade 相关包
用 conda 装的包在系统 Python 里 import 不到先激活对应环境再运行 python；确认当前 shell 用的是哪个 python（which python）
8⑧ 计费规则：运行中才扣钱
要解决什么

"什么时候开始扣钱""关机还收费吗""忘了关机会不会烧光余额"——计费规则不清楚就是钱坑。

核心思路

AutoDL 的计费规则核心一条：实例状态显示「运行中」才开始计费，如不使用请及时关机停止计费。

拆解成三条铁律：

  1. 运行中 = 计费中：创建完成后只要状态是"运行中"就在按小时（或按量）扣钱，不管你在不在操作；
  2. 关机 = 停止计费：不用时去控制台关机，状态变为"已关机"后不再计费（存储一般仍保留并单独计费或保留若干天）；
  3. 高峰期价格浮动：按量计费在高峰时段价格可能上浮，长任务可考虑包周/包月更划算。

好习惯：晚上跑完训练随手关机；跑长任务前先算好预计小时数再决定按量还是包月。

坑在哪
现象原因 / 怎么办
忘关机一觉醒来余额没了训练完立刻关机；可设置停机策略/余额提醒，防手滑
关机后实例被删除/数据丢失部分套餐关机后只保留几天（存储另有计费），长时间不用注意官方保留策略，重要数据同步到网盘
以为关浏览器=关机错，浏览器关了机器还在跑；必须去控制台点关机才停
