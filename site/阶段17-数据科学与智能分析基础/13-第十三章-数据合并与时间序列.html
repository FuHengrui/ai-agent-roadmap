第十三章　数据合并与时间序列

这一章在解决什么问题

业务数据从来不是一张表：订单表、客户表、商品表要"并按某种关联合起来"；销售额是带日期的，想按月份汇总。 这两个技能——表的合并（merge/concat） 与 时间序列处理（to_datetime/resample）——是把 Pandas 从"单表操作"推上"实战分析"的两级台阶。

这一章在整个知识库里的位置 上一章：缺失值、筛选与分组——单表内的清洗与聚合 本章 ← 你在这里：表与时间——多表合并 + 时间序列，Pandas 从"柜子里折腾"到"跨表干活" 下一章：统计、可视化与性能——Pandas 出手出图、大表提速 再往后：MySQL（其多表 JOIN 将与本章 merge 对照理解） 阶段终点：完成"读数据 → 清洗 → 计算 → 可视化 → 入库"链路
学习提示

本章两个主题各一条主线：合并表 先搞清楚"以什么键合并、保留哪些行"（四种 join 方式选一）；时间 先"字符串转 datetime"，再会切片、再会 resample 重采样。它们都遵循"默认返回新表"的铁律。时间序列建议对照画图理解（第 14 章 plot 一章就能用上）。

1① merge：像 SQL 的 JOIN 一样合并
要解决什么

两张表按公共键（如客户 ID）合并成一张宽表——merge 是 Pandas 版的 SQL JOIN。

核心思路 
import pandas as pd

cust = pd.DataFrame({'客户ID': [1, 2, 3], '姓名': ['张', '王', '李']})
order = pd.DataFrame({'客户ID': [1, 2, 4], '订单额': [100, 200, 300]})

pd.merge(cust, order, on='客户ID')     # 按列合并：只保留两边都有的键（内连接）

四种连接方式，用 how 参数切换：

pd.merge(cust, order, on='客户ID', how='left')    # 保留左表所有行，缺的 NaN
pd.merge(cust, order, on='客户ID', how='right')   # 保留右表所有行
pd.merge(cust, order, on='客户ID', how='outer')   # 全留，缺的 NaN
pd.merge(cust, order, on='客户ID', how='inner')   # 默认：只留共有的键

记忆口诀："left 留左、right 留右、outer 全留、inner 只留交集"。键名不同时用 left_on/right_on 指定；无键列时按索引 merge(index)。

坑在哪
现象原因 / 怎么办
合并后行数变多/变少超出预期键在多表有重复：一对多/多对多会笛卡尔积。先查键是否唯一
列名两边都有 '客户ID' 拼表冲突merge 后重复列自动加 _x/_y 后缀；用 suffixes=('左','右') 定制
忘了指定键报错on= 必须写；公共键没有就 left_on/right_on 或按索引
2② concat：轴向拼接表
要解决什么

两张结构一样的表"摞"起来（1 月数据和 2 月数据合并成全年）——concat 按行/按列拼接。

核心思路 
import pandas as pd

d1 = pd.DataFrame({'成绩': [88, 92], '姓名': ['张', '王']})
d2 = pd.DataFrame({'成绩': [76, 85], '姓名': ['李', '赵']})

pd.concat([d1, d2])                     # 默认沿行（axis=0）拼接
pd.concat([d1, d2], ignore_index=True)  # 索引重排 0,1,2,3
pd.concat([d1, d2], axis=1)             # 沿列拼：两张表并排放

与 merge 的区别：

mergeconcat
合并方式按"键值"对齐（像 JOIN）按"轴向"拼接（摞/并）
数据要求有关联的键列结构一致（同列或同索引）
典型场景客户表×订单表1 月表+2 月表

关键参数：ignore_index=True（拼接后索引重排，省去手动 reset）；join='inner' 可只留共有列。

坑在哪
現象原因 / 怎么办
拼接后列对不齐（出现 NaN 列）两表列名不完全一致；先列名对齐或用 join='inner'
索引重复难看ignore_index=True 重排
concat 和 merge 选错同构数据拼接用 concat，异表关联用 merge
3③ 时间类型基础：Timestamp 与 Period
要解决什么

"2026-10-01"是字符串还是时间？ 时间类型才支持加减、比较、重采样——先认识两个时间对象。

核心思路 
import pandas as pd

pd.Timestamp('2026-10-01')          # 时间点：精确到时刻（最常见）
pd.Timestamp('2026-10-01 12:30')    # 带时刻
pd.Period('2026-10', freq='M')      # 时间段（周期）：2026 年 10 月

t = pd.Timestamp('2026-10-01')
t + pd.Timedelta(days=3)            # 2026-10-04：时间点可加减

理解：Timestamp=某个时刻点，Period=某段时间；Timedelta 是时间差（天数/小时），用于运算。业务上"订单时间"是 Timestamp，"2026 年 10 月"是 Period。

判断类型：df['日期'].dtype 显示 datetime64 才说明真的转成时间了（第 ④ 点教转换）。

坑在哪
现象原因 / 怎么办
加减日期报错只有 datetime 类型才能 +/- Timedelta；字符串先转（下一点）
Timestamp 和 Period 混淆点（时刻）vs 段（周期）；resample 按周期聚合时用 Period 思维
4④ to_datetime：字符串 → 日期
要解决什么

"2026/10/1""2026年10月1日"这些五花八门的字符串统一转成 datetime 类型——to_datetime 识别绝大多数格式。

核心思路 
import pandas as pd

df = pd.DataFrame({'日期': ['2026-10-01', '2026/10/02', '2026年10月3日']})

df['日期'] = pd.to_datetime(df['日期'])      # 自动识别格式
df['日期'].dt.year        # 取年：2026 2026 2026
df['日期'].dt.month       # 取月
df['日期'].dt.dayofweek   # 星期几（0=周一）

# 指定格式更稳（性能好）：
pd.to_datetime(df['日期'], format='%Y/%m/%d')
# 解析失败不报错：
pd.to_datetime(df['日期'], errors='coerce')   # 坏值 → NaT

三个配套：

  • .dt 访问器：转完后用 .dt.year/month/day 提取组件；
  • errors='coerce'：转不动的变 NaT（Not a Time，缺失时间）；
  • format 显式指定：性能与精确性双赢（数据规整时推荐）。

转完后务必 df['日期'].dtype 确认是 datetime64。

坑在哪
现象原因 / 怎么办
to_datetime 全变 NaT格式混杂/中文"年月日"混排：用 errors='coerce' 先看坏值，再逐类清理
.dt.year 报"Series 无 dt"还没转成 datetime；确认 dtype 是 datetime64
日期是 20261001 这种纯数字先 astype(str) 再 to_datetime（或 format='%Y%m%d'）
5⑤ 时间索引：set_index / DatetimeIndex / date_range
要解决什么

想按日期切片、重采样，前提是日期成为索引——set_index 设时间索引；date_range 批量生成日期序列是造测试数据的利器。

核心思路 
import pandas as pd

df = pd.DataFrame({'日期': ['2026-10-01', '2026-10-02', '2026-10-03'],
                   '销售额': [100, 120, 90]})
df['日期'] = pd.to_datetime(df['日期'])
df = df.set_index('日期')            # 日期设为索引

df['2026-10-01':'2026-10-02']        # 时间范围切片（字符串即可，含两端！）
df.loc['2026-10']                    # 取整个 10 月

# 造日期序列：
idx = pd.date_range('2026-10-01', periods=7, freq='D')   # 连续 7 天
idx2 = pd.date_range('2026-01-01', '2026-12-31', freq='W-MON')  # 每周一

注意：

  • 时间索引切片含首尾（和 loc 一致）；
  • freq 是频率参数：'D' 天、'W-MON' 每周一、'MS' 月初、'H' 小时；
  • 时间切片用字符串直接写，不必先转对象。

时间索引是后面 resample 的基础设施。

坑在哪
现象原因 / 怎么办
字符串切片报错索引必须真是 datetime 类型（先 set_index 前 to_datetime）
date_range 的 W-MON 以为是别的freq 写法照抄 'W-MON' 等；常用 D/MS/H 先记这三个
切片含不含端点记不住时间索引切片与 loc 一致：含两端
6⑥ resample：时间重采样（按月汇总）
要解决什么

日报表想按周/按月/按季度汇总——resample 就是"按时间分段 groupby"。

核心思路 
import pandas as pd

idx = pd.date_range('2026-10-01', periods=60, freq='D')
df = pd.DataFrame({'销售额': range(60)}, index=idx)

df.resample('M').sum()       # 按月求和 → 每月一行
df.resample('W').mean()      # 按周均值（W 默认周日至周六）
df.resample('Q').sum()       # 按季度
df.resample('M').agg(['sum', 'mean', 'max'])   # 多聚合

要点：

  • resample('频率').聚合方法（sum/mean/max/min/count）——和 groupby 语法同构；
  • 常见频率：'D' 天、'W' 周、'M' 月末、'Q' 季末、'MS' 月初、'H' 时；
  • 前提：索引必须是 datetime 类型（第 ⑤ 点）。

与 groupby 区别：groupby 按类别分组，resample 按时间频率分组——同一套聚合心智，两处复用。

坑在哪
现象原因 / 怎么办
resample 报"only DatetimeIndex"索引不是时间类型；set_index + to_datetime 预处理好
'M' 和 'MS' 结果差一天左右M=月最后一天、MS=月初；要"每月 1 日"用 MS
想按"自然周"分组用 'W-MON'（周一起）等明确锚点
7⑦ shift：前后平移对齐
要解决什么

想算"环比""昨日差值"——把数据挪一格再和原列相减，shift 管平移。

核心思路 
import pandas as pd

df = pd.DataFrame({'销售额': [100, 120, 110]})

df['昨日'] = df['销售额'].shift(1)            # 向下平移 1 行（昨日）
df['环比'] = df['销售额'] - df['昨日']        # 日环比
df['变化率'] = (df['销售额'] - df['昨日']) / df['昨日']

df['下月'] = df['销售额'].shift(-1)           # 向上平移（未来 1 格）

理解：

  • shift(n)：整体下移 n 行（正数向下=取过去值，负数向上=取未来值）；
  • 空出来的位置=NaN（第一行没有"昨日"）——先 fillna 再算；
  • 应用：环比/同比、滚动对比、特征工程里"过去 7 天均值"。

配合 resample：先按月聚合，再 shift(1) 得到"上月值"，即可做环比分析。

坑在哪
现象原因 / 怎么办
平移后第一行 NaN正常，它没有昨日；运算后 dropna 或 fillna
shift 按行移位但数据未排序时间序列务必先 sort_index 再 shift，否则对错格
8⑧ 字符串与数值互转
要解决什么

"¥1,200""80%"这类带格式字符串要参与计算——字符串 ↔ 数值互转，配合 str 访问器。

核心思路 
import pandas as pd

df = pd.DataFrame({'价格': ['¥1,200', '¥800'], '折扣': ['80%', '50%']})

df['价格'].str.replace('¥', '')            # 去符号
df['价格'].str.replace(',', '')            # 去千分位
df['价格'] = df['价格'].str.replace('[¥,]', '', regex=True)   # 正则一步去
df['价格'] = df['价格'].astype(float)      # 转数值

df['折扣'].str.rstrip('%').astype(int) / 100    # 80% → 0.8

# 数值转字符串：
df['价格'].astype(str)                     # 或 str 访问器合并

要点：

  • str 访问器：df['列'].str.xxx 提供字符串方法全家（replace/strip/contains/split）；
  • regex=True 正则替换一口气去多个字符；
  • 转回数值 astype(float)（clean 的数字字符串）或 to_numeric 容错。

这是"清洗真实报表"的最常用套路：符号清理 → 类型转换 → 参与计算。

坑在哪
现象原因 / 怎么办
replace 没替换掉str.replace 默认正则模式要确认转义，或用 regex=True 明确
astype(float) 报错还有残余符号/空格：先 strip 再转，或 to_numeric(coerce)
字符串里中文数字要先映射（如 {'一': 1}）再做 replace
