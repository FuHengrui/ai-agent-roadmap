第四章　控制语句

阶段 1 · 大语言模型基础与工程化实践　|　23 课时　|　难度 ★★☆
这一章在解决什么问题

到上一章为止，你写的代码都是从上往下一路执行到底的——没有判断，不会重复。

但真实需求不是这样：

  • "如果薪资写的是面议，就标记成未知"
  • "对每一条岗位，都去抓一次详情页"
  • "一直重试，直到成功或者试满 3 次"

这三句话里藏着的就是编程里最核心的两个能力：判断（分岔） 和 重复（循环）。

说白了：没有控制语句，程序就是一张写死的清单；有了它，程序才开始"会思考"。 这一章之后，你才真正能写出"干活的程序"。

这一章在整个知识库里的位置 第三章：学会了把一批数据装起来 本章 ← 你在这里：让程序能"判断"和"重复处理"这批数据 第五章 函数 —— 把"判断 + 循环"打包成可以反复调用的功能 第六章 面向对象 —— 把数据和逻辑组织成类 第七、八章 —— 出错怎么办、怎么拆成多个文件 阶段终点 —— 用这些写出一个真正跑得起来的自动化系统
这一章有个思维转变

第三章你关心的是"数据长什么样"，这一章你开始关心"流程怎么走"。

编程里有个说法叫控制流（control flow）——就是"程序下一步去哪里"。所有复杂程序，本质上都是无数个"如果……就……否则……"和"重复做……"拼起来的。

所以这一章的目标不是记语法，是学会"把现实中的规则翻译成 if 和 for"。 讲义里第一节课就叫「控制语句和现实逻辑表达」，说的就是这个。

1① 把现实规则翻译成代码
要解决什么

你脑子里的需求是中文的（"薪资低于 8000 的都过滤掉"），代码是英文符号。中间那一步翻译怎么做？ 这一节先建立方法，后面再补语法。

核心思路

三步翻译法：

中文需求识别关键词代码结构
"如果下雨就带伞"如果……就……if
"如果下雨带伞，否则戴帽子"……否则……if / else
"成绩 90 以上优秀，80 以上良好，剩下的及格"分档if / elif / else
"对每一条岗位都抓详情"对每一条for
"一直重试直到成功"一直……直到while

三种最基本的控制结构（记住这张图，所有程序都是它们的组合）：

# 顺序 分岔 循环 # ┌─────┐ ┌─────┐ ┌─────┐ # │ 语句 │ │ 条件 │◀────────│ 条件 │ # └──┬──┘ └──┬──┘ └──┬──┘ # │ 真 │ 假 真 │ 假 # ┌──▼──┐ ┌────▼┐ ┌───┐ │ # │ 语句 │ │ 语句A│ │语句B│ ┌──▼──┐ # └─────┘ └─────┘ └───┘ │ 语句 │ # └──┬──┘ # └──▶ 回到条件
先想清楚"条件是什么"

新手最常见的错不是语法写错，而是条件本身写反了或漏了情况。

写之前先问自己三句话：

  • 判断的依据是什么？（哪个变量）
  • 边界值算哪边？（>= 还是 >，60 分算及格吗）
  • 所有情况都覆盖了吗？（有没有"以上都不满足"的兜底）
2② 单分支：if
要解决什么

"只有满足条件时才做某件事"——这是最简单的判断。

核心思路 
if 条件:
    满足时执行的代码        # ← 注意缩进！这是 if 的"管辖范围"
salary = 12000
if salary >= 10000:
    print("高薪岗位")
    print("值得投简历")     # 同一缩进 = 都在 if 里面
print("这行无论如何都执行")    # 没有缩进 = 在 if 外面

条件写什么？ 任何能判真假的表达式（第二章第八点讲过真值判断）：

if score > 60:            # 比较运算
if name:                  # 非空字符串
if items:                 # 非空列表
if not result:            # 取反
if user and user.active:  # 组合条件，注意短路

pass 占位——有时候你还没想好写什么，但语法上不能空着：

if score < 0:
    pass          # 先占个位，否则 IndentationError
冒号和缩进
报错原因
SyntaxError: expected ':'if 后面漏了冒号
IndentationError冒号后面没缩进，或缩进不一致
逻辑错但不报错缩进多了/少了，导致代码跑到了 if 外面——这种最难查
3③ 双分支：if / else 与三元运算符
要解决什么

"满足就 A，不满足就 B"——比单分支多了一条出路。

核心思路 
if 条件:
    A
else:
    B
if salary >= 10000:
    level = "高薪"
else:
    level = "普通"

三元运算符——当"两个分支都只是给同一个变量赋值"时，可以写成一行：

level = "高薪" if salary >= 10000 else "普通"
#       └─真时─┘   └──条件──┘      └─假时─┘

# 读法：A if 条件 else B   →  条件成立取 A，否则取 B

什么时候用三元？ 分支里只有一句赋值，而且这句子不太长。超过一行就该退回普通写法——短是手段，不是目的。

三元运算符的读法

a if cond else b 是"条件在中间"的，和很多语言（cond ? a : b）不一样，第一次见容易读反。

记法：把中间那段当成"如果"，句子读成"取 a，如果 cond，否则取 b"。

4④ 多分支：if / elif / else
要解决什么

需求经常是分档的："90 以上优秀，80-89 良好，60-79 及格，60 以下不及格"。用 if/else 套 if/else 会嵌套到没法看。

核心思路 
if score >= 90:
    grade = "优秀"
elif score >= 80:          # elif = else if，前面的都不满足才检查这一条
    grade = "良好"
elif score >= 60:
    grade = "及格"
else:                      # 兜底：上面都不满足
    grade = "不及格"

执行规则非常重要：从上往下检查，命中一个就跳出整个结构。

所以上面这段能成立，是因为用了 >= 而不是 ==：score = 85 时，第一个 85 >= 90 不成立，才轮到第二个 85 >= 80 成立。如果第一个写成 score > 60，那所有大于 60 的都会被判成第一个分支。

顺序就是逻辑。 分档判断一定要从最严格的条件往最宽松排。

三个经典错法
错法后果
用 == 而不是 >=只匹配到边界值，其他分数全都落到 else
顺序写反宽松条件放前面，后面的分支永远进不去（死代码）
漏了 else某些情况 grade 没被赋值，后面用到就 NameError

建议：分档判断里永远写一个 else 兜底，哪怕只是 raise ValueError("分数不合法")。

5⑤ 选择结构的嵌套
要解决什么

真实需求经常是"在某个前提下，再看另一个条件"——比如"是昆明的岗位，且薪资过万，才算重点"。

核心思路 
if city == "昆明":
    if salary >= 10000:        # 内层：只有在外层成立时才会执行
        print("重点岗位")
    else:
        print("昆明普通岗位")
else:
    print("非昆明")

但嵌套超过两层就该重构了——用 and 把条件合并，或者提前 return。

# ✗ 嵌套太深
if user:
    if user.active:
        if user.role == "admin":
            do_something()

# ✓ 用 and 拍平
if user and user.active and user.role == "admin":
    do_something()

# ✓ 或者"提前退出"（卫语句）
if not user:
    return
if not user.active:
    return
if user.role != "admin":
    return
do_something()

"卫语句"是实战中最推荐的写法——把"不满足就滚蛋"的条件先处理掉，剩下的是主流程，层次最浅。

嵌套的缩进地狱

嵌套三层以后，缩进很容易看错，而且改动时要整块重排。经验法则：任何函数的嵌套深度别超过 3 层。 超了就想办法拍平。

6⑥ while 循环
要解决什么

"只要条件成立就一直做"——不知道要做多少次，只知道什么时候停。

核心思路 
while 条件:
    循环体
count = 0
while count < 5:
    print(count)
    count += 1        # ← 千万别忘！否则死循环

while 的三个典型用法：

# 1. 不知道要几轮，靠条件停
while 没成功:
    重试一次

# 2. 交互式，等用户输入
while True:
    cmd = input("> ")
    if cmd == "quit":
        break

# 3. 数字递推
while n > 1:
    n = n // 2

死循环——条件永远为真。while True: 是合法的、而且很常用，只要里面有 break 能出去。

死循环怎么防、怎么救
情况处理
忘了更新循环变量count += 1 这类语句必须在循环体里
条件永远成立用 while True 时必须有 break 出口
已经卡死了终端按 Ctrl + C 强制中断
PyCharm 里卡死点运行窗口的红色停止按钮

防呆写法：不确定循环会不会停时，加一个计数器兜底：

guard = 0
while condition:
    guard += 1
    if guard > 1000:
        raise RuntimeError("循环超过 1000 次，疑似死循环")
7⑦ for 循环与 range
要解决什么

"把这一批数据挨个处理一遍"——这是最常见、也最该用 for 的场景。知道要遍历什么，就用 for；只知道什么时候停，才用 while。

核心思路 
for 变量 in 可迭代对象:
    循环体

"可迭代对象"就是能一个个取出来的东西：列表、元组、字典、字符串、range、文件……

for x in [1, 2, 3]:            # 列表
for ch in "abc":               # 字符串，逐个字符
for k in {"a": 1}:             # 字典，默认遍历键
for i in range(5):             # 0,1,2,3,4

range() 的三种写法：

range(5)            # 0 1 2 3 4
range(2, 5)         # 2 3 4
range(0, 10, 2)     # 0 2 4 6 8
range(10, 0, -1)    # 10 9 8 ... 1  ← 倒数

同时要下标和值？用 enumerate（不要用 range(len(a))）：

for i, x in enumerate(["a", "b"]):
    print(i, x)         # 0 a / 1 b

for i, x in enumerate(a, start=1):     # 从 1 开始编号
    print(i, x)
遍历时别改容器 
for x in a:
    if x < 0:
        a.remove(x)     # ✗ 结果会漏元素（第三章讲过原理）

要"筛选"，就生成一个新容器：a = [x for x in a if x >= 0]。

这和第三章第 ⑤ 点是同一个坑——遍历时容器的长度变了，迭代器的下标就对不上了。

8⑧ 嵌套循环
要解决什么

"对每一行，再对每一列做点什么"——处理表格、打印图形、穷举组合，都是两层循环。

核心思路 
for i in range(3):          # 外层：跑 3 次
    for j in range(3):      # 内层：每次外层循环里跑 3 次
        print(i, j)         # 总共 9 次

关键理解：内层循环会完整跑完一次，外层才前进一格。

经典练习一：九九乘法表

for i in range(1, 10):
    for j in range(1, i + 1):        # 内层次数跟着外层变
        print(f"{j}×{i}={i*j}", end="\t")
    print()                          # 换行

经典练习二：遍历表格

table = [
    ["姓名", "城市"],
    ["张三", "昆明"],
    ["李四", "郑州"],
]
for row in table:
    for cell in row:
        print(cell, end=" | ")
    print()

性能提醒：两层循环的次数是相乘的。外层 1000 × 内层 1000 = 100 万次。嵌套循环是性能杀手，能拍平就拍平。

内外层用同一个变量名 
for i in range(3):
    for i in range(3):     # ✗ 内层把外层的 i 覆盖了
        print(i)

不报错，但逻辑全乱。内外层一定用不同的变量名（i/j、row/col）。

9⑨ break、continue 与循环的 else
要解决什么

有时候你在循环中途就想提前走人（找到了，不用再找），或者想跳过这一轮（这条不合格，看下一条）。还有 for...else 这种长得奇怪但很有用的语法。

核心思路

break：彻底跳出整个循环

for job in jobs:
    if job["title"] == "目标岗位":
        found = job
        break               # 找到了，后面不用看了

continue：跳过本轮剩下的代码，直接进入下一轮

for job in jobs:
    if job["salary"] is None:
        continue            # 这条没薪资，跳过
    print(job["salary"])    # 只有有薪资的才会执行到这

for...else / while...else——这个语法很多人不知道：

for job in jobs:
    if job["title"] == "目标":
        print("找到了")
        break
else:
    # 只有在循环【正常跑完、没被 break】时才执行
    print("全部找完，没找到")

读法：else 是"没被打断"的意思。没有 break 就是"遍历完了"，执行 else。

这比用一个标志变量清爽得多：

# 老写法
found = False
for job in jobs:
    if job["title"] == "目标":
        found = True
        break
if not found:
    print("没找到")

# for...else 写法
for job in jobs:
    if job["title"] == "目标":
        print("找到了")
        break
else:
    print("没找到")
break 只跳一层

break 只能跳出它所在的那一层循环。 嵌套循环里想一次跳两层，常见做法是：

found = False
for i in range(3):
    for j in range(3):
        if 条件:
            found = True
            break          # 只跳出内层
    if found:
        break              # 外层再跳一次

或者把嵌套循环抽成函数，直接 return（第五章会讲，这是最干净的做法）。

10⑩ 循环优化技巧
要解决什么

循环是程序里最耗时的部分。同样跑一亿次，写法不同可能差十倍。 这一节讲几条真正有用的经验。

核心思路

① 把循环里不变的运算挪到外面

# ✗ 每次循环都重新算一次 len(a)
for i in range(len(a)):
    if a[i] > len(a):
        ...

# ✓ 只算一次
n = len(a)
for i in range(n):
    if a[i] > n:
        ...

② 用局部变量代替全局变量

Python 查找变量有顺序：局部 → 闭包 → 全局 → 内置。局部最快。循环里频繁用的全局变量，先赋给一个局部名：

# ✗ 每次都要去全局作用域找
for x in data:
    result.append(x * GLOBAL_FACTOR)

# ✓ 先拿到局部
f = GLOBAL_FACTOR
ap = result.append          # 连方法也先取出来
for x in data:
    ap(x * f)

③ 别在循环里做重复的、能提前算好的事

# ✗ 每次都查一遍表
for job in jobs:
    city = city_map.get(job["city"])

# ✓ 如果 city_map 不变，可以先转成局部变量；如果要反复算，考虑【缓存】

④ 能用推导式 / 内置函数就别手写循环

# ✗ 手写
total = 0
for x in a:
    total += x

# ✓ 内置
total = sum(a)

内置函数是 C 实现的，比 Python 循环快得多。 sum、max、min、any、all、sorted 都是这个道理。

⑤ 循环里避免频繁拼接 / 反复 add

# ✗ 每次都造新字符串
s = ""
for x in a:
    s += x

# ✓ 收集后一次拼
s = "".join(a)
优化的第一原则

先测量，再优化。 不要凭感觉觉得哪里慢就去改——用 time.time() 掐表，或者用 cProfile。

而且九成情况下，真正的瓶颈是 I/O（读写文件、请求网络），不是循环本身。 在错误的点上花时间优化，是最常见的浪费。

11⑪ 推导式与 zip：把循环写短
要解决什么

第三章提过推导式。这一章学完循环，你会更理解它到底替掉了什么——而且它不只列表能用。

核心思路

四种推导式：

[x * 2 for x in range(5)]            # 列表推导式 → [0,2,4,6,8]
{x * 2 for x in range(5)}            # 集合推导式 → {0,2,4,6,8}
{k: k*2 for k in "abc"}              # 字典推导式 → {'a':'aa', ...}
(x * 2 for x in range(5))            # 生成器表达式 → 惰性求值，不占内存

生成器表达式和列表推导式长得很像，但性质完全不同：

列表推导式 [...]生成器 (...)
什么时候算立刻全算完用到才算（惰性）
占内存全部元素都在内存里一次只有当前一个
能重复遍历吗能不能，遍历一次就空了
# 一亿个数，列表推导式会直接把内存撑爆
gen = (x * x for x in range(100_000_000))    # ✓ 瞬间返回，几乎不占内存
next(gen)     # 0
next(gen)     # 1

# 生成器常用在：求和、取前 N 个、喂给别的函数
sum(x * x for x in range(1000))     # 不用加方括号，直接当参数

zip() 并行迭代多个序列：

names  = ["张三", "李四", "王五"]
scores = [90, 85, 88]
cities = ["昆明", "郑州", "文山"]

for n, s, c in zip(names, scores, cities):
    print(f"{n} 在 {c} 考了 {s}")

# 造字典
dict(zip(names, scores))     # {'张三':90, '李四':85, '王五':88}

# 想把两个列表拍成二维
list(zip(names, scores))     # [('张三',90), ('李四',85), ('王五',88)]
zip 的静默截断

zip 按最短的那个截断，多出来的不报错、直接丢掉：

list(zip([1,2,3], "ab"))     # [(1,'a'), (2,'b')]  ← 3 被静默丢了

这在处理长度不一致的数据时非常危险——你会拿到一份"少了几条"的结果，却不知道丢了什么。

防御办法：先断言长度，或用 itertools.zip_longest 补齐：

assert len(names) == len(scores), "两个列表长度不一致！"
12⑫ 综合实战：把这一章串起来
要解决什么

光会语法没用，要知道怎么组合起来解决真问题。这一节用三个例子把前面的东西串一遍。

核心思路

实战一：分组统计（for + dict）

jobs = [
    {"city": "昆明", "salary": 12000},
    {"city": "郑州", "salary":  8000},
    {"city": "昆明", "salary": 15000},
]

stat = {}
for j in jobs:
    city = j["city"]
    if city not in stat:        # 第一次见到这个城市
        stat[city] = {"count": 0, "total": 0}
    stat[city]["count"] += 1
    stat[city]["total"] += j["salary"]

for city, s in stat.items():
    print(f"{city}: {s['count']} 条，平均 {s['total'] / s['count']:.0f}")

实战二：带重试的网络请求（while + try）

for attempt in range(1, 4):        # 最多试 3 次
    try:
        resp = requests.get(url, timeout=10)
        resp.raise_for_status()
        break                      # 成功，跳出重试循环
    except requests.RequestException as e:
        print(f"第 {attempt} 次失败：{e}")
else:
    print("三次都失败，放弃")        # ← 循环的 else 派上用场了

实战三：二维表格的筛选与排序（嵌套循环 + 推导式）

rows = [
    ["岗位",   "城市", "薪资"],
    ["前端",   "昆明", 12000],
    ["后端",   "郑州",  8000],
    ["数据",   "昆明", 18000],
]

data   = rows[1:]                                        # 去掉表头
km     = [r for r in data if r[1] == "昆明"]              # 筛选
top    = sorted(km, key=lambda r: r[2], reverse=True)    # 排序

for i, r in enumerate(top, 1):
    print(f"{i}. {r[0]} —— {r[2]}")
实战里最容易忽略的一件事

先写能跑通的版本，再优化。 上面三个例子都不是"最优写法"，但它们清楚、好改、不容易错。

新手常犯的相反错误是：一上来就追求"Pythonic 一行流"，结果写出来的代码自己三天后都看不懂。能读懂 > 写得短。
