第十三章　正则化与过拟合：让模型学会"举一反三"

阶段 21 · 深度学习框架与神经网络架构　|　神经网络基础　|　难度 ★★★
这一章在解决什么问题

模型把训练数据背得太熟、在没见过的数据上表现稀烂，这叫过拟合——深度学习最普遍的敌人。这一章讲清过拟合的成因与迹象，并给出一套实用武器：训练集/验证集/测试集划分、数据增强、正则化（L1/L2）、Dropout、BatchNorm。重点讲透 Dropout 的 inverted 实现和 BatchNorm 为什么能稳定训练。

上一章→本章→下一章 上一章解决了"怎么更快收敛"。本章解决"收敛之后到底有没有用"：正则化与过拟合，让模型在新数据上依然能打。下一章用完整实战（乳腺癌二分类）把前面所有知识串起来。
1① 过拟合：背题 vs 学会
要解决什么

训练损失很低、测试却很烂，是哪里出了问题？

核心思路

过拟合 = 模型记住了训练数据的"细节和噪声"，而没有学到背后的通用规律。

典型迹象（看曲线）：

  • 训练 loss 持续下降，但验证 loss 开始回升——过拟合的分界线。
  • 模型参数非常多、训练数据非常少时最容易发生。

直觉类比：背题的学生考试课本原题全对，换道变式就抓瞎；学会的学生掌握规律，新题也能做。

> 考试没见过的题才是真考验——验证集/测试集就是"没见过的题"。

应对三板斧：

  1. 加数据（含数据增强）。
  2. 减模型容量（减少层/神经元）。
  3. 加正则化（Dropout、权重衰减等）——本章主角。
坑在哪
现象原因 / 怎么办
训练 loss 低、测试高典型过拟合；检查是否在测试时忘了 model.eval()（Dropout 没关）
欠拟合 vs 过拟合分不清欠拟合：训练 loss 就高（学不动）；过拟合：训练低、验证高（学过头）
一过拟合就删模型层数先试 Dropout/L2，保留模型容量更好调
2② 数据划分：训练/验证/测试三员大将
要解决什么

怎么知道模型是"真学会"还是"背题"？用哪份数据来评估？

核心思路

把数据切成三分，各司其职：

集合用途特点
训练集更新参数模型唯一见过的数据
验证集调超参、观察过拟合训练时反复评估（如每 epoch 看验证 loss）
测试集最终评估只在最后用一次，模拟"没见过的真实世界"
train_set, val_set, test_set = torch.utils.data.random_split(
    dataset, [0.7, 0.15, 0.15])   # 常见 7:1.5:1.5 划分

核心纪律：测试集在训练和调参期间绝不碰——你拿测试集调过参，它就不再"没见过了"，最终分数会虚高。验证集才是训练过程中的裁判，测试集是最后的期终考。

坑在哪
现象原因 / 怎么办
拿测试集反复调参测试分数失真，模型"作弊"；调参只看验证集
随机划分不设种子每次运行不同划分，结果不可复现；random_split 前固定 torch.manual_seed
数据太少还强行三份数据不足时用交叉验证（K 折），一份数据轮流当验证集
3③ L1/L2 正则化 & 权重衰减：给参数"限速"
要解决什么

不想让模型参数太"狂野"（某些权重极大，专门去拟合个别噪声点），怎么办？

核心思路

在损失里加一项"参数大小"的惩罚，逼模型用更小的权重学规律：

L_total = L_data + lambda * R(param)
  • L2 正则：R = Σw²，惩罚"大而分散"的权重 → 权重整体被压小（权重衰减）。实现极简：
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3, weight_decay=1e-4)

weight_decay 一行搞定 L2（PyTorch 里 SGD/Adam 等自带该参数）。

  • L1 正则：R = Σ|w|，会把不重要的权重推到恰好 0，得到稀疏模型（特征选择）。

直觉：L2 让模型"低调做人"，每个权重都小，就不会有单个参数扭曲全局；lambda 控制惩罚力度。

坑在哪
现象原因 / 怎么办
weight_decay 设太大权重全被压死，欠拟合；从 1e-4 起步调小
手写 L2 加到损失里与 weight_decay 重复计算；二选一（首选 optimizer 参数）
分不清 L1/L2 效果L1 产生稀疏（权重归 0）、L2 产生小权重（不归 0）
4④ Dropout：随机"掐掉"一部分神经元
要解决什么

如何强迫网络"多条通路都学会"，而不是依赖某几个神经元死记？

核心思路

训练时，每层按概率 p 随机丢弃一部分神经元（其输出置 0），模型被迫用"残缺"的网络干活——于是每个神经元都得学会独立有用的特征，整个网络变成多个子网络的集成：

model = nn.Sequential(
    nn.Linear(4, 16),
    nn.ReLU(),
    nn.Dropout(p=0.5),      # 训练时随机丢弃 50%
    nn.Linear(16, 3),
)

关键机制（inverted dropout）：

  • 训练时保留的神经元输出要除以 (1-p) 放大（保持期望总和不变）→ 这样推理时什么都不用改，模型行为与训练一致。
  • 这是 PyTorch 内部已自动实现的细节：你设 p，框架在 forward/backward 里处理缩放，无需手写。

推理时必须 model.eval()：eval 模式下 Dropout 自动停用（不再随机），否则预测结果每次都不一样。

坑在哪
现象原因 / 怎么办
不设 p 或设 0.9p 太大信息丢失太多难收敛；常见 0.2-0.5，输入层附近用小 p
推理没 eval()预测随机抖动——排查"同输入不同输出"先查这
手动实现 dropout 忘记除以 (1-p)训练/推理期望不一致；别手写，用 nn.Dropout
Dropout 放哪通常放激活函数之后、下一层之前
5⑤ BatchNorm：把每层输入拉回"正态"
要解决什么

深层网络训练时，中间层输入的分布一直在漂移（内部协变量偏移），导致每层都要重新适应、收敛又慢又不稳。怎么办？

核心思路

BatchNorm：对每个 batch 的当前层输入做"标准化"，再放缩平移：

x_hat = (x - batch_mean) / sqrt(batch_var + eps)
y = gamma * x_hat + beta

gamma（缩放）和 beta（平移）是可学习参数，允许网络"调回"需要的分布。

model = nn.Sequential(
    nn.Linear(4, 16),
    nn.BatchNorm1d(16),   # 输入是 [N,16]，对特征维做归一化
    nn.ReLU(),
    nn.Linear(16, 3),
)

带来的好处：

  • 中间层输入分布稳定 → 训练更快、更稳，允许用更大学习率。
  • 对初始化不那么敏感，还带上一点正则化效果。

模式敏感：

  • train 模式：用当前 batch 的均值方差。
  • eval 模式：用训练过程累计的全局均值方差（running_mean/running_var）。

所以 BatchNorm 层尤其依赖 model.train()/model.eval() 正确切换。

坑在哪
现象原因 / 怎么办
用错维度接口全连接用 BatchNorm1d（N,特征）；图像用 BatchNorm2d（N,C,H,W）；用错直接维度报错
忘记切 evalbatch 很小（如 batch=1）时测试结果剧烈波动——eval 就该用 running 统计
归一化后却"学不到"gamma/beta 是可学习的，通常 auto；别把这两参数冻结
BatchNorm 放 ReLU 前还是后主流取向：BN → ReLU；两种都有，团队统一即可
6⑥ 手段汇总与组合策略
要解决什么

这么多招，实战中按什么顺序上？

核心思路

一张"过拟合处理流程"：

第一步：确认过拟合（训练 loss 降、验证 loss 升）。 第二步：从最便宜的手段开始逐个加：

手段成本力度备注
数据划分 + 监控验证集零发现病根必备
数据增强低强图像翻转/旋转等
L2（weight_decay）一行中optimizer 参数
Dropout一层中隐藏层 0.2-0.5
BatchNorm一层训练稳常一起用
减模型容量 / 早停低兜底早停：验证 loss 不再降就停

实战默认套餐（后续乳腺癌实战就用这套）：MLP + ReLU + BatchNorm + Dropout(0.2~0.5) + Adam(weight_decay 1e-4~1e-5) + 验证集监控 + 早停。

坑在哪
现象原因 / 怎么办
手段全上还过拟合先查数据量是否实在太小，考虑数据增强或换小模型
早停没实现记录验证最优 loss 与对应参数，不下降连续 N 轮就恢复最优并停止
以为正则化越多越好过度正则会欠拟合（训练 loss 都下不去）；组合要试，看曲线说话

本章小结

正则化与过拟合核心结论：

问题答案
过拟合是什么记住训练细节噪声，验证/测试表现差；曲线：训练降、验证升
数据划分纪律训练/验证/测试三分；测试只在最后用一次
L1 vs L2L1 稀疏（权重归 0），L2 小权重（权重衰减，weight_decay 一行）
Dropout训练随机丢弃神经元并除以 (1-p)（inverted）；eval 自动关闭
BatchNorm每个 batch 标准化 + 可学习 gamma/beta；稳定训练、可加大 lr
组合策略先确认过拟合，再按低到高成本逐项叠加，配合早停
7⑦ 数据增强：最便宜的过拟合解药
要解决什么

没有更多数据，又要治过拟合，还有什么"变出"数据的方法？

核心思路

数据增强（Data Augmentation）：对已有样本做不改变语义的变换，扩出大量"新"样本。图像领域尤其丰富：

变换例子
几何变换随机旋转、翻转、裁剪、缩放
色彩扰动亮度、对比度、饱和度微调
噪声注入高斯噪声、随机遮挡
import torchvision.transforms as T

transform = T.Compose([
    T.RandomHorizontalFlip(),      # 随机水平翻转
    T.RandomRotation(15),          # ±15° 随机旋转
    T.ColorJitter(0.2, 0.2, 0.2),  # 亮度/对比度/饱和度扰动
    T.ToTensor(),
])

为什么有效：模型见过了"更多样"的样本，被迫学到语义不变的规律（猫还是猫，不管怎么转），而不是死记像素细节——本质是最廉价的"加数据"。注意：只对训练集增强，验证/测试集保持原样，否则评估失真。

坑在哪
现象原因 / 怎么办
对验证/测试集也增强评估的是"增强后"的分布，结果虚高/失真；增强只在训练集
变换力度过猛翻转文字/倒置人像可能改变语义；先小力度，观察训练 loss
任务本身敏感（如车牌识别）翻转类变换不能随便用；按领域选安全变换
8⑧ 早停：在正确的时间喊停
要解决什么

训练多少轮才"刚刚好"？多跑是不是一定更好？

核心思路

早停（Early Stopping）：监控验证 loss，一旦不再改善就停止训练、回退到最优点。过拟合是"训练 loss 还在降、验证 loss 已经涨"——继续训练只有坏处。

best_val, best_state, patience, wait = 1e9, None, 10, 0

for epoch in range(200):
    ...  # 训练 + 算 val_loss
    if val_loss < best_val:
        best_val = val_loss
        best_state = {k: v.clone() for k, v in model.state_dict().items()}
        wait = 0
    else:
        wait += 1
        if wait >= patience:     # 连续 patience 轮没进步
            break                # 停
model.load_state_dict(best_state)   # 回退最优
  • patience：允许"连续几轮没进步"的容忍度，防抖动误停（常取 10-20）。
  • 与 Dropout/L2 等正交使用：正则化防过拟合，早停防"白训"。

本质：早停 = 在"验证曲线见顶"时自动刹车，省时间还顺手防过拟合。

坑在哪
现象原因 / 怎么办
patience 太小（1-2）验证曲线正常抖动被误判，提前停车；至少 5，常见 10+
停了但没回退最优停的位置不一定是最优点；务必保存并回载最优 state_dict
只按训练 loss 判断训练 loss 只降不升，永远触发不了；必须用验证 loss 判早停

一句话记住本章：过拟合是"背题"，靠验证集发现、靠正则化治疗——L2 压权重、Dropout 断依赖、BatchNorm 稳分布；纪律是测试集最后才碰，推理记得 eval()，收尾用早停兜底。
