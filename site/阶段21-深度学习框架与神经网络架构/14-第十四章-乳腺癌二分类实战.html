1① 数据集认知：先看数据再动手
要解决什么

开始写代码前，为什么必须先搞清楚数据的规模、维度、分布？

核心思路

乳腺癌数据集（经典 scikit-learn load_breast_cancer）关键事实：

  • 569 个样本，30 个特征（细胞核的半径、纹理、面积等 10 个指标的均值/标准差/最差值）。
  • 标签二分类：良性 357、恶性 212（比例约 6:4，基本平衡）。
  • 特征含义：描述细胞核形态的连续数值，量纲相似但数值范围不同。

先 data.shape、data.info()、label.value_counts() 看一眼——特征数、类别分布、缺失值是建模第一信息。这里 30 个特征 vs 569 样本，维度适中，MLP 完全可行。

坑在哪
现象原因 / 怎么办
类别严重失衡（如 99:1）直接训练会学成"全猜多数类"；需加权损失或重采样（本数据集平衡，无碍）
不看分布直接训特征量级巨大差异会让梯度失衡；标准化后就好了
忽略缺失值有缺失要先填充或删除；检查 info()
2② 数据预处理：标准化是回归/MLP 的命门
要解决什么

30 个特征量纲不同（有的 0~1、有的 0~1000），直接训练会怎样？怎么处理？

核心思路

大数值特征会主导梯度，小数值特征"说不上话"。标准化（StandardScaler） 把每个特征变成均值 0、方差 1，让所有特征"说话分量一样"：

from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()
X_train = scaler.fit_transform(X_train)   # 拟合 + 转换训练集
X_val = scaler.transform(X_val)           # 只用 transform！复用训练集的参数
X_test = scaler.transform(X_test)

铁律：scaler 只在训练集上 fit，验证/测试集只 transform——否则验证/测试信息泄漏进预处理流程，评估虚高。

预处理顺序：划分数据集 → 然后才标准化（先 split 再 scale）。

坑在哪
现象原因 / 怎么办
对全量数据 fit 再划分验证集均值方差泄入训练，评估失真；先划分，再对训练集 fit
验证/测试集自己 fit也必须复用训练集的 scaler，否则分布不一致
忘记转成张量sklearn 输出 numpy；训练前转 torch.tensor(..., dtype=torch.float32)
3③ 数据拆分与 DataLoader：7:1.5:1.5 + batch
要解决什么

数据处理好后，怎么变成"训练/验证/测试"三份并分批喂给模型？

核心思路 
from sklearn.model_selection import train_test_split
import torch
from torch.utils.data import DataLoader, TensorDataset

# 1 划分：训练 70%、其余分验证与测试 各 15%
X_train, X_tmp, y_train, y_tmp = train_test_split(
    X, y, test_size=0.3, random_state=42, stratify=y)
X_val, X_test, y_val, y_test = train_test_split(
    X_tmp, y_tmp, test_size=0.5, random_state=42, stratify=y_tmp)

# 2 转张量（float32）
Xtr = torch.tensor(X_train, dtype=torch.float32)
ytr = torch.tensor(y_train, dtype=torch.float32).reshape(-1, 1)  # BCE 用 (N,1)

# 3 分批
train_loader = DataLoader(TensorDataset(Xtr, ytr), batch_size=32, shuffle=True)
  • stratify=y：按类别比例分层抽样，保证训练/验证/测试里正负比例一致。
  • random_state 固定，结果可复现。
  • y 是 0/1，reshape 成 (N,1) 配 BCEWithLogitsLoss。
坑在哪
现象原因 / 怎么办
分层抽样忘了 stratify比例严重失衡时某份可能全是良性，评估失真
随机种子不固定不同次运行结果不同，无法比较调参；统一 random_state/手动 seed
y 形状不匹配BCEWithLogitsLoss 期望 target 与 logits 同形状；reshape(-1,1)
4④ 模型设计与初始化
要解决什么

针对 30 特征二分类，网络应该长什么样？用什么初始化？

核心思路

结构设计：输入 30 → 隐藏层（如 64）→ 隐藏层（如 32）→ 输出 1，中间配 ReLU + Dropout + BatchNorm，输出层单神经元配 BCEWithLogitsLoss：

class BreastNet(nn.Module):
    def __init__(self):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(30, 64),
            nn.BatchNorm1d(64),
            nn.ReLU(),
            nn.Dropout(0.3),
            nn.Linear(64, 32),
            nn.BatchNorm1d(32),
            nn.ReLU(),
            nn.Dropout(0.3),
            nn.Linear(32, 1),      # 输出 1 个数（logit）
        )
    def forward(self, x):
        return self.net(x)

初始化策略：

  • 隐藏层 Linear 默认 kaiming_uniform（ReLU 友好，够用）。
  • 也可显式 model.apply 配 He（Kaiming）/Xavier 统一风格（第 9 章讲过）。
  • BatchNorm 的 gamma=1、beta=0 默认即可。

注意 BatchNorm1d 要求输入第二维 ≥1；batch=1 时 BN 无法计算，batch_size 别取 1。

坑在哪
现象原因 / 怎么办
输出神经元设成 2二分类单神经元 + BCE 即可；2 神经元 + softmax 是绕路写法
Dropout 0.9信息丢太多学不动；0.2-0.5 区间
BatchNorm 与 batch 太小batch=1 时 BN 方差为 0 报错；batch ≥ 16 更稳
顺序 BN→ReLU→Dropout常见组合：先归一化再激活再丢弃；保持全项目一致
5⑤ 训练循环：加验证监控的完整版
要解决什么

训练时怎么"一眼看清"有没有过拟合？保存什么才算"练好了"？

核心思路

在标准五连之外，每个 epoch 末尾在验证集上算一次 loss/准确率，并保存验证最优模型：

model = BreastNet()
loss_fn = nn.BCEWithLogitsLoss()
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3, weight_decay=1e-4)

best_val = 1e9
for epoch in range(100):
    model.train()
    for xb, yb in train_loader:
        optimizer.zero_grad()
        loss = loss_fn(model(xb), yb)
        loss.backward()
        optimizer.step()

    # 验证监控
    model.eval()
    with torch.no_grad():
        val_loss = loss_fn(model(X_val), y_val.reshape(-1,1)).item()
    if val_loss < best_val:
        best_val = val_loss
        torch.save(model.state_dict(), "best_model.pt")   # 只存参数
    if epoch % 10 == 0:
        print(epoch, loss.item(), val_loss)
  • model.eval() + torch.no_grad()：评估时关 Dropout、不建计算图。
  • 用验证 loss 而非训练 loss 选模型（防止过拟合版本被保存）。
  • state_dict() 只存参数，加载：model.load_state_dict(torch.load(...))。
坑在哪
现象原因 / 怎么办
用训练 loss 选模型会选出过拟合版本；必须按验证集选
评估忘记 eval+no_gradDropout 干扰 + 白建计算图；两者搭配用
存整个 model 而非 state_dict存 state_dict 更稳、更省、更通用（结构变了也能 load 参数）
训练完没早停数据够小无所谓；大项目把"N 轮验证不降就停"加上
6⑥ 评估指标：准确率不够，还要看混淆矩阵
要解决什么

训练完，怎么科学地回答"这模型到底准不准"？

核心思路

只在测试集上做最终评估（它训练期间没被碰过）：

model.eval()
with torch.no_grad():
    logits = model(X_test)
    preds = (torch.sigmoid(logits) > 0.5).int()      # 概率 >0.5 → 恶性
    acc = (preds.view(-1) == y_test.int()).float().mean().item()
    print("Test Acc:", acc)

再配混淆矩阵（2×2，看错误类型）：

真实\预测预测良性预测恶性
实际良性TP（真阴性）FP（假阳性）
实际恶性FN（假阴性）TP（真阳性）

关注点：

  • 假阴性（真恶性被判良性）代价极高——漏诊！医学场景宁可多报，不可漏报，此时要调阈值或用 召回率 考核。
  • 多指标：准确率、精确率、召回率、F1、AUC（sklearn.metrics 全有）。

医疗/风控等场景，"指标含义"比"准确率数字"更重要。

坑在哪
现象原因 / 怎么办
只报准确率类别失衡时准确率骗人；配混淆矩阵、召回率、F1
阈值固定 0.5可调：想少漏诊把阈值调低（0.3），想少误报调高；按业务取舍
测试集评估多次评估一次定生死；反复看测试集等于拿它调参。

7⑦ AUC 与 ROC：二分类的"全局体检报告"
要解决什么

阈值调到多少好？除了准确率，有没有"不依赖阈值"的综合指标？

核心思路

AUC（ROC 曲线下面积） 衡量模型把"正负样本排序"的能力，与阈值无关：

  • AUC = 0.5：瞎猜；AUC = 1.0：完美排序。
  • AUC > 0.9 在医学二分类中通常算优秀。
from sklearn.metrics import roc_auc_score, roc_curve

probs = torch.sigmoid(logits).numpy()          # 概率
auc = roc_auc_score(y_test, probs)
fpr, tpr, thresholds = roc_curve(y_test, probs)  # 可画 ROC 曲线
print("AUC:", auc)

ROC 曲线：横轴假阳性率、纵轴真阳性率；曲线越贴近左上角越好，AUC 就是曲线下的面积。

怎么用：AUC 用来选模型（与阈值无关，稳定）；选定模型后，用混淆矩阵按业务需求定阈值（可多报 vs 少漏）。两个指标各司其职。

坑在哪
现象原因 / 怎么办
只用准确率评价二分类不平衡数据失真；ACC/AUC/F1 一起看
拿 AUC 当最终业务指标AUC 是排序能力，业务上还是混淆矩阵+阈值更直接；两阶段使用
概率没 sigmoid 就喂 roc_auc_score该函数接受概率或分数，直接喂 logits 也可用，但记得口径一致
8⑧ 超参调优：先手调后搜索
要解决什么

lr、隐藏层大小、Dropout 这么多超参，怎么找一组好的？

核心思路

先小规模手调，再工具搜索：

第一步：手调关键参数（跑得快，找方向）

  • 固定 5-10 个 epoch，把 lr 在 {1e-3, 1e-4, 3e-4} 里试，选验证集 AUC 最好的。
  • 定 lr 后再调 Dropout（0.2/0.3/0.5）、隐藏层宽（32/64/128）。

第二步：网格/随机搜索（自动扫参数组合）

from sklearn.model_selection import ParameterGrid

grid = {"lr": [1e-4, 3e-4, 1e-3],
        "hidden": [32, 64],
        "dropout": [0.2, 0.3, 0.5]}
for params in ParameterGrid(grid):   # 3×2×3 = 18 组
    run_one_trial(params)            # 每组小 epoch 跑，记录验证 AUC

实践原则：每组试验用小 epoch 快速预筛，锁定 2-3 组优胜者再拉长训练精调；结果全按"验证集"排名，测试集最后用一次。

坑在哪
现象原因 / 怎么办
组合爆炸3 参数×4 取值=64 组全跑浪费时间；先手调降维再小幅搜索
用测试集选参数测试集被"见过"，最终分数虚高；所有调参决策只看验证集
每组跑满 100 epoch预筛选 10 epoch 足够区分好坏；胜者再细训

一句话记住本章：乳腺癌实战 = 标准流水线：认知数据 → 先切分再标准化（只 fit 训练集）→ MLP(ReLU+BN+Dropout, 输出1神经元) + BCEWithLogits + Adam → epoch 循环里用验证集选模型、测试集最后裁决，评估别只看准确率，配混淆矩阵盯住假阴性。
