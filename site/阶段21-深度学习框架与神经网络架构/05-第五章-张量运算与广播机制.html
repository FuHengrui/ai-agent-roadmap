第五章　张量运算与广播机制

阶段 21 · 深度学习框架与神经网络架构　|　PyTorch 入门　|　难度 ★★☆
这一章在解决什么问题

神经网络的核心计算是大量张量的加减乘除和矩阵乘法——每一个神经元都做加权求和，本质就是矩阵运算。这一章把张量的基本元素运算、原地操作、点乘与矩阵乘法的区别、广播机制一次讲透。这些都是后面神经元计算、损失函数、梯度下降的"体力活"。

上一章→本章→下一章 上一章学会了张量类型转换与 NumPy 互转。本章进入运算环节：元素级四则运算、点乘 vs 矩阵乘法（神经网络的线性层本质）、广播机制（形状不同的张量也能算）。下一章学索引切片的形状变换，把"取数"和"整形"两块拼图补完。
1① 元素级运算五件套：add/sub/mul/div/neg
要解决什么

张量和张量怎么相加、相减、相乘、相除？和 Python 里的运算符有什么关系？

核心思路

PyTorch 提供了函数式和运算符式两种等价写法：

函数运算符作用
add()+加法
sub()-减法
mul()*（点乘/逐元素乘）乘法
div()/除法
neg()-（一元）取反
a = torch.tensor([[1., 2.], [3., 4.]])
b = torch.tensor([1., 2.])
print(torch.add(a, b))        # tensor([[2., 4.], [4., 6.]])
print(a + 1)                  # 张量与标量相加

元素级运算就是"对应位置各算各的"，参与运算的形状要么相同，要么满足广播（本章后面讲）。

坑在哪
现象原因 / 怎么办
函数记不住：torch.add vs a.add两者等价；torch.add(a,b) 是函数式，a.add(b) 是方法式
张量和标量混算不知所措PyTorch 支持，标量会广播到整个张量：a+1 就是每个元素加 1
2② 原地操作：函数名加下划线 _ 的含义
要解决什么

看到 a.add_(b)、a.mul_(b) 这种带下划线的写法，是什么意思？

核心思路

函数名后面加下划线 _，表示原地修改原张量：

  • add()：返回新张量，a 不变。
  • add_()：直接改 a 本身，不再返回新结果。
a = torch.ones(2, 2)
a.add_(1)   # a 原地全部加 1，没有新张量产生

原地操作省内存（不产生新张量），但会破坏原数据，用之前想清楚。优化器 optimizer.zero_grad() 这类"清空"性质的操作内部也用原地逻辑。

坑在哪
现象原因 / 怎么办
a.add(b) 后 a 没变，怀疑坏了没下划线就是非原地，a 本来就不该变；想要原地用 a.add_(b)
原地操作与共享内存叠加导致两个变量都变如果 b 和 a 共享内存，a.add_(b) 会把 b 也算进去；先 clone 隔离
3③ 点乘（逐元素乘法）到底是什么
要解决什么

* 运算符代表的"点乘"和数学里的"点积"是不是一回事？

核心思路

注意：PyTorch 的"点乘"不是数学意义上的点积，而是元素级乘法！

  • 点乘：两个张量对应位置的元素相乘，结果形状与输入相同，用 * 或 torch.mul()。
  • 前提：形状完全相同，或满足广播规则。
a = torch.tensor([[1, 2], [3, 4]])
b = torch.tensor([[5, 6], [7, 8]])
print(a * b)   # tensor([[5, 12], [21, 32]])，逐元素相乘

应用场景：特征缩放、逐元素掩码、各种损失函数中间的逐项计算。

坑在哪
现象原因 / 怎么办
把 * 当成线性代数的矩阵相乘大错特错！* 是逐元素乘；矩阵相乘要用 @ 或 matmul（下一知识点）
torch.dot(a, b) 也当逐元素乘torch.dot 是一维向量的点积（内积），返回标量，只接受 1 维输入
4④ 矩阵乘法：matmul / mm / @
要解决什么

真正的"矩阵乘法"（线性代数里的那个）在 PyTorch 里怎么写？

核心思路

用 torch.matmul() 或运算符 @；二维场景还可写 torch.mm()。

a = torch.tensor([[1, 2], [3, 4]])   # 2×2
b = torch.tensor([[5, 6], [7, 8]])   # 2×2
print(torch.mm(a, b))   # 矩阵×矩阵
print(a @ b)            # 等价写法

维度要求：A 是 m×n、B 是 n×p，才能相乘，结果 C 是 m×p——中间维度 n 必须相等。

特性点乘 *矩阵乘法 @
定义对应位置相乘线性代数矩阵乘法
形状要求相同或可广播中间维度相等 (m×n)(n×p)
结果形状与输入相同m×p
典型应用掩码、损失计算神经网络线性层、向量变换

神经网络的线性层（全连接层）本质就是矩阵乘法——这就是为什么必须吃透它。

坑在哪
现象原因 / 怎么办
矩阵乘法报维度错误检查中间维是否相等；(2,3) 乘 (3,4) 可以，(2,3) 乘 (2,3) 不行
mm 和 matmul 分不清mm 只支持二维；matmul 更通用（支持高维和广播），推荐一律用 matmul 或 @
矩阵×向量维度记不住(m×n) 乘 (n,) → 得到 (m,)；中间维 n 对齐即可
5⑤ 广播机制：形状不同的张量也能算
要解决什么

a 是 (2,2)，b 是 (2,)，怎么就能直接相加了？PyTorch 背地里做了什么？

核心思路

广播（Broadcasting）机制：让形状不完全相同的张量进行元素级运算，核心是在不复制数据的情况下，把小张量"逻辑扩展"成大张量再运算。

好处：

  • 代码简洁：不用显式 reshape/复制。
  • 内存高效：逻辑扩展不产生真实副本。
a = torch.tensor([[1, 2], [3, 4]])  # (2,2)
b = torch.tensor([5, 6])            # (2,) 看成一列行向量
c = a + b                           # (2,2)：b 广播成 [[5,6],[5,6]]
坑在哪
现象原因 / 怎么办
以为广播是把小张量真正复制是逻辑扩展，内存里没有多份数据，只是计算时按广播语义执行
广播失败报错就骂 PyTorch是形状真的不兼容；用 .shape 先核对两边形状
6⑥ 广播的两条规则
要解决什么

什么情况下能广播、什么情况下报错？有没有清晰的判断标准？

核心思路

两条规则，从最后一个维度往前比：

规则一：维度对齐 两个张量从最后面的维度开始比较：

  • 维度大小相同 → 兼容；
  • 其中一个维度大小是 1 → 兼容（1 可广播成对方大小）；
  • 都不满足 → 不兼容，报错。

规则二：扩展维度 较小的张量沿着大小为 1 的维度"扩展"成较大张量的形状（逻辑扩展，不复制数据）。

举例：

  • (2,2) 与 (2,)：从后往前，2 vs 2 相同 → 兼容 ✓
  • (2,2) 与 (2,1)：1 vs 2，1 可广播 → 兼容 ✓
  • (2,2) 与 (3,)：2 vs 3 都不为 1 → 报错 ✗
坑在哪
现象原因 / 怎么办
广播条件判断反了记住核心口诀：从后往前比，相同或有一个为 1 就行
想当然认为 (2,3) 和 (3,) 能加从后往前 3=3 相同，能加！广播看的不是"行数"，是维度逐个比
广播结果形状猜不出结果的每个维度取两者中的较大值
7⑦ 广播的实际意义
要解决什么

除了让代码少写几行，广播在深度学习里到底有什么用？

核心思路

广播是深度学习中无处不在的隐形操作：

  • 标准化的等价实现：张量减均值、除以标准差，都是 (N,D) 减/除 (D,) 的广播。
  • 偏置项：全连接层 y = xW + b，b 是 (D,)，通过广播加到每个样本上——神经网络每一层都在偷偷用广播！
  • 特征缩放：每个特征乘一个系数，一行代码完成整列缩放。

可以说：不懂广播，就看不透全连接层和 BatchNorm 这两大核心组件的实现。

坑在哪
现象原因 / 怎么办
以为自己不写广播就用不到你调用的 nn.Linear、损失函数内部全是广播；知道原理才能解释"为什么形状对不上也能算"
广播的"隐形"特性掩盖了 bug形状设计错了广播也不报错，但结果变成垃圾；用 shape 断言（assert）防呆
8⑧ 统计运算：mean/sum/max/min 全家桶
要解决什么

训练里要算均值、总和、最大值来监控损失和准确率，怎么用？

核心思路

PyTorch 提供了一整套统计函数（函数式与方法式等价）：

函数作用
mean()均值
sum()总和
max() / min()最大/最小值（及索引）
median()中位数
std() / var()标准差 / 方差
mode()众数及索引

dim 参数控制按哪个方向算：

  • 不指定 dim → 所有元素一起算。
  • dim=0 → 按列（垂直方向）。
  • dim=1 → 按行（水平方向）。
a = torch.tensor([[1.0, 2.0], [3.0, 4.0]])
print(a.sum())         # 10.0（全部）
print(a.sum(dim=0))    # tensor([4., 6.]) 每列之和
print(a.mean(dim=1))   # tensor([1.5, 3.5]) 每行均值

监控训练曲线（每轮 loss 均值）、算准确率（比较 max 索引）全靠这一组。

坑在哪
现象原因 / 怎么办
dim=0 和 dim=1 记反dim=0 消除第 0 维（压缩行）→ 按列算；dim=1 消除第 1 维（压缩列）→ 按行算
wantmax 的索引抓不到max/min 返回 (值, 索引) 两个元素；分类任务用 pred.argmax(dim=1) 更常用
均值对整型张量报错先转浮点：a.float().mean()
9⑨ 数学计算函数：sqrt/exp/log/abs/ceil/floor
要解决什么

激活函数、概率、误差、损失里要用到各种数学运算，PyTorch 怎么提供？

核心思路

常用数学函数全部内置，且逐元素生效：

函数作用典型场景
sqrt()平方根标准差、距离计算
exp()e^x激活函数、概率计算（Softmax 内部）
log() / log2() / log10()自然/2/10 为底对数信息熵、对数似然
abs()绝对值误差（MAE 损失）
ceil() / floor()向上/向下取整索引处理、离散化
a = torch.tensor([4.0, 9.0, 16.0])
print(torch.sqrt(a))   # [2., 3., 4.]
print(torch.exp(a))    # 指数结果

Softmax、交叉熵、MAE 的公式实现就是这些函数拼起来的——它们在损失函数章节会频繁出现。

坑在哪
现象原因 / 怎么办
e^x 算出来巨大（8e6）以为出错exp 值域就是这么爆炸，正常现象；实际代码里一般不会对原始大数直接 exp
log 和对数底搞混log 默认自然对数 e 底；要 2 底/10 底写 log2/log10，别混用

本章小结

本章补齐了张量计算的所有基础积木：

问题答案
元素级运算add/sub/mul/div/neg，函数与运算符等价（+ - * /）
原地操作函数名加 _（add_ 等），直接改原张量、省内存
点乘* / mul：逐元素相乘，结果形状与输入相同
矩阵乘法@ / matmul / mm：中间维度相等，结果 m×p
广播是什么小张量逻辑扩展成大方算，不复制数据、省内存
广播规则从后往前比：相同或有一个为 1 则兼容，否则报错
广播的意义全连接层偏置、标准化、特征缩放全靠它
统计运算mean/sum/max/min/std/var，dim=0 按列、dim=1 按行
数学函数sqrt/exp/log/abs/ceil/floor，激活与损失的零件

一句话记住本章：逐元素用 +-*/，矩阵相乘用 @，形状不同靠广播（从后往前比，相同或含 1），统计按 dim 定向，数学函数随手取——神经网络的计算积木就齐了。
