第十一章　梯度下降与完整的训练循环

1① 梯度下降：下山的思想实验
要解决什么

参数空间里没有"地图"，怎么找到损失最小的那组参数？

核心思路

把损失函数想成一座山谷地形，参数是位置，损失是海拔。找最低点 = 下山，但你看不到全貌，只能"看脚下"：

  • 梯度 = 上升最快的方向，是"当前地面的坡度方向"。
  • 所以每一步沿梯度反方向走一小步，海拔必然下降。
  • 重复成千上万次，就到了谷底附近的（近似）最优点。
# 单参数下山示意
param = param - lr * gradient_of_loss(param)

两个关键量：

  • 学习率 lr：步长。太大越过谷底乱跳，太小走得慢死。
  • 梯度：方向。来自损失对参数的偏导（第七章的自动微分已经备好）。

所有深度学习的训练，本质上都是这条"下坡路"。

坑在哪
现象原因 / 怎么办
学习率过大会怎样参数振荡、loss 乱跳甚至爆炸（发散）；调小 lr
学习率过小会怎样收敛极慢、像在爬行；调大 lr，或后期再用调度器降 lr
局部最优怎么办实践中高维问题大多是鞍点而非局部最小；Adam 等动量方法可帮逃离
梯度方向为什么是上升数学定义如此：负梯度才下降，更新公式里的减号别丢
2② 前向传播与反向传播：训练循环的两条腿
要解决什么

一次更新参数的过程中，计算到底怎么组织？

核心思路

每个训练步两个半场，缺一不可：

前向传播（Forward）：数据从输入流到输出，算出预测 → 再由损失函数算出 loss。

反向传播（Backward）：从 loss 出发，利用链式法则逐层回传梯度，最终每个参数都拿到自己的 ∂L/∂参数，存进 .grad。

# 半场示意
pred = model(x)              # 前向：预测
loss = loss_fn(pred, y)     # 前向：损失
loss.backward()             # 反向：填满所有 .grad

完整循环（标准五连）：

optimizer.zero_grad()   # 1 清梯度
pred = model(x)         # 2 前向
loss = loss_fn(pred, y) # 3 算损失
loss.backward()         # 4 反向往回传梯度
optimizer.step()        # 5 用梯度更新参数

顺序不可乱：先清零、再前向、再反向、最后更新。漏掉 zero_grad 是头号新手 bug。

坑在哪
现象原因 / 怎么办
前向/反向顺序颠倒backward 必须在 forward 之后；计算图都没建，哪来的梯度
多个 batch 不清梯度梯度累加（上章讲过），loss 曲线会疯
对 eval 模式网络 backward推理阶段不需要；训练才 backward
心想"为什么 optimizer 不自己清梯度"框架给自由度（支持梯度累积技巧）；默认得你手动 zero_grad
3③ optimizer.step()：参数是怎么被更新的
要解决什么

梯度算好了，但"更新参数"这一步到底改了什么？

核心思路

optimizer（优化器） 负责把 .grad 变成"新参数"。最朴素的 SGD（随机梯度下降）就是：

import torch

optimizer = torch.optim.SGD(model.parameters(), lr=0.01)

# step() 内部等价于（对每个参数 p）：
# p.data -= lr * p.grad

注意：

  • 优化器创建时传入 model.parameters()，它记住要更新哪些参数。
  • step() 读取各参数的 .grad，用各自规则更新。
  • 换成 Adam 只需改一行：torch.optim.Adam(...)——更新规则升级，接口不变。

优化器 = "下山策略"，参数 = "你的位置"，梯度 = "当前坡度"，step = "迈一步"。

坑在哪
现象原因 / 怎么办
优化器没接模型参数optimizer 不知道更新谁；创建时必须传入 model.parameters()
在不同迭代改了模型结构重新创建优化器，否则新参数不在优化器管辖内
手动改 p.data 绕过 step破坏优化器内部状态（如动量缓冲）；改参数用 step 机制
4④ DataLoader：一次性喂数据 vs 分批喂数据
要解决什么

全部数据一次算完叫"批量梯度下降"，但数据太大放不下、还容易陷入局部最优，怎么办？

核心思路

三种喂法对比：

方式每次梯度用多少数据特点
批量梯度下降全部数据方向准但慢、可能卡局部最优、放不下
随机梯度下降 SGD1 个样本快但梯度噪声大、不平稳
小批量梯度下降 Mini-batch一小批（如 32/64）实践默认：兼顾效率与稳定性

PyTorch 用 DataLoader 自动实现小批量：

from torch.utils.data import DataLoader, TensorDataset

dataset = TensorDataset(x_data, y_data)          # 打包成数据集
loader = DataLoader(dataset, batch_size=4, shuffle=True)  # 分批+打乱

for x_batch, y_batch in loader:
    # 每轮循环取一个 batch，训练一次
    ...
  • shuffle=True 训练时打乱，避免模型学会"数据顺序"。
  • DataLoader 还支持多进程加速（num_workers）。
  • Epoch：完整过一遍全部数据 = 1 个 epoch；通常训练多个 epoch。
坑在哪
现象原因 / 怎么办
batch_size 过大显存爆调小 batch（如 32→16）；小机器优先小 batch
忘记 shuffle数据天然有序时模型学到序列依赖而非规律；训练设 shuffle=True
DataLoader 取数类型不对TensorDataset 要求所有张量第一维一致（样本数相同）
混淆 epoch 与 iteration1 epoch = 完整数据过一遍；iteration = 处理一个 batch 一次
5⑤ 完整案例：用 PyTorch 训练线性回归
要解决什么

把前面的零件全装起来，第一个"真训练"的程序长什么样？

核心思路

一个可运行的最小完整训练循环：

import torch, torch.nn as nn
from torch.utils.data import DataLoader, TensorDataset

# 1 造数据：y = 2x + 1 （带一点噪声）
x = torch.linspace(0, 1, 40).reshape(-1, 1)
y = 2 * x + 1 + 0.05 * torch.randn_like(x)

# 2 模型 + 损失 + 优化器
model = nn.Linear(1, 1)
loss_fn = nn.MSELoss()
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)

# 3 数据装载
loader = DataLoader(TensorDataset(x, y), batch_size=8, shuffle=True)

# 4 训练 20 个 epoch
for epoch in range(20):
    for xb, yb in loader:
        optimizer.zero_grad()          # 清梯度
        pred = model(xb)               # 前向
        loss = loss_fn(pred, yb)       # 损失
        loss.backward()                # 反向
        optimizer.step()               # 更新
    if epoch % 5 == 0:
        print(epoch, loss.item())

# 5 验证：学到的 w、b 应接近 2 和 1
print(model.weight.item(), model.bias.item())

标准流水线五步：造数据 → 定义模型/损失/优化器 → DataLoader → epoch 循环(内层 batch 四连) → 打印评估。以后所有任务都是这个骨架。

坑在哪
现象原因 / 怎么办
loss 打印用 loss.item()返回 Python 数值，方便看；直接 print(loss) 会带张量信息
lr 太小时 w、b 学不到位调大 lr（0.01→0.1）或加 epoch 数
数据不归一化，大特征小特征特征量级差大导致梯度不平衡；先归一化到相近范围
循环结构写乱记住骨架：epoch 外层 → batch 内层 → zero_grad/forward/loss/backward/step 五连

本章小结

梯度下降与完整训练循环的要点：

问题答案
梯度下降本质沿负梯度方向反复小步走，逼近损失谷底
学习率的作用步长：太大振荡发散，太小收敛慢
前向/反向分工前向算预测和损失，反向用链式法则回传梯度填充 .grad
训练五连zero_grad → forward → loss → backward → step，顺序不可乱
优化器创建时传 model.parameters()，step() 用 .grad 更新参数
DataLoader自动小批量 + shuffle；1 epoch = 全部数据过一遍
最小案例造数据→模型/损失/优化器→loader→epoch 循环→验证
6⑥ Epoch 与 Iteration：训练进度怎么数
要解决什么

训练时要跑多少轮？"跑了 500 步"和"跑了 10 个 epoch"分别什么意思？

核心思路

两个时间单位，搞清楚就不会在进度上犯糊涂：

1 epoch   = 全部数据完整过一遍
1 iteration = 处理 1 个 batch（更新一次参数）

iterations_per_epoch = len(dataset) / batch_size

例：1000 样本、batch_size=100 → 每 epoch 10 个 iteration。跑 20 个 epoch = 200 次参数更新。

for epoch in range(20):                    # 外层：epoch
    for xb, yb in loader:                  # 内层：iteration
        ...                                # 五连
    scheduler.step()                       # 按 epoch 调 lr

看进度：打印 epoch/总数 和 iteration/epoch总数，"刹车"（早停）、"油门"（调 lr）都基于 epoch 粒度操作。

坑在哪
现象原因 / 怎么办
说"训练了 500 次"没说清是 iteration同数据不同 batch 下两者差很多；报进度时说明粒度
epoch 数拍脑袋定先跑 20-50 观察验证曲线，配合早停定合理值
数据量变化后进度对不上换了数据集/切了 batch，每 epoch iteration 数随之变化
7⑦ 训练不收敛：三步排查清单
要解决什么

loss 一直不降或直接 NaN，从哪查起？

核心思路

按"三查"顺序排查，90% 的问题在前两步就解决：

第一步查学习率：lr 太大 → loss 乱跳/NaN；lr 太小 → 几乎不动。先把 lr 调到 1e-3（Adam）或 1e-2（SGD）量级试一轮。

第二步查数据：输入是否归一化（量级差 1000 倍的特征会害死梯度）；标签是否有 NaN/无穷；dtype 是否 float32。

第三步查代码：zero_grad 漏没漏；loss 是不是标量；模型 forward 是否误用 detach；是不是把 train/eval 切反了。

# 常见救火组合：极小实验 + 保守 lr + 干净数据
lr = 1e-3
EPOCHS = 2

最快验证：只用一个 batch 反复训练，loss 能降说明代码链路通；不能降就逐层检查。

坑在哪
现象原因 / 怎么办
loss 变 NaN首选查 lr 和数据；其次查除法/对数是否出现 0 或负（如未加 eps）
loss 纹丝不动先怀疑梯度没传（requires_grad/zero_grad/优化器参数），再怀疑 lr 过小
单点排查就改几个参数一起试一次只改一个变量，否则不知道是谁治好了
8⑧ 模型保存与训练恢复
要解决什么

训练中途关电脑 / 崩了，怎么接着上次继续，而不是从头再来？

核心思路

把"模型 + 优化器 + epoch"一起存成检查点（checkpoint）：

torch.save({
    "epoch": epoch,
    "model": model.state_dict(),
    "optimizer": optimizer.state_dict(),
    "best_val": best_val,
}, "checkpoint.pt")

恢复时：

ckpt = torch.load("checkpoint.pt")
model.load_state_dict(ckpt["model"])
optimizer.load_state_dict(ckpt["optimizer"])   # 动量/自适应状态也恢复
start_epoch = ckpt["epoch"] + 1                # 从断点继续
  • 只恢复 model 也能跑，但会丢掉优化器内部状态（如 Adam 的历史矩），相当于"突然换了新手"。
  • 配合"每 N 个 epoch 存一次 + 验证最优另存一份"，训练再也不用提心吊胆。
坑在哪
现象原因 / 怎么办
恢复后 loss 跳变大概率 optimizer 状态没恢复（或数据集 shuffle 顺序不同，属正常噪声）
只存最优不存最近崩了恢复的是最优版本，可接受；想要"续训"就定期存含 optimizer 的 ckpt
模型结构改了再 load检查点与结构严格绑定；改了结构需重新训练或迁移

一句话记住本章：训练就是"下山"：前向算出损失，反向拿到梯度，优化器沿负梯度迈一小步；五步口诀 zero_grad→forward→loss→backward→step 循环往复，数据交给 DataLoader 分批喂，跑出 loss 下降就是最朴素的成功。
