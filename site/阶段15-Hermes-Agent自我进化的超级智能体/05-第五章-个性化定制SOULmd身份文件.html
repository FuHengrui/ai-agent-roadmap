第五章　个性化定制：SOUL.md 身份文件

阶段 15 · Hermes-Agent 自我进化的超级智能体　|　平台实操　|　难度 ★★☆
这一章在解决什么问题

装好、接好、案例也跑通了——但现在这个 Agent 是"大众脸"：它说话千篇一律，没有性格，也不懂你的偏好。就像请了个能干的实习生，能力有了，但"合不合拍"是另一回事。你要的是一台"会进化的伙伴"，不是一台冷冰冰的通用机器。

AI 的"性格"到底存在哪？ 答案是一个叫 SOUL.md 的文件——它是 Agent 的"身份证"，定义它是谁（语气、风格、立场），直接占据系统提示词的第一位置。改它，就是给 Agent 做"人格手术"。

学完这一章，你能回答：SOUL.md 是什么、它在系统提示词里占什么位置、里面该写什么不该写什么、写多细才叫"好"的 SOUL、怎么用 vim 编辑它、以及它和配置文件三件套（AGENTS/SOUL/USER）各自的分工。改完这一章，你的 Agent 开口就能听出"是它"。

这一章在整个知识库里的位置 上一章（第四章）：Agent 完成了第一次完整交付，验证了"会做事"。 本章 ← 你在这里：给 Agent 注入"人格"——SOUL.md 身份文件，让它从"能干"到"有性格" 下一章：工具与工具集——Agent 的"能力清单"，40+ 内置工具的分类与开关 再往后：Skill 技能系统（第 7 章）→ 持久记忆（第 8 章）→ 皮肤（第 9 章）→ MCP（第 10 章）→ 定时任务与仪表板（第 11 章） 阶段终点：你的持久个人智能体有性格、有工具、有技能、有记忆，是真正"你的" Agent
学习提示

SOUL.md 是每个 Agent 都该配第一份的文件。看本章时抓住一条判断线："SOUL 管'是谁'，AGENTS 管'怎么干活'，USER 管'用户是谁'"——三件套分工清楚，后面配置再也不迷路。

1① SOUL.md：Agent 的主要身份
要解决什么

"给 AI 设性格"听起来玄，总得有个具体的落点。这个落点在哪？改哪个文件？

核心思路

SOUL.md 是 Agent 的主要身份——它是系统提示词的第一部分，定义了 Agent 是谁。

具体机制：Hermes-Agent 的默认身份是硬编码的内置提示词；而 SOUL.md 是一个持久角色文件，位于 HERMES_HOME 目录（默认 ~/.hermes/SOUL.md），在系统提示词中占据位置 #1，取代硬编码的默认身份。

它为什么重要？因为系统提示词的第一位置 = 模型最先看到、权重最高的指令。你写的"你是一位务实的资深工程师，名字叫：红豆"会被模型当作第一准则执行——这是"人格"真正生效的物理位置。

坑在哪
现象原因 / 怎么办
以为改别的配置文件就能改性格性格只认 SOUL.md，它独自占据提示词 #1 位；改 AGENTS 等文件不顶这个位置
以为 SOUL.md 是"可选装"的高阶玩法它是官方默认机制：Hermes 会自动生成初始版 SOUL.md，改它是常规操作不是黑科技
找不到 ~/.hermes/SOUL.md确认 HERMES_HOME 指向（默认 ~/.hermes）；文件不存在可手动创建，Hermes 也会自动生成
2② 它在系统提示词里的"位置 #1"意味着什么
要解决什么

"占据系统提示词中的位置 #1"这句话反复出现，它到底有多重要？为什么这么强调位置？

核心思路

现代 LLM 的处理特性：越靠前的指令，遵循度越高。系统提示词开头的内容是模型的"首要上下文"，优先级高于后续所有内容。因此：

提示词结构内容权重
位置 #1SOUL.md（你是谁、什么风格）最高——人格基准
位置 2+上下文文件、工具说明、用户消息相对更低

SOUL.md 放在 #1 位，保证了：无论后续对话发生什么、用户怎么诱导，Agent 的"人格"都不会被轻易带偏。这也是为什么它在安全扫描和截断后会逐字注入——人格文件不允许被改写或丢弃。

坑在哪
现象原因 / 怎么办
以为 SOUL 内容会出现在上下文文件部分重复出现不会——它只在身份位置出现一次，上下文文件部分不含它（不会重复出现）
以为系统提示词顺序无所谓LLM 对开头指令遵循度更高，SOUL 在 #1 位是"人格优先"的刻意设计
写了 SOUL 却总觉得没生效检查是否逐字注入成功：SOUL 有内容则注入；为空/无法加载则回退内置默认身份（见第 ⑨ 点）
3③ Hermes 如何管理 SOUL.md：自动生成、永不覆盖、只认一个目录
要解决什么

自己手写 SOUL.md 之前，得先搞清 Hermes 对它的"管辖规则"：它会擅自改我的文件吗？我从网上学的"放当前目录"的用法对它有效吗？

核心思路

SOUL.md 的五条管理规则，每一条都是实践里会踩的坑：

规则内容
自动生成如果 SOUL.md 尚不存在，Hermes 会自动创建一个初始版本
永不覆盖现有的用户 SOUL.md 文件永远不会被覆盖——你写的内容是安全的
位置锁定Hermes 只从 HERMES_HOME 加载 SOUL.md
不找当前目录Hermes 不会在当前工作目录中寻找 SOUL.md（与一些其他工具的习惯不同！）
空文件回退如果 SOUL.md 存在但为空/无法加载，回退到内置默认身份

第五条管理规则里最关键的是"只认 HERMES_HOME，不认当前目录"——这是和其他 Agent 框架最大的操作差异，记不住会白改。

坑在哪
现象原因 / 怎么办
把 SOUL.md 放到项目当前目录里以为会被读取Hermes 只看 HERMES_HOME 下的 SOUL.md，放当前目录无效——这是它有别于其他框架的关键差异
担心改坏自带的 SOUL.md 回不去系统不覆盖你的文件；真要恢复，备份后重新生成或参考自带模板
初始化时没看到 SOUL.md 就以为漏装它会在首次运行/需要时自动生成初始版本；也可自行创建于 ~/.hermes/ 下
4④ SOUL.md 里应该放什么
要解决什么

第一次写 SOUL.md，最怕"不知道写什么"。需要一份"该放清单"，明确哪些内容值得进身份文件。

核心思路

SOUL.md 用来定义持久的语气和个性指导，重点五类：

该放示例
语调直接、温和、冷静……
沟通风格简洁、重要点、爱用图
直接程度有话说透，不绕弯
默认交互风格先给结论再展开论证
风格上要避免什么不要阿谀、不要夸大

还要写清楚：Hermes 应如何处理不确定性、分歧或模糊性（比如"不确定就直接说，别编"）。这些是"无论什么任务都成立的性格底色"，值得进 SOUL。

坑在哪
现象原因 / 怎么办
想把"这次任务的指令"写进 SOUL一次性项目指令是临时信息，进 SOUL 会让性格被任务细节污染，下次任务带着旧任务的味道
想把项目路径/仓库规范写进去这些属于环境知识，归 AGENTS/记忆管，SOUL 不负责；见第 ⑪ 点分工
觉得"写这么多干嘛，随便两句"SOUL 是人格基准，写清楚"风格 + 规避"两面，Agent 才真正"有立体感"
5⑤ 好的 SOUL.md 长什么样：四条标准
要解决什么

明白了"放什么"，还得知道"什么样算好"。写得太泛没个性、写得太细又僵化——平衡点在哪？

核心思路

"好 SOUL"的四条标准，堪称"人格文件验收规范"：

标准解读
在不同上下文中保持稳定换任务、换场景，性格不漂移
足够宽泛，适用于许多对话不绑定某个具体项目或话题
足够具体，能实质性地塑造声音不是空话套话，要能让措辞可感知
专注于沟通和身份，而不是特定任务的指令写"怎么说话、是什么人"，不写"这次怎么干"

翻译成人话：SOUL.md 写的是"世界观 + 语言风格"，不是"任务说明书"。拿"是否换了个任务依然适用"来检验你写的每一条——适用，就合格；只对某个任务成立的，就该拿出来。

坑在哪
现象原因 / 怎么办
第一条就写"帮我整理文件时要按类型分档"这是任务指令不是人格，违背第四条标准；SOUL 应该写"做事注重条理"
写得过于抽象（"你要做好人"）无法实质塑造声音，违背第三条；要具体到"说话直接但不冷漠"这种可感知粒度
写一半任务相关一半人格混杂会稀释人格权重；把任务相关的部分移到 AGENTS.md（第 ⑪ 点）
6⑥ 完整示例：一个"红豆"式的 SOUL.md
要解决什么

理论一堆，不如一个真实示例有说服力。下面这份 SOUL.md 模板可直接套用，拆开看它的结构技巧。

核心思路

这里有一份完整 SOUL.md（以"红豆"为例）：

# 个性
你是一位务实的资深工程师，名字叫：红豆，品味很高。
你优先考虑真实性、清晰度和实用性，而非礼貌的客套。

## 风格
- 直接但不冷漠
- 注重实质而非填充内容
- 当某个想法不好时，要提出反对
- 坦率承认不确定性
- 保持解释简洁，除非深度有用

## 要避免什么
- 阿谀奉承
- 夸张的语言
- 如果用户的框架是错误的，不要重复它
- 过度解释显而易见的事情

## 技术立场
- 偏好简单系统而非巧妙系统
- 关心操作现实，而非理想化的架构
- 将边缘情况视为设计的一部分，而非收尾工作

它的结构技巧：身份定位（1 句）→ 风格（正面清单）→ 要避免什么（负面清单）→ 技术立场。正反两面都说，Agent 的"人设"就立起来了。

坑在哪
现象原因 / 怎么办
直接复制"红豆"的名字和措辞示例是"模板"，把名字、语气改造成你自己的才有意义；照抄等于给 Agent 套别人的皮
只写"要做什么"不写"不要做什么"负面清单（避免阿谀/不过度解释）约束力极强，少了它风格容易跑偏
以为 SOUL 只能写"工程师人设"任意人设都行：老师、助理、客服……模板的结构可复用，内容随人设变
7⑦ 用 vim 编辑 SOUL.md：第一步实操
要解决什么

知道了写什么、怎么写，接下来得动手改文件。推荐用 vim 编辑，新手第一次碰 vim 会手足无措，需要手把手把"编辑-保存-退出"讲清楚。

核心思路

一句话："这里我们可以使用 vim 编辑文件，复制进来之后，保存退出 :wq"。三步走：

# 1. 打开文件（在 HERMES_HOME 下）
vim ~/.hermes/SOUL.md

# 2. 按 i 进入插入模式，粘贴/输入内容

# 3. 按 Esc 退出插入模式，输入 :wq 保存并退出
操作按键/命令含义
进入编辑i插入模式，可输入文字
保存退出Esc 后 :wqwrite（存盘）+ quit（退出）
只退出不存Esc 后 :q!放弃修改并退出

不会 vim 也没关系：SOUL.md 就是普通文本文件，用任何编辑器（记事本、VS Code 等）改都可以，vim 只是演示用的工具。

坑在哪
现象原因 / 怎么办
按 i 之前就敲字，没反应/乱动vim 默认是普通模式，先按 i 进入插入模式才能输入
发现改错了想放弃全部修改Esc → :q! 不保存退出，重新进再来
保存时提示只读/无权限确认在 WSL 里以你的用户操作 ~/.hermes/ 下的文件；别名环境权限正常
觉得 vim 太难想换编辑器完全可以：SOUL.md 是普通 Markdown 文件，记事本/VS Code 皆可，保存后重启网关生效
8⑧ 改完 SOUL 怎么确认生效
要解决什么

文件改完了，怎么知道"人设"真的注入生效了？有没有立竿见影的验证方法？

核心思路

推荐"两查一验"：

  1. 查文件：cat ~/.hermes/SOUL.md，确认内容存进的是 HERMES_HOME 下的文件（不是当前目录）；
  2. 查配置：hermes config show，确认 HERMES_HOME 指向正确；
  3. 验行为：重启网关/新开会话后，对话里故意测试风格点——例如用"红豆"风格，就问它一个"简单到不该解释"的问题，看它是直接回答还是啰嗦铺陈；再用冒犯性问题看它会不会礼貌客套。

关键提醒：SOUL.md 在会话开始时注入系统提示词，所以改完重启网关/新开对话再测试，不要在同个老会话里期待立即变化。

坑在哪
现象原因 / 怎么办
改完立刻在当前会话里测，没变化SOUL 是会话开始时注入的，老会话不重载；重启网关或新开会话再验
验证时用"聊天记录里看不出风格"的题目用有明确风格区分度的测试题（是否客套、是否直接反对），别用无差别问答
风格生效但偶尔跑偏人格注入是概率性的，偶尔偏离正常；持续跑偏再回头检查 SOUL 是否被截断/为空
9⑨ 五种边界情况的处理逻辑
要解决什么

SOUL.md 的加载有各种边界情况（不存在、为空、损坏、变来变去），提前知道 Hermes 会怎么处理，才能放心折腾。

核心思路

SOUL.md 的边界情况一览：

情况Hermes 行为
文件不存在自动创建初始版本
用户已写好永不覆盖，用户内容优先
文件为空/无法加载回退到内置默认身份
有内容安全扫描 + 截断后逐字注入
有多份/位置不对只认 HERMES_HOME 那一份，其他目录无效

"安全扫描 + 截断"意味着：即使 SOUL 里写了极端内容，系统也会有防护，不会原样裸注入——这是安全设计，不是让你焦虑的点。

坑在哪
现象原因 / 怎么办
SOUL 很长被截断了它会被截断到安全长度内注入；太长内容请精简，把最核心的人设放最前
写完发现"没生效"怀疑文件坏了按边界表排查：位置对不对（HERMES_HOME）？文件是否为纯文本可加载？会话是否重启？
想在 SOUL 里塞危险/违规内容安全扫描会拦截或截断；别把 SOUL 当"越狱通道"，它是人格文件不是攻击向量
10⑩ "个性"和"皮肤"是两回事
要解决什么

改完 SOUL 你可能还会听到"皮肤（skin）"这个词——改皮肤也算改性格吗？这俩是不是一回事？先把概念分开，别后面学乱。

核心思路

这里专门澄清：对话风格和视觉风格是两个独立的概念。

概念管什么改哪
个性（SOUL.md）Agent 的语气措辞——说话方式、风格、立场~/.hermes/SOUL.md
皮肤（skin）CLI 的外观——横幅颜色、旋转器表情、响应框标签/skin 命令或 ~/.hermes/config.yaml（第 9 章展开）

一句话：个性改"它怎么说"，皮肤改"它长什么样"。本章管的是前者；第 9 章专门管后者，别现在混了。

坑在哪
现象原因 / 怎么办
改皮肤试图改语气皮肤只动外观，语气由 SOUL 管；改错地方当然没效果
在 SOUL 里塞颜色/横幅配置那些属于皮肤配置（skins/*.yaml），贴进 SOUL 会被当人格文本读，乱七八糟
以为"皮肤=人格"的说法官方明确两者独立；做题/配置时按"个性 vs 皮肤"二分记忆
11⑪ 配置文件三件套：AGENTS / SOUL / USER 的分工
要解决什么

阶段 14 讲过 OpenClaw 的三件套，Hermes 也有类似体系。SOUL 讲完了，那 AGENTS 和 USER 是干什么的？三件套怎么分工才不乱？

核心思路

把三件套放进"谁是 Agent、用户是谁、怎么干活"三分法里理解：

文件管什么类比放在哪
SOUL.mdAgent 是谁：身份、语气、立场"性格"~/.hermes/SOUL.md
USER.md用户是谁：你的偏好、沟通风格、期望"用户画像"~/.hermes/memories/USER.md（第 8 章详讲）
AGENTS.md怎么干活：项目约定、工作规范、环境事实"员工手册"按工程/项目上下文加载

组合效应：SOUL 让 Agent 有性格，USER 让它懂你，AGENTS 让它懂活儿。三者各管一段，配合记忆和技能系统，才是完整的"调教"。

坑在哪
现象原因 / 怎么办
把用户偏好写进 SOUL你是"你"，Agent 是"它"；把"用户喜欢简洁"写进 SOUL 等于让 Agent 以为这是自己的性格——应进 USER.md
把项目规范写进 SOUL归 AGENTS.md；SOUL 只收"无论干什么都成立"的人格底色
三件套一个都没配就说"调教完成了"至少配 SOUL（本章必做）做骨架，USER/AGENTS 按需补——配置越完整，Agent 越懂你
12⑫ SOUL.md 调教后的"验收标准"
要解决什么

全部配置完，怎么才算"赢了"？给一组可操作的验收指标，避免自嗨。

核心思路

按"文本层 → 行为层"两层验收：

文本层（立即看）：

  • cat ~/.hermes/SOUL.md 有内容且是你的措辞；
  • 新会话对话时，Agent 的措辞风格与 SOUL 一致（直接/简洁/客套等）。

行为层（任务里看）：

  • 跨任务稳定：换 2-3 个不同类型的任务，风格不漂移；
  • 该反对时反对：SOUL 写了"不好的想法要提出反对"，就测试一个错误方案看它是否真反对；
  • 不重复显而易见的事：SOUL 写了"不过度解释"，看它是否真的言简意赅。

三条行为全过，SOUL 调教才算真正生效——这不是玄学，是可验证的工程。

坑在哪
现象原因 / 怎么办
只验收"文件写没写"不验收行为文件只是原料，行为才是结果；至少用两个任务做行为侧验证
一次没对上就反复重写 SOUL先确认会话是否重启；再确认无空/截断问题；最后才考虑措辞细节
追求"每条都完美执行"人格注入受模型影响有波动，验收看"主线稳定"即可，不要求每句话都严丝合缝

本章小结

这一章你给你的 Agent 注入了"灵魂"：

拿到了什么为什么要紧
SOUL.md 的位置：~/.hermes/SOUL.md，系统提示词 #1 位人格生效的物理位置，全框架最高优先级的指令
五条管理规则：自动生成、永不覆盖、只认 HERMES_HOME、不看当前目录、空则回退改错位置/期待覆盖都是白折腾，规则先背下来
该放/不该放清单：语气、风格、直接程度、规避项；不带任务指令与路径SOUL 写"世界观的底色"，不写"具体任务的说明书"
四条好 SOUL 标准：稳定、宽泛、具体、专注沟通与身份拿"换任务依然适用"检验你写的每一条
红豆模板：身份→风格→规避→立场的四段式可复用的结构骨架，换皮即用
vim 实操：i 编辑、:wq 保存退出第一步文件操作，或换任何顺手的编辑器
三件套分工：SOUL=性格、USER=用户画像、AGENTS=干活规范配置各归其位，不再互相污染

一句话记住本章：SOUL.md 是 Agent 的身份证，写在系统提示词第一行——"只写'它是什么人'，不写'这次干什么'；改完重启会话再见分晓。"
