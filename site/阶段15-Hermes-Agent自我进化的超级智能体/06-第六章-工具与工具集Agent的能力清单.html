第六章　工具与工具集：Agent 的"能力清单"

阶段 15 · Hermes-Agent 自我进化的超级智能体　|　平台实操　|　难度 ★★☆
这一章在解决什么问题

第四章见证 Agent 干活时，你看到的是"黑盒"：它 curl 搜索、写文档、生成网页，背后到底调用了什么、还能调用什么？你现在对它的能力边界一无所知——就像雇了个人却不清楚他会哪些技能，指派任务全凭猜。

"会进化的伙伴"不是凭空变出能力的，它的一切行动都来自"工具"：搜索用 web 工具、跑命令用 terminal、看网页用 browser、生成图片用 image_gen……这些工具被组织成"工具集"，可以按平台启用或禁用。看懂工具的分类地图和开关方法，你就掌握了指挥 Agent 的"完全控制权"。

学完这一章，你能回答：工具和工具集是什么关系、Hermes 内置的八大类工具各管什么、40+ 工具长什么样、怎么查看/启用/禁用工具集、工具集和技能、MCP 有什么区别。这是理解后面所有扩展能力（Skill、MCP、Cron）的基础层。

这一章在整个知识库里的位置 上一章（第五章）：SOUL.md 给 Agent 注入人格——它"是谁"。 本章 ← 你在这里：工具系统——Agent"能做什么"，八大类能力清单与开关 下一章：Skill 技能系统——把"会做的流程"沉淀成可复用的技能 再往后：持久记忆（第 8 章）→ 皮肤（第 9 章）→ MCP 扩展（第 10 章）→ 定时任务与仪表板（第 11 章） 阶段终点：你清楚知道 Agent 的每一项能力边界，并能按需开关、扩展、沉淀
学习提示

本章信息密度高，但结构异常清晰：一张八类工具表 + 三组管理命令。先把"八类"背下来（网络/终端/浏览器/媒体/Agent编排/记忆/自动化/集成），命令随用随查即可。

1① 工具：扩展 Agent 能力的最小单元
要解决什么

"Agent 会做事"听着抽象，落到实处就是一个个具体的"动作"。需要搞清楚：Agent 的能力原子单元到底是什么？

核心思路

讲义定义：工具（tool）是扩展 Agent 能力的函数——每个工具就是 Agent 能执行的一个具体动作。例如：

工具动作
web_search搜索网络
web_extract提取页面内容
terminal执行终端命令
read_file读取文件
image_generate生成图片

Agent 本身只有"脑子"（LLM），一切行动的"手脚"都是通过调用工具实现的。脑子里想"我需要搜索"→ 调用 web_search → 拿到结果 → 再决定下一步。这印证了第四章的观察：它的每次 curl、每次写文件，背后都是某个工具在干活。

坑在哪
现象原因 / 怎么办
以为 Agent 的能力是"模型自带"模型只负责想，执行全靠工具；换模型不换工具，能力不丢（第 2 章"多模型路由"呼应）
把"提示词技巧"当能力提示词只是指挥，工具才是执行；会写提示词+工具齐全，才是真正的"能干活"
以为工具越多越好工具要组织成工具集、按需开启（下一节），全开未必好用，还可能互相干扰
2② 工具集：把工具按平台组织、按需开关
要解决什么

单个工具是原子，但 Agent 不需要每次都把上百个工具全加载——既浪费 token 又增加决策噪音。怎么管理"用哪些工具"这件事？

核心思路

讲义明确：工具被组织成逻辑上的工具集（toolsets），可以按平台启用或禁用。

理解"平台"这个词：不同运行环境（CLI 对话、消息平台、API 调用）可以有不同的工具组合。比如：

场景推荐工具集组合
日常 CLI 对话web + terminal + file + memory
网页检索任务web + browser + extract
媒体创作image_gen + tts + vision
自动化值守cronjob + send_message + web

好处是双重的：按需加载省 token、按场景隔离降干扰。你不需要记住工具仓库里每一个工具，只需要知道"哪个场景开哪个工具集"。

坑在哪
现象原因 / 怎么办
工具全禁了，Agent 啥也不会工具集是能力的开关，全关=裸模型；至少保留 web/terminal/file 三件套再折腾
任意平台都开同一套工具集平台有平台的特点（如消息平台不适合开浏览器），按平台差异化配
以为工具集=工具本身工具集是"组的开关"，组内是具体工具；开文件工具集=能用 read_file 等一批工具
3③ 内置工具注册表：40+ 工具从哪来
要解决什么

"Hermes 内置了广泛的工具注册表"——这个注册表里到底有什么？规模多大？

核心思路

讲义第 26 页：Hermes 内置了广泛的工具注册表，涵盖网络搜索、浏览器自动化、终端执行、文件编辑、记忆、委托、RL 训练、消息传递、Home Assistant 等。

规模上：内置 40+ 种工具（第 10 章 MCP 部分提到"内置了 40+ 工具"）。它们分属不同能力域：

能力域代表工具
网络搜索web_search、web_extract
终端执行terminal、process、patch
文件编辑read_file、write_file 族
浏览器自动化browser_navigate、browser_snapshot
记忆memory、session_search
委托delegate_task
消息传递send_message
其他RL 训练、Home Assistant、MCP 等

40+ 只是"起点"——技能（第 7 章）能加流程、MCP（第 10 章）能无限接外部工具。

坑在哪
现象原因 / 怎么办
以为 40+ 就是全部能力上限这是内置底座；Skill 加"流程手册"、MCP 加"外部工具"，实际能力近乎无限
想把 40+ 工具全部背下来没意义；背八类（下一节）+ 常用几个即可，其余用 hermes tools 现查
以为工具注册表只在 CLI 里可见各平台配置工具也是同一个注册表（hermes tools 交互式配置覆盖多平台）
4④ 八大类工具全景图
要解决什么

40+ 工具零散记不住，需要一张"分类地图"把它们归位。这样看到任何工具名都能立刻判断它属于哪类、大概干嘛。

核心思路

讲义第 27 页给出一张完整的八大类工具表（含类别/示例/描述）：

类别示例工具描述
网络web_search、web_extract搜索网络并提取页面内容
终端与文件terminal、process、read_file、patch执行命令并操作文件
浏览器browser_navigate、browser_snapshot、browser_vision支持文本与视觉的交互式浏览器自动化
媒体vision_analyze、image_generate、text_to_speech多模态分析与生成
Agent 编排todo、clarify、execute_code、delegate_task规划、澄清、代码执行与子 Agent 委托
记忆与召回memory、session_search持久化记忆与会话搜索
自动化与交付cronjob、send_message定时任务与出站消息传递
集成ha_*、MCP 服务器工具、rl_*Home Assistant、MCP、强化学习训练及其它

八类的记忆锚点：从"获取信息（网络/浏览器）→ 操作环境（终端/媒体）→ 自我管理（编排/记忆）→ 主动输出（自动化/集成）"这条主线去理解，自然不忘。

坑在哪
现象原因 / 怎么办
把 web_extract 和 browser_navigate 都当"上网"混用web_extract=抓取指定页面文本；browser=交互式操作浏览器（点击/滚动）；第四章"API 不行就上浏览器"就是两者分工
以为 ha_* 是"哈哈系"娱乐工具ha_*=Home Assistant（智能家居）集成；rl_*=强化学习训练，都是企业/极客向能力
忘记记忆类工具存在memory/session_search 是"进化"的发动机（第 8 章），先在这里记住它们归类
5⑤ 常见工具集清单：17 个可开关的"组"
要解决什么

知道了八类工具，还不能直接操作——实操层面开关的是"工具集名"。有哪些工具集可以直接启停？

核心思路

讲义第 28 页给出的常见工具集清单（可直接在命令里用的"组名"）：

工具集大致对应
web / terminal / file网络、终端、文件
browser浏览器自动化
vision / image_gen / tts媒体三件套
moa多 Agent 协作
skills技能加载
todo任务规划
memory / session_search记忆与检索
cronjob定时任务
code_execution代码执行
delegation / clarify委托与澄清
homeassistant / rl集成类

这些名字就是第 ⑥ 点命令里的参数。记不住全名没关系，用 hermes tools 交互式配置会列出可选清单，名字是给命令用的钥匙。

坑在哪
现象原因 / 怎么办
试图自己发明"工具集名"名字是既定清单，写错会报"未知工具集"；以 hermes tools 列出的为准
以为 skills 工具集=技能本身skills 工具集负责加载/管理技能（第 7 章），技能内容在 ~/.hermes/skills/ 下，两回事
一次性想开 10 个工具集按任务需要开，开太多反而让模型选择困难；最小够用原则
6⑥ 三组管理命令：查看、启用、禁用、按场景指配
要解决什么

工具集的开关命令长什么样？如何在特定场景临时指定工具集？命令行和对话内分别怎么操作？

核心思路

讲义给了三组命令，各管一个场景：

# ① 启动时指定工具集（一次性，按任务）
hermes chat --toolsets "web,terminal"

# ② 查看所有可用工具 / 配置启用工具
hermes tools

对话内（斜杠命令）：

/tools list              # 查看当前工具
/tools disable browser   # 禁用浏览器工具
/tools enable rl         # 启用强化学习工具

三个场景对照：

场景用什么特点
这次任务只要网络+终端hermes chat --toolsets "web,terminal"一次性、不落盘
长期开关某类工具/tools enable/disable <名字>会话内即时生效
按平台交互式配置hermes tools向导式、覆盖各平台
坑在哪
现象原因 / 怎么办
以为 --toolsets 会永久改了配置它是本次启动的限制；hermes tools 交互式配置才是持久设置
斜杠命令和 CLI 命令记混对话内用 /tools（斜杠开头）；终端用 hermes chat/tools；两者都能控工具
disable 了 browser 后第四章那种页面任务做不了页面任务依赖 file/terminal 多些，但"浏览器搜索"会失效——按需开回来即可
7⑦ 工具集与"能力边界"：开什么才有什么
要解决什么

第四章里 Agent"会搜索、会建站、会启动服务器"，那是工具集开得全。如果某类工具没开，Agent 会怎样？需要建立"能力边界"意识。

核心思路

Agent 能做什么 = 开启的工具集决定。工具没开，即使"脑子"知道怎么做也执行不了：

你可以期待前提是开了
上网搜索/提取网页web
跑命令/改文件terminal + file
看网页/点按钮browser
生成图片/语音image_gen + tts
定时跑任务cronjob
记住跨会话的事情memory

所以排查"Agent 为什么不会 X"时，第一反应应是查工具集开没开（hermes tools / /tools list），而不是怀疑模型笨。能力边界是可配置的，这正是"可控权"所在。

坑在哪
现象原因 / 怎么办
Agent 说"我没法上网"先怀疑网络先 /tools list 查 web 开没开——九成是工具集问题不是网络问题
定时任务不跑先怀疑 cron 语法先查 cronjob 工具集是否启用；没开它连调度器都调不到
一遇到能力缺失就"全开"全开=高噪声+潜在安全面扩大；按需开、用完关，才是正确姿势
8⑧ 工具集 vs 技能（Skills）：别搞混的两种扩展
要解决什么

接下来第 7 章要学 Skills，但本章"工具集"里也有一个 skills 工具集——两者极易混淆，需要提前把边界划清楚。

核心思路

用"零件 vs 手册"的比喻理解：

维度工具/工具集技能（Skills）
本质可执行的函数（动作）按需加载的知识文档（流程）
类比螺丝刀、电钻使用说明书
存在形式内置注册表~/.hermes/skills/ 下的 SKILL.md
什么时候参与Agent 行动时直接调用Agent 需要时才载入（渐进披露）
开关/tools enable/disablehermes skills list/install

tool 负责"能做什么动作"，skill 负责"这个动作流程怎么做才对"。二者配合：技能文档指导 Agent 编排工具完成复杂任务。

坑在哪
现象原因 / 怎么办
以为"装个技能"就能获得新工具技能是流程手册，若流程里要用的工具没开，技能也跑不动——工具是地基
工具集里的 skills 名误当"技能列表"skills 工具集管加载技能；查有什么技能用 hermes skills list
认为技能能替代工具集配置两者独立：先确保工具可用，再谈按什么流程用（第 7 章完整展开）
9⑨ 工具集 vs MCP：内置与外部
要解决什么

第 10 章会讲 MCP"无限扩展工具"，和本章的内置工具集什么关系？现在先建立一条清晰的边界。

核心思路

一句话概括：工具集是"内置的手脚"，MCP 是"外接的义肢"。

维度内置工具集MCP（第 10 章）
来源Hermes 内置注册表外部 MCP 服务器提供
数量40+ 固定近乎无限，随接随有
通信框架内直接调用Stdio（本地）/ HTTP（远程）协议
例子web_search、terminalGitHub API 工具、数据库查询工具

讲义原话点明两者关系：Hermes 内置了 40+ 工具，但通过 MCP 可以扩展到几乎无限。学习顺序上：先把内置的用熟，再按需接 MCP。

坑在哪
现象原因 / 怎么办
一上来就想全上 MCP 跳过内置工具内置是基础，很多需求内置就够；先掌握六/七/八章再说 MCP
以为 MCP 工具会出现在 /tools 列表里MCP 工具接入后会成为可用工具的一部分，hermes tools list 能查到它们（讲义第 48 页验证命令）
把 MCP 当"技能"装MCP 是工具通道，技能是流程文档，机制完全不同（第 10 章拆解）
10⑩ 终端与文件类工具的威力与风险
要解决什么

八大类里，"终端与文件"（terminal、process、read_file、patch）风险最高也最强大——它直接让 Agent 操作你的系统。需要正确认识它的双刃剑属性。

核心思路

危险与威力同源：terminal 类工具意味着 Agent 能执行任意命令、读写任意文件。它的威力（第四章建站/启动服务器全靠它）与风险（删库、覆盖文件、下载执行恶意内容）并存。

Hermes 的安全设计正是围绕它展开：

风险安全机制
危险命令（下载即执行等）安全扫描 + 命令审批（第四章 /approve 已见）
工具滥用工具集按需开关（本章）
来源不明技能安装带安全扫描（第 7 章）、MCP 需显式配置（第 10 章）

理解了这个，你就明白为什么"允许所有直接消息"等策略极度危险——陌生人能指挥 Agent 就等于间接拥有你的终端权限（呼应第 3 章）。

坑在哪
现象原因 / 怎么办
只看到 terminal 的威力忘了风险对公开放消息权限 = 把终端权限交给陌生人；第 3 章的权限策略不是摆设
审批弹窗一律 /approve always高危命令模式的永久放行会关掉安全闸门；单次/会话内放行即可
以为本地 Agent 没有权限问题本地 Agent 权限更大（直接碰你的系统），安全配置要更严而非更松
11⑪ 记忆类工具：进化的核心引擎预告
要解决什么

八类工具里"记忆与召回"（memory、session_search）和后面第 8 章是同一件事。但工具视角下的"记忆"和文件视角下的"记忆"是什么关系？先埋下伏笔。

核心思路

工具视角：memory（增删记忆）、session_search（搜历史会话）是两个可调用的工具；文件视角：它们操作的对象是 ~/.hermes/memories/ 下的 MEMORY.md / USER.md 和 state.db（第 8 章）。

工具做什么对应文件
memory添加/替换/删除记忆条目MEMORY.md / USER.md
session_search全文检索历史对话state.db（SQLite+FTS5）

这就把第八章的"记忆系统"挂到了本章的"工具地图"上：记忆不是玄学，是一个叫 memory 的工具在操作两个文件。先把"记忆类工具存在"记住，细节第 8 章展开。

坑在哪
现象原因 / 怎么办
以为"记忆"是模型自动发生的得有 memory 工具显式调用（写入记忆文件）才会记；工具没开=记不住
以为 session_search 会翻出所有历史它搜的是 ~/.hermes/state.db 里的历史会话，覆盖"聊过什么"，不是记忆文件
提前急着玩记忆工具先认识、命令后学；第 8 章用一整章把机制和命令讲透
12⑫ 给你的工具管理"操作手册"
要解决什么

把本章命令串成一份"随用随查"的操作手册，实操时不用翻全章。

核心思路

工具管理操作手册（三查三改）：

# 三查
hermes tools              # ① 查看所有可用工具（终端）
/tools list               # ② 查看当前会话工具（对话内）
hermes tools              # ③ 每个平台配置工具（交互式）

# 三改
hermes chat --toolsets "web,terminal"  # ① 本次任务限定工具集
/tools disable browser                 # ② 会话内禁用某工具
/tools enable rl                       # ③ 会话内启用某工具

配置后验证：/tools list 看变化是否生效（会话内）；持久配置后重启生效（跨会话）。

记住宏观顺序：查能力（hermes tools）→ 配场景（--toolsets / 交互式）→ 会话内微调（/tools enable|disable）→ 验证（/tools list）。

坑在哪
现象原因 / 怎么办
改了工具集后老会话没变化会话内用 /tools 即时生效；改配置文件的持久配置需重启网关/新会话
手册背不下来只记两个入口（hermes tools 终端 / /tools 对话内）+ 一个动作（enable/disable），剩下的现场 --help
验证时发现 disable 的还在确认名字拼写（如 browser 与 browser_navigate 是工具集与工具的区别）；yes 工具集名才有效
