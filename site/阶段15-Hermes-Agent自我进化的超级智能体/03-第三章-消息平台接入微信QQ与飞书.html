第三章　消息平台接入：微信 / QQ / 飞书

阶段 15 · Hermes-Agent 自我进化的超级智能体　|　平台实操　|　难度 ★★★
这一章在解决什么问题

第 2 章你把 Hermes-Agent 装好了，但它现在只是个"终端里的对话窗口"——你不可能时刻蹲在终端前跟它说话。要让它成为"随时随地触达你"的伙伴，必须把它接进你天天在用的聊天软件：微信、QQ、飞书。

接入聊天平台最大的拦路虎是什么？ 不是扫码本身，而是接入时的授权策略：接进来之后，谁可以私信它、谁能进群、群聊消息它要不要回应？这一章教你用"配对审批 + 群聊白名单"把安全和方便都拿住，还特意对比了微信的"设备配对"和 QQ/飞书的"扫码即接"差异。

学完这一章，你能回答：gateway 是什么、微信/QQ/飞书三端分别怎么接入、配对审批和群聊策略怎么选、为什么微信要额外做设备配对。同时手里的 Agent 真正住进你的聊天软件里，发消息就能指挥它。

这一章在整个知识库里的位置 上一章（第二章）：环境装好、模型选好、启动成功——但只在终端里能用。 本章 ← 你在这里：接消息网关（gateway），让 Agent 通过微信/QQ/飞书"聊天即操作" 下一章：第一个应用案例——提示词让 Agent 搜索热门 Agent → 总结成文档 → 生成科技感静态页面 再往后：SOUL.md 个性化（第 5 章）→ 工具与工具集（第 6 章）→ Skill 技能（第 7 章）→ 持久记忆（第 8 章）→ 皮肤（第 9 章）→ MCP（第 10 章）→ 定时任务与仪表板（第 11 章） 阶段终点：你的持久个人智能体住在消息软件里，既会聊天又会干活还能自我进化
学习提示

接入的核心心法只有一句："先扫码接通，再收紧权限"。不管哪个平台，接通动作都简单，真正要动脑的是"谁有资格指挥它"。本章把三种接入方式和两套策略（DM 授权 + 群聊处置）串成一条线记，别记零散步骤。

1① 先认识 gateway：消息进出的总管
要解决什么

"接入微信/QQ/飞书"说了半天，到底接的是什么？是到公众号后台改配置，还是到开放平台注册应用？需要先搞清接入对象：一个叫 gateway 的东西。

核心思路

Hermes-Agent 通过 gateway（消息网关） 连接外部消息平台。所有平台的接入都从一个命令开始：

hermes gateway setup

执行后进入交互式向导，它会引导你逐个接入平台并配置策略。gateway 的角色相当于"前台总管"：

消息方向gateway 的作用
你发消息给 Agent入站接收、鉴权、校验配对/白名单，再转给 Agent
Agent 回复/主动推送出站把回复投递回对应平台的对应会话

也可以理解为：平台见到的"机器人"其实就是 gateway。第 2 章安装时被跳过的"接入应用"一步，现在正式补上。

坑在哪
现象原因 / 怎么办
想找"平台后台配置"去改机器人大部分配置都在 hermes gateway setup 向导里完成，不是到微信/QQ 开放平台后台改
接入配置改完没生效操作节奏：配置完成后要重启网关，消息才能正常收发
以为是多个命令分别接三个平台一个 hermes gateway setup 入口，向导里逐个平台配置，别自己拆成三条命令乱跑
2② 接入 QQ：扫码就完事
要解决什么

QQ 是最省心的入口，先拿它练手，建立"接入平台没那么难"的信心。需要明确：QQ 接入到底几步、用哪个 App 扫。

核心思路

核心就一句：扫码接入就行，很简单哦~

流程就是：hermes gateway setup → 选择 QQ → 屏幕上出现二维码 → 用 QQ 手机客户端扫码 → 授权后即接通。接通后消息可以正常接收（验证点：消息可以正常接收）。

QQ 接入后，还要回答两个"权限问题"，下一节细讲：

  • DM 私信怎么授权（三种策略）；
  • 群聊怎么处理（禁用 / 全部 / 白名单）。

先扫码把通道打通，再做权限收敛——这就是本章心法"先接通，再收紧"。

坑在哪
现象原因 / 怎么办
用微信扫 QQ 的码必须用对应平台的客户端扫：QQ 用 QQ 手机端扫。扫错码等于没扫
扫码后一直不成功确认终端处于前台、二维码完整显示；必要时重跑 hermes gateway setup 重新出码
以为扫码完就万事大吉后面还有 DM 授权 + 群聊策略两个决策点，走完才是完整接入
3③ DM 私信三种授权策略怎么选
要解决什么

Agent 接通后变成"消息联系人"，理论上谁都能私信它、指挥它干活。如果来者不拒，等于把服务器、终端命令权限开放给所有人。必须收敛"谁有资格跟它说悄悄话"。

核心思路

三种 DM（直接消息/私信）授权策略，从上到下安全递增：

策略含义适用
使用 DM 配对审批（推荐）只有通过配对审批的设备/账号能私信个人使用首选，安全与便利平衡
允许所有直接消息任何人都能私信指挥它只在你完全信任环境且公开场景才考虑
仅允许已列明的用户 OpenIDs硬编码白名单账号团队/固定人群场景，清单要自己维护

QQ、微信、飞书三个平台里都标注"使用 DM 配对审批（推荐）"。微信/飞书还会有对应的配对审批流程（第 ⑤、⑦ 点），QQ 按相同策略选择即可。

坑在哪
现象原因 / 怎么办
图省事选"允许所有直接消息"等于把 Agent 的命令权限开放给全网，轻则被骚扰重则被执行危险命令，个人用户强烈不建议
选"仅允许已列明 OpenIDs"却不记得填清单空着=没有人能私信，容易误以为接入失败；先走配对审批最简单
三个平台的策略混着选每个平台接入时各自独立选择，别在 QQ 选完就以为微信也自动同步了
4④ 群聊消息怎么处理：三个策略
要解决什么

私信管住了，还有一关：群聊。Agent 可能被拉进群，群里的 @、消息、闲聊要不要都回应？回应错了/被滥用怎么办？需要一套群聊处置策略。

核心思路

QQ 接入时的群聊处置三选一（微信接入时也有同类选项）：

策略含义适用
禁用群聊（推荐）群里完全不理，只管私信个人使用首选，最省心最安全
允许所有群聊任何群的任何消息都响应群多且希望全量服务时才用，注意刷屏与误触发
只允许列出的群聊 ID硬编码白名单群，只有指定群能指挥团队固定群场景

飞书略有不同：推荐的是"仅在小组中提到 @ 时才响应（推荐）"——即群聊里只有 @ 它才回应，这是飞书场景下推荐的中间态（第 ⑦ 点展开）。

坑在哪
现象原因 / 怎么办
全部选"允许所有群聊"大群里一句话就触发 Agent 干活，可能造成资源浪费和指令混乱；个人使用默认禁用
选了禁用群聊但群里 @ 没反应这正是禁用群聊的预期行为，不是 bug；想响应就要换策略
群聊白名单 ID 不知道怎么拿各平台群 ID 获取方式不同；先用推荐策略（禁用/仅@）避免折腾
5⑤ 接入微信：比 QQ 多一步设备配对
要解决什么

微信接入和 QQ 不同的关键点：微信需要进行设备配对。很多人扫码后收不到消息，就是因为漏了这一步。需要把微信的完整接入链路理清。

核心思路

微信接入 = 扫码 + 授权策略配置 + 设备配对。步骤骨架：

  1. hermes gateway setup → 选择微信 → 扫码；
  2. 选 DM 授权策略（推荐 DM 配对审批）+ 群聊策略（推荐禁用群聊）；
  3. 设备配对：在 WSL 下执行配对命令完成配对（和 QQ 不同，微信需要先做设备配对）：
hermes pairing approve <平台> <配对码>
# 示例结构：hermes pairing approve weixin ZV5J582F
# 实际使用时用你扫码后得到的真实配对码替换 <配对码>

配对完成后，Agent 才正式与你的微信账号绑定，消息才能正常收发。

坑在哪
现象原因 / 怎么办
扫码后没执行配对就等消息微信必须有配对步骤，漏配对=消息不通，这是微信接入失败第一原因
配对码抄错导致 approve 失败配对码以扫码后界面/消息返回的为准，复制粘贴别手打
以为微信也能像 QQ 一样"扫码即通"微信更严，必须扫码+配对两步走；提前知道就不慌
在 Windows 终端跑配对命令配对命令要在 WSL 环境里执行（第 2 章已装好），别在 Windows 的 cmd/PowerShell 里跑
6⑥ 接入飞书：扫码 + 同样的授权体系
要解决什么

飞书是第三大入口，很多企业用户的主力 IM。它和微信 QQ 有哪些异同？接入流程是不是一样反复？

核心思路

飞书接入同样扫码接入就行，很简单哦~，整体思路与微信/QQ 同构：

  1. hermes gateway setup → 选择飞书 → 扫码；
  2. 配置 DM 授权策略（推荐 DM 配对审批）；
  3. 配置群聊策略（飞书推荐：仅在小组中提到 @ 时才响应）；
  4. 与接入微信一样，也需要配对。

可以看到：三个平台的接入骨架高度一致——扫码 → 选 DM 策略 → 选群聊策略 → （微信/飞书）配对。记住这条骨架，等于同时会了三个平台。

坑在哪
现象原因 / 怎么办
飞书扫码后也没消息和微信一样有配对环节，漏了就收不到消息（与接入微信一样，需要配对哦~）
飞书策略选项和微信不完全一样群聊策略里飞书多了"仅 @ 响应"（推荐），微信/QQ 是"禁用/全部/白名单"——按各平台实际选项选即可
以为飞书只能企业号才能接扫码用个人飞书客户端也能完成接入，按向导走
7⑦ 群聊策略的"飞书版"：仅在 @ 时响应
要解决什么

飞书推荐的群聊策略和 QQ/微信不同，是"仅在小组中提到 @ 时才响应"。为什么飞书推荐这条？它和"禁用群聊"什么区别？

核心思路

飞书的"仅在小组中提到 @ 时才响应"是介于"禁用"和"全响应"之间的按需响应策略：

策略Agent 行为场景
禁用群聊群里任何消息都不理完全不用群
仅在 @ 时响应（飞书推荐）只在群里被 @ 时才回应，平时潜水团队协作群首选：想用它就 @，不想被打扰就无视
允许所有群聊群里每条消息都参与群少、消息量可控

这条策略的精髓：触发权在群成员手里（@ 才动），既保留了群协作能力，又避免了刷屏与误触发。QQ/微信虽然推荐"禁用群聊"，如果之后需要群场景，思路是相通的。

坑在哪
现象原因 / 怎么办
群里 @ 了没反应检查会话是否已完成配对/审批；以及 @ 是否真的触发了机器人（个别平台需要精确 @ 昵称）
以为"仅 @ 响应"省事就所有平台都这么设各平台推荐策略不同（QQ/微信推荐禁用群聊），按平台向导的推荐走最稳
群里发消息被回了一堆说明当前策略是"允许所有群聊"，去 gateway 配置里改成禁用或仅 @
8⑧ 授权信息是"谁"，而不是"什么功能"
要解决什么

很多新手接完平台发现"机器人没权限干这干那"，第一反应是去平台后台开权限。但 Hermes 的"授权信息"概念和平台权限是两回事，需要先厘清。

核心思路

接入时反复出现"如何授权信息？"这个标题，底下跟的是"使用 DM 配对审批 / 允许所有直接消息 / 仅允许已列明的用户 OpenIDs"三个选项——注意：这里的"授权"授权的是"谁可以跟 Agent 对话"（人或设备），不是"Agent 能用哪些功能"。

概念对象在哪配
DM/群聊授权谁有权指挥 Agent（人/设备/群）gateway 接入向导
工具集授权Agent 能调用哪些能力（terminal/web/...）hermes tools（第 6 章）
模型授权用哪家模型的额度hermes model（第 2 章）

三条线是独立的：接入向导管"谁叫得动它"，工具配置管"它能做什么"，模型配置管"它用什么脑子"。搞混了就会在错误的地方找错误的功能开关。

坑在哪
现象原因 / 怎么办
"Agent 不会用某个工具"却去改接入策略那是工具集问题，去 hermes tools 配置，不是接入向导的锅
"陌生人能指挥它"却只改模型那是 DM 授权问题，把接入策略收成"DM 配对审批/白名单"
三个平台的授权策略记成一套独立配置，改哪端生效哪端；多平台时逐个核对
9⑨ 配置完为什么必须重启网关
要解决什么

接入策略改完、配对也做了，但消息还是不通。有一句"后续全部 Yes 即可，然后重启网关"——这个重启为什么是必做项？

核心思路

gateway 在启动时加载平台连接、授权策略、配对状态等配置；新增/修改的接入配置不会在运行中热生效，需要重启网关让配置重新加载。

操作节奏（微信接入示例）：

  1. 扫码 + 选授权策略（DM 配对审批）+ 群聊策略；
  2. "后续全部 Yes 即可"——按推荐项确认；
  3. 然后重启网关；
  4. 消息可以正常接收。

常见重启方式：退出当前 gateway 进程/会话后重新 hermes gateway setup，或按向导提示操作。只要"改过接入配置"，就把"重启网关"刻进肌肉记忆——改配置必重启，这是 gateway 场景的通用规律（本阶段第 11 章定时任务也遵循类似重载逻辑）。

坑在哪
现象原因 / 怎么办
改了策略不重启就测测出来的是旧配置行为，极易误判"接入失败"；先重启再测
重启后消息还是不通回到配对环节：微信/飞书是否完成配对？配对码是否正确？
每次重启都问"要不要 Yes"向导的 Yes 基本都是推荐项（DM 配对审批、禁用群聊等），个人使用一路推荐没毛病
10⑩ 接入后的第一轮"验收测试"
要解决什么

接完平台怎么确认"真的接通了"？接完就撒手，结果第二天才发现消息没进来，体验会很差。需要一套接入后的验收清单。

核心思路

按以下顺序对三个平台做统一验收（以微信为例，其余同理）：

验收项操作预期
私信可达用已完成配对的账号给 Agent 发一条"你好"Agent 正常回复
策略生效用一个未配对的账号私信不响应/进入审批流程（证明 DM 策略在工作）
群聊策略在有白名单权限的群里 @ 它按所选策略响应或不响应
收发稳定发 2-3 轮有来有回消息不丢、回复不超时
配对状态复查配对命令的输出状态配对成功、无 pending

验收时重点验证的不是"能收到"，而是"不该收的收不到"——策略收紧才是安全达标。

坑在哪
现象原因 / 怎么办
验收只测"能收到"不测"拒收"安全验证的核心正是"未授权进不来"，只测可达性等于没测安全
用未配对账号测试把 Agent 当 bug未授权不响应正是预期行为，别当成故障去修
验收过了就再不管网关平台侧掉线、Token 过期都可能让接入失效；偶尔复查，出问题先重启网关再查配对
11⑪ 三种平台接入全景对比
要解决什么

微信/QQ/飞书三个平台装在脑子里还容易混，需要一张总表把差异与共性一次性讲透。

核心思路
维度QQ微信飞书
接入动作扫码扫码 + 设备配对扫码 + 配对
DM 推荐策略DM 配对审批DM 配对审批DM 配对审批
群聊推荐策略禁用群聊禁用群聊仅 @ 时响应
配对命令无（扫码即通）hermes pairing approve <平台> <配对码>同微信，需配对
教材定位最简入口，练手首选经典双步接入（扫码+配对）企业场景，群聊@ 响应为特色

共性规律一句话：所有平台都"扫码开通道 + 配对/审批定权限 + 群聊策略控范围 + 改配置必重启网关"。差异主要在"要不要配对"和"群聊怎么控"两处。

坑在哪
现象原因 / 怎么办
记忆里把"微信要配对"记成"QQ 要配对"QQ 扫码即通，微信/飞书才需要配对；用上表锚定
以为三端一次配完永久生效Token 过期、平台风控、版本升级都可能失效，日常使用定期复查
从网上抄来别的 Agent 的接入命令Hermes 的命令体系是 hermes pairing / hermes gateway，认准自己的框架命令
12⑫ 平台没全接上也可以继续往下走
要解决什么

有人会纠结"三个平台必须一口气全接完吗？"时间紧、账号缺、某个平台扫码不方便，会不会卡住进度？

核心思路

不需要全接，一个平台跑通即可继续。理由：

  • 接入是增量可加的：先接一个（推荐 QQ 最省心），走通"聊天即操作"体验，后续随时 hermes gateway setup 补接其他平台；
  • 后续章节（案例、SOUL、工具、技能、记忆）不依赖具体平台——它们作用在 Agent 核心，与走哪个入口无关；
  • 多平台只是"触达入口"多，Agent 的脑子、记忆、技能是同一个。

所以：先接一个平台，验收通过，直接进第 4 章做第一个真实案例；其余平台按需补接。

坑在哪
现象原因 / 怎么办
卡在某个平台接入不成功就停住整个进度换一个平台先通（如 QQ），不阻塞主线；回头再排之前的问题
以为平台没接全=后面章节没法做后续章节是 Agent 核心能力，与哪个入口无关，接一个就能全跑
三平台配置混在一起互相干扰各平台独立配置；一个平台的配对码/策略错了只影响它自己

本章小结

这一章你拿到了住在聊天软件里的 Agent：

拿到了什么为什么要紧
gateway 认知：hermes gateway setup 是全部接入的总入口；消息进出的"前台总管"找到接入的"唯一钥匙"，不再混淆平台后台与网关配置
QQ 接入：扫码即通，最简入口一分钟体验"聊天即操作"，建立信心
微信接入：扫码 + 设备配对（hermes pairing approve）+ 授权策略微信接入的关键差异就是配对，漏配对=消息不通
飞书接入：扫码 + 配对 + "仅 @ 时响应"群聊策略企业场景的推荐形态，按需触发不刷屏
DM 三策略：配对审批（推荐）/ 全放 / 白名单收敛"谁有权指挥 Agent"，安全底线
群聊三策略：禁用（推荐）/ 全响应 / 白名单（飞书为仅 @）控住群聊滥用，防刷屏防误触发
铁律：改配置必重启网关不重启=旧配置，一切验收都会失真

一句话记住本章：扫码接通、配对定权、群聊收紧、改完重启——平台接入不外如是；先接一个，立刻去干活。
