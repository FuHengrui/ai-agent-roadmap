阶段 15 · Hermes-Agent 自我进化的超级智能体　|　实战案例　|　难度 ★★★
这一章在解决什么问题

第 2 章装好、第 3 章接通，但你还没真正见过 Hermes-Agent 完整干一次活。书上说的"会进化、会做事"到底是包装还是真本事，干一次真实的活就知道了。

一个"完整交付"难在哪？ 它同时考验 Agent 五件事：听懂复杂自然语言指令（多步骤、含格式要求）、调度多个工具（搜索、写文档、生成网页）、自己拆解任务并管理进度、遇到危险命令会请求审批、最后把产物落到你能找到的地方。下面这条经典提示词，串起了以上全部场景——从"搜索热门 Agent"到"生成科技感静态页面并在本地启动"。

学完这一章，你能回答：一条"一句话需求"如何被拆解成完整工序、Agent 干活时界面上的每行日志在说什么、危险命令审批怎么处理、产物放在哪、以及"找不到文件"这种真实事故 Agent 如何补救。这是阶段 15 的第一场"真刀真枪"。

这一章在整个知识库里的位置 上一章（第三章）：Agent 已住进微信/QQ/飞书，聊天即操作。 本章 ← 你在这里：用一条真实提示词，让 Agent 独立完成"搜索 → 总结 → 建站 → 启动"整条交付链 下一章：SOUL.md 个性化定制——把 Agent 调教成"你的" Agent（语气、风格、立场） 再往后：工具与工具集（第 6 章）→ Skill 技能（第 7 章）→ 持久记忆（第 8 章）→ 皮肤（第 9 章）→ MCP（第 10 章）→ 定时任务与仪表板（第 11 章） 阶段终点：你的持久个人智能体既能独立交付任务，又能自我进化
学习提示

本章的核心不是背命令，而是观察 Agent 的"行为模式"：它怎么拆任务、怎么用工具、遇到审批怎么处理、干完怎么汇报。把这套行为模式看懂，你后面写提示词、管 Agent 都有判断力。

1① 一条提示词，五层要求
要解决什么

案例的起点是一条自然语言提示词。要理解这场"完整交付"，先拆解这条提示词里到底藏了多少约束条件——这决定了 Agent 要同时满足什么。

核心思路

原始提示词（含个别笔误，逻辑如下）：

> 帮我上网看看最近比较火的 Agent 有哪些？然后总结成文档，注意文档中要附上和技术相关的重要链接（官网、重要博客、GitHub 等）。接着，帮我生成一个静态页面，专门用来展示这个文档。网页要有科技感。完成后，告诉我资源存放在哪里，帮我再本地启动这个前端页面。

拆解这条提示词，它实际上是五个任务的叠加：

#子任务隐含要求
①上网搜最近的 Agent需要网络搜索工具，且要"最近比较火"（时效性）
②总结成文档输出文件，不是聊天里说说
③附上重要链接文档内容有格式要求（官网/博客/GitHub）
④生成静态页面展示文档要写 HTML/CSS，且"要有科技感"（视觉要求）
⑤告诉我资源位置 + 本地启动要交付产物位置 + 起一个本地服务器

能用两行字描述完整交付，本身这就是 Agent 的目标理解能力——它得先听懂，再拆解，再执行。

坑在哪
现象原因 / 怎么办
以为提示词是"随便说说它随便做"这条提示词暗含五个约束，Agent 把它们全识别出来并逐一满足，才是"完整交付"
提示词里的错别字（"卡看""存放再哪里"）不影响理解真实场景提示词不用过于完美，模型能纠错；重点是约束齐全
以为"总结成文档"是聊天输出案例里它是落盘文件（AI-Agents-2025-2026.md），"生成文档"意味着写文件，这个理解差别很关键
2② 先看 Agent 怎么"接单"：任务确认与开场
要解决什么

Agent 收到复杂需求后的第一反应是什么？是直接闷头干，还是先确认理解？这决定了后续过程是否可控。

核心思路

Agent 的开场白：

> "好的！让我一步步来。先上网搜索最近热门的 AI Agent，然后整理成文档，再生成一个科技感十足的静态页面。"

注意它的行为模式：复述任务 + 预告步骤。这样做有两个好处：

  1. 对齐预期：用户能立刻发现 Agent 理解偏没偏（"等等，我不是要整理，是要对比……"）；
  2. 自我规划：它把"搜索 → 文档 → 页面"的顺序说出来，等于给自己立了执行计划。

接下来作业界面会不断输出 ⏳ Still working...（仍在工作）的进度心跳，告诉你它没有卡死，正在推进。

坑在哪
现象原因 / 怎么办
看到长时间 "Still working..." 就以为死机它是多轮迭代执行（案例里迭代计数从 2 一直到 16+），长时间工作是常态，别中途打断
没看到开场复述就担心理解错了有些模型/场景省略复述直接动手；以产物是否符合约束为准判断理解对不对
以为一场任务几十秒就完案例从 3 分钟到 21 分钟，历经十几轮迭代；教训：复杂任务要有耐心，别频繁催促
3③ 工具链第一环：网络搜索（Hacker News API）
要解决什么

"上网看最近比较火的 Agent"——这个动作 Agent 是怎么实现的？它调了什么工具？为什么我们看到的是 curl 命令而不是一个"搜索框"？

核心思路

Agent 第一轮开工，日志里出现的是 curl 调用 Hacker News 搜索 API：

curl -s --connect-timeout 10 "https://hn.algolia.com/api/v1/search?query=...&tags=story&hitsPerPage=20" 2>&1 | python3 -c "..."

这是 Hermes-Agent 内置 web / terminal 工具集的真实工作方式：它不点浏览器搜索框，而是直接调 API + 用 python 处理返回的 JSON。后续又出现第二次搜索（关键词换成了 browser AI agent 2025 2026），说明它在做多关键词检索，而不是搜一次就收工。

这提示我们理解 Agent 的"上网"：= 一系列 API 调用 + 数据处理，是自动化的、可重复的。

坑在哪
现象原因 / 怎么办
以为"上网"就是打开浏览器人工搜索后台是 curl + API + 解析脚本，速度快、结果结构化；只有 API 不够时它才动浏览器（案例后续"Google 被墙了，我用浏览器直接搜索"）
curl 命令里带 python3 解析，看着像不安全这正是"危险的命令需要审批"的案例——curl 结果直接管道给 python3 执行，属于高危模式（下一点细讲）
以为一次搜索就够案例执行了多轮不同关键词的搜索，覆盖不同角度；"全面"取决于迭代次数
4④ 危险命令审批：Agent 的安全闸门
要解决什么

案例中最有教学价值的一幕：Agent 想执行 curl | python3 组合，被安全扫描拦下来，要求用户审批。这个机制是什么？为什么重要？

核心思路

日志显示：Agent 的命令触发了 Dangerous command requires approval（危险命令需要审批），安全扫描给出的原因是：

> [HIGH] Pipe to interpreter: curl | python3 —— 把 curl 下载的内容直接管道给解释器执行，下载的内容会在未经检查的情况下被执行。

这正是"下载即执行"经典漏洞模式（供应链攻击路径之一）。Hermes-Agent 的安全闸门会：

  1. 识别高危命令模式；
  2. 给出风险说明与更安全的替代建议（可参考 tirith / vet 等检查工具）；
  3. 等用户决策：/approve（本次执行）/ /approve session（本会话放行）/ /approve always（永久放行）/ /deny（拒绝）。

审批权在用户手里，这是"本地 Agent"安全模型的关键——模型再聪明，危险操作也要人来拍板。

坑在哪
现象原因 / 怎么办
一看到审批弹窗就担心"是不是中毒了"这是系统主动拦截高危命令，正是安全设计在起作用；不是中毒
图省事直接 /approve always永久放行意味着以后同类高危命令不再询问，风险敞口永久开放；除非你完全信任来源，否则用 /approve 单次放行
把"安全扫描提示"当成 Agent 的废话跳过扫描器提示"curl 结果直接执行"是真实攻击面，阅读提示能帮你判断该不该放行
认为所有 Agent 都有这层闸门不是所有框架都有；Hermes 的亮点之一就是内置安全扫描与命令审批，别把它换成裸执行
5⑤ 浏览器兜底：当 API 不灵时的第二方案
要解决什么

案例中段出现转折："Google 被墙了，我用浏览器直接搜索。""搜索结果不太对，让我换到国际版。"——Agent 在搜索碰壁时做了什么？这透露了它的什么能力？

核心思路

日志还原了 Agent 的降级与自纠过程：

时刻Agent 行为能力点
搜索 API 结果不佳"Google 被墙了，我用浏览器直接搜索"工具降级：API → 浏览器自动化兜底
浏览器搜索结果不对"搜索结果不太对，让我换到国际版"结果自纠：对返回质量做判断并换方案
找到相关文章"让我深入查看几篇最全面的来收集信息"信息筛选：不满足于表面，深挖权威来源

这三步展示的不只是"会用工具"，而是会判断工具结果好不好、并主动换路径——这正是"自主 Agent"和"脚本"的区别。Google 访问受阻是环境现实，Agent 不硬刚，而是绕路。

坑在哪
现象原因 / 怎么办
以为 Agent 只会"一条路走到黑"案例明确演示了 API→浏览器→换国际版的两级降级，失败会换路不会死磕
以为浏览器自动化随时可用它依赖 Node.js v22（第 2 章自动装的组件就是为它准备的），环境不全时浏览器能力会报错
把"搜索结果不太对"当作 Agent 无能恰恰相反，能发现结果不对并调整是高级能力；评估 Agent 要看它如何应对失败
6⑥ 进度心跳：Still working 里藏着任务拆解
要解决什么

案例全程日志都是 ⏳ Still working... (3 min elapsed — iteration 2/90, running: delegate_task)。这行字背后代表什么？"iteration 2/90"是什么意思？

核心思路

进度心跳的格式是：已耗时 + 第几轮迭代/总迭代上限 + 当前正在运行的子任务。

拆解关键字段：

字段含义
3 min elapsed从开工到现在的耗时
iteration 2/90执行到第 2 轮，总迭代上限 90 轮（防止无限循环）
running: delegate_task当前正在调用的工具是"任务委托"（delegate_task）

delegate_task 是 Hermes 内置工具（第 6 章工具集里的"Agent 编排"类）——Agent 会把子任务委派给子 Agent 并行处理。这也是为什么后面会有"子任务超时了，我直接来搜索吧"这样的自白：它连子任务的失败都能接管重做。

90 轮迭代上限告诉我们：Agent 的自主性是有边界的，不会无限空转。

坑在哪
现象原因 / 怎么办
看到 iteration 计数上涨就焦虑迭代上限（90）是保护机制不是故障；计数在涨=任务在推进
任务耗时超过想象就判定"异常"复杂任务 15-20 分钟正常（案例从 3 分钟干到 21 分钟）；这个案例本身就是长任务
以为所有子任务都一次成功案例里子任务超时被父任务接管重做——失败处理也是 Agent 能力的一部分
7⑦ 写到一半的转折：文档 → 页面
要解决什么

收集完信息后，Agent 如何"收尾"？从"写文档"到"做网页"之间它自己是怎么衔接的？

核心思路

日志给的衔接线索：

> 信息足够了！现在让我汇总整理文档并生成网页。→ 先写 Markdown 文档：→ 文档写好了！现在来生成科技感静态页面。

这个衔接展示了 Agent 的执行链管理：前面 5 个子任务（第 ① 点）它按依赖关系排队执行——先搜齐信息、再写文档、再基于文档做页面，不会任务还没完成就急着出网页。

产出物的规模从最终汇报能反推：Markdown 文档 14KB、页面 43KB、收录 20+ 项目分 6 大类——说明"总结"不是敷衍几句，而是真材实料的整理。

坑在哪
现象原因 / 怎么办
以为 Agent 会"边搜边出页面"它有任务依赖意识：文档完成才开工页面，输出对得上顺序
以为"生成网页"是套模板案例页面带动态粒子背景、霓虹光效、卡片悬停动画、对比表格——是定制开发不是套壳
文档 14KB/页面 43KB 当成固定值每次执行结果大小随内容变化，重要的是"有实质内容"这个性质
8⑧ 交付汇报：文件在哪 + 怎么访问
要解决什么

任务干完，Agent 怎么让用户"拿到结果"？好的交付不是丢一句"完成了"，而是告诉你文件在哪、怎么打开、内容是什么。

核心思路

案例结尾 Agent 的汇报结构化得堪称模板：

> 📦 资源存放位置：所有文件在 ~/ai-agents-showcase/ 目录下 > - AI-Agents-2025-2026.md（14KB 完整 Markdown 文档） > - index.html（43KB 科技感静态展示页面） > 🌐 访问方式：本地服务器已启动，访问 http://localhost:8080 > 📋 内容涵盖：收录 20+ 热门 AI Agent 项目，分 6 大类（多智能体框架、编程 Agent、浏览器 Agent、协议标准、低代码平台、企业级）

三大块齐全：位置（路径+文件清单）、访问（URL）、内容概览（收录了什么）。这种"交付即汇报"的习惯，正是指挥 Agent 干活的理想体验——你不用自己翻目录找。

坑在哪
现象原因 / 怎么办
以为要自己进 WSL 一层层翻目录Agent 会明确告诉路径并解释文件用途；找不到再让它复制（见下一点）
汇报里的 URL 打不开确认本地服务器进程还在（WSL 里跑的 http://localhost:8080 在 Windows 浏览器通常也能访问）；重启后可访问性下降
内容概览很丰富=Agent 编的？文档与页面来源是搜索结果整理，样例数据以实际执行为准；评估时抽查文档里的链接是否真实
9⑨ 真实事故：用户找不到文件，Agent 如何补救
要解决什么

案例最真实的一幕：Agent 汇报完，用户说"没找到文件所在位置，能清晰一点么"——交付翻车了。Agent 怎么处理这个"用户没找到"的问题？

核心思路

Agent 的补救动作非常标准：

  1. 定位问题：用户不看 WSL 路径，习惯看 Windows 桌面；
  2. 换交付位置："你的 Windows 用户名是 <你的用户名>。我把文件复制到你的 Windows 桌面上，这样你就能直接找到了"；
  3. 新路径汇报：C:\Users\<你的用户名>\Desktop\ai-agents-showcase\（WSL 文件被复制到 Windows 侧）；
  4. 双保险："直接双击 index.html 就能看 / 或者访问 http://localhost:8080（服务器还在 WSL 里跑着）"；
  5. 确认反馈："现在桌面能找到文件夹了吗？"——做完了还问你确认。

这演示了第 2 章"WSL 与 Windows 文件互通"的实际应用：Agent 能读取 Windows 用户名、跨文件系统复制文件、并且用"用户听得懂的方式"交付。它不甩锅、不辩解，直接调整交付方式直到用户满意。

坑在哪
现象原因 / 怎么办
WSL 里的路径 Windows 用户不熟就让 Agent 复制到 Windows 桌面再交付，这是用户视角最友好的位置（案例已演示）
以为只能给一个访问方式案例给了"双击文件 + 访问 URL"双保险，交付冗余越高用户越省心
交付完没有"确认反馈"环节好的交付带二次确认；如果你的 Agent 不确认，提示词里可以加一句"完成后问我是否满意"
10⑩ 案例复盘：一场"完整交付"包含哪些环节
要解决什么

看完整个案例，需要把散落的片段串成一条"完整交付链"，作为以后判断 Agent 是否"靠谱"的参照系。

核心思路

把案例 21 分钟的过程归纳为七环节交付链：

#环节案例中的证据
1听懂需求复述任务并预告步骤
2拆解规划五层约束拆成子任务链
3工具调度curl API、python 解析、浏览器兜底
4安全把关危险命令触发审批，用户拍板
5失败自纠子任务超时接管、搜索结果不对换方案
6组装交付文档 + 网页 + 本地启动
7交付汇报与补救路径/URL/内容概览，找不到就复制到桌面

这条链就是"自主 Agent"的定义级行为。以后你指挥 Hermes 干活，评估它"行不行"就看这七环有没有走全。

坑在哪
现象原因 / 怎么办
以为"能聊"= Agent 合格合格线是七环交付链，不是话术；用"给个真实任务"检验它
某环节失败就全盘否定失败与自纠（第 5 环）恰恰证明它是"自主的"；看它能不能从失败里走出来
以为每次任务都要 20 分钟小任务秒级完成；这个案例长是因为搜索+建站都是重活，耗时随任务规模浮动
11⑪ 从案例看 Hermes 的核心优势
要解决什么

案例跑完，回到第一章的承诺："会进化的伙伴"。这个案例里能看到哪些"进化"的苗头？它和普通 Agent 的差别到底落在哪？

核心思路

从案例里能观察到 Hermes-Agent 区别于普通 Agent 的三个"进化特征"：

特征案例证据意义
自主规划拆五层约束、排队执行子任务、90 轮迭代上限内自我管理不是"一步步被喂指令"，而是"接单后自己排工"
工具降级与自纠API→浏览器→换国际版；子任务超时接管有"判断力"，会绕路会补救
安全内置危险命令审批、/approve 体系自主能力越强，安全闸门越重要——它把"自主"和"可控"绑在一起

结合第一章：这次任务中的搜索方式、文档结构、网页风格，都可能成为后续自动沉淀的技能/记忆素材——一次完整交付，就是一次进化的养料。

坑在哪
现象原因 / 怎么办
案例成功就以为"什么任务都放心交给它"案例有 90 轮上限、命令审批兜底；高风险/破坏性任务仍需人工审核，它自主但你要掌舵
没看到"进化"直接发生就怀疑进化是跨任务积累的（技能/记忆沉淀在第 7/8 章讲），单次任务看不到"长出来"很正常
以为审批机制是"半自动=不智能"恰恰相反：该自主的自主、该请示的请示，这是成熟 Agent 的分寸感
12⑫ 给你的第一条实战提示词框架
要解决什么

看完案例，你手痒想自己试。怎么写出"高质量任务提示词"？有没有可复用的框架？

核心思路

从案例提示词倒推出一条五要素任务提示词框架（照着填就能用）：

要素案例原文作用
动作帮我上网看看 / 搜一下明确要干什么
对象+范围最近比较火的 Agent限定搜什么、多新
输出格式总结成文档，附重要链接定义产物与规格
增值要求生成科技感静态页面展示加码交付形态
交付方式告诉我资源位置，本地启动明确"结果给我放哪、怎么用"

记住：约束越具体，交付越可控。案例提示词虽然口语化，但五个要素全齐，所以 Agent 才能"无歧义"地跑完整个交付链。

坑在哪
现象原因 / 怎么办
只写"帮我做个东西"就期待完整交付缺输出格式/交付方式，Agent 只能自由发挥；把五要素补全
要素全却互相矛盾（如"简短文档+详细页面"）冲突会让 Agent 猜；一次只提一致的目标
以为提示词必须长要素齐全比长度重要；案例提示词本身也就两句话，信息密度高

本章小结

这一章你亲眼见证了一场从一句话到一次完整交付的全过程：

拿到了什么为什么要紧
五层要求的提示词：搜（时效）→ 写文档（含链接）→ 建页面（科技感）→ 交付位置 + 本地启动学会"要素齐全"的指令写法，这是你指挥 Agent 的基本功
危险命令审批：curl\python3 触发的安全扫描与 /approve 决策体系读懂安全闸门，正确使用审批权限，别永久放行
工具降级链：API → 浏览器 → 换国际版，子任务超时自动接管理解"自主=会绕路、会自纠"，评估 Agent 能力的正确角度
进度心跳：Still working + iteration 2/90 + running 工具看得懂作业日志，不再把长任务误判为卡死
交付汇报模板：位置 + 文件 + URL + 内容概览你的验收标准：交付完必须能拿到路径和访问方式
事故补救示范：用户找不到文件 → 复制到 Windows 桌面 → 二次确认WSL/Windows 文件互通的实际运用，交付要落在用户视角

一句话记住本章：好的 Agent 交付 = 听懂需求 + 自主拆解 + 工具降级 + 安全审批 + 失败自纠 + 汇报补救；你只需下一条"五要素"指令，剩下的交给它，但权限永远在你手里。
