学习提示

这一章是典型"装环境"章，按顺序机械执行即可，难点只有三个：① Windows 先 WSL2；② 装前还原 pip/npm 镜像；③ 模型选错用 hermes model 补救。把这三句话抄在纸上，你就能少走 80% 的弯路。

1① 唯一前提：先装好 Git
要解决什么

安装说明里列了一堆东西（Python、Node、ripgrep、ffmpeg），新手容易以为要手动逐个装。需要明确：哪些必须自己装、哪些是安装脚本包办。

核心思路

结论很明确：唯一的前提条件是 Git。安装程序会自动处理其他所有事项——你无需手动安装 Python、Node.js、ripgrep 或 ffmpeg，安装程序会自动检测缺失的组件并安装。

Git 下载：https://git-scm.com/?hl=zh-cn （官方中文页面），一直 Next 装完即可。装完可在终端验证：git --version 能打印版本号就算可用。

安装脚本自动代劳的组件及用途：

组件用途
uv快速 Python 包管理器
Python 3.11通过 uv 安装，无需 sudo
Node.js v22浏览器自动化和 WhatsApp 桥接
ripgrep快速文件搜索
ffmpegTTS 的音频格式转换
坑在哪
现象原因 / 怎么办
想手动把 Python/Node 全装一遍"求稳"安装脚本会自动装它要的版本；手动装老版本反而可能冲突。让脚本管，你只保证 Git 可用
Git 装完不确定成没成终端跑 git --version；能输出版本即成功，报"不是内部或外部命令"则检查 PATH 或重装
以为要 sudo 装 Python笔电/桌面环境没 sudo 也不怕——Python 3.11 由 uv 安装，不需要系统权限
2② Windows 用户先过 WSL2 这一关
要解决什么

如果你是 Windows 用户（本阶段多数用户是）：官方现在也提供原生 Windows 脚本（install.ps1），但本教程仍以 WSL2 为主线——依赖、路径、报错都好排查，踩的坑最少——原生可以 PowerShell 直接跑 iex (irm https://hermes-agent.nousresearch.com/install.ps1)，或者装 MSIX 桌面包。本章仍以 WSL2 为主线，因为网关常驻、文件权限这些坑少一些；想用原生，把本节换成官方 Windows 指南即可，后面的命令一致。

核心思路

结论很明确：原生 Windows 支持仍处于实验阶段，请安装 WSL2 后在其中运行 Hermes Agent。WSL2 是微软官方提供的"Windows 里的 Linux 子系统"，装了它，Linux 命令、Linux 环境都能在 Windows 里跑。

安装 WSL2 的官方姿势：

  1. 以管理员身份打开 PowerShell；
  2. 输入：wsl --install；
  3. 按提示重新启动计算机。

重启后可以验证/安装指定发行版：

wsl --list --verbose        # 列出已安装的发行版及其 WSL 版本
wsl --install -d Ubuntu-24.04   # 安装 Ubuntu 24.04 发行版

装好 Ubuntu 后，进入 WSL（终端输入 wsl 即可），Hermes-Agent 就装在这个 Linux 环境里。

坑在哪
现象原因 / 怎么办
装完 WSL 没生效，命令找不到大概率是重启没完成。特别提示：官网说只重启一次，实际可能要 2-3 次
用"关机再开机"代替"重启"特别注意：是重启，不是关机再开机——两者生效机制不同，务必选"重启"
装了 WSL1 或旧发行版用 wsl --list --verbose 看 VERSION 是否为 2；不是 2 则 wsl --set-default-version 2 或按提示升级
管理员 PowerShell 拼写/权限不对开始菜单搜"PowerShell"→ 右键"以管理员身份运行"，再执行 wsl --install
3③ 一键安装：真正的安装命令就一行
要解决什么

环境备齐后，进入正式安装。安装步骤多不多？要不要翻墙？命令是什么？这一节给你确切的答案。

核心思路

Hermes-Agent 安装无需任何前置依赖手工处理（Git 除外），支持 Linux、macOS 和 WSL2，一键自动安装所有组件。安装命令只有一行：

curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash

要点拆解：

  • curl -fsSL：静默跟随重定向下载脚本（-f 失败不报错、-s 静默、-S 显示错误、-L 跟随跳转）；
  • 脚本下载后直接交给 bash 执行，自动检测缺什么装什么；
  • 想看到每一步的执行过程、便于排查问题，可加 -x：... | bash -x（这一点值得专门记住）。

网络提示：安装时无需翻墙；"非要翻墙，请你自重（如果实在下载不动，那你翻吧）"。

坑在哪
现象原因 / 怎么办
装到一半失败，报各种组件错误先看是不是没还原 pip/npm 镜像（下一节专讲）；再看 WSL 里网络是否正常
想找"Windows 原生安装包"别找了，原生 Windows 实验性——规规矩矩在 WSL2 里装
复制命令时网址少了个 s / 拼错地址是 hermes-agent.nousresearch.com/install.sh，与前章官网域名一致；从官方页面复制最稳
等了很久没动静以为卡死自动安装依赖阶段确实"安装时间有点长"，保持网络畅通耐心等
4④ 翻车重灾区：先把 pip 和 npm 镜像还原
要解决什么

这一步是给"用国内镜像源"的用户专门排雷的。很多人装 Python/Node 项目时配过清华、阿里等镜像，这些配置在 Hermes 安装时反而会导致安装失败——而且会失败得莫名其妙。

核心思路

加粗警告：程序员注意！请将 pip 镜像和 npm 镜像还原（别问，问就是坑，大坑，天坑）。

原因：安装脚本会自动调用 pip / npm 下载组件，如果你之前配置了国内镜像源（如清华 PyPI、淘宝 npm），部分镜像的同步延迟或缺包会导致安装脚本认为"依赖装不上"或装到旧版本，从而中断或行为异常。还原成官方源再跑安装脚本，是最省心的做法。

常见镜像还原操作示例（改回官方源）：

# pip —— 删除或注释用户级镜像配置
pip config unset global.index-url

# npm —— 改回官方源
npm config set registry https://registry.npmjs.org/

如果之前是写进配置文件（如 ~/.pip/pip.conf、~/.npmrc）的，也一并改回官方源。装完 Hermes 后如果需要，可以再改回镜像。

坑在哪
现象原因 / 怎么办
"我没配过镜像啊"也装失败检查全盘配置文件：pip config list、npm config get registry，有非官方输出就还原
还原了还失败确认在正确的环境里执行：WSL2 里的 pip/npm 和 Windows 的是两套，都要还原
装完又想用回镜像可以改回，但注意以后凡是 Hermes 相关升级、技能安装也可能受镜像影响，出问题优先想到它
只用 pip 没用过 npm，只还原 pip 行不行安装脚本两个都要用，两个都还原才保险
5⑤ 安装流程：从下载到启动的完整节奏
要解决什么

命令敲下去之后会发生什么？中间要不要输入什么？走到哪一步算成功？提前要知道全流程，避免瞎等或误操作。

核心思路

安装流程大致四步：

步骤发生什么你要做什么
1. 自动装依赖检测并安装 uv/Python/Node/ripgrep/ffmpeg 等，时间较长保持网络畅通，耐心等待（安装时间有点长）
2. 输入密码提示输入 WSL 的密码输入 WSL（Ubuntu）用户密码，进入下一步
3. 选择模型向导询问选哪个 LLM 服务商/模型选熟悉的或额度够的（如 DeepSeek）；全部跟着推荐走也可以
4. 接入应用询问是否接入微信/QQ/飞书等这里可以先跳过，后面单独接入（第 3 章）

第 4 步之后，输入 hermes 启动应用，看到正常对话界面即安装成功（第 8 页"到这里就成功了!"）。

坑在哪
现象原因 / 怎么办
等依赖自动安装时反复切窗口/断网安装中途断网=整体失败，重跑一行命令最稳；保持终端别关
忘了 WSL 密码装 WSL 发行版时设置的就是；忘了可在 Windows 里对发行版执行 wsl -u root 重置
接入应用时被一堆选项吓到全部跳过或选默认即可，不影响安装；第 3 章专门细讲接入
走到一半界面卡住某些机型/终端渲染问题，连按回车或重跑脚本，多数可恢复
6⑥ 模型选错了怎么办：hermes model 随时改
要解决什么

安装向导让你选模型时，选错了、额度用完了、想换一家服务商，怎么办？是重新装一遍吗？

核心思路

不需要重装。执行 hermes model 可以随时重新选择 LLM 服务商和模型（向导提示的原话是"如果选择错了怎么办？执行 hermes model 重新选择"）。

也就是说：模型选择不是"安装时一次性决定"，而是一条独立的管理命令。安装时先随便选一个能用的（或跟着推荐走），后面随时可以换：

hermes model        # 重新选择 LLM 服务商和模型

这背后是 Hermes 的"多模型路由"设计（它的亮点之一就是多模型路由）：同一套 Agent 框架可以对接不同服务商，模型只是"大脑供应商"，可插拔。这也意味着选模型时优先选自己有额度的（如 DeepSeek），别硬选用不起的旗舰模型。

坑在哪
现象原因 / 怎么办
以为选错模型=重装整套一条 hermes model 搞定，重装是浪费生命
选了个没额度的模型导致对话报错换回有额度的；各家模型 API Key 配置按服务商向导填写
以为"全部跟着推荐走"会选到付费最贵的推荐通常是"配置最顺"而非"最贵"；没把握就选自己常用的模型服务商
换模型后以前的功能丢了模型只影响"大脑"，记忆/技能/配置都在文件里，不受换模型影响
7⑦ 接入应用先跳过，后面单独接
要解决什么

安装向导里有一大块"接入应用（微信/QQ/飞书）"，很多人会纠结：现在接还是不接？接的话那一堆授权选项怎么选？

核心思路

官方建议是：接入应用，这里可以先跳过，后续我们单独接入。

理由很实在：安装阶段的重点是先把核心跑起来、把模型配置好；接入平台涉及扫码、配对审批、授权策略一堆选项，混在安装流程里容易手忙脚乱出错。第 3 章会用一整章专门演示 hermes gateway setup 的完整接入流程（QQ 扫码、微信设备配对、飞书接入、DM/群聊策略）。

而且接入是可逆的、可后补的——跳过不影响安装成功，随时想接随时执行 hermes gateway setup。

坑在哪
现象原因 / 怎么办
跳过后找不到"在哪再次接入"随时执行 hermes gateway setup 重新进入接入向导
接入时不小心选了"允许所有直接消息"可在网关配置里改授权策略；推荐 DM 配对审批（第 3 章详述）
以为必须先接平台才能启动 hermes完全可以先本地启动对话，平台接入是"锦上添花"的触达方式
8⑧ 启动成功长什么样
要解决什么

装完了，怎么判断"成功了"？启动命令是什么？成功标志是什么？失败怎么排查？

核心思路

启动命令就是：

hermes

启动成功后你会进入一个交互式对话界面（CLI 对话），可以像聊天一样直接与 Agent 对话。界面上直接标注"到这里就成功了!"——即能进入对话、Agent 能正常回应，就是安装成功的标志。

启动不顺利时的排查顺序（按频率）：

  1. WSL 是否就绪：wsl --list --verbose，VERSION 应为 2；
  2. Git 是否可用：git --version；
  3. pip/npm 镜像是否已还原（第 ④ 点）；
  4. 安装是否真的完整：重新执行一次安装命令，脚本会幂等地补装缺失组件。
坑在哪
现象原因 / 怎么办
输入 hermes 报"command not found"安装未完成或 PATH 未生效：重跑安装脚本；WSL 里新开终端让 PATH 生效
启动后立刻退出/报模型配置错检查模型额度与 Key；执行 hermes model 重新选一个可用的
界面出现乱码/字符错位WSL 终端字体问题，用 Windows Terminal 打开 WSL 再启动
对话没反应看是否在等模型响应（网络/额度）；换 hermes model 里的其他可用模型试试
9⑨ 第一组必须记住的 hermes 命令
要解决什么

安装完面对一个全新 CLI，最需要一份"高频命令速查表"，知道什么时候该敲哪条。

核心思路

完整的常用命令表如下，全部背下来：

命令说明
hermes启动交互式对话
hermes setup运行完整配置向导
hermes model选择 LLM 服务商和模型
hermes tools配置启用的工具集
hermes gateway setup配置消息网关（接入平台）
hermes update更新到最新版本
hermes --version查看当前版本
hermes config show查看当前配置
hermes skills list查看已安装的技能

记忆技巧：把命令按"日常操作（hermes）→ 改配置（setup/model/tools/gateway）→ 看状态（version/config show/skills list）→ 升级（update）"分组记，很快就能形成肌肉记忆。

坑在哪
现象原因 / 怎么办
想查看配置却敲 hermes config会提示缺子命令；完整形式是 hermes config show
升级时犹豫要不要 update定期 hermes update 保持跟进；升级后如遇问题可用旧版本备份回退
技能装了一堆但忘了有哪些随时 hermes skills list；第 7 章会细讲 skills 的浏览/搜索/安装
网关配置和工具配置搞混gateway setup=接平台；tools=开/关能力，两条命令职责完全不同
10⑩ WSL 里的文件怎么和 Windows 互通
要解决什么

装是装在 WSL2（Linux）里的，但日常文件在 Windows 桌面/磁盘上：Agent 写出来的东西我怎么在 Windows 里打开？Windows 的资料怎么喂给 WSL 里的 Agent？需要一条文件互通的通道。

核心思路

WSL2 与 Windows 之间有两条互通的"桥"（有一张图专门讲这个）：

① Windows 里看 WSL 文件：打开任意文件夹（如"此电脑"），在地址栏输入 \\wsl$ 回车，就能看到已安装的 WSL 发行版（如 Ubuntu）；进入发行版找到目标目录（例如 home/你的用户名/），Windows 拖拽/复制粘贴都行。

② WSL 里看 Windows 文件：WSL 里 Windows 磁盘挂在 /mnt/c/、/mnt/d/ 等位置，例如 Windows 桌面在 WSL 里就是 /mnt/c/Users/你的用户名/Desktop/，直接 cp 即可。

如果 Agent 在 WSL 里生成了 ~/ai-agents-showcase/ 下的文件，而你希望它出现在 Windows 桌面，Agent 会自动帮你复制过去（第 4 章案例里有完整演示）。

坑在哪
现象原因 / 怎么办
地址栏输 \\wsl$ 打不开确认 WSL 发行版在运行（先执行 wsl 进一次）；地址栏要输完整 \\wsl$ 而不是 wsl$
在 /mnt/c 里复制大文件很慢WSL2 跨文件系统 IO 有开销，大文件用 Windows 侧操作或搬进 WSL 再处理
找不到 Agent 生成的文件先 ls ~/项目名/ 看 WSL 侧路径，再决定复制到 Windows 哪里；让 Agent 直接复制到桌面最省事（第 4 章）
11⑪ 装完先跑通一个最小验证
要解决什么

"能启动"不等于"配置都对"。装完环境最好先做一次最小验证：确认模型通了、工具能调、记忆目录生成了，再往下走不会越走越乱。

核心思路

建议按"四连查"验证安装完整性：

hermes --version        # ① 版本正常（没有 version 子命令）
hermes model            # ② 模型配置可查看/可修改
hermes config show      # ③ 配置可读
hermes skills list      # ④ 技能目录初始化完成

然后进 hermes 对话，问一个简单问题（如"你好，介绍一下你自己"），确认 Agent 能基于所选模型正常回复——能回复=模型链路通了，安装这一步就算彻底达标。

之后你还能验证记忆初始化：~/.hermes/ 目录下应存在配置与状态文件（SOUL.md、memories/、state.db 等），这些是第 5、8 章的主角。

坑在哪
现象原因 / 怎么办
四连查某一条报错就慌逐条看：version/config 报错=安装不完整；skills list 报错=技能目录未生成，重跑安装脚本即可
简单问题都不回模型额度/网络问题优先；换 hermes model 里另一个服务商再试
以为验证完就万事大吉这只是"安装"达标；平台的接入、个性化、技能、记忆还要逐步配置，别停在最浅层
