# 阶段 9 · 智能运营平台：逐章检查点

> 用法：每章做完对一遍。对不上就回上一节，别往下走。

## 第 1 章 项目全景与技术选型
- **目录里应该有**：还没有代码目录——本章只出蓝图（原文：纯看蓝图的章，不用装环境），该有的是四模块 + 三层架构的一张图
- **跑这条**：原文未给具体命令，本章不写代码，命令从第 3 章才开始出现
- **应该看到**：不看书画出 Vue3 → /api → FastAPI routers → MySQL 8 + Coze 的三层，并说清 `t_sections` 是「方向」、`t_titles` 是「具体一篇」、一条 title 对多条 `t_publish_records`
- **卡点**：跳过第 2 章建表直接写接口 → 没有表只能返回假数据，顺序不能换

## 第 2 章 数据库设计与初始化
- **目录里应该有**：`.env`、`app/config.py`（`quote_plus` + `TORTOISE_ORM`）
- **跑这条**：Navicat 查询窗口粘 `CREATE DATABASE ai_operation DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;`，导入建表脚本后再跑 `SHOW TABLES;`
- **应该看到**：`SHOW TABLES;` 正好 8 行，含 `t_users`、`t_sections`、`t_titles`、`t_title_images`、`t_style`、`t_models`、`t_publish_records`、`t_publish_images`；`t_style` 里有 2~3 条种子、`t_models` 里有 1 个文本模型 + 1 个图像模型
- **卡点**：密码含 `@`、`#` 却没走 `quote_plus` → 报 `Access denied`，可 Navicat 又能连

## 第 3 章 后端工程搭建：uv 与 FastAPI 骨架
- **目录里应该有**：`pyproject.toml`、`uv.lock`、`.python-version`、`.venv`、`config.py`
- **跑这条**：`uv init operation && cd operation && uv venv && uv add fastapi uvicorn "tortoise-orm[asyncmy]" aerich pydantic-settings`
- **应该看到**：`uv run python --version` 输出 `Python 3.12.x`；`pyproject.toml` 里有 `requires-python = ">=3.12"` 和 `tortoise-orm[asyncmy]`，并且生成了 `uv.lock`
- **卡点**：用 `pip install` 装依赖 → `uv run` 里照样 `ModuleNotFoundError`，依赖必须 `uv add` 进 `pyproject.toml`

## 第 4 章 数据模型与 Aerich 迁移
- **目录里应该有**：`app/models/` 包（`__init__.py` 导出全部类，`user.py`/`section.py`/`title.py`/`image.py`/`style.py`/`publish.py` 各管一张表）、`migrations/`
- **跑这条**：`uv run aerich init -t app.config.TORTOISE_ORM && uv run aerich migrate --name change_something && uv run aerich upgrade`
- **应该看到**：`migrations/models/` 出现 `0_20250401120000_init.py` 这类文件 + 同名 `.json` 快照（**没有 `.sql`**）；每个模型的 `Meta.table` 都是 `t_xxx`，不是默认模型名
- **卡点**：库已被建表 SQL 建好还跑 `aerich init-db` → 报「表已存在」；已有库只走 `init → migrate → upgrade`

## 第 5 章 应用启动与测试 API
- **目录里应该有**：`main.py`、`app/database.py`（`RegisterTortoise` 生命周期）、以及 `from app.routers import test` 指向的测试路由文件
- **跑这条**：`uv run uvicorn main:app --host 127.0.0.1 --port 8000 --reload`
- **应该看到**：日志出现 `Uvicorn running on http://127.0.0.1:8000`；`curl http://127.0.0.1:8000/v1/test/styles` 返回 `code`/`message`/`data` 三件套（`code` 为 200，`data` 是风格数组，每项有 `id`/`name`/`fengge`）；`/docs` 里能点到 `GET /v1/test/styles`
- **卡点**：查询漏了 `await` → 拿到的是协程对象，报 `TypeError`；`Style.all()` 必须 await

## 第 6 章 JWT 登录与认证鉴权
- **目录里应该有**：`auth.py`（`/login` + `_make_token` + `get_current_user_id`），`config.py` 里新增 `JWT_SECRET`、`JWT_ALGORITHM`、`JWT_ACCESS_EXPIRE_SECONDS`
- **跑这条**：`curl -X POST http://127.0.0.1:8000/v1/auth/login -H "Content-Type: application/json" -d "{\"username\":\"admin\",\"password\":\"你的密码\"}"`
- **应该看到**：返回 `code`/`message`/`data` 三件套（`message` 为「登录成功」，`data` 里有 `token` 与 `user`）；`token` 是三段用 `.` 分隔的字符串；不带 token 打业务接口是 HTTP 401「未登录」，token 改一个字符是 403「无效令牌」
- **卡点**：给 `/login` 也挂上 `Depends(get_current_user_id)` → 自己都登不进来；白名单接口绝不能挂鉴权

## 第 7 章 前端工程接入与联调
- **目录里应该有**：`operation_ui/`、`vite.config.ts`（`/api` 代理 + rewrite）、`request.js`（`baseURL: '/api'`）
- **跑这条**：`cd operation_ui && yarn install && yarn dev`
- **应该看到**：dev server 起在 `5173`；登录后 cookie 里出现 `accessToken`；`/api/v1/test/styles` 被 rewrite 成 `http://127.0.0.1:8000/v1/test/styles` 并返回 200；未登录直接敲 `/home` 被守卫踢回 `/login`
- **卡点**：`yarn build` 后接口全挂 → Vite proxy 只在 dev 生效，Nginx 的 `proxy_pass http://127.0.0.1:8000/;` 结尾斜杠少一个就全 404

## 第 8 章 Coze 选题智能体打造
- **目录里应该有**：`.env` 里的 `BOT_ID_TOPIC`、`BOT_ID_CONTENT`、`COZE_TOKEN`（`pat_` 开头）、`USER_ID`
- **跑这条**：原文未给具体命令（这是平台操作）：Bot 编辑页 → 发布 → 选「API/应用」→ 复制 Bot ID
- **应该看到**：调试区输出**纯 JSON**，5 个 key 正好是 `每日行业热点`/`热点榜单`/`专业知识榜单`/`人设共鸣`/`灵感广场`，每个数组 10 条 `{"title": "...", "sort_order": 1}`，合计 50 条；发布后拿到的 Bot ID 形如 `76xxxxxxxxxxxx72`
- **卡点**：改完人设只在编辑页「保存」没「发布」→ API 调的还是旧行为，保存 ≠ 发布

## 第 9 章 Coze API 调用与工作流编排
- **目录里应该有**：`app/agent/coze_agent.py`（`_get_coze`、`hot_topic`、`content_creation`）
- **跑这条**：`coze.chat.create_and_poll(bot_id=BOT_ID_TOPIC, user_id=USER_ID, additional_messages=[Message.build_user_question_text("新能源汽车")])`
- **应该看到**：`chat.messages` 里只有 `type == "answer"` 的 `content` 是答案 JSON，其余是 `function_call`/`tool_response` 过程消息；单轮常见 15~60 秒，90 秒是平台上限
- **卡点**：没给 `base_url=COZE_CN_BASE_URL`（`https://api.coze.cn`）→ 默认走海外域名，token 直接 401

## 第 10 章 选题生成 API 与数据落库
- **目录里应该有**：内容生成路由的 `create.py`（`/start`、`/themes`、`/load`），库里 `t_sections`、`t_titles` 开始有数据
- **跑这条**：`curl -X POST http://127.0.0.1:8000/v1/create/start -H "Content-Type: application/json" -H "Authorization: Bearer <token>" -d "{\"theme\":\"新能源汽车\"}"`
- **应该看到**：`t_sections` 多 5 行（`source_name` 就是主题），`t_titles` 多 50 行（`sort_order` 1~10、`status=0`）；`/v1/create` 前缀下的 `/themes` 返回去重后的主题列表；空主题 → 400「主题不能为空」
- **卡点**：直接 `json.loads(text)` 解析 AI 原文 → 混排文本必炸；必须先过 `_extract_json` 三级降级，失败返回 500 让用户重试

## 第 11 章 文案创作与编辑管理
- **目录里应该有**：文案相关的四个路由能对上——`/copy`、`/title/{title_id}`、`/save-copy`、`/styles`（都挂在内容生成路由下，`t_titles` 与 `t_style` 被本章读写）
- **跑这条**：`curl -X POST "http://127.0.0.1:8000/v1/create/copy?title_id=1" -H "Authorization: Bearer <token>"`
- **应该看到**：返回 `code`/`data` 两件套，`data` 里是 `id` 与 `content`；`t_titles.content` 是 220~420 字、`status` 从 0 变 1；对 `status` 为 2 或 3 的标题再调 → 400；`/styles` 返回 `id`/`name`/`fengge`
- **卡点**：`t_titles` 没有 `user_id` 列，只按 `title_id` 取 → 越权改到别人的稿；必须顺 `section_id` 再查 `Section.get_or_none(id=title.section_id, user_id=user_id)`，否则 404

## 第 12 章 AI 配图与 OSS 上传发布
- **目录里应该有**：`upload.py`、`qwen_agent`（拼提示词）、`scripts/publish-xiaohongshu.mjs`（puppeteer 发布脚本）
- **跑这条**：原文未给具体命令；验证路径是 `ImageSynthesis.call` 拿到图 → 转存 OSS → 看 `t_title_images` 是否多一行
- **应该看到**：`dashscope.ImageSynthesis.call` 用 `model="qwen-image-2.0-pro"` 与 `size="960*1696"`，结果在 `resp.output.results[0].url`；入库的 `image_url` 是 `https://{OSS_BUCKET}.{OSS_ENDPOINT}/{oss_key}` 形式的 OSS 链接（不是百炼临时 URL），`image_type` 按 0/1/2 写对
- **卡点**：照老教程用 `oss2` → 报 `AttributeError: module 'oss2' has no attribute ...`；本项目用的是 `alibabacloud_oss_v2`
