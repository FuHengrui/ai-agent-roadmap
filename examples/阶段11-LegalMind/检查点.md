## 第 1 章 LegalMind 项目全景与技术选型

- **应该看到**：`postgres`、`redis` 两个服务都是 `healthy`（镜像分别是 postgres:16-alpine、redis:7-alpine，端口 5432 / 6379）
- **表清单**：`users`、`cases`、`chat_sessions`、`chat_messages`、`generated_documents` 五张，主键用 UUID 字符串

## 第 5 章 用户认证系统
- **目录里应该有**：`app/api/auth.py`、`app/utils/security.py`、`app/dependencies.py`
- **跑这条**：`curl -X POST http://localhost:8000/api/auth/register -H 'Content-Type: application/json' -d '{"username":"demo","email":"demo@test.com","password":"<demo_password>"}'`
- **应该看到**：注册和登录都返回 `access_token`、`"token_type": "bearer"`、`username`、`nickname`；`curl http://localhost:8000/api/chat/sessions` 不带 token → 401 `{"detail":"无效的认证凭证"}`，带 `Authorization: Bearer <token>` → `{"sessions":[]}`
- **卡点**：`get_current_user` 返回的是 `User` 对象（不是 dict），照另一套契约写 `user_info["user_id"]` 会 KeyError/AttributeError——本章起统一用 `user.id`

## 第 7 章 文本向量化与向量库

- **跑这条**：`python scripts/seed_cases.py`，再 `python scripts/build_index.py`
- **应该看到**：先打印一行以 `待索引 ` 开头的统计（`print(f"待索引 {len(new_cases)} 条（跳过 {len(cases) - len(new_cases)} 条已索引）")`），最后一行以 `✅ 索引完成` 开头、后接向量库总条数（`print(f"✅ 索引完成，向量库共 {store.count()} 条")`）；Chroma 集合名 `legal_cases`，`hnsw:space` 是 `cosine`，向量 512 维
- **卡点**：两个脚本顺序反了（先 `build_index` 再 `seed_cases`）→ 会得到"有数据但库里空"的假象；重复跑还会报 collection already exists

## 第 10 章 聊天与文书生成 API

- **接口应该有**：`/api/chat/send`（POST）、`/api/chat/stream`（POST）、`/api/chat/sessions`（GET）、`/api/chat/sessions/{id}/messages`（GET）、`/api/chat/sessions/{id}`（DELETE）；文书在 `/api/documents` 前缀下，有 `/templates` 与 `/generate/stream`
- **跑这条**：原文未给具体命令（本章只给了接口表和路由函数，没有 curl 示例）
