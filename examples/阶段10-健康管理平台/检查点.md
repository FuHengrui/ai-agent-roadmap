# 阶段 10 · 健康管理平台：逐章检查点

> 用法：每章做完对一遍。对不上就回上一节，别往下走。

## 第 1 章 项目全景与技术选型
- **目录里应该有**：还不用建目录（本章只出蓝图）；但在蓝图上要能指到 `app/core/`、根目录 `.env`、`config.py`，以及 `patient` / `blood_sugar` / `diet` / `medication` / `exercise` / `health_report` / `chat` 七组路由
- **跑这条**：原文未给具体命令（本章只出蓝图；验收标准里的 `uvicorn main:app --reload` 要等第五章搭完才跑得起来）
- **应该看到**：五个节点的顺序是 `classify` → `load_context` → `retrieve` → `generate` → `assess_risk`；增量技术只列 LangChain、ChromaDB、LangGraph 三件；`diabetes` 库 7 张表、医学知识 20 条
- **卡点**：库名写成 `diabets`（本章 trap 原话就是 `diabets`/`diabetes`）→ 建库、`.env`、`config.py` 三处不一致，后面所有连接都连不上

## 第 2 章 数据库设计与初始化
- **目录里应该有**：MySQL 里的 `diabetes` 库（utf8mb4）和 7 张表：`patients`、`blood_sugar`、`diet_records`、`medications`、`exercise_records`、`health_reports`、`chat_history`——表名全是复数，写成单数就错
- **跑这条**：在 Navicat 查询窗口把本章 7 段 `CREATE TABLE IF NOT EXISTS` 按 patients 打头的顺序跑完
- **应该看到**：`blood_sugar` 有 `value` FLOAT、`measure_type` VARCHAR(20)、`measured_at` DATETIME，外键是 `ON DELETE RESTRICT`；`diet_records` 有 `portion` FLOAT DEFAULT 1.0；`medications` 的 `is_active` 默认 1
- **卡点**：建外键报 errno 150——先建了子表、`patient_id` 不是 INT、或引擎/字符集不是 InnoDB + utf8mb4，三者查一遍

## 第 3 章 后端工程搭建与核心配置
- **目录里应该有**：`diabetes_assistant/` 下 `main.py`、`.env`、`pyproject.toml`、`uv.lock`；`app/` 下 `config.py`、`database.py`、`models/`（7 个模型文件 + `__init__.py`）、`schemas/`、`routers/`、`core/` 七个引擎文件
- **跑这条**：`uv --version; python --version; netstat -ano | findstr :3306`
- **应该看到**：uv 版本号、Python 版本是 3.12、3306 那一行带 PID 和 `LISTENING`；Navicat 能连上 `diabetes` 并看到 7 张表
- **卡点**：`uv add` 那一长串里把 `tortoise-orm[asyncmy]` 写成 `tortoise-orm` → 启动连 MySQL 报"找不到数据库驱动"

## 第 4 章 数据模型层与计算属性
- **目录里应该有**：`app/models/__init__.py` 里从 `from app.models.patient import Patient` 一路导到 `from app.models.chat_history import ChatHistory`，`__all__` 列出七个类
- **跑这条**：原文未给具体命令；把本章那句 `from app.models import BloodSugar` 粘进项目里的 Python 执行，不报 ImportError 即通过
- **应该看到**：`BloodSugar` 的 `Meta` 里 `table = "blood_sugar"`；`status` 上限按 `fasting` 6.1 / `postprandial` 7.8 / `random` 11.1 分档，`gi_level` 以 55 和 70 分档，`bmi_category` 是偏瘦/正常/超重/肥胖四档
- **卡点**：新模型写了却忘了在 `app/models/__init__.py` 导出 → 启动不报错，查询才报"模型不存在"（实测提示 `Module "app.models" has no models`）

## 第 5 章 应用启动与患者管理 API
- **目录里应该有**：`main.py` 里 `add_middleware` → `include_router(main_router)` → `register_db(app)` 三步齐；`database.py` 里自己写的 `register_db`；`app/routers/__init__.py` 的 `APIRouter(prefix="/api", tags=["main"])`；`patient` 路由的 `APIRouter(prefix="/patients", tags=["patients"])`；Schema 四件套 `PatientBase` / `PatientCreate` / `PatientUpdate` / `PatientResponse`
- **跑这条**：`python main.py`（等价于 `uvicorn main:app --host 0.0.0.0 --port 8000 --reload`）
- **应该看到**：`http://localhost:8000/docs` 能打开；`http://localhost:8000/api/patients/` 返回空列表 `[]`；POST 建一个患者后响应里有 `id`、`bmi`、`bmi_category`
- **卡点**：用 `Patient.get()` 查不存在的 id → 抛 `DoesNotExist`、接口 500 而不是 404；必须 `get_or_none()` 再判空抛 404

## 第 6 章 血糖管理模块与统计分析
- **目录里应该有**：`app/core/health_analyzer.py`（`class HealthAnalyzer` + 底部 `health_analyzer = HealthAnalyzer()` 单例）、血糖模块的四个路由——创建、按患者查 `/patient/{patient_id}`、统计 `/patient/{patient_id}/stats`、更新 `/{record_id}`——以及 `BloodSugarBase` / `BloodSugarCreate` / `BloodSugarUpdate` / `BloodSugarResponse` / `BloodSugarStatsResponse`
- **跑这条**：`curl "http://localhost:8000/api/blood-sugar/patient/1/stats?days=7"`
- **应该看到**：JSON 里有 `period_days`、`record_count`、`avg`、`min`、`max`、`std`、`high_count`、`low_count`、`normal_count`、`time_in_range`、`trend`、`risk_level`；没有记录时是 200 加 `error` 字段，值是 `暂无血糖数据`，不是 500
- **卡点**：阈值只写一套 3.9/10.0、不按 `measure_type` 分档 → 空腹 8.5 判成"正常"、达标率虚高，还会出现"达标率 100%、风险却是中风险"

## 第 7 章 饮食、用药、运动三大记录模块
- **目录里应该有**：`DietRecord`、`Medication`、`Exercise` 三个模型各配一套 CRUD，三个路由前缀分别是 `/diet`、`/medication`、`/exercise`，另有每日营养的 `/patient/{patient_id}/daily`
- **跑这条**：`curl "http://localhost:8000/api/medication/patient/1?active_only=false"`
- **应该看到**：默认只返回"正在吃"的药（`is_active` 为真且 `end_date` 为空或 ≥ 今天），传 `false` 后停药记录也回来；运动记录的 `bs_change` 是 `round(self.blood_sugar_after - self.blood_sugar_before, 1)`
- **卡点**：只按 `is_active` 过滤、不看 `end_date` → 停药时只填了 `end_date` 的药一直被当成"正在吃"；要加 `Q(end_date__isnull=True) | Q(end_date__gte=date.today())`

## 第 8 章 智能饮食引擎：DietAdvisor 剖析
- **目录里应该有**：核心引擎 `diet_advisor`（路由里 `from app.core.diet_advisor import diet_advisor`），内含 `RECOMMENDED_FOODS`（10 条）、`_calorie_status`、`_carb_status`、`recommend_meal`，文件底部 `diet_advisor = DietAdvisor()`
- **跑这条**：`curl "http://localhost:8000/api/diet/patient/1/daily?date=2026-11-01"`
- **应该看到**：`avg_gi` 是过滤掉 None 后的均值（当天没有 GI 数据时是 0.0）；`calorie_status` 出三档文案（<1200 偏低 / ≤1800 适中 / >1800 偏高）；`total_calories` 已经乘过 `portion`
- **卡点**：`recommend_meal` 把 GI 排序写成降序 → 血糖 >8.0 时推的反而是 GI 最高的；必须 `sorted(suitable, key=lambda x: x["gi"])` 升序取前 4

## 第 9 章 健康报告与 LLM 客户端
- **目录里应该有**：`LLMClient` 类及其 `chat` 方法（参数 `system_prompt`、`user_message`、`chat_history`）、报告路由的 `@router.post("/generate/{patient_id}", response_model=HealthReportResponse)`、`HealthReport` 模型，以及响应 Schema 里 `patient` 字段放的是 ID 不是外键对象
- **跑这条**：`curl -X POST "http://localhost:8000/api/reports/generate/1?report_type=周报"`
- **应该看到**：响应带 `report_type`、`period_start`/`period_end`、`avg_blood_sugar`、`blood_sugar_std`、`time_in_range`、`summary`、`recommendations`、`risk_level`、`generated_at`；`summary` 形如"近7天血糖概况：共记录N次，平均值…"，库里由 `HealthReport.create` 多落一行
- **卡点**：没有血糖数据还硬调 LLM → 空转甚至编数字；`analysis.get('error')` 为真时必须短路，直接写"血糖数据不足，无法生成报告。"

## 第 10 章 血糖统计与健康仪表盘
- **目录里应该有**：`src/api/index.ts`（`baseURL: '/api'`、`timeout: 60000`）、`stores/bloodSugar.ts`、`utils/charts.ts`、`Dashboard.vue`、`vite.config.ts`（代理 `/api` → `http://localhost:8000`）
- **跑这条**：`npm run dev`
- **应该看到**：起在 5173；折线图三条辅助线是 3.9"低血糖 3.9"、7.0"目标上限 7.0"、10.0"高血糖 10.0"，y 轴单位 `mmol/L`、写死 min/max（本项目 2–16，超过 16.7 的高危点会被裁掉，本章提示可放宽到 20+）；达标率 ≥90% 时仪表盘 90 分、绿色（≥80 绿 / ≥60 橙 / <60 红）
- **卡点**：切换患者后仪表盘不刷新——少了 `watch(() => patientStore.currentPatient?.id, loadAll)`，看到的一直是上一个患者的数据

## 第 12 章 LangGraph 工作流与 AI 对话
- **目录里应该有**：`AgentState`（`TypedDict`，带 `total=False`）、五个节点函数、`create_agent_workflow()`、`agent_app`、`run_agent`，以及 chat 路由的 `@router.post("/message", response_model=ChatResponse)`
- **跑这条**：`python main.py`（第五章的启动命令），在 `/docs` 里调 chat 路由的 `/message` 接口，请求体 `{"patient_id": 1, "message": "最近血糖高了怎么办"}`
- **应该看到**：`input_type` 是 `blood_sugar`（消息含"血糖"，关键词命中即短路）；`chat_history` 先落 `role="user"` 再落 `role="assistant"` 两行；`response` 末尾按等级追加警告（高风险建议就医、中风险提醒、低风险不加）
- **卡点**：`risk_level` 拿不到时用 `or` 兜成"安全"/低风险 → 没有血糖数据的患者被当成没事，高风险患者收不到就医提示；数据不足不等于低风险
