# examples/：三个项目的逐章检查点

这里**没有**完整项目代码——只放「走到哪、对不对」的自检清单。

## 为什么不是代码包

| | 完整代码包 | 检查点（本目录） |
|---|---|---|
| 体积 | 几千行、几十个文件 | 每个项目约 80 行 Markdown |
| 维护 | 依赖一升级就跑不起来，得持续改 | 只是路径和命令，几乎不会过期 |
| 对读者的作用 | 「看别人的代码」 | 「确认自己没走丢」 |
| 与书的关系 | 书里 15%~25% 的代码 + 一个外部包 | 书里每一章都对应 4 行检查点 |

书里三个项目阶段（9 / 10 / 11）的代码是**关键代码节选**：阶段 9 约 400 行、阶段 10 约 730 行、阶段 11 约 800 行，而真实全栈项目通常 3000 行以上。所以**照着抄不会自动得到完整项目**，得按章拼。

阶段 11 另有 29 处「以下省略 N 行」，那几处需要按上下文自己补。

## 怎么用

1. 打开对应项目的 `检查点.md`
2. 每做完一章，对一遍那 4 行：
   - **目录里应该有**：文件在不在
   - **跑这条**：命令能不能跑
   - **应该看到**：输出特征对不对（状态码、表名、字段名、页面元素）
   - **卡点**：这一章最容易错的地方
3. 对不上就回上一节，别继续往下走——这三个项目是**层层依赖**的，跳一步后面全是坑

## 三个项目

| 目录 | 项目 | 章数 | 技术栈 |
|---|---|---|---|
| `阶段09-智能运营平台/` | 选题 + 文案生成平台 | 12 | FastAPI + Tortoise + MySQL 8 + Vue3 + Coze |
| `阶段10-健康管理平台/` | 血糖/饮食/用药管理 | 12 | FastAPI + Tortoise + MySQL 8 + LangGraph + RAG |
| `阶段11-LegalMind/` | 法律咨询系统 | 12 | FastAPI + Tortoise + Postgres + Chroma + Vue3 + Docker |

## 说明

- 检查点里的路径、命令、接口，**都取自对应章节原文**；原文没给具体命令的章，会明写「原文未给具体命令」而不是编一个。
- 如果你发现检查点和正文对不上，以正文为准，并告诉我们（开 issue 即可）。
