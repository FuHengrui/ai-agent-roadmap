@@h1 第三章　神经网络剪枝基础
@@sub 阶段 23 · 模型压缩与高性能推理优化　|　剪枝入门　|　难度 ★★☆

@@why 这一章在解决什么问题
大模型的参数里真正"干活"的只是一部分，很多权重/神经元贡献极小。**神经网络剪枝（Pruning）** 就是把这些不重要的结构删掉：删完连接、神经元甚至整个通道，模型仍然能保持原有精度，而体积与计算量实打实下降。本章解决三个入门问题：**剪枝是什么、为什么有效、和非结构化/结构化两种粒度的选择**。

@@map 上一章→本章→下一章
上一章总览了压缩全景图（剪枝/量化/蒸馏/紧凑网络）与框架生态。**本章进入第一座大山：剪枝——先讲概念、收益与两种粒度**。下一章讨论剪枝的时机（什么时候剪最合适）与流程；再下一章讲剪枝的工程细节（掩码、稀疏度、非结构化实战）。

@@point ① 剪枝的定义：删掉不重要的参数
@@need 要解决什么
剪枝到底"剪"的是什么？把模型哪里切掉？

@@idea 核心思路
**模型剪枝（Pruning）**：把网络中对最终输出贡献很小的参数移除，得到更紧凑的模型。

"移除"分两个层面：
- **权重层面**：把某些权重直接置 0（等于切断了这条连接）。
- **结构层面**：把一整个神经元/通道/卷积核删掉（结构与体积真正变小）。

直觉类比：修剪树木——剪掉无用的枝叶，主干依然茂盛，但树木变得清爽。剪枝剪掉的是**冗余**，保留的是**核心表达**。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为剪枝是"砍层数" | 剪枝通常是删参数/神经元/通道，不一定删整个网络层 |
| 把置0与真删除混为一谈 | 置0（掩码）只省计算不一定省存储；删通道/神经元才真正缩小结构 |

@@point ② 剪枝为什么有效：冗余的存在
@@need 要解决什么
剪掉参数为什么往往不掉精度？模型里哪来的冗余？

@@idea 核心思路
深度神经网络存在**大量冗余参数**，成因有三：

1. **过拟合驱动**：为了在训练集上达到极好效果，模型被加到很大，很多参数只是"记住"而非"理解"。
2. **表达能力溢出**：大模型的容量往往超过任务所需，多出来的容量就是可压缩空间。
3. **参数分布不均**：大量参数的绝对值很小，对输出的加权贡献微乎其微。

因此"参数≈知识"是错觉：**知识存在关键模式里，冗余存在于细微之处**。剪掉低贡献参数，模型依然保留了全部关键模式。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为参数越少必然精度下降 | 只要冗余剪得准，精度可保持不变甚至更好（顺带正则化作用） |
| 认为所有模型都冗余 | 紧凑网络（已设计好）冗余少，剪枝空间小，压缩方法要按模型选 |

@@point ③ 剪枝的三个直接好处
@@need 要解决什么
投入剪枝工程，能得到哪些具体回报？

@@idea 核心思路
剪枝的收益可以拆成三份：

1. **减少模型体积**：配合稀疏存储，只有非0参数与索引被保存，文件大幅变小。
2. **降低推理计算量**：被置0的连接在计算时可以跳过（配合稀疏算子），FLOPS 下降。
3. **降低内存消耗**：权重与中间结果占用更少显存，模型更容易部署到低配硬件。

三个好处对应上一章的"压缩率/理论加速比"两把尺子：剪枝让分子变小、分母不变，两个指标同时受益（实际上是非0部分变小）。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 只看到"体积变小" | 剪枝的完整收益=体积+计算量+内存，评估要三个维度一起看 |
| 忽略配合要求 | 收益需要稀疏格式与稀疏算子的配合，纯密集推理提速有限 |

@@point ④ 剪枝与 Dropout 的区别
@@need 要解决什么
剪枝把参数置0，Dropout 训练时也随机置0，两者是一回事吗？

@@idea 核心思路
完全是两码事：

| 维度 | 剪枝 | Dropout |
|---|---|---|
| 目的 | 压缩模型（部署期） | 正则化，防过拟合（训练期） |
| 动作对象 | 永久删除低贡献参数 | 训练中随机临时丢弃神经元 |
| 对结构影响 | 模型结构永久变小 | 推理时全量恢复，结构不变 |
| 判断依据 | 基于重要性分数 | 随机（按概率） |

一句话：**Dropout 是训练时的"训练技巧"，剪枝是部署前的"模型雕琢"**。二者可以共存：训练时用 Dropout 防过拟合，训练完剪枝瘦身。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 用 Dropout 替代剪枝 | Dropout 不改变模型体积，无法达到压缩目的 |
| 剪枝后保留 Dropout 层 | 推理时 Dropout 是透明的，但剪枝目的与 Dropout 目的混淆会误判效果 |

@@point ⑤ 两种剪枝粒度：非结构化 vs 结构化
@@need 要解决什么
剪枝按"剪多细"分几种？各自优劣如何？

@@idea 核心思路
剪枝分两个粒度：

- **非结构化剪枝（Unstructured）**：逐连接剪（weight pruning），任意权重可被置 0。压缩比高、灵活，但矩阵变得不规则稀疏，**需要专门稀疏算子/硬件**才有实际加速。
- **结构化剪枝（Structured）**：按神经元/通道/卷积核整块剪（如 channel pruning）。结构规整，**对现有框架硬件友好、直接加速**，但压缩比通常低于非结构化。

表格对比：

| 维度 | 非结构化 | 结构化 |
|---|---|---|
| 粒度 | 单一连接 | 神经元/通道/核 |
| 压缩比 | 高 | 中 |
| 加速落地 | 需稀疏算子 | 通用算子即可 |
| 实现难度 | 较简单 | 需要结构设计 |

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 只看压缩比选型 | 非结构化压缩比高但无稀疏硬件时跑不快，落地要权衡"纸上数字"与"实测速度" |
| 以为结构化剪枝无损 | 剪整块结构对精度的冲击通常更大，需要细化评估与微调补偿 |

@@point ⑥ 非结构化剪枝的实现要点
@@need 要解决什么
真正做非结构化剪枝，关键动作是什么？

@@idea 核心思路
非结构化剪枝的经典实现（以权重剪枝为例）：

```
1. 训练一个够用的基准模型
2. 计算每个权重的重要性（常用|权重|绝对值）
3. 设定稀疏度目标（如剪掉80%的权重）
4. 生成掩码：重要权重标1，不重要的标0
5. 置0并保存：权重×掩码，配合稀疏存储
6. 可选：微调（fine-tune）恢复精度
```

核心洞察：**重要性≈权重的绝对幅值**。幅值大的权重对输出影响大，优先保留；幅值小的删掉损失小。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 剪完不做微调就上线 | 剪枝会造成精度损失，通常需要微调补偿，尤其是高稀疏度时 |
| 用训练后参数直接评估重要性 | 正确做法是按训练收敛后的权重算重要性，不是中途快照 |
| 忽略 masking 是"暂时置0" | 微调时掩码要锁定（Masked 训练），否则被剪权重可能在梯度回传后复活 |

@@point ⑦ 结构化剪枝的实现思路
@@need 要解决什么
结构化剪枝具体怎么做？怎么判断一个神经元该不该留？

@@idea 核心思路
结构化剪枝的通用流程：

```
1. 对每个神经元/通道计算重要性分数
2. 按分数排序，删除分数低于阈值/排名靠后的
3. 输出新网络结构（通道数减少）
4. 用原模型权重初始化：保留结构微调训练
5. 得到更小的模型，可直接部署
```

**重要性的衡量**有多种方案：
- 神经元权重向量的 **L1/L2 范数**（幅值总和）——简单常用；
- 激活后对损失的**贡献**；
- 训练 BN 层的缩放因子 γ（见后文"BN 缩放因子"专题）。

结构化剪枝的价值：**剪完的结构是规整矩阵，任何深度学习框架都能直接享受加速**，无需专用稀疏硬件。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 拿通道分数直接删掉不管关联 | 删除一个通道意味着下游所有相关计算都要调整，要用框架支持或重训练 |
| 只看范数不看层内分布 | 不同层的权重幅值尺度不同，最好按层/按通道相对比较 |

@@point ⑧ 本章小结：剪枝是什么、为什么、怎么分
@@need 要解决什么
学完本章，剪枝的核心认知框架是什么？

@@idea 核心思路
本章建立剪枝的"是什么-为什么-怎么分"三层认知：

```
是什么：删掉低贡献参数，得到更小更快的模型
为什么：深度网络存在大量冗余参数
收益：体积↓ 计算量↓ 内存↓（配合稀疏存储/算子）
与Dropout区别：剪枝=部署期永久瘦身；Dropout=训练期正则技巧
两种粒度：非结构化（灵活高压缩/需稀疏硬件） vs 结构化（规整友好/直接加速）
```

后续章节将在两个粒度上继续深挖：时机与流程、掩码与稀疏度、神经元剪枝、BN 缩放因子等。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 学完概念不看实践环节 | 剪枝的坑藏在时机、掩码锁定、微调补偿这些工程细节里，光懂概念不够 |
| 忘记与量化/蒸馏衔接 | 剪枝常与量化搭配（详见量化章节的"协同优化"），压缩体系需要组合拳 |

@@summary
这一章建立了剪枝的基础认知：

| 要点 | 内容 |
|---|---|
| 剪枝定义 | 移除对输出贡献很小的参数/结构 |
| 有效性来源 | 神经网络存在大量冗余参数 |
| 三大收益 | 体积小、计算量低、内存占用少 |
| 与Dropout区别 | 压缩 vs 正则；部署期 vs 训练期 |
| 非结构化 | 逐连接剪，压缩比高，需稀疏算子/硬件 |
| 结构化 | 剪神经元/通道，规整友好，直接加速 |

一句话记住本章：**剪枝就是"删掉不重要的参数"——因为深度网络冗余多，剪掉低贡献参数能让体积、计算量、内存三降而精度基本不掉；按粒度分非结构化（逐连接剪、压缩比高但要稀疏硬件）与结构化（整块剪神经元/通道、对现有框架友好可直接加速）两种路线，是后续所有剪枝技术的地基。**
