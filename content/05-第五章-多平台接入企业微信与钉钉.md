@@h1 第五章　多平台接入：企业微信与钉钉
@@sub 阶段 14 · 小龙虾 OpenClaw 实战　|　平台实操　|　难度 ★★★

@@why 这一章在解决什么问题
**为什么 AI 聊个天，要先接企业微信和钉钉？** 前几章你完成了部署、配好了 AGENTS/SOUL/USER——OpenClaw 已经"认识你"了，但它目前只会在命令行里对话：你得打开终端、敲命令，它才理你。这不算助理，算工具。真正的助理应该待在消息列表里，随叫随到：你在聊天框里发一句话，它就帮你把事情办了。

**"接入 IM"到底接的是什么？** OpenClaw 把每一个聊天平台称为一个 **channel（通道）**。接进企业微信或钉钉之后，你在聊天框里 @ 机器人发消息，这条消息就进入 OpenClaw，由它调用模型思考、执行工具，再把回复原路发回聊天框。这就是**消息驱动的交互**——聊天即操作，命令即对话，用户不再需要任何终端操作。

本章把两条平台链路完整走通：企业微信（管理后台建机器人 → 拿到 Bot ID/Secret → 写进 openclaw.json）和钉钉（开发者平台建应用 → 添加机器人能力 → 发布上线 → 拿 Client ID/Client Secret → 配 channel）。学完你获得的不只是两个平台，而是一套**可复制的方法论**：下一章接飞书、QQ、小红书，流程完全一样。

@@prep 开始之前
要有企业微信管理员账号和钉钉开发者账号，各自建机器人拿凭证；部署好的 OpenClaw 得在线。

@@goal 学到这儿就够了
能在企微后台建 API 模式机器人、在钉钉建应用并发布，把两套凭证填进 channel 后能收到消息，这章就算过了。

@@note info 学习提示
本章全是平台后台操作，没有复杂代码（全文代码不到 20 行）。建议用**边看边点**的方式学：开一个浏览器跟着步骤走，卡在哪一步就回看哪一步。注意，凡是出现 ID/Secret 的地方，这里都只给占位符，真实值由你自己从平台复制——截图里的值一律是打码的。

**上一章**（阶段 14 · 配置 AGENTS / SOUL / USER）：你给 OpenClaw 配好了"人格"——AGENTS 定行为规范、SOUL 定性格、USER 定你是谁，AI 开始"认识你"
**本章** ← 你在这里：把 AI 接进真实 IM——企业微信与钉钉，让"聊天即操作"落地（channel 概念 + 双平台实操）
**下一章**：接入飞书 / QQ / 小红书——同一套"建机器人 → 拿凭证 → 配 channel"的流程再复制三遍

**阶段终点**：完成部署 + 配置 + 五平台接入，一套 OpenClaw 在所有主流 IM 里随叫随到

@@point ① 为什么先接 IM：消息驱动交互，channel 是 OpenClaw 的"入口"
@@need 要解决什么
OpenClaw 已经能跑了，但只能在命令行里对话，这不算"可用"。你需要的明明是一个真实的交互入口——打开手机上的聊天软件就能指挥 AI。接入哪个平台、为什么是 IM，先把这个问题想清楚再动手。

@@idea 核心思路
OpenClaw 把每个消息渠道称为 **channel（通道）**：企业微信、钉钉、飞书、QQ、小红书各有各的 channel。接入的本质就是三步：**在平台后台建一个机器人 → 拿到凭证 → 在 OpenClaw 里配置对应 channel**。

选 IM 作为第一入口有三个理由：

| 理由 | 说明 |
|---|---|
| 零门槛 | 用户不用装客户端、不用懂命令行，聊天软件人人会用 |
| 消息驱动 | 用户发一条，机器人回一条，天然一问一答，和 AI 对话形式完全吻合 |
| 平台即后台 | 企业微信、钉钉本身就是办公场景的"主界面"，AI 直接出现在工作流里 |

记住这个心智模型：**模型是大脑，channel 是嘴巴**。上一章（阶段 14 第四章 配置文件三件套）配的是"大脑"，本章开始配"嘴巴"。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为接入 IM 要先写一堆服务端代码 | 接入不是编程，是"平台后台点按钮 + 填凭证 + 改配置"，约 90% 的操作在网页后台完成 |
| 五六个平台一次性全接 | 一次只接一个：先接企业微信或钉钉把全链路验证通，再复制流程接其余平台。同时接多个，出问题都不知道卡在哪个环节 |

@@point ② 企微前置准备：管理员权限与创建/注册企业
@@need 要解决什么
接入企业微信机器人的第一步不在电脑上，而在企业微信官网——但机器人创建只对管理员开放。如果你没有企业、也没有管理员权限，第一步就会被卡住。

@@idea 核心思路
前往**企业微信官网**，使用**有企业管理员权限的账号**登录。如果你还没有企业：参考官网的"创建&注册企业"流程，先创建一个新企业（个人也能注册企业，注册即是企业创建者，天然拥有管理员权限），再进入管理后台。

| 检查项 | 说明 |
|---|---|
| 账号权限 | 必须是管理员，普通成员看不到"安全与管理"等后台菜单 |
| 企业状态 | 至少拥有一个企业（新建即可），机器人挂在某个企业名下 |
| 登录入口 | 用企业微信官网的管理后台登录，不是手机客户端 |

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 用普通成员账号登录，找不到管理后台菜单 | 权限不足。机器人相关操作对管理员开放；换管理员账号登录，或找管理员给你开通权限 |
| 以为企业微信必须有公司主体才能注册 | 个人也可以创建/注册企业，按官网引导走一遍即可拿到一个属于自己的企业和管理员身份 |
| 手机 App 里翻不到"智能机器人" | 机器人创建在**官网管理后台**，不是在手机端 App 里操作 |

@@point ③ 企微后台创建智能机器人：安全与管理 > 管理工具
@@need 要解决什么
进入管理后台后，左侧导航菜单有一大堆，"智能机器人"藏得比较深。找错入口会让你在原地打转——它不是"自建应用"，不在应用管理里。

@@idea 核心思路
在企业管理后台的左侧导航中，依次找到并进入：

1. **安全与管理**
2. **管理工具**
3. 选择 **智能机器人**
4. 在页面内点击 **创建机器人**

路径很短，但层级是固定的：安全与管理 → 管理工具 → 智能机器人 → 创建机器人。按这个路径点，一次到位。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 在"应用管理 / 自建应用"里找机器人，找不到 | 企业微信智能机器人归属在 安全与管理 > 管理工具 下，是管理类工具，不是业务应用，别按应用管理的思路找 |
| 点了"创建机器人"没有弹窗 | 浏览器弹窗被拦截（尤其 Chrome/Edge）；允许企业微信官网弹窗后刷新页面重试 |

@@point ④ 手动创建 + API 模式创建：两条必经步骤
@@need 要解决什么
创建机器人的弹窗里有一堆入口：模板创建、可视化创建……选错一个，做出来的机器人没有 API 接口，OpenClaw 根本调不动。这个坑必须在第一步就避开。

@@idea 核心思路
创建弹窗里分两步走：

1. 在弹出的弹窗中点击 **手动创建** 按钮
2. **滑到页面最底端**，点击 **API 模式创建** 按钮

关键认知：**API 模式 = 给 OpenClaw 用的机器人**。OpenClaw 是程序，不是图形化工具，它只能通过 API 与机器人通信。模板/可视化创建出来的机器人没有 API 凭证，无法接入。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 弹窗里找不到"API 模式创建" | 该按钮在页面**最底端**，先向下滚动到底再找，很多人在第一屏就放弃了 |
| 用了模板/图形化创建，后面接 OpenClaw 接不上 | 模板机器人没有 API 接口和凭证；重新回到创建流程，改走 手动创建 → API 模式创建 |
| 以为"手动创建"就是写代码 | "手动创建"只是不套模板，全程仍是填表单，不用写任何代码 |

@@point ⑤ 长连接方式接入（推荐）：URL 回调是什么
@@need 要解决什么
API 模式创建时，页面让你选接入方式、还要填一个 URL。这个 URL 到底是什么？"长连接"又是什么？填错或理解错，机器人建好了也收不到消息。

@@idea 核心思路
明确一点：企微接收消息有**两种互斥方式**——**长连接**（推荐，不用公网地址、不用回调 URL）和 **URL 回调**（必须有公网可达地址）。走长连接就选前者，别填回调 URL：

| 参数 | 含义 |
|---|---|
| URL | 回调消息的地址，即企微把收到的用户消息转发到哪个地址。**需要看 OpenClaw 的接口说明**，不能随便填个网址 |

理解"长连接 vs 轮询"：如果机器人客户端每隔几秒主动问服务器"有新消息吗"，这叫**轮询**——浪费资源、有延迟、高峰期容易被打爆；**长连接**是消息一出现服务器就主动推给客户端，实时、省资源。这也是推荐长连接方式的原因，OpenClaw 会与企微保持长连接，消息秒级送达。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 不知道 URL 填什么，随便填了个官网地址 | URL 是回调消息地址，必须填 OpenClaw 提供的对外接口；先查 OpenClaw 接口文档，别猜 |
| 觉得"长连接"和"使用 URL 回调"可以一起用 | 它们是**二选一**：长连接由 OpenClaw 主动连企微网关，URL 回调则由企微反向调你的公网地址。选长连接就不需要公网 IP，也不用填回调 URL |
| 回调 URL 有反斜杠/端口，复制时漏字符 | URL 要**整段复制**进表单，手打最容易漏；之后在应用管理页签还能核对（见第 ⑦ 点） |

@@point ⑥ 获取并保管 Bot ID 与 Secret
@@need 要解决什么
机器人创建完成后，页面给出 Bot ID 和 Secret——这是 OpenClaw 连接企微机器人的"身份证 + 钥匙"。但这两个字符串是敏感信息，一旦泄露，机器人就归别人管了。怎么获取、怎么保管，值得专门说。

@@idea 核心思路
流程上：获取到 **Bot ID** 和 **Secret** 后，点击保存，就算创建完成。

保管上，把两个值当作密码对待：

1. 立即复制到一个**密码管理器**（或本地记事本），并标注"企微机器人凭证"
2. 后面写进 openclaw.json 时用真实值，但**任何对外展示的文档、截图、代码示例一律用占位符**
3. Secret 泄露 = 别人能用你的机器人身份收发消息，可撤销或轮换凭证是最后的补救手段

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 把 Secret 明文写进文档并提交到公开仓库 | 凭证外泄是最常见的事故；真实值只放本机配置文件，示例一律写 <你的BotId> / <你的Secret> |
| 当时没存，回头找不到 Secret 了 | 部分平台的 Secret 只完整显示一次，创建时就要存好；找不回时在后台重新生成/重建机器人 |
| Bot ID 和 Secret 互相填反 | Bot ID 是身份标识（不保密），Secret 是密钥（保密），OpenClaw 配置里弄反会一直鉴权失败 |

@@point ⑦ 查看应用管理页签与回调 URL
@@need 要解决什么
机器人创建好了，但它是否在运行、回调 URL 配得对不对，需要一个地方能回头检查。找不到查看入口，就无法验证配置有没有写对。

@@idea 核心思路
创建完成后，进入**应用管理页签**，可以看到创建好的机器人列表与配置界面。在这里重点做两件事：

1. **查看 URL 地址**：与你在第 ⑤ 步填的回调地址核对，确认和 OpenClaw 的接口地址一致
2. 确认机器人处于正常状态，便于后续排查"消息没到"的问题

应用管理页签就是企微这边的"控制台"——之后改配置、看状态都回到这里。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 在"创建机器人"弹窗里找已建机器人，找不到 | 机器人列表在**应用管理页签**里，创建弹窗只在创建时出现 |
| 页签里的 URL 和 openclaw.json 里填的不一致 | 两者必须完全一致，不一致会导致消息转发失败；以应用管理页签显示的 URL 为准去改 OpenClaw 配置 |
| 改了 URL 后消息还是不到 | 改完要保存生效；同时确认 OpenClaw 服务已重启（见第 ⑧ 点） |

@@point ⑧ 核心配置文件：openclaw.json
@@need 要解决什么
企微后台这边都准备好了，接下来是 OpenClaw 侧：它怎么"认识"这个机器人？所有平台的凭证和通道配置统一写在哪个文件里、改了为什么没生效？

@@idea 核心思路
OpenClaw 的核心配置文件位于 **/home/admin/.openclaw/openclaw.json**（这是官方文档给定的部署机路径；本地安装则以你自己的安装目录为准）。把前面拿到的 Bot ID、Secret 等凭证填入对应 channel 配置：

```json
{
  "channels": {
    "wecom": {
      "botId": "<你的BotId>",
      "secret": "<你的Secret>"
    }
  }
}
```

改完配置后，**重启 OpenClaw**（或执行其 reload 命令）让配置生效——配置文件是启动时加载的，热改不会自动生效。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 改了配置，机器人毫无反应 | 配置文件改完必须**重启 OpenClaw** 才会重新加载；没重启 = 白改 |
| 在别的目录又生成了一份 openclaw.json | 配置文件路径以部署时为准（示例为 /home/admin/.openclaw/openclaw.json），改错文件等于没改，先确认你在改哪个文件 |
| JSON 少了个逗号/括号，服务起不来 | openclaw.json 是严格 JSON；改完先校验格式（编辑器高亮或 json 校验工具），再重启 |

@@point ⑨ 钉钉前置准备：开发者平台创建应用
@@need 要解决什么
企微接完了，钉钉的玩法几乎完全不同：钉钉没有"智能机器人"入口，机器人是长在"应用"身上的。第一步不是建机器人，而是**先创建一个钉钉应用**——这一步思路转不过弯，就会在平台里找不到北。

@@idea 核心思路
钉钉里，机器人是应用的一项"能力"，所以要先有"应用"这个壳：

1. 前往**钉钉开发者平台**（https://open-dev.dingtalk.com/），使用**具有管理员权限的账号**登录
2. 进入"**应用开发 - 钉钉应用**"管理页面
3. 点击 **创建应用**，填写 **应用名称** 和 **应用描述**

应用名和描述先随意起，后续会给这个应用添加机器人能力——应用只是载体，能力才是关键。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 用普通员工账号登录开发者平台，看不到创建入口 | 应用创建需要管理员权限；换管理员账号，或找管理员开通 |
| 以为企微有企业，钉钉就能直接登录 | 企业微信和钉钉是两家独立平台，钉钉开发者平台要单独登录/注册，账号体系互不相通 |
| 应用创建页面找半天"应用名称"在哪 | 创建弹窗/页面的字段就是"应用名称 + 应用描述"两项，填完直接提交，不用做别的选择 |

@@point ⑩ 钉钉添加机器人能力
@@need 要解决什么
应用建好了，但它只是一个空壳——没有任何实际功能。下一步要让它具备"机器人"这个能力，但添加能力的入口藏得比较深，容易找不到。

@@idea 核心思路
选择上一步创建的那个应用，进入应用详情后：

1. 找到 **为应用添加能力** 的入口
2. 选择 **机器人**
3. 点击 **添加**

添加后应用就"长出"了机器人能力，接下来进入机器人配置页（见第 ⑪ 点）。能力是按应用归属的——你选哪个应用，能力就加给哪个应用。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 在开发者平台首页翻不到"添加能力" | "添加能力"在**具体某个应用的详情页**里，先点进你创建的那个应用 |
| 添加机器人后什么都没发生 | 正常，添加只是开了头，后面还有机器人配置、发布两步（见下一节） |
| 建了多个应用，不知道机器人加到了哪个 | 机器人挂在**你选中的那个应用**上；记住应用名称，后面发凭证也是从这个应用里找 |

@@point ⑪ 钉钉机器人配置必填项 + 发布上线（含应用可见范围）
@@need 要解决什么
机器人能力加上去了，但配置页面一堆字段：哪些必填、哪些可以不管？填完就算完成了吗？很多人在这一步"保存"就以为上线了，其实离真正上线还差一次"确认发布"。

@@idea 核心思路
按平台操作顺序，一共四步：

1. 在"**机器人配置**"页面，填写**所有必填项**，其他**可选项保留默认值**即可
2. 点击 **发布**
3. 点击页面上方的 **查看版本详情**，点击 **编辑图标** 继续编辑
4. 完成所有必填项；在"**应用可见范围（可选项）**"中配置**能添加这个钉钉机器人的员工范围**（全公司/指定部门按需勾选，不配则默认）——点击 **保存**，在弹出的窗口点击 **确认发布**

发布后，版本详情页会显示 "**已上线**"，这才是真正的上线状态。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 点了保存就以为上线了，版本一直显示未就绪 | **保存 ≠ 发布**：保存后还要在弹出的窗口里点"确认发布"，版本详情显示"已上线"才算完成 |
| 员工在钉钉里搜不到这个机器人 | 检查"应用可见范围"：可见范围外的员工无法添加该机器人，把需要用到机器人的范围勾上 |
| 必填项漏填，发布按钮点不动/被驳回 | 机器人名称、头像、回调等必填项要填全；可选项（如机器人介绍）保持默认即可 |

@@point ⑫ 钉钉凭证：Client ID 与 Client Secret（数据安全）
@@need 要解决什么
机器人上线了，OpenClaw 对接钉钉还需要"钥匙"——但钉钉的凭证叫法和企微完全不同：不是 Bot ID/Secret，而是 **Client ID 与 Client Secret**。藏得深、易混淆、还特别敏感。

@@idea 核心思路
进入"**凭证与基础信息**"页面，找到 **Client ID** 与 **Client Secret** 两个参数：

1. 复制后保存到**个人记事本或密码管理器**（平台页面明确提示：**注意数据安全，勿泄露**）
2. 后续为 OpenClaw 配置钉钉 channel 时使用

两者关系：**Client ID 是身份标识（相当于用户名），Client Secret 是密钥（相当于密码）**。泄露 Client Secret 的后果不是"换个值"那么简单——别人可以用你应用的身份调用钉钉开放接口，读取你可见范围内的组织和员工信息，甚至冒充你的机器人对外发消息。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 把 Client Secret 截图/明文发到群里或公共文档 | 属于凭证泄露事故；正确做法是只存本机密码管理器，对外展示一律用 <你的ClientId> / <你的ClientSecret> 占位 |
| Client ID 和 Client Secret 填反 | Client ID 相当于用户名不保密，Client Secret 相当于密码要保密；填反会导致鉴权一直失败 |
| 凭证放在 openclaw.json 后随手把文件传到网盘/仓库 | 配置文件本身也要保密；真实凭证只留在部署机，用占位符版本对外 |

@@point ⑬ 最后一步：为 OpenClaw 配置模型和通道（channel）
@@need 要解决什么
钉钉的凭证到手、企微的配置也写好了——但 OpenClaw 只靠凭证还不够：它得知道"用哪个模型来思考、用哪个通道来收发消息"。这一步是把前面所有准备工作**合成一个可用系统**的收尾动作。

@@idea 核心思路
接下来为已经完成部署的 OpenClaw 配置**模型**和**通道**（即 **OpenClaw channel**，如钉钉）：

1. **模型**：确认 OpenClaw 已配置一个可用模型（模型是大脑，没有模型机器人只会"嗯嗯"不回话）
2. **通道**：在配置/CLI 中把钉钉 channel 加上，填入第 ⑫ 步的 Client ID 与 Client Secret；企微 channel 已在第 ⑧ 步的 openclaw.json 里配好

```text
openclaw channels add dingtalk --client-id <你的ClientId> --client-secret <你的ClientSecret>
```

配完后重启 OpenClaw，在钉钉/企业微信里 @ 机器人发一句话验证：能收到回复 = 全链路打通。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 通道配好了，机器人不回话 | 优先查**模型**有没有配好（没模型=没大脑）；再看凭证是否有误、服务有没有重启 |
| 以为通道配置只在平台后台改 | 平台后台是"注册身份"，OpenClaw 的配置/CLI 才是"登录密码"落地的位置，两边都要对齐 |
| 企微配好了，钉钉照抄字段 | 两个平台凭证不同：企微是 Bot ID/Secret，钉钉是 Client ID/Client Secret，别互相代填 |

| 拿到了什么 | 为什么要紧 |
|---|---|
