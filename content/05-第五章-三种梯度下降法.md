@@h1 第五章　三种梯度下降法：批量、随机与小批量
@@sub 阶段 20 · 机器学习算法与工程实战　|　梯度下降　|　难度 ★★☆

@@why 这一章在解决什么问题
上一章给了梯度下降的"骨架"（方向+步长+循环），但漏了一个关键参数：**每走一步，用多少数据来算梯度？** 用全部 → 太慢；用 1 条 → 太飘。这一章讲清三种选择：**批量梯度下降（BGD）、随机梯度下降（SGD）、小批量梯度下降（Mini-Batch GD）**，以及配套的 **epoch（轮次）与 batch（批次）** 概念。

这不仅是理论的三种流派，更是工程上的三个模式：深度学习框架里的 `batch_size` 参数、训练日志里的 epoch 轮数，全部源自这一章。学会这三个概念，你就看懂了几乎所有训练日志。

@@map 上一章→本章→下一章
上一章建立了梯度下降的通用框架（初始化→算梯度→更新→收敛）。**本章把"按什么粒度算梯度"说透：BGD/SGD/Mini-Batch 各自的流程、优缺点、适用场景，并讲清 epoch 与 batch 的区别**。下一章上代码：手写三种梯度下降、实现学习率衰减，对比它们的收敛轨迹。

@@point ① 批量梯度下降 BGD：全量视野的稳行
@@need 要解决什么
最"正统"的梯度下降怎么算？为什么它稳，又为什么在现代工程中渐渐失宠？

@@idea 核心思路
**批量梯度下降（Batch Gradient Descent）**：每更新一次参数，就**遍历全部样本**求梯度。
```
对全部 m 个样本：
    gradient = (1/m) · Σ (ŷ_i - y_i) · x_i   # 看完全部样本
    w = w - η · gradient                     # 再统一更新一次
```
特点：
- **稳**：梯度是"全局平均"视角，方向精准，损失曲线平滑下降。
- **准**：每一步都朝全局最优方向走，理论上能收敛到最优点。
- **贵**：一次更新 = 一次全量遍历。数据 100 万条，每步都要算 100 万次——迭代几百步就是上亿次运算。

**适用**：数据量小（万级以下）的经典场景。数据一大，BGD 每轮等待时间极其难熬。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为"批量梯度下降 = batch_size 很大" | 经典 BGD 是**全量**，没有 batch 概念；batch_size 是 Mini-Batch 的专属参数 |
| 小数据也吐槽 BGD 慢 | 万级以内 BGD 完全够用且最稳；别为性能焦虑而乱用 SGD |

@@point ② 随机梯度下降 SGD：单样本的快跑
@@need 要解决什么
BGD 太慢的根源是"每步看全部"。如果把每步的样本量降到 1，速度会怎样？代价是什么？

@@idea 核心思路
**随机梯度下降（Stochastic Gradient Descent）**：每步**随机挑 1 个样本**，用它的梯度当"全局梯度的近似"来更新。
```
每步：
    随机选一个样本 i
    gradient = (ŷ_i - y_i) · x_i          # 只看这一条
    w = w - η · gradient
```
好处：
- **快**：每步只算 1 条，一步顶 BGD 的万分之一成本。
- **能"跳坑"**：单样本梯度带噪声、有波动，恰好帮助跳出局部最优（非凸场景的意外惊喜）。
代价：
- **飘**：单样本的梯度方向不等于全局方向，损失曲线剧烈抖动、不走直线，像个醉汉下山。
- 但统计上**期望方向仍指向全局最优**，长期看会收敛（波动中下降）。

**收敛技巧**：SGD 通常配合**学习率衰减**——早期大步探索、后期小步收敛，把抖动抑制在可接受范围（下一章代码实现）。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 看到损失曲线乱抖就断定"代码写错了" | SGD 天然抖动；看**整体趋势**是否下行，不是看单步 |
| 挑选样本时顺序固定（挨个取） | 顺序固定会引入偏差，模型偏向数据的前段；**必须随机**（或先打乱再取） |

@@point ③ 小批量梯度下降 Mini-Batch：折中的王者
@@need 要解决什么
"全量太贵、单条太飘"，有没有既快又稳的中间态？——有，而且它成了深度学习的事实标准。

@@idea 核心思路
**小批量梯度下降（Mini-Batch Gradient Descent）**：每步用**一小批样本**（如 32、64、128 条）求平均梯度再更新。
```
每步：
    随机抽一批 batch_size 条样本
    gradient = (1/batch_size) · Σ_{i∈batch} (ŷ_i - y_i) · x_i
    w = w - η · gradient
```
为什么它是王者：
- **稳而不贵**：128 条样本的平均梯度已接近全局梯度，方向可信，波动远小于 SGD。
- **吃硬件**：批内运算可并行（numpy/GPU 矩阵运算），128 条和 1 条的成本差不了多少。
- **内存友好**：不必把全部数据载入内存，一批批流式处理。

**batch_size 是深度学习里最常调的超参数之一**：常见取 32/64/128；调大 → 更稳但更慢、内存更大；调小 → 更快但更飘。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| batch_size 设成 1 或 全部 | 那就退化成 SGD 或 BGD 了；Mini-Batch 的定位就是中间态 |
| 每批取样本不随机打乱 | 数据顺序有偏（如先全 A 类后全 B 类）会让每批梯度方向歪；**每 epoch 前先 shuffle 再切批** |

@@point ④ epoch 与 batch：两个不一样的"轮"
@@need 要解决什么
训练日志里既有 epoch 又有 batch_size，很多人混成一个概念。它们的区别是什么？

@@idea 核心思路
- **batch（批次）**：一次参数更新所用的样本数（batch_size）。它描述"**每步吃多少**"。
- **epoch（轮次）**：**全部训练数据完整过一遍模型**记为 1 epoch。它描述"**整桌菜吃了几遍**"。
- **steps per epoch（每轮步数）** = 样本总数 ÷ batch_size（向上取整）。比如 1000 条数据、batch_size=100，则每 epoch 更新 10 次。

关系式（务必记牢）：
```
总更新次数 = epoch 数 × (样本数 ÷ batch_size)
```
一个平平无奇的例子：1000 条数据，batch_size=100，训练 5 epochs → 更新 5×(1000/100)=50 次。
"背唐诗"类比：背 100 首唐诗**从头到尾过一遍** = 1 epoch；一次背 3 首 = batch_size=3。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 报告结果时只说"训练了 5000 次"不说 batch | 信息不完整；必须同时给出 batch_size 与 epoch 才能复现 |
| 以为 epoch 越大模型必然越好 | epoch 过大 → 过拟合；要配合验证集早停（后续章节早停策略） |

@@point ⑤ 三种方法的收敛轨迹对比
@@need 要解决什么
三种方法理论讲完了，直观感受一下：它们在损失地形上走出来的路径有什么不同？

@@idea 核心思路
可以这样想象同一座山谷里三个人的下山方式：
- **BGD**：每步先看清全山再迈脚 → 路线笔直、稳健、直达谷底（路径平滑，收敛确定）。
- **SGD**：闭眼随手拉个人问一句就往那迈 → 路线歪歪扭扭、忽左忽右，但大方向还是向下；偶尔还能借"跑偏"跨过小坑（路径抖，波动大，长期收敛）。
- **Mini-Batch**：每步问 32 个路人综合判断再迈 → 路线基本直、偶尔小拐（路径略抖但总体平滑）。

视觉化验证手段：把每轮的损失值画成曲线——
- BGD：光滑下降曲线。
- SGD：锯齿状抖动曲线（但趋势下降）。
- Mini-Batch：轻微锯齿的平滑下降曲线。

这一条对比是本章的"验收题"：能说清三种曲线长相，说明真懂了。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 用 BGD 的曲线去要求 SGD 平滑 | 会误判"不收敛"；SGD 要看趋势而非平滑度 |
| 只凭曲线形态判断，不看最终误差 | 三种方法收敛后的**最优解应接近一致**；若差异大，检查学习率或轮次 |

@@point ⑥ 噪声的角色：SGD 的"抖"是缺点也是优点
@@need 要解决什么
SGD 的波动让人头疼，但它也不是全无价值——这个"噪声"在什么场景反而是优势？

@@idea 核心思路
- **缺点面**：损失曲线抖、收敛慢、最终在最优解附近"徘徊"（下不准）。
- **优点面**：噪声驱动的波动 = 天然的"探索性"：当损失地形非凸、有多个坑时，SGD 的随机性有机会**冲出局部小坑**，朝全局更优的位置走。BGD 则可能被第一次看到的坑"锁死"。

这一认识很接近深度学习的实战哲学：**训练早期需要探索（大步+噪声），后期需要收敛（小步+确定）**，所以实际训练常配合"学习率衰减"实现这种"先野后稳"的节奏。

另外注意"在线学习"场景：数据一条条流进来（如实时点击流），**SGD/Mini-Batch 能边到边学**，BGD 只能等数据攒齐——这也是 SGD 家族在现代工业界的生命力所在。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 听说"噪声好"就故意加大抖动 | 噪声是"附带属性"，刻意制造噪声要控制量，否则收敛不了 |
| 在线学习场景还用 BGD | 数据流式到达时 BGD 无法工作；选 SGD 或 Mini-Batch |

@@point ⑦ 学习率衰减：从大步探索到小步精修
@@need 要解决什么
SGD 早期需要大步伐快速下降，后期需要小步伐稳稳落底。固定一个学习率做不到，怎么动态调整？

@@idea 核心思路
**学习率衰减（Learning Rate Schedule）**：训练过程中让 η 随轮次逐渐变小。
经典思路：
```
η = initial_η / (1 + decay_rate × epoch)
```
或分段式：每 N 轮把 η 缩小一半。

为什么有效：
- 早期 η 大：快速跨越平坦区域、接近谷底，还能跳出局部坑。
- 后期 η 小：在最优解附近精细打磨，抑制 SGD 的抖动，让它"落定"而不是"徘徊"。

这正是"先野后稳"节奏的工程实现。sklearn 的 `SGDRegressor` 自带类似机制（学习率参数设为 adaptive 等），深度学习框架里则有多级调度器（step/cosine 等），理念一脉相承。**下一章代码会亲手实现这个衰减**。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 衰减太快：几步之后 η≈0，模型冻结 | 衰减要平滑；把握"前期明显下降、后期缓慢趋零"的节奏 |
| 衰减太慢：后期还在抖 | 收敛精度差；适当加大衰减速率或分段骤降 |

@@point ⑧ 三种方法 vs 两类问题：怎么选
@@need 要解决什么
面对具体任务（数据多大、损失凸不凸、要不要在线），该选哪种？给出一张决策表。

@@idea 核心思路
| 场景 | 推荐 | 理由 |
|---|---|---|
| 数据小（万级）、要精确 | BGD | 全量梯度最准，成本可接受 |
| 数据大（百万级+） | Mini-Batch | 稳快兼顾，GPU 并行友好 |
| 非凸损失（深度学习） | Mini-Batch + 衰减 | 噪声助探索、批平均值助收敛 |
| 流式/在线数据 | SGD 或 Mini-Batch | 边到边学，无需全量 |
| 想快速粗调验证 | SGD | 每步成本最低，先看趋势 |

工程内存心法：**"默认 Mini-Batch；数据小求准用 BGD；数据流/求快用 SGD。"** 深度学习实战绝大多数 = Mini-Batch + 学习率衰减。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 到处套"默认值"不验证 | batch=默认 32 只是起点；数据分布怪时先画损失曲线诊断再定 |
| 把"选型"当成一劳永逸 | 数据、任务变化时回到这张表重新决策，动态调整 |

@@summary
三种梯度下降与配套概念，一次收齐：

| 方法 | 每步用多少数据 | 优点 | 缺点 | 适用 |
|---|---|---|---|---|
| BGD 批量 | 全部样本 | 稳定、方向准 | 每步太贵 | 小数据求精确 |
| SGD 随机 | 1 个样本 | 快、能跳局部坑、支持在线 | 抖动大 | 大数据看趋势/在线学习 |
| Mini-Batch | 一小批(32/64/128) | 稳而不贵、可并行 | 需调 batch_size | 深度学习默认 |

| 概念 | 含义 |
|---|---|
| batch | 一次参数更新的样本数 |
| epoch | 全部数据完整过一遍 |
| 总更新次数 | epoch × (样本数 ÷ batch_size) |
| 学习率衰减 | η 随轮次变小：先大步探索、后小步精修 |

一句话记住本章：**看一次全量叫批量（稳）、看一条叫随机（快而飘）、看一小批叫小批量（折中王者）；epoch 是"卷子刷几遍"，batch 是"一次做几道题"，深度学习默认小批量+学习率衰减。**
