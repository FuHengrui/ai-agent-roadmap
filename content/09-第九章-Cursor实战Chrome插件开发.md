@@point ② manifest.json：插件的大脑与身份证
@@need 要解决什么
Chrome 插件的一切都从 manifest.json 开始。它的核心结构长什么样？关键字段有哪些？

@@idea 核心思路
**manifest.json** 是 Chrome 扩展的**核心配置文件**：声明插件的名称、版本、权限、入口页面、图标等——没有它，Chrome 不认这个"插件"。

一个最小可用示例（Manifest V3）：

```json
{
  "manifest_version": 3,
  "name": "示例插件",
  "version": "1.0.0",
  "description": "一个用 Cursor 开发的演示插件",
  "permissions": ["storage", "activeTab"],
  "action": {
    "default_title": "点击打开插件",
    "default_popup": "popup.html"
  },
  "icons": {
    "16": "icons/icon16.png",
    "48": "icons/icon48.png",
    "128": "icons/icon128.png"
  }
}
```

关键字段速记：

| 字段 | 作用 |
|---|---|
| `manifest_version` | 清单版本（**MV3 是当前主流**，MV2 已逐步淘汰） |
| `name` / `version` | 插件名称 / 版本号 |
| `description` | 插件描述 |
| `permissions` | 权限声明（最小权限原则） |
| `action.default_popup` | 点击图标弹出的页面（popup） |
| `icons` | 各尺寸图标 |

**Manifest V3（MV3）** 与旧版 V2 的一个重要区别：**MV3 默认使用 Service Worker 作为后台脚本**（替代 V2 的后台页面），并强化权限安全模型。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 写 MV2 的旧语法在 MV3 上报错 | 确认 `manifest_version: 3`；MV3 后台用 Service Worker，别照搬 MV2 的 background page |
| 声明权限但没用到，或用到了没声明 | 权限与代码**一一对应**；多声少声都会有问题（少声报错、多声过度索权） |
| 图标缺尺寸导致商店/工具栏显示异常 | icons 尽量给全 16/48/128；开发期可先用临时图占位 |

@@point ③ 插件安装的两种路径：开发者模式 vs 应用商店
@@need 要解决什么
开发期和分发期装插件的方式完全不同——两套路径分别怎么走？

@@idea 核心思路

**路径一：离线安装（加载已解压的扩展程序）——开发期主力**

1. 在 Chrome 地址栏输入 `chrome://extensions/`；
2. 打开右上角的**开发者模式**开关；
3. 点击**加载已解压的扩展程序**；
4. 选择插件目录（含 manifest.json 的目录）；
5. 加载成功后插件图标出现在工具栏，代码改动后点"刷新/重新加载"生效。

**路径二：在线安装（Chrome 应用商店 Web Store）——分发期/用户侧**

- 开发者将插件打包后发布到 Chrome 应用商店；
- 用户从商店搜索安装、自动更新。

**打包**：扩展加载后，"打包扩展程序"生成 `.crx`（Chrome 扩展安装包）与 `.pem`（私钥，**保留好，更新签名要用**）。

**两者关系**：开发时用路径一（秒加载、秒重载），成熟后走路径二（商店分发）。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 菜单里找不到"加载已解压的扩展程序" | 没开**开发者模式**；开关在右上角 |
| crx 装到别人电脑上被拦 | crx 分发涉及签名；开发验证用"开发者模式"，正式分发走商店/企业策略 |
| .pem 私钥丢了 | 更新版无法用原密钥签名（用户要重新安装）；**私钥备份到安全位置** |
| 改了代码页面不生效 | 回到 `chrome://extensions/` 点扩展的**刷新**按钮（重新加载） |

@@point ④ 三种页面：popup / options / content——插件 UI 三件套
@@need 要解决什么
插件的界面长在哪几种形态？各自管什么？什么时候用哪个？

@@idea 核心思路

| 页面类型 | 触发方式 | 典型用途 |
|---|---|---|
| **popup（弹窗页）** | 点击工具栏图标弹出 | 快捷操作入口：翻译、截图、当前页信息等 |
| **options（设置页）** | 右键"选项"/插件详情打开 | 用户配置：默认语言、开关项、账号等 |
| **content（内容脚本）** | 注入到网页中执行 | 操作页面 DOM：改样式、抓数据、加按钮 |

**popup / options 各是一个 HTML 文件**（+ 关联 CSS/JS），结构与普通网页一致，例如 popup.html。注意 **content script 不是 HTML 页**——它是靠 manifest 里 `content_scripts` 注册、注入到别人页面里跑的 JS，没有独立页面；要往页面里塞 UI 才自己造 DOM：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>我的插件</title>
  <style>
    body { width: 260px; font-family: sans-serif; }
    button { width: 100%; margin: 4px 0; }
  </style>
</head>
<body>
  <h3>翻译当前页面</h3>
  <button id="translate">点击翻译</button>
  <script src="popup.js"></script>
</body>
</html>
```

要理解的核心分工：**popup 负责"点一下就干"、options 负责"攒配置"、content 负责"进网页里干活"**。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 想改网页内容却写在 popup.js 里 | 网页 DOM 的操作要在 **content 脚本**里做；popup 与网页是隔离的 |
| popup 打开就闪退 | 检查 popup.js 有无运行时报错（右键 popup → 检查）；控制台看 error |
| 页面样式用 CDN 引外链 | 插件页**建议本地化资源**（离线可用、避免 CSP 限制）；审查网络依赖 |

@@point ⑤ 调试与排错：控制台、错误信息、重载三板斧
@@need 要解决什么
插件报错不工作，到哪里看错误？调试的标准姿势是什么？

@@idea 核心思路

**调试三板斧：**

1. **看控制台（Console）**：右键插件 popup/页面 → **"检查"**，打开开发者工具查看报错；
2. **看扩展错误页**：`chrome://extensions/` 中插件卡片上显示的错误信息（加载失败/清单错误会直接标红显示）；
3. **改完重载**：代码修改后回 `chrome://extensions/` 点**刷新**，或直接用 `Cmd/Ctrl + R` 在扩展页重载。

**常见报错速查：**

| 报错 | 常见原因 |
|---|---|
| Manifest is not valid JSON（后面会跟 Line/column） | manifest.json 语法错：缺逗号、引号不配对、字段名拼错 |
| Permission not declared | 使用了未在 permissions 声明的 API |
| 想要"从右侧滑出"却做不出来 | 那是 `chrome.sidePanel`（Chrome 114+，manifest 加 `side_panel` 与 `sidePanel` 权限，再 `setPanelBehavior`），本章示例用的是 `action.default_popup` 弹窗，两种不是一回事 |
| Cannot access contents of the page | 被页面 CSP 或受保护页面（商店页/系统页）拦截 |
| Service worker registration failed | MV3 后台脚本（service worker）注册失败，检查脚本路径 |

**用 Cursor 辅助排错**：把报错信息贴进 Ask，再 @ 相关代码文件，AI 能快速定位"哪一行哪段"。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 控制台没报错但功能不生效 | 检查**权限是否声明**、content 脚本是否在 manifest 的 `content_scripts` 里注册 |
| 报错信息贴给 ChatGPT 却答偏 | 报错要**带上版本和上下文**（MV3、插件页面）；用 @ 文件把代码也喂进去 |
| 改了 manifest 不重载 | manifest 改动必须**回扩展页重新加载**才生效 |

@@point ⑦ 实战需求设计：精美句子收集插件的四功能
@@need 要解决什么
本实战的插件到底做什么？需求设计是什么样？先看需求再开发，避免"AI 自由发挥"。

@@idea 核心思路
本实战的需求是"**精美句子收集插件**"，包含 4 个功能：

**1. 文本选中记录功能**
- 用户用鼠标在网页中选中一段文字，鼠标释放后自动弹出插件图标/悬浮小按钮（靠近选中文本）；
- 点击"保存"后弹出快捷保存面板，支持：编辑句子内容（可选）、选择/新建分类（写作、演讲、情感、灵感等）、可选添加标签或备注；
- 自动记录当前网页标题和网址作为来源信息。

**2. 插件主界面（点图标弹出的面板）**
- 点击插件图标（地址栏右侧）打开这个面板；
- 面板含：分类列表、精美语句展示区（按时间/分类/搜索排序）、搜索框、每条句子的"复制"/"编辑"/"删除"按钮、"喜欢/星标"标记。

**3. 快速粘贴功能**
- 鼠标右键菜单或快捷面板中支持快速复制句子到剪贴板；
- 可考虑提供快捷键唤出常用句面板（如 Alt+M）。

**4. 数据本地持久化存储**
- 所有句子数据保存在本地（插件存储），不依赖云端。

**要点**：这是一个典型的"AI 帮你开发真实产品"案例——**需求清楚（四功能）、存储本地（隐私友好）、界面具体（右侧面板）**，正好匹配前面学的 manifest、三种页面、内容脚本等全部知识点。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| "让 AI 随便做个插件"导致功能飘 | 先把需求**写清楚**（如上四功能），再喂给 Cursor；需求越具体 AI 越收敛 |
| 悬浮小按钮/右键菜单/快捷键都想要却不会实现 | 分别对应 content 脚本（悬浮）、contextMenus 菜单（右键）、commands（快捷键）——先查官方文档再让 AI 生成 |
| 本地存储选错方案 | 用 **chrome.storage（local）** 做本地持久化，而非网络存储；数据格式（分类/句子/标签/来源）提前设计 |

@@point ⑧ 需求红线：让 Rules 替你把"不准做"锁死
@@need 要解决什么
实战里 AI 最容易犯的错：改多了、改歪了、加了调试代码。需求设计里直接给了一份"红线清单"——怎么让 AI 自动遵守？

@@idea 核心思路
插件需求设计阶段有一份**需求设计约束清单**（即"需求红线"），逐条都是防止 AI 跑偏的硬约束：

| 红线 | 防止什么 |
|---|---|
| 不得删除或更改与本次修改无关的代码或功能 | AI 顺手改别的 |
| 修改前需完整浏览上下文，理解整体结构和逻辑 | AI 不看全局瞎改 |
| 保持与现有项目的命名规范、代码风格、格式完全一致 | 风格分裂 |
| 变量命名需语义明确，禁止使用 a/b/c 等无意义命名 | 可读性崩坏 |
| 禁止添加日志输出、调试页面、调试语句 | 污染交付物 |
| 除非特别要求，否则不得自动生成任何测试代码 | 擅自加测试 |
| 统一使用当前推荐的标准 API，禁止调用已弃用接口 | 用过时 API |
| 一律使用 Windows 命令，禁止使用任何 Linux 命令 | 平台环境不符 |
| 所有代码注释必须使用中文 | 语言一致性 |

**怎么落地**：把这些红线**写进 Cursor Rules（Project/User）**，AI 生成代码时会自动遵守——这就是第 08 章"规则体系"在真实项目里的用法：**需求红线 = Rules 内容**。项目里的每一份"约束清单"都可以规则化。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 红线只放在需求文档里没写进 Rules | 规则文档人看的，**Rules 是 AI 看的**；两条腿都要有 |
| 红线列一堆但 AI 仍违规 | 检查规则是否**已生效**（User/Project 位置、glob 范围）；违规行为贴回 Ask 让它改正并补充规则 |
| 平台类约束（Windows 命令）写进全局规则 | 平台约束属于**项目/环境特定**，写 Project Rules；别污染全局 |
