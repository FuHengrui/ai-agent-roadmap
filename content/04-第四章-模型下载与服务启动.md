@@point ① 模型下载的两条路：HuggingFace 与 ModelScope
@@need 要解决什么
vLLM 要加载模型权重，权重去哪下载？

@@idea 核心思路
主流两个模型仓库：

- **HuggingFace Hub**：国际最全，但国内网络下载慢/不稳。
- **ModelScope（魔搭，阿里）**：国内平台，**速度与稳定性好**，大量开源模型（Qwen、Llama 中文版等）同步托管。

这里的选择：**国内部署用 ModelScope 下载**。下载到的模型是本地目录（包含权重、配置、tokenizer 等文件），vLLM 直接加载该目录。

```
模型目录示例:
qwen3-0.6b/
├── config.json
├── model.safetensors   ← 权重
└── tokenizer.json
```

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 下载到一半断掉 | 用 ModelScope CLI 的断点功能/downloader 重试，别用浏览器手点 |
| 只下权重文件 | config/tokenizer 缺失会导致加载失败，整目录下载 |

@@point ② 用 ModelScope CLI 拉取模型
@@need 要解决什么
具体命令是什么？怎么把"模型"变成"本地目录"？

@@idea 核心思路
第一步装 SDK（虚拟环境内）：

```
pip install modelscope
```

第二步克隆模型到本地（以 qwen3-0.6b 为例）：

```
modelscope download --model Qwen/Qwen3-0.6B --local_dir ./qwen3-0.6b
```

- `--model`：ModelScope 上的模型 ID（组织/模型名）。
- `--local_dir`：保存到本地的目录（之后 vLLM 加载它）。

下载完成后确认目录里有权重文件（.safetensors/.bin）与 config 文件即可。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 模型 ID 写错 | 先在 ModelScope 网页搜索确认完整 ID 与名称大小写 |
| 下载目录权限不足 | 用当前用户可写目录，避免装到系统保护路径 |
| 混用 HF CLI 命令 | 两个平台 CLI 参数不同，ModelScope 用 `modelscope download --model` |

@@point ③ 启动服务：vllm serve 一行命令
@@need 要解决什么
模型下载好了，怎么把它变成可调用的 API 服务？

@@idea 核心思路
vLLM 提供超简启动命令（服务模式）：

```
vllm serve Qwen/Qwen3-0.6B --port 8000
```

- 参数位置：模型 ID（或本地目录路径）。
- 默认暴露 OpenAI 兼容接口 `http://localhost:8000/v1`。
- 也可以直接传本地目录：

```
vllm serve ./qwen3-0.6b --port 8000
```

启动成功后终端会出现服务地址与模型信息，此时即可按 OpenAI 格式调用。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 端口被占用 | `--port` 换一个空闲端口，或先释放占用进程 |
| 启动报显存错误 | 换更小模型 / 更低位宽 / 调整 gpu-memory-utilization（见后） |
| 传 HF ID 但网络不通 | 加载本地目录或改用 ModelScope 下载的路径 |

@@point ④ 服务相关参数：host / port / served-model-name
@@need 要解决什么
服务端三个常用参数分别控制什么？

@@idea 核心思路

| 参数 | 作用 | 示例 |
|---|---|---|
| `--host` | 监听地址 | **默认 0.0.0.0**（所有网卡）；只想本机访问要显式 `--host 127.0.0.1` |
| `--port` | 服务端口 | `8000` |
| `--served-model-name` | 对外暴露的模型名 | `qwen`（客户端 requests 里填这个名字） |

重点理解 **served-model-name**：它是"对外名字"（API 里返回/校验的模型名），可以与真实模型名不同——便于对外隐藏内部模型或统一接口名。客户端调用时用这个名字，**与模型 ID 无关**。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 外网访问不到服务 | 默认已经绑 `0.0.0.0`，先查**安全组 / 防火墙 / 端口映射**有没有放行 |
| 客户端报"模型不存在" | 请求里的 model 字段必须填 served-model-name（或默认模型名），不是本地路径 |
| 把 served-model-name 当真实模型名下载 | 它只是服务别名，真实权重还是本地目录里的 |

@@point ⑤ 性能相关参数：tensor-parallel-size 与 gpu-memory-utilization
@@need 要解决什么
大模型/多卡场景，两个性能参数怎么设？

@@idea 核心思路

**tensor-parallel-size（张量并行度）**：把模型切到几张卡上跑。

```
vllm serve qwen-14b --tensor-parallel-size 2   # 2卡并行
```

**gpu-memory-utilization（显存利用率）**：vLLM 最多可用多少比例的显存（默认 0.9）。

```
vllm serve qwen-14b --gpu-memory-utilization 0.95
```

使用逻辑：

- 单卡放不下 → 张量并行（卡数整除模型头/层配置）。
- 留显存给其他进程/更激进缓存 → 调低利用率；反之调高。

调参目标：**在"不 OOM"与"给 KV 缓存最大化空间"之间找平衡**。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 张量并行度随便设 | 必须按模型可切分维度选（通常幂次、整除），否则启动报错 |
| 利用率设 1.0 | 预留 0.05~0.1 给框架/驱动开销，设满易 OOM |
| 以为利用率越高越准 | 它管显存用量，不管模型精度；精度由模型本身决定 |

@@point ⑥ 生成长度参数：max-model-len 与 max-tokens
@@need 要解决什么
模型最多能生成多长？这个限制在哪配？

@@idea 核心思路
两个"长度"参数分工不同：

| 参数 | 层级 | 作用 |
|---|---|---|
| `--max-model-len` | 服务级 | 模型支持的最大上下文总长（输入+输出），决定**单条序列**的 KV 上限（总预算看 utilization） |
| `max_tokens` | 请求级 | 单次请求允许生成的最大 token 数（客户端传参） |

示例：

```
vllm serve ./qwen3-0.6b --served-model-name qwen --max-model-len 8192   # 客户端才用 model='qwen'
# 客户端: {"model":"qwen","max_tokens":1024,...}
```

KV 缓存的**总预算**由 `--gpu-memory-utilization` 划定（总显存×比例 − 权重 − 激活峰值）；`--max-model-len` 只决定**单条序列**最多吃多少 KV——设得越大，同样显存下能同时跑的并发越少，超过可分配块会直接启动失败或请求报长度超限。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| max-model-len 超模型承受 | 超模型训练长度会输出质量下降/报错，按模型规格设 |
| 把两者混为一谈 | 服务级限制兜底，请求级限制单个请求，两层都要设对 |

@@point ⑦ 一次启动完整示例
@@need 要解决什么
把各参数组合起来，一个"生产感"的启动命令长什么样？

@@idea 核心思路
组合示例（覆盖常用场景）：

```
vllm serve ./qwen3-0.6b \
    --host 0.0.0.0 \
    --port 8000 \
    --served-model-name qwen \
    --gpu-memory-utilization 0.9 \
    --max-model-len 8192
```

含义一览：

```
host=0.0.0.0      外部可访问
port=8000         服务端口
served-model-name=qwen   客户端的 model 字段
gpu-memory-utilization=0.9  显存用90%
max-model-len=8192  上下文最长8192
```

启动日志出现 "Uvicorn running on ..." 等字样即表示服务就绪。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 参数堆砌不校验 | 每个参数都要能解释为什么，启动报错才能快速定位 |
| 把启动当一次性动作 | 参数是"部署配置"，建议沉淀成脚本/文档，统一管理 |
