@@why 这一章在解决什么问题
"跑个深度学习模型，笔记本风扇都快起飞了""实验室没 GPU 服务器，租云平台又太贵""想学 AI 但电脑配置太拉胯"——这三句话是绝大多数入门同学的现状。深度学习模型训练和推理依赖大规模 GPU 算力，本地显卡不支持 CUDA 就寸步难行。这一章要解决的问题只有一句：**怎么在普通电脑上，白嫖到一块够用的云端 GPU，把模型跑起来。**

本章全是平台操作（登录、绑定、授权、看额度），**全文代码不到 10 行**。建议**边看边点**：开一个浏览器跟着步骤走，卡在哪一步就回看哪一步。

@@prep 开始之前
只需浏览器，注册 ModelScope 并绑定阿里云账号、领免费额度，就能开第一台 Notebook。
> **材料在哪**：本章不依赖任何本地文件，全部在浏览器里操作。没有账号也能读——重点看「Notebook 实例怎么起、目录挂在哪、免费额度怎么算」，这三件事在别的平台也是同一套逻辑。

@@goal 学到这儿就够了
能说清 PAI-DSW 与 EAIS 的差别和免费额度怎么算，能自己开出一台能跑代码的 Notebook，这章就算过了。

@@map 上一章→本章→下一章
前面阶段讲了 Python、大模型原理、微调、Agent、OpenClaw、Web 系统构建……但"在哪跑"这个问题一直没系统解决：本地 4GB 内存、无独显跑不动小模型微调，只能干看。从这一章开始，进入**开发工具平台**环节：**本章先解决"有没有 GPU 用"（ModelScope 云端 Notebook），下一章解决"环境怎么配"（Conda 与 Web-IDE），再后面用 AutoDL 讲"按任务选 GPU 与远程开发"**。学完这两章，你就有了一个浏览器里能白嫖 GPU 的深度学习练手基地。

@@point ① 本地算力受限，借云端的 GPU
@@need 要解决什么
笔记本只有 CPU、显卡不支持 CUDA，或者显存只有 2~4GB——而神经网络训练动辄需要几十 GB 显存。没有一个"按需付费甚至免费"的算力来源，深度学习根本练不了手。

@@idea 核心思路
把计算资源搬到**云端数据中心**：云端有大规模的 GPU 集群，你通过浏览器远程连接，**按需申请**一块资源来跑训练与推理。本地只当一个"遥控器"（浏览器 + 写代码的页面），所有重活都在云端完成。这样硬件门槛直接消失：只要电脑能开浏览器，就拥有了顶配显卡。

```
本地电脑（浏览器）  ←——网络——→  云端 GPU 集群（训练/推理）
   只做输入输出                       真正算数的地方
```

云端算力的三个关键词：**按需**（用多少租多少）、**弹性**（不够了扩，不用了缩）、**低成本**（短任务用免费额度，长任务按小时计费，比买卡便宜得多）。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 本地明明装了 CUDA 还是跑不动模型 | 看**显卡型号**而不是 CUDA 版本：N 卡不带 RTX 前缀的入门卡、A 卡、核显都不适合训练；判断标准是显存大小和 CUDA 计算能力 |
| 以为云端"免费"等于无限用 | 免费额度有小时数上限（如 GPU 36 小时），用完要么等刷新要么按量付费，动手前先看额度余量 |

@@point ② ModelScope Notebook 是什么
@@need 要解决什么
有了 GPU 还不够——还要一个**能用 Python 编程、能存文件、能管理环境**的云端开发环境。自己租 GPU 服务器再从零装环境，对初学者是灾难。

@@idea 核心思路
ModelScope Notebook 是**阿里云提供的云端机器学习开发环境**：浏览器里就能写 Python、训模型、处理大规模数据，且**在额度内可免费使用 GPU 资源**。它把三件事打包在一起：算力（GPU）+ 开发界面（Jupyter/VS Code）+ 存储（持久化目录）。社区常把这种"用免费额度蹭高端算力"的模式戏称为**白嫖**——这也是最适合学生的玩法。

一句话：**ModelScope Notebook = 云端能用 Python 训模型的 Jupyter/VS Code，且初始额度免费。**

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 把 ModelScope 当成一个"模型网站" | 它本质是**平台**：既看模型（模型库）也提供**算力开发环境**（Notebook）。本章用的是 Notebook 能力，不是下载模型 |
| 浏览器关掉就以为环境没了 | 云端环境在服务器上，换设备、换浏览器都能接着用；环境跟着**账号**走 |

@@point ③ 云端算力池：PAI-DSW 与 EAIS
@@need 要解决什么
"免费 GPU"听起来美好，但具体是哪家的算力？申请流程长不长？——需要知道背后是谁在提供资源，才好判断稳定性与额度规则。

@@idea 核心思路
ModelScope Notebook 的算力来自阿里云两个合作产品，像"算力池"一样供你取用：
- **PAI-DSW**：阿里云 PAI 平台的交互式开发环境，适合**需要长期保留实验数据**的场景。
- **EAIS**：弹性加速计算服务，用于**短期训练或临时算力补充**。

申请时你不用理解这两套系统的细节，只要知道：**点哪个按钮，就从对应池子里申请到一块 CPU/GPU 资源**。平台把底层调度封装掉了，你面对的是"实例"和"额度"两个概念。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 申请资源时看到一堆阿里云产品名词发懵 | 认准两个池子：要持久化数据 → 选 PAI-DSW；只临时跑一下 → 选 EAIS。其余参数按引导默认即可 |
| 以为申请一次资源永久有效 | 资源是**实例**，有关机/恢复概念；额度和实例状态都能在控制台看到 |

@@point ④ Jupyter 与 VS Code 双模式
@@need 要解决什么
有的人习惯 Jupyter 的"边写边看结果"，有的人离不开 VS Code 的工程化体验。如果云端只能二选一，总有一半人不顺手。

@@idea 核心思路
ModelScope Notebook **默认提供 Jupyter Notebook**，同时可一键切换到 **VS Code Online（Web-IDE）**。两者共用同一个云端环境和同一份文件，只是操作界面不同。切换入口就在界面右上角（Web-IDE 里点图标可返回 Jupyter）。习惯哪种就用哪种，环境不重复创建、文件不重复存储。

这个设计解决的是**习惯隔离**问题：工具只是皮，算力、存储、环境是共享的核。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 在 Jupyter 里的文件切到 VS Code 找不到了 | 两个模式共用工作区，**切模式后要刷新文件树**（或等同步完成）；不是文件丢了 |
| 以为两种模式是两套环境 | 环境是同一个，分别在两个界面操作而已；装的包两边都能用 |

@@point ⑤ 资源配额可视化
@@need 要解决什么
免费额度是有限的：GPU 用了多少小时？还剩多少？会不会跑着跑着突然被停？——心里没数就容易被"断供"坑到。

@@idea 核心思路
控制台**实时展示实例状态、算力额度和运行日志**。你可以随时看到：当前实例是运行中还是已关机、GPU 免费额度剩多少、日志里报了什么错。这方便你做两件事：一是**课程/项目排期**（知道额度还够撑几天），二是**及时发现异常**（比如实例挂了，日志会告诉你原因）。

用法建议：每次开跑前先看额度余量，像看手机电量一样养成习惯。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 训练跑到一半实例被关机 | 大概率是免费额度用尽或实例计费时间到了；**跑长任务前先确认额度够用** |
| 以为关了浏览器就停止计费 | 计费跟着**实例状态**走（运行中即计费），不是跟着浏览器走；不用时去控制台**关机**才能真正停 |

@@point ⑥ 依赖管理与自定义镜像
@@need 要解决什么
每次新开一个云端环境都要重新装 matplotlib、transformers、torch……太浪费时间。能不能把"装好的环境"保存下来复用？

@@idea 核心思路
Notebook 支持两种环境复用方式：
1. **自定义镜像**：把当前环境（含已装的包）打包成镜像，下次开实例直接选用，秒级回到熟悉环境。
2. **requirements.txt 导入**：把依赖清单写成文件，新实例里一键批量安装。

进阶做法是把镜像 + requirements.txt 结合：镜像兜底（保证基础环境一致），requirements 增量（保证项目依赖一致）。这样团队多人协作或课程多期复用时，环境不会"在我电脑上能跑"。

```
新实例启动 = 基础镜像（环境骨架）
           + requirements.txt（项目依赖）
           = 一致可复现的开发环境
```

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 换了新实例后 import 报 ModuleNotFoundError | 新实例是全新环境，**没装包**；用 requirements.txt 重装或改用自定义镜像启动 |
| 镜像保存失败 | 常见原因是实例存储空间不足或正在运行中打包；先清理大文件再打镜像 |

@@point ⑦ 持久化存储 /mnt/workspace/
@@need 要解决什么
云端实例是"租"的，关机、重建都有风险。如果代码、模型、数据集存在临时目录，一关实例就全没了，损失惨重。

@@idea 核心思路
PAI-DSW 提供**持久化存储目录 `/mnt/workspace/`**：放在这里的 Notebook、模型、数据集，**实例关停甚至重建后依然保留**。而放在其它路径（如 /tmp、/root 下临时文件）的数据，实例释放后就会消失。

**原则：所有重要资产一律放 `/mnt/workspace/` 下。** 装环境、存模型、放数据集都往这个目录指，这几乎是你在这个平台上唯一的"保险箱"。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 重启实例后代码没了 | 代码肯定写在 /tmp 之类临时目录了；检查路径，把文件放进 /mnt/workspace/ |
| 数据盘"满"了，模型存不进去 | 存储空间有上限；大模型文件动辄几个 GB，先清理旧模型或用外部存储（见本阶段 AutoDL 网盘章） |
| 以为 EAIS 也有持久化 | **EAIS 暂无持久化存储**；要保留数据的实验务必用 PAI-DSW |

@@point ⑧ PAI-DSW 与 EAIS 免费配额对比
@@need 要解决什么
免费额度有两套（PAI-DSW 和 EAIS），规格和时数都不一样。选错了要么白白浪费时数，要么存储没保障。需要一张表快速决策。

@@idea 核心思路
每类合作云产品的免费配额如下（以官方最新页面为准，表格为基准参考）：

| 维度 | PAI-DSW | EAIS |
|---|---|---|
| CPU 环境 | 8核/32G，长期使用 | 8核/32G，长期使用 |
| GPU 环境 | 8核/32G 显存24G，免费限额 36 小时 | 8核/32G 显存16G，免费限额 64 小时 |
| 持久化存储 | /mnt/workspace/ 目录 | 暂无 |
| 适用场景 | 需要持续保留实验数据 | 短期培训、临时算力补充 |

**决策口诀**：要存数据、要长期项目 → **PAI-DSW**；只想临时跑个验证、看重 GPU 时长 → **EAIS**。两个都免费，互不冲突，可以都领。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| EAIS 显存 16G 比 DSW 24G 小，但时长多 28 小时 | 这是**时长与显存的权衡**：小模型选 EAIS 更划算，大模型（如 7B 微调）需要 24G 显存就选 DSW |
| 额度页面数字和表格对不上 | 免费额度会被平台调整，**以控制台实际显示为准**；表格是理解思路，不是合同 |

@@point ⑨ 构建第一个 Notebook：登录→绑定→授权→领额度
@@need 要解决什么
知道了平台是什么，就差最后一步"怎么把它点亮"。构建流程卡在哪一步都可能领不到额度，需要一条顺畅的动线。

@@idea 核心思路
构建 ModelScope Notebook 共 5 步，按顺序走完就能用：

1. **登录 ModelScope 账号**：使用机构或个人账号登录 ModelScope 平台（手机号或阿里云账号均可）。
2. **绑定阿里云账号**：按引导完成阿里云账号绑定——算力由阿里云提供，必须先绑定才能申请 CPU/GPU 资源。
3. **登录阿里云账号**：进入阿里云登录页，输入账号信息完成登录（注意这里登录的是**阿里云**，不是 ModelScope）。
4. **授权 Notebook 所需权限**：在授权页面**勾选全部权限**，确保 Notebook 能正常调用计算与存储资源——漏勾会导致后面申请资源报权限错误。
5. **确认额度发放**：授权成功后系统自动下发免费初始额度，到**控制台**查看余量，按需开始使用。

**检查项**：走完 5 步后，控制台应能看到实例列表和额度余量；若看不到，八成是第 4 步授权漏勾了，回到授权页重勾。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 第 2 步绑定提示失败 | 确认当前 ModelScope 账号与阿里云账号是同一主体（同手机号/同实名）；绑定是单向的，换号需重新绑定 |
| 授权页面说"权限不足" | 当前账号不是阿里云主账号或没有权限管理角色；用主账号操作，或让管理员授权 |
| 领完额度还是无法创建实例 | 先刷新控制台，再看有没有**实名认证**——免费额度通常要求实名用户 |
