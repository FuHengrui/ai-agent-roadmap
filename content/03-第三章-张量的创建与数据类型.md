@@why 这一章在解决什么问题
神经网络里所有的数据——图片、文本、特征、标签——在 PyTorch 里都是一种叫**张量（Tensor）**的结构。它是整个框架的数据地基：模型吃的是张量，吐的也是张量。这一章就把"什么是张量、怎么创建张量、张量有哪些数据类型、默认该用哪种"彻底搞明白。地基不牢，后面所有代码都会在形状和类型上报错。

@@point ① 张量是什么：从维度理解
@@need 要解决什么
"张量"这名字很唬人，它到底是个什么东西？

@@idea 核心思路
**张量（Tensor）就是 PyTorch 中的基本数据结构，本质是多维数组**。从维度理解最直观：

| 维度数 | 名字 | 例子 |
|---|---|---|
| 0 维 | 标量（单个数字） | 3.14 |
| 1 维 | 向量 | [1, 2, 3, 4] |
| 2 维 | 矩阵 | [[1,2,3],[4,5,6]] |
| 3 维及以上 | 高维张量 | 一张 3×224×224 的彩色图片 |

一张灰度图是 2 维（高×宽），彩色图是 3 维（通道×高×宽），一批图片就是 4 维（批量×通道×高×宽）。**张量就是把"数字堆成什么形状"这件事统一表达出来**。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为张量是某种高深数学对象 | 它就是多维数组，和 NumPy 数组是"近亲"；学了 NumPy 就懂了 80% |
| 分不清"维度"和"形状" | 维度是层数（几层方括号），形状是每一层的大小，如 (3, 4) 是 2 维、3 行 4 列 |

@@point ② torch.tensor：根据数据创建
@@need 要解决什么
我手里已经有一组数字了，怎么把它变成张量？

@@idea 核心思路
用 **`torch.tensor(数据)`**，数据可以是标量、列表或嵌套列表，PyTorch 会自动推断出对应的形状和维度：

```python
import torch
scalar = torch.tensor(3.14159)          # 0维：标量
vector = torch.tensor([1, 2, 3, 4])     # 1维：向量
matrix = torch.tensor([[1, 2, 3],       # 2维：矩阵
                       [4, 5, 6]])
tensor_3d = torch.tensor([[[1, 2], [3, 4]],
                          [[5, 6], [7, 8]]])  # 3维
print(scalar.dim(), vector.dim(), matrix.dim(), tensor_3d.dim())
```

**谁更懂数据，torch.tensor 最懂**：它会完全按你给的数据生成，最常用。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 给 torch.tensor 传了形状但传成 `torch.tensor(2,3)` | 会报错：tensor() 要的是"数据"不是"形状"；想要按形状创建要用 torch.Tensor(2,3) |
| 列表里数字类型混着传 | int 和 float 混在一起会按"高精度优先"统一，建议直接指定 dtype 或保持类型一致 |

@@point ③ torch.Tensor：按形状创建
@@need 要解决什么
我不要具体数值，只想要一个"某形状的空壳"张量，行不行？

@@idea 核心思路
**`torch.Tensor(形状...)`** 两种用法都能用：
- 传数据：`torch.Tensor([3.14159])` → 和 torch.tensor 类似。
- 传形状：`torch.Tensor(2,3)` → 创建 2×3 的张量（值为未初始化的随机内存数）。

注意它是一个**类**，名字里的"T"大写，和 torch.tensor 函数不是一回事，不要混。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| `torch.Tensor(2,3)` 出来的数值很怪 | 这是**未初始化内存**的随机残值，不是有意生成的数据；想要全 0/全 1 用后面学的 torch.zeros/ones |
| 把 Tensor 和 tensor 当成同一个函数 | `torch.Tensor` 是类（可传形状），`torch.tensor` 是函数（只接收数据）；大小写与参数含义都不同 |

@@point ④ 按类型创建：FloatTensor / LongTensor / BoolTensor 家族
@@need 要解决什么
为什么创建张量时还能见到 FloatTensor、IntTensor 这类带类型的写法？

@@idea 核心思路
PyTorch 为每种常用数据类型准备了"快捷工厂"：

| 函数 | 数据类型 |
|---|---|
| torch.FloatTensor | float32（默认浮点） |
| torch.DoubleTensor | float64 |
| torch.HalfTensor | float16 |
| torch.IntTensor | int32 |
| torch.LongTensor | int64（默认整型） |
| torch.ShortTensor | int16 |
| torch.ByteTensor | uint8 |
| torch.BoolTensor | bool |

用法上**既能传数据也能传形状**：`torch.FloatTensor([1,2,3])` 或 `torch.LongTensor(2,3)`。它比 torch.Tensor 多的就是"锁定了类型"。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| `torch.IntTensor([3.14159])` 打出 3 | 类型转换会**截断小数**；想要保留小数必须用浮点型工厂 |
| 搞不清默认类型 | 记住：**浮点默认 float32（FloatTensor），整型默认 int64（LongTensor）** |

@@point ⑤ 数据类型：默认选什么
@@need 要解决什么
这么多 dtype 到底选哪个？选错了会怎样？

@@idea 核心思路
一个非常省心的默认策略：
- **大多数深度学习任务：用默认的 torch.float32 即可**。
- **整数作为索引/标签：用默认的 torch.int64（LongTensor）**。
- 特殊场景再换：
  - 需要高精度计算 → torch.float64；
  - 需要节省内存 → torch.float16（半精度，GPU 场景常用）；
  - 布尔掩码 → torch.bool。

选型的本质是**精度 vs 内存/速度的权衡**：float32 是深度学习的事实标准，绝大多数模型参数都用它。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 高精度差一点点就换 float64 全量训练 | 内存翻倍、GPU 加速可能失效；除非研究需要，float32 够用且最快 |
| 标签用 float32 传给需要 long 的损失函数 | 报错如 "expected dtype Long"；交叉熵类损失要求标签是 int64 |

@@point ⑥ GPU 上的张量：设备（device）概念
@@need 要解决什么
张量默认在 CPU 上，怎么用到 GPU？放到 GPU 上会自动加速吗？

@@idea 核心思路
**关键认知：张量存储在哪里，并不会因为可用 CUDA 就自动切换到 GPU**。必须显式指定！两种方式：

```python
device = 'cuda' if torch.cuda.is_available() else 'cpu'


cpu_tensor = torch.randn(2, 3)          # 先在 CPU 上造一个，下面两种方式把它挪过去
t1 = cpu_tensor.to(device)              # 1. .to(device)：最推荐，设备可切换
# 2. .cuda()：快捷方式
t2 = cpu_tensor.cuda()                  # 2. .cuda()：快捷写法，等价于 .to('cuda')
```

如果电脑没 GPU（或装的是 CPU 版 torch），`.to('cuda')` 会**直接报错**——`RuntimeError: Torch not compiled with CUDA enabled` / `No CUDA GPUs are available`。它**不会**默默回退到 CPU，别指望它自动降级。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| `.to('cuda')` 但机器无 GPU | 不报错但也没加速；先 `torch.cuda.is_available()` 确认再写 device 逻辑 |
| CPU 张量和 GPU 张量直接运算 | 报 "device mismatch"；把所有张量统一 `to(device)` 到同一个设备再算 |
| 以为装 GPU 版就自动快了 | 数据、模型都要显式 `.to(device)`，否则全程 CPU |

@@point ⑦ 统一值张量：ones / zeros / full 家族
@@need 要解决什么
想创建一个全 1、全 0 或者全 6 的张量，怎么最省事？

@@idea 核心思路
PyTorch 提供了"统一值"工厂 + "照形状"版本：

| 函数 | 作用 |
|---|---|
| torch.ones(size) | 全 1 张量 |
| torch.zeros(size) | 全 0 张量 |
| torch.full(size, 值) | 全部填指定值 |
| torch.ones_like(t) / zeros_like(t) / full_like(t, 值) | 与 t **形状相同**的全 1/全 0/定值 |

```python
ones = torch.ones((2, 3))
zeros = torch.zeros((2, 3))
sixes = torch.full((2, 3), 6)   # 2x3 全是 6
like_ones = torch.ones_like(sixes)  # 形状跟随 sixes
```

_like 系列在"想复制某张量的形状但换初始值"时特别实用（例如初始化与权重同形的掩码）。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 传 `torch.ones(2, 3)` 当成两个参数 | 正确写法是传一个元组 `(2, 3)`；传两个单独数字也能跑但易读性差、易错 |
| 用 torch.full 忘了传填充值 | full 必须给值和形状两个参数，缺一报错 |

@@point ⑧ 线性张量：arange 与 linspace
@@need 要解决什么
想要一串等间隔的数字（比如 0~9、0~1 十个点），怎么生成？

@@idea 核心思路
两个一字之差但语义不同的函数：

| 函数 | 生成方式 | 区间 |
|---|---|---|
| torch.arange(start, end, step) | 按**步长**生成整数序列 | **左闭右开**（不含 end） |
| torch.linspace(start, end, num) | 在区间内生成**指定个数** | **左闭右闭**（含 end） |

```python
print(torch.arange(0, 10, 2))   # [0, 2, 4, 6, 8]，不含 10
print(torch.linspace(0, 1, 5))  # [0, 0.25, 0.5, 0.75, 1]，含两端
```

**范围语义不同是最高频的坑**：arange 不含终点、linspace 含终点。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| `torch.arange(0, 10)` 期待到 10 | 它是左闭右开，只会到 9；要包含 10 就写 arange(0, 11) |
| 想要 10 个均匀点却用 arange | arange 按步长不按个数；均匀取 N 个点用 linspace(0, 1, N) |

@@point ⑨ 随机张量：rand 与 randn
@@need 要解决什么
神经网络的权重初始值要随机，怎么生成随机张量？两种随机有什么区别？

@@idea 核心思路

| 函数 | 分布 | 范围 |
|---|---|---|
| torch.rand(size) | 均匀分布 | [0, 1) 之间 |
| torch.randn(size) | 标准正态分布 | 均值为 0、标准差为 1 |

**rand 均匀且限幅，randn 正态且不设边界**（大值为小概率）。初始化权重常用 randn，因为正态分布更接近权重的理想初始状态。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为 randn 的"n"表示范围 | n 是 normal（正态），值理论上无限；想要限幅用 rand 或手动 clamp |
| 随机结果每次不一样，怀疑出错 | 正常！随机性就是如此；想复现实验要设种子（见下一知识点） |

@@point ⑩ 随机种子：让实验可复现
@@need 要解决什么
同一段代码每次跑结果都不同，论文和实验怎么复现？

@@idea 核心思路
用种子固定随机数生成器的起点：
- `torch.random.initial_seed()`：查看当前初始种子。
- `torch.random.manual_seed(n)` / `torch.manual_seed(n)`：手动设置种子。

```python
torch.manual_seed(42)          # 设好种子
print(torch.randn(2, 2))       # 每次运行结果都一样
```

**CPU 串行执行，相同种子结果必然一致**；但 CUDA 并行运算下，即使相同种子，由于线程更新顺序不确定，结果也可能不一致——所以追求完全可复现时要在 GPU 上额外配置相关种子参数。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 设了种子还是不一样 | 检查是不是在 GPU 上跑；GPU 多线程随机性无法像 CPU 一样严格复现 |
| 只在训练前设一次种子 | 每轮实验前重新手动设同一个种子，才保证起点一致 |

@@summary
本章把张量的"出生方式"全部讲完：

| 问题 | 答案 |
|---|---|
| 张量是什么 | PyTorch 的多维数组：0 维标量、1 维向量、2 维矩阵、3 维+高维 |
| 根据数据创建 | torch.tensor(数据)，自动推断形状维度 |
| 按形状创建 | torch.Tensor(2,3)，值为未初始化内存 |
| 按类型创建 | FloatTensor/LongTensor/BoolTensor 等，锁定 dtype |
| 默认类型怎么选 | 浮点 float32、整型 int64；高精度 float64、省内存 float16 |
| GPU 怎么用 | 显式 .to(device) 或 .cuda()，不会自动加速 |
| 统一值张量 | ones/zeros/full + 各自的 _like 版本 |
| 等间隔序列 | arange 左闭右开按步长；linspace 左闭右闭按个数 |
| 随机张量 | rand 均匀 [0,1)；randn 标准正态 |
| 可复现 | torch.manual_seed(42)，GPU 下需额外处理 |

一句话记住本章：**张量 = 多维数组；创建方式按"数据/形状/类型/值/序列/随机"选，牢记 float32、int64 两个默认与 .to(device) 的显式搬运。**
