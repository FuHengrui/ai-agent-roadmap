@@point ① 决策树的特点：像人一样做判断
@@need 要解决什么
决策树凭什么"解释性好"？先建立心智模型：它的预测过程就是人类做决策的过程。

@@idea 核心思路
**决策树决策过程**：从根节点开始，每个内部节点是一个"特征提问"（如"年龄≥30 吗？"），按答案分叉到子节点，重复直到叶子节点给出结论（类别或数值）。
举例（贷款审批）：是否稳定工作？→ 是 → 月收入≥1万？→ 是 → 批准。这就是一棵树。

特点盘点（要点精髓）：
- **决策过程接近人的思维习惯**：问"如果…就…"，天然可解释。
- **比线性模型解释性更强**：线性回归的参数 w 要人解读，树是"人能复述的规则"。
- **能图形化展示**：画出来就是树状图，非技术人员也能懂。
- **处理离散/类别特征容易**：无需哑变量编码的"数值化"思维，直接按取值分叉。
- **几乎不需要归一化**：树只用"比较大小"（≥某阈值），不涉及距离，量纲无碍。

**知识卡片**：决策树的数学表达——每个节点是一个条件（特征维度 j 与阈值 t），样本按"x_j < t / ≥ t"分派；整个树是一族 if-else 规则的嵌套。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 决策树输出是类别，别用「距离」类指标评估 | 分类树看准确率/混淆矩阵；回归树看 MSE/RMSE——先分清任务再选指标 |
| 认为树"不用预处理"就啥都不做 | 归一化确实可省，但缺失值、类别编码仍要处理；别把"免归一化"夸大成"免全部预处理" |

@@point ② 分裂指标之一：Gini 不纯度
@@need 要解决什么
树分裂时要选"问哪个特征、卡什么阈值"最好。用什么数字衡量"这次分裂值不值"？第一个答案：**Gini 不纯度**。

@@idea 核心思路
**Gini 不纯度**衡量一个节点内"类别的混乱程度"：
```
Gini = 1 - Σ_k p_k²
```
- p_k：节点内第 k 类的占比。
- **Gini = 0**：节点内全是同一类（最纯，无需再分）。
- **Gini 越大**：类别越混杂（接近均匀分布时最大）。

分裂策略：对候选切分，比较**切分前父节点 Gini** 与**切分后子节点 Gini 的加权平均**，选**下降最大**的那个特征+阈值：
```
Gini 下降 = 父Gini - Σ (n_child/n_parent) · 子Gini
```
sklearn 的 `DecisionTreeClassifier(criterion='gini')` 正是此口径（默认）。

直观：Gini 就是"我从这个节点随便抽一个样本，猜错类别的概率"——越小越纯。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 把 Gini 和准确率混为一谈 | Gini 是"节点内纯度"（0~1 之间），准确率是"整树预测对的比例"，完全是两码事 |
| 选切分只看"子节点最纯"不看下降量 | 选切分看的是**下降量**（父比子的改善），不是子节点绝对值 |

@@point ③ 分裂指标之二：信息熵与信息增益
@@need 要解决什么
除了 Gini，另一套经典指标来自信息论：**信息熵 + 信息增益**。它与 Gini 是什么关系？

@@idea 核心思路
**信息熵（Entropy）**：衡量系统的"不确定性"：
```
H = -Σ p_k · log2(p_k)
```
- 全同一类 → H=0（确定性最高）；类别均匀 → H 最大（最不确定）。
- **信息增益（Information Gain, IG）**：分裂后熵的下降量：
```
IG = H(父) - Σ (n_child/n_parent) · H(子)
```
- **IG 越大 = 这次分裂让"不确定性"减少得越多 = 越值得分**。

Gini vs 熵的工程现实：两者选出的分裂**高度相似**，sklearn 默认 gini（计算更快）；教学上信息熵更能解释"信息增益"的概念来源。**记住它们都是"越纯越好"的度量器即可**。

**代码速览**：
```python
from sklearn.tree import DecisionTreeClassifier
clf = DecisionTreeClassifier(criterion='entropy', max_depth=3)  # 或 'gini'
clf.fit(X_train, y_train)
```

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为 entropy 一定比 gini 准 | 实测差距很小；gini 更快是 sklearn 默认的原因；不必纠结 |
| 把信息增益与信息熵记反 | 熵是"当前不确定性"，增益是"分裂后减掉了多少不确定性"；增益=父熵-加权子熵 |

@@point ④ 经典算法三兄弟：ID3、C4.5、CART
@@need 要解决什么
"经典决策树算法"到底是哪个？——是三个演进版本。理清各自的改进点，树模型的历史就通了。

@@idea 核心思路
| 算法 | 年份/作者 | 分裂准则 | 关键升级 |
|---|---|---|---|
| ID3 | 1986 Quinlan | 信息增益 | 开山之作；**偏向取值多的属性**（ID 号特征增益总是最大，坑） |
| C4.5 | 1993 Quinlan | 信息增益率 | 引入**分裂信息**惩罚取值多的属性，修正偏好；支持连续属性二分、缺失值、剪枝 |
| CART | 1984 | Gini（分类）/MSE（回归） | 满二叉树（每次只分两支），分类回归通吃——**sklearn 用的就是 CART** |

两个教科书级知识点：
- **ID3 的偏好多值特征**：属性值越多，切得越细、熵降得越多 → 增益虚高。身份证号当特征能"完美切分"，但全是过拟合。
- **C4.5 的信息增益率**：给增益除以"分裂信息"（衡量该属性分裂的广度/均匀性）——惩罚多值属性。连续属性处理：排序后取相邻值中点当候选阈值。

**现状**：工程上 ID3/C4.5 基本被 CART 取代（sklearn 的 DecisionTree* 是 CART 实现），但理解演进史对读论文/面试极有价值。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 把"ID3 用信息增益、C4.5 用增益率"记反 | 时间线记：ID3 先犯"多值偏好"的错，C4.5 针对它修——修的就是增益率 |
| 在 sklearn 里找"ID3/C4.5 参数" | sklearn 只实现 CART（criterion 只有 gini/entropy 供分类选），别找不存在的选项 |

@@point ⑤ 何时停止分裂：全生长 vs 剪枝
@@need 要解决什么
树能无限分下去直到每个叶子只有一个样本——那时"训练集完美"，但真会这样吗？

@@idea 核心思路
**无限生长的后果（fully grown tree）**：
- 每个叶子都能分到"最纯"（甚至单样本），训练误差趋近 0。
- 但模型**背下了训练集**——测试集严重过拟合（训练好、测试差）。

**剪枝（Pruning）**：给树"减肥"，是治理决策树过拟合的有效方法。两大策略：
1. **前剪枝/预剪枝（pre-pruning）**：构建过程**提前停止**——把切分条件设严（限制最大深度 max_depth、最小样本数 min_samples_split、最小不纯度下降），树还没长茂就收住。**代价小、最常用，sklearn 直接给参数**。
2. **后剪枝（post-pruning）**：树**先长满再修剪**——从底层剪掉对验证集没有提升的分支。常见三种：REP（错误率降低）、PEP（悲观剪枝，C4.5）、CCP（代价复杂度剪枝，CART）。

**CCP 一句话图解**：为每棵子树定义"代价（被剪掉而增加的错分样本）与复杂度（剪掉减少的叶子数）"，用 α 权衡；对每个非叶节点算 α，循环剪掉最小 α 的子树，得到一串候选树，再用验证误差挑最好的。（sklearn 的 `ccp_alpha` 参数对应。）

**工程结论**：预剪枝（调 max_depth 等）是日常首选；后剪枝更精细但复杂，Alpha 由 `DecisionTreeClassifier(ccp_alpha=...)` 暴露。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| max_depth 不设，树疯长 | 默认不限制；**必须先设 max_depth**（3~10 常见起步），否则默认必然过拟合 |
| 以为剪枝一定提升准确率 | 剪枝也许会让训练精度略降，但"泛化"提升才是目的；评估看测试集 |
| min_samples_split/min_samples_leaf 混用 | leaf 是"叶子最少样本"（更狠），split 是"内部点最少样本"；先调 leaf 更直观 |

@@point ⑥ 决策树的优缺点平衡
@@need 要解决什么
学完主流内容，决策树的"全面体检表"是什么？它为什么"单打独斗"一般，下一章又为什么"组团出道"？

@@idea 核心思路
**优点**：
1. 决策过程接近人的思维习惯（可解释的天花板）。
2. 模型容易解释，比线性模型解释性更好。
3. 能图形化描述（plot_tree 直接出图）。
4. 处理定性（类别）特征容易。

**缺点**：
1. **单棵准确率一般不如其他模型**——这正是集成学习（下章）出现的理由。
2. **不支持在线学习**：新样本来了要整树重建（不像 SGD 能增量更新）。
3. **容易过拟合**：不剪枝就疯长。

**一句话定位**：决策树单打是"解释之王、精度平平"，但它是集成学习的**基础构件**——随机森林、GBDT 都是"用大量决策树投票/求和"。下一章的舞台就是"那么多树怎么组团"。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 树模型精度不行就判死刑 | 跟上集成学习再判；单树打不过集成模型是常态，不是树本身没用 |
| 在线学习场景还用决策树 | 数据流式到达请绕道 SGD/增量模型；树的场景是"训练集固定" |

@@point ⑦ 分类树的评估与可视化
@@need 要解决什么
决策树怎么"验收"？除了准确率，树有独门验收手段：**把树画出来人眼审查**。

@@idea 核心思路
```python
from sklearn.tree import DecisionTreeClassifier, plot_tree
import matplotlib.pyplot as plt

clf = DecisionTreeClassifier(max_depth=3, random_state=42).fit(X_train, y_train)
print(clf.score(X_test, y_test))            # 测试集准确率

plt.figure(figsize=(14, 6))
plot_tree(clf, feature_names=feature_names,
          class_names=class_names, filled=True)   # 彩色树图
plt.show()
```
验收三看：
1. **准确率**：测试集 score（老规矩，测试集成绩说话）。
2. **树图**：看分支有没有"明显违背常识"的提问（树是黑盒的天敌：能看出模型逻辑）。
3. **特征重要性** `clf.feature_importances_`：哪些特征被用在靠近根的位置 → 重要度高。这也是树的隐藏福利——**免费的特征筛选器**。

回归树同理 `DecisionTreeRegressor(criterion='squared_error')`（sklearn 1.0 起取代了旧的 `'mse'`，新版本写 `mse` 会报错），评价用 RMSE，不展开。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 树图太大画成「一团黑」 | max_depth 限制 3~5 再画；或只画部分分支展示 |
| 只看准确率不看树图 | 树的核心价值是解释性；画图审查"模型在想什么"才算完整验收 |

@@point ⑧ 代码实战：鸢尾花分类与第一视角过拟合演示
@@need 要解决什么
上代码跑一次完整闭环：不同 max_depth 下，训练/测试准确率怎么变？直接目击"过拟合"长什么样。

@@idea 核心思路
```python
from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier
import matplotlib.pyplot as plt

iris = load_iris()
X_train, X_test, y_train, y_test = train_test_split(
    iris.data, iris.target, random_state=42)

train_acc, test_acc = [], []
for depth in range(1, 11):                 # 深度 1~10 扫描
    clf = DecisionTreeClassifier(max_depth=depth, random_state=42)
    clf.fit(X_train, y_train)
    train_acc.append(clf.score(X_train, y_train))
    test_acc.append(clf.score(X_test, y_test))

plt.plot(range(1, 11), train_acc, 'o-', label='train')
plt.plot(range(1, 11), test_acc, 's-', label='test')
plt.xlabel("max_depth"); plt.ylabel("accuracy")
plt.legend(); plt.show()
```
预期画面：
- 训练准确率随深度单调上升（往 1 逼近）。
- 测试准确率先升后降（比如 depth=3 附近最高，depth 增大后 **测试不升反降**）。
- 交叉点右侧就是**过拟合区**——深度再大只是"背答案"。

这就是"深度 → 复杂度 → 过拟合"的第一手证据；最佳深度在"测试曲线峰值"处。**再往后，这个扫描套路会被"网格搜索+交叉验证"自动化**（笔试题里常出现）。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 只扫一次 `max_depth` 就定稿 | 参数不止深度（min_samples_leaf、ccp_alpha 等）；小数据集组合搜一下更稳 |
| 用测试集反复试深度直到"最好" | 反复看测试集=测试集泄漏成训练集；严谨做法：验证集/交叉验证选参，测试集只碰一次 |

@@point ⑨ 决策树完整知识闭环
@@need 要解决什么
整棵"树"的知识装订成册：从提问到剪枝到实战，把记忆锚点串起来。

@@idea 核心思路
一条主线（背下来）：**"树 = 一串 if-else；分裂靠 Gini/熵选'切得最纯'的特征；经典三兄弟 ID3→C4.5→CART 演化就是修'多值偏好'+支持连续+满二叉树；树不控制就疯长过拟合，所以预剪枝（max_depth）或后剪枝（CCP）保命；单树知道自己在问什么（可解释），但精度一般还拒绝在线学习——接下来靠集成学习翻盘。"**

关键参数速查（sklearn DecisionTree*）：
| 参数 | 作用 | 常见值 |
|---|---|---|
| criterion | **分类树**：gini / entropy / log_loss；**回归树**另见下 | gini（默认） |
| criterion（回归） | squared_error / absolute_error / friedman_mse / poisson；旧的 `'mse'` 已删除，写它会报错 | squared_error |
| max_depth | 预剪枝：最大深度 | 3~10 起步 |
| min_samples_leaf | 叶子最少样本数 | 1~20 |
| min_samples_split | 内部分裂最少样本 | 2~20 |
| ccp_alpha | 后剪枝代价复杂度 | 0（默认无），可小步尝试 |

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 参数一把抓全调 | 先 max_depth/min_samples_leaf 起步，够用即止；参数越多越易过拟合验证集 |
| 树的知识学完就扔 | 它是随机森林/GBDT 的砖头——下一章所有算法都建立在"一棵树"之上，别断层 |

@@summary
决策树章节收官：

| 问题 | 答案 |
|---|---|
| 决策树是什么 | 一串 if-else 提问：问特征 → 分叉 → 叶子给结论 |

| 过拟合 | 树无限生长=背答案；预剪枝（max_depth）/后剪枝（CCP）治理 |
| 缺点 | 单树精度一般、不支持在线学习、易过拟合 |
