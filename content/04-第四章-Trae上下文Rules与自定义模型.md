@@why 这一章在解决什么问题
**你用 Chat 提问、用 Builder 建项目，但 AI 偶尔答非所问：它"看不到"你的代码、你的终端、你的项目结构，只能靠你一句句喂。** 这是 AI 编程工具最大的使用门槛——**上下文（Context）怎么给**。给对了，AI 像你肚子里的蛔虫；给错了，AI 就是在盲人摸象。

**这一章还解决第二个问题：AI 的"口味"怎么定。** 你希望它输出中文注释、用你熟悉的风格、不碰某些 API？这些偏好可以用 **Rules（规则）** 固化下来；你甚至可以把**自定义模型**（比如你自己的 API Key 接的模型）接进 Trae，让模型选择更多元。

@@point ① 为什么 AI 需要"指定上下文"
@@need 要解决什么
你不说清楚"看哪里"，AI 就只能猜。指定上下文是让 AI 回答精准的第一步。

@@idea 核心思路
与 AI 助手对话时，你可以**指定 Trae 中的内容（包括代码、文件、文件夹、工作空间）作为上下文**供 AI 助手阅读和理解，从而确保 AI 的答复更符合你的要求。

为什么重要？因为模型本身"看不见"你的磁盘。默认情况下，AI 只能依赖你输入框里的文字；你**指定**哪些内容给它看，它才知道针对什么作答。上下文越精准，回答越贴合；上下文给错，回答就跑偏。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 问项目相关问题时 AI 答得泛泛 | 没指定上下文，AI 在"瞎猜"；把相关文件/文件夹加进对话 |
| 一次塞太多无关文件 | 上下文占用 token 且引入噪声；只给和问题相关的部分 |
| 以为 AI 自动能看到全部代码 | 除了"当前打开的编辑器文件"默认可见，其他都要显式指定（第 ②-⑤ 点） |

@@point ② 方式一/二：编辑器内容与终端内容
@@need 要解决什么
最自然的两种上下文：正在编辑的代码、刚跑完的终端输出。怎么"选中即加入对话"？

@@idea 核心思路
**方式一：将编辑器内的内容作为上下文**

当编辑器中存在正在编辑的代码文件时，AI 助手默认能看到当前文件，可直接提问当前文件相关的问题。若只想针对文件中某一段代码提问：

1. 选中代码；
2. 点击悬浮菜单中的**添加到对话**按钮，将选中内容加入侧边对话框。

**方式二：将终端中的内容作为上下文**

若希望对终端输出的内容提问（如帮助修复报错）：

1. 在终端中，点击输出内容片段；
2. 在内容片段区域右上角，点击**添加到对话**按钮。

指定的上下文会显示在侧边对话底部的输入框，并标注上下文来源及行号（如 `demo.py:15`），一眼可知"AI 正在看哪里"。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 选中代码但没看到"添加到对话" | 悬浮菜单需鼠标停留触发；确保选中的是有效代码区域 |
| 终端报错太长懒得选 | 全选关键报错几行即可；给 AI 完整堆栈太长反而稀释重点 |
| 上下文来源行号显示乱 | 文件被改动导致行号偏移；重新添加一次上下文 |

@@point ③ 方式三：# 键添加上下文的核心用法
@@need 要解决什么
除了选中的方式，还有更标准的做法：在输入框里用 **#** 符号直接引用代码、文件、文件夹、工作区、网页。这是 Trae 上下文系统的"主入口"。

@@idea 核心思路
在侧边对话的输入框中，你可以通过 **#** 符号添加多种类上下文，包括代码、文件、文件夹和工作区。通常列表会展示与当前编辑文件相关的推荐内容，也可以自行搜索添加；**可以组合添加多种来源**（例如同时添加代码和文件）。

在输入框输入 `#` 后出现的候选类型：

| 类型 | 写法 | 作用 |
|---|---|---|
| 代码 | `#Code` | 把函数/类的相关代码作为上下文；列表默认展示当前编辑器打开文件中的函数或类，可预览、可搜索 |
| 文件 | `#File` | 把指定文件全部内容加入上下文；列表默认展示近期打开过的文件，注意同名文件的目录区分 |
| 文件夹 | `#Folder` | 把指定文件夹中所有内容作为上下文 |
| 工作区 | `#Workspace` | 提出有关整个工作空间的问题，AI 自动查找最相关内容回答——**接手陌生项目首选** |
| 网页 | `#Web` | 把线上网站内容作为上下文；在 `#Web` 后直接输入问题，触发联网搜索回答 |

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 输入 # 没弹出候选 | 部分输入法抢占按键；切英文输入，或先点选文件树再问 |
| #Code 里找不到想要的函数 | 列表只展示当前打开文件的函数/类；先用关键词搜索，或在文件里选中后"添加到对话" |
| 同名文件选错 | #File 列表展示目录以便区分；选前看路径后缀确认 |
| #Workspace 回答慢 | 它要在全工作区检索，项目大时耗时正常；可改用 #Folder 收窄范围 |
| #Web 联网失败 | 需要网络权限；确认联网正常，或手动把网页内容复制进对话 |

@@point ④ 忽略文件：哪些内容 AI 不该看
@@need 要解决什么
项目里不是所有东西都适合喂给 AI——日志、生成目录、密钥文件、node_modules。Trae 提供"忽略"机制。

@@idea 核心思路
Trae IDE **默认忽略 `.gitignore` 文件中罗列的文件**。除此之外，你可以**自主设置 Trae 额外忽略的文件列表**，作为 `.gitignore` 的补充。

使用 `#Workspace` 或 `#Folder` 添加上下文时，**被忽略的文件或文件夹将无法被作为上下文**——这既保护隐私（比如 `.env` 密钥文件），也减少噪声（比如构建产物）。

`.ignore` 文件示例（这是 Trae 自身配置，不是某个特定项目里的文件）：

```text
/**foo: 忽略 /foo, a/foo, a/b/foo 等
config.js: 忽略当前路径的 config.js 文件
/mtk/: 忽略整个文件夹
*.zip: 忽略所有 zip 文件
/list
```

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 把密钥文件喂给 AI 了 | 敏感文件（.env、token 文件）务必写进忽略规则，别指望 AI"自觉不看" |
| 忽略写错语法、误伤源码 | 先小范围测试语法（如 `*.log` 只忽略日志）；谨慎使用通配符/绝对路径忽略 |
| 改了忽略规则不生效 | 新规则对已开对话需重新添加上下文；必要时重启 Trae |

@@point ⑤ 什么是 Rules：给 AI 立规矩
@@need 要解决什么
AI 默认"千人一面"：你希望它简洁、它啰嗦；你希望中文注释、它写英文。Rules 就是给 AI 定制行为规范的机制。

@@idea 核心思路
Rules 是一项强大的**代码规范管理工具**，允许团队或开发者**自定义并强制执行代码风格和最佳实践**。分两个层级：

**个人规则**：基于个人使用习惯为 AI 定制的规则，**在所有项目中生效**。可配置维度包括：

- **语言风格**：偏好简洁/严谨/幽默等表达方式；
- **操作系统**：提供针对 Windows 或 macOS 的回答；
- **内容深度**：是否需要详细解释、示例或仅需结论；
- **交互方式**：倾向于直接答案，还是引导式提问。

**项目规则**：针对当前项目 AI 需遵循的规则，**仅在所配置的项目中生效**。可配置维度包括：

- **代码风格**：缩进（空格/制表符）、命名规范（驼峰式/snake_case）等；
- **语言与框架**：优先使用的编程语言（如 Python/JavaScript）或框架（如 React/Django）；
- **API 限定**：勿使用某些 API。

一句话：**个人规则管"你这个人"（全局），项目规则管"这个项目"（局部），两者叠加生效。**

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 个人规则写了一大堆互相矛盾 | 规则要短而准；冲突时 AI 可能随机取舍。定期精简 |
| 以为项目规则全局生效 | 项目规则只在配置的项目里生效，换项目就失效——这正是设计意图 |
| 规则全写"不要做什么"没写"要做什么" | 正面+负面规则结合效果更好（示例见第 ⑥ 点） |

@@point ⑥ Rules 实战案例：用提示词规范 Chakra UI 开发
@@need 要解决什么
规则到底长什么样？先看一个实战案例——用 Chat 优化 CSS，通过提示词配置项目规则和个人规则。

@@idea 核心思路
假设我们要使用 **Chakra UI** 来优化 CSS，可以通过提示词配置规则。一份高质量的项目规则示例：

```text
你是一位精通 React 和 Chakra UI 的前端开发专家。

## 核心原则
- 编写清晰、简洁且技术性强的回答，并提供精确的 Chakra UI 示例。
- 利用 Chakra UI 的组件和工具类提升开发效率并确保响应式设计。
- 注重代码的可维护性和可读性，遵循简洁规范的 HTML 与 CSS 编码实践。
- 使用具有描述性的类名和结构，提升代码清晰度，方便团队协作。

## Chakra 使用规范
- 通过 Chakra UI 实现合理的组件组合结构
- 使用 Chakra UI 内置的无障碍功能
- 利用 Chakra UI 的颜色模式实现暗黑模式
- 在应用的根组件使用 ChakraProvider
- 使用 Chakra UI 的断点系统实现响应式样式
- 使用 Chakra UI 的 Hooks 提升功能性

## 其他约定
- 请始终保持对话语言为中文
- 请在生成或编辑代码时补充详细的注释
- 在回答用户问题时，请详细解释每一步改动的原因
```

可以看到好规则的共性：**角色设定 + 分节规范 + 明确要求（语言/注释/解释），全是可执行的指令，不是空话。**

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 规则太长 AI 反而忽略 | 规则要在"信息量"和"可执行性"间平衡，太长容易被稀释 |
| 抄案例时带上无关框架描述 | 你的项目用什么技术栈，规则就写什么；照抄 React 规则到 Vue 项目会误导 AI |
| 规则里写了具体版本号/废弃 API | 规则要跟随项目演变，定期更新（新库、新规范）|

@@point ⑦ 神级提示词网站：站在巨人肩膀上
@@need 要解决什么
自己写规则费劲，网上有没有现成的"神级提示词"库可以直接抄？

@@idea 核心思路
有一个值得推荐的提示词资源站：**CursorRulesCN**（神级提示词网站）：https://www.cursorrulescn.cn/

该站收集了大量针对不同技术栈（React、Vue、Node、Python 等）的优质规则提示词，可以：

- **直接参考**：找到匹配你技术栈的规则模板，改改就能用；
- **学习写法**：看别人怎么把"角色+规范+约束"组织成清晰结构；
- **覆盖常见组合**：Chakra UI、Tailwind、Next.js 等热门组合都有现成配方。

注意它虽然叫 CursorRules，规则写法在 Trae、Cursor 等 AI 编程工具间是通用的（都是给 AI 立规矩）。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 照搬神级提示词不修改 | 别人的规则含特定技术栈假设，直接套用可能水土不服；按自己的项目裁剪 |
| 相信"神级=万能" | 提示词是辅助不是魔法；复杂项目仍需你理解架构与业务 |
| 只看一个站 | 神级提示词站有好几个，多看多对比；本站是重点推荐，先从这里开始 |

@@point ⑧ 多模态输入回顾：图片也是上下文的一部分
@@need 要解决什么
上一章 Builder 讲过多模态建项目，这里从"上下文"角度再收拢一层：图片是上下文的一种。

@@idea 核心思路
你可以在会话中添加图片——报错截图、设计稿、参考样式——从而更加准确高效地表达需求。

在上下文体系里，图片和代码、文件一样，都属于"喂给 AI 的输入材料"。**能传图的时候别只打字**：一张报错截图往往比贴十行描述更准；一张设计稿比"大气一点、高级一点"强一万倍。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 图片里的隐私信息（密钥、手机号）被 AI 看到 | 发图前打码！报错截图先遮掉路径/账号等敏感字段再发 |
| AI 读图描述偏差 | 图+文字的定位（"图中红框处报错"）能大幅提升准确率 |

@@point ⑨ 切换模型：内置模型随便换
@@need 要解决什么
Trae 预置了一批知名模型，怎么在对话中切换？不同模型能力差异在哪？

@@idea 核心思路
Trae 预置了一系列**业内表现比较出色的模型**，可直接切换使用：

- 在 AI 对话输入框的右下角，点击当前模型名称，打开模型列表；
- 选择你想使用的模型；
- 各模型能力不同，鼠标**悬浮至模型名称**上可查看该模型支持的能力。

实际操作中：日常开发默认模型即可；涉及**大长文本处理、复杂推理、多模态**等专项需求，切换到擅长对应能力的模型。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 换模型后回答风格突变 | 正常，不同模型表达风格不同；按任务选模型即可 |
| 想要的模型不在预置列表 | 用自定义模型接入（第 ⑪ 点），或等 Trae 更新预置列表 |

@@point ⑩ 模型排行榜：怎么判断哪个模型强
@@need 要解决什么
预置模型那么多，选哪个看什么？下面是一份基于"实际应用场景"的排行榜参考。

@@idea 核心思路
基于实际应用场景的模型能力参考：

| 名次 | 模型 | 上下文能力 | 适合场景 |
|---|---|---|---|
| 🏆 | Gemini 2.5 Pro | 200 万 token | 处理整部小说/技术文档、分析多个竞品完整产品文档、大型数据集综合分析 |
| 🥈 | GPT-4.1 | 100 万 token | 分析完整代码库、长篇研究报告、多轮复杂对话保持上下文 |
| 🥉 | Claude 4 | 20 万 token | 单个大型文档分析、复杂代码项目理解、深度技术文档生成 |

选择逻辑很清晰：**上下文（token）越大，越适合"吃下大输入"的任务；场景越复杂（代码库、长文档），越值得用高端模型。**

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 迷信 200 万 token 就一直用 | token 大有代价（更贵/更慢）；小任务用轻量模型更快更省 |
| 忽略场景匹配 | 排行榜是"参考"不是"军规"；写个小脚本用大模型纯属浪费 |
| 上下文数字记混 | 复习表内三个梯度：Gemini 200 万、GPT-4.1 100 万、Claude 4 20 万 |

@@point ⑪ 添加自定义模型：用 API Key 接入自己的模型
@@need 要解决什么
预置模型不满足需求怎么办？想用别的模型、或用自己的模型资源——Trae 支持接入自定义模型。

@@idea 核心思路
通过 **API 密钥（API Key）** 可以连接你自己的模型资源或第三方模型服务商。添加步骤：

1. 在 AI 对话框右上角，点击**设置**图标 > **模型**，打开模型窗口；
2. 点击 **+ 添加模型**，打开添加模型窗口；
3. 选择**服务商**，可选项有：Anthropic、DeepSeek、OpenRouter、火山引擎、硅基流动、阿里云、腾讯云、模力方舟、BytePlus、Gemini 等；
4. 选择**模型**：
   - 直接从列表选择 Trae 为该服务商预置的模型（默认版本）；
   - 或用其他模型/特定版本：点**使用其他模型**，填写模型 ID；
5. 填写 **API 密钥**（可点"获取 API 密钥"跳到对应服务商配置页）；
6. 点击**添加模型**，Trae 会调用服务商接口检测密钥有效性：
   - 连接成功 → 模型被添加；
   - 连接失败 → 显示错误信息和服务商返回的错误日志，据此排查。

添加后可管理：**编辑**（修改服务商/模型/密钥）、**删除**（二次确认后移除）、**启用/禁用**（禁用的模型保留在设置里、不出现在选择列表）。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 密钥填错连不上 | 对照错误日志排查；注意密钥前后空格、是否复制完整 |
| 密钥泄露风险 | API 密钥=钱！**不要把密钥写进代码/规则/对话发给 AI**；妥善保管在服务商控制台 |
| 服务商列表没你想要的 | 列表覆盖主流服务商；个别冷门服务商可先确认是否支持 OpenAI 兼容协议 |
| 禁用后找不到模型 | 禁用不等于删除：模型保留在设置页，启用即可恢复 |
