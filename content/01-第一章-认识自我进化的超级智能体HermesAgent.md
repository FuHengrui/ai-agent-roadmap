@@point ① 一个会进化的伙伴：Hermes Agent 是什么

@@idea 核心思路

| | 普通 AI 工具 | Hermes Agent |

@@point ② 核心定位：An agent that grows with you
@@need 要解决什么
市面上所有 AI 工具都在宣传"强、快、准"，但没一个回答"**它会不会越用越懂我**"。你需要一个明确的定位判断：这个工具到底把"成长"放在多高的优先级。

@@idea 核心思路
Hermes Agent 的核心定位就一句话：**"An agent that grows with you"（与你共同成长的 Agent）**，它最大的特点就是**可自进化**。

翻译成用户能感知的行为，就是三件事：

- **部署在你的服务器上**——程序和数据的所有权在你手里，不依赖厂商云端；
- **连接你的消息账号**——微信、QQ、飞书等里多一个"AI 联系人"，聊天即指令；
- **成为你的持久个人智能体**——它学习你的项目、自动构建技能、随时随地触达你。

它强调的不是"一次性帮你完成某件事"，而是"**长期陪你、越陪越懂你**"。"成长"不是宣传口号，而是后面每一章都会兑现的机制：记忆（第 8 章）、技能（第 7 章）、个性化（第 5 章）。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为"成长"只是个概念、没法验证 | 可验证：第 7 章看它自动生成 Skill、第 8 章看 MEMORY.md 里积累的条目——都有文件实锤 |
| 以为"陪你成长"= 必须云端账号 | 恰好相反，它部署在你**自己的服务器**，成长数据留在自己手里 |
| 以为装完就自动懂你 | "成长"需要**使用过程**：你用得越多、聊得越深，记忆和技能越厚。裸装不聊天它也长不大 |

@@point ③ 金鱼记忆 vs 会进化的伙伴：它赢在哪
@@need 要解决什么
市面上的 AI 工具用起来总有种"失忆感"：上午教它的约定，下午它就忘；昨天让它学会的流程，今天就归零。你想知道：Hermes Agent 到底靠什么摆脱这种"金鱼记忆"。

@@idea 核心思路
普通 AI 工具和 Hermes Agent 的差距可以浓缩成一句话：**别的 AI 工具是"金鱼记忆"，Hermes Agent 是"会进化的伙伴"**。两者的本质差异在三个层面：

| 层面 | 金鱼记忆的 AI | 会进化的 Hermes Agent |
|---|---|---|
| 记忆 | 会话结束就清空 | 跨会话持久化，且在系统提示词中注入（第 8 章） |
| 技能 | 要什么功能都得重新指定 | 从交互中自动沉淀为 Skill（第 7 章） |
| 使用体验 | 每次都是"新员工" | 越来越像"老搭档" |

"金鱼记忆"不是骂人，是事实描述：对话模型的上下文窗口本来就是一次性的。Hermes Agent 的解法是**把该记的写到磁盘文件里**（MEMORY.md / USER.md / skills/ ），会话开始时再读回来——用工程手段对抗模型失忆。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为"记忆"是模型自带的能力 | 模型本身没有跨会话记忆，Hermes 是靠**文件持久化 + 会话注入**实现的，这是它的工程亮点不是模型属性 |
| 以为记忆=无限上下文随便存 | 记忆有**字符上限**（第 8 章：MEMORY 约 800 tokens / USER 约 500 tokens），存满会自动合并腾空间——是"精选记忆"，不是"倾倒式存储" |
| 以为有了记忆就能跨会话无缝衔接 | 记忆是"冻结快照"注入，只能覆盖该记的事；一次性的项目指令、临时路径它**刻意不存**，别指望它记住所有细节 |

@@point ④ 不是聊天机器人，不是代码补全工具
@@need 要解决什么
网上对 AI Agent 的称呼五花八门，容易把 Hermes Agent 和 ChatGPT、代码补全插件混为一谈。需要先划清边界：它到底是什么、不是什么。

@@idea 核心思路
先排除两个误认：**"不是聊天机器人，不是代码补全工具"**，而是一个"住在你机器上、每天都在变聪明的智能体"。

把它和三类产品放一起对比：

| 产品类型 | 在干嘛 | 谁来干活 |
|---|---|---|
| 聊天机器人（ChatGPT 等） | 生成回答 | 模型单方面输出 |
| 代码补全工具（Copilot 等） | 补全光标处的代码 | 模型+编辑器 |
| Hermes Agent | 部署、接入消息、跨会话记忆、自动建技能、动手干活 | 模型+框架的"手脚+记忆+技能" |

它和"聊天机器人"最本质的差别是**有没有手脚和长期记忆**；和"代码补全工具"最本质的差别是**服务对象不是编辑器，而是整个你**——你的项目、你的账号、你的日常。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为"能聊天 = 会做事 = 会进化" | 三层递进：聊天（模型能力）→ 做事（工具+操作）→ 进化（记忆+技能沉淀）。Hermes 是第三层 |
| 以为它只是"给程序员用的" | 交互层是聊天软件，人人可用；编程能力只作用于"扩展功能"环节 |
| 拿它和代码补全工具比"补全准不准" | 比错了维度：它比的是"能不能长期替你干活并越干越好" |

@@point ⑤ 核心创新：内置自学习循环
@@need 要解决什么
前面说它"会进化"，但"进化"到底是营销话术还是真实机制？需要看到具体的循环链路，才能判断这个产品到底值不值得投入。

@@idea 核心思路
Hermes Agent 的核心创新是：**它不是简单地调用 LLM，而是通过内置的学习循环不断优化自身**。这个循环拆开看是四步：

| 环节 | 内容 | 对应章节 |
|---|---|---|
| 自动生成 Skill（技能） | 从交互中沉淀可复用能力 | 第 7 章 |
| 持续迭代技能 | 使用中不断改进已有技能 | 第 7 章 |
| 主动持久化知识和用户偏好 | 把"该记的事"写进记忆文件 | 第 8 章 |
| 跨会话构建对用户的深度理解 | 每次会话都用上之前积累 | 第 5、7、8 章 |

这就是"成长"的完整链路：**用 → 沉淀 → 复用 → 更懂你**。普通 Agent 是"每次从零开始干"，Hermes 是"干一次、进步一次"。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为"自动生成技能"= 用户不用写任何技能 | 自动沉淀针对的是复用性强的行为；复杂的专业技能仍可手工编写（第 7 章会演示手写天气 Skill） |
| 以为学习循环是实时的 | 它是**使用驱动**的：沉淀发生在任务执行过程中，不是装完就自带 |
| 以为"自学习"=模型自己在后台偷偷变 | 学的都是你的项目、偏好、约定，且以文件形式可查可控，不涉及隐私上传到外部厂商 |

@@point ⑥ 它部署在哪里：你的服务器
@@need 要解决什么
"你的 AI 在哪儿跑"决定了数据的归属和可控性。想要一个能托付长期记忆和技能的智能体，部署位置是关键决策。

@@idea 核心思路
要强调：Hermes Agent **部署在你的服务器上**（个人电脑、云服务器皆可），这是"伙伴"定位的前提：

- **数据在自己手里**：记忆、技能、对话记录都存在你的机器（~/.hermes/ 下），不依赖厂商托管；
- **稳定在线**：部署在服务器（或常开设备）上，配合消息网关才能随时触达——你发微信它就能回；
- **长期积累**：只有"同一份安装在持续运行"，记忆和技能才能跨会话累积。

这也决定了它的运行平台要求：官方支持 **Linux、macOS 和 WSL2**；**原生 Windows 仍处于实验阶段**（第 2 章会专门讲 WSL2 安装）。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为必须买云服务器才能用 | 个人电脑装好、长期开着也行；想要"随时随地触达"体验才建议常驻服务器 |
| 以为装在 Windows 上直接双击就能跑 | 原生 Windows 实验性，务必走 WSL2，否则会遇到一堆兼容性问题（第 2 章详述） |
| 以为数据都在本地=绝对安全 | 本地不等于免密：接入各平台要管好 Token、配对审批、群聊白名单（第 3 章） |

@@point ⑦ 它连接什么：你的消息账号
@@need 要解决什么
既然要"随时随地触达你"，总不能每次打开终端才能指挥它。需要回答：日常交互入口是什么？

@@idea 核心思路
Hermes Agent 通过 **gateway（消息网关）** 连接你的消息账号：**微信、QQ、飞书**等，接入后你在聊天软件里就能直接指挥它，实现"**聊天即操作**"。

接入机制（第 3 章展开）：

- 执行 `hermes gateway setup` 进入配置向导；
- QQ、飞书扫码接入即可，微信额外需要一次**设备配对审批**；
- 接入时可以选择**授权策略**（推荐 DM 配对审批）和**群聊策略**（推荐禁用群聊或仅 @ 响应）。

这意味着你的智能体像"住在聊天软件里的联系人"：发消息下指令，收消息拿结果，全程不需要打开命令行。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为接入=无门槛放权 | 从扫码到配对审批、从 DM 策略到群聊白名单有很多安全选项，建议按官方推荐的默认选项走，别图省事全 Yes |
| 以为一个网关只能接一个平台 | 可同时接入多个平台，但**先跑通一个**再扩，别一上来全铺开 |
| 接入失败就怀疑安装有问题 | 微信/飞书有配对环节，漏了配对是接入失败最常见原因（第 3 章有完整命令） |

@@point ⑧ 它和你项目的边界：学习你的项目、自动构建技能
@@need 要解决什么
"帮你干活"和"学习你的项目"是两回事——前者按指令执行，后者需要理解项目结构、约定和环境。需要明确它如何"学习项目"。

@@idea 核心思路
把它的"项目学习"拆开看是两层能力：

- **学习你的项目**：通过读取文件、执行命令、观察工作流，把项目结构、技术栈、约定沉淀进记忆（MEMORY.md），下次不用重新解释；
- **自动构建技能**：当它发现"这个流程你反复在用"，就把它封装成 Skill（操作手册），复用不再重新摸索。

这两层配合"自学习循环"，就是"伙伴"式体验的来源：**第一次帮你干活是工作；第 N 次帮你干活是本能**。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为它会主动扫描你整个硬盘学习 | 它学的是**你让它干活过程中暴露的项目与约定**，不是后台翻你全部文件 |
| 以为"自动构建技能"一次就成型 | 技能会**持续迭代**：用得多、发现问题多，Skill 更新越快（原话是"在使用中持续迭代技能"） |
| 以为学习的内容不可控 | 学到的偏好进 USER.md、环境知识进 MEMORY.md，都是本地文件，可查可改 |

@@point ⑨ 和 OpenClaw 什么关系：功能类似，内核不同
@@need 要解决什么
阶段 14 刚学完 OpenClaw，现在又来一个"功能类似"的 Hermes Agent，两者到底怎么取舍？需要给出清晰的定位关系。

@@idea 核心思路
说法很直接：Hermes Agent"**功能类似于之前的 OpenClaw**"。两者同时满足"本地部署 + 消息驱动 + 动手做事"这类 Agent 框架共性。但内核定位不同：

| 维度 | OpenClaw（阶段 14） | Hermes Agent（阶段 15） |

简单说：**先学 OpenClaw 是为了建立"AI Agent 会做事"的整体认知；学 Hermes Agent 是看"AI Agent 如何自我进化"的更先进形态**。两者不冲突，是同一个演进脉络上的两站。

@@point ⑩ 你需要提前准备什么：Git 与平台
@@need 要解决什么
概念清楚了，就该问：要用它，我机器上得先有什么？避免装到一半发现缺这个缺那个。

@@idea 核心思路
准备清单非常克制：**唯一的前提条件是 Git**，其他组件（uv、Python 3.11、Node.js v22、ripgrep、ffmpeg）都由安装程序自动检测并安装。

- **Git**：下载 https://git-scm.com/ （中文页面）安装即可；
- **平台**：Linux / macOS 直接装；**Windows 需先装 WSL2**（管理员 PowerShell 跑 `wsl --install`）；
