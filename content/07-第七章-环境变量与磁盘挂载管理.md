@@why 这一章在解决什么问题
两台"看不见的系统"在幕后决定你的体验：**环境变量** 和 **磁盘挂载**。

- 为什么你敲 `java`、`mysql` 命令系统"认得"？因为 PATH 环境变量里存着命令的地址。很多人配 JAVA_HOME 时把 PATH 覆盖了，重启后连 ls 都找不到——这个坑后面装 JDK 必踩。
- 为什么新加一块硬盘，系统里根本"看不到"它？因为硬盘要经过**分区 → 格式化 → 挂载**三步才出现在目录树里，而且默认挂载重启就丢。不会配 fstab，重启一次数据目录就消失了。

这一章先讲环境变量（PATH、export、profile 文件、source），再完整走一遍"新硬盘从零到能用且重启不丢"的全流程（df/lsblk 查看、fdisk 分区、mkfs 格式化、mount 挂载、fstab 永久挂载）。配完这章，你才算真正"驯服"了这台机器。

@@point ① 环境变量：PATH 就是"命令的通讯录"
@@need 要解决什么
为什么敲 `ls`、`ps`、`java` 系统直接执行了？系统怎么知道这些命令在哪个目录？——全靠 PATH 这个环境变量。

@@idea 核心思路
**PATH 里存着一串目录路径**（冒号分隔）。你敲一个命令时，Shell 按顺序到这些目录里找同名文件，找到就执行：

```bash
echo $PATH
# 输出类似：/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/root/bin
echo $JAVA_HOME     # 没配过的话输出空行（变量不存在而已）
```

两个关键点：
- 查变量要加 `$`：`echo $PATH` 打印值，`echo PATH` 只打印字母 PATH；
- PATH 的顺序就是查找顺序，第 1 个目录里没有才找第 2 个。

自定义变量示例：

```bash
MY_NAME=dev
echo $MY_NAME       # 输出 dev
```

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| `echo PATH` 输出了个字母 PATH | 忘了 `$`；变量引用必须写 `$PATH` |
| 新装的命令敲名字找不到 | 它不在 PATH 列表里：要么把目录加进 PATH，要么敲全路径执行 |
| 变量赋值带空格报错（name = dev） | 赋值号两边**不能有空格**：写 `name=dev` |

@@point ② 系统级 vs 用户级：/etc/profile 和 ~/.profile
@@need 要解决什么
配 JAVA_HOME，是写给所有用户用，还是只给自己用？不同层面的配置放哪？

@@idea 核心思路
配置分两层：

| 层级 | 文件 | 生效对象 | 使用场景 |
|---|---|---|---|
| 系统级 | /etc/profile | 所有用户的登录环境 | JDK、全局 PATH 等公共配置 |
| 用户级 | ~/.profile（或 ~/.bash_profile） | 当前用户 | 个人别名、个人工具路径 |

注意：还有 /etc/environment 等辅助文件，但记住这两个主力就够日常用。

选择原则：**只给自己用的放用户级，动了不应影响别人的公共配置放系统级**。改系统级 = 影响全机器，动手前三思。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 在 /etc/profile 里乱加变量，其他用户环境全乱了 | 系统级配置影响所有人；个人偏好一律放 ~/.profile |
| 改了 ~/.profile 当前终端没效果 | 新配置只对**新登录的会话**生效（详见第 ③ 点的 source） |
| 分不清 ~/.profile 和 /etc/profile | 带 ~ 的是当前用户家目录下的（私人），带 /etc 的是系统的（公共） |

@@point ③ export 与 source：怎么让配置"活过来"
@@need 要解决什么
配好了变量，怎么让当前命令行立刻生效？export 和 source 分别是干什么的？

@@idea 核心思路
两件事分开记：

```bash
# ① export：把【当前 shell】里的变量传给子进程（临时生效）
export MY_NAME=dev
export JAVA_HOME=/usr/local/jdk
export PATH=$PATH:$JAVA_HOME/bin    # 追加而不是覆盖！
```

```bash
# ② source：重新执行一遍配置文件（让文件里的配置在当前会话生效）
source /etc/profile
# 等价简写：. /etc/profile
```

| 手段 | 生效范围 | 什么时候用 |
|---|---|---|
| export 直接敲 | 仅当前终端 | 临时测试 |
| 写入 profile + source | 当前终端立即 + 以后登录永久 | 正式安装（JDK 等） |

**最经典的坑**：配置 PATH 时不带 `$PATH`，直接 `export PATH=/opt/jdk/bin`——把原有目录全覆盖了，连 ls、vim 都找不到了。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| export PATH=/opt/jdk/bin 之后，ls、vim 全"command not found" | 覆盖了 PATH！恢复方法：`export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:$PATH` 或重开终端；**永远用 $PATH:追加** |
| 改了 /etc/profile 但当前终端没变化 | profile 只在登录时读；执行 `source /etc/profile` 让当前会话立即生效 |
| 新开一个终端配置又"没了" | export 只在当前 shell 有效；正式配置请写进 profile 文件，别只敲 export |

@@point ④ df：磁盘还剩多少
@@need 要解决什么
服务器跑着跑着报"磁盘空间不足"，怎么一眼看出哪个分区满了？

@@idea 核心思路

```bash
df -h          # -h 人性化单位（G/M）
df -T          # -T 显示文件系统类型（ext4、xfs…）
```

输出理解：每一行是一个文件系统（分区挂载点），重点看 **Use% 列**：

```
文件系统        大小  已用  可用  Use% 挂载点
/dev/sda1      50G   45G   2.4G   95% /
```

Use% 超过 90% 就要警惕了；空间找回来靠第 ⑥ 点的 find -size 定位大文件。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| df 显示 / 满了，但 ls 单目录看不大 | df 看的是"整个文件系统"的用量，不是当前目录；到 / 下用 du -x 或 find -size 找大头 |
| 想精确定位哪个目录最占空间 | df 给不了；用 `du -sh /要查目录` 逐级排查 |

@@point ⑤ lsblk：系统里有几块盘、几个分区
@@need 要解决什么
机器上到底有几块硬盘？每块盘分了几区？加的新盘为什么"看不到"？——lsblk 一览无余。

@@idea 核心思路

```bash
lsblk              # 树状显示所有块设备和分区
lsblk -f           # -f 额外显示文件系统类型和 UUID
```

输出长这样：

```
NAME   MAJ:MIN RM SIZE RO TYPE MOUNTPOINT
sda      8:0    0  20G  0 disk
├─sda1   8:1    0   1G  0 part /boot
└─sda2   8:2    0  19G  0 part /
sdb      8:16   0  20G  0 disk          ← 新盘：无分区，所以"看不到"
```

- **sda = 第一块盘，sdb = 第二块**（sda、sdb 的排号随时可能随插拔变化）；
- 磁盘下面挂着分区（sda1、sda2）和挂载点；
- 新加的盘 sdb 没有分区、没有挂载点，所以在文件系统里"隐身"——接下来 ⑥⑦⑧ 把它变出来。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 新盘在系统里看不到 | 它没有分区/文件系统/挂载点，df 自然不会显示；用 lsblk 确认它在 |
| 以为 sda/sdb 编号固定 | 编号是**探测顺序**，插拔可能变；关键场景（fstab，见第 ⑨ 点）用 UUID 而不是盘符 |

@@point ⑥ fdisk 分区：给新硬盘划地盘
@@need 要解决什么
sdb 还是一整块"白纸"，怎么把它划成能用的分区（比如先建 1 个分区占满全盘）？

@@idea 核心思路
交互式分区工具，操作流程固定：

```bash
fdisk /dev/sdb        # 对第二块盘分区（千万别对 sda 动手！）
```

进入交互菜单后依次按键：

```bash
n        # new：新建分区
p        # 主分区（primary）
1        # 分区号 1
回车      # 起始扇区，默认即可
回车      # 结束扇区，默认 = 占满剩余空间
w        # write：把方案写入磁盘（关键一步！）
```

其中 **p 打印分区表**、**q 不保存退出**、**d 删除分区**。完成后 `fdisk -l` 或 `lsblk` 看到 `/dev/sdb1`。

背景知识：老式 MBR 分区表最多 4 个主分区、单分区上限 2TB；超过 2TB 或分区数更多的场景要用 **GPT** 分区表（fdisk 新版默认 GPT，或用 gdisk/parted）。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 配了半天，fdisk -l 没变化 | 忘了按 `w`；w 才真正写入，q 是放弃！ |
| 对着正在用的盘（如 sda）敲 fdisk | 会破坏数据；**操作前先 lsblk 确认盘符**，新盘才敢动 |
| 分区报"no free sectors" | 空间都被占了/表满了；删一个分区或换 GPT |
| MBR 只能 4 个主分区，建第 5 个失败 | 用扩展分区或把表转 GPT；学习场景 1-2 个分区够用 |

@@point ⑦ mkfs 格式化：给分区装上"文件系统"
@@need 要解决什么
sdb1 建好了，但 df 还是不显示？——分区还差一步：**格式化**（建文件系统）。

@@idea 核心思路
**文件系统**是"目录怎么组织、数据怎么定位"的规则：Windows 用 NTFS/FAT32，Linux 常用 ext4、xfs。

```bash
mkfs -t ext4 /dev/sdb1     # 指定类型格式化
mkfs.ext4 /dev/sdb1        # 等价写法（ext4 专用）
mkfs.xfs /dev/sdb1         # xfs 格式（CentOS 默认）
```

⚠️ 警告：**格式化会清空该分区所有数据**。这步是"把分区变成空白可用"，请确认盘符无误再执行。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 格式化 sda1 把系统盘清了 | 盘符写错了！格式化**不可逆**，操作前 lsblk 反复确认 |
| mkfs 报"设备忙"（busy） | 该分区已被挂载/被占用；先卸载（umount）再格式化 |
| 忘了格式化直接挂载 | 挂载会失败："wrong fs type"——必须先 mkfs 建文件系统 |

@@point ⑧ mount / umount：临时挂载与卸载
@@need 要解决什么
分区格式化好了，怎么让它出现在目录树里能被访问？——**挂载**：把一个目录当作入口"接入"分区。

@@idea 核心思路
Linux 没有"打开 D 盘"这个动作，一切访问都通过目录树。挂载 = **把分区挂到一个空目录上**，之后访问这个目录 = 访问这个分区：

```bash
mkdir /data                    # 先准备一个空目录当挂载点
mount /dev/sdb1 /data          # 把 sdb1 挂到 /data
df -h                          # 确认挂载成功（/data 一行出现）
umount /data                   # 卸载（挂载点里没有进程占用时才能卸）
```

注意事项：
- **挂载点是目录**：卸载后再 mount 其他分区，直接用同一个目录也行；
- 卸载时该目录下不能有进程在用，否则报 `target is busy`。

方法步骤就三步：**mkfs 建文件系统 → mkdir 建挂载点 → mount 挂上**。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 挂载到有内容的目录，原内容不见了 | 挂载会"盖住"目录原内容（不是删除！）；卸载后内容就回来了。别往挂载点里塞重要东西 |
| umount 报 "target is busy" | 有进程在用该目录：`lsof /data` 找出进程，关掉后再卸载 |
| 挂完重启又没了 | mount 是临时的！要开机自动挂载走第 ⑨ 点 fstab |

@@point ⑨ fstab 永久挂载：重启也不丢
@@need 要解决什么
mount 的盘一重启就消失，每次手动挂太蠢。怎么让系统开机自动挂载？

@@idea 核心思路
改 `/etc/fstab`（filesystem table），加一行"开机自动挂载"规则。格式**六个字段缺一不可**：

```bash
设备  挂载点  文件系统类型  挂载选项  dump  fsck
```

用 UUID 最稳（盘符 sda/sdb 会变，UUID 唯一不变）：

```bash
# 先查 UUID
blkid /dev/sdb1
# 输出：/dev/sdb1: UUID="xxxx-xxxx" TYPE="ext4"
```

然后编辑 /etc/fstab 追加一行：

```bash
UUID=xxxx-xxxx  /data  ext4  defaults  0  0
```

| 字段 | 含义 |
|---|---|
| 第 1 列 | 设备（UUID 或 /dev/sdX1） |
| 第 2 列 | 挂载点目录 /data |
| 第 3 列 | 文件系统类型 ext4/xfs |
| 第 4 列 | 挂载选项（默认写 defaults） |
| 第 5 列 | dump 备份标记（0 不备份） |
| 第 6 列 | fsck 检查顺序（0 不检查） |

**改完先 `mount -a` 验证**（重新读 fstab 尝试全部挂载），成功无误再重启——fstab 写错可能开机卡住进不了系统。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 改完 fstab 直接重启，结果开机起不来 | fstab 任何一个字段错都可能启动失败（紧急模式）；**先 `mount -a` 试**，成功再重启 |
| 盘符 sdb 变 sdc 后挂载失效 | 这就是要用 **UUID 而不是 /dev/sdb1** 的原因——UUID 不随插拔变 |
| fstab 里少写一个字段 | 六字段缺一不可，少一段 mount -a 就报错 |

@@point ⑩ 系统状态检测：看网卡、看内核、看内存、看谁登录过
@@need 要解决什么
接手一台服务器，想快速摸底：什么系统？内存多大？谁来过？运行了多久？

@@idea 核心思路
一条命令一个维度，全部背下来：

```bash
ip addr                      # 网卡和 IP 地址
uname -a                     # 内核版本、主机名等
cat /etc/redhat-release      # 发行版信息（redhat 系）
free -h                      # 内存使用（-h 人性化）
last                         # 最近登录记录（谁、什么时候、从哪来）
history                      # 当前用户敲过的命令历史
uptime                       # 运行时长 + 平均负载
```

重点解读 **uptime 的负载**：

```
load average: 0.30, 0.15, 0.10
```

三个数字分别是 **1 / 5 / 15 分钟的平均负载**——它是"排队等 CPU/IO 的任务数"，**不是 CPU 占用率**。0.5 不是"用了 50% CPU"，而是"平均 0.5 个任务在等/在跑"；负载接近或超过 CPU 核数才是压力大的信号。

内存解读优先看 **available**（可用量），而不是 used——Linux 会拿空闲内存做缓存，used 大不代表不够用。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 把 load average 当 CPU 使用率 | 负载是"排队任务数"，CPU 使用率是"忙碌百分比"，两码事；1/5/15 分钟三个时间窗，不是 5/10/15 |
| free 显示 used 占 90% 就以为内存不够 | Linux 把空闲内存用作缓存（cache/buffer），真正要看的指标是 available |
| history / last 能查出"谁干过坏事" | 可以辅助排查，但这俩都可能被清除/伪造，不能当唯一证据 |

@@summary
| 问题 | 答案 |
|---|---|
| PATH 是什么 | 命令查找目录列表；`echo $PATH` 查看，配置时永远 `$PATH:新目录` 追加 |
| 配置放哪 | 系统级 /etc/profile（所有人）；用户级 ~/.profile（自己）；改完 source 立即生效 |
| export 和 source | export 当前 shell 临时生效；source 重读配置文件让配置立刻活 |
| 怎么看磁盘 | df -h（用量）+ lsblk（盘/分区结构）；加 -f 看 UUID |
| 新盘三步 | fdisk 分区（n→p→1→回车→回车→w）→ mkfs 格式化 → mkdir+mount 挂载 |
| 永久挂载 | /etc/fstab 写六字段（UUID 挂载点 类型 选项 0 0），先 mount -a 验证再重启 |
| 系统状态 | ip addr / uname / free -h / last / uptime；load average 是 1/5/15 分钟平均负载 |

一句话总结：**环境变量靠"追加 PATH + export + 写 profile + source"来配置和维护，新硬盘则按"fdisk 分区、mkfs 格式化、mount 挂载、fstab 用 UUID 永久化"四步上线——这一章之后，你能自己给服务器"加内存条般的加盘"，也能随意调配命令路径，下一章装 JDK/MySQL 就是环境变量+挂载的实战。**
