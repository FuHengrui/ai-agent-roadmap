@@h1 第四章　文件类型与权限管理
@@sub 阶段 18 · 云原生开发环境与 DevOps 工具链　|　Linux 基础　|　难度 ★★★

@@why 这一章在解决什么问题
上一章你学会了"系统怎么认人"（用户与组），这一章要解决它的下半句：**系统怎么认文件、以及"这个人能不能动这个文件"**。

很多同学第一次 `ls -l` 看到 `drwxr-xr-x` 就懵了：这串天书是什么？为什么有的文件能执行有的不行？为什么我明明能"写"这个文件却删不掉它？为什么教程里动不动 `chmod 755`，数字又是哪来的？——这一章把文件类型、九位权限、chmod 的符号法与数字法一次讲透，讲完你就能读懂任何文件的"门禁卡"，也能自己设对权限。

@@map 这一章在整个知识库里的位置
**上一章**：用户与用户组管理——搞定了"谁在用这台机器"
**本章** ← 你在这里：搞清"文件是谁的、谁能动它"（类型 + 权限字 + chmod/chown/chgrp）
**下一章**：目录与文件操作命令——看懂权限后，开始大量操作文件（增删改查、查看内容）
**阶段终点**：云原生开发环境与 DevOps 工具链，权限模型是所有容器/云资源隔离的思想源头

@@note info 学习提示
本章的难点不在命令（chmod/chown 就三个），而在**读权限字**。建议先拿一个真实文件的 `ls -l` 输出，对照第 ① 点一栏一栏拆，拆通一个后面全通了。数字法 421 的换算要亲手算几遍，别只靠"chmod 777"一招。

@@point ① ls -l：一行输出到底说了什么
@@need 要解决什么
`ls -l` 出来一行：`drwxr-xr-x 2 root root 4096 日期 目录名`。这十几个字段分别是什么？看不懂就没法和权限打交道。

@@idea 核心思路
一行输出拆成 8 段（从前往后）：

```
-rw-r--r--. 1 root root 1865 6月 12 10:30 install.log
│─────────│ │ │   │    │   └──────────┘ └────────┘
    ①      ② ③   ④    ⑤       ⑥              ⑦
└─────────────────────────────────────────────────┘
                      ⑧ 文件名（这段不算"属性"）
```

| 段 | 含义 |
|---|---|
| ① 类型 + 权限 | 第 1 位是文件类型，后 9 位是权限字（本章主角） |
| ② 硬链接数 | 有多少个名字指向这个文件（普通文件一般 1，目录是子目录数+2） |
| ③ 属主 | 文件的主人（owner） |
| ④ 属组 | 文件归属的组（group） |
| ⑤ 大小 | 单位是**字节**，目录显示 4096 是目录自己占的块 |
| ⑥ 修改时间 | 最后一次修改时间 |
| ⑦/⑧ 文件名 | 名字本身 |

只要记住"**类型权限 | 链接数 | 属主 | 属组 | 大小 | 时间 | 名字**"这个顺序就够用了。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 看到目录大小显示 4096，以为目录里有 4096 字节内容 | 那是**目录项本身占的块**，不是里面文件的总大小；目录的内容大小要看 du |
| 搞不清第 ② 段数字是啥 | 普通文件一般是 1（一个名字）；目录会是 2 或更大，别把它当"文件数"猜 |

@@point ② 文件类型：第一个字符一眼分辨
@@need 要解决什么
权限字第一位那个 `-`、`d`、`l` 到底代表什么？为什么有的文件图标长得不一样？

@@idea 核心思路
第一位是**文件类型**，常见的就 4 种，其余认识即可：

| 字符 | 类型 | 举例/说明 |
|---|---|---|
| `-` | 普通文件 | 文本、图片、程序、压缩包 |
| `d` | 目录 | 一切从 / 开始的树都是它 |
| `l` | 软链接 | 相当于 Windows 的快捷方式，指向另一个文件 |
| `c` | 字符设备 | 键盘、终端这类按字符流读写的设备 |
| `b` | 块设备 | 硬盘、U 盘这类按"块"读写的设备 |
| `p` / `s` | 管道 / 套接字 | 进程间通信用的特殊文件 |

一句话：**第一个字符是"类型"，后面九个字符才是"权限"**，先分清这两个概念。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为只有 ".exe" 才算可执行文件 | Linux **不看扩展名**，看有没有 x 权限和可执行的文件头；`.sh`、`.py` 改个名照样能执行（权限对就行） |
| 看到 /dev/sda 以为是个普通文件 | 是**块设备文件**（b 开头），代表"这块硬盘"，不是普通数据文件 |

@@point ③ 九位权限：三类身份 × 三种操作
@@need 要解决什么
`rwxr-xr-x` 这九个字母，怎么看出"谁"能做什么？

@@idea 核心思路
九个字符固定分成三组，每组三位：

```
 rwx  r-x  r-x
 ──   ──   ──
属主  属组  其他
owner group others
```

- **每组三个字符**依次是 r（读 read）、w（写 write）、x（执行 execute）；
- **有权限显示字母，没权限显示 `-`**；
- 顺序永远是 `属主-属组-其他`，这个顺序不能乱。

以 `-rwxr-xr--` 为例读出来就是：属主可读可写可执行，属组可读可执行，其他人只能读。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 把权限读串位：以为 rwx 是"读-执行-写" | 顺序固定 r→w→x；先读属主组，再属组组，最后其他组 |
| 看到 9 位里有 10 个字符（drwxr-xr-x） | 第一个 d 是类型，不占权限位；**权限永远 9 位**，别把类型当权限 |

@@point ④ 对目录的权限和对文件的权限完全不同
@@need 要解决什么
同一组 rwx，按在"文件"和"目录"上，含义居然不一样？为什么明明有文件的写权限却删不掉它？

@@idea 核心思路
这是 Linux 权限最经典的认知坑，务必背下来：

| 权限 | 对**文件** | 对**目录** |
|---|---|---|
| r | 能读文件内容 | 能列出目录里有哪些文件名 |
| w | 能改文件内容 | 能**在目录里新建/删除/改名文件** |
| x | 能执行文件 | 能进入目录（cd 进去），也叫"通过权" |

关键推论：
- 能不能**删一个文件**，看的是**它所在目录的 w 权限**，而不是文件自己的权限（文件自己的 w 只管"改内容"）；
- 目录最少要有 **x** 才能进去，否则连 cd 都不行；
- 想要完整使用一个目录，通常是 r + x 或 r + w + x 一起给。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| "我对文件有 rw 权限，怎么删不掉/建不了新文件" | 删除是"目录级"操作：看所在目录的 w；把目录的 w 给上才是答案 |
| chmod 给目录只加了 r，还是进不去 | 目录没有 x 就没有进入权；`chmod +rx` 一起给才顺手 |
| 在 /tmp 里删不掉别人的文件，报权限不足 | /tmp 有粘滞位（见第 ⑧ 点）：目录可写但只能删自己的文件，这是安全设计 |

@@point ⑤ chmod 符号法：用字母精确改权限
@@need 要解决什么
只给"属主"加个执行权限，不想碰其他位，怎么改？

@@idea 核心思路
符号法=`谁 + 操作 + 权限`，好读好记：

| 身份字母 | 含义 | 操作符 | 含义 |
|---|---|---|---|
| u | 属主（user） | + | 加上 |
| g | 属组（group） | - | 去掉 |
| o | 其他（others） | = | 直接设为 |
| a | 全部（all） | | |

用法示例：

```bash
chmod u+x install.log     # 属主加执行权
chmod g-w install.log     # 属组去掉写权
chmod o= install.log      # 其他人啥权限都不给
chmod a=rwx install.log   # 三组全设为可读可写可执行（= 是整体覆盖！）
chmod g+w,o-x install.log # 逗号分隔，一次改多组
```

特点：**+/- 是"动一个位"，不影响其他位；= 是"整个覆盖"**。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 用了 a=rwx 后原来别人的权限丢了 | `=` 是整体覆盖不是追加；想追加用 `a+rwx` |
| chmod 后没变化 | 检查命令里的身份字母和当前身份对不对得上：只有属主/root 才改得动属主位 |
| 一条命令改了 w 又改 x，结果乱套 | 多组操作用逗号分隔一次写完，别分两条覆盖 |

@@point ⑥ chmod 数字法：rwx = 421
@@need 要解决什么
教程和群里天天"chmod 755"，数字到底怎么来的？为什么总和 7、5、4 这几个数纠缠？

@@idea 核心思路
数字法的规则很简单：**r=4，w=2，x=1，没有权限=0**，每组三个值相加得到一个 0~7 的数，三位数字依次对应属主/属组/其他：

```
r w x   → 4+2+1 = 7
r - x   → 4+0+1 = 5
r - -   → 4+0+0 = 4
- - -   → 0
```

所以：

```bash
chmod 755 file   # 属主 7(rwx)，属组 5(r-x)，其他 5(r-x)
chmod 640 file   # 属主 rw-，属组 r--，其他 ---
chmod 777 file   # 所有人全部权限（能不用尽量别用）
```

换算口诀：**7=全都有，5=读+执行，4=只读**。剩下的 3=写+执行、6=读+写、1=只执行、2=只写，按需组合。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 把 754 当一个整体数猜含义 | 必须**拆成三组独立计算**：7(rwx) 4(r--) 4(r--) 是"554"的常见误认也要注意：三位分别对待主/属组/其他，不是求和 |
| 遇到"权限不对就好不了"永远是 chmod 777 | 777 等于给所有人开后门，是安全大忌；先想清楚"谁需要什么"，再给最小权限 |
| chmod 后文件还不能执行 | 看属主对不对、路径对不对，还要注意文件内容本身得是能执行的程序 |

@@point ⑦ chown / chgrp：改文件的"主人"和"班组"
@@need 要解决什么
文件是 root 建的，现在要交给 dev 用，或者要换个组共同维护——但文件还是 root 的，别人碰不得。

@@idea 核心思路
两个命令，一个改属主（owner），一个改属组（group）：

```bash
chown dev install.log        # 属主改为 dev
chown root:dev install.log   # 属主 root、属组 dev 一起改（冒号分隔）
chgrp bigdata install.log    # 只改属组为 bigdata
chown -R dev /opt/app        # -R 递归：连同目录下所有文件一起改
```

注意事项：
- **只有 root 能 chown**——普通用户不能把文件"送人"（不然系统就乱套了）；
- 属主 + 属组常用 `chown 属主:属组` 一条搞定，比 chgrp 用得更多。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 普通用户执行 chown 报 "operation not permitted" | 正常！chown 是 root 特权；需要时 `sudo chown …` 或切 root |
| chown user file 后，属组也自动变了？ | 不会，属组保持不变；想一起改用 `chown user:group file` |
| 忘了 -R，改完一看子目录还是旧的 | 递归是另一件事：目录本身和里面内容分开，需要 -R 才一起生效 |

@@point ⑧ 特殊权限：遇到 s 和 t 别慌
@@need 要解决什么
`ls -l` 偶尔看到权限位出现 `s` 或 `t`（比如 /usr/bin/passwd 和 /tmp），字母不认识，是不是权限坏了？

@@idea 核心思路
这是三种"特殊权限"，平时少见，认识即可：

| 标记 | 名字 | 出现在 | 效果 |
|---|---|---|---|
| s（属主位） | setuid | 可执行文件 | 运行时以**属主身份**执行（如 passwd 由普通用户执行却以 root 身份改 shadow） |
| s（属组位） | setgid | 可执行文件/目录 | 文件按属组身份执行；目录下新建文件自动继承目录属组 |
| t | sticky（粘滞位） | 目录 | /tmp 这类目录：大家都能写，但**只能删自己的文件** |

数字法对应：**4xxx=setuid，2xxx=setgid，1xxx=sticky**，加在三位数字前面（如 `chmod 1777 /tmp`）。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 看到权限位是 s 而不是 x 就慌"坏了" | 小写 s = setuid + x；大写 S = setuid 但**没有 x**（组合奇怪，一般是误设）；不用主动去设，认得出就行 |
| 想当然给所有文件都加 s 让它"提权" | setuid 是双刃剑：等于把 root 权限借给所有人，被入侵就是提权通道；**默认不要碰** |
| /tmp 删不掉别人的文件又问是不是权限坏了 | 是 sticky 位在保护，故意为之 |

@@point ⑨ 最小权限原则：权限管理的安全底线
@@need 要解决什么
权限学完了，实践中到底给多少合适？为什么老运维总说"别一上来就 777"？

@@idea 核心思路
**最小权限原则**：只给"刚好够用"的权限，多一分都不给。

- 服务跑文件：属主读写+执行即可，别给其他用户写；
- 配置文件：属主只读（甚至 600），密码类文件绝不公开；
- 目录：按"谁需要进入/列出/管理"分三档给，不滥用 -R 大范围授权。

```bash
# 一个"克制"的示例：日志目录只让运维组读写，其他组只读
chown -R root:devops /var/log/app
chmod 750 /var/log/app        # root 全权，devops 组读写执行，其他无
```

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| "解决不了就 chmod 777 /tmp 或 /" | 等于给全世界开后门；被入侵后坏人第一件事就是找你这种目录 |
| 一套权限走天下（所有目录 755 或全部 777） | 权限要和角色匹配：共享目录用组授权 + 合理位，别一刀切 |
| 改完权限服务起不来 | 常见于权限改小了：看服务日志报的"Permission denied"对应哪个文件，精准补那个文件/目录的权限 |

@@summary
| 问题 | 答案 |
|---|---|
| ls -l 一行怎么读 | 类型+权限 \| 链接数 \| 属主 \| 属组 \| 大小 \| 时间 \| 文件名 |
| 文件类型怎么看 | 首字符：- 普通、d 目录、l 软链、c/b 设备、p/s 特殊 |
| 九位权限结构 | 属主 rwx + 属组 rwx + 其他 rwx，有权限给字母，没权限给 - |
| 目录权限和文件权限 | 目录 w=能增删文件、x=能进入；删文件看目录的 w，不是文件的 w |
| chmod 符号法 | u/g/o/a + +/-/= + r/w/x，可逗号组合 |
| chmod 数字法 | r=4 w=2 x=1，三组分别相加，如 755=rwxr-xr-x |
| 改属主属组 | chown（root 专属）、chgrp；-R 递归 |
| 特殊权限 | s=setuid/setgid、t=sticky；认识即可，默认别乱设 |

一句话总结：**权限字就是"类型 1 位 + 三类身份各 3 位"的 10 个字符，看清它再动手；改权限用 chmod 符号法（精确）或数字法（421 换算），改归属用 chown/chgrp，并时刻守住"最小权限"这条安全底线。**
