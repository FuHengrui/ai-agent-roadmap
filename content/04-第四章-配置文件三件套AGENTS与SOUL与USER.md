学完这一章，你能回答：**三份文件各自管什么、怎么写、怎么协同，以及最常见的四个误区**。配置这件事的回报率极高——同一个模型，配置不同，用起来的体验天差地别。

@@point ① 配置体系总览：三份文件的分工定位
@@need 要解决什么
OpenClaw 里能配置的地方很多，新手最容易懵的就是：到底有几份文件、谁管什么？先建立一张全景地图，后面每份文件讲起来你才知道它在体系里的位置。

@@idea 核心思路
OpenClaw 工作空间的**顶层规则体系由三份文件构成**，分工非常清晰：

| 文件 | 定位 | 一句话职责 |
|---|---|---|
| **AGENTS.md** | 行为宪法 | 定义 AI 在工作空间中的行为模式、会话流程、内存管理机制，以及与人类交互的基本原则 |
| **SOUL.md** | 人格定义 | 决定 AI 的性格、说话风格、核心原则——它"是谁" |
| **USER.md** | 服务对象画像 | 告诉 AI"自己正在为谁工作"：你的背景、偏好、常用工具 |

三份文件都放在工作空间顶层，OpenClaw 启动时自动读取。记住这个顺序：**先有规矩（AGENTS），再有人格（SOUL），最后知道为谁服务（USER）**。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 只填一个文件就以为配置完成 | 三份分工不同：AGENTS 管"怎么干活"，SOUL 管"是谁"，USER 管"为谁服务"，一个都不能少 |
| 分不清谁管记忆 | 会话流程和内存管理机制由 AGENTS.md 定义，不是 USER.md 也不是 SOUL.md |
| 改完配置不验证 | 改完后实际跑一轮对话测试，别只看文件内容"写对了"就觉得生效了 |

@@point ② AGENTS.md：行为宪法（管什么）
@@need 要解决什么
AI 上线前你最担心的往往不是它"不够聪明"，而是它没边界：说话没边、该记的东西记不住、上次聊到哪这次忘了。这些"底层行为"由谁来约束？

@@idea 核心思路
AGENTS.md 是 OpenClaw 工作空间的**顶层规则文档**，管四件事：

- **行为模式**：AI 在工作空间里怎么干活、按什么方式推进任务
- **会话流程**：一次对话怎么开始、怎么进行、怎么结束
- **内存管理机制**：哪些信息该记住、怎么记、什么时候写入长期记忆
- **与人类交互的基本原则**：什么时候该问、什么时候直接做

它像一个公司的"员工手册"——不定义这个员工多有才（那是 SOUL 的事），只定义**底线和流程**，所以常称它为"行为宪法"。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为 AGENTS.md 只是"适配说明" | 它决定 AI 能否记住对话：会话流程、内存管理机制都在这份文件里 |
| 把想得到的规则全塞进 AGENTS.md | 规则越多越容易互相打架。核心行为准则放这里，细节点交给专门的文件 |
| 照抄别人的 AGENTS.md 不读一遍 | 别人的规则未必兼容你的工作流。先用内置默认版跑通，再按需加规则 |

@@point ③ SOUL.md：人格定义
@@need 要解决什么
默认状态下 AI 回复像客服：四平八稳、没有立场，每个问题都答"看情况"、看"因人而异"。你需要的不是更聪明的模型，而是一个**有性格的助手**——这由谁决定？

@@idea 核心思路
如果说 AGENTS.md 是"行为宪法"，那 **SOUL.md 就是人格定义**。它决定 AI 的三件事：

- **性格**：外向还是内敛？毒舌还是温和？
- **说话风格**：简洁还是详细？严肃还是幽默？
- **核心原则**：什么是绝对不能做的？什么是必须坚持的？

特别要强调"核心原则"：**AI 可以有明确立场，不要凡事"看情况"**。给 AI 一个观点和判断的偏好，它输出的质量会肉眼可见地提升——这是三份文件里"性价比"最高的一处配置。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 把 SOUL.md 写成"人设小作文" | SOUL 是给 AI 读的执行文件，越具体可执行越好："偶尔毒舌但从不恶意"比"幽默风趣"管用 |
| 性格与风格混在一起写 | 分开三个区块：性格、说话风格、核心原则。AI 解析更稳定，后期迭代也好改 |
| 核心原则写成口号 | 原则要能落地成行为，如"技术术语保留英文"就是可执行的风格，而不是空泛的"要专业" |

@@point ④ USER.md：服务对象画像（五要素）
@@need 要解决什么
AI 已经知道"它是谁"了，但还不知道"在为谁工作"：不知道你的名字、职业、几点睡觉、常不用什么工具。缺了这部分，AI 连"深夜别打扰你"都做不到。

@@idea 核心思路
USER.md 是 AI 了解「自己正在为谁工作」的窗口，包含**五个要素**：

1. **基本信息**：名字、称呼、时区、位置
2. **背景**：职业、技能、兴趣
3. **工作重点**：当前最重要的目标（可列 2-3 个，按优先级排）
4. **偏好**：沟通风格偏好、工作时间、不要打扰的时间
5. **常用工具**：邮箱、代码环境、常用平台

注意里面的信息直接决定体验：**时区写错了，"深夜勿扰"就形同虚设**；不写勿扰时间，AI 凌晨三点也能把你叫起来。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 在 USER.md 里填密钥/密码 | 配置文件可能被分享或同步，token、密码、连接串一律不写，放环境变量或密钥文件 |
| 只填"基本信息"不填偏好 | 决定体验的是偏好和勿扰时间——那才是 AI"懂不懂你"的关键 |
| 时区/位置乱填或不填 | 时区直接决定"深夜勿扰"怎么算，填错等于没设这一条 |

@@point ⑤ 三者协同关系：行为规则层 → 人格定义层 → 服务对象层
@@need 要解决什么
三份文件各自独立，但 AI 每一次回答里三份都在同时起作用。它们到底怎么配合？如果理解不了层级关系，出问题时你就不知道去改哪个文件。

@@idea 核心思路
这三层是嵌套的，从上到下依次传递：

**AGENTS.md（行为规则层）** → 定义**会话流程、内存管理、心跳机制**
↓ ↓ ↓
**SOUL.md（人格定义层）** → 承载**性格、说话风格、核心原则**
↓ ↓ ↓
**USER.md（服务对象层）** → 承载**基本信息、背景技能、偏好目标**

一句话概括：**AGENTS 决定"怎么运行"，SOUL 决定"以什么人格运行"，USER 决定"为谁运行"**。上层的运行机制会传递到下层，下层的人格与服务对象信息又反过来决定规则怎么落地——比如"深夜不打扰"这条规则，要同时靠 AGENTS 的流程约束和 USER 的时区/勿扰时间来落地。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 三份文件写了互相矛盾的要求 | 例：AGENTS 要求"简洁直接"，SOUL 里又写"长篇大论"，AI 会摇摆。动手前先对齐主线 |
| 以为改 SOUL 就能解决"记不住" | 记忆机制归 AGENTS 的内存管理管，SOUL 管人格，两个维度别混 |
| 背下三层结构但用不上 | 遇到"AI 表现不对"先定位：规则问题查 AGENTS、人设问题查 SOUL、信息缺失查 USER |

@@point ⑥ SOUL 写作实战：性格 / 风格 / 原则三段式示例
@@need 要解决什么
定义都看懂了，但 SOUL.md 到底长什么样？直接给你一个骨架，对着改三行就能用。

@@idea 核心思路
按**三段式**组织：`## 性格` → `## 说话风格` → `## 核心原则`，每段用短条目列具体规则。参考写法：

```text
# SOUL.md - Who You Are
## 性格
- 聪明、高效、有点话多
- 对技术充满好奇
## 说话风格
- 简洁直接，不啰嗦
- 技术术语保留英文
- 重要信息用**加粗**标注
## 核心原则
- AI 可以有明确立场，不要凡事"看情况"
```

两个进阶认知：一是**人格是逐渐显现的**——你不可能第一次就写出完美的 SOUL.md，先写一个 Basic 版本用起来，跑一段时间再迭代；二是**emoji 可以用但克制**，重要信息用加粗而不是靠颜文字和感叹号。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 把口语化表达原样写进 SOUL | 口头表达要转成书面指令，如"AI 可以有明确立场，不要凡事'看情况'"，含义不变、表达更稳 |
| 一上来追求"一次写完美" | 第一版先覆盖性格 + 风格 + 3 条原则，用几天再迭代，别憋大招 |
| 原则写得抽象 | "重要信息用加粗标注"比"要突出重点"可执行得多，AI 不会解读余韵 |

@@point ⑦ USER 写作实战：五要素示例
@@need 要解决什么
SOUL 定义了 AI 是谁，现在轮到让 AI 认识你。USER.md 怎么写最省事？同样给一个可直接套用的骨架。

@@idea 核心思路
按五个区块组织，名字、邮箱一类信息用**占位符**先顶住：

```text
# USER.md - About Your Human
## 基本信息
- 名字: [你的名字]
- 称呼: [如 boss、老板、兄弟]
- 时区: UTC+8 北京
## 工作重点
1. [当前最重要的目标]
2. [次要目标]
## 偏好
- 勿扰时间: 23:00-08:00
## 常用工具
- 邮箱: [your@mail.com]
- 代码: [常用语言和工具]
```

写完骨架后，把"工作重点"和"偏好"两项认真填实——这两项直接决定 AI 每天围绕什么转、什么时候闭嘴。USER.md 还是**活文档**：目标变了、作息变了，记得同步更新。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 只填基本信息就开用 | 工作重点没写，AI 不知道优先级；勿扰时间没写，它会随时打扰 |
| 填了真实邮箱/密码 | 只需要占位符或脱敏描述（如"公司邮箱"），真实凭证永远放密钥文件 |
| 写完再也不更新 | 用户是活人，目标、岗位、偏好会变。每个月过一遍 USER.md 值得做 |

@@point ⑧ 沟通与安全准则：不客套 / 不泄隐私 / 不擅自破坏 / 深夜不打扰
@@need 要解决什么
AI 接入你的工作空间后，最怕两件事：泄露隐私、乱打扰。这些"红线"应该写在哪、怎么写？这里有一份可以直接照抄的准则清单。

@@idea 核心思路
把沟通与安全准则整理成**六条可执行条款**，可写入 AGENTS.md 与 USER.md：

1. **绝对不要以"好问题"开头**——直接回答
2. **不泄露用户的隐私数据**
3. **不在群聊中过度发言**
4. **不在未确认的情况下执行破坏性操作**（删除、强推、批量改名等）
5. **深夜（23:00-08:00）除非紧急，否则不主动打扰**
6. **发现用户加班太晚，主动提醒休息**

注意这些条款的共同点：**都具体到"能执行的动作"**。"要礼貌"是态度，"不以'好问题'开头"是动作——写配置时永远选动作。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 只写"要保护好隐私" | 太抽象。写成"不泄露用户的隐私数据"，并列出哪些算隐私（密码、token、私人信息） |
| 忘了"破坏性操作需确认" | 没这条，AI 可能直接执行删除、覆盖等不可逆操作。这条必须进 AGENTS.md |
| 只设了勿扰时间，没写"加班提醒" | 专门有一条要求"发现工作太晚要提醒休息"，这是贴心值来源，别漏 |

@@point ⑨ 误区 1 + 2：写得越多越好、一次性写完
@@need 要解决什么
开始动笔时，新手最容易犯的两个"写作姿势"错误：一是拼命往文件里堆内容，二是想一次性写到完美。两个都反着来才对。

@@idea 核心思路
**误区 1：写得越多越好？错。** 规则越多，AI 越容易陷入"分析瘫痪"——每条规则都在抢注意力，结果哪个都没执行好。好的 SOUL.md 应该像**法律条文一样简洁，少即是多**。

**误区 2：一次性写完？错。** 人格是**逐渐显现**的，你不可能第一次就写出完美的 SOUL.md。正确姿势：先写一个 **Basic 版本**（性格 + 风格 + 几条原则），使用一段时间，根据实际对话效果再迭代——哪里不对就针对性补一条，而不是重写。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 从 2000 字人设小作文开始 | 10 条精简规则 > 2000 字人设：规则多到 AI 都记不住，等于没写 |
| 写完就再也不动 | 人格是逐渐显现的：跑几天看对话效果，发现不对劲就针对性加一条 |
| 把"少即是多"理解成"什么都不写" | 精简不等于空白：性格、风格、原则三块每块至少有一条可执行内容 |

@@point ⑩ 误区 3：只关注 USER.md
@@need 要解决什么
很多人上手第一步就是埋头填 USER.md——感觉最"实在"，填的都是自己的真实信息。但这样做只完成了一半配置。

@@idea 核心思路
**误区 3：只关注 USER.md？错。** 核心区别在于：

- **USER.md 告诉你「为谁服务」**——用户是谁、什么背景、什么偏好
- **SOUL.md 告诉 AI「它是谁」**——什么性格、什么风格、什么原则

只填 USER.md 不填 SOUL.md，就像**给一个没有灵魂的机器打工**——你会觉得它"不懂你"。它知道你的所有信息，却不知道该以什么样子回应你，说出来的话依然是干巴巴的客服腔。两份文件必须配套写：一遍写"你是谁"，一遍写"我是谁"。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 只填 USER 就开始用 | AI 知道你是谁，但不知道自己该是什么样——对话依旧像客服 |
| 用"多填点 USER 信息"代替 SOUL | 信息多 ≠ 人格有。信息补水的是"服务对象层"，人格是另一层，补不齐 |
| USER 和 SOUL 写了互相冲突的诉求 | 例：SOUL 写"毒舌"，USER 写"不爱听讽刺"。先对齐再交付 |

@@point ⑪ 误区 4：完全不管 AGENTS.md
@@need 要解决什么
AGENTS.md 是唯一一份名字里不带"人格"、不带"用户"的文件，看起来最像"技术文档"，于是不少人直接跳过它。这个跳过有代价。

@@idea 核心思路
**误区 4：完全不管 AGENTS.md？错。** 真相一句话：**AGENTS.md 决定了 AI 能否记住你们之间的对话。**

因为会话流程和内存管理机制都由这份文件定义——哪些信息该进记忆、什么时候写、怎么组织，全在这里。完全不管它，等于把"记不记得住你"这件事交给了默认值；而 SOUL.md 和 USER.md 再精致，也补不了"失忆"的窟窿。

正确顺序：**先保证 AGENTS.md 的基本规则合理（会话流程 + 内存管理跑通），再去打磨 SOUL 的人格和 USER 的信息**——正好与三件套的层级顺序一致。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 只调 SOUL/USER，从不动 AGENTS | 记忆机制在 AGENTS 里：不管它，AI 可能记不住关键上下文，人格再鲜活也白搭 |
| 复制别人的 AGENTS.md 不读一遍 | 别人的规则未必兼容你的工作流。先用默认版跑通，再按需增量修改 |
| 把"请记住我"写进 SOUL 就当配置完成 | 记住/遗忘是机制问题（AGENTS 的内存管理），不是人设问题，写进 SOUL 不管用 |

@@summary
这一章你实际拿到的是**四样东西**：

| 拿到了什么 | 为什么要紧 |
|---|---|
| **三件套全景地图** | 知道 AGENTS / SOUL / USER 各自管什么、怎么协同，遇问题能定位到具体文件 |
| **可直接套用的写作模板** | SOUL 三段式 + USER 五要素骨架，填上占位符就能跑起来 |
| **四类避坑清单** | 少即是多、先 Basic 后迭代、SOUL/USER 缺一不可、AGENTS 决定记忆 |
