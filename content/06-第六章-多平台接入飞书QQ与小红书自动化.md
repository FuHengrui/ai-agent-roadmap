@@h1 第六章　多平台接入：飞书、QQ 与小红书自动化
@@sub 阶段 14 · 小龙虾 OpenClaw 实战　|　平台实操　|　难度 ★★★

@@why 这一章在解决什么问题
部署好的 OpenClaw 像一台只会"思考"的机器——它有了模型、有了网关，但还没有任何入口，谁都用不上它。
**同事在飞书群里想让机器人帮忙汇总日报，它怎么进群？** 你想让它到小红书上自动发笔记、追热点，它凭什么能操作账号？这一章要解决的就是这两件事：把 OpenClaw 接进飞书、QQ 两个聊天平台，再给它装上能自动运营小红书的技能包。

**为什么偏偏是这三个平台？** 飞书和 QQ 代表"通道接入"：机器人挂在 IM 里收消息、回消息，这是企业协作与个人服务最常见的形态；小红书代表"技能扩展"：Agent 不再等人来聊天，而是自己上平台搜索、发布、互动、做内容运营。前者靠配置，后者靠技能包，两种完全不同的接入形态在这一章一次走完。

学完这一章，你能回答：**飞书机器人从注册应用到配对授权要走完哪几步？QQ 机器人的凭证去哪拿？怎么让 OpenClaw 自动运营一个小红书账号？**

@@map 这一章在整个知识库里的位置
**上一章**：OpenClaw 完成了部署与基础概念，先接入了企业微信与钉钉，走通了"内部 IM 接入"的第一课
**本章** ← 你在这里：把"应用注册 → 拿凭证 → 配权限 → 连网关"这套思路在飞书、QQ 上再走一遍，并升级到内容平台——装上能自动运营小红书的技能包
**下一章**：多平台入口就绪后，进入真实业务编排——把飞书/QQ/小红书的能力组合成自动化工作流
**阶段终点**：OpenClaw 完成部署 + 模型与通道配置 + 企微、钉钉、飞书、QQ、小红书五平台接入，成为一个"多条腿走路"的自动化助手

@@point ① 飞书准备：开放平台注册 + 创建企业自建应用
@@need 要解决什么
OpenClaw 想"变成"飞书里的一个机器人，得先有合法身份——飞书只认在开放平台注册过的应用。这一节的任务是注册开发者账号，并创建"企业自建应用"作为机器人的载体。

@@idea 核心思路
第一步：打开飞书开放平台 https://open.feishu.cn/ 并注册账号，注册流程按提示即可完成。
第二步：创建企业自建应用——这是在飞书体系里登记一个属于自己团队的"应用壳"，后面的能力、权限、机器人全部挂在这个壳上。

| 步骤 | 做什么 | 产出 |
|---|---|---|
| ① 注册 | open.feishu.cn 按提示完成注册 | 可登录开放平台的开发者身份 |
| ② 创建 | 创建企业自建应用 | 专属应用壳，准备挂机器人能力 |

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 用手机飞书 App 登录后没有"创建应用"入口 | 开发者身份要在开放平台 open.feishu.cn 注册，注册流程按提示走完才具备创建权限 |
| 找不到"企业自建应用"选项 | 该应用类型需要有企业/团队主体；先创建或加入一个团队，再回来创建应用 |

@@point ② 获取应用凭证：App ID / App Secret
@@need 要解决什么
应用建好了，但 OpenClaw 还得能证明"我就是这个机器人"。飞书给每个应用发一对凭证：App ID（公开身份）和 App Secret（密钥）。没有它们，OpenClaw 连不上飞书。

@@idea 核心思路
第三步：获取应用凭证，在应用详情页拿到两个值：
- **App ID**：应用的公开标识，相当于"用户名"；
- **App Secret**：应用的密钥，相当于"密码"——**重要：请妥善保管 App Secret，不要分享给他人**，任何人拿到它都能冒充你的机器人收发消息。

这步产出的凭证就是后面配置 OpenClaw 飞书通道（<你的AppId> 占位处的真实值）的依据。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 把 App Secret 截图发群/贴进公开仓库 | 等于公开了机器人"密码"；尽快在开放平台重置凭证，新 Secret 只存入自己的密码管理器 |
| 只记了 App ID 就关页面 | 两个值后面都要用；复制后立刻存进本地备忘录或密码管理器，别靠脑子记 |

@@point ③ 添加应用能力 + 配置权限：聊天与群组，im 双身份全开
@@need 要解决什么
光有应用壳，机器人还是"哑巴"：飞书不知道它能否进群、能否收发消息。要给应用声明权限——聊天与群组权限，并且应用身份和用户身份两类都要。

@@idea 核心思路
第四步：添加应用能力，声明这个应用提供什么功能。
第五步：配置应用权限——这里我们添加**聊天与群组权限**。注意**应用身份权限和用户身份权限都要开通**，可以搜索 im 统一选中，一次配齐。

| 权限类别 | 管什么 | 要不要开 |
|---|---|---|
| 应用身份权限 | 机器人作为应用自己收发消息 | 要 |
| 用户身份权限 | 应用在用户授权下替用户操作 | 要 |

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 只开了应用身份，群里收发消息报权限不足 | 两类身份是不同授权面；按平台做法搜索 im 统一选中，聊天与群组权限一次全开 |
| 权限列表太长无从下手 | 正确路线：搜索 im，把聊天与群组相关权限统一选中，配完再进下一步启用机器人能力，顺序别反 |

@@point ④ 启用机器人能力 + 长连接保存
@@need 要解决什么
机器人能力启用后，飞书需要知道"消息往哪里推"。OpenClaw 跑在你自己的机器上、没有公网回调地址，所以直接点保存会失败——这是实际操作中最常见的坑，需要换一条路走。

@@idea 核心思路
第六步：启用机器人能力。但在配置过程中**点击保存会失败**——缺少可访问的消息回调地址。解法：点击保存失败时弹出的提示文本中有**超链接**，点进去用 **Python 形式创建长连接**（Long Connection），让飞书通过长连接把事件实时推到本地，从而不再需要公网地址。长连接创建成功后，再回来保存配置即可通过，飞书这一侧就绪。

准备阶段记好：长连接创建时要使用应用的凭证（<你的AppId> 占位处填真实值），并确保和后面 OpenClaw 通道配置用的是同一个应用。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 点保存就一直报错 | 回调地址没配或不可公网访问；别硬填公网 URL，改用长连接（点弹出文本里的超链接，用 Python 形式创建） |
| 长连接建好了消息还是收不到 | 长连接进程必须保持运行；同时确认创建长连接用的应用与后续通道配置是同一个 |

@@point ⑤ 为 OpenClaw 配置模型和通道 + 启动网关
@@need 要解决什么
飞书一侧就绪了，但 OpenClaw 还不知道"用哪个模型思考、从哪个通道收发消息"。要把飞书这个 channel 配置进 OpenClaw，并让配置真正生效。

@@idea 核心思路
为已经完成部署的 OpenClaw 配置模型和通道（即 OpenClaw channel，如飞书）：把飞书应用的凭证填入飞书通道配置（<你的AppId> 占位处换真实 App ID / App Secret），选定一个可用的大模型后保存。
然后启动并测试，分两步走：
- **第一步：启动网关** `openclaw gateway restart`，让模型与通道配置装载生效；
- **第二步：发测试消息** 在飞书中找到你创建的机器人，发送一条消息。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 改了模型/通道配置没有反应 | 必须 `openclaw gateway restart` 重启网关，配置在重启时才装载生效 |
| 飞书里搜不到自己的机器人 | 确认机器人能力已启用、应用已发布（至少企业内部可见）；新建应用要发布后才能被搜到 |

@@point ⑥ 配对授权：批准配对码
@@need 要解决什么
消息发出去了，机器人却不会直接答话，而是回你一个配对码——这是 OpenClaw 的安全机制：防止陌生人随便用你的机器人、白嫖你的模型额度。你要批准这个配对，机器人才会为你服务。

@@idea 核心思路
默认情况下，机器人会回复一个**配对码**，你需要批准此代码：

```text
su admin
openclaw pairing approve feishu <配对码>
```

先 `su admin` 切换到部署用户（避免权限错误），再执行 `openclaw pairing approve feishu <配对码>`（把 <配对码> 换成机器人实际回复的代码）。批准后即可正常对话。

配对授权相当于一份"白名单"：只有被批准的用户，机器人才会响应。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 发消息后机器人毫无反应 | 检查网关是否已 restart、飞书通道配置是否正确、长连接进程是否还在运行 |
| 直接 approve 报权限错误 | 正确流程是 先 `su admin` 切换用户 → 再配对，别跳过切换直接批准 |
| 配对码输错或过期 | 重新向机器人发一条消息拿新配对码，再执行 approve |

@@point ⑦ QQ 平台：手机扫码注册
@@need 要解决什么
QQ 机器人的注册方式和飞书完全不同：不用填表注册开发者账号，手机 QQ 扫码一步到位。先理解这条"扫码即注册"的路径，并完成注册进入配置页。

@@idea 核心思路
前往腾讯 QQ 开放平台官网 https://q.qq.com/qqbot/openclaw/index.html ，用**手机 QQ 扫描页面二维码**进行注册/登录：
- 若当前尚未注册 QQ 开放平台：执行扫码后，系统会**自动完成注册流程**，并把扫码所用的 QQ 账号与该平台账号进行绑定；
- 手机 QQ 扫码后选择**同意**，即完成注册，进入 QQ 机器人配置页。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 用电脑浏览器直接注册找不到入口 | 官网主流程是手机 QQ 扫码；用页面显示的二维码扫码，别绕道网页表单 |
| 扫错 QQ 号 | 绑定的是你扫码所用 QQ 账号，平台归属也随之确定；先确认扫的是自己的号再点同意 |

@@point ⑧ 创建 QQBot + 获取凭证
@@need 要解决什么
注册只是拿到了平台"身份"，你还缺一个真正能用的机器人对象，以及它的凭证——AppID 和 AppSecret。OpenClaw 后续接入 QQ 时要用这对凭证。

@@idea 核心思路
在 QQ 开放平台的 QQ 机器人页面，单击**创建机器人**，即可直接新建一个 QQ 机器人。
机器人创建完成后，在页面中找到 **AppID** 和 **AppSecret** 两个参数，分别点击右侧"复制"按钮，保存到个人记事本或备忘录中（**请妥善保存勿泄露，注意数据安全**），后续步骤需要使用（<你的AppId> 占位处填真实值）。

和飞书一样：AppID 是公开标识，AppSecret 是密钥，谁拿到 Secret 谁就能控制你的机器人。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 创建完机器人找不到凭证在哪 | 在机器人详情页面找 AppID / AppSecret 两个参数，右侧有"复制"按钮，逐个点击复制保存 |
| 把 AppSecret 贴进聊天记录/共享文档 | 属于密钥泄露；尽早去开放平台重置，新 Secret 只进自己的密码管理器 |

@@point ⑨ xiaohongshu-skills 是什么：小红书自动化 Skills
@@need 要解决什么
飞书、QQ 都是"人等机器人聊"，小红书的玩法反过来了——让 OpenClaw 主动去运营账号：搜索、发笔记、互动。官方开放接口门槛高、能力受限，这里走另一条路：一套基于浏览器自动化的技能包。

@@idea 核心思路
xiaohongshu-skills 是**小红书自动化 Skills**，基于 **Python CDP 浏览器自动化引擎**。
- **CDP（Chrome DevTools Protocol）**：Chrome 浏览器提供的调试协议，外部程序通过它驱动一个真实的浏览器，像真人一样打开页面、点击、滚动、输入；
- 相比平台 API，CDP 方式**不需要申请平台开放接口**，覆盖"登录保持、页面操作、多账号切换"这类 API 难做的场景；代价是环境里要有一个可用的浏览器运行。

于是 OpenClaw 借这个技能包，就能像真人一样在小红书执行操作——这正是"基座模型 + 专用技能"组合思路的又一次实战。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为它是小红书官方 API 封装 | 它是基于 CDP 的浏览器自动化技能包，驱动真实浏览器操作页面，不是调官方开放平台接口 |
| 启动技能后浏览器打不开/连不上 | CDP 依赖本机浏览器环境；先按技能包说明核对环境要求（浏览器可用性等），再排查其他问题 |

@@point ⑩ 技能矩阵五件套：auth / publish / explore / interact / content-ops
@@need 要解决什么
技能包一口气带了五个以 xhs- 开头的子技能，各管一摊。你需要一张"谁管什么"的能力地图，否则遇到需求时不知道该叫哪个技能。

@@idea 核心思路
技能包核心能力一览（技能矩阵）：

| 技能 | 说明 | 核心能力 |
|---|---|---|
| xhs-auth | 认证管理 | 登录检查、扫码登录、多账号切换 |
| xhs-publish | 内容发布 | 图文/视频/长文发布、定时发布、分步预览 |
| xhs-explore | 内容发现 | 关键词搜索、笔记详情、用户主页、首页推荐 |
| xhs-interact | 社交互动 | 评论、回复、点赞、收藏 |
| xhs-content-ops | 复合运营 | 竞品分析、热点追踪、批量互动、内容创作 |

记忆顺序：**auth 打底 → explore / interact 动作层 → publish 产出层 → content-ops 编排层**。先保证登录态，再谈发现、互动与发布；要"运营级"动作就直接找 content-ops。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 技能报"未登录/登录失效" | 先走 xhs-auth 完成登录检查与扫码登录；auth 是其他所有技能的前提 |
| 把"批量互动""竞品分析"拆成单技能硬拼 | 这类复合运营动作由 xhs-content-ops 直接负责，它内部会自动组合多个能力，别自己拼流水线 |

@@point ⑪ 复合指令串联：一句话让多个技能接力
@@need 要解决什么
五件套是"零件"，真实需求是"整机"："帮我找最火的笔记、收藏它、再总结一下讲了什么"。自己逐个记忆技能调用细节太累，要的是**用一句自然语言，让 Agent 自动编排一整条操作链**。

@@idea 核心思路
技能包支持**连贯操作**：用自然语言下达复合指令，Agent 会自动串联多个技能完成任务。
示例指令："搜索刺客信条最火的图文帖子，收藏它，然后告诉我讲了什么"
Agent 会自动执行：**搜索 → 筛选图文 → 按点赞排序 → 收藏 → 获取详情 → 总结内容**。

拆开看这条链：搜索与排序落在 xhs-explore，收藏落在 xhs-interact，获取详情与总结由 explore + 模型理解共同完成——一条自然语言，把"发现 → 互动 → 分析"串成完整工作流。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 复合指令太模糊，编排出的链路不对 | 指令里带齐对象、动作和排序标准（如"最火 = 按点赞排序"），Agent 编排才有依据 |
| 以为复合指令是固定写死的脚本 | 每次执行按当前页面状态实时编排，登录态失效、页面改版都会影响结果；跑完核对是否真正完成了目标动作 |

@@point ⑫ 安装部署：git clone + uv sync + chown + 重启网关
@@need 要解决什么
技能包还躺在 GitHub 上，得先装进 OpenClaw 才能用。安装有四个关键动作：拉代码、装依赖、修权限、重启网关——任何一步漏掉，技能都调不起来。

@@idea 核心思路
进入服务器、以 OpenClaw 部署用户身份，按顺序执行：

```text
cd /home/admin/.openclaw/workspace/skills
git clone https://github.com/autoclaw-cc/xiaohongshu-skills.git
cd /home/admin/.openclaw/workspace/skills/xiaohongshu-skills
uv sync
cd /home/admin/.openclaw/workspace/skills
chown -R admin:admin xiaohongshu-skills
openclaw gateway restart
```

拆解四步：`git clone` 把技能包下载到 skills 目录；`uv sync` 按项目安装 Python 依赖；`chown -R admin:admin` 把克隆文件属主改回 admin，网关进程才有权读取；`openclaw gateway restart` 重启网关加载新技能——最后一步必做。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| `uv sync` 报 uv 不存在 | uv 是 Python 项目依赖管理工具，环境缺的话先安装 uv，再回到技能目录重跑 uv sync |
| 装完技能不生效 | 大概率忘了重启网关：openclaw gateway restart 后新技能才会被加载 |
| 网关读技能报权限错误 | 克隆文件属主不对：回 skills 目录执行 chown -R admin:admin xiaohongshu-skills 后重启网关 |

@@summary
这一章你实际拿到的是**四样东西**：

| 拿到了什么 | 为什么要紧 |
|---|---|
