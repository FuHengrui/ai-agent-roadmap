@@point ① 关键词抽取是干什么的
@@need 要解决什么
"这篇文章讲什么？"这个问题，机器怎么用程序回答？

@@idea 核心思路
**关键词抽取** 就是从文本中自动选出**最能代表文本主题的若干个词或短语**。典型应用：

- 文档标签自动生成、文章分类。
- 搜索引擎的文档索引与召回。
- 新闻聚合、舆情监控（快速知道热点话题词）。
- 学术论文关键词推荐。

它的直觉是：**重要的词在文本里出现得多、但又不能是到处都有的废词**。围绕这两点发展出了 TF-IDF 和 TextRank 两大算法。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 把"出现次数最多"的词当关键词 | 高频词往往是"的、了、我们"这类停用词，必须先过滤 |
| 关键词抽取结果当全文摘要 | 关键词只是"线索词"，不是有语法的摘要句，用途要分清 |

@@point ② TF-IDF：词频 × 逆文档频率
@@need 要解决什么
怎么量化"又常见又有区分度"？TF-IDF 的数学直觉是什么？

@@idea 核心思路
**TF-IDF（Term Frequency - Inverse Document Frequency）= 词频 × 逆文档频率**，是信息检索最经典的词权重算法：

- **TF（词频）**：词在**当前文档**中出现的次数/比例。出现越多越重要。
- **IDF（逆文档频率）**：`log(总文档数 / 包含该词的文档数)`。**越少文档包含它，它越能区分文档**，IDF 越大。

```
TF = 词在当前文本出现的次数 / 当前文本的总词数
IDF = log(总文档数 / (包含该词的文档数 + 1))
TF-IDF = TF × IDF
```

"的"虽然 TF 高，但几乎每篇文档都有它，IDF 趋近 0，乘积被压制；"Transformer"如果只在少数文档出现，IDF 大，权重高——这样就能同时兼顾"常见"与"有区分度"两个目标。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 忘了 IDF 需要"文档集合" | TF 是单文档统计，IDF 必须依赖语料库（多篇文档），没有语料库算不出 IDF |
| 认为 TF-IDF 能理解语义 | 它是纯统计权重，不理解词义；同义词、反义词处理不了，要看语义得用词向量 |

@@point ③ jieba 实战：extract_tags 抽取关键词
@@need 要解决什么
不自己实现 TF-IDF，jieba 一行代码能抽关键词吗？

@@idea 核心思路
jieba 的 `jieba.analyse.extract_tags` 内置了 TF-IDF 实现（默认基于 IF-IDF 权重），直接调用即可：

```python
import jieba.analyse

text = "人工智能正在深刻改变自然语言处理领域，\
大模型的出现让机器翻译的准确率大幅提升。"

keywords = jieba.analyse.extract_tags(
    text, topK=5)  # topK: 返回前5个关键词
print(keywords)
# 输出形如：['大模型', '自然语言处理', '机器翻译', ...]
```

常用参数：`topK`（返回个数）、`withWeight=True`（同时返回权重分数，便于调阈值）。它内部会自动分词并过滤停用词，非常省事。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| topK 设太大 | 返回的都是低权重词，噪音多；一般 5-10 个就够 |
| 不同版本结果不一致 | extract_tags 依赖内置 IDF 语料与 jieba 版本，升级版本后结果可能微变，属正常 |

@@point ④ TextRank：让词"投票"选关键词
@@need 要解决什么
没有文档集合（算不了 IDF）时，还能怎么抽关键词？

@@idea 核心思路
**TextRank** 借鉴了 PageRank 的思路，**只依赖当前文本内部的词共现关系**，不需要外部语料库：

1. 把文本分词、去停用词，得到候选词。
2. **窗口滑动**：在窗口大小内共现的词之间建立"投票关系"（连边）。
3. **迭代传播**：与更多重要词相连的词得分更高，迭代到收敛。
4. 按得分排序取 topK。

直觉类比：一篇文档里，"大模型"总是和"训练""参数""推理"一起出现，说明它们是同一个话题簇，互相加权抬高得分。TextRank 适合**单篇文本、无语料库**的场景（比如单独分析一篇新闻）。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为 TextRank 比 TF-IDF 好 | 无绝对优劣：有语料库时 TF-IDF 通常够用；单篇、要词间关系时 TextRank 更稳 |
| 窗口大小乱调 | 窗口太大导致所有词都相连、失分；太小关系稀疏，一般 2-5 为宜 |

@@point ⑤ 停用词：关键词抽取的隐形功臣
@@need 要解决什么
为什么抽关键词之前必须先干掉"的、了、和、在"？

@@idea 核心思路
**停用词（Stop Words）** 是"没有信息量、到处都是"的功能词（的、了、是、在、和、我、你）。它们：

- 频率极高，会霸占 TF 计算的权重。
- 不含主题信息，抽出来也是噪音。
- 在文本分类里起不到区分作用。

处理方式：维护一张**停用词表**，分词后过滤掉停用词再统计权重。jieba 内置了部分停用词处理，也可以在 extract_tags 前自行过滤，或者用 `stop_words.txt` 类文件扩展（jieba.analyse 支持 `set_stop_words`）。注意：**领域停用词**（如某平台的"点击""参与"）要按业务补充，不能只靠通用表。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 只用通用停用词表 | 业务场景有自己高频无义词（如"扫码""下单"），要叠加领域停用词 |
| 把"不""很"当停用词过滤 | 否定词和程度词在情感分析里有语义作用，不同任务停用词表不同——抽主题词和做情感分析的表不该一样 |

@@point ⑥ 词性标注是什么
@@need 要解决什么
"我喜欢研究"里的"研究"是动词，"这项研究很有价值"里的"研究"是名词——机器怎么区分？

@@idea 核心思路
**词性标注（Part-of-Speech Tagging, POS）** 就是给句子中每个词**标注词性标签**（名词 n、动词 v、形容词 a、副词 d 等），让机器知道每个词在句子里扮演的语法角色。

词性很重要，因为：

- **词义消歧**：同一个词不同词性可能含义不同（"运动"名词 vs 动词）。
- **特征工程**：很多 NLP 任务（命名实体、依存分析、问答）依赖词性作为输入特征。
- **语法理解**：知道主语、谓语、宾语，才能分析句子结构。

jieba 中对应组件是 `jieba.posseg`，`posseg.cut()` 返回"词 + 词性"对。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为一个词词性固定 | 中文词类活用严重，词性必须结合上下文判断，"研究"名动两可 |
| 混淆词性和语义 | 词性描述"语法角色"，语义描述"含义"，两者是不同维度 |

@@point ⑦ jieba.posseg 实战
@@need 要解决什么
一句中文，怎么在代码里拿到每个词的词性？

@@idea 核心思路
使用 `jieba.posseg.lcut()`（新版）或 `jieba.posseg.cut()`：

```python
import jieba.posseg as pseg

text = "我喜欢自然语言处理"
for word, flag in pseg.cut(text):
    print(f"{word}/{flag}")
# 我/r  喜欢/v  自然语言处理/n   （示意）
```

- 返回的每个元素有 `.word`（词）和 `.flag`（词性标记）。
- `pseg.lcut()` 返回列表，便于下标访问。
- 自定义词典中指定的词性会直接生效（`词 词频 词性` 的第三列），这又体现了自定义词典的价值。

词性标注结果可以直接用于：命名实体识别雏形（人名 nr、地名 ns）、关键词筛选（只保留名词/动词）、句法分析的输入。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 忘记自定义词典里的词性 | 词典第三列指定了词性，load 之后 posseg 会按它标注，别与默认结果混淆 |
| 中文词性标记看不懂 | 需要对照 jieba 词性对照表（n 名词、v 动词、a 形容词、ns 地名、nr 人名、t 时间词…） |

@@point ⑧ 常见词性标记速查
@@need 要解决什么
posseg 输出的一堆字母（nr、ns、v、d）到底代表什么？

@@idea 核心思路
jieba 采用北大词性标注体系的简化版，常见标记速查：

| 标记 | 含义 | 示例 |
|---|---|---|
| n | 名词 | 学习、苹果 |
| nr | 人名 | 张三、李白 |
| ns | 地名 | 北京、长江 |
| nt | 机构名 | 清华大学 |
| v | 动词 | 研究、跑步 |
| a | 形容词 | 美丽、快速 |
| d | 副词 | 很、非常 |
| m | 数词 | 三、一百 |
| q | 量词 | 个、只 |
| p | 介词 | 在、从 |
| c | 连词 | 和、因为 |
| x | 未知/其他 | —— |

实用技巧：抽取关键词时通常只保留 `n/v/a` 类；提人名地名做实体识别时只看 `nr/ns/nt`。词性表是 NLP 的"语法零件",不用背，用到时查表即可。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 死记硬背所有标记 | 记住高频的几个（n/v/a/r/d/ns/nr）就够起步，其他按需查表 |
| 把 jieba 词性等同标准词性体系 | 各家体系（北大、宾州）不完全一致，看文档要确认用的是哪套 |

@@point ⑨ 关键词 + 词性的组合玩法
@@need 要解决什么
关键词抽取和词性标注都学了，两者怎么配合做出更实用的功能？

@@idea 核心思路
组合起来的典型流水线：

```python
from collections import Counter
import jieba.posseg as pseg

text = "人工智能改变教育，大模型赋能千行百业。"
words = []
for word, flag in pseg.cut(text):
    if flag[0] in "nv" and len(word) > 1:
        words.append(word)
count = Counter(words)
print(count.most_common(3))
# 输出形如：'人工智能' 1, '教育' 1, '大模型' 1
```

这套组合的用处：

- **限定词性抽主题词**：只保留名词（主题词通常是名词），过滤动词形容词。
- **实体初步抽取**：筛 `nr/ns/nt` 攒出人名地名机构名候选。
- **词频画像**：统计高频名词 = 文档主题概览。

它是一把"轻量瑞士军刀"，没有深度学习也能做出可用的文本分析小工具。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 过滤规则写太死 | 词性过滤 + 长度过滤会误杀有用单字名词，按任务调阈值 |
| 文本太长直接全量统计 | 先按需求抽 topN 再分析，避免内存和时间浪费 |

@@summary
本章把关键词抽取和词性标注两把词法工具用熟了：

| 问题 | 答案 |
|---|---|
| 关键词抽取 | 选出代表文本主题的词 |
| TF-IDF | 词频 × 逆文档频率，兼顾常见度与区分度 |
| TextRank | 利用词共现关系迭代投票，无需外部语料库 |
| 停用词 | 高频无信息词，必须先过滤 |
| 词性标注 | 给每个词标语法角色（名词/动词/…） |
| posseg | jieba.posseg.cut 返回 词+词性 |
| 组合玩法 | 按词性过滤 + 关键词统计 = 主题画像 |

一句话记住本章：**抽关键词用 `extract_tags`（TF-IDF）或 TextRank，做词性标注用 `jieba.posseg`，两者都以分词为基础、都以"过滤停用词+按需筛选"为上策。**
