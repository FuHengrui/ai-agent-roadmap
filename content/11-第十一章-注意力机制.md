@@h1 第十一章　注意力机制
@@sub 阶段 22 · 自然语言处理与Transformer架构　|　注意力　|　难度 ★★★

@@why 这一章在解决什么问题
上一章末的瓶颈：解码器每一步都只能从"同一个压缩向量"里捞信息，长句必然失真。这一章给出破解方案：**注意力机制（Attention）**。它让解码器在生成每个词时，"回头查看"源句中的每一个词，按相关性分配**注意力权重**——译到哪个词就重点看原文哪几个词。这一章吃透 Q、K、V 和缩放点积注意力这两个核心概念，Transformer 的大门就开了一半。

@@map 上一章→本章→下一章
上一章 Seq2Seq 的解码器"瞎翻"长句。**本章给它装上"注意力眼镜"：按需翻看源句任意位置**。下一章把注意力的对象从"编码器输出"换成"自己"——自注意力，让一个序列内部每个词互相看，为 Transformer 做准备。

@@point ① 注意力想解决什么：解码器的"近视"
@@need 要解决什么
生成"爱"这个英文词时，解码器最应该参考原文的哪个词？固定向量给不了答案。

@@idea 核心思路
Seq2Seq 解码器的每一步都在"盲写"：它只有整句的压缩向量 z，**不知道当前输出的词最该对应原文的哪个部分**。

人类翻译的做法是**对齐（Alignment）**：译 "love" 时，眼睛盯的是原文的"爱"字。注意力机制把这种"对齐"数学化：

- 解码器每生成一个词，都计算它**与源句每个词的相似度**；
- 相似度高的源词获得高权重，被重点"阅读"；
- 把源句各词向量按权重加权求和，作为解码当前步的"精选上下文"。

直觉：**与其从整句压缩里捞，不如每个词都"回头翻原文，按需取用"**。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为注意力是"一个模块" | 它是"一种机制"：查(q)找键(k)对值(v)做加权求和，可内嵌到任何架构 |
| 混淆"注意力"和"全文拼接" | 注意力不是把所有词拼起来，而是**按权重比例**合成一个针对性向量 |

@@point ② 从数据库检索理解注意力：Q、K、V
@@need 要解决什么
"查询(Query)、键(Key)、值(Value)"这三个名字听着玄，怎么理解？

@@idea 核心思路
把注意力想象成**软性数据库查询**：

- **查询 Q（Query）**：你"要什么"——解码器当前步的需求（如：生成 'love' 需要找原文里跟"爱"相关的词）。
- **键 K（Key）**：数据的"检索标签"——源句每个词的身份描述（如："我"、"爱"、"你"）。
- **值 V（Value）**：数据的"实际内容"——源句每个词的向量表示。

查询过程：拿 Q 去和每个 K 算相似度 → 得到权重 → 按权重把 V 加权求和：

```
注意力 = Softmax(Q·K^T / √d) · V
```

结果是一个以"Q 的需求"为导引、聚合了"所有 V"的上下文向量。**Q/K 决定"看哪里看得重"，V 决定"取到什么内容"**。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 把 Q/K/V 当三个固定向量 | 不同的解码步有不同 Q；源句每个位置有自己的 K 与 V，它们是"一个集合" |
| 以为 Q 直接等于当前输入 | Q 由当前解码状态变换而来（W_q·h），K/V 由源句变换而来（W_k/W_v·h），形状与 h 相关但维度可不同 |

@@point ③ 得分函数：怎么算"相关"
@@need 要解决什么
拿 Q 和每个 K 比"像不像"，具体用什么数学量？

@@idea 核心思路
最常用的求相似度方式是**点积（内积）**：两个向量方向越一致、模长越大，点积越大。

```
score_i = Q · K_i
```

直观理解：Q（需求"爱相关"）与 K_爱（"爱"的语义身份）的点积大 → 这一位置权重高；与 K_我 的点积小 → 权重低。

完整流程：

```
1. 每个解码步算: scores = Q·K^T          # [1, 源长]
2. Softmax 归一: weights = softmax(scores)  # 和为1
3. 加权求和:     context = weights · V       # 上下文向量
4. context 与解码状态拼接 → 预测当前词
```

Softmax 保证权重和为 1（更像"比例"而非"量级"），可解释为"看源句每个词的概率分布"——这就是**注意力热力图**的来源。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 忘记 Softmax | 不归一，权重量级不可比，加权求和无意义 |
| 以为权重总是"非0即1" | 是连续比例（如 0.7 看"爱"、0.2 看"我"），不是硬对齐 |

@@point ④ 缩放点积：为什么除以 √d
@@need 要解决什么
点积算出来数值很大，Softmax 之后梯度变得极小——怎么解决？

@@idea 核心思路
公式里的 **√d 就是"缩放因子"**：

```
Attention(Q, K, V) = softmax(Q·K^T / √d) · V
```

问题背景：当向量维度 d 较大时，点积的数值会**随维度增长而变大**（多个维度求和累加），导致 Softmax 输入过大 → 软max 输出趋近"一个 1、其余 0"（饱和）→ 饱和区梯度≈0，训练困难。

除以 √d 把点积**拉回温和区间**，Softmax 分布不饱和，梯度顺畅。这是一处"不起眼但致命"的工程细节，很多新手实现漏了它导致训练不稳。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 图省事不除 √d | 大维度下梯度饱和、训练不动；小维度玩具场景看不出差别，正式用必须除 |
| 除错数（除 d 不除 √d） | 除过头会把分数压过小，区分度下降；规格是 √d |

@@point ⑤ 权重可视化：注意力可解释性
@@need 要解决什么
注意力除了提升效果，还能给我们什么"看得见"的收益？

@@idea 核心思路
注意力的 Softmax 权重就是一个**对齐矩阵**，可以直接可视化：

```
      我  爱  你        ← 源句
I     0.9 0.05 0.05    ← 生成 I 时重点看"我"
love  0.1 0.8  0.1     ← 生成 love 时重点看"爱"
you   0.05 0.1  0.85   ← 生成 you 时重点看"你"
```

用途：

- **机器翻译**：自动学到"词对齐"（中英词对），无需人工标注。
- **摘要生成**：看生成句引用了原文哪些片段（可解释 + 溯源）。
- **诊断**：翻译错了，看注意力热力图通常是"看错了词"。

这是注意力机制"自带解释性"的红利——深度模型里少有的"可审计"组件。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为注意力权重=因果解释 | 权重是"相关"信号，不一定是"因果"，下结论要克制 |
| 单层权重当全局依据 | 多层注意力叠加后对齐信息被混合，通常看"平均/最后一层"更稳 |

@@point ⑥ 注意力不只是"加个模块"：它再造了信息流
@@need 要解决什么
加上注意力机制后，Seq2Seq 的架构和信息流发生了什么变化？

@@idea 核心思路
改造后的架构（Bahdanau 2015 版思路）：

1. **编码器**：保留，输出**每一步**的隐藏状态（不再是只留最后的 z）。
2. **解码器每步**：
   - 用当前解码状态算 Q；
   - 与编码器各时刻 h 的 K 算权重；
   - 加权得到上下文向量 c_t；
   - `c_t 与当前解码状态拼接 → 预测当前词`。
3. **好处**：解码步 t 的信息来源 = **动态选取的源句片段**，而不是固定压缩 z——长句翻译质量显著提升。

信息流从"单向压缩"变成"多路按需检索"，这就是**神经机器翻译（NMT）从 2015 年起全面转向注意力架构**的原因。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为加了注意力就不需要编码器 | 编码器仍是"提供原文表示"的一方，注意力只是"取用方"，两者协作 |
| 解码器初始状态接 z 的写法忘改 | 新架构里 z 不再是唯一信息源，上下文 c_t 参与每一步预测，别只留旧写法 |

@@point ⑦ 注意力家族的常见变体
@@need 要解决什么
除了"Q·K/√d·V"，注意力还有其他形态吗？怎么选？

@@idea 核心思路
注意力按"得分函数"可分为几类：

| 变体 | 得分函数 | 特点 |
|---|---|---|
| 加性注意力 (Additive) | v^T·tanh(W·[q;k]) | 早期（Bahdanau），适用于 q/k 维度不一致 |
| 点积注意力 (Dot-product) | q·k | 简单快速，需 q/k 同维度 |
| 缩放点积 (Scaled Dot-product) | q·k/√d | Transformer 标配，数值稳定 |
| 乘法 vs 加法 | —— | 点积可用矩阵运算并行、快，工程首选 |

现代几乎统一使用**缩放点积注意力**：实现简单、GPU 并行友好、数值稳定。理解其他变体主要是为了读旧论文。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 觉得"只要是注意力就行" | 得分函数影响数值稳定性与速度，现代实现统一用缩放点积是经过验证的选择 |
| 读旧论文被加性注意力绕晕 | 记住三种的共同骨架：算分→归一→加权求和，变体只换"算分"这一小步 |

@@point ⑧ 从注意力到自注意力：下一步
@@need 要解决什么
注意力已经解决了"解码器看原文"，为什么还要再发明"自注意力"？

@@idea 核心思路
回顾注意力的形态：**Q 来自解码器、K/V 来自编码器**——这是"两个序列之间"的注意力（交叉注意力）。

接下来一个问题冒出来：**同一个序列内部，词与词之间也需要"互相看"**。比如"它站在银行旁边"里的"它"指代谁，需要"它"去和全句每个词算注意力——这就是**自注意力（Self-Attention）**：Q、K、V**全部来自同一个序列**。

自注意力的意义：

- 每个词一步直达**任意距离**的另一个词（不再靠 RNN 一步一步传）。
- 所有位置**并行**计算（不再顺序处理）。
- 它是 Transformer 的发动机，下一章就详细拆解。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 把"交叉注意力"和"自注意力"混为一谈 | 交叉：两个不同序列之间（解码器看编码器）；自注意力：同一序列内部 |
| 以为自注意力丢弃了顺序 | 顺序靠"位置编码"补上（后续章节），注意力本身确实不感知顺序——这是设计的关键细节 |

@@summary
本章把注意力机制拆到底：

| 概念 | 要点 |
|---|---|
| 动机 | 解码器需要"按需翻原文"，打破单向量瓶颈 |
| Q/K/V | 需求 / 检索标签 / 实际内容 |
| 计算 | softmax(Q·K^T/√d)·V |
| √d | 缩放防止 Softmax 饱和、梯度消失 |
| 可解释 | 权重即对齐矩阵，可热力图可视化 |
| 架构变化 | 编码器输出全时刻状态，解码器动态取用 |
| 变体 | 加性/点积/缩放点积，现代统一缩放点积 |
| 下一站 | Q/K/V 同源 → 自注意力 → Transformer |

一句话记住本章：**注意力机制 = 拿查询 Q 对每个键 K 打分，Softmax 归一后用权重加权取回值 V——它让解码器"边写边翻原文"，长句翻译质的飞跃，而同样的招式用到"自己看自己"上，就是下一章的自注意力。**
