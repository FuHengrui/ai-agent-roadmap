@@h1 第九章　皮肤主题与外观定制
@@sub 阶段 15 · Hermes-Agent 自我进化的超级智能体　|　平台实操　|　难度 ★★☆

@@why 这一章在解决什么问题
Agent 有人格（SOUL）、有能力（工具）、会做事（技能）、记得住（记忆）——**但它的"外貌"还是出厂默认**：黑底白字的终端、朴素的横幅、一个转圈的加载动画。天天看着这套界面，多少有点"工装味"。

**皮肤（skin）就是 CLI 的"换装系统"**：改横幅颜色、改旋转器表情、改响应框的标签——让终端界面有辨识度、有情绪。别小看这一步：**皮肤和 SOUL 一外一内，共同塑造"这个 Agent 是谁"的完整感知**。而且皮肤机制（YAML 配置文件）是后面 MCP、Cron 里"用配置驱动行为"思路的预热。

学完这一章，你能回答：**皮肤在 CLI 里改哪些东西、9 款内置皮肤怎么切换、`/skin` 命令怎么用、皮肤和 SOUL 的分工边界、自定义皮肤 YAML 怎么写**。五分钟完工的一章，但能让你的 Agent 从"默认款"变成"定制款"。

@@prep 开始之前
不用准备什么，也不用装环境——Hermes 能启动就能改，五分钟的事。

@@goal 学到这儿就够了
会用 /skin 在 9 款内置皮肤间切换，并能照着 YAML 改出一套自己的横幅和标签，这章就算过了。

@@map 这一章在整个知识库里的位置
**上一章（第八章）**：持久记忆——Agent"记得住"了。
**本章** ← 你在这里：皮肤主题——外观个性化（CLI 换装），内外兼修的最后一块拼图

**再往后**：定时任务与 Web 仪表板（第 11 章）——自动化与监控

@@point ① 皮肤是什么：CLI 的"外貌系统"
@@need 要解决什么
"给 Agent 换皮肤"具体能改哪些东西？皮肤到底作用在界面上的哪几处？

@@idea 核心思路
定义：**皮肤（skin）控制 CLI 的外观**，具体影响：

| 皮肤控制项 | 举例 |
|---|---|
| 横幅（banner） | 启动时显示的 Hermes 字样/配色 |
| 旋转器（spinner） | 等待时的加载动画表情 |
| 响应框标签 | 每条回复信息边框上的标签文字 |

把它类比成"终端主题"：**默认皮肤是出厂款，skin 可换 9 款内置皮肤，也支持 YAML 自定义**。操作方式是对话内斜杠命令 `/skin`。

◎ 与第 5 章的边界再划一次：皮肤改"脸"，SOUL 改"性格"——改皮肤不会让你 Agent 说话变温柔，改 SOUL 也不会让终端变好看。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为换皮肤会改变回复语气 | 皮肤只管外观（banner/spinner/标签）；语气归 SOUL.md（第 5 章） |
| 在皮肤设置里找"个性选项" | 个性的入口是 SOUL.md，别在 /skin 里找人格开关 |
| 以为皮肤只在 GUI 里能配 | 皮肤是终端/CLI 的外观系统，用 /skin 斜杠命令直接换 |

@@point ② 9 款内置皮肤 + 支持自定义
@@need 要解决什么
"换皮肤"到底有多少款可选？自定义怎么搞？先摸清供给清单。

@@idea 核心思路
一句话概括：**提供 9 款内置皮肤，支持用户自定义皮肤**。

| 皮肤类型 | 怎么获得/使用 |
|---|---|
| 9 款内置皮肤 | 通过 `/skin` 命令切换（免安装） |
| 自定义皮肤 | 写 YAML 配置文件（第 ⑤ 点）放对应目录 |

切换动作就是对话里敲 `/skin`，按提示选择想要的款式。想确认有哪些，跑一遍 `/skin` 就能看到列表。**外观定制就是这样"一行命令 + 一个选择"的轻量操作**——不是重工程量。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 想"安装皮肤"却发现没有商店 | 内置 9 款即装即用；自定义走 YAML 文件，没有额外的"皮肤市场" |
| /skin 里没有自己想要的款 | 那就写自定义 YAML（第 ⑤ 点），管够 |
| 换了皮肤重启又变回默认 | 自定义/选择的皮肤要确认保存进配置；重启后仍生效才是持久配置 |

@@point ③ /skin 命令：切换皮肤的操作入口
@@need 要解决什么
换皮肤具体怎么操作？命令长什么样？有没有"马上换、马上试"的即时反馈？

@@idea 核心思路
对话内输入斜杠命令：

```text
/skin
```

然后再跟提示选择目标皮肤即可。这个命令的核心体验是**交互式 + 即时生效**——敲了、选了、界面立刻换装，不需要重启、不需要改配置。

实际操作节奏（典型）：

| 步骤 | 动作 |
|---|---|
| 1 | 对话里输入 `/skin` |
| 2 | 列出可用皮肤（9 款内置 + 可能的自定义） |
| 3 | 选择心仪皮肤 -> 界面即时更新 |
| 4 | 不喜欢？再 `/skin` 换另一款，直到满意 |

这和 CLI 的其它斜杠命令（/tools、/cron）一致：**对话内即改即用**。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 敲 /skin 没反应 | 确认当前会话支持斜杠命令（CLI 会话内）；消息平台里某些斜杠命令语法不同 |
| 选择后外观没变 | 看终端是否支持 ANSI 彩色/表情渲染；不支持的环境换色不可见（官方皮肤依赖终端能力） |
| 以为皮肤切换要改配置文件 | /skin 对话内即改；YAML 自定义文件是"新增皮肤"的途径，两者不冲突 |

@@point ④ 皮肤配置的存在形态：YAML 与配置文件
@@need 要解决什么
自定义皮肤"写 YAML"到底写什么、放哪？皮肤配置和框架主配置文件什么关系？

@@idea 核心思路
细节上：**自定义皮肤支持在 `~/.hermes/config.yaml` 中配置，也可以通过单独的 YAML 文件（skins/ 目录）定义**。

| 配置方式 | 位置 | 适合 |
|---|---|---|
| 主配置内联 | `~/.hermes/config.yaml` 的皮肤段 | 简单改样式参数 |
| 独立皮肤文件 | `~/.hermes/skins/*.yaml` 各一个 | 一套套皮肤独立管理、可分享 |

YAML 皮肤文件的结构（示意）：

```yaml
name: my-skin
banner:
  color: "#00ff88"
  text: "Hermes"
spinner:
  frames: ["◐", "◓", "◑", "◒"]
label:
  user: "你"
  assistant: "红豆"
```

**把它当"外观配置"即可**——和 config.yaml 管理工具/技能启用的思路一脉相承（第 7 章见过"配置驱动"模式）。想自定义到什么程度，取决于你对终端审美的耐心。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| YAML 写错导致启动报错 | YAML 对缩进敏感；用 2 空格缩进、引号括字符串，改完跑 `hermes` 验证 |
| 把皮肤字段塞进 SOUL.md | 皮肤配置是 YAML（config/skins），不是 Markdown 人格文件；放错文件毫无效果 |
| 改 config.yaml 前不备份 | 动主配置先备份（cp config.yaml config.yaml.bak），改坏可回滚，这是配置操作铁律 |

@@point ⑤ 自定义皮肤完整流程：从写 YAML 到生效
@@need 要解决什么
想拥有一款属于自己的皮肤，完整流程怎么走？从文件创建到应用生效一共几个动作？

@@idea 核心思路
自定义皮肤五步走：

```text
① 创建文件   在 ~/.hermes/skins/ 下新建 my-skin.yaml（参考内置皮肤模板）
② 填写结构   name + banner/spinner/label 等字段（按 YAML 语法）
③ 验证语法   启动 Hermes 无报错 / hermes --version 类命令不带配置错误
④ 选择应用   对话内 /skin → 选 my-skin
⑤ 确认生效   观察横幅/转圈/标签变化。注意 `/skin` **只对本次会话生效**；要重启后仍然生效，得在 `~/.hermes/config.yaml` 里写 `display.skin: my-skin`
```

若不想独立文件，也可以直接在 `~/.hermes/config.yaml` 的皮肤配置块内联定义，效果等同。**核心心法：先抄内置模板，改小参数，逐步加花活**——别一上来手搓全套 YAML。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 找不到 skins/ 目录 | 不存在就自己建（~/.hermes/skins/）；或先看 config.yaml 里皮肤段写法 |
| 自定义皮肤在 /skin 列表里不出现 | 检查文件扩展名 .yaml、放在正确的 skins 目录、name 字段唯一 |
| 改了半天没效果 | 先换回内置皮肤确认基线；再逐步二分定位是哪个字段写得不对（或终端不渲染） |

@@point ⑥ 皮肤与主题：别被"theme"绕晕
@@need 要解决什么
文档里可能同时出现 skin、theme、主题——它们是不是一个东西？术语边界在哪？

@@idea 核心思路
在这个框架的语境里，**skin（皮肤）就是主题/外观的正式称呼**：

| 术语 | 在 Hermes 语境 |
|---|---|
| skin | 官方术语：控制 CLI 外观的配置单元（皮肤） |
| theme / 主题 | 用户口语/中文翻译，指的就是 skin |
| 外观定制总称 | 横幅、旋转器、标签 = 皮肤的作用范围 |

所以不用纠结"skin 和 theme 谁是谁"——**看到 skin 当作主题即可**（区别于其它框架里 theme 可能指颜色方案、font 等，这里统一叫皮肤）。唯一要防的是把"皮肤（外观）"和"个性（语气）"搞混，第 ① 点已划清。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 满世界找 "theme 设置" 找不到 | 在这套框架里入口就是 `/skin`，叫法不同，本质一个 |
| 以为 theme 会改回复风格 | 不管叫 skin 还是 theme，都是外观；人格仍然在 SOUL |
| 网上教程说"改 theme 文件" | 对应这里的皮肤 YAML；别按别的框架的术语脑补路径 |

@@point ⑦ 皮肤与配置文件的"配置驱动"理念
@@need 要解决什么
皮肤这章其实在反复出现一个词：YAML、config.yaml、配置块。这个"配置驱动"的思路为什么重要？它和后面章节什么关系？

@@idea 核心思路
皮肤系统的本质是**配置驱动的外观系统**：一切外观都由 YAML 声明的参数决定，不写死代码。这个理念贯穿 Hermes 全家桶：

| 子系统 | 配置驱动体现 |
|---|---|
| 皮肤 | skins/*.yaml 声明颜色/表情/标签 |
| 工具集 | config.yaml 声明各平台启用哪些 |
| 技能 | SKILL.md 元数据声明触发条件 |
| 记忆 | MEMORY.md/USER.md 文件即配置 |
| MCP（第 10 章） | config.yaml 声明服务器与工具 |
| 定时任务（第 11 章） | /cron 生成 cronjob 配置 |

**看到"配置"就该想到"改配置→重启/重载→验证"这套循环**（第 3 章"改网关配置必重启"同理）。理解这条主线，后面 MCP/Cron 学起来就是同一套打法。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 每章配置都从零学，觉得重复 | 抓住统一循环：**改配置→重启/重载→验证**，各章只是配置对象不同 |
| 改配置不备份 | 任何 config/skins 改动前备份是铁律；万一改坏快速回滚 |
| 只依赖 CLI 命令不愿看配置文件 | 高级玩法（自定义皮肤、MCP 精确配置）要碰 YAML；命令与文件两手都要 |

@@point ⑧ 皮肤是"锦上添花"，别本末倒置
@@need 要解决什么
有人会在皮肤上耗费大量时间（配色、转圈表情、每款都试）。需要给一个清醒的边界提示：皮肤的权重到底该多大？

@@idea 核心思路
诚实地说：**皮肤是纯外观，不改变 Agent 的任何行为或能力**。它的价值排序应该是：

| 优先级 | 该做什么 |
|---|---|
| ★★★ | SOUL/工具/技能/记忆（行为层） |
| ★★ | 网关/平台接入（可用层） |
| ★ | 皮肤外观（体验层） |

建议：**"出厂款难看就换一个顺眼的，五分钟后继续前进"**。什么时候值得深玩自定义皮肤？只有当你有明确的美观诉求（演示、分享、仪式感）时——否则让它"看得顺眼"即可。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 花一小时试 9 款皮肤 | 换装 5 分钟即可收手；时间应留给 SOUL/技能等行为层配置 |
| 以为换皮肤=调教完成 | 行为层（人格/工具/技能/记忆）才是"调教"，皮肤是外壳 |
| 因皮肤暂时无法渲染就否定框架 | 外观是增强项；核心价值在行为层，别因装点问题影响主线 |

@@point ⑨ 皮肤应用效果不佳时的排查表
@@need 要解决什么
皮肤切换后没看到变化，怎么快速定位问题？给一张按"由轻到重"排序的排查表。

@@idea 核心思路
皮肤未见效排查表（从最常见开始）：

| # | 排查项 | 动作 |
|---|---|---|
| 1 | 命令用对了吗 | 确认在对话内用 `/skin`（非终端 shell 命令） |
| 2 | 终端支持渲染吗 | ANSI 颜色/表情在部分终端/SSH 下禁用，换 Windows Terminal 等验证 |
| 3 | 选的是持久皮肤吗 | 自定义皮肤确认 name 唯一、文件在 skins/ 目录 |
| 4 | 会话重启了吗 | 若是从配置文件改的，重启 Hermes 会话让其加载 |
| 5 | 配置有语法错吗 | YAML 缩进/引号错误会静默失败；`hermes` 启动看报错 |

排查思路与工具/MCP 配置同源：**先测最小改动，再二分定位**。这条"排查逻辑"适用于全部配置类问题，不止皮肤。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 重装框架想"解决"皮肤问题 | 皮肤问题 99% 是配置/终端环境，重装解决不了还丢配置 |
| 只看命令不看文件状态 | 先看文件：皮肤选中的配置持久化了吗？YAML 合法吗？ |
| 现场只改一个变量一次性试 | 一次只改一个变量，改完重启验证，别同时改 5 个字段无从定位 |

@@point ⑩ 皮肤配置的安全与共享：别把"秘密"写进外观
@@need 要解决什么
自定义皮肤文件可以分享（跟技能一样）——但皮肤文件跟主配置同目录，万一里面有敏感信息呢？需要强调配置文件的卫生。

@@idea 核心思路
**皮肤 YAML 只声明外观字段**（颜色、表情、标签），不该出现任何凭据；但它和 config.yaml 同在一处，分享时注意：

| 场景 | 注意 |
|---|---|
| 分享皮肤文件 | 只发 skins/*.yaml（外观字段），别把整个 ~/.hermes 打包扔出去 |
| 备份整个配置目录 | 备份前检查有没有 API Key/Token 混进 config.yaml（密钥应走环境变量） |
| 用别人的皮肤 | 先读一遍 YAML 内容，确认没有可疑指令/URL 再应用 |

这延续了全书的密钥红线：**任何配置文件都不该含明文密钥；分享任何配置文件前先扫一眼**。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 把 API Key 顺手填进皮肤 YAML "方便配色" | 密钥与外观无关，绝不进皮肤文件；.env / 环境变量才是家 |
| 打包 ~/.hermes 全目录分享"我的配置" | 大概率带出密钥与私人记忆；只分享想分享的皮肤/技能文件 |
| 应用来路不明的皮肤文件 | 先审 YAML 内容再应用；配置即代码，来历不明一律警惕 |

@@point ⑪ 皮肤与多平台：CLI 之外，消息平台上能看到吗
@@need 要解决什么
把皮肤折腾到家了，微信/QQ 里看到的 Agent"长什么样"？皮肤影响消息平台吗？

@@idea 核心思路
**皮肤的改动只作用于 CLI（终端）界面**。消息平台（微信/QQ/飞书）显示的是平台自己的聊天界面，Agent 的回复文字在其中正常展示——**平台的"外观"由平台决定，皮肤管不到；但皮肤里定义的"响应框标签"等也不会出现在平台侧**。

| 界面 | 皮肤影响 |
|---|---|
| CLI 终端 | ✅ 横幅/转圈/标签全生效 |
| 消息平台聊天 | ❌ 平台界面，皮肤不参与 |

所以别指望"换个皮肤，微信里的机器人头像也变";跨平台的外观一致性不是皮肤的事。**皮肤是你的终端私享体验**——这反而让它可以大胆实验而不影响任何线上行为。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 在消息平台上找皮肤效果找不到 | 皮肤只作用于 CLI；平台界面由平台自身控制 |
| 担心换皮肤影响线上机器人行为 | 纯外观，行为零影响；随便折腾 |
| 以为平台机器人"也该配个皮肤" | 没有这个需求；平台侧的可视化在 Web 仪表板（第 11 章）有个入口 |

@@point ⑫ 小结：外观定制的"够用"清单
@@need 要解决什么
最后一节把本章压缩成一份"够用就好"的检查清单，防止过度工程。

@@idea 核心思路
外观定制"够用"清单（按序做，做完收工）：
