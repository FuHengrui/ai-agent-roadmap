@@why 这一章在解决什么问题
BERT 擅长"理解"，却写不出新文本。**GPT（Generative Pre-trained Transformer）** 走完全相反的路：用**解码器 + 语言模型目标**预训练，模型只会一件事——**预测下一个词**。可正是这"最简单"的目标，配上超大参数量与海量数据，解锁了对话、写作、代码、推理等通用能力。这一章梳理 GPT-1 到 GPT-4 的演进逻辑、RLHF 对齐技术，以及 GPT 与 BERT 的本质差异。

@@point ① GPT 的基本思路：只做一件事，预测下一个词
@@need 要解决什么
BERT 要生成文本却"不会写"，GPT 怎么设计才能生成？

@@idea 核心思路
GPT 的原则：**用标准语言模型目标（自回归预测下一个 token）预训练一个解码器式 Transformer**。

```
输入:  今天天气真 [??]
预测:  → "好"（下一个词）
```

- **结构**：只用 Transformer 的**解码器**（掩码自注意力），无编码器、无交叉注意力。
- **训练**：在海量网页/书籍上自监督学"下一个词"。
- **生成**：推理时不断把自己输出的词拼回去再预测下一个——这就是生成。

要点：**没有为任何具体任务设计结构**。翻译、问答、摘要……全是"预测下一个词"的换皮。GPT 用最朴素的目标，赌"会预测下一词，就会一切"。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为 GPT 有编码器 | GPT 只用解码器；"GPT=通用预训练 Transformer"的名字里并不含编码器 |
| 把"预训练语言模型"和"BERT 的 MLM"混为一谈 | GPT 是自回归 LM（只看左文），BERT 是 MLM（看左右）；这是两条明确的路 |

@@point ② GPT 的"免费午餐"：下游任务不用大改
@@need 要解决什么
BERT 每个任务要换头，GPT 怎么处理多任务？

@@idea 核心思路
GPT 的迁移方式是**任务提示化（Prompting）**——把任务描述成"续写"：

- 翻译："英语：Hello，中文："
- 摘要："摘要这篇文章：[原文] 摘要："
- 问答："Q：首都是哪？A："
- 情感："这段影评情感是：[影评] 情感："

用特殊分隔符（如 `翻译：`、`Q:`）把任务封装成文本，GPT 直接续写就是答案——**不需要设计任务头**。GPT-2 时代这种能力还弱，到 GPT-3 的**上下文学习（In-Context Learning）**爆发：模型看一眼示例就能模仿任务（few-shot），甚至不需要更新参数。

这就是 GPT"通用"的本质：**把一切任务翻译成"预测下一个词"**。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为 GPT 不能做分类 | 用"情感：正面/负面"式提示即可续写出标签，照样能分类 |
| few-shot 需要梯度更新 | 上下文学习只在输入里放示例，不更新权重——这是它的神奇之处 |

@@point ③ GPT-1 → GPT-2：从"能聊"到"无监督多任务"
@@need 要解决什么
GPT 1 和 2 各解决了什么，才有了后来的爆发？

@@idea 核心思路

**GPT-1（2018，1.17 亿参数）**：

- 提出"预训练 + 微调"的生成式路线（稍晚于 BERT，表现略逊）。
- 贡献：验证**解码器 + LM 也能学好语义表示**。

**GPT-2（2019，15 亿参数）**：

- 核心实验："**Larger = Better**"——大模型在未见过的任务上零样本小涌现。
- 提出**无监督多任务学习**：不微调，靠提示直接完成任务。
- 40GB WebText 语料；"语言模型就是无监督多任务学习器"。

转折点：从 GPT-2 起，"**规模**"成为主角——更多数据 + 更多参数 = 更强涌现能力。GPT2 的 15 亿参数在当时已算巨兽，为 GPT-3 的百倍规模铺路。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 把 GPT-1 当成"弱 BERT" | 路线不同：BERT 做理解、GPT 做生成；不能以单一指标定胜负 |
| 忽略规模化的意义 | GPT-2 的真正遗产是"涌现"信号——这直接决定 OpenAI 加注千亿参数豪赌 |

@@point ④ GPT-3：1750 亿参数与上下文学习
@@need 要解决什么
GPT-3 凭什么"一次训练、什么都会"？

@@idea 核心思路
GPT-3（2020）三大动作：

1. **规模**：1750 亿参数（GPT-2 的 117 倍），45TB 语料。
2. **上下文学习（In-Context Learning）**：
   - few-shot：输入里放 2-3 个示例，模型照做。
   - zero-shot：连示例都不给，直接提示。
   - 不更新任何参数——能力从"预训练知识 + 示例模式"中涌现。
3. **通用性**：写代码（Codex）、翻译、数学题、新闻生成……同一模型直接上岗。

关键洞察：**"预测下一个词"在千亿规模下，自动涌现出推理、模仿、泛化能力——这不是设计出来的，是规模喂出来的**。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为 few-shot 是微调 | 是提示词里的示例，模型权重完全冻结——"上下文学习"≠"梯度学习" |
| 迷信 GPT-3 全知全能 | 它有幻觉（编造事实）、偏见、逻辑错误，能力涌现但不完美 |

@@point ⑤ 对齐技术 RLHF：让模型听人话
@@need 要解决什么
GPT-3 会写但可能说错话、有毒、不听话——怎么把它"调教"成助手？

@@idea 核心思路
**RLHF（基于人类反馈的强化学习）** 三步走：

```
①监督微调 SFT: 人工写优质问答，让模型先模仿
②奖励模型 RM:  人类对多个回答排序 → 训练打分模型
③强化学习 PPO: 用 RM 当"裁判"，优化模型让它答得更好
```

- **步骤 1** 让模型有基本对话能力。
- **步骤 2** 把"人类偏好"变成可优化的奖励信号。
- **步骤 3** 用强化学习把偏好"内化"进模型。

效果：模型更愿意**遵循指令、拒绝有害请求、语气亲和**。ChatGPT 的高质量体验来自这一步——不是模型更"聪明"，而是更"对齐"。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 把 SFT 当 RLHF 全部 | SFT 只是第一步；RLHF 的核心价值在 RM + PPO 的偏好优化 |
| 以为 RLHF 提升知识量 | 它改变的是行为/安全/风格，不是知识水平——知识靠预训练 |
| 写"RLHF=人类反馈"就完事 | 完整三阶段（SFT→RM→PPO）才算讲清，缺一都不叫 RLHF |

@@point ⑥ GPT-4 与多模态：工程与能力的全面跃升
@@need 要解决什么
GPT-4 相对 GPT-3 到底"新"在哪？

@@idea 核心思路
GPT-4（2023）的关键事实与升级：

- **规模与数据**：未公开具体参数；更大训练量 + 更高质量数据（重保真、重清洗）。
- **多模态（Multimodal）**：输入支持**图像**（看懂图表、照片、草图），输出仍是文本。
- **能力提升**：复杂推理、长文、考试（美国律师/医师资格考过线）、代码水平显著超过 GPT-3.5。
- **安全对齐强化**：更稳的安全护栏与拒绝机制。

意义：**"泛化能力随规模上台阶"被再次验证；多模态标志着"文本预训练"向"世界理解"演进**——给模型看世界，它才对世界有常识。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为 GPT-4 只是"更大 GPT-3" | 数据质量、多模态、对齐三条线同时升级，是系统工程不是单纯堆参 |
| 夸大 GPT-4 的可靠性 | 仍有幻觉与错误，尤其多模态图像细节识别会出错 |

@@point ⑦ Hugging Face 使用 GPT：从加载到生成
@@need 要解决什么
自己机器上怎么把 GPT 模型跑起来生成一句话？

@@idea 核心思路
用 `transformers` 加载 GPT-2（本地可跑的入门选择）：

```python
from transformers import GPT2LMHeadModel, GPT2Tokenizer

tokenizer = GPT2Tokenizer.from_pretrained("gpt2")
model = GPT2LMHeadModel.from_pretrained("gpt2")

prompt = "Once upon a time"
inputs = tokenizer(prompt, return_tensors="pt")
out = model.generate(
    **inputs, max_new_tokens=50,
    do_sample=True, top_p=0.9,
)
text = tokenizer.decode(out[0], skip_special_tokens=True)
print(text)
```

要点与参数：

- `LMHeadModel` 自带语言模型头，`generate` 封装自回归生成。
- `do_sample=True` 允许随机采样（而非贪心），`top_p` 控制多样性。
- `max_new_tokens` 限制生成长度。

这就是"下载权重 → 生成文本"的标准姿势；换成 `gpt2-medium`/`gpt2-large` 只需改名字符串。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 本地直接加载 GPT-4 权重 | GPT-4 不公开权重，本地只有开源替代（LLaMA/Qwen 等）；示例用 gpt2 讲原理 |
| 不用 generate 手写循环 | 手写容易漏采样/停止逻辑，用官方 `generate` 更稳 |

@@point ⑧ GPT 与 BERT：一张表看懂两大路线
@@need 要解决什么
预训练时代最经典的二选一，到底差在哪？

@@idea 核心思路

| 维度 | BERT | GPT |
|---|---|---|
| 结构 | Transformer 编码器 | Transformer 解码器 |
| 注意力 | 双向（全可见） | 单向（掩码，只看左） |
| 预训练目标 | MLM + NSP | 自回归预测下一个词 |
| 擅长 | 理解：分类/匹配/抽取 | 生成：写作/对话/代码 |
| 迁移方式 | 任务头微调 | 提示/上下文学习 |
| 参数量级别 | 亿级（1亿-3亿） | 十亿~千亿级（GPT-3 是 1750 亿）；GPT-4 官方**未公开**参数量 |
| 代表演进 | BERT→RoBERTa→… | GPT-1→GPT-4→… |

**选型口诀**：理解类任务（分类、检索、抽取、匹配）优先 BERT 系；生成类任务（创作、对话、摘要）用 GPT 系。大模型时代两系逐渐融合（LLM 多支持理解+生成），但理解原理仍然重要。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为"解码器更强"全面替代编码器 | 编码器在理解/抽取类任务上仍有性价比优势，不是被淘汰 |
| 混淆掩码含义 | BERT 的 [MASK] 是训练任务；GPT 的掩码是注意力上三角（防看未来）——同名"掩码"，用途不同 |

@@summary
本章收束 GPT 全貌：

| 问题 | 答案 |
|---|---|
| 核心思路 | 解码器 + 语言模型目标（预测下一个词） |
| 迁移方式 | 提示/上下文学习，无需换头 |
| GPT-1→2 | 验证预训练生成式路线 + 规模化效果 |
| GPT-3 | 1750 亿参数、上下文学习、能力涌现 |
| RLHF | SFT→RM→PPO 三阶段，让模型对齐人类偏好 |
| GPT-4 | 多模态 + 数据质量 + 更强对齐 |
| 实操 | Hugging Face `generate` 几行生成 |
| vs BERT | 编码器理解系 vs 解码器生成系 |

一句话记住本章：**GPT 用"预测下一个词"这一最朴素的目标训练解码器，靠规模在 GPT-3 时代涌现出提示学习、通用任务能力，再用 RLHF 把模型调教成听话的助手，GPT-4 的多模态又把能力推向世界理解——它与 BERT 一生成一理解，共同定义了预训练大模型的完整版图，而阶段 22 的 NLP 之旅也到此收束：从词向量到 Transformer，从 ELMo 到 BERT/GPT，你已亲手走过现代 LLM 的全部关键节点。**
