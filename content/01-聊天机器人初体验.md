@@sub 阶段 1 · 大语言模型基础与工程化实践　|　难度 ★☆☆

@@why 这一章在解决什么问题
你有没有想过，ChatGPT 那种东西到底是怎么跑起来的？更实际一点：**能不能在自己电脑上跑一个——不用联网、不花钱、聊天内容不外传？**

这一章就是干这件事的。它**不教你大模型的原理**（那是后面阶段的事），也**不要求你会 Python**。它只做一件事：**把开发环境搭起来，亲手跑通一个最小的聊天机器人**。

跑通之后，你对"大模型"这个词的感觉会从"听说过"变成"**我电脑上就有一个，我知道它怎么被叫起来的**"。这个直观感受很重要——后面学 RAG、Agent 的时候，你脑子里得先有个具体的东西。

因为先啃九章语法，你会在"**不知道这有什么用**"的状态下学两个月，然后放弃。先跑通一个真东西，后面学语法时你心里有目标——"我是在补上改那个脚本的能力"。

@@point ① 什么是大语言模型（LLM）
@@need 要解决什么
你得先知道你要装的那个东西**到底是什么**，否则后面所有操作都是照抄命令，出错也不知道错在哪。
@@idea 核心思路
**大语言模型（Large Language Model，简称 LLM）就是一个"接话茬"接得特别好的程序。**

你给它一段文字，它预测"接下来最该出现什么"，然后把这段文字续下去。就这么简单——但它见得多（海量文本），所以续出来的东西常常像模像样。

准确一点的说法：它通过在**海量文本**上训练，学到了语言的**统计规律**、**语义结构**、**上下文关系**以及一部分**世界知识**，因此能完成翻译、总结、问答、写代码等大量自然语言任务。
@@trap 别被术语吓住
「大」指的是**参数量大**（几十亿到上千亿个数字）、**训练数据大**，不是指它神秘到无法理解。你完全可以在自己电脑上跑一个「小号」的——这一章就干这个。

@@point ② 为什么要跑在本地
@@need 要解决什么
网上免费的 AI 一大把，为什么要费劲在自己电脑上装一个？**因为有些场景下，联网和上传是不能接受的。**
@@idea 核心思路
这是笔明账，两边都要看：

| 本地跑的好处 | 要付出的代价 |
| **隐私**——你的合同、病历、公司代码不出本机 | **占用本地资源**——内存、显存、磁盘 |
| **低成本**——不按次数付费，跑一万次也是零 | **能力弱于云端顶级模型** |
| **可离线**——断网照用 | **要自己维护**——版本、参数都得自己管 |
| **延迟稳定**——不受网络波动影响 | 模型越大，对机器要求越高 |
@@trap 硬件不够怎么办
要求是「**8GB+ 内存**」，建议留 10GB 磁盘，无 GPU 也能跑小模型。但 4GB 档位的老机器跑 `qwen3:4b` 会非常吃力，甚至起不来。按自己的情况选：

| 内存 | 建议 |
| 4GB 左右 | 先用最小的 `qwen:0.5b` 把流程跑通——**理解每一步在做什么，比模型多聪明重要** |
| 8GB 以上 | 按推荐方案跑 `qwen3:4b` |
| 想跑更大的 | 放到有独显的机器，或用云端算力，不要在本地硬扛 |

@@point ③ 两个主角：Ollama 与 Qwen
@@need 要解决什么
大模型本身是一堆几百 MB 到几十 GB 的文件。你得有东西帮你**下载它、管理它、把它跑起来**，还得有个"窗口"让你的 Python 程序能跟它说话。
@@idea 核心思路
分工很明确：

| 角色 | 是什么 | 干什么 |
| **Ollama** | 本地模型的「管家 + 服务台」 | 下载/管理/运行模型，并在本机开一个 HTTP 接口（默认 `127.0.0.1:11434`）——**你的 Python 程序就是通过这个接口跟模型说话的** |
| **Qwen** | 通义千问系列模型 | 真正干活的「大脑」。中文友好、开源、可本地运行，体积从轻量到中等都有得选 |

记住这条链路，后面所有 AI 应用都是在这上面加东西：

```cmd
# 你的 Python 脚本
#       │  HTTP POST（发一段文字）
#       ▼
#   Ollama 服务      ← 本机 127.0.0.1:11434
#       │  调用模型
#       ▼
#   Qwen 模型        ← 真正的"大脑"
#       │  生成回复
#       ▼
#   返回 JSON  → 你的脚本打印出来
```
@@trap 新手最容易懵的地方
「Ollama」和「模型」是**两样东西**。Ollama 装了不等于有模型——你还得单独 `pull` 一个模型下来。报错 `model not found` 基本都是忘了这步。

@@point ④ 把开发环境搭起来：Python 与 PyCharm
@@need 要解决什么
要写 Python 代码，你需要**两样东西**：一个能执行 Python 的**解释器**，一个写代码顺手的**编辑器**。缺一个都干不了活。
@@idea 核心思路
| 装什么 | 它是什么 | 为什么需要 |
| **Python** | 解释器 | 真正执行你写的代码。**这是必须的** |
| **PyCharm** | 集成开发环境（IDE） | 写代码的地方。能自动补全、提示错误、单步调试。**新手强烈建议装**，因为它会帮你发现低级错误 |

装完之后，在命令行敲 `python --version` 能打出版本号，就说明装好了。

**第一个程序**——新建一个文件 `hello.py`，写一行：

```python
print("hello world")
```

然后运行它。看到终端打出 `hello world`，你的开发环境就算通了。
@@trap 这一步的坑
| 现象 | 原因 / 怎么办 |
| `python` 不是内部或外部命令 | 装 Python 时**没勾「Add Python to PATH」**。重装一遍并勾上，或手动把 Python 目录加进环境变量 |
| 装了 Python 但 PyCharm 找不到 | 在 PyCharm 里手动指定解释器路径：`Settings → Project → Python Interpreter` |
| 中文在 PyCharm 里显示乱码 | 文件编码设成 **UTF-8**；新建文件时注意右下角显示的编码 |
| 敲了 `Print` 报错 | Python **大小写敏感**，必须是小写 `print` |

@@point ⑤ Python 程序的格式：缩进、注释
@@need 要解决什么
Python 用**缩进**来表示"这几行属于同一块"，而不是像 C/Java 那样用大括号。这个设计让代码更干净，但**缩进错了程序就直接报错**——这是新手第一个高频翻车点。
@@idea 核心思路
三条规则，记住就够用：

- **缩进用 4 个空格**，不要用 Tab（或全用 Tab，但别混着来）
- **同一层的代码，缩进必须完全一致**——差一个空格都可能报 `IndentationError`
- **冒号 `:` 后面跟缩进块**：`if`、`for`、`while`、`def`、`class` 都是这个套路

注释是写给人看的，Python 会忽略：

```python
# 这是单行注释，用井号开头

"""
这是多行注释（其实是字符串），
常用来写函数的说明，
或者临时把一段代码"注释"掉。
"""

print("代码照样能跑")  # 行尾也能加注释
```
@@trap 缩进的经典报错
| 报错 | 真实原因 |
| `IndentationError: unexpected indent` | 多缩进了，或者不该缩进的地方缩进了 |
| `IndentationError: expected an indented block` | 冒号后面该缩进却没缩进 |
| `TabError: inconsistent use of tabs and spaces` | Tab 和空格混用了——**把编辑器设成「Tab 自动转 4 空格」** |

@@point ⑥ 跑通第一个聊天机器人
@@need 要解决什么
前面都是准备。这一步才是"真的跑起来"。**跑通一次，抵得上读十页原理。**
@@idea 核心思路
三步：装 Ollama → 拉一个模型 → 写个脚本调它。

**步骤 1　安装 Ollama**，到官网下载安装包，双击装完即可：<https://ollama.com/download>。装完确认服务在跑：

```cmd
> ollama --version
# 或者浏览器打开 http://127.0.0.1:11434 看看有没有响应
```

**步骤 2　拉一个模型下来**：

```cmd
> ollama run qwen3:4b
```

内存或磁盘吃紧就换小模型，命令一样只换名字：`ollama run qwen:1.8b`，甚至 `qwen:0.5b`。**首次拉取要从网上下几个 GB，慢是正常的。**

**步骤 3　写聊天脚本**，新建 `chat.py`：

```python
import requests

MODEL   = "qwen3:4b"   # 如果你拉的是小模型，改成对应名字
API_URL = "http://127.0.0.1:11434/api/chat"


def chat_once(prompt: str) -> str:
    """问一次，返回模型的回答。"""
    resp = requests.post(
        API_URL,
        json={
            "model": MODEL,
            "messages": [{"role": "user", "content": prompt}],
            "stream": False,        # 一次性返回，不做流式输出
        },
        timeout=30,
    )
    resp.raise_for_status()          # 出错了直接抛异常，别硬撑
    data = resp.json()
    return data["message"]["content"]


def main() -> None:
    print("输入提问（输入“再见”退出）：")
    while True:
        user_input = input("> ").strip()
        if user_input == "再见":
            print("再见！")
            break
        if not user_input:
            continue
        try:
            reply = chat_once(user_input)
            print("Qwen:", reply)
        except requests.RequestException as exc:
            print(f"请求失败：{exc}")


if __name__ == "__main__":
    main()
```

运行：

```cmd
> python chat.py
```

看到 `>` 提示符就可以打字了。打「你好」，它会回你一句。
@@trap 这一步最容易踩的坑
| 现象 | 原因 / 怎么办 |
| `requests` 找不到 | 没装库。执行 `pip install requests` |
| 连接被拒绝（Connection refused） | Ollama 服务没在跑。重新打开 Ollama，看任务栏有没有它的图标 |
| `model not found` | 还没 `ollama pull` 这个模型，或者 `chat.py` 里的名字写错了 |
| 回一句话要等很久 | 内存不够跑大模型的正常表现。**换更小的模型**是唯一现实的办法 |
| 整个电脑卡死 | 内存被吃满了。用 `ollama stop <模型名>` 停掉，换小模型 |

@@point ⑦ 报错了怎么办：读懂错误的三个位置
@@need 要解决什么
新手看到一屏红字就慌。其实 Python 的报错信息**结构非常固定**，读懂了你自己就能修，不用每次都问人。
@@idea 核心思路
报错信息分三部分，**从下往上读**：

```cmd
Traceback (most recent call last):
  File "chat.py", line 12, in <module>     ← ② 出错的位置
    print(1 / 0)
ZeroDivisionError: division by zero         ← ① 错误类型和原因
```

- **① 最后一行**：错误类型（`ZeroDivisionError`）+ 原因（除以零）。**先看这个**
- **② 往回找**：哪一个文件、哪一行。行号是最有用的线索
- **③ 中间的调用链**：多层函数调用时能看出"是谁调用了谁"

三个最常见的错误类型：

| 报错类型 | 什么意思 | 常见原因 |
| `SyntaxError` | 语法错误 | 少括号、少冒号、拼错关键字 |
| `IndentationError` | 缩进错误 | 见前面第 ⑤ 点 |
| `NameError` | 名字未定义 | 变量名拼错，或者用在了定义之前 |
| `TypeError` | 类型不对 | 字符串和数字相加、参数个数不对 |
@@trap 两个坑
**坑一：看不出来就把报错原文复制去搜。** 不要只搜"我的程序报错了"——把 `ZeroDivisionError: division by zero` **整句**丢进搜索引擎，十有八九有人踩过。

**坑二：改一个地方就重跑一次。** 新手常犯的错是一次改五处，结果不知道是哪一处生效了。**一次只改一个地方。**

@@point ⑧ Python 是什么，能干什么
@@need 要解决什么
学语言之前先搞清楚：**为什么是 Python？** 编程语言那么多，选错方向会浪费很多时间。
@@idea 核心思路
一句话：**Python 是"门槛最低、但能干重活"的语言。**

它的特点是**语法接近英语、代码短**，同样的功能，Python 常常只有 Java 的三分之一长度。代价是运行速度比 C/C++ 慢——但在 AI 这个领域，**真正的计算是底层 C++ 库在做**，Python 只是"指挥"，慢不到哪去。

Python 在 AI 领域的三个主要岗位方向：

| 方向 | 干什么 | 需要额外学什么 |
| **算法工程师** | 训练/微调模型 | 数学、PyTorch、论文 |
| **AI 应用工程师** | 用现成模型搭产品 | 后端、数据库、**大模型 API**、RAG/Agent |
| **数据工程师** | 数据采集、清洗、管道 | SQL、分布式、调度 |

**这套笔记主要奔着第二个去的**——不要求你会训练模型，要求你会**把模型用起来**。这是个好消息：门槛低得多，岗位需求还很多。

@@note info 必须听的正确学习方法
先记住四条学习方法：

- **敲，不要只看。** 照着敲一遍。看懂和敲出来是两码事
- **允许自己忘。** 忘了就查，查多了自然记住。**不要因为记不住就停下来背**
- **先跑通，再深究。** 遇到不懂的先跳过，把流程跑通；回头再看，很多地方自动就懂了
- **出错了才是学习发生的时候。** 一次就过说明太难的不够，或者你在抄
