@@h1 第五章　词向量与Word2Vec
@@sub 阶段 22 · 自然语言处理与Transformer架构　|　词向量　|　难度 ★★☆

@@why 这一章在解决什么问题
上一章的 NLTK、前面的 jieba 都是在"处理词的表面形式"，但机器要学会"词义"，必须把词变成**数值向量**。最简单的 one-hot 编码为什么不行？怎么用稠密向量让"国王-男人+女人≈女王"？这一章吃透 **Word2Vec**：从 one-hot 的缺陷、分布式表示思想，到 CBOW、Skip-gram、负采样的完整原理。

@@map 上一章→本章→下一章
前四章解决的是"词的形态"，本章解决"词的语义"——**用向量把词义装进去，语义相近的词在向量空间离得近**。下一章进入序列建模：RNN 处理"有顺序的文本"，其中每个词的输入就是本章的向量。

@@point ① one-hot 编码：最朴素也最笨的表示
@@need 要解决什么
词要变成数字，最简单的办法是什么？它有什么天生缺陷？

@@idea 核心思路
**one-hot（独热）编码**：为词汇表里每个词分配一个唯一位置，该位置为 1，其余为 0：

```
词汇表：[苹果, 香蕉, 西瓜, ...]
苹果 → [1, 0, 0, ...]
香蕉 → [0, 1, 0, ...]
```

实现简单、可解释，但缺陷致命：

1. **维度爆炸**：词汇表有几万几十万个词，向量就有几万几十万维，绝大部分是 0，极度稀疏。
2. **无语义**：任意两个词向量的"距离"都一样（正交），"苹果"和"香蕉"与"苹果"和"汽车"在向量上毫无差别，语义关系完全丢失。
3. **无法计算相似度**：内积恒为 0，词之间"远近距离"没有意义。

一句话：one-hot 只区分了"你是谁"，没表达"你像谁"。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为 one-hot 只是维度大一点 | 它不只是维度问题，而是语义真空：任何两词等价，模型无法利用词义 |
| 想用 one-hot 做相似度 | 余弦相似度恒为 0，方案不可行，直接换分布式表示 |

@@point ② 分布式表示：让词义"摊"到每个维度上
@@need 要解决什么
怎么用一个不稀疏、又能表达语义的向量表示词？

@@idea 核心思路
**分布式表示（Distributed Representation）** 的核心思想：**用一个稠密低维向量（如 100~300 维）描述词，向量的每一个维度都承载部分语义特征**，整体由数据自动学出来。

比如学完后，"水果"相关语义可能集中在某些维度：

```
苹果 → [0.9, 0.1, 0.8, ...]   （水果、甜味、可吃...）
香蕉 → [0.8, 0.2, 0.9, ...]
汽车 → [0.1, 0.9, 0.1, ...]   （机械、交通工具...）
```

这样语义相近的词，向量距离就近，相似度可计算。**稠密 + 低维 + 语义可类比**，这就是词嵌入（Word Embedding）的基本形态，也是说好"果实"的 Word2Vec 的产出物：模型训练好后，Embedding 表的每一行就是一个词的向量。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为词向量是"人设计的特征" | 词向量的每个维度没有固定含义，是模型从语料中自动学出的隐含特征 |
| 词向量维度越大越好 | 维度增大收益递减、成本上升，300 维左右通常够用，视语料规模定 |

@@point ③ Word2Vec：让词向量从语料里"长出来"
@@need 要解决什么
前面说分布式表示好，那具体怎么从一堆文本里训练出这些向量？

@@idea 核心思路
**Word2Vec（2013，Mikolov）** 是基于神经网络的无监督词向量训练方法，核心思想一句话：**"看一个词的上下文，就能知道这个词的意思"**（distributional hypothesis：语义由分布决定）。它有两个变体：

- **CBOW**：用上下文词**预测中心词**（"__ 在 河边" → `bank`）。
- **Skip-gram**：用中心词**预测上下文词**（`bank` → "__ 在 河边"）。

训练不需要人工标注：只要扔进大海量无标注文本（语料），模型通过反复"填词"游戏，最终学到的模型参数（嵌入矩阵）就是词向量。这是"预训练词向量"理念的鼻祖。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为 Word2Vec 是"一个模型" | 它是"两套结构（CBOW/Skip-gram）+ 若干训练技巧（负采样/分层softmax）"的家族 |
| 以为词向量是训练的"目的" | 对外目标是词向量，模型内部目标其实是"预测概率"，向量是副产品——但正是这个副产品最值钱 |

@@point ④ CBOW：上下文猜中心词
@@need 要解决什么
CBOW 具体怎么训练？"我 __ 学习"里的空格填什么？

@@idea 核心思路
**CBOW（Continuous Bag-of-Words）**：输入是中心词**前后窗口内**的上下文词向量，输出是中心词的概率分布。

训练流程：

1. **初始化**：随机初始化词嵌入矩阵（每个词一个向量）和参数。
2. **滑动窗口**：窗口大小设为 2，每移动一位取一批训练样本：`[我, 爱, 学习]` 中的"爱"为中心词，上下文是 ["我", "学习"]。
3. **前向**：把上下文词向量求和/平均，过 Linear+Softmax 得到词汇表每个词的概率。
4. **反向**：让"爱"这个真实词的概率最高，用交叉熵算损失，反向传播更新嵌入矩阵和参数。
5. **循环**：不断滑窗、训练，直到损失收敛。

CBOW 结构简单、训练快，适合**中小语料**；多个上下文词的信息被"求和平均"，长距离信息容易稀释。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 忘了窗口大小的影响 | 窗口越大上下文越丰富但训练越慢；常用 2~10，任务不同可选不同 |
| CBOW 上下文词做平均丢了顺序 | 这是 CBOW 的设计取舍：快但忽略词序细节，需要词序信息就选 Skip-gram |

@@point ⑤ Skip-gram：中心词猜上下文
@@need 要解决什么
反过来，用中心词预测周围词，结构上有什么好处？

@@idea 核心思路
**Skip-gram**：输入一个中心词向量，输出它**上下窗口内每个词**的概率分布。

同样的窗口，样本是：

```
中心词: 爱 → 上下文: 我、学习
```

训练时每个中心词要分别去预测每个上下文词，等于同一对关系被反复强化。它的特点：

- **每个词作为"独立预测器"**，学到的向量对**词的语义细节、低频词**更敏感。
- 训练更慢（样本量更大），但**语料大、词频低时效果更好**。
- 因此**Skip-gram 通常比 CBOW 更准**，特别是稀有词，是工程上更常用的选择。

选型口诀：**语料小选 CBOW（快），语料大/重视低频词选 Skip-gram（准）**。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为两个模型结果一样 | CBOW 平滑、快；Skip-gram 精细、慢、对低频词友好，生成的向量质量通常更高 |
| 选了 Skip-gram 却嫌慢 | 它有办法提速：负采样、子采样高频词，下面介绍 |

@@point ⑥ 负采样：让训练"轻快"起来
@@need 要解决什么
词汇表 10 万词，每次预测都要算 10 万类的 Softmax，太慢了怎么办？

@@idea 核心思路
**负采样（Negative Sampling）** 把"十万分类"问题改成"二分类"问题：不预测全词表，而是**判断"这个词是不是真正的上下文词"**。

- 正样本：真实出现的（中心词, 上下文词）对。
- 负样本：随机从词表采样几个"干扰词"（如 (中心词, 香蕉)），告诉模型"这俩不该配对"。

每次更新只计算**1 个正样本 + k 个负样本**（k 通常 5~20），计算量从 O(词表大小) 降到 O(k)，训练速度暴涨，效果却几乎不损。负采样也是现代很多语言模型训练的标准技巧（如 word2vec gensim 默认实现、部分推荐系统）。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 负采样数量越大越好 | k 太大增计算且边际收益递减，5-20 是常用范围 |
| 以为负采样改变词向量含义 | 它只改"训练方式"（损失函数），不改变"学到语义相近向量"的目标 |

@@point ⑦ 训练流程全貌：从语料到向量
@@need 要解决什么
给一个真实项目，怎么从零把 Word2Vec 训练出来？

@@idea 核心思路
完整训练流程五步：

```python
from gensim.models import Word2Vec
import jieba

# 1. 准备语料：每句话分词成词列表
corpus = ["人工智能改变教育", "大模型赋能千行百业"]
sentences = [list(jieba.cut(s)) for s in corpus]

# 2. 训练模型
model = Word2Vec(
    sentences,
    vector_size=100,  # 词向量维度
    window=5,         # 上下文窗口
    min_count=2,      # 低频词过滤
    sg=1,             # 1=Skip-gram, 0=CBOW
    negative=5,       # 负采样个数
    epochs=10,        # 训练轮数
)

# 3. 使用：查向量/找相似词/类比
v = model.wv["人工智能"]
sim = model.wv.most_similar("大模型")
print(v[:3], sim)
```

工程要点：语料和质量决定上限（越大越好、清洗越干净越好）；`min_count` 过滤罕见词防噪声；训练后 `model.save()` 存档复用。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 用少量句话训练就指望有效果 | 词向量靠统计共现，语料至少几十万句级别才有语义；玩具语料只能跑通流程 |
| 不设 min_count | 只出现一两次的词学不到稳定向量，纯噪声，过滤掉更干净 |
| 训练完不保存 | 训练耗时，`model.save()` 后直接加载推理，别反复重训 |

@@point ⑧ 评估词向量：类比是黄金标准
@@need 要解决什么
训练完怎么判断词向量"有没有学到语义"？怎么证明"国王-男人+女人≈女王"？

@@idea 核心思路
经典评估手段：**词向量类比（Word Analogies）**。利用向量的可加性：

```
vec("国王") - vec("男人") + vec("女人") ≈ vec("女王")
```

代码验证：

```python
result = model.wv.most_similar(
    positive=["女人"], negative=["男人"], topn=1
)
# = vec(男人->女人 方向) + 关系 检索
```

另一种简单评估是 **most_similar / similarity 直觉检查**：

```python
print(model.wv.most_similar("北京"))  # 应出现:上海、广州...
print(model.wv.similarity("猫", "狗"))  # 应高于 猫 vs 汽车
```

质量判断标准：**同义词/同类词近，反义词/无关词远；类比关系成立**。正式评测用 Google Analogy 数据集、词相似度数据集打分。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 拿低频词做类比 | 低频词向量不可靠，类比要挑高频、语义明确的词 |
| 期望类比完美成立 | 向量类比是"倾向性"结果，top1 不一定精确，看 topN 整体质量 |

@@summary
本章把词向量从概念到实践讲透了：

| 问题 | 答案 |
|---|---|
| one-hot 缺陷 | 维度爆炸、无语义、距离开不了 |
| 分布式表示 | 稠密低维向量，语义相似则向量相近 |
| Word2Vec 变体 | CBOW（上下文猜中心词）、Skip-gram（中心词猜上下文） |
| 负采样 | 二分类加速，每次只算 k 个负样本 |
| 训练流程 | 语料 → 分词 → 设参训练 → 保存 → 评估 |
| 评估 | most_similar / 类比（国王-男人+女人≈女王） |
| 选型 | 语料小 CBOW、语料大 Skip-gram |

一句话记住本章：**Word2Vec 用"看上下文猜词"的预训练，把词映射成稠密语义向量，one-hot 的维度灾难和语义真空都被治愈，而 CBOW/Skip-gram 的选择、负采样和语料质量决定了向量好不好用，下一章我们就把词向量喂给 RNN 处理序列。**
