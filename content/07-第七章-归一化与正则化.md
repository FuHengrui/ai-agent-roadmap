@@h1 第七章　归一化与正则化：量纲对齐与防止过拟合
@@sub 阶段 20 · 机器学习算法与工程实战　|　特征工程与正则化　|　难度 ★★☆

@@why 这一章在解决什么问题
上一章结尾的预告实验暴露了实战头号杀手：**特征量纲悬殊**。年龄 25 岁、收入 80000 元、身高 1.75 米——这些数字单位不同、量级不同，直接喂给梯度下降，损失地形被拉成"峡谷"，怎么调学习率都别扭。这一章先解决**归一化/标准化**（把数据压到同一量纲），再顺势解决第二个实战大坑：**过拟合**——模型把训练数据背得滚瓜烂熟，新数据一来就露馅。防过拟合的通用武器就是**正则化（regularization）**，也就是"给模型戴枷锁：不许你太放肆"。

两个问题一个在数据侧（归一化）、一个在模型侧（正则化），是数据挖掘工作流里出现频率最高的两个动作。学完本章，你能解释"为什么好多教程第一行都是 StandardScaler"以及"为什么 L2 正则叫 Ridge、L1 正则叫 Lasso"。

@@map 上一章→本章→下一章
上一章代码实验看到量纲问题让梯度下降收敛困难。**本章先给数据做"美容"（两种归一化及其对比），再讲模型"戴枷锁"（L1/L2 正则化），并回答欠拟合与过拟合的判断**。下一章把这些工具组装成完整武器：Ridge/Lasso/ElasticNet 与多项式升维，最后用"保险花销预测"这个大案例把所有招式串起来。

@@point ① 为什么必须归一化：峡谷与碗
@@need 要解决什么
归一化到底解决了什么数学问题？用上一章的"峡谷"意象把它彻底讲透。

@@idea 核心思路
当特征量纲差异巨大（x1 在 0~1，x2 在 1万~2万）：
- 损失函数等高线被拉成**又长又窄的椭圆峡谷**：短轴方向（小特征）陡峭、长轴方向（大特征）平缓。
- 梯度下降在一个方向步长太大（震荡）、另一个方向步长太小（龟速），同一学习率顾此失彼。
- 归一化把各特征按同一尺度缩放后，等高线变回**圆形碗**，梯度下降在任何方向步进均匀，收敛丝滑。

一句话：**归一化是为迭代优化器（梯度下降）服务的"地形整形术"**。解析解一步到位、无迭代，所以不归一下也能算——但工程上几乎总是加上，因为还有下一节的收益。

此外归一化还有两个附带收益：①让各个特征的权重系数 w 可比（否则"收入"的系数天然比"年龄"小，不代表不重要）；②与正则化配合时，惩罚更公平。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 数据量纲统一了还坚持不归一化 | 权重不可比、正则化偏斜；**默认归一化是工程习惯**，除非特征天然同量纲 |
| 以为归一化能修好所有收敛问题 | 只是"地形成型"；学习率、初始化、轮次仍是独立要调的参数 |

@@point ② 最小-最大归一化（Min-Max Scaling）
@@need 要解决什么
第一种归一化：把数据压到 [0, 1] 区间。公式是什么？有什么局限性？

@@idea 核心思路
**最小-最大归一化**：用最大值最小值把数据线性映射到 [0,1]：
```
x_norm = (x - x_min) / (x_max - x_min)
```
- 特点：**区间确定**（严格 [0,1]），保留原始分布形状（线性变换）。
- 实现：sklearn 的 `MinMaxScaler`。
- **致命局限**：对**离群值极敏感**。数据里混进一个超大值，x_max 被拉大，其余所有样本挤到 0~0.1 一小截，信息被压缩。所以数据有离散点/长尾分布时慎用。

适用场景：对值域有硬性要求的算法（如图像像素 0~255 归一、神经网络输入的固定范围）。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 数据有离群值，归一化后大部分点挤在一起 | MinMax 被离群值带偏；改用标准化或先做离群值处理 |
| 测试集到来时用测试集的 min/max 算 | **必须用训练集算出的 min/max**（否则训练/预测口径不一），见第④点 |

@@point ③ 标准归一化（StandardScaler）
@@need 要解决什么
推荐程度最高的标准化叫什么？它把数据变成什么分布？为什么"减均值除方差"是标配？

@@idea 核心思路
**标准归一化（标准分数/标准化）**：对每个特征，减均值、除标准差（方差开方）：
```
x_std = (x - μ) / σ
```
- 变换后数据**均值为 0、方差为 1**，近似标准正态分布 N(0,1)。
- sklearn 的 `StandardScaler(with_mean=True, with_std=True)` 正是同时完成"均值归一化 + 方差归一化"——这也是它名字的由来（同时做均值和方差归一化已成了特征工程的标准动作）。
- 相比 MinMax：**对离群值容忍度高**（σ 由全体数据统计，单个离群点影响有限），且不锁定区间、保留了数据的相对分布结构。

**结论：默认首选 StandardScaler。** 保险实战、逻辑回归、以及几乎所有 sklearn 示例都用它。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 标准化后出现负数或超 1 的值，以为错了 | 标准化的结果本来就不限区间，可正可负可超 1；正常现象 |
| 用 MinMax 的思维要求 StandardScaler 的区间 | 两者定位不同：要区间找 MinMax，要鲁棒+正态用 StandardScaler |

@@point ④ 训练集与测试集同分布：fit 与 transform 的纪律
@@need 要解决什么
标准化时最容易踩的坑：测试集怎么算均值方差？什么时候用 fit，什么时候用 transform？

@@idea 核心思路
金科玉律：**一切预处理参数只能从训练集学，测试集只用同一套参数变换。**
```python
from sklearn.preprocessing import StandardScaler

scaler = StandardScaler().fit(x_train)      # ① 只用训练集算 μ、σ
x_train_scaled = scaler.transform(x_train)  # ② 训练集变换
x_test_scaled = scaler.transform(x_test)    # ③ 测试集用同一套 μ、σ 变换
```
为什么？因为我们**假设训练集和测试集来自同一分布**：
- 若测试集用自己的 μ、σ 另算，等于给测试集"作弊"了一组新坐标系，分布假设被破坏。
- 实际部署时新数据一批批来，不可能先等它们算全局均值——只能沿用训练时的 scaler。

**常见错误**：对测试集调 `fit_transform`（重新算了 μ、σ）；正确姿势是只对训练集 fit，测试集仅 transform。同时注意：**scale 要在切分完之后做**（先切分，再对训练部分 fit），否则切分前的整体归一已经"看了一眼"测试集，造成信息泄漏。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 对测试集也 fit_transform | 默认了训练/测试各自分布，违背同分布假设；务必改成 transform |
| 先归一化全量数据再切分 | 归一化参数里已经混入测试集信息 = **数据泄漏**，测试成绩虚高；先切再 scale |
| 忘记把训练好的 scaler 与模型一起保存 | 部署时新数据没有 μ/σ 可用，预测口径崩；**scaler 与模型打包保存** |

@@point ⑤ 欠拟合与过拟合：模型的两个极端状态
@@need 要解决什么
"模型不好"具体是哪种不好？得先给问题命名，才能对症下药。

@@idea 核心思路
| 状态 | 训练误差 | 测试误差 | 本质 | 比喻 |
|---|---|---|---|---|
| 欠拟合 | 高 | 高 | 模型太简单，没学到规律 | 学渣：卷子做不对，新题也不行 |
| 刚好 | 低 | 低 | 学到规律又没死记 | 学霸：会举一反三 |
| 过拟合 | 低 | 高 | 模型太复杂，背下了训练数据 | 背答案：原题满分，新题露馅 |

关键判据：**只看测试集误差**。训练误差低、测试误差高 = 过拟合；两者都高 = 欠拟合。

造成过拟合的常见原因：模型复杂度超过数据信息量（特征太多、多项式阶数太高、训练太久、数据太少）。治理手段正是本章主角——**正则化**，以及更多的数据、更简单的模型。

欠拟合治理：换更复杂模型、加特征、多项式升维（下一章）。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 拿训练集 99 分到处炫耀 | 过拟合假象；**荣誉只属于测试集** |
| 误把"数据噪声大"当欠拟合 | 先看测试误差：噪声大只会让下限抬高，拟合不足是"趋势都没学到" |

@@point ⑥ 正则化的核心思想：好模型 = 拟合 + 简洁
@@need 要解决什么
如何用数学方式"阻止模型死记硬背"？核心思想就一句话，理解它胜过背十页公式。

@@idea 核心思路
**正则化（regularization）**：在损失函数后面加一项"惩罚项"，让目标变成：
```
总损失 = 数据拟合损失 + λ · 惩罚项(W)
```
- 数据拟合损失（如 MSE）：逼模型把训练数据拟合好。
- 惩罚项：**逼模型的权重 W 尽量小**（越简单越好）。W 大 = 特征被赋予"夸张"的杠杆，往往是过拟合的信号。
- λ（lambda，超参数）：**惩罚力度**。λ 大 → 更看重简洁（W 变小），λ 小 → 更看重拟合。

**本质权衡：牺牲一点点训练集正确率，换取测试集上的泛化能力。** "让模型收敛但别太自信"——这句话是对正则化最直觉的理解。线性回归三大正则化衍生算法（Ridge/Lasso/ElasticNet）全是这个公式的不同变体，下一章登场。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为加了正则化训练误差会不变 | 必然稍微变差（牺牲拟合）——**这是理性交换**：换泛化 |
| λ 设成 0 | 退化成普通回归，正则化白加；λ 过大则欠拟合（W 被压扁） |

@@point ⑦ 两种惩罚：L1 与 L2
@@need 要解决什么
惩罚项具体怎么定义？L1 和 L2 一字之差，效果天壤之别。

@@idea 核心思路
- **L2 惩罚**：惩罚项 = Σ w_j²。惩罚"大权重"——权重越大罚越狠。效果：把权重向 0 压缩但不精确到 0，所有特征都保留一点贡献 → **系数整体变小、模型平滑**。
- **L1 惩罚**：惩罚项 = Σ |w_j|。罚的是"绝对大小"。效果：部分权重**被精确压成 0**，即特征选择——不重要的特征直接被"裁员" → **稀疏模型**。

直观理解（从梯度下降更新公式看）：
- L2：每步更新时权重额外乘一个略小于 1 的系数，整体"缩水"，谁也到不了 0。
- L1：每步更新时权重额外减一个常数，小权重被"磨"成 0（小于常数直接归零）。

选型：特征多且怀疑大量无用 → L1（Lasso，裁员省内存、可解释）；特征都有价值、要稳定平滑 → L2（Ridge）；两个都要 → ElasticNet（下一章）。注意这些惩罚的单位与量纲相关，反过来再次印证**先归一化再正则化**的秩序。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| L1/L2 记反 | 记"L1 像剪刀剪掉不重要的轴（到0），L2 像海绵把大的压小（不到0）" |
| 归一化前直接上 L1/L2 | 量纲大的特征被罚得重（不公平）；**先 StandardScaler 再正则** |

@@point ⑧ 惩罚强度 λ 的调参：牵一发动全身
@@need 要解决什么
λ 怎么定？设多大合适？调它的时候模型发生了什么变化？

@@idea 核心思路
作用链条（务必按序理解）：
```
λ 增大 → 惩罚加重 → 权重 W 整体变小 → 模型更简单 → 训练误差↑ 测试误差先↓后↑
```
- λ 太小：几乎不约束，过拟合。
- λ 过大：权重被压扁，模型欠拟合（退化成"预测均值"）。
- **最优 λ 在中间**：测试误差最低点。

调参手段：画"λ vs 测试误差"曲线，找谷底（网格搜索 GridSearchCV 是工程标准，后续章节展开）。经验起步：`alpha=1e-3 ~ 10` 范围试，或直接用 `RidgeCV`/`LassoCV` 自动选。

**含义提醒**：λ 是"超参数"，不是"模型参数"——它不通过学习学到，要靠人/自动搜索设定。模型参数（w）由训练学得，超参数由人的经验或搜索决定，这两个概念是整个机器学习调参体系的地基。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 只调 λ 不看曲线，凭感觉 | 用"λ-误差曲线"或交叉验证选参，别拍脑袋 |
| 把 λ 当模型参数以为 fit 会学它 | λ 是超参数，fit 学的是 w；λ 靠外部搜索（GridSearchCV）定 |

@@summary
本章两块拼图完成：

| 问题 | 答案 |
|---|---|
| 为什么归一化 | 量纲悬殊把损失地形拉成峡谷，梯度下降收敛变难；归一化整形回碗 |
| Min-Max | (x-x_min)/(x_max-x_min)，区间固定但怕离群值 |
| StandardScaler | (x-μ)/σ，均值0方差1，鲁棒，**默认首选** |
| fit/transform 纪律 | 只对训练集 fit，测试集沿用同一套参数；先切分再 scale |
| 欠拟合/过拟合 | 看测试误差：都高=欠拟合；训练低测试高=过拟合 |
| 正则化思想 | 损失 + λ·惩罚(W)，牺牲拟合换泛化 |
| L1 vs L2 | L1 权重砍到0（稀疏/选特征），L2 权重压小但不到0（平滑） |
| λ 怎么调 | 超参数，靠 λ-误差曲线/交叉验证找中间谷底 |

一句话记住本章：**归一化（默认 StandardScaler，只从训练集学参数）把数据地形整回碗形；正则化在损失上按权重大小加罚（L1 砍到0、L2 压小），用牺牲一点训练精度换测试泛化——过拟合的"背答案"就靠它治。**
