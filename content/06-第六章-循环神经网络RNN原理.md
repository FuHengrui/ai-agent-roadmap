@@why 这一章在解决什么问题
"我在银行取钱"和"我在河边钓鱼"，同一个"银行"意思完全不同——因为上下文不同。前面学的全连接网络、CNN 都是**各输入独立处理**的，处理不了这种"前后词互相依赖"的序列。这一章介绍序列建模的第一件武器：**循环神经网络（RNN）**——它凭什么能记住前面说过的话、怎么训练、又有什么天生缺陷（梯度消失/爆炸）。

@@point ① 为什么需要 RNN：序列的"前后依赖"
@@need 要解决什么
"bank"到底是银行还是河岸？普通网络为什么答不出来？

@@idea 核心思路
语言是**有顺序、有依赖**的：当前词的含义依赖前文。经典例子：

- "我在**银行**取钱" → bank=银行。
- "我在河边**钓鱼**"、"They stood on the river **bank**" → bank=河岸。

全连接网络、CNN 处理的是**固定长度、彼此独立**的输入——每个词被单独编码，前文的"河边"无法影响"bank"的理解。这就需要一个能**把前面的信息传递下来**的结构：**RNN 正是为此而生**。

RNN 的核心直觉：**网络不仅吃当前输入，还吃上一个时刻的"记忆"（隐藏状态）**，像一个边读边记的人——读到 bank 时，脑子里已经有"river"的上下文了。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为 RNN 只处理文本 | 语音、股价、视频帧这些"时间序列"都是它的主场，文本只是最典型的序列 |
| 以为"循环"是网络里有环 | 是"按时间步展开"的循环：每个时刻都用同一个参数模块处理"新输入+旧状态" |

@@point ② RNN 的基本结构：一个"带记忆的处理器"
@@need 要解决什么
RNN 的"记忆"到底存在哪里？网络结构长什么样？

@@idea 核心思路
RNN 在时间步 t 的处理公式非常简洁：

```
h_t = tanh(W_hh * h_{t-1} + W_xh * x_t + b)
y_t = softmax(W_hy * h_t + b_y)
```

拆开看：

- **输入**：当前词向量 `x_t`。
- **上一时刻隐藏状态**：`h_{t-1}`（记忆）。
- **当前隐藏状态**：`h_t = 激活(上一个记忆 + 当前输入)`，也就是"旧记忆 + 新信息"的融合。
- **输出**：`y_t` 由 `h_t` 变换而来，用于分类/预测。

把时间展开：`h_1 → h_2 → h_3 → ... → h_t` 一条链，**所有时刻共享同一套权重 W**（参数不随时间变），这是 RNN 与"把每步当独立网络"的本质区别。共享权重意味着它能处理**任意长度**的序列。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为每时刻一套参数 | RNN 全程一套 W，参数共享，这也是它"轻量"的原因 |
| 忘记激活函数 | tanh 引入非线性并让值域收敛到 (-1,1)，防数值爆炸；没有激活就是线性叠加 |

@@point ③ 前向传播：一句话如何流过 RNN
@@need 要解决什么
"我爱学习"这四个字，是怎么一步步走过 RNN 的？

@@idea 核心思路
假设词向量是 ["我", "爱", "学", "习"]（每个 100 维），RNN 展开：

```
t=1: x=我 → h1 = f(0, 我)      → 记住了"我"
t=2: x=爱 → h2 = f(h1, 爱)     → 记得"我" + 看到"爱"
t=3: x=学 → h3 = f(h2, 学)     → 记得"我爱" + 看到"学"
t=4: x=习 → h4 = f(h3, 习)     → 记得"我爱学" + 看到"习"
```

每一步的 `h_t` 都**浓缩了从开头到当前的完整信息**（理论上）。`y_t` 可以每步输出（如词性标注：每步标一个词性），也可以只取最后一步的输出（如情感分类：整句一个标签）。这个"逐步累积上下文"的过程就是 RNN 理解序列的方式。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 分不清"每个时刻都输出"还是"只最后输出" | 由任务决定：序列标注每步输出，分类/翻译只取最终状态 |
| 认为 h_t 存了"全部"信息 | 实际因梯度消失只能"记得"附近几步，长距离依赖要靠 LSTM（后面章节） |

@@point ④ RNN 训练：时间反向传播（BPTT）
@@need 要解决什么
有了公式和前向，怎么让 RNN 学会做任务？梯度怎么算？

@@idea 核心思路
RNN 用 **BPTT（Backpropagation Through Time，时间反向传播）** 训练：

1. **前向展开**：把序列按时间展开成"深网络"（t 步 = t 层）。
2. **算损失**：用输出与目标算损失（如交叉熵）。
3. **反向链**：误差从最后时刻**沿时间轴往前传**——`∂L/∂W` 要经过 h_T → h_{T-1} → … → h_1 整条链。
4. **参数更新**：所有时刻共享的 W 用梯度累计更新一次。

复杂度上，BPTT 的运算量 ≈ 序列长度 × 单步反向成本。实战里常用**截断 BPTT**：只沿最近 k 步反向，降低计算量，效果通常也不差。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为 RNN 用普通反向传播 | 要沿时间维度展开反向，即 BPTT；序列越长计算越贵 |
| 忽略截断 | 超长序列一次性 BPTT 又慢又易爆，用截断 BPTT 分段训练 |

@@point ⑤ 梯度消失：RNN 的"失忆症"
@@need 要解决什么
RNN 记不住远一点的上下文？数学上是什么原因？

@@idea 核心思路
反向传播时，梯度要沿时间轴**连乘**若干次：每乘一个小于 1 的因子（tanh 导数 ≤1、权重小），连乘结果指数级趋近 0——**梯度消失（Vanishing Gradient）**。

结果：

- 距离远的位置梯度≈0，参数收不到更新信号。
- 网络"记不住"十几步之前的词——长距离依赖失效。
- 例："我去年在北京工作，现在在___工作"里的空，RNN 很难想起"北京"。

梯度消失是 RNN 的**根本痛点**，后面 LSTM/GRU/注意力机制全都是冲着"让远距离信息传得动"去的。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为梯度消失只在 RNN | BPTT 的连乘结构让它特别严重，这是 RNN 比 CNN 更难训的主因 |
| 可视化损失没降就调参 | 先确认是不是梯度过小（打印 grad 范数），再换初始化或换 LSTM |

@@point ⑥ 梯度爆炸：反向的"雪崩"
@@need 要解决什么
连乘的因子大于 1，会发生什么？很危险吗？

@@idea 核心思路
与梯度消失对称：如果连乘的因子都**大于 1**，梯度会**指数级暴涨**——**梯度爆炸（Exploding Gradient）**：

- 参数一步更新巨大，损失跳到 NaN/Inf。
- 训练直接崩掉。

应对手段：

- **梯度裁剪（Gradient Clipping）**：限制梯度范数上限（如 max_norm=5.0，PyTorch 的 `clip_grad_norm_`），是标准操作。
- **合理的参数初始化**：让权重不过大。
- **激活选择**：用 tanh 这类**饱和**激活限制状态幅度；**ReLU 无上界**，在 RNN 里只帮着缓解梯度消失，对爆炸没用甚至更糟（它不控上界）。

工程口诀：**消失用结构救（LSTM/GRU），爆炸用裁剪救（clip）**。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 看到 loss=nan 就换模型 | 先加梯度裁剪 + 降学习率，十有八九能救回来 |
| 裁剪设太小 | 裁剪阈值过小会扭曲梯度方向，5.0 附近是常用起点，按需微调 |

@@point ⑦ 缓解梯度消失的工程手段
@@need 要解决什么
在换 LSTM 之前，有哪些"常规操作"能缓解 RNN 的梯度消失？

@@idea 核心思路
通用手段（不一定能根治，但有效）：

1. **换激活函数**：tanh 导数值域有限，ReLU 在正区间导数恒 1，缓解连乘衰减。
2. **参数初始化**：把小权重的初始值放大些，或使用正交初始化，让连乘更接近 1。
3. **截断 BPTT**：把传播距离限制在可学范围内（k 步），远离"消失"区域。
4. **梯度裁剪**：管住爆炸一端（与消失配合的兜底）。
5. **换门控结构**：LSTM/GRU 引入"门"直通路径，让梯度有一条"高速公路"，这是治本方案（第 8 章）。

理解这几种手段后，才能看懂框架里每个"训练技巧"在干什么。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 把"换激活"当万能药 | ReLU 只是缓解，长序列仍会失真，正规解是门控结构或注意力 |
| 多个技巧一起乱上 | 一次只改一个变量（如先 clip、再 init），否则分不清是谁起的作用 |

@@point ⑧ RNN 的变体与新路线
@@need 要解决什么
RNN 除了"单向从左到右"，还有哪些常见变体？它后来为什么被替代？

@@idea 核心思路
RNN 家族的常见演进：

- **双向 RNN**：前向读一遍 + 后向读一遍，每个位置结合前后文（第 9 章）。
- **LSTM / GRU**：加门控，解决梯度消失（第 8、9 章）。
- **深层 RNN**：纵向堆多层、每层抽象层次不同。

而 **Transformer 为什么后来取代了 RNN**：RNN 必须**逐词顺序处理**，无法并行，长序列又慢又容易丢信息；Transformer 的注意力机制**所有位置并行计算、一步直达远距离依赖**。本阶段第 10 章起就会看到注意力如何彻底解决 RNN 的两大痛点（不能并行、长依赖弱）。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为 RNN 已死、不用学 | RNN/LSTM 在时序预测、语音等场景仍活跃，且大模型时代前的思想（记忆、门控）都源自它 |
| 对比 RNN 和 Transformer 时忘了"顺序处理"这个关键差异 | Transformer 的并行性和直接注意力正是针对 RNN 缺点的设计，抓住这点才能理解架构演进 |

@@summary
本章把 RNN 的骨架和病灶讲清楚：

| 问题 | 答案 |
|---|---|
| 为什么需要 RNN | 序列各元素有前后依赖，需要记忆 |
| 核心公式 | h_t = tanh(W·[h_{t-1}, x_t])，参数共享 |
| 前向 | 逐步融合"旧记忆+新输入"，累计上下文 |
| 训练 | BPTT 沿时间轴反向传播 |
| 梯度消失 | 连乘<1，长距离信息传不动（失忆） |
| 梯度爆炸 | 连乘>1，损失 NaN，用梯度裁剪 |
| 缓解 | 换激活/初始化/截断，治本靠门控 |
| 演进 | 双向RNN → LSTM/GRU → 注意力/Transformer |

一句话记住本章：**RNN 靠"隐藏状态 + 参数共享"记忆序列历史，但 BPTT 的连乘让梯度要么消失要么爆炸——消失靠门控（LSTM/GRU）救、爆炸靠裁剪救，而这两个病根也正是后面注意力机制登场的原因。**
