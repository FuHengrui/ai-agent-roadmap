@@h1 第十二章　自注意力机制
@@sub 阶段 22 · 自然语言处理与Transformer架构　|　自注意力　|　难度 ★★★

@@why 这一章在解决什么问题
上一章注意力是"解码器看源句"，这一章要回答一个更根本的问题：**一个句子内部，词与词之间怎么互相看？** "它站在河边"里的"它"要靠看后半句才能确认。自注意力（Self-Attention）让序列里**每个词同时和所有词算关系**，一步直达、全位置并行——这正是 Transformer 取代 RNN 的发动机。这一章把自注意力的完整计算过程用"我爱学习"的实例彻底算一遍。

@@map 上一章→本章→下一章
上一章掌握了 Q/K/V 和缩放点积注意力。**本章把注意力的 Q/K/V 全部换成"自己"：同一序列内部的自注意力**。下一章再进一级：多头注意力（多视角并行）+ 位置编码（补上顺序信息）——至此 Transformer 的单层零件全部到齐。

@@point ① 为什么需要自注意力：词与词内部的关系
@@need 要解决什么
RNN 用"一步一步传"来建模词间关系，有没有更直接的办法？

@@idea 核心思路
句子理解依赖词与词的关系："我**爱**学习"里，"爱"和"我"是主谓、和"学习"是动宾。RNN 要建模这种关系，得让信息顺着时间轴**一步步传到目标位置**——慢、且远距离会丢。

**自注意力**改为：**每个词直接和全句所有词同时算"相关度"**。

- 位置 i 的词"看向"位置 j 的词，权重高就说明两者关系强。
- 所有词对的关系**一步算出**、彼此**并行**，不再依赖距离。
- 长距离依赖（"它"指代 10 词前的"小猫"）也能直接连线。

一句话：**自注意力=序列内部的全连接"关系图"，每条边权重由数据学出来**。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为自注意力"只是换了个方向" | 它是**变 RNN 的"顺序传递"为"全对全直连"**——并行与长依赖两大优势都源于此 |
| 担心它看不见顺序 | 顺序信息确实不内置，稍后用位置编码补——这是设计的一部分，不是缺陷 |

@@point ② 自注意力的 Q/K/V 从哪来：同一个序列
@@need 要解决什么
自注意力里 Q、K、V 都是"自己"，具体怎么得到？

@@idea 核心思路
对序列的**每个词向量 x_i**，通过三个可学习的权重矩阵变换出各自的 Q/K/V：

```
q_i = W_Q · x_i
k_i = W_K · x_i
v_i = W_V · x_i
```

一句话总结区别（对照第 11 章）：

- **交叉注意力**：Q 来自解码器，K/V 来自编码器（两个序列）。
- **自注意力**：Q、K、V **全部来自同一个序列的词向量**（都从 x 变换）。

每个词都拥有自己的 q/k/v，然后三者互相之间计算——这就构成了"自己看自己"。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为 Q/K/V 就是 x 本身 | 是 x 经过三个不同 W 线性变换而来，各有各的可学习参数 |
| 三个 W 混用 | W_Q/W_K/W_V 是三个独立矩阵，互换就失去"查询-键-值"的分工 |

@@point ③ 自注意力计算四步走
@@need 要解决什么
有了每个词的 q/k/v，完整计算流程是什么？

@@idea 核心思路
以第 2 个词的"听该看谁"为例，四步：

```
1. 算分:  q_2 与 每个词 k_1..k_4 点积
         score_21, score_22, score_23, score_24
2. 归一:  softmax → 权重 w_1..w_4（和为 1）
3. 加权:  context_2 = w_1·v_1 + w_2·v_2 + w_3·v_3 + w_4·v_4
4. 输出:  context_2 就是第 2 个位置的"自注意力结果"
```

每个位置都做同样的四步（可矩阵化一次算完）：

```
Attention(X) = softmax( (X·W_Q)·(X·W_K)^T / √d ) · (X·W_V)
```

输出是一个**形状等于输入**的新序列（词的个数不变、每个词向量维度由 V 的维度决定），每个位置的向量都"吸收"了全句信息。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为每个词只得到一个权重 | 每个词得到"对所有词的权重向量"，第 i 行就是第 i 个词的全句注意力分布 |
| 忘了 softmax 按"行"做 | 归一化沿词维度进行（对第 i 个词的各来源打分求和为 1），写代码时 dim 选错就全错 |

@@point ④ 实例跑一遍："我爱学习"的自注意力
@@need 要解决什么
光有公式抽象，拿"我爱学习"真实算一遍，每一步长什么样？

@@idea 核心思路
假设 4 个词（我、爱、学、习），词向量 3 维（示意）：

```
x = [
  我: [0.9, 0.1, 0.2],
  爱: [0.5, 0.8, 0.3],
  学: [0.2, 0.4, 0.9],
  习: [0.1, 0.2, 0.7],
]
```

① 每个词经 W_Q/W_K/W_V（示意值）得 q/k/v：
`q_爱 = [0.6, 0.7], k_我 = [0.8, 0.1], k_爱 = [0.4, 0.6], ...`

② "爱"的查询与所有 k 点积（示意）：
`score(爱,我)=0.55, score(爱,爱)=0.66, score(爱,学)=0.48, score(爱,习)=0.30`

③ softmax 归一 → `w ≈ [0.27, 0.32, 0.24, 0.17]`（和为 1）——"爱"最关注"爱"本身（自指）与"我"（主谓关系）。

④ 加权 v 求和 → `context_爱 = 0.27·v_我 + 0.32·v_爱 + 0.24·v_学 + 0.17·v_习`。

实际训练时，这个权重分布由注意力头自动学出（常常对应主谓、动宾、指代等语言学关系）。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 期望算出的权重"一定符合语法" | 注意力学的是统计相关，有时会学到"看似不合理"的关系，也是正常的 |
| 拿示意的 3 维向量当真实词向量 | 真实语义空间 100~1000 维，本例只是演示计算过程 |

@@point ⑤ 注意力矩阵：一个句子的"关系全景图"
@@need 要解决什么
一句话的所有词对关系，怎么一次性组织起来？

@@idea 核心思路
把"每词×每词"的注意力权重组织成 **权重矩阵 A**：

```
     我    爱    学    习
我  [0.8   0.1   0.05  0.05]   ← "我"关注自己（自指）
爱  [0.27  0.32  0.24  0.17]   ← "爱"看"我"和"爱"
学  [0.2   0.3   0.4   0.1 ]
习  [0.1   0.2   0.3   0.4 ]
```

- **行**：某个词"看向"全句的分布（行和为 1）。
- **列**：全句对某个词的"被关注度"。
- 对角线大 = 词更依赖自身（修饰/指代场景常见）。

一次前向就把全句的**关系图**算出来了，这就是 Transformer 里 attention map 可视化的由来。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 把行/列含义弄反 | 行=关注者视角，列=被关注者视角；看热力图前先确认方向 |
| 以为矩阵一定对称 | 词 i 看词 j 的权重 ≠ 词 j 看词 i 的权重，矩阵一般不对称 |

@@point ⑥ 自注意力 vs RNN：为什么它更快更强
@@need 要解决什么
同样建模词间关系，自注意力凭什么让 RNN 退居二线？

@@idea 核心思路

| 维度 | RNN | 自注意力 |
|---|---|---|
| 信息传递 | 一步一步传 | 全对全一步直达 |
| 长距离 | 距离越远越弱 | 距离无关（权重决定） |
| 并行性 | 顺序处理，不能并行 | 全位置并行，GPU 友好 |
| 复杂度 | O(序列长) 步 | 每步 O(n²)，但 n 内并行 |
| 顺序信息 | 天然有（时间步） | 没有，需位置编码补 |

结论：**自注意力用"两两全算"换速度与长程能力**。代价是序列变长时 O(n²) 计算量暴涨——这也是后续稀疏注意力、线性注意力研究的方向，但在常规长度下，自注意力优势压倒性明显。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 不看复杂度就吹自注意力 | n 很大（几万 token）时 O(n²) 是痛点，但语言模型主流长度下仍然划算 |
| 以为自注意力取代了"顺序"概念 | 它不感知顺序，顺序靠位置编码，二者是互补关系不是替代 |

@@point ⑦ 掩码自注意力：生成任务不能"偷看未来"
@@need 要解决什么
训练"我爱学习"的生成式模型时，能不能让"我"看到后面的"习"？不能，怎么办？

@@idea 核心思路
解码器做文本生成时，**第 t 个词只能看它自己及其之前的词**，不能看未来——否则训练时"偷看答案"、推理时却看不到，结果崩坏。

**掩码自注意力（Masked Self-Attention）**：在算权重矩阵时，把"未来位置"的分数设成 -∞，Softmax 后权重变成 0：

```
     我    爱    学    习
我  [0.8    -∞    -∞    -∞ ]  →  [1, 0, 0, 0]
爱  [0.4    0.6   -∞    -∞ ]  →  [0.4, 0.6, 0, 0]
学  [0.2    0.3   0.5   -∞ ]  →  正常
习  [0.1    0.2   0.3   0.4 ]  →  正常（所有词可见）
```

形式就是**上三角矩阵置 -∞**（或 0 加 mask）。这样每个位置只聚合"已生成前缀"的信息，"我爱"预测"学习"时的"学"就不知道后面有"习"。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 编码器也加掩码 | 编码器处理完整输入，不加掩码（全可见）；**只有解码器/生成端才加** |
| 掩码加在 softmax 之前还是之后 | 加在 softmax **之前**（用 -∞ 或加 mask 偏置），之后再加等于没加 |

@@point ⑧ 从自注意力到 Transformer：还差什么
@@need 要解决什么
自注意力这块拼图齐了，Transformer 还需要补哪几块？

@@idea 核心思路
Transformer 的编码器单层 = 自注意力 + 三大配角：

1. **多头注意力（Multi-Head）**：多组 Q/K/V 并行，每组学一种关系视角（位置/指代/句法），再拼接融合——下一章主角。
2. **位置编码（Positional Encoding）**：给每个位置加上唯一的"坐标"向量，让自注意力知道先后顺序。
3. **前馈网络（FFN）**：对每个位置的向量独立做非线性变换，增强表达能力——同样下一章。
4. **残差连接 + 层归一化**：防梯度消失、稳定训练。

至此，你已经理解 Transformer 的"发动机"（自注意力）与"燃料"（位置编码）——剩下的就是把这些零件按顺序装起来。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为 Transformer = 自注意力 | 自注意力是核心但不唯一，位置编码/FFN/残差/层归一化共同决定性能 |
| 跳过本教材后面直接啃论文 | 第 13-14 章就是按"零件→整机"顺序讲的，跟着走一遍后再回看论文会豁然开朗 |

@@summary
本章吃透自注意力：

| 问题 | 答案 |
|---|---|
| 动机 | 序列内部词与词直接关联，一步直达、全并行 |
| Q/K/V 来源 | 全部由同一序列的 x 经三个 W 变换 |
| 四步计算 | Q·K^T 算分 → softmax 归一 → 加权 V → 输出 |
| 权重矩阵 | 行=关注者，列=被关注者，行和为 1 |
| vs RNN | 并行、长距离强；代价 O(n²) |
| 掩码自注意力 | 上三角 -∞，生成端防止偷看未来 |
| 还差什么 | 多头、位置编码、FFN、残差+层归一化 |

一句话记住本章：**自注意力让每个词与全句所有词两两直连、按权重互看，并行且无距离衰减，RNN 的顺序瓶颈被打破；生成端还要用"上三角掩码"管住"不能偷看未来"，而它的注意力矩阵本身就是理解句子结构的一幅热图。**
