@@point ① 用 uv 初始化 FastAPI 项目
@@need 要解决什么
为什么用 uv 而不是 pip？怎么从零拉起一个可运行的后端工程？

@@idea 核心思路
uv 是新一代 Python 项目管理工具，安装依赖比 pip 快一个数量级，还能直接管理 Python 版本。安装流程：

```bash
# 1. 退出 conda 环境（避免环境冲突）
conda deactivate

# 2. Windows PowerShell 安装 uv
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

# 3. 创建项目文件夹并用 Cursor 打开
mkdir diabetes_assistant && cd diabetes_assistant

# 4. 初始化项目
uv init

# 5. 安装全部依赖（一次装齐）
uv add "fastapi>=0.115.6" "uvicorn[standard]>=0.34.0" \
  "pydantic-settings>=2.7.1" "tortoise-orm[asyncmy]>=0.23.0" \
  "langchain>=1.3.4,<2.0" "langchain-openai>=1.0.0" \
  "langgraph>=1.2.4,<2.0" "openai>=1.80.0" \
  "chromadb>=1.5.9,<2.0" "python-dotenv>=1.1.0" \
  "python-multipart>=0.0.20" "tzdata>=2026.2"
```

注意依赖分三组理解：**Web 组**（fastapi/uvicorn/python-multipart）、**数据组**（tortoise-orm[asyncmy]——asyncmy 驱动是 MySQL 异步连接的关键）、**AI 组**（langchain/langchain-openai/langgraph/chromadb/openai）。根目录会生成 `pyproject.toml` 和 `uv.lock`，版本锁定交给 uv。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| conda 环境没退出来，装的东西全进 base | 先 `conda deactivate` 再 `uv init`，避免 Python 环境串扰 |
| tortoise-orm 装成了不带驱动的裸包 | 必须以 `tortoise-orm[asyncmy]` 安装，缺 asyncmy 时连 MySQL 报"找不到数据库驱动" |

@@point ② 工程目录结构：先搭骨架
@@need 要解决什么
代码文件多了之后，目录散乱会让人找不到"路由在哪个文件、模型在哪定义"。

@@idea 核心思路
本项目采用的分层目录（标准 FastAPI 工程骨架）：

```
diabetes_assistant/
├── main.py                 # 应用入口：创建 app、挂路由、注册数据库
├── .env                    # 环境变量（数据库/LLM Key 都在这）
├── app/
│   ├── config.py           # 读取 .env、构造 DATABASE_URL、TORTOISE_ORM 配置
│   ├── database.py         # register_tortoise 生命周期注册
│   ├── models/             # Tortoise 模型目录
│   │   ├── __init__.py     # 统一导出所有模型
│   │   ├── patient.py
│   │   ├── blood_sugar.py
│   │   ├── diet_record.py
│   │   ├── medication.py
│   │   ├── exercise.py
│   │   ├── health_report.py
│   │   └── chat_history.py
│   ├── schemas/            # Pydantic Schema（请求/响应模型）
│   ├── routers/            # API 路由
│   │   └── __init__.py     # 主路由聚合
│   └── core/               # 核心引擎：AI 与统计（本阶段增量！）
│       ├── llm_client.py
│       ├── health_analyzer.py
│       ├── diet_advisor.py
│       ├── vector_store.py
│       ├── knowledge_base.py
│       ├── rag_engine.py
│       └── langgraph_agent.py
```

分成五块记忆：**入口（main.py）→ 配置（config.py）→ 数据（models/schemas）→ 接口（routers）→ 引擎（core）**。AI 相关全部在 core，这是与普通 CRUD 系统的最大差别。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 把引擎代码放路由文件里 | 路由文件越来越臃肿，AI 逻辑没法单独测试；必须进 core/ |
| models 目录忘记 `__init__.py` | Tortoise 扫描 "app.models" 找不到模型类；表是 SQL 建的、不会自动补，接口一查就报 relation 不存在 |

@@point ③ .env 环境变量：配置与代码分离
@@need 要解决什么
数据库密码、LLM API Key 这种敏感配置不该硬编码进代码——万一代码上传到 GitHub 就泄露了。

@@idea 核心思路
`.env` 文件放在项目根目录（不进 git），内容如下（**Key 已占位符化，实际开发填你自己的**）：

```ini
# 数据库配置
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=你的数据库密码
DB_NAME=diabetes

# LLM 配置
LLM_MODEL=qwen3.7-max
LLM_API_KEY=sk-xxx（替换为你的 DashScope 密钥）
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_TEMPERATURE=0.7
LLM_MAX_TOKENS=4096

# 血糖阈值
BG_LOW_THRESHOLD=3.9
BG_HIGH_THRESHOLD=10.0

# 向量数据库配置（HuggingFace token 按需）
HF_TOKEN=hf_xxx（替换为你的 HF token）
CHROMA_PERSIST_DIR="./data/chroma_db"
CHROMA_COLLECTION_NAME="medical_knowledge"
RAG_TOP_K=5
```

命名规律：**全大写 + 下划线**，业务相关（血糖阈值、向量库集合名）也能放这——改阈值不用改代码，改 .env 即可。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| .env 被提交进 git，API Key 泄露 | .env 必须加进 .gitignore；代码里只 `os.getenv()` 读取 |
| 密码带 @#$ 等特殊字符 | 直接拼 URL 会解析错乱；必须用 URL 编码（见下一点） |

@@point ④ config.py：构造数据库连接串
@@need 要解决什么
Tortoise 需要一条 MySQL 连接 URL，但密码里可能带特殊字符会拆坏 URL——怎么安全拼出来？

@@idea 核心思路
```python
import os
from urllib.parse import quote_plus
from dotenv import load_dotenv

# 加载环境变量
load_dotenv()

# 数据库配置
DB_HOST = os.getenv('DB_HOST', "localhost")
DB_PORT = os.getenv('DB_PORT', "3306")
DB_USER = os.getenv('DB_USER', "root")
DB_PASSWORD = os.getenv('DB_PASSWORD', "")
DB_NAME = os.getenv('DB_NAME', "diabetes")

# 密码 URL 编码处理：密码里的特殊字符（@、:、#、%等）会被转义
_encoded_password = quote_plus(DB_PASSWORD)

# 数据库连接 URL
DATABASE_URL = (
    f"mysql://{DB_USER}:{_encoded_password}@{DB_HOST}:{DB_PORT}/{DB_NAME}"
    f"?charset=utf8mb4"
)
```

关键点 `quote_plus`：连接串是 `mysql://user:password@host:port/db` 格式，如果密码是 `abc@123`，裸拼会把 `@` 当作分隔符导致连接失败。`quote_plus('abc@123')` 会转成 `abc%40123`，安全。注意只有拼进 URL 的密码需要这一层；模型 API Key 之类不要编码，编了反而用不了。 另外，如果 `.env` 里压根没写 `DB_PASSWORD`，`getenv` 会拿到空串，连接时只报一个含糊的认证失败——先确认 `.env` 存在、且 `load_dotenv()` 在读取前执行过。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 密码含 @ 连接报 "Access denied for user" | 密码没 URL 编码；加 `from urllib.parse import quote_plus` 处理 |
| load_dotenv 没生效，读到的全是 None | .env 文件必须与运行目录同级；或在 config.py 显式 `load_dotenv()`（本项目做了） |

@@point ⑤ TORTOISE_ORM 配置：注册模型与连接
@@need 要解决什么
Tortoise 靠一份结构化的 ORM 配置知道"连哪个库、扫描哪些模型"，配置错了等于没连数据库。

@@idea 核心思路
```python
# Tortoise ORM 配置
TORTOISE_ORM = {
    "connections": {
        "default": DATABASE_URL
    },
    "apps": {
        "models": {
            "models": ["app.models"],   # 扫描路径：app/models/__init__.py 导出的所有模型
            "default_connection": "default",
        }
    }
}
```

结构拆解：
- `connections.default`：默认数据库连接串；
- `apps.models.models`：**模型扫描路径列表**——这里写 `["app.models"]` 表示遍历 `app/models/` 包，通过 `__init__.py` 里导出的所有模型类建立映射；
- `default_connection`：该 app 用哪个连接。

这就是为什么前面第②点强调 `models/__init__.py` 必须统一导出——Tortoise 靠它发现模型。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 模型定义了但建表/查询报"模型不存在" | TORTOISE_ORM 的 models 列表没包含 `app.models`，或 __init__.py 没导出该类 |
| connections 和 apps 键名写错 | 必须严格用 `connections` / `apps` / `default`，拼错静默失败 |

@@point ⑥ model 定义能直接建表吗：generate_schemas 的取舍
@@need 要解决什么
常有人问"建了模型还要手写 SQL 吗"？这涉及 Tortoise 的 `generate_schemas` 参数。

@@idea 核心思路
Tortoise 提供 `generate_schemas=True` 可自动建表，但**本项目明确不用它自动建表**，而是手动执行建库 SQL。原因：

1. **SQL 已在上章手工执行**，表结构以 SQL 为准；
2. 医疗系统表结构要**精确可控**（外键约束、默认值、索引），自动建表的行为不可预期；
3. 与阶段 9 不同（用 Aerich 迁移），本项目直接用 SQL 脚本初始化，简单直接。

正确流程：**表由 SQL 建好 → 模型与之对齐（字段名/类型/表名一致）→ 服务只做 CRUD**。模型与 SQL 不一致时，以"能跑通查询"为对齐目标，两边要同步修改。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 开了 generate_schemas=True 后表结构被自动改坏 | 关掉自动建表，手动管理 SQL；`generate_schemas=False` |
| 模型有字段但 SQL 表里没有 | 查询报 1054 Unknown column；同步 SQL 与模型定义 |

@@point ⑦ 环境验证：启动前自检清单
@@need 要解决什么
写代码前先确认环境链路通不通，避免"写了几百行代码一启动才发现连不上库"。

@@idea 核心思路
动手前跑一组自检，确认地基稳了：

```bash
# 1. uv 安装成功
uv --version

# 2. Python 版本 3.12
python --version

# 3. MySQL 服务在跑（小皮面板绿灯）
netstat -ano | findstr :3306

# 4. 用 Navicat 能连上 diabetes 库（最直观）
#    连接成功 → 看到 7 张表

# 5. .env 文件存在且格式正确（无 BOM、无中文引号）
```

网络自检：小皮面板的 MySQL 状态、Navicat 连接测试，两者都通过才往下走。**这一步 5 分钟，能省回后面 5 小时的排查**。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 3306 端口被别的进程占用 | `netstat -ano | findstr :3306` 看 PID，通过任务管理器处理；或改 MySQL 端口后同步 .env |
| MySQL 启动失败但 .env 没动 | 先看小皮日志；多半是内存不足/端口冲突，与代码无关 |

@@point ⑧ 环境复现要点
@@need 要解决什么
技术选型里的环境（Windows11/Cursor/Python3.12）踩过哪些细节坑，提前说清。

@@idea 核心思路
| 项 | 本项目口径 | 复现要点 |
|---|---|---|
| 操作系统 | Windows 11 | 小皮、Navicat 都是 Windows 软件；Linux 需换方案 |
| 开发工具 | Cursor | 本质是 VS Code 分支，装 Python/uv 插件即可；别纠结编辑器 |
| Python | 3.12 | uv 可自动下载指定版本：`uv python install 3.12` |
| 数据库客户端 | Navicat | 可用其他客户端替代（DBeaver），但连接串参数相同 |
| 大模型 | qwen3.7-max（DashScope） | LLM_BASE_URL 指向阿里云兼容接口，OpenAI 协议的 ChatOpenAI 可直接用 |

一个隐含前提：**LLM API Key 需要真实可用的 DashScope 密钥**，否则 AI 相关章节只能"看不能跑"。没 Key 时先把 CRUD 学完，AI 部分留到有 Key 再联调。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| LLM 调用报 401/InvalidApiKey | LLM_API_KEY 占位符没换或换错；DashScope 控制台重新生成后更新 .env |
| 换 Key 后不生效 | uvicorn reload 不会重读 .env？——会重新 load_dotenv，但**已启动的 Python 进程缓存了环境变量**；改 Key 后重启服务 |
