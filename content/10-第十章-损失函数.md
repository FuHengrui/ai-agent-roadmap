@@h1 第十章　损失函数：训练的裁判标准
@@sub 阶段 21 · 深度学习框架与神经网络架构　|　神经网络基础　|　难度 ★★★

@@why 这一章在解决什么问题
模型预测得准不准，总得有个**客观度量**——这就是损失函数（Loss Function）。它既是"裁判"，也是"教练"：预测误差越大损失越大，梯度下降全靠它带路。这一章讲清回归与分类两大场景的标配损失，以及 PyTorch 里对应的 nn 接口，包括最容易踩的"交叉熵已内置 Softmax"大坑。

@@map 上一章→本章→下一章
上一章搭好了模型。**本章给模型配"裁判"：回归用 MSE、分类用交叉熵损失**。下一章进入完整训练：梯度下降如何用损失带参数下山。

@@point ① 损失函数是裁判也是教练
@@need 要解决什么
凭什么是"收敛了"？凭什么说哪个模型更好？

@@idea 核心思路
**损失函数 L 度量"预测与真值的差距"**，同时是训练的唯一目标函数：

- 作为**裁判**：L 越小 = 预测越准，损失曲线是训练是否顺利的仪表盘。
- 作为**教练**：梯度下降的方向完全由 **∂L/∂参数** 决定——损失定义了"向哪改是对的"。

选择逻辑：
- **回归**（预测连续值，如房价）→ 常用 MSE/MAE。
- **分类**（预测类别）→ 交叉熵。

**任务类型决定损失**，损失错了，训练再久也是空转。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 分类任务用 MSE | 梯度不友好、收敛慢；分类标配交叉熵 |
| 只看训练损失不看验证损失 | 训练损失低不等于泛化好；过拟合时训练降、验证升 |
| 损失一直不降还硬跑 | 先查学习率、初始化、数据归一化，再查损失本身是否用错 |

@@point ② MSE：回归任务的标准答案
@@need 要解决什么
预测房价 120，真实 100，误差怎么量才算"合理"？

@@idea 核心思路
**MSE（均方误差）** = 平均 (预测 - 真值)²：

```python
loss_fn = nn.MSELoss()                 # 默认取平均值
pred = torch.tensor([120., 130., 110.])
y    = torch.tensor([100., 120., 115.])
print(loss_fn(pred, y))   # (400+100+25)/3 = 175
```

就知道的小细节：
- **平方放大误差**：差 10 的惩罚是差 5 的 4 倍 → 对离群点敏感。
- 想改变尺度：`reduction='sum'` 求和，或 `'none'` 逐元素。
- 与梯度关系：对参数求导后带 (pred−y) 因子，误差大梯度大，更新快。

**MSE 是回归的默认选择**；若训练数据存在大量大误差离群点而你想更稳健，再考虑 MAE。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 预测和真值维度/类型不匹配 | 两者 shape、dtype 必须一致（多为 float32 且形状相同） |
| reduction 混淆 | 默认均值；数值差异大的场景注意统一口径（loss 只用于比较相对大小） |
| 数据量级差异造成 loss 巨大 | 先归一化特征/目标；MSE 对量级敏感 |

@@point ③ MAE 与 Huber：MSE 的备选项
@@need 要解决什么
数据里有离群点，MSE 被个别大误差带偏怎么办？

@@idea 核心思路
**MAE（平均绝对误差）** = 平均 |预测 − 真值|：对离群点更稳（非平方，不受大误差过度影响），但在 0 点附近不可导、梯度恒定，收敛较慢。

**Huber** 是两者的折中：误差小时像 MSE（平滑可导），误差大时像 MAE（稳健）——实践中常用。

```python
loss_fn1 = nn.L1Loss()        # MAE
loss_fn2 = nn.HuberLoss(delta=1.0)  # Huber，delta 控制切换点
```

**选择口诀**：数据干净优先 MSE；有明显离群点用 Huber；要求绝对误差可解释用 MAE。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 把 MAE 当 MSE 用 | 两者梯度特性不同，换了损失训练动态会变，观察曲线再决定 |
| Huber 的 delta 乱调 | delta 越大越像 MSE、越小越像 MAE；先默认 1.0 再调 |

@@point ④ 交叉熵：分类任务的标配
@@need 要解决什么
二分类/多分类，怎么定义"预测的概率分布 vs 真实标签"的差距？

@@idea 核心思路
**交叉熵（CrossEntropy）** 度量两个概率分布的差异。分类时：真实标签是"独热分布"（对的那个类概率 1，其余 0），预测是网络的概率输出；交叉熵越小，预测概率分布越接近真实分布。

```python
# 多分类：logits 直接喂，内部自动做 softmax
logits = torch.tensor([[2.0, 1.0, 0.1],
                       [0.5, 2.5, 1.0]])
labels = torch.tensor([0, 1])           # 真实类别索引
ce = nn.CrossEntropyLoss()(logits, labels)
print(ce)
```

关键规则（新手必背）：
- **nn.CrossEntropyLoss 内部已包含 Softmax**：输入必须是**未过 softmax 的 logits**。
- 标签传**类别索引**（0,1,2…），不是 one-hot 向量，也不是概率。
- 输出层**不要**再手动加 Softmax——那是双重 softmax。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 双重 softmax | 输入已过 softmax 又喂 CE，训练 bug 难排查；牢记"CE 内置 softmax" |
| 标签喂成 one-hot | CE 要整数索引；one-hot 请改用 NLLLoss（配合 log_softmax）或先 argmax |
| 输出通道数 ≠ 类别数 | 输出层神经元个数必须等于类别数 |
| 二分类用 CE 还是 BCE | 二分类用 **BCEWithLogitsLoss**（更稳），或多分类形式 CE 也兼容 |

@@point ⑤ BCE / BCEWithLogits：二分类专属
@@need 要解决什么
只有两个类别（有病/没病、点击/不点击），损失怎么写最优？

@@idea 核心思路
二分类的交叉熵叫**二元交叉熵（BCE）**。PyTorch 两个接口：

```python
probs = torch.sigmoid(logits)                # 先转概率
loss1 = nn.BCELoss()(probs, targets)          # 需要手动先 sigmoid

logits = torch.tensor([[1.2], [-0.8]])       # 没 sigmoid 的原始输出
targets = torch.tensor([[1.0], [0.0]])
loss2 = nn.BCEWithLogitsLoss()(logits, targets)  # 内部自动 sigmoid，数值更稳
```

**BCEWithLogitsLoss 是首选**：把 sigmoid 和 BCE 合并计算，数值稳定性更好、也不用担心忘写 sigmoid。targets 是 0/1 浮点。

**"WithLogits" 后缀是 PyTorch 的福利记号**——类似的还有 CrossEntropyLoss（内置 softmax），都优先用带 Logits 版本。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| BCELoss 忘了先 sigmoid | 概率超过 (0,1) 时 log 报错/数值 NaN；换 BCEWithLogitsLoss 根治 |
| targets 喂了整数而非 0/1 浮点 | BCE 系列要求 target 处于 [0,1] 且为浮点；one-hot 的每一列也可用 |
| 输出层是单个神经元还是两个 | 二分类输出层用**单个神经元 + BCE**，别再搞"两个神经元 + softmax"的教科书做法 |

@@point ⑥ 一个损失池：碰到的都在这
@@need 要解决什么
课本任务还会碰到别的损失吗？各自长什么样？

@@idea 核心思路
给一张"常用损失速查表"，遇到再回来找：

| 损失/接口 | 任务 | 关键点 |
|---|---|---|
| nn.MSELoss | 回归 | 默认均值，对离群点敏感 |
| nn.L1Loss | 回归 | MAE，稳健但梯度恒定 |
| nn.HuberLoss | 回归 | MSE 与 MAE 折中，稳健平滑 |
| nn.CrossEntropyLoss | 多分类 | **内置 softmax**，标签传索引 |
| nn.BCEWithLogitsLoss | 二分类 | **内置 sigmoid**，数值更稳 |
| nn.BCELoss | 二分类 | 需手动 sigmoid，少用 |
| nn.NLLLoss | 或然分类 | 配 log_softmax 手动，底层组件 |
| 自定义损失 | 特殊任务 | 返回标量张量即可，参与计算图 |

**原则：先选对任务类型（回归/分类），再在同一类型里挑合适的变体。**

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 多分类误用 BCE | 类别互斥用 CE；多标签（一个样本可属多类）才用 BCE |
| 自定义损失返回向量 | 返回标量（.mean()）；否则 backward 报错 |
| 损失函数即模型的一部分 | 损失参与计算图，权重参数照样会被 autograd 追踪 |

@@summary
损失函数选择与使用要点：

| 问题 | 答案 |
|---|---|
| 损失函数作用 | 裁判：度量误差；教练：定义梯度方向 |
| 回归默认 | nn.MSELoss；离群点多换 HuberLoss |
| 多分类默认 | nn.CrossEntropyLoss：内置 softmax，标签传索引 |
| 二分类默认 | nn.BCEWithLogitsLoss：内置 sigmoid，标签 0/1 浮点 |
| 最大坑 | CE/BCEWithLogits 前不要再手动过 softmax/sigmoid |
| 怎么选 | 先分任务（回归/分类），再按数据特性选变体 |

@@point ⑦ 加权交叉熵：类别不平衡的补救
@@need 要解决什么
正样本 100 条、负样本 9000 条，模型学会"全猜负"损失也很低，怎么办？

@@idea 核心思路
**加权损失**：给少数类更高的惩罚权重，逼模型重视它：

```python
class_counts = torch.tensor([9000, 100])          # [负, 正] 样本数
weights = 1.0 / class_counts.float()              # 权重 = 频率倒数
weights = weights / weights.sum() * len(weights)  # 归一化
criterion = nn.CrossEntropyLoss(weight=weights)

# 二分类同理
criterion2 = nn.BCEWithLogitsLoss(pos_weight=torch.tensor(90.0))
```

- CE 填 `weight`（按类别）
- BCEWithLogits 填 `pos_weight`（正类权重放大）

**思路本质**：让损失"一碗水端平"——少数类错一次罚得更重，梯度方向就不会被多数类垄断。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 权重瞎设 | 从 1/频率 起步，观察验证集召回率再微调 |
| 加权了训练 loss 仍稳 | 先确认标签真的不均衡（value_counts），再查加权参数是否生效 |
| 只想偷懒用 accuracy | 不平衡数据 accuracy 会骗人；以召回率/F1 为考核 |

@@point ⑧ 从损失曲线诊断训练
@@need 要解决什么
训练跑起来了，怎么从 loss 曲线判断"正常、欠拟合、过拟合还是不收敛"？

@@idea 核心思路
把训练/验证 loss 画图看趋势，四种典型形态：

| 曲线形态 | 诊断 | 处理 |
|---|---|---|
| 两者一起稳步下降 | 正常 | 继续训练 |
| 训练降、验证升 | **过拟合** | 加正则/早停（下章详解） |
| 两者都高且平 | 欠拟合 / 学习率太小 | 加容量、加数据、调大 lr |
| 剧烈震荡或变大 | 学习率太大 / 数据没归一化 | 调小 lr，检查预处理 |

**绘图很便宜，收益极高**：每个 epoch 存 train/val loss，结束后画一条线，比盯 100 次 print 都直观。以后所有实战都按这个"仪表盘"来驾驶。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 只记训练 loss | 看不到过拟合分界；验证 loss 才是"举一反三"的信号 |
| 曲线锯齿状就当失败 | 小 batch 噪声正常，看整体趋势而非单个点 |
| 一股脑跑完才看 | 边跑边画（或定期打印验证 loss），异常早发现早止损 |

一句话记住本章：**回归用 MSE（离群点换 Huber），分类用交叉熵——多分类 CrossEntropyLoss、二分类 BCEWithLogitsLoss，两者都内置了归一化层，别再手动加 softmax/sigmoid 铸成双保险 bug。**
