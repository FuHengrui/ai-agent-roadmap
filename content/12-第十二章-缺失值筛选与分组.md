@@point ① 缺失值认知：NaN 与 None
@@need 要解决什么
数据里出现"空"，**Pandas 用什么表示？NaN 和 None 是一回事吗？** 先搞懂怪物长什么样，才能处理和它有关的一切。

@@idea 核心思路
Pandas 里缺失值两种形态：

- **NaN**（Not a Number）：数值列的空值，float 型；
- **None**：Python 原生空值——Pandas 会**自动转成 NaN**（对象列里也可能保留）。

```python
import pandas as pd
import numpy as np

s = pd.Series([1, np.nan, 3, None])
# 0    1.0
# 1    NaN
# 2    3.0
# 3    NaN      ← None 已被统一成 NaN，dtype 变 float64

s.isna()          # 逐元素判断是否缺失 → 布尔 Series（isnull 等价）
s.notna()         # 反操作
s.isna().sum()    # 缺失个数（统计标配）
```

关键认知：

- **NaN ≠ 0 ≠ ''**：它表示"数据不存在"，参与计算会传染（NaN + 1 = NaN）；
- **isna() 是判断缺失的唯一正道**（不要用 `s == np.nan`，NaN 不等于任何东西，包括它自己！）；
- info() 里"非空计数"就是用 isna 统计出来的。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| s == np.nan 永远 False | NaN != NaN，必须用 isna()/notna() 判断 |
| 含 NaN 的运算结果全是 NaN | 正常传染；处理完缺失再算 |
| 整列变 float | 只要有一个 NaN，整列升为 float 容纳它 |

@@point ② fillna：缺失值填充
@@need 要解决什么
缺的值**补什么**？填 0、填均值、填前一个值（时间序列惯性）——按业务选策略，别一填了之。

@@idea 核心思路

```python
import pandas as pd

df = pd.DataFrame({'成绩': [88, None, 76], '身高': [170, 165, None]})

df['成绩'].fillna(0)                    # 填常量 0
df['成绩'].fillna(df['成绩'].mean())    # 填均值（最常见策略）
df['身高'].ffill()   # pandas 3.0 已移除该参数，直接用 ffill()/bfill()       # 前向填充：用上一个值补（时间序列）
df['身高'].bfill()                    # 后向填充（pandas 3.0 已移除 method 参数）
df.fillna({'成绩': 0, '身高': 170})      # 按列分别填
```

选择策略的三条经验：

- **数值类缺失**：业务上"没有就是 0"填 0；"缺损合理"填均值/中位数；
- **时间序列**：ffill（用上一时刻的值继承）通常合理；
- **分类/文本缺**：填"未知"/众数。

fillna 默认返回新表；加 inplace=True 原地。**填充前先想清楚"这个空代表什么业务含义"**——盲目填 0 是数据分析事故高发地。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 填均值后统计仍异常 | 填充改变了分布（均值拉向中心）；先想这个空值是否"天然不填"（如没买过保险的金额） |
| ffill 首行没法填 | ffill 后开头仍 NaN，可再 fallback bfill 或常量 |

@@point ③ dropna：删除缺失行/列
@@need 要解决什么
缺失值**不值得补**（脏到没法用）或者量大——直接删行删列。dropna 按轴与"how"决定删谁。

@@idea 核心思路

```python
df = pd.DataFrame({'A': [1, None, 3], 'B': [4, 5, None]})

df.dropna()                       # 删掉含任一缺失的行（how='any' 默认）
df.dropna(how='all')              # 只删"整行全缺"的行（保留部分信息）
df.dropna(axis=1)                 # 删列（把含缺失的列整个删掉）
df.dropna(thresh=2)               # 保留非空值 >=2 的行
df['A'].dropna()                  # 某列删空值（最常见：单列）
```

决策链：

- **核心列缺了** → 不能删整行时用 fillna 或先看缺多少；
- **缺的行很少**（<5%）→ dropna 简单安全；
- **某列大面积缺** → 考虑直接 drop 该列（axis=1）。

经验：**drop 前先 print(df.isna().sum()) 看缺多少**——缺 80% 的列直接删列比填均值诚实的多。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| dropna 后行数骤减 | how='any' 只要有一列缺就删整行；先看各列缺失分布再决定 |
| 想删列删成了行 | axis=1 才是列，别记反（可用 axis='columns' 字符串防错） |

@@point ④ 重复值：duplicated / drop_duplicates
@@need 要解决什么
**数据重复录入**（同一个订单记了两遍）——查重、去重两步走。

@@idea 核心思路

```python
df = pd.DataFrame({'姓名': ['张', '王', '张'], '成绩': [88, 95, 88]})

df.duplicated()                    # 布尔 Series：标记重复行（默认从第二行起标 True）
df.duplicated().sum()              # 重复行数
df.drop_duplicates()               # 去重（保留第一个）
df.drop_duplicates(subset=['姓名'])   # 按"姓名"判重
df.drop_duplicates(keep=False)     # 把所有重复的都删掉
```

关键参数：

- **subset**：只看这几列判重（默认全列一致才算重）；
- **keep**：'first'（默认留第一条）/ 'last' / False（全删）。

去重后通常要 reset_index(drop=True) 重整序号。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 看着像重复却没被判重 | 可能隐藏空格/大小写差异；先 df['列'] = df['列'].str.strip() 赋值回去（strip 返回新 Series，不赋值等于没做），再判重 |
| 去重后索引断档 | reset_index(drop=True) 重编号 |

@@point ⑤ loc 与 iloc：标签 vs 位置（必考）
@@need 要解决什么
**取"行为上的自由的子集"**：loc 按标签（含行含列名）、iloc 按位置（整数下标）——这是 Pandas 面试考烂、实战天天用的区分。

@@idea 核心思路

```python
df = pd.DataFrame({'成绩': [88, 95, 76]}, index=['张', '王', '李'])

df.loc['王']                # 按索引标签取行 → Series
df.loc['张':'王']           # 标签切片：含两端！（与普通切片不同）
df.loc[['张', '李']]        # 标签列表

df.iloc[0]                 # 按位置取第 0 行
df.iloc[1:3]               # 位置切片：含头不含尾
df.iloc[:, 0]              # 位置取列（所有行第 0 列）
```

对比表格：

| 方法 | 凭什么取 | 切片端点 | 典型用途 |
|---|---|---|---|
| loc | 索引标签+列名 | 含两端 | 业务名/日期定位 |
| iloc | 整数位置 | 含头不含尾 | 程序化取前 N 行 |

组合形态：`df.loc[条件, 列名列表]`——"挑了行再挑列"一步完成（第 ⑥ 点展开）。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| loc 切片莫名多一行 | loc 含端点（和 iloc 不同）！这是新手最大的隐性差异 |
| 数字索引时 loc[0] 和 iloc[0] 结果不同 | 索引标签为人的 0 和位置 0 概念不同；确认自己到底想按哪个取 |

@@point ⑥ 条件筛选：布尔索引
@@need 要解决什么
**"成绩>80 且性别=男"这种业务筛选**——布尔 Series 当索引，Pandas 筛选第一神器。

@@idea 核心思路

```python
import pandas as pd

df = pd.DataFrame({'姓名': ['张', '王', '李'], '成绩': [88, 55, 76], '性别': ['男', '女', '男']})

df[df['成绩'] > 80]                  # 单条件
df[(df['成绩'] > 80) & (df['性别'] == '男')]   # 且：& 必须加括号！
df[(df['成绩'] < 60) | (df['成绩'] > 90)]      # 或：|
df[df['姓名'].isin(['张', '王'])]              # 集合成员：isin
```

三条铁律：

1. **比较得到布尔 Series，df[布尔] 就筛行**；
2. **多条件必须 &（且）/ |（或），且每个条件加括号**——忘括号是最高频报错（ValueError on truth value）；
3. **isin 是"在集合里"的标准写法**（别用 == 拼多个）。

进阶组合：`df.loc[df['成绩'] > 80, ['姓名', '成绩']]`——筛行 + 只留指定列，一步完成。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 条件筛选报"truth value ambiguous" | 用了 and/or；数组逻辑必须用 `&` / `\|` 并加括号 |
| 连续条件写 df['成绩'] > 70 < 90 | 不生效（从左到右布尔比较）；写成 (df['成绩']>70)&(df['成绩']<90) |
| 用 == 判多个值 | 用 isin 列表 |

@@point ⑦ query：字符串式的条件查询
@@need 要解决什么
一堆括号看得眼花？**query 用字符串表达式写条件**，可读性翻倍（适合条件多、长脚本）。

@@idea 核心思路

```python
df = pd.DataFrame({'成绩': [88, 55, 76], '性别': ['男', '女', '男']})

df.query('成绩 > 80')                          # 单条件
df.query('成绩 > 70 and 性别 == "男"')          # and/or 可以直接用！
df.query('成绩 > @lower')                      # @局部变量
```

与布尔索引对比：

- **query 里 and/or 直接写**（字符串层面解析，无语法陷阱）；
- **@变量名** 引用外部 Python 变量（不加 @ 会被当列名）；
- 列名含空格时用反引号括：query('`my col` > 5')。

选择建议：个人脚本两者皆可；**维护性优先时 query 更清晰，性能两者接近**。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| query 里引用外部变量没生效 | 加 @ 前缀才是外部变量 |
| query 报"列名未定义" | 拼写或该列名有空格/特殊字符 → 反引号包住 |

@@point ⑧ sort_values 与 replace：排序与值替换
@@need 要解决什么
**按某列排序**、以及**把某些值替换成另一些值**（如"1/0"换成"是/否"）——数据处理的两个小高频。

@@idea 核心思路

```python
df = pd.DataFrame({'成绩': [88, 55, 76], '性别': [1, 0, 1]})

df.sort_values('成绩')                        # 升序
df.sort_values('成绩', ascending=False)       # 降序
df.sort_values(['性别', '成绩'])              # 多列排序（先性别后成绩）

df['性别'].replace({1: '男', 0: '女'})        # 值映射替换（字典）
df['成绩'].replace(55, 60)                   # 单值替换
df.replace({'成绩': {55: 60}})               # 指定列替换
```

要点：sort_values 默认返回新表，要原地 `inplace=True` 或赋值；replace 支持**字典精准映射**（值→新值）和数值替换，是"打标签"的有效手段。

对比 map：**replace 是替换数值/文本专用、支持整表批量；map 是逐元素函数应用**，窄替换用 replace。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| replace 用 inplace 后忘了看结果 | 原地也行，但统一用赋值更保险（版本差异警告） |
| 想"把 NaN 也换掉" | NaN 用 fillna，replace 默认不匹配 NaN（可加正则参数） |

@@point ⑨ get_dummies：哑变量编码
@@need 要解决什么
**机器学习要数值、业务里是"男/女/红/蓝"文本**——把分类列转成 0/1 的哑变量（one-hot），get_dummies 一键完成。

@@idea 核心思路

```python
import pandas as pd

df = pd.DataFrame({'颜色': ['红', '蓝', '红']})

pd.get_dummies(df['颜色'])
#    红  蓝        ← 每类一列，是则该类=1
# 0  1  0
# 1  0  1
# 2  1  0

pd.get_dummies(df['颜色'], prefix='色')        # 加列名前缀
pd.get_dummies(df, columns=['颜色'])           # DataFrame 整体转
```

要点：

- 输出与原列**等长**，每行只有一类为 1（one-hot）；
- `prefix=` 给新列名加前缀，防止和原列冲突；
- **drop_first=True** 可以丢掉第一列（避免多重共线性，模型场景常用）。

真用途：把"颜色""城市"这类类别特征喂给模型前的标准动作。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 转完列数爆炸 | 高基数类别（上千个城市）不适合 one-hot；先看类别数量 |
| 新列名很怪 | prefix 参数定制前缀；或转完重命名 |

@@point ⑩ cut：按值分箱
@@need 要解决什么
**把连续分数分成"优/良/及格/不及格"段位**——cut 按你指定的**边界**分箱。

@@idea 核心思路

```python
import pandas as pd

scores = pd.Series([88, 55, 90, 72, 61, 45])

bins = [0, 59, 69, 79, 100]              # 边界：0-59, 60-69, 70-79, 80-100
labels = ['不及格', '及格', '良', '优']

pd.cut(scores, bins=bins, labels=labels) # 边界分箱
pd.cut(scores, bins=4)                   # 不写边界：等宽均分 4 段（返回区间对象）
```

特性：

- **cut 按边界（值域）分箱**：你定边界，它严格遵守；
- 返回 **Categorical**（类别）：可直接 value_counts 统计、groupby、画图；
- 不传 labels 时显示为区间 (a, b]。

用途：年龄分段、分数档位、时长分段——业务上"层级化"连续值。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 数值落在边界上不知道归哪边 | cut 默认左开右闭 (a, b]；差 1 分被分错就检查边界定义 |
| labels 数量与 bins 段数不一致 | 段数 = len(bins)-1，labels 必须一样多 |

@@point ⑪ qcut：按分位数分箱
@@need 要解决什么
cut 按"绝对值边界"分，**但数据分布不均时（一堆 60-70，几个 95+）**：cut 分出来人数悬殊。此时按"人数均分"——qcut 按分位数。

@@idea 核心思路

```python
import pandas as pd
import numpy as np

s = pd.Series(np.random.randn(100) * 20 + 60)   # 随机成绩，分布不均

pd.qcut(s, 4)                    # 4 等分位数 → 每段约 25 人
pd.qcut(s, [0, .25, .5, .75, 1]) # 自定义分位点
pd.qcut(s, 4, labels=['差', '中', '好', '优'])
```

与 cut 的核心区别：

| | cut | qcut |
|---|---|---|
| 分箱依据 | 数值边界（值域等/自定义） | 分位数（频数等） |
| 箱内人数 | 可能悬殊 | 大致相等 |
| 用途 | 层级有业务含义（分数线） | 只看"排名分布"（电商分客群） |

**选型口诀：分数线（业务边界）用 cut；人群分层（等量分组）用 qcut。**

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| qcut 报"bins must increase monotonically" | 数据大量重复值导致分位点重叠；改用 cut 或处理重复 |
| qcut 分完各段人数仍不等 | 有并列值时无法精确均分，属正常边界情况 |

@@point ⑫ groupby：分组统计入门
@@need 要解决什么
**"每个班的平均分""每个城市的总销售额"**——groupby 就是"按某列分类，对组内做统计"。

@@idea 核心思路

```python
import pandas as pd

df = pd.DataFrame({'班级': ['A', 'A', 'B', 'B'], '成绩': [88, 92, 76, 85]})

g = df.groupby('班级')
g.mean()                    # 每班成绩均值
g['成绩'].mean()            # 只对成绩列求均值
g.size()                    # 每组行数（count 是组内非空计数，别混）
```

理解链：

- **groupby('班级') → GroupBy 对象**（还没有任何计算！）；
- 对 GroupBy 对象调聚合方法（mean/sum/count/max/min）才出结果；
- 多列分组：`df.groupby(['班级', '性别']).mean()` → 结果索引是组合键。

**结果是"以分组列为索引"的表**——后续想做普通表就 reset_index()（第 11 章）。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| groupby 后只有索引没有列 | 聚合默认对数值列生效；想指定列 g['成绩'].mean() |
| size 和 count 混淆 | size=组内行数（含 NaN）；count=组内非空数 |
| 结果想当普通表处理 | 加 reset_index() 释放索引 |

@@point ⑬ agg：多聚合一站式
@@need 要解决什么
**一组数据又要均值又要最大又要中位数**——agg 把多个聚合塞进一个调用，还能对不同列用不同聚合。

@@idea 核心思路

```python
import pandas as pd

df = pd.DataFrame({'班级': ['A', 'A', 'B', 'B'],
                   '成绩': [88, 92, 76, 85],
                   '身高': [170, 165, 175, 180]})

df.groupby('班级').agg(['mean', 'max', 'min'])          # 每个函数都算
df.groupby('班级').agg({'成绩': ['mean', 'std'],        # 按列指定不同聚合
                        '身高': 'max'})
df.groupby('班级')['成绩'].agg(avg='mean', top='max')   # 给结果列起名
```

理解：

- **agg 参数可以是函数名列表**：对每列都跑；
- **可以是 {列: 函数/函数表} 字典**：分列定制；
- 结果列名默认=函数名，可命名（上面最后一例）。

这是"一次分组，全面统计"的标配写法——一份 groupby 汇总表往往是分析报告的骨架。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| agg({'成绩': ['mean']}) 没生效 | 字典写法需列名精确匹配；列名拼写/空格查一下 |
| 聚合结果列名重复 | agg 函数列表相同时列名重复；用命名 agg（avg='mean'）避免 |

@@point ⑭ stack / unstack：行列透视切换
@@need 要解决什么
**分组结果想"行变列"（宽表↔长表）**——stack 把列"压"进索引，unstack 把索引"撑"成列，二者互为逆操作，透视表（第 14 章 pivot）的底层。

@@idea 核心思路

```python
import pandas as pd

df = pd.DataFrame({'班级': ['A', 'A', 'B', 'B'],
                   '性别': ['男', '女', '男', '女'],
                   '成绩': [88, 92, 76, 85]})

p = df.pivot_table(index='班级', columns='性别', values='成绩')
# 性别   女   男
# 班级
# A     92   88
# B     85   76

p.stack()        # 列 → 索引：变成长表（性别进入行索引）
p.stack().unstack()      # 对宽表直接 unstack 不是 stack 的逆；要「先压长再摊回」才能验证互逆
```

理解：

- **stack：把"最内层列"挪进索引**（宽→长）；
- **unstack：把"最内层索引"挪回列**（长→宽）；
- groupby 多列分组结果 `unstack()` 后就变成"每个组合一列"的透视形态。

用途：透视分析、画图（每列一条线）、数据供给模型。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| stack 后列名消失/变 MultiIndex | 宽表变长表后列名变索引值，MultiIndex 是正常的 |
| 透视出现 NaN | 没有该组合的格子即 NaN；fillna(0) 处理 |

@@summary
这一章，数据洗涤三件套全部交付：

| 能力 | 关键 API | 一句话 |
|---|---|---|
| 缺失值 | isna / fillna / dropna | 判断用 isna，填充看业务，删除看占比 |
| 重复值 | duplicated / drop_duplicates | subset 判重、keep 留谁 |
| 定位取数 | loc（标签含端点）/ iloc（位置） | 本质区别，切莫搞混 |
| 条件筛选 | df[布尔] & / \| / isin | 多条件加括号，集合用 isin |
| 字符串查询 | query('col > @x') | 可读性优先，@ 表示外部变量 |
| 排序替换 | sort_values / replace | 多列排序、字典映射 |
| 哑变量 | get_dummies | 分类转 0/1 |
| 分箱 | cut（值域）/ qcut（分位） | 分数段用 cut、人群分层用 qcut |
| 分组 | groupby → mean/agg | 分组对象再聚合，agg 分列定制 |
| 透视切换 | stack / unstack | 宽长互转，透视表底层 |

一句话记住本章：**NaN 用 isna 找、fillna/dropna 治；要哪块数据用 loc/iloc 和布尔筛；"每一组"开头的问题全交给 groupby+agg；分层用 cut/qcut——清洗与聚合的双手就绪，下一章把多张表和时间拉进来。**
