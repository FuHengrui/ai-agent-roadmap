@@point ① 为什么要用函数
@@need 要解决什么
不写函数也能干活——那为什么所有正经代码都在用函数？
@@idea 核心思路
**四个理由，按重要性排**：

| 好处 | 说明 |
| **避免重复** | 同一段逻辑只写一遍，改的时候只改一处 |
| **能命名** | `clean_salary(raw)` 比 15 行 if-else 好读得多——**名字就是文档** |
| **能隔离** | 函数内部的变量外面看不见，不怕重名，不怕被误改 |
| **能测试** | 一个函数一个职责，出问题好定位，也好单独测 |

**判断标准**：当你发现自己**复制粘贴了一段代码**，就该把它抽成函数了。

**另一个判断标准**：当你需要**给一段代码写注释解释它在干什么**，考虑把它抽成函数，用函数名代替注释。
@@trap 别走极端
不是越碎越好。`def add(a, b): return a + b` 这种"包一层"往往没意义。

**经验法则**：一个函数只做一件事，而且**它的名字能准确地概括这件事**。如果你起不出好名字，通常说明它做的事太多了。

@@point ② 定义与调用
@@need 要解决什么
最基础的语法。**但里面有两个新手必踩的坑：定义不等于执行、必须先定义后调用。**
@@idea 核心思路
```python
def 函数名(参数列表):
    """文档字符串（可选）"""
    函数体
    return 返回值          # 可选
```

```python
def greet(name):
    """打个招呼。"""
    print(f"你好，{name}")

greet("小明")              # 调用 → 你好，小明
```

**三条必须记住的规则**：

- **`def` 只是"定义"，不执行函数体**。写了 `def` 之后不调用，里面的代码一行都不会跑
- **必须先定义、后调用**。Python 是从上往下执行的，调用写在定义前面会 `NameError`
- **函数名本身是一个对象**（下一点细讲）。写 `greet` 是"引用这个函数"，写 `greet()` 才是"调用它"

**函数分类**——按参数和返回值分：

| 类型 | 有参数？ | 有返回值？ | 例子 |
| 无参无返回 | ❌ | ❌ | `def show_menu(): print(...)` |
| 有参无返回 | ✅ | ❌ | `def log(msg): print(msg)` |
| 无参有返回 | ❌ | ✅ | `def now(): return time.time()` |
| 有参有返回 | ✅ | ✅ | `def add(a, b): return a + b` |
@@trap 忘了写括号
```python
greet          # 这是"函数对象本身"，什么都不会发生
greet()        # 这才是调用
```
**这个错特别隐蔽**——不报错，但什么都没发生。而且回调（比如 `sort(key=...)`）里传的**恰恰就是函数对象、不带括号**，所以两种写法都有用，得看场合。

@@point ③ 形参、实参与文档字符串
@@need 要解决什么
"参数"这个词经常被混用。**分清楚形参和实参，你才能看懂报错信息。**
@@idea 核心思路
```python
def add(a, b):        # a、b 是【形参】——定义时的占位符
    return a + b

add(1, 2)             # 1、2 是【实参】——调用时真正传进去的值
```

**文档字符串（docstring）**——函数体第一行的字符串，用三引号：

```python
def clean_salary(raw: str) -> float | None:
    """
    把薪资原文清洗成月薪数字。

    参数:
        raw: 原始薪资文本，如 "8-15K·13薪"、"1.2-1.8万"

    返回:
        月薪下限（float）；解析不出来时返回 None
    """
    ...
```

**写 docstring 的三个好处**：

- `help(clean_salary)` 能直接显示
- PyCharm 里鼠标悬停能看到
- **逼你把"这个函数到底干什么"想清楚**——写不出来通常说明函数职责不清

**类型注解**（`raw: str -> float | None`）不是强制的，Python 不检查，但它：
- 让 PyCharm 能提示参数类型
- 让读代码的人一眼看出意图
- 配合 `mypy` 这类工具能做静态检查
@@trap 参数个数不匹配
```python
def add(a, b): return a + b
add(1)              # TypeError: add() missing 1 required positional argument: 'b'
add(1, 2, 3)        # TypeError: add() takes 2 positional arguments but 3 were given
```
**报错信息里会告诉你有几个、缺哪个**——照着读就能改。

@@point ④ 返回值
@@need 要解决什么
"函数算出来的结果怎么交给外面"——这是函数和外部世界交换数据的主要方式。
@@idea 核心思路
**`return` 做两件事：把值传出去 + 立刻结束函数。**

```python
def divide(a, b):
    if b == 0:
        return None       # 提前返回，后面的代码不再执行
    return a / b
```

**返回多个值**——本质是返回一个元组：

```python
def get_min_max(a):
    return min(a), max(a)      # 实际返回 (min, max)

lo, hi = get_min_max([3, 1, 4])    # 解包接住
result = get_min_max([3, 1, 4])    # 也可以整个元组接住 → (1, 4)
```

**没有 `return` 会怎样？返回 `None`。**

```python
def log(msg):
    print(msg)          # 没有 return
x = log("hi")           # x 是 None
```

**"就地修改"的函数也返回 `None`**——这个规律在第三章见过（`sort()`），这里再次出现：

```python
a.sort()        # 返回 None，但 a 被改了
sorted(a)       # 返回新列表，a 不变
```

**这是 Python 的一个设计约定**：

| 函数做什么 | 返回什么 |
| **算出新东西** | 返回结果（`sorted`、`sum`、`len`） |
| **就地修改** | 返回 `None`（`append`、`sort`、`update`） |

**记住这个约定，就不会写出 `b = a.sort()` 这种错。**
@@trap return 与 print 的区别
```python
def add_wrong(a, b):
    print(a + b)        # ✗ 只是打印，没有返回

def add_right(a, b):
    return a + b        # ✓ 把结果交出去

x = add_wrong(1, 2)     # 屏幕上看到 3，但 x 是 None
x = add_right(1, 2)     # x 是 3
```
**"打印"是给人看的，"返回"是给程序用的。** 调试时可以 print，但别拿 print 当返回值。

@@point ⑤ 函数也是对象
@@need 要解决什么
在很多语言里函数是"特殊的东西"。在 Python 里，**函数就是普通对象**——能赋值、能传参、能放容器里。理解这一点，后面理解回调和装饰器就顺了。
@@idea 核心思路
**函数有类型、有 id、能赋值给变量、能当参数传、能当返回值**：

```python
def add(a, b): return a + b

print(type(add))        # <class 'function'>
f = add                 # 把函数赋给变量（注意：没有括号）
print(f(1, 2))          # 3

# 放进列表
ops = [add, lambda a, b: a - b]
for op in ops:
    print(op(5, 3))     # 8 / 2

# 当参数传（这就是"回调"）
def apply(func, x, y):
    return func(x, y)
apply(add, 1, 2)        # 3

# 当返回值（这就是"闭包"的基础）
def make_adder(n):
    def adder(x):
        return x + n
    return adder
add5 = make_adder(5)
add5(10)                # 15
```

**实战里的用途**：`sort(key=...)` 就是典型：

```python
jobs.sort(key=lambda j: j["salary"])       # 把"怎么排"交给调用者决定
```
@@trap 带括号和不带括号
```python
apply(add, 1, 2)        # ✓ 传函数对象
apply(add(1,2), 1, 2)   # ✗ 传的是 add 的【返回值】3，会报错
```
**记法**：**`函数名` 是"这个东西"，`函数名()` 是"做这件事"。** 需要"告诉别人怎么做事"时，传"这个东西"。

@@point ⑥ 作用域与 LEGB 规则
@@need 要解决什么
"为什么我在函数里改了变量，外面的没变？"——这是新手最困惑的问题之一。答案是**作用域**。
@@idea 核心思路
**作用域就是"一个变量在哪些地方能被看到"。** Python 查找变量名时按固定的顺序，叫 **LEGB**：

```cmd
#  L  Local      当前函数内部            ← 先找这里
#  E  Enclosing  外层函数（嵌套函数时）     ← 再找这里
#  G  Global     模块（当前 .py 文件）      ← 再找这里
#  B  Built-in   Python 内置（print/list） ← 最后找这里
#                                      都找不到 → NameError
```

```python
x = "全局"

def outer():
    x = "外层"
    def inner():
        x = "内层"
        print(x)        # 内层 ← 先在 Local 找到
    inner()
    print(x)            # 外层
outer()
print(x)                # 全局

# 三个 x 互不干扰，因为它们是三个不同的变量
```

**关键区别：在函数里"读"全局变量可以，"改"全局变量会变成新建局部变量。**

```python
count = 0

def bad():
    count = count + 1   # ✗ UnboundLocalError！
    # Python 看到你对 count 赋值，就把 count 当成本函数的局部变量
    # 但右边又要读 count，此时局部变量还没赋值 → 报错
```

**要用 `global` 明确声明**：

```python
def good():
    global count
    count = count + 1   # ✓ 现在改的是全局那个
```

**为什么 Python 要这么设计？** 因为它**倾向于让函数的副作用最小**——你在函数里改一个名字，默认是改自己的，不会意外污染外面。**这是个好设计，但写着别扭。**
@@trap 能不用 global 就别用
`global` 让函数**依赖并修改外部状态**，会让代码难以追踪（"这个变量什么时候被谁改的？"）。

**更好的做法**：把值传进去、把结果返回出来。

```python
# ✗ 靠 global 传递
total = 0
def add_to_total(x):
    global total
    total += x

# ✓ 靠参数和返回值
def add(total, x):
    return total + x

total = add(total, 5)
```

@@point ⑦ 参数传递：可变对象 vs 不可变对象 ★
@@need 要解决什么
**这是本章最关键的一节。** 很多"我明明没改它"的 bug，根源就在这里。
@@idea 核心思路
先破一个常见误解：**Python 的参数传递既不是"传值"也不是"传引用"，而是"传对象引用"**（传的是引用的值，可以叫"传共享"）。

**核心规则一句话**：

> **函数内部"重新赋值"不影响外面；"就地修改对象"会影响外面。**

**不可变对象（int / str / tuple）**——改不了，所以永远安全：

```python
def change(n):
    n = 100              # 只是让局部变量 n 指向新对象

x = 1
change(x)
print(x)                 # 1   ← 没变
```

**可变对象（list / dict / set）**——能就地改，所以危险：

```python
def add_item(lst):
    lst.append(4)        # 就地修改了【外面那个】列表

a = [1, 2, 3]
add_item(a)
print(a)                 # [1, 2, 3, 4]   ← 被改了！
```

**但如果函数内部是"重新赋值"呢？**

```python
def reassign(lst):
    lst = [9, 9, 9]      # 只是让局部变量指向新列表

a = [1, 2, 3]
reassign(a)
print(a)                 # [1, 2, 3]   ← 没变！
```

**画图理解**：

```cmd
#  lst.append(4)              lst = [9,9,9]
#
#  外部 a ──┐                  外部 a ──▶ [1,2,3]
#          ├──▶ [1,2,3,4]                 （原对象没动）
#  函数 lst ┘                  函数 lst ──▶ [9,9,9]（新对象）
#
#  改的是【对象本身】          改的是【局部变量指向谁】
#  → 外面看得见                → 外面看不见
```
@@trap 实战中的防御写法
| 场景 | 做法 |
| 不想让函数改调用者的列表 | 传副本：`func(a[:])` 或 `func(a.copy())` |
| 想改但不想影响原数据 | 在函数内部先复制：`lst = list(lst)` |
| 函数要返回一批新数据 | **别就地改参数，直接 `return` 一个新列表** ← 最推荐 |

**最推荐的写法**：

```python
# ✗ 就地改，容易埋雷
def filter_high(jobs):
    jobs[:] = [j for j in jobs if j["salary"] > 10000]

# ✓ 返回新的，调用者自己决定怎么用
def filter_high(jobs):
    return [j for j in jobs if j["salary"] > 10000]

jobs = filter_high(jobs)     # 调用者清楚自己在替换
```

@@point ⑧ 浅拷贝与深拷贝 ★
@@need 要解决什么
上一节说"传副本就安全了"。**但如果列表里装的还是列表（嵌套），副本可能不够。**
@@idea 核心思路
**三种"复制"的深度完全不同**：

```python
import copy

a = [1, 2, [3, 4]]

b = a                    # 别名：还是同一个对象
c = a.copy()             # 浅拷贝：外层是新的，内层还是共享的
d = a[:]                 # 同上，也是浅拷贝
e = list(a)              # 同上
f = copy.deepcopy(a)     # 深拷贝：递归复制，完全独立
```

**用图看区别**：

```cmd
#  原对象 a = [1, 2, [3,4]]
#     ┌──────────────────┐
#     │ 1 │ 2 │ ─────────┼──▶ [3, 4]   ← 内层列表
#     └──────────────────┘
#
#  浅拷贝 c = a.copy()
#     ┌──────────────────┐
#     │ 1 │ 2 │ ─────────┼──▶ [3, 4]   ← 【同一个内层对象】
#     └──────────────────┘
#
#  深拷贝 f = deepcopy(a)
#     ┌──────────────────┐
#     │ 1 │ 2 │ ─────────┼──▶ [3, 4]   ← 【全新的副本】
#     └──────────────────┘
```

**验证**：

```python
c[0] = 99
print(a[0])         # 1     ← 改外层，原对象没变（浅拷贝生效了）
c[2].append(5)
print(a[2])         # [3, 4, 5]   ← ！改内层，原对象【变了】

f[2].append(6)
print(a[2])         # [3, 4, 5]   ← 深拷贝不受影响
```

**结论**：**浅拷贝只保护第一层。嵌套结构要用 `copy.deepcopy()`。**
@@trap 什么时候用哪个
| 数据结构 | 用什么 |
| 一维列表（元素都是数字/字符串） | `a.copy()` 够了 |
| **嵌套结构**（列表套列表、字典套列表） | **必须 `copy.deepcopy()`** |
| 只是想把参数传进去不被改 | 优先"不改参数、直接返回新的"（上一节的推荐写法） |

**注意**：`deepcopy` 会**递归复制所有层级**，对大数据结构可能很慢。不是必须就别用。

@@point ⑨ 参数的四种类型
@@need 要解决什么
一个函数可能要接不同数量的参数、可能要可选参数。**这四种参数类型覆盖了绝大多数需求。**
@@idea 核心思路
**① 位置参数**——最普通，按顺序传：

```python
def add(a, b): return a + b
add(1, 2)
```

**② 默认值参数**——没传就用默认值：

```python
def connect(host, port=11434, timeout=30):
    ...
connect("127.0.0.1")                    # port=11434, timeout=30
connect("127.0.0.1", 8080)              # port=8080
```

**③ 命名参数（关键字参数）**——调用时写明参数名，顺序可以打乱：

```python
connect(host="127.0.0.1", timeout=60)   # 跳过了 port，用默认值
```

**④ 可变参数**——接任意多个：

```python
def total(*args):            # args 是一个【元组】
    return sum(args)
total(1, 2, 3)               # 6

def show(**kwargs):          # kwargs 是一个【字典】
    for k, v in kwargs.items():
        print(k, v)
show(a=1, b=2)

def f(a, b, *args, sep="-", **kwargs):     # 全都要
    ...
```

**参数定义的顺序是固定的**：

```cmd
#  位置参数 → 默认值参数 → *args → 强制命名参数 → **kwargs
#  def f(a, b=1, *args, sep="-", **kw)
```
@@trap 默认值参数的经典大坑
```python
def add_item(x, lst=[]):        # ✗ 危险！
    lst.append(x)
    return lst

print(add_item(1))     # [1]
print(add_item(2))     # [1, 2]   ← ！！居然记住了上次的
print(add_item(3))     # [1, 2, 3]
```

**原因**：默认值**只在函数定义时求值一次**，之后所有调用**共用同一个列表对象**。

**正确写法——用 `None` 当哨兵**：

```python
def add_item(x, lst=None):
    if lst is None:
        lst = []            # 每次调用都新建
    lst.append(x)
    return lst
```

**这是 Python 最著名的坑之一，面试也爱问。** 记住：**默认值参数永远不要用可变对象。**

@@point ⑩ lambda 与 eval
@@need 要解决什么
有时候你需要一个**只用一次的小函数**，专门为它写个 `def` 太啰嗦。另外 `eval` 很危险但你会遇到，得知道风险在哪。
@@idea 核心思路
**lambda：匿名函数**，语法是 `lambda 参数: 表达式`

```python
# 普通函数
def square(x):
    return x * x

# 等价的 lambda
square = lambda x: x * x

# 真正的用途：当作参数传给别的函数，不用起名字
jobs.sort(key=lambda j: j["salary"])
jobs.sort(key=lambda j: (j["city"], -j["salary"]))     # 多级排序
nums = [1, 2, 3]
list(map(lambda x: x * 2, nums))       # 现在更推荐写成推导式
```

**lambda 的三个限制**：

- **只能有一个表达式**，不能有语句（不能写 `if` 语句块、不能 `for`、不能 `print`）
- 不能有 docstring
- **复杂逻辑别用 lambda**——超过一行就该写 `def`

**`eval()` 与 `exec()`——知道有这回事，但基本别用**：

```python
eval("1 + 2")                    # 3        把字符串当表达式求值
exec("x = 1")                    # 执行字符串里的语句
eval("[1,2,3]")                  # [1, 2, 3] 把字符串转成列表（但该用 json.loads）
```

**为什么危险？** `eval` 会**真的执行**传进去的代码：

```python
user_input = "__import__('os').system('rm -rf /')"    # 用户输入的东西
eval(user_input)         # ✗ 灾难
```

**这就是"代码注入"**——如果 `eval` 的参数来自用户输入或网络，攻击者可以执行任意代码。

**安全替代**：

| 你想做的 | 该用什么 |
| 字符串转列表/字典 | `json.loads()` |
| 字符串转数字 | `int()` / `float()` |
| 安全的表达式求值 | `ast.literal_eval()`（只认字面量，不执行代码） |
@@trap 什么时候可以用 lambda
**只在"临时用一次、逻辑只有一个表达式"时用**：

```python
# ✓ 合适
sorted(data, key=lambda x: x[1])

# ✗ 不合适，应该写 def
f = lambda x: x * 2 if x > 0 else (x + 1 if x < -5 else 0)
```

@@point ⑪ 递归
@@need 要解决什么
有些问题**天生是"自己包含自己"的**——目录树、JSON 嵌套、快速排序。用循环写很别扭，用递归却很自然。
@@idea 核心思路
**递归 = 函数调用自己。** 必须有两个部分：

- **终止条件（基准情形）**：什么时候停下来
- **递归步骤**：把问题缩小一点，再调用自己

```python
def factorial(n):
    if n <= 1:              # ← 终止条件，必须写！
        return 1
    return n * factorial(n - 1)     # ← 递归步骤
```

**执行过程是一直"往下钻"，再一层层"往上返回"**：

```cmd
#  factorial(4)
#    → 4 * factorial(3)
#         → 3 * factorial(2)
#              → 2 * factorial(1)
#                   → 1              ← 触底
#              ← 2 * 1 = 2
#         ← 3 * 2 = 6
#    ← 4 * 6 = 24
```

**每一层调用都会创建一个"栈帧"，保存自己的参数和局部变量。** 这就是"栈"：

```cmd
#  ┌─────────────────┐
#  │ factorial(1) n=1│  ← 栈顶
#  ├─────────────────┤
#  │ factorial(2) n=2│
#  ├─────────────────┤
#  │ factorial(3) n=3│
#  ├─────────────────┤
#  │ factorial(4) n=4│  ← 栈底
#  └─────────────────┘
```

**递归真正好用的场景是"树形结构"**：

```python
def walk(node, depth=0):
    """遍历一个嵌套的目录/JSON 结构"""
    print("  " * depth + node["name"])
    for child in node.get("children", []):
        walk(child, depth + 1)          # 每个子节点再来一遍
```

**用循环写这个会非常痛苦**（得自己维护一个栈），递归一行就解决了。
@@trap 递归的两个致命问题
| 问题 | 说明 |
| **忘记终止条件** | 无限递归 → `RecursionError: maximum recursion depth exceeded` |
| **Python 有递归深度限制** | 默认约 1000 层。太深会报错——**Python 没有尾递归优化**，深递归要用循环改写 |
| **性能** | 每层都有函数调用开销，比循环慢。斐波那契那种"同一个子问题算很多遍"的，要用**缓存**（`functools.lru_cache`） |

@@point ⑫ 嵌套函数、nonlocal 与闭包入门
@@need 要解决什么
有时候一个函数只是给另一个函数打杂的，**不想让外面看到它**。这时候就把它定义在里面。
@@idea 核心思路
**嵌套函数 = 函数里定义函数**，主要用来"隐藏"：

```python
def process_jobs(jobs):
    def is_valid(job):              # 只给 process_jobs 用
        return job.get("title") and job.get("salary")
    return [j for j in jobs if is_valid(j)]
```

`is_valid` **在外面根本访问不到**——这叫"数据隐藏"，也是模块化的一种。

**`nonlocal`：修改外层函数的变量**

```python
def counter():
    n = 0
    def inc():
        nonlocal n          # 声明"我要改的是外层那个 n"
        n += 1
        return n
    return inc

c = counter()
c()     # 1
c()     # 2
```

**`nonlocal` vs `global`**：

| | 改哪个变量 |
| `global x` | 模块级（文件顶层）的 x |
| `nonlocal x` | 外层函数的 x |

**闭包 = 内层函数 + 它记住的外层变量**。`counter()` 返回的 `inc` 记住了 `n`——即使 `counter()` 已经执行完了，`n` 还活着。

**这就是"装饰器"的基础。** 后面学 LangChain 时你会看到大量 `@something` 的写法，它们本质都是闭包。
@@trap 循环里创建闭包的经典坑
```python
funcs = []
for i in range(3):
    funcs.append(lambda: i)      # ✗ 全部返回 2

print([f() for f in funcs])      # [2, 2, 2]
```

**原因**：闭包**记住的是变量本身，不是当时的值**。循环结束后 `i` 是 2，三个函数看到的都是 2。

**修复：用默认值参数把当时的值"固定"下来**：

```python
for i in range(3):
    funcs.append(lambda i=i: i)  # ✓ 默认值在定义时就绑定
print([f() for f in funcs])      # [0, 1, 2]
```

| 拿到了什么 | 为什么要紧 |
