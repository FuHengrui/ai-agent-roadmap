@@point ① 复用第三章的模拟数据
@@need 要解决什么
梯度下降需要"真实答案已知"的数据来验证收敛正确性——继续用第三章那批带噪声的线性数据。

@@idea 核心思路
```python
import numpy as np

np.random.seed(1)
X = 2 * np.random.rand(100, 1)
y = 4 + 3 * X + np.random.randn(100, 1)

X_b = np.c_[np.ones((100, 1)), X]   # 拼全 1 列吸收截距
```
- 真实参数：w0=4、w1=3（噪声存在，训练结果会接近而非等于）。
- 设 seed 保证本章每次运行结果可复现。

接下来的每种实现都遵循统一框架：**初始化 → 循环（算梯度 → 更新 w）→ 记录损失 → 对比真实参数**。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 忘了 seed，每次"跑对"结果却对不上 | 数据每次不同，无法判断收敛对不对；**先固定 seed 再比较策略** |
| 忘记拼 X_b 导致截距丢失 | 手写梯度下降的公式里没有单独处理截距的项，全靠全 1 列吸收 |

@@point ② 手写批量梯度下降 BGD
@@need 要解决什么
先从最"正统"的开始：每轮用全部样本算梯度，更新一次。

@@idea 核心思路
```python
eta = 0.1            # 学习率
n_iterations = 1000  # 迭代轮数
w = np.random.randn(2, 1)   # 随机初始化两个参数

for iteration in range(n_iterations):
    gradients = 2/100 * X_b.T.dot(X_b.dot(w) - y)  # (XᵀX·w - Xᵀy) 的展开
    w = w - eta * gradients

print(w)  # 应接近 [[4.], [3.]]
```
逐行解读：
- `X_b.dot(w) - y`：预测值减真实值 = 残差向量（100×1）。
- `X_b.T.dot(残差)`：每个特征与残差的内积 = 梯度（2×1）。
- `2/100`：来自 MSE 求导（J=1/m·Σ(...)² 求导出 2/m；为简化常写 1/m，这里保留 2/m 也能收敛，只是路径不同）。
- `w = w - eta * gradients`：核心更新公式，逐轮执行。

与解析解 `np.linalg.inv(X_b.T.dot(X_b)).dot(X_b.T).dot(y)` 的结果对比，应高度一致——这是"凸损失下两种方法殊途同归"的实证。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 梯度公式里的 2/100 记不住哪来的 | 由 MSE=1/m·Σ(ŷ-y)² 对 w 求导得到 2/m·Xᵀ(ŷ-y)；**m=100 是样本数** |
| 迭代 1000 次还没收敛 | 学习率太小或轮次不够；先看损失曲线（下一点）再调参 |

@@point ③ 用损失曲线监控收敛
@@need 要解决什么
"接近 [[4.],[3.]]"只能事后判断。怎么在训练过程中实时确认没跑偏？

@@idea 核心思路
在循环里记录每一轮的 MSE，训练后画出来：
```python
import matplotlib.pyplot as plt

cost_history = []
for iteration in range(n_iterations):
    gradients = 2/100 * X_b.T.dot(X_b.dot(w) - y)
    w = w - eta * gradients
    cost = np.mean((X_b.dot(w) - y)**2)   # 当前 MSE
    cost_history.append(cost)

plt.plot(cost_history)
plt.xlabel("iteration"); plt.ylabel("MSE")
plt.show()
```
正确长相：一条**快速下降、逐渐平坦**的曲线（指数衰减形态）。如果曲线上扬或锯齿状乱抖 → 学习率太大；如果缓慢下滑不达谷底 → 学习率太小。

**损失曲线 = 梯度下降的仪表盘**，后续所有实验第一件事都是先看它。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 曲线前段飞涨再崩溃 | η 过大导致发散；立即把 η 缩小 10 倍重跑，别再加大迭代次数硬扛 |
| 只看最终数值不看曲线 | 曲线能区分"没收敛"与"收敛到错误位置"，信息量大得多 |

@@point ④ 手写随机梯度下降 SGD：防止取样偏差
@@need 要解决什么
每步只用一个样本，怎么保证"随机"两个字是真的随机而不是顺序偏差？

@@idea 核心思路
```python
n_epochs = 50          # 全部数据过 50 遍
t0, t1 = 5, 50         # 学习率衰减的两个参数

def learning_schedule(t):
    return t0 / (t + t1)    # 轮次越大，学习率越小

w = np.random.randn(2, 1)

for epoch in range(n_epochs):
    for i in range(100):                       # 每轮遍历 100 个样本
        random_index = np.random.randint(100)  # 随机抽 1 个样本下标 ← 关键
        xi = X_b[random_index:random_index+1]  # 取出该样本（保持二维）
        yi = y[random_index:random_index+1]
        gradients = 2 * xi.T.dot(xi.dot(w) - yi)   # 单样本梯度
        eta = learning_schedule(epoch * 100 + i)   # 学习率随步数衰减
        w = w - eta * gradients

print(w)  # 同样应接近 [[4.], [3.]]
```
三个关键点：
- `np.random.randint(100)`：**真随机**抽取样本下标，避免顺序遍历带来的偏差。
- 学习率 `learning_schedule(step)`：随步数增大而变小——先大步探索、后小步精修。
- 双层循环：外层 epoch（过几遍数据），内层每遍逐样本更新。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 固定 `range(100)` 顺序取，还说自己是 SGD | 那是"顺序更新"，每轮样本顺序相同会产生周期偏差；**必须随机下标** |
| 忘记切片保留二维（取成 1 维） | `X_b[i:i+1]` 保持 (1,2) 形状，才能和 (2,1) 的 w 做矩阵乘法；取 `X_b[i]` 会变一维报错 |

@@point ⑤ 学习率衰减的影响：先野后稳
@@need 要解决什么
同一个 SGD，固定学习率 vs 衰减学习率，收敛结果差多少？做一次对照实验就知道。

@@idea 核心思路
对照实验设计：
- 方案 A：固定 eta=0.1 跑 50 epochs 的 SGD。
- 方案 B：用 `learning_schedule` 衰减跑同样的 50 epochs。
- 对比两者最终 w 与解析解的接近程度。

结果通常：**方案 B 明显更接近真实参数**。原因：
- 固定大 η：后期在最优解附近"来回横跳"、精度上不去。
- 衰减 η：后期步长极小，能"落定"到最优解近旁——既有前期的探索速度，又有后期的收敛精度。

这就是"学习率衰减是 SGD 标配"的最直观证据。工程上 sklearn 的 `SGDRegressor(learning_rate='constant'/'adaptive'/'invscaling')` 正是这些策略的封装。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 衰减参数 t0、t1 随便设，效果差 | t0/t1 决定"起点多大、降多快"；教程给的 5/50 是经验值，可微调观察 |
| 衰减曲线做成了"断崖式跳水" | 应平滑衰减；突变式学习率会导致训练波动异常 |

@@point ⑥ 手写小批量梯度下降 Mini-Batch
@@need 要解决什么
三兄弟只剩 Mini-Batch 没写：按批取样本、批内求平均梯度。它与前两者的代码差异就两行。

@@idea 核心思路
```python
n_epochs = 50
batch_size = 20          # 每批 20 个样本
n_batches = int(100 / batch_size)   # 100 条数据 → 5 批

w = np.random.randn(2, 1)

for epoch in range(n_epochs):
    shuffled = np.random.permutation(100)      # 打乱样本顺序 ← 关键
    for batch in range(n_batches):
        indices = shuffled[batch*batch_size : (batch+1)*batch_size]
        xi = X_b[indices]                       # 一批样本 (20,2)
        yi = y[indices]                         # 对应标签 (20,1)
        gradients = 2/batch_size * xi.T.dot(xi.dot(w) - yi)  # 批内平均梯度
        eta = learning_schedule(epoch * n_batches + batch)
        w = w - eta * gradients

print(w)  # 同样接近 [[4.], [3.]]
```
与 SGD 的两处关键差异：
- `np.random.permutation(100)`：每 epoch 前**整体打乱**，再按顺序切批——保证每批内部随机、不重不漏。
- `2/batch_size`：梯度取批内平均，方向比单样本稳。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 不打乱直接 `X_b[:20]` 切批 | 每 epoch 的批构成完全相同，等于固定噪声模式，收敛会变差；**先 permute 再切** |
| batch_size 不能整除样本数 | 整除优先；不整除时最后一批不满也照常处理（或用丢弃/补齐策略） |

@@point ⑦ 用 sklearn 的 SGDRegressor 验证
@@need 要解决什么
手写版验证了原理，工程上当然有现成实现。sklearn 的 SGDRegressor 就是这个"现成版"——直接对比它的结果。

@@idea 核心思路
```python
from sklearn.linear_model import SGDRegressor

sgd_reg = SGDRegressor(max_iter=1000, tol=1e-3,
                       eta0=0.1, learning_rate='constant', random_state=1)
sgd_reg.fit(X, y.ravel())     # 注意 y 要一维
print(sgd_reg.intercept_, sgd_reg.coef_)
```
- `learning_rate='constant'` + `eta0=0.1`：等价于固定学习率版本。
- 改 `learning_rate='invscaling'`（默认是 `adaptive`）即开启衰减策略。
- `max_iter`、`tol`：最大轮数与收敛阈值（损失变化小于 tol 即停）。
- 收敛后 `intercept_` 与 `coef_` 应逼近 (4, 3)。

这样"手写 → 调包"双线对照完成：**先懂原理再上工具，出问题时能自己算**。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| `fit(X, y)` 报维度错 | SGDRegressor 要求 y 一维：`y.ravel()` 或 `y.reshape(-1)` |
| 不给 `random_state`，每次结果不同 | SGD 有随机性；**设 seed 保证可复现**，实验报告必须注明 |
| 用含缺失值的原始数据直接 fit | 梯度下降不接受 NaN；先清洗（后续归一化章节的主战场） |

@@point ⑧ 归一化对梯度下降的决定性影响（预告实验）
@@need 要解决什么
真实数据各列量纲差异巨大（年龄 25 vs 收入 80000），梯度下降会怎样？做一个 30 秒的预告实验为下一章铺垫。

@@idea 核心思路
造一个两特征数据：x1 量级 0~1、x2 量级 10000~20000，跑同样学习率的梯度下降：
```python
X2 = np.c_[np.random.rand(100, 1),          # 小量纲特征
           10000 + 10000 * np.random.rand(100, 1)]   # 大量纲特征
y2 = 4 + 3*X2[:, 0:1] + 2*X2[:, 1:2] + np.random.randn(100, 1)

w = np.random.randn(3, 1)
for i in range(500):
    gradients = 2/100 * X2_b.T.dot(X2_b.dot(w) - y2)
    w = w - eta * gradients
```
典型现象：**损失曲线迟迟不收敛，或收敛极慢、参数抖动**。原因：特征量纲差异让损失"山谷"变成又长又窄的"峡谷"，垂直方向陡、水平方向缓，同一学习率在两个方向上一快一慢，步长怎么调都顾此失彼。

**解法（下一章主线）**：归一化/标准化把各特征压到同一量纲，把"峡谷"整形回"碗"，梯度下降立刻恢复丝滑。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 数据量大纲不一但解析解却"没事" | 解析解一步到位不迭代，天然免疫此问题——**归一化主要是"喂"给迭代法的** |
| 以为归一化只影响收敛速度 | 还影响特征权重可比性与正则化效果，下一章细讲 |

@@summary
代码落地完毕，盘点：

| 实现 | 核心代码 | 关键点 |
|---|---|---|
| BGD | gradients = 2/m·X_b.T.dot(X_b.dot(w)-y) | 每轮全量、方向准、曲线平滑 |
| 损失曲线 | cost_history.append(MSE) | 一切调参的第一仪表盘 |

| Mini-Batch | permutation 打乱 + 批平均梯度 | 稳快折中、深度学习标准 |

| 预告实验 | 量纲悬殊数据 + 梯度下降 | 收敛变差 → 引出归一化 |
