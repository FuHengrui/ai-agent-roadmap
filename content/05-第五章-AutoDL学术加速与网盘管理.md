@@point ① 学术加速是什么
@@need 要解决什么
AutoDL 实例在国内机房，访问 GitHub、HuggingFace 等海外站点时速度极慢甚至无法访问，直接导致拉模型、克隆代码、下数据集全部卡壳。

@@idea 核心思路
**学术加速** 是 AutoDL 内置的**网络加速服务**：开启后，实例访问以下学术/开源资源的速度显著提升：

- github.com
- githubusercontent.com
- githubassets.com
- huggingface.co

两条重要声明（出自平台说明）：
1. **仅限学术用途**：解决"学术使用 github 和 huggingface 网络速度慢的问题"；
2. **不承诺稳定性保证**：导流加速是便利服务，不保证 100% 稳定，关键时刻（如大规模下载）请多留余量。

**适用范围**：Git 仓库克隆、Hugging Face 模型/数据集下载等科研相关场景。加速解决的是"慢"的问题，不改变你要访问的内容本身。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 加速后有些网站依旧慢 | 加速只覆盖 github/huggingface 相关域名；其他海外站点请另找合适的国内镜像 |
| 以为加速能访问一切网站 | 不能；它只加速指定学术域名，不承诺稳定性，更不是万能的 |
| 大规模下载偶尔失败 | 加速不承诺稳定；重要大文件建议配合网盘方式（本章后文）分发 |

@@point ② 终端方式开启学术加速
@@need 要解决什么
明确了加速能干什么，接下来就是"怎么开"。终端是最基本的方式，一条命令生效。

@@idea 核心思路
在实例的 **终端（Terminal）** 中执行：

```bash
source /etc/network_turbo
```

执行后**当前终端会话**即处于加速网络下。说明两点：

- 该命令本质是**加载代理环境变量**（http_proxy/https_proxy 指向加速通道）；
- 加速是**会话级**的：重开终端、重连 SSH 后往往需要重新执行一次。

**验证**：执行后 `env | grep proxy` 能看到 http_proxy/https_proxy 变量，即为加速中；随后 `git clone`、`wget`、`huggingface-cli download` 等下载任务即可提速。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| source 后提示找不到文件 | 确认是 AutoDL 官方镜像/实例；个别社区镜像可能没有该脚本，重开官方镜像实例 |
| 重连后速度又变慢 | 会话级加速失效了，重新 source 一次即可 |
| source 后下载正常但很慢 | 加速不承诺稳定性；换低峰时段或改用网盘/镜像源 |

@@point ③ Notebook 方式开启学术加速
@@need 要解决什么
在 Jupyter Notebook / JupyterLab 里跑实验时，没有"终端"可敲 source 命令；或者希望在**代码里**先把加速打开再执行下载，需要编程方式注入代理。

@@idea 核心思路
在 Notebook 的单元格里执行以下代码，即可把加速代理注入当前 Python 进程的环境变量：

```python
import subprocess
import os
result = subprocess.run('bash -c "source /etc/network_turbo && env | grep proxy"',
                       shell=True, capture_output=True, text=True)
output = result.stdout
for line in output.splitlines():
    if '=' in line:
        var, value = line.split('=', 1)
        os.environ[var] = value
```

代码逻辑拆解：

1. `source /etc/network_turbo && env | grep proxy`：在 bash 子进程里开启加速并**抓取代理环境变量**；
2. 拿到输出后按行解析形如 `http_proxy=xxx` 的键值对；
3. 逐条 `os.environ[var] = value` 写入当前 Python 进程。

执行完该单元格，**当前 Notebook 内核**里的下载（hf 下载、requests、wget 子进程等）都会走加速通道。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 执行后 env 里没有新变量 | 先确认实例是官方镜像；或直接在终端手动 source 一次再回 Notebook |
| 单元格报 subprocess 相关错误 | 环境缺依赖概率低；检查是否在 Notebook 内核而非普通 python 脚本中执行 |
| 只在当前内核生效 | 重启内核需重跑该单元格；这是进程级注入的正常行为 |

@@point ④ 取消学术加速
@@need 要解决什么
加速走的是代理中转，平台**建议不用时关闭**，因为"该加速可能对正常网络造成一定影响"——比如访问国内资源被绕路变慢。

@@idea 核心思路
取消加速只需清掉两个代理环境变量：

```bash
unset http_proxy && unset https_proxy
```

**什么时候需要取消**：
- 下载/访问国内资源感觉变慢（被代理绕路）；
- 某些工具对代理敏感、报代理相关错误；
- 本次学术下载已完成，回归纯净网络。

**注意**：unset 只对当前终端会话生效；重开终端本来就不带加速，无需操作。想确认当前状态，用 `env | grep proxy` 查看变量是否还在。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| unset 后下载仍走代理 | 正在运行的进程继承的是**启动时**的环境；退出重开相关进程/终端 |
| 忘了一直开着加速 | 不一定要关，但跑长任务前评估一下；国内资源优先场景建议关 |
| 关闭后又想开 | 再 source /etc/network_turbo 即可，来回切换没有副作用 |

@@point ⑤ AutoPanel 公网网盘与访问密码
@@need 要解决什么
代码、小文件用 SSH 传没问题，但模型权重十几 GB、数据集几十 GB，用命令行传既慢又容易中断。需要一个浏览器就能用的**云端文件中转站**。

@@idea 核心思路
**AutoPanel 公网网盘**是 AutoDL 实例内置的文件管理面板。打开方式：

1. 实例**开机**后，在控制台「快捷工具」一列找到 **AutoPanel** 入口；
2. 点击进入后，打开 **「公网网盘」**。

**第一步是设置独立访问密码**——这一点被很多人忽略但非常重要：

- 该密码**只用于网盘面板访问**，与实例系统密码无关；
- 平台提示：**密码要更复杂、更安全**，因为你接下来授权的网盘个人账户信息（如阿里云盘授权凭证）会**通过该密码加密保存**；
- **如果忘记密码则需重新初始化**，之前配置的授权会作废。

设置完成后，公网网盘界面就是你的网页版文件管理器：可以浏览、上传、下载实例文件，图形化、比纯 scp 可靠，还能当异地备份用。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| AutoPanel 打不开 | 确认实例处于**运行中**；关机状态快捷工具入口不可用 |
| 访问密码设得太简单 | 它加密的是你的云盘授权信息，务必用复杂密码并记牢 |
| 忘记访问密码 | 只能重新初始化面板，已授权的云盘账号要重新授权 |

@@point ⑥ 授权阿里云盘
@@need 要解决什么
AutoPanel 上传要先经本地中转，几十 GB 的大文件还是费劲。阿里云盘下载速度快、免流量，把模型/数据集提前放进自己的阿里云盘，授权后实例直接拉取，一次到位。

@@idea 核心思路
在 AutoPanel 公网网盘的网盘列表中选择 **阿里云盘**：

1. 网盘列表里找到「阿里云盘」入口并点击；
2. 使用**阿里云盘 APP 扫码授权登录**（手机打开阿里云盘 App 扫二维码，确认授权）；
3. 授权成功后，该网盘出现在面板的可用网盘列表中，可进入浏览文件。

授权后你的阿里云盘就像"挂"到了 AutoDL 上，实例侧可以直接从里面取文件。**前提准备**：提前把要用的模型权重/数据集压缩包传到自己的阿里云盘（网盘空间和上传由你自己的阿里云盘账号承担）。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 扫码后没反应 | 确认登录的是**你自己的阿里云盘账号**，App 是最新版；换网络重试 |
| 网盘列表看不到阿里云盘 | 先确认访问密码已设置完成，再刷新面板 |
| 授权了但浏览为空 | 文件需在阿里云盘可见目录（如根目录/我的资源）；先到手机 App 确认文件在 |

@@point ⑦ 从网盘下载文件到实例
@@need 要解决什么
授权完成，最后一步是"怎么把文件真正拿到实例里"——下载到哪个目录、能不能自己挪位置。

@@idea 核心思路
授权后的下载非常简单，**不需要敲命令**：

1. 在 AutoPanel 网盘里选中要下载的网盘（如阿里云盘）；
2. 浏览网盘中的文件，选中目标文件/文件夹；
3. 点击 **下载**，文件即传输至**本实例（本地）**。

下载位置规则（平台固定行为）：
- 文件**固定下载到实例的 /root/autodl-tmp 下**；
- 下载完成后，你可以**自行移动**到需要的目录。

**为什么固定到 /root/autodl-tmp**：这是实例的数据盘，空间大、持久可靠，正是放模型/数据集的正确位置——你大概率不用再挪。

**检查**：下载完成后在终端 `ls /root/autodl-tmp` 确认文件已就位；再按需 `mv` 到组织好的目录。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 下载后找不到文件 | 去 /root/autodl-tmp 找；注意是数据盘路径，不是 /root 根目录 |
| 下载到一半失败 | 大文件可先在阿里云盘分卷压缩；或换网络低谷期重试 |
| 想下到别的目录 | 先在网盘下载到 autodl-tmp，再用 mv 移动；画布规则是固定落点 |

@@point ⑧ 大文件与数据盘的正确姿势
@@need 要解决什么
网盘、加速都配好了，但很多新手依然踩"跑着跑着磁盘满了""数据莫名其妙没了"的坑——本质是没搞清系统盘和数据盘的分工。

@@idea 核心思路
AutoDL 实例的磁盘分工（默认逻辑）：

| 磁盘 | 路径 | 特点 | 适合放 |
|---|---|---|---|
| 系统盘 | /root（除 autodl-tmp 外） | 空间小（默认几十 GB），重装镜像可能清空 | miniconda 环境、pip 包、代码脚本 |
| 数据盘 | /root/autodl-tmp | 空间大（按之前扩容），持久可靠 | 数据集、模型权重、checkpoints、训练日志 |

**黄金习惯**：
1. 模型/数据集/输出**全部放数据盘**：`/root/autodl-tmp/dataset/`、`/root/autodl-tmp/models/`；
2. 代码脚本放系统盘或项目目录（体积小，方便 IDE 同步）；
3. 重要结果定期**备份到网盘**（AutoPanel 公网网盘），防实例数据丢失；
4. 磁盘空间不足时，先看数据盘占用，再清理旧 checkpoints（模型文件通常最大）。

**检查命令**：`df -h` 查看各磁盘占用；`du -sh /root/autodl-tmp/*` 看数据盘下各目录体积。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 买了大容量数据盘还是提示空间不足 | 文件可能写到了系统盘；用 df -h 确认，大文件迁到 autodl-tmp |
| 重装/换镜像后代码数据没了 | 系统盘随镜像重置；**重要数据务必先备份网盘**，别赌数据盘 |
| 训练产物散落各处 | 固定目录结构（dataset/models/logs），脚本里写死这些路径 |
