@@point ① 压缩方法的完整分类：两个大方向
@@need 要解决什么
模型压缩有哪些流派？它们之间的本质区别是什么？

@@idea 核心思路
从"数据、模型、硬件"多维度看，压缩方法分两大类：

**① 压缩已有的网络（针对既有模型）**
- **张量分解**：把大矩阵拆成多个小矩阵的乘积，用低秩近似。
- **模型剪枝**：删掉不重要的连接、神经元或通道。
- **模型量化**：用低精度整数/浮点代替高精度浮点。

**② 构建新的小型网络（针对新模型）**
- **知识蒸馏**：大老师教小学生，把知识迁移到小网络。
- **紧凑网络设计**：从结构上就设计得轻量（如 MobileNet 的深度可分离卷积）。

区别一句话：**前者是"把已训好的大模型变小"，后者是"直接设计一个天生就小的模型"**。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 把两大方向混为一谈 | 先判断手里是"现成模型"还是"从零设计"，决定走哪条技术路线 |
| 漏掉紧凑网络设计 | 它属于"构建新网络"分支，与剪枝/量化是并列关系而非从属 |

@@point ② 三大压缩已有网络的技术对比
@@need 要解决什么
剪枝、量化、张量分解各有什么特点？什么时候用哪个？

@@idea 核心思路

| 技术 | 思路 | 收益侧重 | 特点 |
|---|---|---|---|
| 张量分解 | 大矩阵≈小矩阵乘积（低秩） | 体积、速度 | 结构性变换，实现较复杂 |
| 模型剪枝 | 删掉不重要的连接/通道 | 体积（配合稀疏存储） | 直观，可与量化搭配 |
| 模型量化 | 浮点→定点/低比特 | 体积、速度、功耗 | 工业界最常用，收益直接 |

三者的关系不是互斥而是互补：生产实践中常见"剪枝 + 量化"组合（先剪掉冗余连接，再把剩余权重压到 8bit），收益叠加。张量分解因实现复杂，现代大模型场景用得少一些。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为只能选一种技术 | 典型的"协同优化"就是剪枝+聚类+量化叠加，效果 1+1>2 |
| 忽略各技术的适用土壤 | 张量分解偏好结构规整的层，剪枝对冗余多的模型效果好，量化基本通吃 |

@@point ③ 知识蒸馏：把大模型"教"成小模型
@@need 要解决什么
知识蒸馏和剪枝/量化有什么本质区别？

@@idea 核心思路
**知识蒸馏（Knowledge Distillation, KD）** 属于"构建新网络"路线：用一个已经训练好的大模型（老师）去"教"另一个小模型（学生）。

- 老师模型通常更强（更大/更准），学生模型在老师指导下"突破自我"，学到比自己独立训练更好的表现。
- 学生拿着老师的输出分布（软标签，含类别相似度信息）当学习目标，而不只是硬标签（0/1）。

它与剪枝/量化的本质区别：**剪枝和量化"动的是大模型本身"，蒸馏"造的是一个全新小模型"**。所以蒸馏适合"目标就是要一个小模型"的场景，而不是"必须保留原模型架构"的场景。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为蒸馏是"压缩大模型" | 学生是独立的小网络，蒸馏是"知识迁移"，不是"压缩原模型文件" |
| 混淆迁移学习与蒸馏 | 迁移学习复用预训练特征，蒸馏复用"老师的输出分布"，目标不同 |

@@point ④ 紧凑网络设计：一步到位的轻量方案
@@need 要解决什么
能不能不折腾压缩，直接设计一个轻快的小网络？

@@idea 核心思路
**紧凑网络设计**：从架构上就让模型天生小而快，代表作：

- **MobileNet**：深度可分离卷积，把标准卷积拆成逐通道卷积 + 1x1 卷积，计算量骤降。
- **ShuffleNet**：通道洗牌 + 分组卷积，进一步压缩计算。
- **EfficientNet**：用复合缩放（深度/宽度/分辨率一起调）在精度与代价间找最优。

这类方法**直接构建新模型**，不需要先训大模型再压缩。它与蒸馏是"小模型路线"的两条子路：蒸馏靠老师教，紧凑设计靠结构本身省。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 把紧凑网络设计塞进"压缩已有网络" | 它是"构建新网络"分支，对象是全新模型，不是改造已有模型 |
| 忽略它与蒸馏的搭配 | 紧凑网络 + 蒸馏是常见组合：学生用小型结构，老师提供训练信号 |

@@point ⑤ 框架支持矩阵：工具链决定落地
@@need 要解决什么
理论再好也要有工具，主流框架都支持哪些压缩能力？

@@idea 核心思路
常见工具与能力概览：

| 框架/工具 | 支持能力 |
|---|---|
| QKeras | 量化感知训练（QAT） |
| TensorFlow Model Optimization Toolkit | 剪枝 + 量化 |
| PyTorch | 剪枝 + 量化（`torch.nn.utils.prune`、`torch.ao.quantization`） |
| TensorRT | 训练后量化（PTQ） |
| Distiller（偏研究型） | 剪枝、量化、知识蒸馏 |
| ncnn | 量化 |

选择逻辑：**生产部署优先看 TensorRT/PyTorch 的 PTQ 能力（快、易用），研究探索用 Distiller（全都要）**；移动端轻量推理可看 ncnn。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 只看框架名气不查能力 | 不同工具擅长不同技术（如 QKeras 只做 QAT），先核对能力矩阵再选型 |
| 忽略工具链的硬件绑定 | TensorRT 绑定 NVIDIA GPU，ncnn 面向移动端，框架选型跟着部署平台走 |

@@point ⑥ 从"数据、模型、硬件"多维度看压缩
@@need 要解决什么
为什么说压缩要从多个层面综合看，而不是只盯着模型？

@@idea 核心思路
一个概括："从数据、模型和硬件**多维度**的层面来分析压缩和加速的方法"：

- **数据维度**：输入能否降维/剪枝（如只喂关键 token）、用廉价数据校准量化。
- **模型维度**：剪枝/量化/蒸馏/紧凑结构——本书主线。
- **硬件维度**：GPU/FPGA/ASIC 的能力差异决定量化激进程度与算子优化空间（如 FPGA 可做更激进的量化）。

**压缩不是模型单方面的事**——同样的量化，在不同硬件上收益天差地别；同样的模型，配不同数据校准，量化精度也不同。多维协同才叫"系统优化"。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 压缩只看模型参数 | 数据与硬件维度同样贡献收益，忽略它们会错过大量优化空间 |
| 把"模型压缩"与"推理加速"割裂 | 二者同源：都是为了又快又小，硬件算子配合是落地关键 |

@@point ⑦ 生产实践里的主流组合
@@need 要解决什么
知道这么多技术，实际项目里最常用的是哪一套组合？

@@idea 核心思路
工业界 LLM 推理最常见的技术栈组合：

1. **量化为主力**：权重压到 int8/int4/FP8（如 AWQ/GPTQ/FP8 量化），直接省显存、提吞吐。
2. **剪枝与蒸馏做增强**：模型冗余明显时先剪枝/蒸馏减小基础模型，再量化。
3. **稀疏算子配合**：剪枝后要配备稀疏矩阵算子，否则剪了白剪。

现代推理引擎（vLLM、TensorRT-LLM）已把量化、算子优化、KV 缓存优化打包成开箱即用的能力——压缩思想已经"内置"到推理框架里，工程师更多是选参数而非从零实现。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 以为生产要"从零写剪枝代码" | 主流框架/SDK 已封装，重点是理解原理后正确选用与调参 |
| 只量化权重不关心激活 | 激活量化同样是显存与带宽大头，全整数/混合精度方案强调两者一起处理 |

@@point ⑧ 本章小结：一张压缩全景图
@@need 要解决什么
学完本章，如何把压缩方法记成一张清晰的图？

@@idea 核心思路
用一棵"树"收拢全貌：

```
模型压缩
├── 压缩已有网络
│   ├── 张量分解（低秩近似）
│   ├── 模型剪枝（删连接/通道）── 本书重点
│   └── 模型量化（浮点→定点）── 本书重点
└── 构建新小网络
    ├── 知识蒸馏（老师教学生）── 本书重点
    └── 紧凑网络设计（MobileNet等）
框架与工具：PyTorch / TensorFlow / TensorRT / Distiller / ncnn
```

后几章将按 "剪枝 → 量化 → 知识蒸馏" 的顺序展开，每章都在这个全景图里有明确坐标。

@@trap 坑在哪
| 现象 | 原因 / 怎么办 |
|---|---|
| 只见技术不见框架 | 技术路线与工具链要一起记，落地离不开框架支持 |
| 混淆五大技术归属 | 时刻用"压已有网络/建新网络"二分法定位，就不会张冠李戴 |

@@summary
这一章铺开了模型压缩的完整路线图：

| 分类 | 技术 | 一句话|
|---|---|---|
| 压缩已有网络 | 张量分解 | 大矩阵拆小矩阵乘积 |
| 压缩已有网络 | 模型剪枝 | 删掉不重要的参数/通道 |
| 压缩已有网络 | 模型量化 | 浮点换低比特表示 |
| 构建新小网络 | 知识蒸馏 | 大模型教师教小模型学生 |
| 构建新小网络 | 紧凑网络设计 | 天生小而快的架构（MobileNet 等） |
| 工具链 | PyTorch/TF/TensorRT/Distiller/ncnn | 压缩能力落地靠框架 |

一句话记住本章：**模型压缩分两大路：对已有网络做"张量分解、剪枝、量化"，对全新网络做"知识蒸馏、紧凑设计"；框架工具决定落地路径（PyTorch 剪枝量化、TensorRT 做 PTQ、Distiller 研究全家桶），从数据、模型、硬件多维度协同才是完整优化——本书接下来依次深挖剪枝、量化和蒸馏三座大山。**
