# 内容抽检报告（2026-10-28）

> 范围：全库 238 章的机器扫描 + 8 章人工逐字读。
> 原则：只报有把握的；拿不准的进「存疑」，不硬改。
> 行号是**修改前**的行号。

## 一、方法

| 手段 | 覆盖 | 查什么 |
|---|---|---|
| 版本声明扫描 | 全库 89 处 / 26 个不同值 | 版本号、包名、命令行、模型名是否还成立 |
| 安装命令扫描 | 全库 236 条 | 包名写法、版本约束、命令是否合法 |
| 端口一致性扫描 | 全库 | 同一章里 8000/8080/5173/9200/3306 等是否自相矛盾 |
| import 与安装指引对照 | 全库 72 个第三方包 | 代码用到、但全书没教怎么装的包 |
| 人工逐字读 | 8 章（阶段 6/9/10/13/18/21 各取） | 事实、可运行性、自测题与知识点对应、章内自相矛盾 |
| 代码块语法扫描 | 930 个 python 块 / 13 个 json / 5 个 js | 拼写类语法错 |

**关于语法扫描的说明**：它报了 75 个「错」，但绝大多数是**片段**——`await` 写在函数外、带 `…` 的示意、`PUT /news` 这种 HTTP 请求标成了 json。这类不是错，不能当问题修。它的价值在于「如果连片段都能编译过，说明没有低级语法灾难」；真正的错还得人读。

## 二、结论摘要

- **版本声明全部成立**：`Vite 8`、`Python 3.14` 经查确实存在；`Python 3.3+`（命名空间包）、`3.7+`（字典有序）、`MySQL 8.0.16`（CHECK 约束才开始强制）都是历史事实。
- **没有系统性错误**：端口没有成片冲突；安装命令的包名与版本约束写法正确。
- **但抽读的 8 章里翻出 6 个「必须改」**，都是**照抄就报错**那一类，不是文风问题。
- 自测题在抽读的章节里**都能在正文找到对应内容**，没发现答案不唯一或题目本身出错。

## 八、第二遍复核（2026-10-29 晚）

> 第一遍查「照抄会不会报错」；第二遍换角度：**概念因果、章内自洽、数据流闭环、自测题可推导**。

### 为什么值得做

第一遍修完不等于对了。第二遍在这 18 章里又抓出 27 条必须改，其中 3 条是**我第一遍自己改坏的**：

| 我改坏的 | 症状 |
|---|---|
| RAG 章把 `top_k` 传成 `top_k * 3` | retriever 内部已乘 3，实际每路 45 条、合并 90 条 |
| RAG 章 `await self.retriever.retrieve(...)` | 那是同步方法，`await` 它直接报错 |
| RAG 章把 `$contains` 换成 `$in` | `laws` 存的是拼接串，`$in` 查单条永远不相等 → 过滤恒空 |

### 二轮抓到的典型（第一遍看不出来）

- **Docker**：`catalina.sh` 不带 `run` → 打印用法就退出，容器秒退；`catalina.out` 在 `logs/` 不在 `bin/`
- **vLLM**：KV 缓存**总预算由 `--gpu-memory-utilization` 划定**，不是 `--max-model-len`
- **vLLM**：章首「10 倍」与正文「2~4 倍」是两个口径（前者对 HF 默认实现，后者对 FasterTransformer）
- **血糖**：阈值不分测量类型，空腹 8.5 被判「正常」，达标率 100% 而同批平均值又判「中风险」
- **LangGraph**：`create_agent` 不在 `langgraph.prebuilt`；interrupt 恢复是**节点重跑**不是续行
- **向量库**：`similarity_search_with_score` 返回**距离**，正文按「分数 > 0.7」判断，方向反了
- **文生图**：`MultiModalConversation` 是多模态理解，文生图要用 `ImageSynthesis`
- **选题/文案**：`t_titles` 没有 `user_id` 列；`/v1/save-copy` 漏 `/create`；reset 与 copy 没有状态守卫

### 结论

- 「读过一遍」只保证**没有明显的照抄错误**；要保证**讲得对**，得换角度再读一遍。
- 二轮成本约等于一遍的 60%（不用再查语法），但产出的是完全不同的一类错。
- 剩余 220 章都没做二轮——这是当前最大的已知缺口，不能算「已核对」。
