# 内容抽检报告（2026-10-28）

> 范围：全库 238 章的机器扫描 + 8 章人工逐字读。
> 原则：只报有把握的；拿不准的进「存疑」，不硬改。
> 行号是**修改前**的行号。

## 一、方法

| 手段 | 覆盖 | 查什么 |
|---|---|---|
| 版本声明扫描 | 全库 89 处 / 26 个不同值 | 版本号、包名、命令行、模型名是否还成立 |
| 安装命令扫描 | 全库 236 条 | 包名写法、版本约束、命令是否合法 |
| 端口一致性扫描 | 全库 | 同一章里 8000/8080/5173/9200/3306 等是否自相矛盾 |
| import 与安装指引对照 | 全库 72 个第三方包 | 代码用到、但全书没教怎么装的包 |
| 人工逐字读 | 8 章（阶段 6/9/10/13/18/21 各取） | 事实、可运行性、自测题与知识点对应、章内自相矛盾 |
| 代码块语法扫描 | 930 个 python 块 / 13 个 json / 5 个 js | 拼写类语法错 |

**关于语法扫描的说明**：它报了 75 个「错」，但绝大多数是**片段**——`await` 写在函数外、带 `…` 的示意、`PUT /news` 这种 HTTP 请求标成了 json。这类不是错，不能当问题修。它的价值在于「如果连片段都能编译过，说明没有低级语法灾难」；真正的错还得人读。

## 二、结论摘要

- **版本声明全部成立**：`Vite 8`、`Python 3.14` 经查确实存在；`Python 3.3+`（命名空间包）、`3.7+`（字典有序）、`MySQL 8.0.16`（CHECK 约束才开始强制）都是历史事实。
- **没有系统性错误**：端口没有成片冲突；安装命令的包名与版本约束写法正确。
- **但抽读的 8 章里翻出 6 个「必须改」**，都是**照抄就报错**那一类，不是文风问题。
- 自测题在抽读的章节里**都能在正文找到对应内容**，没发现答案不唯一或题目本身出错。
