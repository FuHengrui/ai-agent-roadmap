# 维护手册

> 这份是给「三个月后的自己」看的：怎么加一章、怎么改一个错、CI 红了先看哪儿。
> 全部基于仓库里现成的脚本，不需要额外装东西（只用 Python 标准库 + 可选的 `pyyaml`）。

---

## 0. 先认清结构

```
content/*.md        238 章的**源文件**（唯一的真源，改内容只改这里）
site/**/*.html       由 content 生成的**产物**（要一起提交，为了能双击离线看）
tools/build_*.py     生成器：site / search / sitemap / ledger
tools/check_*.py     检查器：内容、一致性、事实、import、发布扫描
docs/                报告与台账（抽检报告、覆盖台账、事实清单、待办、冒烟测试）
.github/workflows/   CI：10 道闸 + 部署
```

一句话：**改 `content/`，跑生成器，再跑检查器，然后提交。**

---

## 1. 加一章：五步

1. **建文件**：`content/NN-<章名>.md`，`NN` 是两位数编号（如 `03-`）。文件名里的编号必须和正文 `@@h1` 里的章号一致，否则 `check_consistency.py` 会报。
2. **写头部**：第一行 `@@h1 第一章 xxx`，第二行 `@@sub 阶段 X · 阶段名　|　分组名　|　难度 ★★☆`。`@@sub` 里的阶段号要和 NAV（`tools/site_config.py`）对得上。
3. **写六块**：`@@why`（为什么学）、`@@map`（上一章→本章→下一章）、`@@prep`（开始之前）、`@@goal`（学到这儿就够了）、正文若干 `@@point`、`@@summary`（小结）、`@@quiz`（自测）、`@@links`（参考）。
4. **生成 + 检查**：
   ```bash
   python tools/build_site.py && python tools/build_search.py && python tools/build_sitemap.py && python tools/sync_index.py
   python tools/check_content.py && python tools/check_consistency.py
   python tools/build_ledger.py        # 把新章补进覆盖台账
   ```
5. **提交**：`git add -A && git commit -m "..." && git push`。CI 绿了会自动部署。

**顺序别搞反**：`@@summary` 必须在最后一个 `@@point` 之后，`@@quiz` 在 `@@summary` 之后，`@@links` 最后。放错位置 `check_content.py` 会直接报「小结在知识点前」。

## 2. 改一个错：三条规矩

这三条是**踩出来的**，不是理论：

1. **改句子中间，只能用子串替换，不许整行覆盖**
   我干过：用「按行替换」修 `@@map` 里的半句话，结果把整段压成了 `FP16（Float16）`；另一处把 `models = {` 的语法弄坏。构建和检查全绿，只有下一轮逐字读才发现。
2. **改完必须回看那一行**
   批量替换后 `git diff` 扫一眼，或者直接 `read` 那几行。`text.count(old)==1` 只保证“命中一次”，不保证“没吃掉上下文”。
   > 补一条 2026-10-29 又犯的：**子串替换也要选整句**。改「会在 user 表生成 user_id 列」时我只替换了前半段，拼出「会在 ChatSession 表生成 user 表生成 user_id 列」——半句话拼半句话，比原错更糟。
3. **改完跑全量**（不是只跑 `check_content`）
   漏跑 `build_search.py` 会被 CI 的「站点一致性」抓住（`search-index.js` 没更新）。

---

### 2.1 四条硬规矩（这两天用命换的）

1. **改一个说法前，先 grep 它在几处出现；改完再 grep 一次确认归零。**
   同一说法分散在正文、陷阱表、小结、自测题里——只改到处，就会出现「一处说 A、一处说 B」。
2. **多行命令块别用行号手术，整段替换。**
   按行号插入/删除会把多行命令的续行符、对齐注释全部弄错（Docker 那章我连错三次）。
3. **别把检查输出 `*> $null` 吞掉。**
   为此红过两次 CI：规则报了，我没看，直接推上去。
4. **示例必须演示出它自己要讲的问题。**
   `x = 5` 演示不出 `&` 与 `and` 的差别、`[1.0,2.0,3.0]` 演示不出截断、单 seed 的 KMeans 演示不出初始化差异。

## 3. 十道闸：红了看哪道

| # | 闸 | 报什么 | 常见原因 |
|---|---|---|---|
| 1 | `check_content.py` | 缺块、知识点数、密钥、个人信息、残句、`@@summary` 位置、表格列数 | 少写 `@@prep`；表格里 `\|` 没转义 |
| 2 | `check_consistency.py` | NAV 重复、`@@sub` 阶段与 NAV 不符、`@@h1` 章号与文件名不符 | 复制章节忘了改编号 |
| 3 | `check_facts.py --check` | 事实清单里的「错误写法」又出现 | 改稿时手滑写回旧说法 |
| 4 | `check_imports.py --strict --check` | 自称「完整示例」却缺 import | 复制片段时漏了 import |
| 5 | `build_ledger.py --check` | 台账行数 ≠ 238 | 加/删章后没重跑台账 |
| 6 | `stats.py --check` | README 里的数字与实际不符 | 加了知识点/坑/自测题没更新 README |
| 7 | `smoke_test.py --check` | 4 个示例跑不通（**不阻塞构建**） | CI 环境装包失败，多为网络 |
| 8 | `check_publish.py` | 密钥、课程品牌、本地路径泄漏 | 手滑贴了 Key 或品牌名 |
| 9 | 站点一致性 | `site/` 与 `content/` 重建结果不一致 | 只跑了 `build_site`，没跑 `build_search` |
| 10 | `verify_site.py` | 页面缺 CSS、死链 | `@@links` 写了不存在的 URL |

**排查口诀**：先看是「内容错」还是「产物没同步」——第 1–6 是内容，第 9–10 是产物，第 8 是安全。

## 4. 数字怎么改

README 和首页上那些数字（阶段 24 / 章节 238 / 知识点 2,189 / 避坑 2,070 / 自测 1,628）**不要手算**：

```bash
python tools/stats.py          # 打印实际数字
python tools/stats.py --md     # 打印可直接粘贴的表格
python tools/stats.py --check  # CI 用的校验，不一致就退出码 1
```

改完内容 → 跑 `--md` → 把新表贴进 README → 再跑 `--check` 确认。

## 5. 防复发工具（现在有六个）

| 工具 | 干什么 | 什么时候用 |
|---|---|---|
| `tools/facts.py` + `docs/事实清单.md` | 记录「错过的那些事实」（正确答案 + 曾经的错法 + 正则） | 又发现一个**跨章重复**的错，就加一条 |
| `tools/build_ledger.py` + `docs/覆盖台账.md` | 逐章覆盖表，手改「已读/备注」 | 每轮自查后更新；下次只挑没读的 |
| `tools/check_imports.py` | 查「用了某个库却没 import」 | 默认只报告（片段多，误报多）；`--strict` 只查「完整示例」 |
| `tools/smoke_test.py` | 真跑 4 个示例（FastAPI/Tortoise/Pandas/LangGraph） | 改了这些章的代码，或想确认环境没坏 |
| `tools/check_content.py`（4 条结构规则） | 见下面「内容规则清单」 | 每次 push 都会跑，红了就改 |
| `run_chapter.py`（临时脚本，不入库） | 把某章的 ```python 块抽出来逐块真跑 | 怀疑「代码能跑但结论错」时 |

**加一条事实**的写法：在 `tools/facts.py` 的 `FACTS` 里加一个 dict，字段 `id / fact / right / wrong / chapters / bad`，`bad` 是正则列表（能匹配旧说法）。然后 `python tools/check_facts.py --doc` 重新生成文档。

**内容规则清单**（`tools/check_content.py`，都对应一个真实踩过的坑）：

| 规则 | 拦什么 | 为什么加 |
|---|---|---|
| 小结位置 | `@@summary` 落在 `@@point` 之前 | 小结跑章中间，读者以为读完了 |
| 表格列数 | 同一张表每行单元格数与表头不一致 | 多打一根竖线，整张表渲染错位（我自己犯过两次） |
| 非注释语言的 `#` 注释 | `scala/java/json/xml` 块里出现 ` # 说明` | Scala 里 `#` 非法、JSON 里注释直接解析失败 |
| bash 里的中文尖括号 | `<名字>`、`<你的ID>` | bash 把 `<` 当输入重定向，照抄报 `No such file` |

**真跑一章的办法**（比读十遍都准）：

1. 抽代码块：把 ```python 块顺序执行（同一命名空间，模拟读者边看边敲）
2. 先换成无头环境：`MPLBACKEND=Agg`，并把 `plt.show()` / `uvicorn.run(...)` 置空
3. 看哪块报错：`ModuleNotFound` 多为缺依赖（可能是真缺安装步骤）；`NameError` 多为**变量在后面才定义**；`SyntaxError` 多为**伪代码被当成可跑代码**

判据：**能用一两句话解释清楚「为什么这块跑不了」才算合格**。解释不了，就是书的问题。

⚠️ **正则别写得太贪**：正确写法里经常包含否定词（「它**不会**把数据变成正态」「不是「再加 2 份」」），一条正则会把正确句子也抓出来。写不准就留 `"bad": []`，标注「靠人读」。

## 6. 内容写作规矩（写新章时照着做）

- **别用固定条数**：「三条原则」「五个要点」这种，一旦增删就对不上。用「几条」或直接列。
- **`@@prep`/`@@goal` 别写「掌握/了解/熟悉」**，写能验证的事：「能跑通 xx」「能说清 xx 为什么」。
- **理论章可以不装环境**：`@@prep` 就写「不用准备什么，也不用装环境」。
- **自测题要能在正文找到答案**，别出开放题。
- **代码块**：要么完整可跑（首行 import 齐），要么在首行注明「片段，承接上文」。这是 `check_imports.py --strict` 的依据。

## 7. 发布流程

```
本地改 → 跑生成器 + 检查器 → commit → push
   ↓
CI：内容质检 → 冒烟 → 构建 → 发布前扫描 → 站点一致性 → 站点自检 → 部署 Pages
   ↓
绿了才会部署；红了看第 3 节
```

**确认部署成功**的办法（CI API 限流时也能用）：抓线上页面，看有没有这次改的新内容——Pages 只在 CI 全绿后才部署，所以看到新内容就等于 CI 也过了。

## 8. 已知边界（别假装这些做过）

- **238 章都做过两轮**：一轮逐字读、一轮「概念因果 / 跨章契约 / 数据流」复核（台账全部 `是`）。但**两轮都是「读」**，不等于验证过——见下一条。
- **有 20 章的代码真跑过**（清单见 docs/代码验证清单.md：187 个代码块、146 个通过），其余 218 章仍是静态判定。
- **绘图块没跑**：本机没装 matplotlib（pip 在此环境会卡住），凡 import matplotlib 的块都记「跳过」，但同一块里绘图之前的数据处理部分是跑过的。
- **Docker / Spark / CUDA / vLLM 的示例没在真机跑过**（需要 GPU、云账号或装库），只有静态判定。
- **第三方营销数字没核**（飞桨开发者数、AutoDL 价格、ModelScope 额度），标了「存疑」。
- **约 6 条需要外部信息**的疑点留在 `docs/待办.md` 第三节，没猜。
