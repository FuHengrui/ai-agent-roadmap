# 事实清单（错过的那些）

> 由 `tools/facts.py` 生成，别手改；要加一条就改那个文件。
> 检查器 `tools/check_facts.py --check` 会在 CI 里盯住这些「错误写法」复发。

## RDD 的 MEMORY_ONLY 内存不够时怎么办

- **正确**：丢掉装不下的分区，下次用到时按血缘重算；只有 MEMORY_AND_DISK 才落盘。RDD 的「弹性」主要靠血缘重算。
- **曾经的错**：说 MEMORY_ONLY 内存不足会自动溢写磁盘
- **涉及章节**：阶段 13 RDD 章、缓存章、SparkSQL 章
- **检查器盯的写法**：`MEMORY_ONLY[^。\n]{0,20}溢出`、`内存不够[^。\n]{0,10}溢写到磁盘`

## sortBy / sortByKey 在多分区下是否全局有序

- **正确**：用 RangePartitioner，分区之间按区间有序，所以多分区结果本身是全局有序的；代价是要全量排序。写单文件才需要 coalesce 到 1 个分区。
- **曾经的错**：说多分区只是「分区内局部有序、跨分区不确定」
- **涉及章节**：阶段 13 行动算子章、SparkSQL 章、RDD 实战章
- **检查器盯的写法**：`多分区[^。\n]{0,12}局部有序`、`sortBy[^。\n]{0,24}交叉分区[^。\n]{0,6}不确定`

## union 去不去重、是什么依赖

- **正确**：union 不去重（并集），只是分区拼接：N 个父分区拼成 N 个，子分区与父分区一一对应，仍是窄依赖。
- **曾经的错**：说 union 会去重；或说它「一个子分区依赖多个父分区」
- **涉及章节**：阶段 13 转换算子章、内核章
- **检查器盯的写法**：`union[^。\n]{0,8}并集[^。\n]{0,6}（?不重`、`union[^。\n]{0,10}一对多`

## 闭包里的变量会不会被自动广播

- **正确**：不会。autoBroadcastJoinThreshold 只对 join 的小表生效；闭包变量要显式 sc.broadcast。
- **曾经的错**：说「≤10MB 的闭包变量 Spark 会自动广播」
- **涉及章节**：阶段 13 并行度与广播变量章
- **检查器盯的写法**：`自动广播闭包`、`10MB 以下[^。\n]{0,8}自动`

## StorageLevel 里的 _2 是什么意思

- **正确**：每个分区存两份、落在两个节点上（共 2 份），不是「在原有基础上再加 2 份」。
- **曾经的错**：把 _2 解释成「再加 2 份副本」
- **涉及章节**：阶段 13 缓存与 Checkpoint 章
- **检查器盯的写法**：`[+＋]2 份副本`

## Spark 排序时 null 排在哪

- **正确**：ASC 时 null 在前、DESC 时 null 在后（所以 desc_nulls_last 就是默认）。要让 DESC 时 null 仍在前，用 desc_nulls_first。
- **曾经的错**：说 orderBy 默认 null 排最后、desc 时反而在最前
- **涉及章节**：阶段 13 DSL 与 SQL 章、阶段实战章
- **检查器盯的写法**：`null 排最后（desc`、`desc 时 null 在前`

## SGDRegressor 是什么算法、learning_rate 默认值

- **正确**：随机梯度下降（可 partial_fit 增量训练）；learning_rate 默认是 'invscaling'（η=η0/t^power_t），adaptive 要显式指定。
- **曾经的错**：说它是 BGD/Mini-Batch；或说默认是 adaptive
- **涉及章节**：阶段 20 梯度下降实战章、衍生回归章
- **检查器盯的写法**：`SGDRegressor[^。\n]{0,20}默认是\s*`?adaptive`、`本质[^。\n]{0,6}BGD/Mini-Batch`

## StandardScaler 会不会让数据变正态

- **正确**：不会。它只是减均值、除以标准差，线性变换不改变分布形状；要正态得另做 log / Box-Cox。
- **曾经的错**：把「变正态」当成标准化的收益
- **涉及章节**：阶段 20 归一化与正则化章
- **检查器盯的写法**：（无法用正则安全匹配，靠人读）

## pandas 里 fillna(method=...) 还能用吗

- **正确**：不能。2.1 起弃用、3.0 已移除，改用 df.ffill() / df.bfill()。
- **曾经的错**：示例里写 fillna(method='ffill')
- **涉及章节**：阶段 17 缺失值章
- **检查器盯的写法**：`fillna\(\s*method\s*=`

## Chroma 返回的分数是相似度还是距离

- **正确**：是距离，越小越相似；阈值判断要用 <=，或先换成 1-score 再比。
- **曾经的错**：把分数当相似度、用 >= 过滤
- **涉及章节**：阶段 11 向量化与向量库章
- **检查器盯的写法**：`if d\[1\] >= settings\.RAG_SCORE_THRESHOLD`

## hermes memory 有没有 list / delete 子命令

- **正确**：没有。memory 工具只有 add / replace / remove（靠 old_text 定位）；条目就是 Markdown 文本，直接读改 memories 目录，或用 hermes journey 看时间线。
- **曾经的错**：写 hermes memory list / hermes memory delete <id>
- **涉及章节**：阶段 15 记忆章、定时任务章
- **检查器盯的写法**：`hermes memory (list|delete)`

## JWT 是加密还是只签名

- **正确**：只签名、不加密，payload 是明文 base64；能做的只有「验签」+「解出 payload」。
- **曾经的错**：写「解密验签」
- **涉及章节**：阶段 11 用户认证章、阶段 9 JWT 章

## docker rm -v 会不会删掉具名卷

- **正确**：只清匿名卷；具名卷要单独 docker volume rm。
- **曾经的错**：说 rm -v 会连挂载的数据卷一起删

## Dockerfile 是不是每条指令都加一层

- **正确**：只有 RUN / COPY / ADD 才加文件系统层；ENV、CMD、EXPOSE 只改镜像配置（BuildKit 下不占层）。
- **曾经的错**：说「每一条指令都生成一个独立镜像层」
- **涉及章节**：阶段 18 镜像仓库与架构章

## KMedoids 的中心是什么

- **正确**：medoid——簇内真实样本点（让簇内距离和最小的那个样本），不是中位数。
- **曾经的错**：说 KMedoids 用「中位数」当中心

## nn.Module.to() 是原地还是新建

- **正确**：Module.to() 原地改并返回 self；只有张量的 .to() 返回新张量、要接收返回值。

- **正确**：惯例是 (N, in)；一维 (in,) 也能算，输出 (out,)。只有后面接 BatchNorm 这类层才必须补 batch 维。
- **曾经的错**：说 nn.Linear 要求输入必须自带 batch 维

## LangGraph 的 interrupt 恢复时从哪继续

- **正确**：节点/工具**从头重跑**，interrupt 返回你传入的 resume 值；所以 interrupt 之前的副作用必须幂等，也不要拿 try/except 把 interrupt 包起来。
- **曾经的错**：说「恢复后从 interrupt 那一行继续执行」
- **涉及章节**：阶段 8 HITL 章

## join 是不是必然要 shuffle、必然切 Stage

- **正确**：RDD 的 join 默认要 shuffle；但如果两侧已按同一 partitioner 分区（co-partitioned），或走广播 join，就可能在同一个 Stage 里。
- **曾经的错**：说「join 就是宽依赖必切」
- **涉及章节**：阶段 13 内核章
- **检查器盯的写法**：`join 就是宽依赖必切`

## fold/aggregate 里的 zero 会被加几次

- **正确**：(分区数 + 1) 次——每个分区一次，最后合并还要一次。
- **曾经的错**：说只加「分区数」次
- **涉及章节**：阶段 13 行动算子章
- **检查器盯的写法**：`分区数[×x*]\s*zero`

## Structured Streaming 能不能用 countDistinct

- **正确**：不支持，会抛 AnalysisException；改用 `dropDuplicates` + count、`approx_count_distinct`，或放进 `foreachBatch` 用批处理算。
- **曾经的错**：在流式聚合里直接 countDistinct
- **涉及章节**：阶段 13 实战收官章
- **检查器盯的写法**：`countDistinct("user_id")`

## Chroma 的 metadata 能存什么、过滤怎么写

- **正确**：只能存**标量**（字符串/数字/布尔），数组会被拒；过滤用 `$eq` / `$in`，没有「数组包含」这种写法。
- **曾经的错**：写 {"laws": {"$contains": ...}} 并按数组理解
- **涉及章节**：阶段 11 RAG 检索章
- **检查器盯的写法**：`\$contains`

## Docker Hub 是 Registry 还是 Repository

- **正确**：Docker Hub 是**注册中心（Registry）**，里面按名字分成多个仓库（Repository），例如 `library/nginx`。
- **曾经的错**：把 Docker Hub 直接叫「仓库」
- **涉及章节**：阶段 18 Docker 概述章
- **检查器盯的写法**：`仓库（Repository）就是集中存放镜像的地方`
