# 事实清单（错过的那些）

> 由 `tools/facts.py` 生成，别手改；要加一条就改那个文件。
> 检查器 `tools/check_facts.py --check` 会在 CI 里盯住这些「错误写法」复发。

## RDD 的 MEMORY_ONLY 内存不够时怎么办

- **正确**：丢掉装不下的分区，下次用到时按血缘重算；只有 MEMORY_AND_DISK 才落盘。RDD 的「弹性」主要靠血缘重算。
- **曾经的错**：说 MEMORY_ONLY 内存不足会自动溢写磁盘
- **涉及章节**：阶段 13 RDD 章、缓存章、SparkSQL 章
- **检查器盯的写法**：`MEMORY_ONLY[^。\n]{0,20}溢出`、`内存不够[^。\n]{0,10}溢写到磁盘`

## sortBy / sortByKey 在多分区下是否全局有序

- **正确**：用 RangePartitioner，分区之间按区间有序，所以多分区结果本身是全局有序的；代价是要全量排序。写单文件才需要 coalesce 到 1 个分区。
- **曾经的错**：说多分区只是「分区内局部有序、跨分区不确定」
- **涉及章节**：阶段 13 行动算子章、SparkSQL 章、RDD 实战章
- **检查器盯的写法**：`多分区[^。\n]{0,12}局部有序`、`sortBy[^。\n]{0,24}交叉分区[^。\n]{0,6}不确定`

## union 去不去重、是什么依赖

- **正确**：union 不去重（并集），只是分区拼接：N 个父分区拼成 N 个，子分区与父分区一一对应，仍是窄依赖。
- **曾经的错**：说 union 会去重；或说它「一个子分区依赖多个父分区」
- **涉及章节**：阶段 13 转换算子章、内核章
- **检查器盯的写法**：`union[^。\n]{0,8}并集[^。\n]{0,6}（?不重`、`union[^。\n]{0,10}一对多`

## 闭包里的变量会不会被自动广播

- **正确**：不会。autoBroadcastJoinThreshold 只对 join 的小表生效；闭包变量要显式 sc.broadcast。
- **曾经的错**：说「≤10MB 的闭包变量 Spark 会自动广播」
- **涉及章节**：阶段 13 并行度与广播变量章
- **检查器盯的写法**：`自动广播闭包`、`10MB 以下[^。\n]{0,8}自动`

## StorageLevel 里的 _2 是什么意思

- **正确**：每个分区存两份、落在两个节点上（共 2 份），不是「在原有基础上再加 2 份」。
- **曾经的错**：把 _2 解释成「再加 2 份副本」
- **涉及章节**：阶段 13 缓存与 Checkpoint 章
- **检查器盯的写法**：`[+＋]2 份副本`

## Spark 排序时 null 排在哪

- **正确**：ASC 时 null 在前、DESC 时 null 在后（所以 desc_nulls_last 就是默认）。要让 DESC 时 null 仍在前，用 desc_nulls_first。
- **曾经的错**：说 orderBy 默认 null 排最后、desc 时反而在最前
- **涉及章节**：阶段 13 DSL 与 SQL 章、阶段实战章
- **检查器盯的写法**：`null 排最后（desc`、`desc 时 null 在前`

## SGDRegressor 是什么算法、learning_rate 默认值

- **正确**：随机梯度下降（可 partial_fit 增量训练）；learning_rate 默认是 'invscaling'（η=η0/t^power_t），adaptive 要显式指定。
- **曾经的错**：说它是 BGD/Mini-Batch；或说默认是 adaptive
- **涉及章节**：阶段 20 梯度下降实战章、衍生回归章
- **检查器盯的写法**：`SGDRegressor[^。\n]{0,20}默认是\s*`?adaptive`、`本质[^。\n]{0,6}BGD/Mini-Batch`

## StandardScaler 会不会让数据变正态

- **正确**：不会。它只是减均值、除以标准差，线性变换不改变分布形状；要正态得另做 log / Box-Cox。
- **曾经的错**：把「变正态」当成标准化的收益
