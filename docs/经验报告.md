# 经验报告：238 章知识库的三轮复核与 60 章实跑

> 项目：`ai-agent-roadmap`（24 阶段 / 238 章 / 约 173 万字 / 2,189 个知识点）
> 时间：2026-10-27 ~ 2026-11-01
> 撰写：DSH-35799，2026-11-01 定稿后复盘

---

## 一、这个项目原来是什么状态

一本写给零基础读者的 AI Agent 学习路线，238 章，从「Python 是什么」写到「把大模型部署成服务」。

写作方式是**一章一章堆出来的**，所以：

- 术语在不同章里叫法不一样（同一概念两种叫法、同一条目三种口径）
- 数字靠手工维护（知识点数、避坑数、字数）
- 代码块是手写进 Markdown 的，**没人保证它真能跑**
- 没有任何自动化检查，改一处不知道会不会弄坏另一处

**开始时已知的问题**：有读者反馈「照着敲报错」。

## 二、我做了什么（四层递进）

| 层 | 做法 | 触发原因 |
|---|---|---|
| ① 逐字通读 | 一章一章读，抓概念错、错别字、残句 | 最先想到的办法 |
| ② 跨章复核 | 概念因果 / 跨章契约 / 数据流闭环 | 发现单章读不出来，必须对照 |
| ③ 只找硬伤 | 只认三类：照抄会报错、事实/数值错、同章自相矛盾 | 二轮密度不降反升，说明角度比遍数重要 |

- 真跑脚本两个（单章 `run_chapter`、批量 `run_gpu_batch`）

## 三、错误的性质：八类

| # | 性质 | 一句话 | 真实例子 |
|---|---|---|---|
| 1 | **事实错** | 世界的真相说错了 | MKL/OpenBLAS 说成编译器；逻辑回归说成非凸损失 |
| 2 | **机制错** | 因果链讲反 | 阈值方向反（1=良性却让调低）；one-hot 喂 NLLLoss；stdio 说成每次调用起进程 |

| 6 | **示例失效** | 能跑但演示不出命题 | `x=5` 演示 `&`/`and`；单 seed KMeans；`add_word("特朗普")` |
| 7 | **版本时效** | 写时对，世界变了 | LangChain 1.x 删了 `StructuredOutputParser`；「Ollama 只认 GGUF」已过时 |

## 四、病因：五类，其中一类占四成

| 病因 | 说明 | 例子 |
|---|---|---|
| ① 本来就没懂 | 作者认知错 | 编辑器当编译器；「翻译只取最终状态」 |
| ② 时代漂移 | 写时正确，后来失效 | API 改名、库被删 |
| ③ **改稿副作用** | 局部改了，全局没同步 | 加警告没改步骤；列名只改一处 |
| ④ 抽象层错位 | A 层规则套到 B 层 | SQL 的自动广播阈值套到 RDD；`Dataset[T]` 的编译期检查套到字符串列名 |
| ⑤ 复制粘贴残留 | 从别处搬来没改净 | `patient` 外键（别项目的）、`diabets` 拼写、`<你的ClientId>` |

**③ 是数量最多的，粗估四成**：正文改了，陷阱表没改、小结没改、自测题没改——于是同一个事实在书里有两种说法。

## 五、最关键的发现：可检测性决定防线

```
第一层：读一遍就能看出来      → 残句、术语错、明显语法错
第二层：对照才能看出来        → 同章不同处、跨章说法
第三层：执行才能看出来        → API 改名、变量未定义、路径不存在
第四层：验证世界才能看出来    → 版本时效、第三方数字
```

**四层对应四道防线**：人工读 / 机器规则 / 真跑 / 查新版。

> **光靠「读」永远抓不到第三、四层。** 三轮阅读都没发现 `boxplot(labels=)` 已改名——跑一遍就现形。

### 按后果再分一次，最危险的是「静默」

| 颜色 | 表现 | 例子 |
|---|---|---|
| 红错（最友好） | 一跑就崩 | SyntaxError、参数不存在 |
| 黄错 | 能跑，结果错 | `distance` 当 `similarity` 比阈值；`labels` 与 `input_ids` 两次独立编码 |
| **黑错（最坏）** | 不报错、看着也合理，但知识是错的 | `case_type` 筛选永远返回空；TomEE 空目录；阈值方向反 |

**黑错的共同特征是静默失败**：程序不崩、页面正常、结果看着合理，只是「你要的那个东西根本没发生」。

## 六、十个最值得记住的案例

1. **KMeans 的 `X` 定义在最后一个代码块** —— 读者按顺序敲，前四个块全 NameError
2. **`x = 5` 演示 `&` 和 `and`** —— 5 的二进制是 101，两个都对，命题不成立
3. **单 seed 的 KMeans** —— 实测 seed=0 时两种初始化 SSE 完全相同；改扫 50 个种子才看出「4/50 更差」
4. **Chroma 返回距离当相似度用** —— 检索结果完全相反，且不报错
5. **`labels` 与 `input_ids` 两次独立编码** —— 标签泄漏，loss 照样降
6. **`docker.io/tomee` 用 tomcat 的目录** —— docker 静默建空目录，演示永远看不到页面
7. **7B 全参微调写 60GB** —— 实算 110GB（权重14+梯度14+主权重28+动量28+二阶28）
8. **两个 `@@h1`** —— 后者覆盖整页标题，面包屑还写着第十章
9. **`boxplot(labels=)`** —— matplotlib 3.9 改名 `tick_labels`，照抄 TypeError
10. **GitFlow 打标签人在 develop 上** —— 标签落在合并提交，与「标签打在发布提交上」矛盾

## 七、我自己犯的错（必须写进去）

这轮抓到我前几轮改出来的**二十来条回归**：

- 把 `UploadFile = File(...)` 说成「必须写」——其实注解成 `UploadFile` 就走 multipart
- 第 3 章钉 `matplotlib==3.8.2`，第 4 章却用 3.9 才有的 `tick_labels`
- 给 `PositionalEncoding` 补了成员变量，**没补类定义**
- 把方法签名改成不带 `self`，函数体里的 `self.salary` 没改
- checkpoint 打在**源 RDD** 上，等于没截断血缘
- 给 Coze 加了「旁白要先并入」的警告，**下面四步清单没跟着改**

**结论：改内容比写内容更容易制造矛盾。**

## 八、我最后形成的五条硬规矩

1. **改一个说法前先 grep 全库有几处，改完再 grep 一次确认归零**
2. **多行命令块不要用行号逐行修改，整段替换**
3. **不要用 `*> $null` 丢弃检查输出**（为此红过两次 CI）
4. **示例必须演示出它自己要讲的问题**
5. **判不准就不写正则**（写宽了全是噪音，比如「`**` 必须成对」误报 25 处）

| # | 做法 | 省掉什么 |

## 十二、给别的项目抄的清单

如果你也要审一本几十万字的技术书：

1. **先建台账**，标清哪些读过、哪些没有——否则永远不知道进度
2. **两种角度交替**：逐字读（抓局部）+ 跨章对照（抓矛盾），别指望一遍搞定
3. **第三遍只找硬伤**，把「措辞/风格」明确排除，否则会被噪音淹没
4. **能跑就跑**，跑不了的写清「没跑」，别假装
5. **每修一个错，加一条能拦它的规则**——这是唯一能让错误不再复发的手段
6. **边界写进文档**，让读者知道哪部分可以直接照抄、哪部分要自己判断
